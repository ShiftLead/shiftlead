## §4.2

- 2026-11-13 (TD-1815 design, designer-ao-1): *A subagent's event, for a tool with no channel*: for a tool with no permission channel, an event carrying `subagent` (a tool event, a start, a stop) also removes the main-thread permissions, writing nothing into `kept`, since such a tool's prompt may name no thread. Round 1 replaced a first draft (a `unplaced` prompt field, an entry kept apart while a subagent was counted) with this rule: Fable's review found it did the same with no field, no count and no gap after a `subagents_reset`. Build TD-1817.

## §4.3

- 2026-11-13 (TD-1815 design, designer-ao-1): *A subagent's events* (Grok Build's): Grok 1.0.77's child prompt carries the parent's `sessionId` and no `subagentType` (`hooks-subagents.jsonl`), so the hook sends it as the main session's and §4.2's rule ends it on the child's next event; the per-child keying of the prompt is dropped, and attributing a prompt to the thread of the last `PreToolUse` is rejected (a call the other thread runs unasked fires one too, and a wrongly placed prompt can stick). Build TD-1817.
