## §4.7

- 2026-11-14 (TD-1795): `ao feedback intake --issues <file> --root <root> [--json] [--read <number>…]` is built,
  in `shiftlead.feedback_intake` on TD-1794's shared rules, as §4.7 *The intake, in file mode* gives it. A
  refusal's `<field>` is the field's bare name (`what: bad type`), never an item's index; the reports are
  ordered by issue number; a `login` not of GitHub's shape prints `null`, as a deleted author's does; a number
  named twice after `--read` counts once toward the 5; a JSON top level that is no object is `block does not
  parse`; `cut.counts` counts the kept items whose count was over 999, `cut.text` the kept `what` and `fix`
  strings the 300-character cut shortened.
  A body's CRLF line ends are read as LF (GitHub's form keeps a textarea's CRLF), and a `v` of `1.0` is `unknown v`.
  The shared normalize step drops a lone surrogate (category Cs) as it drops Cc and Cf, so no stranger's string
  makes the printed JSON unencodable, in the report or the intake.
