# TD-2232: Adding a second tool's login under a used name stops stored sessions finding their account

## What it does

A stored session remembers the name of the login it ran under. Today two tools can each have a login of the same
name on one host, and when the second is added, every session stored under that name stops finding its login and
its account: it cannot be resumed, and its spend is counted under a key no reserve is kept under. This design makes
a login's name unique on its host across every tool, so a stored name always points at the one login it was
written under.

## The key choices, and why

- One name per host, whatever the tool, so every reader of a stored session stays as it is.
- A forgotten login's name stays taken for good. Its sessions point at no login while it is forgotten, and come
  back when its folder is added again and takes the name back. Nothing else can take that name meanwhile.
- Every place that names a login keeps the rule: adding a login refuses a name another tool's login has, live or
  forgotten, with its own words for each; the suggested name skips them; setting up a container node adds no login
  under such a name and says so; the switch-over refuses an answers file that would break it.
- A name held by a plain-shell profile, or one whose tool is not registered, is held during the switch-over only;
  a login added under it afterwards reads those sessions as its own, accepted because they have no account or
  transcript to mix.
- A file edited by hand to share a name is accepted as stranding its sessions, since nothing shiftlead writes makes
  one.

## What it rules out

- Writing the tool's full key into every stored session, or reading a stored session by its login first: each
  changes every reader for a case the rule already rules out.
- Telling shared names apart by the session's tool when reading: cheaper, but one name would still name two folders.
- Reading a forgotten login's transcript while it is forgotten is not in this design: the tools page promises it,
  no reader gives it yet, and TD-2280 designs it on its own.

## What you will see

Adding a login under a name another tool already uses on the host, or once used, is refused with a message naming
the holder. Nothing else changes: stored sessions keep finding their account after another tool's login is added.
