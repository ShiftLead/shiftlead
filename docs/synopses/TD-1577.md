# TD-1577: Test a model integration without relying on the model answering well

## What it does

Today a new model seat is judged by running it on live pull requests for weeks, where a seat that never answers
and a model that answers badly look the same. This design splits the question in three:
- **Does the wiring work?** A test in the normal suite plays a whole seat's life with a fake tool standing in for
  the real one: it starts, is asked, reads its inbox, replies, and is closed. No model, no network, every adapter.
- **Does the real tool run unattended?** The seat smoke starts the real tool exactly as a seat is started, with no
  one answering prompts, and sends one ask. Any reply within ten minutes with no NEEDS YOU passes it.
- **Does the model judge well?** A fixed set of doc changes with known, planted mistakes is handed to the role.
  Its replies are scored by a program: caught, missed, false. At least ten cases, three with no mistake, and at
  least ten mistakes. Only the fact-checker gets a set now; a reviewer's waits for its own entry.

## The key choices, and why

- The fake tool replays what the real tools were recorded doing, so it tests our side and never guesses theirs.
- The smoke's ask names the reply command's options on purpose, so Gemini's guard against untrusted flags meets
  the same road a real fact-check does. That guard is what stopped the fact-check seat (TD-1576).
- The smoke and the scoring run are run by hand: by the builder of a change, before a seat lands on a profile,
  and after a tool upgrade. Nothing runs them on a schedule, so no quota is spent unasked. Noticing an upgrade by
  itself is TD-1650's to design. A smoke spends one prompt and one reply; a scoring run, one ask per case.
- Scoring needs no model. A finding counts when it names a file and line inside a planted mistake or the code
  that disproves it. A repeat of the same catch is not counted against the model.
- Each case runs in a throwaway repository with no history, so the answers are out of the seat's reach.
- The bar is the same one the live trial uses: few misses, few false findings, few silences.

## What it rules out

- A model taking the fact-checker role alone before a scoring run on its profile has passed.
- A new seat line on a profile that no seat smoke has passed on.
- Both are a rule the pull request adding the seat line follows and its reviewer reads, with no check behind
  them. Seat lines already declared stand, and so does a seat asked beside another, as the Gemini trial's is.
- Running either live check in the continuous build.
- A Gemini profile passing the scoring run before TD-1582 changes its reply road.

## What you will see

- A row per scoring run in a judgment page in the repo, the Gemini trial's tally entered as its first row.
- A one-line result from the seat smoke quoted in the pull requests that need it.
- Three builds: the fake-tool test, the seat smoke, then the planted-mistake set.
