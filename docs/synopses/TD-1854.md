# TD-1854: A lift PR the gate sweep opens reaches nobody: hand each one to a reader

## What it does

Every pull request the home's daily gate sweep opens becomes work a grinder takes at once. Today only a live
check's lift is anyone's job. This adds every other lift (a date reached, an event seen) and the sweep's own
board pull requests (the items it files on this repo's board, or on another repo's). The home still merges
none of them: a grinder reads each one, checks it is still right, and merges it or closes it with a comment.
In a repo no team looks after, each one is a row in your Inbox instead.

## The key choices, and why

- A work order a grinder picks up, the road a live lift, a red pull request and a forgotten filing pull
  request already take.
- The branch name alone says a pull request is the sweep's. The stranded-work sweeper seat moves its own
  branches to a new name so the two are never mixed up.
- The grinder checks each lift before merging: an event lift's check is run again (a home-log check is taken
  on the home's word, since only the home can read that log); a date lift waits for its day; a lift whose
  gate has already gone is closed. An event lift whose check now reads not yet, or can no longer happen, is
  closed too, and the sweep does not open it again: you lift that gate by hand if the event comes back. An
  early date lift you opened yourself is left for its day, or merged.
- A sweep board pull request is merged as the sweep wrote it. The review rounds tried three ways to spot one
  gone stale and each was wrong, so an item you settled in the meantime is yours to close again. It is closed
  only where it no longer merges onto the board, and for another repo's notices that costs its other items a
  month's wait, since a closed notice counts as your no.
- A lift whose check keeps failing is dropped by each grinder that tries it, and the sweep's own item asks you
  about the broken check.
- Where a repo's own reviewer must read these files, the grinder asks that reader as the author would, and the
  reader merges.

## What it rules out

- The home merging its own pull requests.
- Any pull request being two kinds of work at once: the sweep's, or a red one, or a filing one, never two.
- A lift being merged before its day, or after its gate went another way.

## What you will see

- The sweep's pull requests merged or closed by grinders within the day, with nobody prompting.
- On a repo's page and in its summary, *lift* and *sweep* tags and counts beside the red ones.
- In a repo no team looks after, or one not set up for the cadence, an Inbox row for each, marked as yours.
