# TD-1541: An unstamped ask from a node's session draws on another repo's kept card through the bare kept: key

## What it does

A question from a session names an entry like TD-64 without saying which repo it means. Since messages began
carrying their sender's repo, that is read as the sender's repo's TD-64. Older messages carry no repo, so the
Queue works it out: from the record left when its sender went away, else from the sender's session record, else
from the team the sender belonged to. When none of these names a repo, the question now stays in the Inbox. It
no longer lands on whichever card happens to hold a TD-64, which is how a contractmatch question ended up on a
finished ShiftLead card.

## The key choices, and why

- The sender's session is looked up by its full address, the session's name plus the machine it runs on. The old
  lookup used the bare name, so it missed every session on a container node. That miss caused the contractmatch
  case.
- A session on another machine is never named by the last folder of its path. A path on a node says nothing
  about which repo this machine reads there.
- A team serves one repo, so an older message whose sender is gone can still be placed by its team. This only
  works when the team's sessions all point to one repo. If they point to several, the message stays in the Inbox.
- A message with no known repo matches nothing by a bare number: no open card, no finished card, no design link.
  An entry written in full, like contractmatch#TD-70, is still read as written.
- Closing a question once its work merges uses the same order. There it names a node's sessions by that node's
  own list of repos, and counts only live sessions.

## What it rules out

- A question drawn on another repo's card because the two repos share an entry number.
- Guessing a repo from a folder name on another machine.
- Messages sent since the repo stamp began are unchanged. So are red pull requests and board lines.

## What you will see

The four older contractmatch questions leave the finished ShiftLead cards. Each moves to a contractmatch card
where this machine reads that repo, or else to the Inbox. Newer questions draw where they did before.
