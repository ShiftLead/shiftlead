# TD-1835: A Grok session runs under the person's Claude Code permission mode and rules

## What it does

Grok reads the person's own Claude Code settings, and on the installed version a Claude permission mode there beats
the mode ShiftLead asks for at launch, so every Grok seat ran under the Claude classifier. Every Grok launch now runs
with a home of its own: a copy of the person's home made of links, missing only Claude Code's two personal settings
files and the person's own Grok home. An unattended Grok seat that must ask every permission is refused at launch
when a repo's or the machine's Claude settings would set another mode.

## The key choices, and why

- A home of links, not a Grok setting: no Grok config key or variable tried beat the Claude mode, and the one file
  that did is Claude Code's own, which ShiftLead never writes for the person.
- Everything else stays reachable through the links (git, ssh, GitHub sign-in, Claude's instructions and skills).
- The links are refreshed at each launch; a file a session rewrites in place of a link is moved aside, never deleted.
- A repo's own Claude settings still reach Grok, being the repo's; where they would stop a watched seat asking,
  the launch refuses rather than run unasked.
- The techlead took this over the alternative of saying the person's Claude settings simply apply.

## What it rules out

- Your Claude permission mode, allow and deny rules no longer apply to Grok seats; a Grok profile's mode is its own.
- A file a session writes at the top of its home lands in the profile's links folder, not your home.
- No watcher: a change to your home reaches a running Grok session at its next launch.

## What you will see

- Grok seats that ask permissions as their profile says, whatever your Claude mode.
- A refusal naming the file, when a repo or machine setting would stop a watched seat from asking.
- Doctor notes on a Grok profile when your Claude settings set a mode or rules that no longer reach it.
- One build, TD-1836; the walk TD-1637 waits on it.
