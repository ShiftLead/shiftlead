# TD-2080: Temporary files keep exhausting the machine's shared temporary disk and stopping every session

## What it does

- Unattended seats get a temporary pool of their own, so their test runs and clones no longer fill the space your
  sessions and the machine depend on. Your own sessions stay where they are.
- When the seats' pool runs low, shiftlead clears what can be rebuilt straight away, without waiting for the hourly
  sweep: finished and dead test runs, directories of runs that ended over an hour ago, and old build leftovers.
- If a pool stays low, you are told once, in the Inbox and by Telegram or push, with its three largest holders.
- The test suite and shiftlead's own scripts stop writing to the bare shared directory.

## The key choices, and why

- Only unattended seats use the pool, as you asked. A seat you take over stays in it until its next fresh start,
  and a session you turn unattended stays out until then.
- On this machine the pool is a 6 GB memory disk. The root disk was about half as fast and is 77% full. Memory is
  capped because the machine has 30 GB, and everything in the temporary directory held 2.6 GB when measured.
- Clearing starts at 25% free and stops at 35%. You are told at 15%.
- Git work is protected as it is today. A live seat's clones and temporary trees are never cleared, only named.
- The shared temporary directory is watched but never cleared by this design, because what is in it is yours and
  the machine's. Its existing session-start cleanup carries on.

## What it rules out

- A hard limit per seat. Every seat is the same user, so that would need privileged code on every host. Seats
  therefore share the pool, and one that fills it can stop its siblings until space is cleared.
- Raising the inode limit on the shared temporary directory, since the seats' load leaves it.
- Putting the pool on the root disk.

## What you will see

- One step for you, on the board once the first build lands: create and mount the pool, set it for this host,
  restart the host agent, then stop and start the teams. Until then nothing moves. If the mount is ever missing,
  unattended seats refuse to start and say why, rather than filling the root disk; your own sessions are unaffected.
- A new Inbox row, temporary space low, with a Snooze, only when a pool stays low.
- The disk report shows each pool, how full it is and what holds it.
