# TD-1954: The Flows page

## What it does

A flow says how a ledger entry moves from filed to done, and you build one on a page instead of in prose.
A flow is a list of stages. Each stage does one kind of work, design, build or review, on a model you pick,
and a fresh session takes the entry every time it enters a stage. A session ends its stage by naming one of a
few fixed outcomes, such as work pushed, ship or changes wanted. For each outcome you choose where the entry
goes next: another stage, merge it, or you.

## The key choices, and why

- One kind of work per stage, so the choices stay few and a check can prove the flow works.
- The session names the outcome with one command, and the home checks the facts first. A red check is not an
  outcome. No stage ends while the home is down; the session tries again.
- Any move can carry a limit: up to three times, then it comes to you. A total cap catches the rest.
- What comes to you is a question on the entry, with answers to press, on your Queue. Each question is a small
  pull request on main.
- Merge is a place an outcome goes, not a stage, so no model is spent on merging.
- A review can run only when the work touches protected files. The tech lead stops reading those; a review
  stage does.
- Audits run on a clock and file what they find. Today's docs and test auditors become two of them.
- Where an entry is lives on one ShiftLead branch in the repo, written only by the home, so it survives a restart.
- The tech lead, board answers, pull requests nobody holds, manager and sweeper are in every flow, and you
  choose only their models.
- Sonnet and Haiku each wrote working flows from the written description alone, in three trials.
- What a push to that branch and a question cost against the forge's limits is unmeasured until the first build.
- Everything switches at one cut-over, which waits until the team page, TD-1153, is designed and built.

## What it rules out

- One session that designs and builds, or carries on from one stage to the next. That is an interactive session.
- Stages for triage, tests or merging, and hunts started by a ledger entry.
- Work without a pull request, for now.
- A higher round limit for far-reaching designs, a model that reads only a design's first round, and a session
  that judges when a design's rounds end. At a limit you answer carry on, and the count restarts.

## What you will see

A Flows page that lists the built-in flows, td, build-review and build, and your own. You copy one to change
it, add stages by clicking a kind, and pick each outcome's next step from a list. The page says whether the
flow works and marks the row that does not. A second tab walks an entry through the flow, and a third shows
the file it saves. Each stage and audit picks a brief, a standard one or one you wrote on the Briefs page.
