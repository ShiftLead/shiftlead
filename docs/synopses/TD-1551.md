# TD-1551: Order what a started member reads so sessions share the prompt cache

## What it does

It measured what a session ShiftLead starts reads from the prompt cache, first from 511 kmaster transcripts and then by
recording what Claude Code actually sends, through a small logging proxy. A start already reads the tool definitions
and the whole system prompt, ShiftLead's preface included, from another start's cache: about 29 thousand tokens. It
reads nothing after that, because Claude Code marks no cache point inside the first message, and that message names
the worktree and the date. So each start writes its first message fresh, about 27 thousand tokens, and a role's brief
(a grinder's is about 8 thousand) is part of it.

Its builds move the text that is the same for every start of one kind — a role's brief, and the Add entry
form's instructions — into the system prompt, where the cache reads it, and puts every value that differs per start
(the new entry's repo, type and priority, and your own words) after it, in the typed first message. A brief is already
the same for every member of one team line, so it moves whole. It moves only for a tool whose cache reads that spot,
Claude Code today, and only for a session the home starts itself; Gemini CLI and a node's members keep the brief
typed until their own cache is recorded.

## The key choices, and why

- Claude Code's dynamic-sections option is not used: on an interactive start it changes
  nothing, since Claude Code already keeps the working directory, date and git status out of the system prompt.
- Nothing in the first message is reordered: no other session ever reads it, whatever the order.
- One per-start byte in the system prompt would cost the whole system prompt's share, so no per-start value goes there.
- Every tool ShiftLead runs caches its own way, so recording a start's cache layout is a step of each adapter's
  conformance walk, with the capture script TD-1664 commits. TD-1664 also moves the Add entry form's
  instructions; TD-1669, split out after four review rounds kept finding new cases in it, moves a member's brief.

## What it rules out

- Filing anything with Claude Code's makers: that is outward-facing and yours.
- Reordering or trimming agent-cadence's session-start output: it lands after the system prompt either way, and it is
  about a thousand tokens. The larger item there is the claude.ai connectors' instructions, about five and a half
  thousand tokens a start; whether a member's profile loads them is your setting.

## What you will see

- TD-1664 has your go. A decision on the board: Go on TD-1669 once a review round finds nothing build-changing.
- If it lands, Focus still shows a member's brief under *told at start*, read from its context file. A member's
  start writes about its brief's size less when another member of the same line started within the hour, and about
  two thousand tokens more when its brief is its own.
