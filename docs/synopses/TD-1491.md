# TD-1491: /shiftlead-feedback: a procedure that reviews seats' transcripts for machinery friction

## What it does

It makes the review you ran by hand on 2026-11-06 a procedure you start from a session you drive. You pick
the seats and a window. A command condenses each seat's conversations in that window into short text, and
one fresh agent per piece looks for where shiftlead, the cadence or ledgerboard got in the seat's way. The
session merges what they find, checks it against the open and archived ledgers of all three repos, groups
it by cause and shows you a report. Nothing is filed until you answer each group.

## The key choices, and why

- The procedure ships with ShiftLead and prints with one command; a thin skill here points at it.
- The condensing reads through each tool's adapter, so no tool's file layout leaks into the core and a seat
  on a container node is read through the home. It keeps prompts to three lines, the seat's own words whole,
  and failed calls; successful calls become a count; thoughts and subagents' steps are dropped, so a step
  repeated by hand is found only where the seat says so.
- A seat whose read fails partway gets no text at all, so no agent reads half a seat as if it were whole. You
  are told which conversation failed, and either condense every seat again leaving it out, or let that seat
  go unread, asked again after each failed try until you let it go. A seat you let go stays unread even if a
  later try reads it. The filing PR names what went unread; later runs offer to re-read that run's whole
  window until a newer filing PR merges, and a declined offer is lost.
- A finding counts as known only when an entry's title and Why name the same symptom, checked by reading the
  entry, never by a keyword alone; ids the seat named and open PRs' entries too. A fixed entry whose symptom
  came back after its resolved day is filed again as recurred.
- Each finding has a fixed shape (seat, days, count, what, evidence, why, fix, area), and the report gives
  a noise figure for each agent, each seat and the run.
- Evidence quotes stay in the report (a seat's repo may be private, a ledger public). The condensed text goes only to
  the agents your session starts, on your session's account, which may not be the seat's: a Gemini seat's text is read
  by Claude. A seat's directory may also hold your own sessions; the session lists every conversation first so you can
  leave those out.
- The filing PR records the window, what went unread and what was sent elsewhere; it opens when the run writes
  even one note, else the next run starts where this one did, and no run starts while one is open. A note
  like an earlier one (same seats, overlapping window) is marked already noted and left out of "all notes";
  for parts sent elsewhere you check the last PR's sent list, or your memory after a run with no PR.

## What it rules out

- A seat running it on a schedule (the last step is your approval), or a run outside a shiftlead checkout at the home.
- Reports from other people's installs: that is phase 2 (TD-1718), after a privacy design round.
- Gemini seats' failed calls are not shown until a recorded failing call lands (TD-1719).

## What you will see

A report in the session's chat: the window, the seats, counts by outcome, the noise, then each group with
its proposed entry. You answer each group file, edit (which can drop one repo's part), merge or drop, and say
which notes on known entries to write. Shiftlead's entries then arrive in one PR titled with the window;
another repo's go to its question seat; problems with the coding tool itself are listed for you to report.
