# TD-2103: Sweep detached worktrees that have fully landed

## What it does

The hourly disk sweep has always kept every worktree that is not on a branch, however old. This design lets it
remove one once nothing in it can be lost. Measured today, that frees 12 of the 26 such worktrees, about 360 MB.

## The key choices, and why

- A worktree counts as landed only if its commit is already part of the default branch on GitHub.
- A commit that exists only in the worktree's own history keeps it, because removing the worktree would lose it.
- A team member's worktree is kept while the member's session record exists, even if that session has ended.
- Once that record is gone the worktree can be removed, and the member's next start makes a fresh one. The host
  agent does not read the team definitions, so the record is the only sign of a seat it has.
- A rebase or similar operation in progress keeps the worktree, and so does a commit that moves during the sweep.

## What it rules out

It deletes no branch and changes nothing for worktrees on a branch. Anything with uncommitted changes, written
within the last 7 days, or holding files git ignores stays, which is why most of the 3.4 GB first estimated
is not reclaimed: one worktree alone holds 2.1 GB of build output.

## What you will see

Fewer old worktrees on disk. The disk page names why each remaining detached worktree is kept.
