# TD-2103: Sweep detached worktrees that have fully landed

## What it does

The hourly disk sweep has always kept every worktree that is not on a branch, however old. This design lets it
remove one once nothing in it can be lost. Measured today, that frees 12 of the 26 such worktrees, about 360 MB.

## The key choices, and why

- A worktree counts as landed only if its commit is in the default branch on origin, as this machine last
  fetched it.
- A commit that exists only in the worktree's own history keeps it, because removing the worktree would lose it.
- Any session's worktree is kept while that session's record exists, even if the session has ended. A closed
  session's record lasts a day, an exited one's until it is removed. The host agent does not read the team
  definitions, so a seat is known only by its record.
- Once the record is gone the worktree can be removed, and a seat's next start makes a fresh one.
- A rebase or similar operation in progress keeps the worktree, and so does a checkout that moved by removal
  time.

## What it rules out

It deletes no branch and changes nothing for worktrees on a branch. Anything with uncommitted changes, written
within the last 7 days, or holding ignored files that cannot be rebuilt stays, which is why most of the 3.4 GB
first estimated
is not reclaimed: one worktree alone holds 2.1 GB of build output.

## What you will see

Fewer old worktrees on disk. The disk report names why each remaining detached worktree is kept, and its
preview removes nothing.
