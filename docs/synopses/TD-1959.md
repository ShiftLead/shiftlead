# TD-1959: The Focus page's file links follow only the session's starting worktree

## What it does

When a session moves its work, its Focus page now shows where it went. The Git card names the worktree beside the
branch when the two differ, and where the session's tool reports working in another folder, the card holds a
link that opens that folder in your editor. A file the session prints from there opens where it wrote it, and a
path printed with a brace set, such as a pair of screenshots, opens the first of its files that exists.

## The key choices, and why

- The card's changed files, its commit picker and the recent files stay those of the session's own worktree:
  that is the worktree the session owns, checks before a close and removes when it is closed, so the moved
  folder is offered as a link rather than read in its place.
- The folder the tool reports is kept only while it differs from the session's own, so a session that never
  moved shows nothing new.
- A path the session prints is looked for in the folder it reports first, then in its own, so a link reaches
  the file it meant; opening one from the moved folder brings forward that folder's editor window.
- The worktree and branch are named together only on a worktree whose branch has another name, so the main
  checkout's card is unchanged.
- A brace set opens the first of its files found; none found leaves it as text, as any unknown path is.

## What it rules out

- Only Claude Code reports its folder today; other tools' sessions show no working-in link.
- Nothing the home does reads the moved folder: closing, cleaning up and the wind-down still check the
  session's own worktree.
- A path with two brace sets, or one inside another, is not expanded.

## What you will see

The Git card's top line reads, for example, worktree td-1153 · on branch td-1953-tools · 4 unpushed. Under it,
when the session works elsewhere, a line reads working in, then the folder, which opens it in your editor.
