# TD-1437: A live check waits for its build to be live on a gate

## What it does

A live check stays out of the grinders' lanes until its build runs, held by a gate on the entry, not by the PR
numbers on its Kind line. The home keeps a tag, promote/live, on each promoted repo's origin at the live commit.
The PR that makes an entry a live check adds a gate that passes once the entry's file, as that PR wrote it, is
in the tagged commit; the event runner lifts it with a lift PR a grinder re-checks and merges at once.

## The key choices, and why

- A tag the home moves, not a deploy branch: the live commit lives only on the home, a forge check needs a
  ref to read, and a tag sits in no branch list and no branch rule refuses it. The other two roads did not
  fit: the squash commit does not exist when the PR is written, and the home's log has no promote event and
  would miss a promote on the merge day.
- The gate reads the entry's file at the tag, so it names no commit and every earlier PR of the build is
  already included. Gate names are never reused (a lifted gate's text stays in the file): a later fix PR of
  the build adds live-2, live-3; the fix for a failed check adds one named for the fix. These names are
  reserved, so no other gate can pass at the tag.
- The tag names only a build a promote or rollback run finished at, its smoke passed; a failed build, a run
  still going and a hand install are not tagged, and the tag stays put, even on a build no longer live.
- A failed promote blocks only its own commit (Paul's Hold): the automatic promote retries once main moves past
  it, a failure never refuses your Promote or a rollback, which clears it, and a note says why it failed. A
  failed rollback blocks main's head as you pressed it, so a later merge goes live. There is no Dismiss: a
  hold ends only when a Promote of main's head concludes.
- A copy you install by hand is tagged only by a run, never by the automatic promote: its row reads installed
  by hand, promote to tag it; an older commit installed by hand is tagged by a rollback to it.
- The home reads the tag every full pass. A tag already at live is adopted; a tag moved by someone else, or a
  branch of the same name, stops the home pushing and sends you one note saying how to clear it.
- After a push the home sweeps that repo's gates on the next tick, not just once a day. It opens lift PRs and
  merges none; a lift whose re-check reads not yet is closed and a fresh gate written in its place.
- Kind line PR numbers stay as words; nothing picks or holds by them. Four builds land in order: the failure
  and hand-install changes (TD-1559), the tag and sweep (TD-1450), the gates in the briefs and on every open
  live check (TD-1451), then the reader stops holding on the numbers (TD-1452).

## What it rules out

- No session ever pushes the tag; it is the home's alone, and assumes one home per origin.
- A lift is one way: a rollback after it leaves the check pickable, and the grinder that finds its build not
  live adds a fresh gate.
- A repo with no promote block has no tag; its gate never passes until a person lifts it by hand.
- On a public repo the tag makes the live commit public.

## What you will see

A live check not yet live reads waits on event (live) with not live #n beside it on the Repo page and in ao
repo, and lift #n open while its lift waits. A system note reaches you if a promote fails, or if someone moves
the tag or makes a promote/live branch.
