# TD-1815: A Grok child's permission prompt carries no subagent marker: how it is read and cleared

## What it does

When a Grok Build session runs a helper agent (a subagent) and that helper asks to run something, Grok's
notice of the question looks exactly like one from the main session: it names the parent and nothing of the
helper. Today the card then says the session needs you, and nothing clears it until the main session moves
again, so a session can read "needs you" for a helper's whole run. With this design the card clears as soon
as either the main session or any helper moves on, since either may be the one that asked.

## The key choices, and why

- The rule is general: for any tool that cannot answer its prompts through ShiftLead, a helper's activity
  clears the main session's open permission questions, just as the main session's own activity already does.
  No new field marks a prompt; nothing counts helpers to decide.
- A helper starting also clears the question that asked to start it, since it only starts once allowed.
- Grok's hook passes on a helper's finishing and stopping events, tagged with the helper's own id, carrying no
  state of their own, so a helper can never make an idle session read working, nor point the card at the
  helper's own transcript.
- Guessing which agent asked from the last tool started was rejected: a wrong guess could leave a question
  stuck with nothing to clear it.

## What it rules out

- The card cannot say which helper asked; it shows the question as the session's own, answered in the terminal.
- Early clears are accepted: a question can clear while its answer is still owed, when the other agent moves
  first. The terminal title, where Grok's can be read, is the check.
- A few cases Grok's recording did not show are accepted as they fall: an idle notice during a helper's
  question, a helper that asks you a question, a cancelled helper's count, a helper outliving a clear.

## What you will see

A Grok session whose helper asks permission shows "needs you" with the question to answer in the terminal, and
goes back to working, or idle, as soon as the helper carries on. A session no longer reads "needs you" for a
whole helper run after you allowed it to start.
