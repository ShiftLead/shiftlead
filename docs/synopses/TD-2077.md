# TD-2077: Comparing flows needs its metrics recorded from the start

## What it does
Each entry's stage record, the file the home keeps per entry on the repo's state branch, now also keeps
what a later comparison of one flow against another needs. Every time a session's part in an entry ends,
however it ends, the record notes which model, tool, version and login that session ran on, what it spent,
how many questions it put to you, and which version of the flow it ran under. Lost sessions, questions the
home asks you, limits reached and a review's count of findings each leave a mark. A closed record is kept
as a copy instead of being deleted after thirty days. A table in the design says where each reading is.

## The key choices, and why
- One store: the readings live on the entry's own record, which no rule acts on, so nothing new is kept
  elsewhere and nothing about how entries move changes.
- A flow's version is a fingerprint of its definition and its stage instructions, and the text behind each
  fingerprint is kept, so runs before and after an edit to a flow can be told apart.
- The spend written when a stage ends is a floor; the comparison reads it again from the home's spend file,
  kept thirteen months, which has the session's last turns.
- A review stage gives two counts, every finding and those it would not ship with, which stand in for the
  finding classes a design's review rounds have.
- Closed records are copied, not read from the branch's history, so a comparison reads plain files.
- All three builds land before the switch-over window, since it waits on this design.

## What it rules out
- Defects a build or a review let through are not counted: the ledger marks only a design's misses, and
  your request was about defects that trace back to designs.
- A follow-up entry is not linked to what it follows.
- Per-stage cost, time, questions and losses have no baseline from before the switch-over, since the old
  way of working kept no stages; cost per entry and review comments do.
- The comparison itself is later work (TD-2078).

## What you will see
Nothing changes on any page. A review stage's session is told to give its two counts when it ends, and the
review comment it leaves carries the real count.
