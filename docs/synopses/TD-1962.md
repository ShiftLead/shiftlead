# TD-1962: A failed layer listing refuses Add entry and Start session, and the design says nothing of it

## What it does

When agent-cadence's listing of your layers fails (it cannot run, exits with an error, or prints nothing usable),
every start that would have read your own rules is refused, in the listing's own words, and nothing starts. The
code already behaves this way; the design now says so.

## The key choices, and why

- A failed listing is never treated as "no layer set": you set a layer, so a start without your rules and no word
  saying so would be wrong.
- Each start refuses in its own way: a team start stops on the member it was composing and names it; a session
  started from the command line or the New session form is refused with the words; Add entry is refused, so no
  Add entry session starts; Start session on an entry lands on its form with the words as the reason.
- Only a start that would read your rules refuses: a role with no place for them, or a typed opening prompt, reads
  no layer. Where there is no agent-cadence at all to list your layers, a start still goes on, naming the lack (the
  New session form shows your own rules as none). Only a listing that ran and failed refuses.
- A failure is remembered for a minute, so one team start runs a failing listing only once per checkout.

## What it rules out

- A session started quietly without the rules you set.
- A team half-started past a failed listing.

## What you will see

The listing's error, word for word, in the refusal: the team start's message, the command's error line, the form's
reason, or the Add entry press's refusal. Mend the listing and press again; within a minute of the failure, the
press meets the same remembered words.
