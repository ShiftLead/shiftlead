# TD-2164: After the switch-over nothing takes a sync, lift or sweep pull request

## What it does

Today any grinder in a lane takes three kinds of pull request nobody holds: the cadence's sync and pin bumps, the
gate sweep's lifts of a waiting entry's gate, and its sweeps of the board. After the switch-over there are no
lanes. This design gives all three to the built-in seat that already takes red and filing pull requests nobody
holds, as jobs of their own, so none is left with no taker.

## The key choices, and why

- The job's session judges each one as a lane's taker does today, but never merges it and never asks a reader:
  the team's own review stages read it and the home merges it, as for any work under a flow.
- A session that closes its pull request unmerged (a lift whose gate is gone or whose event check says not yet,
  a sweep it cannot redo) ends its job with a word of its own, which the home checks against the forge.
- A sync's job is offered before the seat's other jobs, as a sync order comes first in the pick order today.
- A live check's lift that reads not yet becomes the fresh gate in the same pull request, since the session
  cannot merge a second one.
- A pin bump waiting on a review of the upstream changes is reviewed by the session, and the home's sync policy
  leaves alone any pull request a job is working, so two mergers never act on one.
- The job remembers what kind of pull request it was given, since the session's own push changes how it reads.

## What it rules out

- A forked sync pull request gets no job, since a session never takes a stranger's pull request; it is yours,
  drawn as the red pull request row in your Inbox.
- No job runs in a repo no team serves, and none while all of a repo's teams are stopped.

## What you will see

- A sync, lift or sweep pull request nobody holds is worked by the seat's job and merged by the team's flow.
- A live check's lift turned into a fresh gate still reads as an open lift on the old gate until it merges.
- Accepted costs: a lift check that errors once is a board line for you, where today a grinder retries it; a
  lift's check is not re-run at the merge; each of these pull requests now runs the flow's review stages, one
  job at a time per repo; and a sync waits while no team of its repo is started.
