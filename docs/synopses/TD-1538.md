# TD-1538: A board line that needs the person has no PR anchor: the design never says whether one ties by a PR

## What it does

A line on a repo's board can name a pull request instead of a ledger entry, as the board's own format line
allows ("PR #164"). Today the Queue cannot place such a line, so it stays in the Inbox. With this design, the
Queue finds the entry that pull request is about, by its title or branch, and draws the line on that entry's
card, just as it already does for a question that carries only a pull request.

## The key choices, and why

- The pull request's entry stands in for an entry the line would have named. Any such line goes to that
  entry's card while the card is open: one not yet due, one already decided, a watch or an fyi line.
- Only a line that still needs you goes further. If the entry is finished, it goes on that entry's kept
  card. If the entry is on no card, or the pull request names no entry, it goes on a loose card of its own.
  This matches how a question that carries only a pull request is placed.
- A line that names an entry keeps working as today. Any pull request it also names is just words.
- The pull request is read from the board's own repo. A pull request written with another repo's name in
  front of it is a mention, and that line stays in the Inbox.
- A line tied this way never counts as covering the entry's own row on the card. It never closes itself
  when the pull request merges: it leaves the card when you check it off or decide it.

## What it rules out

- No new field on a board line. The pull request is read from the line's context, where the format
  already puts it.
- No link to a design's pull request for such a line, since it names no entry.
- A line on a board the home cannot place in a repo stays in the Inbox.

## What you will see

A board line like "Context: PR #164" that needs you appears on the Queue card of the entry #164 is about,
instead of in the Inbox. The Queue and Inbox counts still add up to everything that waits on you.
