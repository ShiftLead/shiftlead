# TD-1976: The switch-over from profiles to logins has no procedure: the cut-over window's design

## What it does

It says how this home moves, in one sitting, from what runs today (profiles, team members, lanes) to the new shape
(logins, flows, teams as settings). There is no page for it. A session of your own runs three commands and asks you
what it needs: a check that changes nothing, the move, and an undo. It also says how every session is started on a
login once the move is done.

## The key choices, and why

- Commands and an interview, not a page. The move is made once per home, and a session can read a failure and decide
  with you where a page could only show an error.
- Your choices sit in one file you can read first: a name for each login, each team's new flow, its logins in order
  and its counts, and the models and logins for the built-in seats. The check suggests all of it.
- The move runs only with every team stopped and nothing standing in its way. It takes a backup, works through ten
  steps, and can be run again after a failure. Your own sessions stay up throughout.
- No sign-in is lost. Folders stay where they are, and each becomes one login.
- The repos are not part of the sitting. After it, a team block left in a repo's file is ignored, and each repo
  tidies its file later by an ordinary pull request.
- Work in flight keeps its pull request. An entry with an open pull request is handed to the new flow at its design
  or build stage with nobody holding it, so a fresh session picks it up and the new reviews read it again. A claim
  with no pull request is released.
- You can undo until you start the first team. An undo discards every setting, team and login changed since the
  move, and says so before it acts. After the first Start the way is forward.
- The old code is removed afterwards, once one entry has gone from filed to merged on the new shape. Until then both
  shapes are in the code, and only one ever runs.
- When a login reaches its reserve or a limit, its unattended sessions move to the next login in the list and carry
  on from a summary of their own transcript. A session you drive is never moved.
- What it costs: the fact-check seats on Gemini and Grok go, since the new flow has none; a separate entry asks how
  those two tools are then tested. Reviews under way at the move are done again. For a while the code carries both
  shapes. On a node, the node picks the login, and the home learns only what it reports.

## What it rules out

- A page of prepared moves, and six repo pull requests held and merged inside the sitting.
- Running old and new side by side for any team, and going back after a team has been started.
- Moving a session to another model when its logins run out. It waits.

## What you will see

Before the day: the check's print of the logins, teams and blockers, and a rehearsal on a copy. On the day: the
session winds the teams down, asks before it stops what is left, runs the move and shows its report. Afterwards every
team's page reads as switched and stopped; you press Start on one, watch an entry through, then start the rest.
