# TD-2129: Stop sessions leaving working copies outside their scratch directories

## What it does

Sessions have been leaving test runs, review copies and screenshots in the home cache folder, the shared temporary
folder on disk and a screenshots folder in the home directory, where nothing cleans them up. This design gives each
kind of working file one supported place, all but one inside the session's own scratch space, which is cleaned.

- Test runs, scratch homes and temporary files go in the scratch space, which now fits a socket's path.
- A review copy, and a copy a reviewer runs code in, go in the scratch's copies folder, which ages out.
- Screenshots and the scripts that take them go in the scratch's shots folder.
- The briefs and two out-of-date memories are corrected to say so.

## The key choices, and why

- The cure is the briefs and memories, not a new sweep, because the causes were a path limit that is now fixed,
  stale memories, and no place for a reviewer's copy. A look two weeks on checks that nothing new lands outside.
- A reviewer's copy is a plain clone with the reviewed commit marked as pushed, so the cleanup can age it.
- ShiftLead removes nothing it did not make by rule. What earlier sessions left is listed once, and you answer.
- The list keeps anything recent, in use, named by a brief or memory, or holding uncommitted work. A clone whose
  commits exist nowhere else needs your word. Old worktrees whose commits stay on their branches are proposed.

## What it rules out

- The installed screenshot library and the tools' own caches stay, and so does another repo's precheck cache.
- Unknown folders in the cache are only counted and are never removed.
- Because the repository is public, the committed list names only session-made entries, and a private repo's
  copy is shown by number and size alone.

## What you will see

- A decision on the board once the list is made: remove what it proposes, remove it with changes you name, or
  keep everything. A session then removes exactly that, and reports what went and what space it freed.
- The review rounds ended at their cap of four with one fix no review has read, about the list writing nothing
  as it reads. So the end-of-rounds question recommends one more round.
