# TD-1921: Sessions leave scratch data, worktrees and caches nothing cleans up, and they filled the machine's disk

## What it does

- Every session run gets one private scratch folder of its own, and its temporary files, a test's scratch home
  and the tool's own temp files land there unasked. The folder sits under the temporary-files area (in memory
  on this machine), so a reboot empties it.
- The host agent's hourly clean-up grows to four kinds: a finished session's scratch folder a day after it
  ended, worktrees older than a week that are fully landed and idle, the oldest finished run logs once they
  pass 2 GB in total, and the cached copies of agent-cadence older than two weeks that no repo pins.
- A new reading, printed by a new command, shows per host what each kind holds, what was freed in the last
  pass and in 30 days, what was kept and why, and how full the scratch area is in space and in file count,
  with a warning under a tenth free of either. A dry run lists what a pass would remove without removing it.
  A host that cannot answer shows as unreachable, and the others still answer.

## The key choices, and why

- **Transcripts are never removed**, by your rule: every tool names where it keeps them, the clean-up refuses
  any path inside, or holding, one of those places, never follows a link, and a test plants transcripts to
  prove it.
- Unpushed work is never lost: a worktree or a scratch folder holding a commit that exists only on this
  machine, unless that work has already landed on the default branch, or a changed or untracked file, is
  kept and reported, and nothing deletes a branch.
- Landed means what the cadence's reap script means: the branch's own files read the same on the default
  branch, or its squash merged there before later edits to the same files, or it has no work of its own.
- Worktrees and cached trees are swept only by your real home, never by a test's scratch home, which cannot
  see your sessions; a worktree a session is starting in at that moment is kept.
- A restart or a Resume keeps the session's scratch, since the same conversation reads what it wrote there;
  a fresh start gets a new folder.
- A live session's scratch, its git folders included, is marked as used each hour, without changing when its
  files were last written, so the system's own ten-day clean-up never takes it from a long-running seat.
- The worktree checks are rebuilt inside the host agent (the script deletes branches and weighs no single
  worktree), and a test holds both to the same verdicts.
- The clean-up runs beside the host agent's loop and never holds it up; slow worktree checks take at most a
  minute a pass and carry on next pass, and sizes read as partial after a restart until all are measured.

## What it rules out

- A repo's own precheck caches stay that repo's to prune, since only its script knows when they are in use.
- Your own sessions' temporary files and scratch left from before this build are not touched.
- No setting turns the transcript rule off.

## What you will see

- Each host's disk reading and its dry run, and the scratch location with four new keep settings on the
  Settings page's Hosts card.
- The leftovers measured at about 10 GB a month swept each hour instead of piling up.
