# TD-2104: Clear local branches and stale refs that have already landed

## What it does

The hourly disk sweep gains a rule that deletes local branches whose work has already landed, once a day, in every
registered repo. Separately, one job clears the main repository's old copied references and repacks it, if you say so.

Measured today, almost all of the space comes from the repack, not the branches. The 654 MB pack falls to about
122 MB on a test copy from repacking alone. Removing the landed branches frees about 6 MB more, and the old copied
references about 15 MB more. The real result will be somewhat larger than the copy's.

## The key choices, and why

- A branch counts as landed only if its commit is on the default branch, or is exactly the head of a pull request
  merged into the default branch. Having been pushed is not enough, since pushed work may never have merged.
- A branch is kept if a worktree holds it, if it moved within the worktree age setting (a week by default), if it
  still follows a live remote branch, or if its history holds a commit found nowhere else.
- If GitHub cannot be asked, only the first proof counts, so fewer branches go until it answers again.
- Each deletion is logged with its commit, so the branch can be put back while git still has that commit.
- A branch with no commits of its own that you keep as a bookmark is deleted once past that age and on the default
  branch. Nothing is lost but the name and its settings.
- The sweep never repacks. Git does that by itself, but its threshold has not been reached here, so the one-time job
  does it now.
- The one-time job deletes a copied reference only if origin still has its commit, and it skips any that moved in
  the last day, since a reviewer may be reading it.

## What it rules out

The sweep never touches a remote branch, a tag or anything outside local branches. The one-time job leaves the two
recovered references, the two stashes, the tags and all branches alone, whatever you answer.

## What you will see

Of the 406 local branches not in use, the first run deletes 190. About 180 more go over the following weeks as they
age out, and 37 stay because their work has not landed or they follow a live branch. The disk report lists the
branches deleted and kept, with why. You get two questions: whether to build the rule, and whether to run the job.
