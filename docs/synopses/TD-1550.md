# TD-1550: Integrate xAI's Grok Build CLI as an adapter, and run Grok as a fact-checker behind Gemini

## What it does

- Grok Build, xAI's open-source coding-agent command line, becomes a third tool ShiftLead can run, beside Claude
  Code and Gemini CLI: its sessions report working, idle and needs-you, take mail by the doorbell, and close like
  any other, on your SuperGrok sign-in. Its version is pinned, with its own updater off.
- Its first job is a second fact-checker on every doc-only PR, with its own trial comment and its own tally.
- Every fact about the tool was read from its user guide, never from a run, since it is not installed here; the
  build reads each again against the installed tool and corrects the design where they differ.

## The key choices, and why

- "Behind Gemini" is read as beside it: a seat of its own, asked on every doc-only PR as the Gemini seat is, not a
  backup asked only when Gemini cannot answer, which would give few lines and make each one mean Gemini failed.
  Two seats spend two of the hour's six seat starts on a PR, which is accepted.
- The seat is added only after the adapter's live walk and an unattended trial run have passed, so its lines
  measure the model, not the plumbing.
- It is fed by the tool's own hooks, which copy Claude Code's events. The tool cannot answer a permission from
  outside, so a Grok prompt is answered in its terminal, as Gemini's is.
- Each Grok profile has a home of its own, which ShiftLead writes its hook file into; your own Grok home is never
  touched. Two homes on one SuperGrok login count as one account.
- Every launch clears any xAI API key, so an expired sign-in never falls silently onto a bill; a profile billed by
  key waits for an entry of its own. Every launch also trusts the session's folder, so the repo's instructions
  and hooks load, writing nothing to the tool's trust list.
- The repo's start hooks run in the host agent before the Grok pane starts, and their output goes into the first
  prompt after the brief. Until that prompt is in, the session takes no message: a send is refused, a wrap-up
  stops it, and ShiftLead's own lines wait (your redesign, after five rounds on the old wait).
- Your Claude Code and Cursor hooks and MCP servers are off inside a Grok session; the kill and CI-watch guards
  apply as on the other tools.

## What it rules out

- The tool's headless mode, its own worktrees and its JSON-RPC mode: a session is the interactive terminal.
- Moving Grok's brief to where its prompt cache reads, until the walk has recorded how Grok caches; where Grok
  offers no usable way to watch what it sends, the walk says so and the brief stays typed.
- Rate-limit reports for now, so a Grok seat at its limit is not routed around: its asks expire.
- A role that needs a start context, which a Grok session cannot take.
- The adapter is not merged if the walk finds no steady composer row, hooks that do not see the session's
  environment, or a moved home that leaves the hooks and the sign-in behind.
- Until agent-cadence's TD-252 lands, the one-agent-per-directory check does not see a Grok session.

## What you will see

- One decision: install Grok Build (its script checks no checksum and edits your shell's startup file) and sign
  in two homes on SuperGrok, then Go; or one more round, since five fixes to how the brief waits for the start
  hooks are unread, and each review there has found a new race; or hold it with a note; or not now. Grok's
  builds also land after TD-1577's. xAI's terms page could not be read, so whether a subscription may be driven
  this way is yours to weigh.
