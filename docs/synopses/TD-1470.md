# TD-1470: No check asks whether open work has a live session able to act on it; a send to a down home is lost

## What it does

Each tick the home asks of every piece of open work whether any live session is able to act on it, and when none
has been for longer than that kind's wait, it tells you once, on the work's card, naming why. It also makes sure a
session whose send hit a down host agent learns the send did not land and is told again once the agent is back.

## The key choices, and why

- One alarm over every cause. It rings no session and presses nothing: the routing around, the idle nudge, the
  daily start cap and the held member (TD-1443, TD-1435, TD-1441, TD-1434) keep their own cures and become the
  reasons it reports. It runs in the home's own tick, so a stuck seat cannot stop it.
- Two kinds of work, as your Hold asked: a question to a session (60 minutes, twice the routing-around time) and a
  decided board line waiting on a session (60 minutes). Open PRs are not read here; TD-1572 brings them back
  once the claim model is simpler.
- A board line's actor is whoever holds its lease, as the lanes already read it; with no holder, the lanes that
  take it. A holder idle on its close PR's review reads stuck after the wait, like any idle holder.
- A session counts as able when it is working, or idle with a subagent or shell running, and not stalled; an empty
  seat that can be filled counts too. Any other state is the reason: limited, interactive, parked, gated, gone,
  a team's hold, or no lane takes it.
- The clock runs one wait from the last moment anything moved (a claim, a release, an answer), never two, never
  moves back, and is kept on disk, so a restart keeps the row and time the home was down counts.
- When every reason names its own end within the wait, the work shows as waiting, not as a need.
- A send to a down host agent exits with words that say it did not land, and leaves a mark naming only the
  command. The next tick back notes the session; with no session left to run it, you get the note.

## What it rules out

- Work held only by your own live sessions is never stuck: you are already there.
- A board line you are already asked about is not read while that question stands: any open question or steer
  to you about the line's entry, from that repo, whoever sent it. A question you snoozed out of sight does not
  count, so the line can still reach you.
- Steers to a session, questions to you, and a question a seat passed up are not read as stuck questions.
- When ao itself is missing, nothing can know who ran it; the briefs say to run such a command again.

## What you will see

The work's card reads needs you, with a Do item such as: stuck 1h: the One more round on TD-1437 — ao-grind is
held by its daily start cap: 3 idle starts today. Work naming no entry goes to the Inbox under Needs you. A
decided line already shown moves rather than doubling. Open goes to that session's Focus; the cure stays where
it is drawn now.
