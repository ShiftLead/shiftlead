# TD-1470: No check asks whether open work has a live session able to act on it; a send to a down home is lost

## What it does

Each tick the home asks of every piece of open work whether any live session is able to act on it, and when none
has been for longer than that kind's wait, it tells you once, on the work's card, naming why. It also makes sure a
session whose send hit a down host agent learns the send did not land and is told again once the agent is back.

## The key choices, and why

- One alarm over every cause. It rings no session and presses nothing: the routing around, the idle nudge, the
  daily start cap and the held member (TD-1443, TD-1435, TD-1441, TD-1434) keep their own cures and become the
  reasons it reports, so a cause nobody has named yet still reaches you.
- It runs in the home's own tick, which no seat runs, so a stuck seat cannot stop it. A home that is down runs
  nothing; the page's agent-down banner and the missed sends cover that.
- Three kinds of work, each with its wait: a question to a session (60 minutes, twice the routing-around time,
  so routing has tried first), a decided board line waiting on a team's lanes (60 minutes), and an open PR a
  session's claim names, green or not (2 hours, past a precheck and its merge).
- A session counts as able when it is working, or idle with a subagent or shell running, and not stalled two
  ticks; an empty seat that can be filled counts too. Any other state is the reason: limited, interactive,
  parked at its fill ceiling, gated, gone and the rest; a team's hold (its daily start cap, its usage gate, not
  running); a PR whose claim was dropped reads released by its last holder, and one its last holder finished
  is no longer read. A session holding several claims is a holder of every PR they name.
- The clock runs one wait from the last moment anything moved, never two, never moves back, and is kept on
  disk, so a restart keeps the row and time the home was down counts. A repo it could not read that tick keeps
  its work as stored.
- When every reason names its own end within the wait (a usage reset, a scheduled start), the work shows as
  waiting, not as a need: nothing is yours to do yet.
- A send to a down host agent exits with words that say it did not land and to run it again when rung, and
  leaves a mark naming only the command, never what it said. The next tick back notes the session; with no
  session left to run it, you get the note.

## What it rules out

- Work held only by your own live sessions is never stuck: you are already there.
- Steers, questions to you, and a question a seat passed up are not read; a holder whose PR claim waits on
  your answer is not counted, the PR read through its other holders or, with none, left until you answer; one
  waiting on a reader's question is read as that question. A PR no claim named stays on the Repo page alone.
- When ao itself is missing (command not found), nothing can know who ran it. A note to every session after
  every install was weighed and not taken, since it would ring them all on each promote; the briefs say such a
  command did not land, the idle nudge rings a member with open work, and a session with nothing open may lose it.

## What you will see

The work's card reads needs you, with a Do item such as: stuck 1h: the One more round on TD-1437 — ao-grind is
held by its daily start cap: 3 idle starts today. Work naming no entry goes to the Inbox under Needs you. A
decided line already shown moves rather than doubling, and one parked seat behind several works reads once.
Open goes to that session's Focus; the cure (Restart, Hand back, a team's Start) stays where it is drawn now.
