## Should a session delete the old copied references in the main repository and repack it, freeing about 530 megabytes?

**Kind:** decide
**Added:** 2026-11-23
**Context:** TD-2113 decision (paul)
**Due:** 2026-11-30
**Answers:** Yes, and repack (default) — a session deletes the copied references, repacks and records the size | Repack only — a session repacks and deletes nothing | Neither — a session records the size and drops this

- **Context:** The main repository's history takes 654 MB on disk, and almost all of that is duplicate copies git has not merged yet. On a test copy, repacking alone brought it to about 122 MB; the real result will be somewhat larger.
  - The old copied references are 2,699 from September and October that nothing uses, plus about 13 other leftovers. Removing them frees about 15 MB more.
  - Each is deleted only if origin still has its commit and it has not moved in the last day. Two recovered references, two stashes, the tags and all branches are kept whatever you answer.
- **Question:** Should a session delete the old copied references in the main repository and repack it?
- **Caveats:** A repack is safe while sessions work and loses nothing. A deleted reference cannot be listed again, though origin keeps its commit.
- **Recommended:** Yes, and repack — it frees most of the space and loses nothing. **Otherwise:** Repack only, if you would rather keep the old references; Neither, if you would rather leave the repository as it is.
