No ledger entry holds this.** Observed live on `ao-agentorc-tdgrind-ao-1` at 14:58Z: state `stalled?` (confidence `scraped`), `ao explain` giving no rule and no evidence, `last_hook` 14:28:28Z — while the pane showed a **completed** `/compact` ("Compacted (ctrl+o to see full summary)", five files listed below it) above an **empty composer**. That session is `idle` in substance: every lane item done or dropped, tree clean, nothing running. **The mechanism, from the code:** `translate()` (`src/agentorc/adapters/claude_code/hook.py:43-87`) passes `SessionStart` straight into `STATE_EVENTS` → `working` (`hook.py:24-28`) with **no look at the payload's `source`** — and Claude Code's documented compaction sequence ends by firing `SessionStart` again with `source: "compact"` (`PreCompact` → `PostCompact` → `SessionStart(compact)`; the hooks guide's own "re-inject context after compaction" recipe matches on exactly that). Neither `PreCompact` nor `PostCompact` is in `HOOK_EVENTS` (`adapters/claude_code/__init__.py:30-42`), so nothing ever reports the compaction finishing; the record sits `working` until the liveness cross-check at `agent.py:556-559` flips it to `stalled?` at `STALL_AFTER`. I did not capture the 14:28:28Z payload, so *which* event set `working` is inference — but it is the only registered event the documented sequence fires, and `/compact` is a built-in that most likely never reaches `UserPromptSubmit` at all. **The shape of the bug is already solved next door in the same function:** `SessionEnd` is checked against `SESSION_END_STILL_RUNNING` (`{"clear", "resume"}`, `hook.py:31`) precisely because some lifecycle events are not what they appear — `SessionStart`'s `source` wants the same treatment, or `PostCompact` wants registering as the explicit "compaction over" signal, or both. **Why it is worth your time rather than a curiosity:** auto-compaction is routine for exactly the long-running unattended workers this system exists to watch, so every one of them will eventually read `stalled?` while perfectly healthy. Today that only misleads a human reading the Herd and an orchestrator following its brief (I did not nudge — the tail shows output and the session holds no open reference, so the prescribed nudge had nothing to say). But §6's stall policy is **"`working` with no output past `stall_after` → flag `stalled?`, nudge once, then wrap up"**, and when that becomes agent code it will nudge and then wrap up a session whose only sin was compacting its context. **Sharpened 15:32Z, and it is worse than first written: the mislabel does not clear itself.** At 15:32Z the record still read `stalled?` with `last_hook` unmoved at 14:28:28Z, even though `last_output` had advanced to 15:26:06Z on an otherwise unchanged screen. The reason is that the liveness check is a one-way door: `agent.py:559` is the only assignment of `stalled?` anywhere, and its branch is guarded on `s.state == "working"`, so once the record leaves `working` that branch is structurally unreachable and no amount of fresh `last_output` can bring it back. Two paths *can* clear the state, and neither fires here: any hook carrying a mapped state reaches `_apply_event` (`agent.py:574-594`), whose `set_state` is unconditional — `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `Stop`, `SessionEnd` and `Notification` would all clear it — and the screen fallback (`_screen_verdict`, `agent.py:552-555,566-571`) would clear it if a rule matched, since it is not guarded on the current state. But a session resting at an empty composer emits no hook at all, and `ao explain` answers `match: null, reason: "no screen rule matched"` because no rule covers an idle composer. So the mislabel is not transient: nothing the system does on its own corrects it, and in practice it clears only when somebody submits a prompt — a submitted prompt being the only one of those events an idle session is likely to produce. That is precisely the window a supervisor acts in, which is what turns a cosmetic wrong badge into a policy that would nudge and then wrap up a healthy worker.
