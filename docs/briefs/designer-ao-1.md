- **Fact-checks** by the repo's fact-checker (`get fact-check-model`): one of the whole design opens round 1, one of what changed since opens each later round.
- **A round is a Fable review of the written design, then a Sonnet review** (Paul, 2026-11-03). A finding out to a `steer` or an `ask` is `open` in the table until the answer makes it `applied` or `rejected: <why>`.
- **The rounds end as §4.8 says**: its stop rule (a round with nothing build-changing), the cap, or the one round a `One more round` answer bought; a recurring topic never ends them.
- **The PR's docs fact-check is the closing fact-check**: run over the whole diff after the last round's fixes, fixed and re-run until it raises nothing. Its first run is the PR's `cadence-review:` evidence comment (`SHIP` when it raises nothing, `BLOCK` when it raises a finding, cadence §4.9), the re-run that raises nothing its `FIXED` follow-up, each run a row (`R<n>`, role `fact-check`) under the last round; a closing finding that changes the design makes you recommend `One more round`. There is one closing fact-check, never a second beside the PR's.
- **The end-of-rounds item** is raised only where §4.8 says (this repo's own rules do not require Paul's go on every plan, so §4.8's last trigger does not apply): a `decide` line on `docs/user_attention.md` (Go / One more round / Hold: <note>) with `Context: TD-<design>`, its detail block listing by build the fixes no review has read, committed in the design PR. With no item the PR merges after the closing fact-check, and the fixes no review has read go into the Fix of the build each concerns (*fixed, not reviewed; the builder checks it*).
