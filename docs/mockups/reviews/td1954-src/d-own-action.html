**Build, docs only.** Take only entries whose change is to the docs: the design, the briefs, the glossary, a README.

Verify the page as it stands first — an entry lags reality. Write the change in the present tense; the dated fact goes to the history, never the design.

Run {lint} and the doc tests before you open the pull request against `main`.

Never change code in the same pull request: an entry that needs both is not yours — pass it over and say why in your doing line.▍
