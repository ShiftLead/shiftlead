### 4.3 Adapter contract

One package per tool under `shiftlead/adapters/<tool>/`. Core never imports tool-specific
names outside the adapter. The `shell` adapter is the degenerate case and ships in phase 1
(it is how repo-less hosts get cards at all).

```python
class Adapter(Protocol):
    name: str                         # "claude-code"
    label: str                        # "Claude" — the tool's display name, for the usage chip and nowhere it is keyed on (TD-122)
    def launch_cmd(self, *, profile: Profile, resume: str | None, prompt_file: Path | None, unattended: bool) -> list[str]
    def launch(...) -> LaunchSpec                     # argv + env + adapter_id; names the hooks layer (Claude Code writes one per profile; Gemini's is the machine's).
                                                      # `start_context: str | None`: text the session holds from its start that is no
                                                      # prompt — no turn runs for it and nothing is typed. Claude Code:
                                                      # `--append-system-prompt-file <path>` (§4.1 *No prose in the argv*;
                                                      # the flag is in the binary of 2.1.290, though `--help` gives it no
                                                      # entry of its own), given
                                                      # again at every launch of the conversation, a resume included,
                                                      # since the tool keeps it in no file of the session's. The `prompt`
                                                      # is not argv's either: `LaunchSpec.first_prompt`, which the host
                                                      # agent types at the composer (§4.1). An adapter that can carry one says so
                                                      # (`start_context = True`); a create that hands one to an adapter
                                                      # that cannot (`shell`) is refused in words, never folded into a
                                                      # prompt. The record keeps the text (`start_context`) and so does
                                                      # the launch record, so a restart, a Resume and a profile switch
                                                      # launch with it, and a resume that names none carries the
                                                      # conversation's own; a page shows it as text and nothing else
                                                      # (§4.5a **Told at start**)
    def state_source(self) -> Literal["hook", "scraped"]
    permission_channel: bool             # whether a pending permission is answered through the hook channel
                                         # (Allow / Deny, §4.5a): True where unset, as `agent` is; Claude Code
                                         # True, Gemini CLI False (TD-112); `shell` has no permissions
    asking_args: list[str]               # the launch arguments that make the tool ask every permission whatever
                                         # the person's default mode, added under `permission_prompts: all`
                                         # (§4.2a, TD-823): Claude Code `["--permission-mode", "manual"]`;
                                         # where an adapter declares none, nothing is added
    def classify_pane(self, tail: str) -> State | None   # only for scraped adapters; a hook-fed adapter's screen
                                                          # rules are its `explain`, given the pane's title too (TD-112)
    state_in_title: bool                 # the tool writes its state into its terminal title: the tick asks `explain`
                                         # with the title and writes its verdict as `confidence: title` (§4.2);
                                         # False where unset, Gemini CLI True (TD-785)
    def transcript_path(self, session_id: str, cwd: Path, profile: str | None = None) -> Path | None
                                                          # `profile` names the tool's home where the adapter keys
                                                          # its files on it (Gemini CLI, TD-112)
    def context(self, session_id: str, cwd: Path, profile: str) -> dict | None
                                                          # the session's context size now — {tokens, at, window}, keyed by the
                                                          # profile *name* as `model_in_use` is — from the
                                                          # tool's own records: Claude Code, the last top-level `assistant` entry's
                                                          # `usage` (input + cache_read + cache_creation), the tail read `model_in_use`
                                                          # makes, `window` the one the session's status line last reported
                                                          # (`context_window.context_window_size`, kept by `shiftlead-hook
                                                          # --statusline` per tool session, whose `current_usage` tokens win
                                                          # when later than the turn), else the model's from a table; None when
                                                          # it cannot tell (§6 rule 5). Read on the tick for unattended
                                                          # records once a minute, never a grep
    def background(self, pid: int, proc: ProcReader) -> list[dict] | None
                                                          # the tool's live background tasks under the pane's process `pid` —
                                                          # [{pid, start, cmd}], `start` /proc's start time and `cmd` what the task
                                                          # runs — read through the host agent's `ProcReader` (§4.8a), which gains
                                                          # `children` and `cmdline`. Claude Code: from `pid` to the first process whose
                                                          # `comm` is `claude` (the pane's own, or a descendant under a hand-started
                                                          # shell; bounded), then its direct children that are its command wrapper
                                                          # (`bash -c source …/shell-snapshots/…`), `cmd` the wrapper's first child's
                                                          # argv. Read only while the record is idle with no live subagent (§4.2
                                                          # *Working on its own*, TD-761); None when it finds no `claude`. An adapter
                                                          # without the method (`shell`) is never read, as `context` is found

              cursor: int = 0) -> tuple[list[Link], int] | None

                                                          # assistant's text and tool results — `Link(url, at)` — and the new
                                                          # cursor, for the record's `links` (§4.2, TD-543); None when there is
                                                          # no file. An adapter without a transcript lacks it, and the
                                                          # conformance suite (TD-112) names it among the reads one declares.
    def prompts(self, session_id: str, cwd: Path, profile: str, *,
                cursor: int = 0) -> tuple[list[Prompt], str | None, int] | None
                                                          # the prompts the transcript holds past byte `cursor` at the top level
                                                          # — `Prompt(at, text, drawn, whole, reply)` — leaving out the lines no person
                                                          # typed (Claude Code: its meta lines, a local command's output, the
                                                          # compaction summary, the interrupt lines, a reminder- or
                                                          # notice-only entry), a slash command drawn as the line typed
                                                          # (`/x args`); the first text line past `cursor` before any
                                                          # prompt (the reply to the record's newest); and the new cursor, for the
                                                          # record's `prompts` (§4.2, TD-975). `drawn` opens the pane row the tool

                                                          # line's first forty characters, in the form the captured pane shows,
                                                          # trailing spaces trimmed), or None; `whole` when
                                                          # `drawn` holds the first line uncut, so the walk needs
                                                          # equality, not a prefix. None
                                                          # when there is no file. An
                                                          # adapter without a transcript lacks it, as `links`.
    def read_transcript(self, session_id: str, cwd: Path, profile: str, *,
                        before: int | None = None, turns: int = 20, raw: bool = False) -> Transcript | None
                                                          # the tool's transcript as neutral entries — a prompt, text, a thought, a
                                                          # tool call with its result, a compaction, a sidechain group — the last
                                                          # `turns` before byte `before` (None: the file's end), with the offset that
                                                          # asks for earlier ones; with `raw`, the file's last `turns` lines as text.
                                                          # Keyed by the profile *name*, as `context` is; None when there is no file
                                                          # or the profile is unknown. No field name of the tool's leaves this
                                                          # method, as none of `usage` does (§4.5 screen 9)
    def quirks(self) -> Quirks                      # first-run dialogs, settings pre-seed
    def usage(self, profile: Profile) -> Usage | None     # this account's quota windows: Usage(windows=[Window(label, pct,
                                                          # resets), ...], fetched). The labels are the adapter's; nothing
                                                          # above reads them — one window, three or none are all legal, and
                                                          # no tool's field name leaves this file. A tool with no
                                                          # quota endpoint reports None: no chip. Called once per account
                                                          # (§4.2a): the profile names the credentials, the reading
                                                          # is the account's. Every window the endpoint reports is carried,
                                                          # a per-model one labelled by the adapter with the model
                                                          # (`week · Fable`), so the chip's worst-window rule sees it
    def usage_for(self, profile: str) -> dict | None      # the same by profile name, for the core (it cannot build a Profile)
    def usage_report(payload: dict) -> dict | None       # optional: the windows a session of the
                                                          # tool was told, read from what its hook command was handed —
                                                          # {windows: [{label, pct, resets}], work, sid}: the labels `usage` gives
                                                          # the same windows, pct to one decimal, resets an instant, `work`
                                                          # the session's running total of API work and `sid` whose, from which
                                                          # the command sets the RPC's `fresh`: whether the session had a
                                                          # response since its last report; None when the payload carries none.
                                                          # Claude Code: the status line's `rate_limits` (`5h`, `week`) and
                                                          # `cost.total_api_duration_ms`; a per-model window is not in it and
                                                          # is read only when the endpoint is asked (§4.4 *Usage*)
    def account_for(self, profile: str) -> str | None     # optional: the account a profile runs under, which the core keys
                                                          # the usage poll, its cache and its back-off on (§4.2a);
                                                          # an adapter without it, or None, keys on the profile itself
    def doctor_profiles(self) -> list[dict]               # optional: each profile it runs as `ao doctor` reads it (§4.7,
                                                          # TD-465) — config dir, credentials, a metered profile's key, its
                                                          # settings layers and whether each command resolves; the core
                                                          # cannot read a profile
    def setup_note(self) -> dict | None                   # optional: what the machine needs a person for before its
                                                          # sessions can run, read at the host agent's start, when
                                                          # `profiles.yml` changes and hourly — {key, text}, noted once per key;
                                                          # {key: None} all is as wanted (Gemini's layer, TD-875)
    def machine_layers(self, hook: str) -> list[tuple[str, str]]  # optional: (where, bytes) of each root-owned file a
                                                          # container node's root stage installs, naming `hook` (TD-875)
    def composer(self, tail_raw: list[str]) -> str | None  # optional: the text painted in the tool's input line ("" empty,
                                                           # None when no composer is on screen); lets `send` confirm a submit (TD-027)
    def title(self, pane_title: str) -> str | None   # optional: the session's name as the tool holds it, from the terminal
                                                     # title it set (tmux `#{pane_title}`), the tool's own decoration removed;
                                                     # None when it is not a name (the tool's default, a hostname).
                                                     # Display only (§4.5a)
    def credentials_ok(self, profile: Profile) -> bool | None
    def mail(self) -> MailDelivery | None   # optional: how a session of this tool is handed inbox entries and woken by
                                            # them — a command it runs, an injection at the top of a turn, a tool call,
                                            # or a hook. None means no native path: the core falls back to a pane write,
                                            # which is a `send`, and §4.10's message/control line is then a convention
                                            # this adapter's brief keeps rather than a gate the host agent enforces (§4.10)
```

Prompt injection is **core**, not adapter: `copy-mode -q` first, before anything is typed (a pane a person scrolled back is in copy
mode, where the Enter would be the mode's — §4.6 *Typing returns the pane to the live screen*,
TD-667; nothing when it is in no mode), then `tmux load-buffer` + `paste-buffer -p` (bracketed
paste, so a multi-line brief lands as one prompt), then `Enter` — no blind `C-u`, since the pane may
not hold a readline line. When the adapter implements `composer`, the Enter waits for the paste to
paint and is confirmed by the composer emptying, with one `C-m` retry (§4.2, TD-027); adapters
without it get the blind paste + Enter. **Send is disabled** while a permission or question is
pending (the pane owns a dialog) and, for scraped adapters, while a foreground process runs;
otherwise it is enabled — Claude Code queues input typed while it works.

**Mail is not prompt injection** (§4.10): prompt injection supplies a turn, mail is handed *to* a
turn the session runs itself. So `mail` is the adapter's and the paste is core's: the mailbox is
tool-neutral data on a record, but how a session comes to read an entry is as tool-specific as
its hooks (not every tool has a shell to run `ao inbox` in).

**A record with no agent** (TD-665; Paul, 2026-10-13, on a shell opened by **Open shell here**:
*make sure everything there is specifically for a shell/command instead of an agent*). An adapter
says whether what is typed at it is a prompt an agent runs a turn on — **`agent`**, an optional
attribute looked up as `start_context` is, `True` where unset; `shell` and `command` set it `False`.
The record's view carries it (`agent`, derived from the record's adapter by the host agent that
serves the view, a node's own records included, never stored), and **every reader keys on it, never on an adapter's name**. On a record whose
adapter says `agent: False`:
- **The host agent types nothing of its own into it.** Text a person sends is the one way in
  (Send, `ao send` by a person or a controller). The wrap-up is refused: the `send` RPC with
  `wrapup` says *a shell runs no turns: there is nothing to wrap up — Close it*. A stop time
  (§6 *Stop time*) and `ao team stop` kill at once, with no wrap-up and no ten-minute wait. There
  is no pause or resume prompt (§6 *Usage gate*), no idle nudge, no doorbell (§4.10), no fill and
  no restart prompt. English typed into bash runs as a command line, and any `$(`, backtick or `;`
  in it would run something.
- **Mail to it is refused**: `msg` naming it as an addressee says *nothing reads `<name>`'s inbox —
  it runs no agent*. Mail sent from it is unchanged; a shell the person opened runs as the person
  (§4.8 *The person's own shell is the person*).
- **No claim is derived for it** (§4.4 *Repo facts*, `reports.derive`). A shell opened in a
  worker's worktree shares the worker's branch, and that branch's claim is the worker's.
- **Its mode stays interactive**: `set_mode` to `unattended` is refused, since a shell is the
  person's (§4.8).
- **What the pages draw** for it is §4.5a *A record with no agent*. A session adopted from a
  hand-started tmux session is a `shell` record whatever runs in it: an agent the person starts by
  hand inside a shell is the person's own process, out of shiftlead's reach.

A **turn** is one cycle of work (§3, [ADR](../decisions/2026-09-13-openai-agents-api.md)): a session
is durable, a turn is one piece of work. Send does two things, in one sentence: **to an `idle` session it starts a turn; to a `working` one it steers the turn in flight** where the tool reads a message mid-turn (Claude Code; Gemini CLI queues it for the next turn, *The second adapter* below) — the same paste and Enter, one control. Menus and questions
are answered *in* the terminal (keys pass through); permissions go through the hook decision
channel (§4.2) where the adapter has one (`permission_channel`), else in the terminal too. The core never types a menu choice into a pane.

**A kill the guard refuses (TD-489).** The rule is §4.8's — a session signals only a pid it started
and holds — and the adapter's `PreToolUse` hook for `Bash` is a net under it: it answers `deny`, with a
reason the session reads as it reads any refused tool call, to a command whose shape reaches what
nobody looked at — `pkill` or `killall` as a command word; `kill` of `-1`, of `1` or of `$PPID`; `kill`
of a substitution that runs `ps` or `pgrep` (`kill $(ps …)`, backticks alike); and a command that both
reads a parent pid (`ppid`, `PPID`) and runs `kill`. A literal pid, a variable, a job (`%1`) and a
pidfile (`kill $(cat x.pid)`) pass: they are what the rule allows, and the guard cannot tell a held pid
from a found one. The reason: *shiftlead: refused — a kill by pattern, of a parent or of everything;
signal only a pid you started and hold (design §4.8)*. The decision is the hook's own, in the
session, with no call to the host agent (a hook that cannot reach it still refuses); the event still
reports `working` as any `PreToolUse` does. The guard is wiring, so it is the adapter's (§4.3) — a
tool without a pre-tool hook, the `shell` adapter among them, has the rule in words alone.

**A wait the guard refuses (TD-991).** The rule is §4.10's — a session never waits inside its own
turn — and words did not hold it for a CI watch: on briefs that name `timeout 1800 gh pr checks <n>
--watch` as the background command, members ran that very command in the foreground. (The held path's
stage sentence, `grinder.stage.md`, names `gh pr checks <n> --watch` without *in the background*; TD-992
adds the words.) The adapter's
`PreToolUse` hook for `Bash` is a net under it too, on two things together:

- **The command is a CI watch**, read from its text by `shiftlead/wait_guard.py`, as the kill guard
  reads it: the text masked (quoted text, here-document bodies and comments blanked, `kill_guard.mask`),
  each command's word found past the same wrappers (`timeout`, `nohup`, `env`, …), and the command is
  `gh pr checks` with `--watch` (or `--watch=…`), or `gh run watch`, past any `gh` option before the
  subcommand (`-R <repo>`, `--repo <repo>`). A single `gh pr checks <n>`, a short `sleep` before
  one, and a loop are not refused: the first two are one bounded poll, and the tool already refuses a
  long bare `sleep` itself.
- **It runs in the foreground, on the main thread, of an unattended record.** The call's
  `run_in_background` is not true — a shell `&` (`nohup … &`) is not the background form, since a
  shell job's end fires nothing and so wakes nobody, and the reason names the one that does; the event
  carries no `agent_id` (a subagent's tool event sets no state and opens no main-thread call, §4.2, so
  a refusal there would answer a thread the record does not model — a subagent's wait is its caller's
  to put in the background); and the host agent says the record is `unattended`. The hook cannot know that last one
  itself, since a session's mode flips on Take over and Hand back while its environment stays as it
  started; so it sends the event with `wait: true`, as a Gemini CLI turn's event carries `mail: true`,
  and the host agent's reply carries `refuse_wait: true` when the record it holds is `unattended` — on
  a node, the node's replica, which holds the field and which `set_mode` reaches in the same call
  (§4.4a), read as the permission rules already read it there — the field alone, with no link to the
  home needed, since the refusal files nothing. An interactive session, the person's or
  one taken over, is never refused: the person decides how their own session waits.

Both true, the hook answers `deny` with *shiftlead: refused — a foreground CI watch in an unattended
session; run the same command in the background (`run_in_background`) and end the turn: its end
wakes you (design §4.10)*. The reply is the event's own, with no second call; one that does not come
(the host agent down, or past the hook's 3-second wait for an event's reply (`SHIFTLEAD_EVENT_WAIT`),
so the event is queued, and the queued copy carries no `wait`, as Gemini CLI's carries no `mail`) lets the call run, since this
is a wait and not a kill. The hook prints at most one decision: a command the kill guard refuses is
denied for that, before anything is sent, and the wait is not asked; a wait's deny is printed and
flushed as the reply lands, before the hook exits. The guard is wiring, so it is the adapter's: the
`shell` adapter has §4.10's words alone, and so does Gemini CLI, whose `run_shell_command` has its own
background form (`is_background`), until a follow-on wires it (its kill guard is wired, TD-785).

**The second adapter: Gemini CLI** (TD-112; Paul chose the tool on 2026-10-13 and the designer to design
it on 2026-10-16). Every fact below was read from Gemini CLI 0.64.0's installed package and `--help` on
kmaster, never from a run; the build pins the version it was read against (`general.enableAutoUpdate:
false` in the layer) and the conformance suite (below) is what says a later one still fits. **It is
hook-fed**, not scraped: what the tool lacks is narrower than the phase plan feared, and named here
method by method, so neutrality is a list rather than a hope.

- **The profile's home is its `config_dir`** (§4.2a, `adapter: gemini`): every launch sets
  **`GEMINI_CLI_HOME`** to it — the tool's whole `.gemini/` moves under it (settings, credentials,
  chats, the trust file), as `CLAUDE_CONFIG_DIR` moves Claude Code's — and a profile naming none
  uses the tool's own (`~`, so `~/.gemini`), as Claude Code's defaults to `~/.claude`. With it,
  `GEMINI_FORCE_FILE_STORAGE=true`, so two profiles never share an OS keychain entry. Signing a home
  in is the person's act, in a terminal, as for Claude Code. A metered profile's key is
  `GEMINI_API_KEY` in the launch environment, which the tool prefers to a stored one. The launch
  also clears `GOOGLE_API_KEY` as a precaution: the tool reads it only under Vertex auth, or as the
  SDK's fallback where no Gemini key is passed, and a profile's billing should not hang on which.
  `doctor_profiles` notes one found in the host agent's environment. `credentials_ok` reads that the
  home's `settings.json` names `security.auth.selectedType` and that its credential exists:
  `<home>/.gemini/gemini-credentials.json` (the file store, which `GEMINI_FORCE_FILE_STORAGE` forces;
  `oauth_creds.json` its older name), or `GEMINI_API_KEY` in the profile's environment.
- **`launch`.** The binary by absolute path (it is on `PATH` only in a login shell). The session id
  is ShiftLead's, chosen at launch: **`--session-id <uuid>`**, refused by the tool for an id that
  exists; a resume is `--resume <uuid>` (the two are exclusive), launched from the same directory,
  since the tool finds a session by its project. `permission_prompts: skip` (§4.2a)
  adds `--approval-mode yolo`. The model is `--model`. The env carries `SHIFTLEAD_SESSION`,
  `CADENCE_ATTENTION_SCOPE`, `CLI_TITLE` (the session's name, which the tool puts in its title) and
  **`GEMINI_CLI_SYSTEM_SETTINGS_PATH`**, naming **the machine's layer**, `/etc/shiftlead/gemini-settings.json`:
  the tool's highest-precedence file, whose `hooks` **concatenate** with the person's rather than
  replace them — the shape of Claude Code's per-launch layer (§4.2), with one difference the tool
  forces. It reads a system settings file only when **root owns the file and every directory above it
  to `/`, symlinks on the way included, and none is writable by group or others** (0.64.0's
  `isFileAndDirectorySecureSync`); any other it
  skips with a *Security Warning* and runs with no layer, so no hook ever reaches the record (TD-871,
  read live 2026-10-17). So the layer is **installed by the person, once per machine, with `sudo` —
  never by ShiftLead** (Paul, 2026-10-17). Its content varies by nothing per launch or profile — the
  hook command by absolute path, which a promote keeps, and the settings below — so it is one file:
  ShiftLead writes **the wanted copy**, `~/.shiftlead/gemini-settings/layer.json`, and `ao doctor`'s
  **hooks** line (§4.7) compares the installed file with it and prints the one line that installs it:
  `sudo install -d -o root -g root -m 0755 /etc/shiftlead && sudo install -o root -g root -m 0644
  ~/.shiftlead/gemini-settings/layer.json /etc/shiftlead/gemini-settings.json` (the directory made
  0755 in so many words, since a `sudo` umask of 0077 would leave it unreadable and the tool would skip
  the file). **A launch reads the installed file first**: missing, not
  secure by the tool's own test (the same walk up every directory), or naming no hook command that resolves, and the launch is
  **refused in words** naming `ao doctor`, since a session with no hooks never leaves its launch
  state; differing from the wanted copy otherwise (a build that changed the settings), it launches,
  and `ao doctor` reads *stale* with the same line. Only a launch that names the variable reads the
  file, so the person's own `gemini` runs are untouched. **The person meets the step at setup, not
  at a refused launch** (gemini-support's review of #2094): README's install steps carry it for a
  machine with a Gemini profile, and the host agent, on its start (which a promote is) and whenever
  `profiles.yml` gains a Gemini profile, and hourly, since the layer lives outside the home, so an
  undone install is noted again without a restart, reads the installed layer against the wanted copy and,
  where it is missing, insecure or stale, sends the person **one system note** with the line — once
  per wanted copy and reading, so the same bytes in the same state note once, and a layer
  installed and later gone notes again — since nothing unattended can run `sudo`. **The
  file is kept stable**, so a reinstall is rare: it names the hook by the live venv's absolute path
  (`bin/shiftlead-hook` beside the host agent's own interpreter, never a `PATH` lookup), which a
  promote keeps, and holds nothing that varies — what differs per launch is read inside
  the hook, from the launch's environment. Only a change to the hook events, the settings below or
  the hook's path makes it stale, and the build that makes one says so in its PR. **A container
  node needs no `sudo`**: its generated Dockerfile already has a `USER root` stage (tmux's, §4.4a
  *A container node*), where it installs the node's own wanted copy — the hook at
  `/shiftlead/venv/bin/shiftlead-hook` — root-owned, the directory 0755 and the file 0644, so the
  node's `ao doctor` reads *ok*; a stale one there is cured by the node's rebuild. A plain node is a
  machine like the home: its own `ao doctor` and its own note. **A host without root runs no Gemini
  session**: a profile home set aside for ShiftLead, its user settings written by ShiftLead, is still a
  home the person signs in with, and a second road would double the adapter's paths; it is written
  here as ruled out, not forgotten. The root layer is the workaround while the tool takes no
  user-owned per-launch layer; asking upstream for one is the person's to do.
  The layer holds the hooks, `hooksConfig.notifications:
  false`, `ui.hideTips`, `ui.hideBanner`, the pinned update setting, and the title settings the state
  check reads — `ui.dynamicWindowTitle: true`, `ui.hideWindowTitle: false`, `ui.showStatusInTitle: false` — so a person's own
  settings cannot turn the check off.
- **`quirks`: trust before anything.** With folder trust on (`security.folderTrust.enabled`, on in
  0.64.0's settings schema, though its bundled doc still says off), the tool runs **no hook at all**

  `permission_prompts: skip` would start asking permissions nobody answers.

- **`state_source`: `hook`, with the title as the check.** The layer's hooks call
  **`shiftlead-hook --adapter gemini`** — the flag read from argv before any import, as
  `--statusline` is (§4.1 *The hook keeps its traceback*), since a Gemini payload names no adapter,
  shares event names with Claude Code's and even sets `CLAUDE_PROJECT_DIR`. The adapter's own module
  maps the payload:
  - `SessionStart` (`startup`, `resume`, `clear`) → `idle`: every launch lands at the composer, so
    this is the first hook the host agent waits for before typing the first prompt (§4.1, TD-717);
    `SessionEnd` with `reason: exit` → `exited` (the tool fires only `exit` and `clear`).
  - **`/clear`** (alias `/new`) starts a new session in the same process under a new id: the tool
    fires `SessionEnd` (`clear`, never `exited`), then `SessionStart` (`clear`) carrying the new
    `session_id`. The record adopts it as its `adapter_id` and re-points its transcript, as Claude
    Code's `/clear` does (§4.2), so a resume names the newest id.
  - `BeforeAgent` → `working`, once per prompt, carrying the prompt mark (`prompt: true`) that
    confirms a `send` (§4.1) and judges a doorbell's ring; `BeforeTool`/`AfterTool` → `working`;
    `AfterAgent` → `idle`.
  - `Notification` (`notification_type: ToolPermission`) → `needs-you`: `pending.kind` is
    `permission` where `details.type` is `exec`, `edit`, `mcp` or `info`, and `question` otherwise
    (the tool's `ask_user` and `exit_plan_mode` come the same way), its text from `message` and
    `details`.
  - Each payload carries `session_id` and `cwd`; `transcript_path` is `""` until the tool starts
    recording, so the record's transcript is set from the first payload that carries one.

  **Two gaps**: `AfterAgent` does not fire when a turn is cancelled (Esc) or fails on an API error,
  and nothing fires when a permission is answered. **The title fills them.** The tool writes its
  state into the terminal title (`ui.dynamicWindowTitle`, pinned by the layer): `◇  Ready (…)` idle;
  `✦  Working… (…)` responding; `✋  Action Required (…)` a confirmation pending *or* the tool's
  embedded shell gone quiet after output, waiting for input; `⏲  Working… (…)` that shell quiet
  with no output. Each is a glyph, two spaces, the words and the context, padded to 80 characters,
  and `✦` and `⏲` both read *Working…* (the layer pins `ui.showStatusInTitle: false`, so `✦` never shows the model's thought), so the rules match on the leading glyph alone. The adapter's screen rule (its `explain`, given the pane's title as well as its tail, so
  `ao explain` prints the title as the evidence) reads `#{pane_title}` and **maps the glyph alone**:
  `◇` → `idle`, `✦` or `⏲` → `working`, `✋` → `needs-you` with `pending: {kind: question}` and
  no text. **The tick decides**, holding the record: once a hook has reached it (`hook_seen_at`),
  the verdict replaces the record's **hook-confirmed** state (`confidence` hook or title) when the
  two differ and the last hook is older than one tick, and the tick writes `✋`'s text by the state
  it replaces — *the tool's shell waits for input* over `working` (and over `stalled?`), *the tool waits for a
  confirmation* over `idle` (a custom command's shell confirmation, shown with no turn). The tick's
  own states are not compared: `exited` and `closed` stand, and a `stalled?` record is ended only
  by a verdict other than `working` (`◇` or `✋`: the tool has moved on), a `working` verdict over
  it being no event. A verdict equal to the record's state is no event either, so the tick's other
  checks, the stall check among them, still run. Its consequences: `◇` ends a cancelled or failed turn; `✦` or `⏲` ends an answered
  permission (no hook says so until `AfterTool`); `✋` over `working` is the embedded shell
  waiting; `✦` over `idle` is a slash command calling the model. A verdict whose state equals the
  record's never replaces its `pending`, so under a `Notification`'s `needs-you` the `✋` title
  is that confirmation and the hook's permission stands. **Before the first hook the title is not
  read**: the tool writes `◇  Ready` at mount, before its hooks run, and that is its screen, not
  its word on a turn; the first prompt waits for `SessionStart` as above.

**Spend per turn** (TD-128). For
any profile (§4.2a) an adapter reports `spend(profile, cursors) -> (turns, cursors)` — `cursors` a byte offset
per transcript path, `turns` a list of `Turn(at, id, source, offset, response, model, input, output,
cache_read, cache_write, cost, conversation, cwd, subagent)`, `id` the entry's own (Claude Code's `uuid`), `source` and `offset`
naming the transcript and the entry's position in it, `conversation` the tool's session id the
entry belongs to (Claude Code: the transcript's name, or for a subagent's transcript under
`<session>/subagents/agent-*.jsonl` the name of the directory two levels up, its parent's), `cwd` the directory the entry was written in, `subagent`
whether it is a subagent's turn (§4.4 *Spend per seat* charges a turn by these three), `response` the API response's id (one response
is written as an entry per content block, each carrying the response's usage: the adapter counts it
once within a read, the home once across two reads it straddles, §4.4) — from the tool's own records: Claude Code: the `usage` on each `assistant` entry of
every transcript under the profile's config directory past its cursor, sessions shiftlead did not
start included (a plain `claude` in a shell on the same key spends the same money) and subagent
turns included (they are billed), never the whole file each tick and never a grep — a cursor past
its transcript's current end means the tool rewrote the file (a compaction does), and the adapter
reads it from offset 0 again, the home dropping what it already ledgered (§4.4); an
OpenAI-compatible endpoint: the response's `usage`. Four token kinds, because a coding agent's
input is mostly cache reads priced at a tenth of input: an adapter that folded them into `input`
would report a bill several times the real one. `cost` is filled by the adapter where the tool
prices its own turns, else by the home from the profile's prices, else absent. The core sums, the
adapter reports, and neither knows a price list by heart: a metered profile's prices are the profile's
declaration, and the chip's hover shows tokens by kind, so a wrong price is visible. The one list
the core ships is `spend.weights`' default (§5), which weighs a turn with no cost for the seat
ledger alone and is drawn, dated, on the Settings page. An adapter that
cannot report spend for a metered profile says so once (`reason`), and the chip draws *spend
unknown*, never nothing — a metered profile with no reading is the runaway this exists to bound.
A **subscription** profile's `spend` is asked by the seat ledger alone (§4.4 *Spend per seat*), with
its own cursors: the same read, the same turns, `cost` absent. An entry whose `model` is
`<synthetic>` (the tool's own notice, zero usage) is no turn.
The core cannot read a profile, so the adapter says how one is billed: `billing_for(profile) ->
{billing, prices}` as `profiles.yml` declares it, an adapter without it billing every profile as a
subscription.
