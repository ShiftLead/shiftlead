When Paul asks for the frontend-design skill to be run on a mockup, render two versions:
- the skill's own recommendation, free to choose its type, palette and layout;
- the refinement held to ShiftLead's tokens and facet style.

Say which is which and what adopting the unconstrained one would cost: it clashes with the rest of the page, or it means restyling the app.

**Why:** in TD-1203 (2026-10-28) the session ran the skill held to "refine, don't rebrand" and showed only that (A3). Paul then asked to *show me the restyled version (that the design skill recommended)*. He had expected the skill's own pick. From the unconstrained version (A4) he took one idea into A3: member blocks whose height says the state.

**How to apply:** in any interactive UI round where the skill is invoked, alongside [[ui-review-screenshots]] and [[agree-the-layout-before-model-reviews]]. Offer the pick-and-mix: name the unconstrained version's ideas one by one so Paul can take some of them into the house-style shape.
