# ADR 2026-10-13: Muse — Meta's personal agent, Muse Code, and who each is for

Status: survey (2026-10-13, at Paul's request). **Nothing here changes the design by itself.** It
says what Muse is, whether it takes shiftlead's ground, whether the two can run together, and what is
worth borrowing. A companion to the [Grok Bot ADR](2026-10-13-grok-bot.md) of the same day.

## Context

Paul asked for the Grok Bot comparison again for [muse.ai](https://muse.ai/), with a framing: *the
big companies are targeting everyday users; shiftlead targets developers and tech leads who
understand the development process, LLMs and harnesses, and want full control.* A Sonnet agent
surveyed the coverage; the session re-read the sources the comparison rests on (see *What was
checked*).

**Every source is secondary.** `muse.ai` answers with a redirect into a Meta login (its
content-security policy names `*.facebook.com` and `*.meta.ai`, which confirms the owner), and no
Meta newsroom or help page was found. The product launched five weeks ago and ships weekly; read
this as of 2026-10-13. The domain's former owner, a video host, is not the product here.

### Muse Code: the developer product, and a different animal

A month before Muse, Meta shipped **Muse Code**: *"We're excited to release Muse Code (beta), a
terminal coding agent powered by Muse Spark 1.2"* ([Decrypt](https://decrypt.co/375001/muse-code-meta-ai-coding-agent-claude-code-and-codex),
2026-08-05). Installed by a curl script, *"available now via the Meta Model API"*, it coordinates
*"multiple persistent subagents for each task"* and logs every model call, tool run, approval and edit
to a local event log, so it *"can resume precisely where it stopped"* (same). Search coverage adds
macOS and Linux, pay-as-you-go token pricing, and sub-agents in isolated working trees; not re-read.
Nothing found says whether it has hooks, a headless mode or MCP.

Muse Code is not a competitor to shiftlead: it is **one more harness of the kind shiftlead runs**,
the way it runs Claude Code, Gemini CLI and Codex (§4.3's table).

## Who each is for

Paul's framing holds, with one qualification from the design itself.

- **Muse** is for everyone with a phone: no repo, no terminal, no model choice, no setup, and
  revenue from subscriptions and a fee on transactions. **Grok Bot** is for office work on a vendor
  cloud, billed through Cursor (its ADR). Both hide the harness and the model on purpose; that is
  what makes them easy.
- **shiftlead, now,** is for the developer or tech lead who already runs coding agents, knows what a
  harness and a context window are, and wants the sessions on their machines, with their tool, their
  model, their login and their repo's rules, and a terminal they can take over. That is the sequence's
  first step in §4.5c: *self-hosted for developers (now)*.
- **The qualification.** §4.5c calls *"automated context management for people who are not
  developers"* the later and strongest step (*cadence-as-a-product*). So "only developers" is the
  current market, not the end state. Muse shows the consumer end of that is a Meta-scale fight over
  errands and checkout; the ground §4.5c names is narrower and different — work that lands as
  commits, ledger lines and board items for someone who never learns what a branch is. Muse and Grok
  Bot keep their record in the vendor's memory; nothing in either lands in a repo.

## Does it usurp shiftlead?

**No, and less than Grok Bot does.** Grok Bot at least shares the org-of-agents concept and sits next
to a coding product. Muse is one personal agent doing consumer errands; it shares only the *agent
works while you are away, comes back for approval* loop.

| | Muse | shiftlead |
|---|---|---|
| Who | consumers, US only | developers and tech leads running coding agents |
| Where the agent runs | a VM in Meta's cloud; the person's Mac, once that ships | tmux on the person's machines and container nodes (§4.1, §4.4a) |
| Which agent and model | Meta's agent on Meta's models | the person's tool and model per profile (§4.2a, §4.3) |
| Whose bill | free, $20 or $100 a month, plus a fee on transactions | the person's own subscription (§6 *Usage gate*) |
| The person intervenes by | watching the browser, approving | attaching to the terminal and typing, answering the dialog, mail (§4.5, §4.10) |
| Consent | Sentinel gates outbound traffic; per-app read/write; asks before sensitive acts | permission prompts relayed to the UI's Allow/Deny (§4.2); grants on every act of control (§4.8) |
| Record | an audit trail in Meta's product; memory the person can prune | commits, PRs, the ledger and the board |
| Data | trains Meta's models unless opted out | stays on the person's hosts (§4.5c) |
| Many agents | one, plus its gatekeeper | an org: leads, workers, a techlead seat, teams (§4.9) |

## Can it run with shiftlead?

- **shiftlead driving Muse:** no. No API, SDK, MCP server, webhook or CLI was found; the surfaces are
  apps and WhatsApp.
- **Muse driving shiftlead:** not usefully. Its GitHub connector could in principle read or act on
  the PRs shiftlead's sessions open, but no source describes what it can do there, and a consumer
  agent with write access to a repo shiftlead governs bypasses the review and merge rules shiftlead
  exists to keep.
- **shiftlead running Muse Code:** yes, in principle, and the only pairing worth anything. A terminal
  agent with no adapter of its own runs today under the `shell` adapter, scraped like Aider
  (foreground process, prompt, exit code; §4.3); a tool-specific adapter adds state where the tool
  exposes it, and Muse Code's local event log is a likely source if
  it has no hooks. That is exactly the neutrality §4.5c calls the moat: when a vendor ships a new
  harness, shiftlead gains a tool rather than a rival.

## What to learn

1. **A second agent that gates the first.** Sentinel reviews what the agent sends out, read and write
   kept apart. shiftlead's gate is the person (Allow/Deny, §4.2) plus grants (§4.8); a policy-run
   reviewer that approves routine prompts and escalates the rest is the same idea, and Grok Bot's
   Auto-review rules are its rule-based cousin. *A note for whoever next designs approvals; not filed.*
2. **An audit trail that shows what is planned, not only what was done.** shiftlead's org view shows
   what each session is doing; a session's declared next steps beside its record is the half Muse
   adds. *A note, not filed.*
3. **Muse Code as an adapter candidate.** When it leaves beta, check it for hooks, a headless mode and
   its event log's format, and add a row to §4.3's table. *A note, not filed.*

**Not wanted:** a model and harness chosen by the vendor, interactions that train the vendor's models
by default, and a record that lives only in the vendor's product.
