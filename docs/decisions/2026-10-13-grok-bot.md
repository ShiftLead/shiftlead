# ADR 2026-10-13: Grok Bot — the vendor's "AI teammates", and where shiftlead differs

Status: survey (2026-10-13, at Paul's request). **Nothing here changes the design by itself.** It
says what Grok Bot is, whether it takes shiftlead's ground, and what is worth borrowing.

## Context

Paul read the [Grok Bot launch](https://x.ai/news/introducing-grok-bot) and asked whether it
usurps shiftlead, and whether its recent Anthropic-model announcement is API-only. A Sonnet agent
surveyed the launch, the docs and the coverage; the session re-read the primary sources for every
claim the comparison rests on (see *What was checked*). Sources are dated; the product is in beta and
moves weekly, so read this as of 2026-10-13.

### The Anthropic models: server-side routing, not a choice the person makes

On 2026-10-07 Musk posted *"Going forward, @SpaceX will use the best back end model for any given
task, including Claude Opus 5.5, MidJourney, Suno and other leading APIs"*
([The Next Web](https://thenextweb.com/news/grok-bot-claude-opus-midjourney-suno-musk), 2026-10-07).
The post names @SpaceX, not Grok Bot; the coverage applies it to Grok Bot. What it is:

- **No model picker.** *"Cursor manages model selection, so there is no model picker"* (docs,
  settings page). The person cannot pick Claude.
- **Not bring-your-own-key, not a Claude subscription.** Neither the docs nor the plans page mention
  Anthropic, Claude or API keys; no source found says a Claude Pro/Max login or an Anthropic key can
  be used. Claude is a backend xAI calls on its own API account and bills inside Cursor's usage.
- Per [Implicator](https://www.implicator.ai/grok-bot-claude-model-routing/) (citing the docs):
  usage analytics name the model that served each request, enterprise teams have a model allowlist
  honoured by default, and *"billing follows the serving model, and the provider mix can change over
  time."* Not re-read at the docs.
- No timeline and no task split were given (The Next Web). Nothing found says what happens to
  data sent to a third-party model.

So the answer to Paul's question: **effectively API-only, and not even the person's API** — it is
xAI's routing to Anthropic's API, invisible except in analytics.

## Does it usurp shiftlead?

**No — it takes the concept, not the job.** Both sell *an org of agents that pass work between
themselves and come back to you only for judgment*. Grok Bot is a strong answer to "AI teammates I
can hand work to from my phone" and shiftlead will not beat it on setup. But its unit is a Bot on a
vendor's cloud computer doing office and browser work; shiftlead's unit is a live coding-agent
session on the person's own machine, working a git repo under the repo's own rules.

| | Grok Bot | shiftlead |
|---|---|---|
| Where the agent runs | Cursor's cloud computer (optionally commands on your desktop) | tmux on the person's machines and container nodes; sessions outlive the UI and the host agent (§4.1, §4.4a) |
| Which agent and model | xAI's harness; the vendor routes the model; no picker | the person's own tool (Claude Code first, adapters for others) and their own login and model per profile (§4.2a, §4.3) |
| Whose bill | Cursor/SpaceX usage, weekly grant plus on-demand | the person's subscription; usage windows planned around (§6 *Usage gate*) |
| The person intervenes by | a chat thread; approvals | attaching to the live terminal and typing, answering the real dialog, mail (§4.5, §4.10) |
| Consent | Auto-review rules, admin-enforceable | the hook relays permission prompts to the UI, where Allow/Deny answers them (§4.2); grants checked on every act of control (§4.8) |
| Where work lands | the Bot's memory and the apps it touched | the repo: commits, branches, PRs, the ledger and the board (dev-cadence) |
| Engineering rules | none described: no git, PR, review or repo features in the docs | branch → PR → review evidence → merge; held paths and the techlead gate; promote and rollback; the anchor rule (§9) |
| Who decides behaviour | the vendor, weekly | the design: every control is in §4.5a, invariants in §9 |
| Isolation between agents | none: one computer, every Bot sees everything on it | one agent per directory (§9 invariant 2), worktrees, controllers and grants |

## Where shiftlead differentiates

1. **Your agent, your model, your bill.** Grok Bot made the model a vendor decision the person
   cannot see except in analytics. shiftlead runs the tool the person already pays for, with the
   login and model each profile names. This is §4.5c's *neutrality is the moat* in its plainest
   form: the vendor's Claude routing is exactly the "hosted copy of one" §4.5c says shiftlead must
   not become.
2. **A live session to take over.** A Bot is a chat thread. A shiftlead session is a terminal the
   person can watch mid-turn and type into — the same differentiator the Paperclip ADR found first.
3. **Work lands in git, under the repo's rules.** Grok Bot's record of what was decided is its own
   memory, which the person cannot inspect or export (Vellum, below). shiftlead's is a commit, a PR,
   a ledger line and a board item, and a merge is gated by review evidence and grants.
4. **On machines the person owns.** Grok Bot's local execution runs commands on the desktop, but
   the Bot, its memory and its browser sessions live in Cursor's cloud. shiftlead's sessions, repos
   and credentials never leave the person's hosts; the relay (§4.5b, §4.5c) keeps it that way when hosted.

**The risk.** Cursor is the vendor's coding surface and SpaceX owns it. A coding-focused Bot with
repo and PR awareness and decent oversight would make "an org of coding agents" a crowded pitch,
and leave shiftlead the ground of people who want self-hosting, auditability, their own model and
their own rules. That ground is real, and it is the one §4.5c already chose; the survey is a
reason to keep the relay and cadence-as-a-product on course, not to change them.

## Can it run with shiftlead?

Paul's follow-up the same day. A second Sonnet pass read the docs for every integration surface; the
session re-read the routines, approvals and private-networks pages.

- **shiftlead driving Grok Bot: no.** No API, SDK, MCP server, webhook or CLI for Grok Bot is
  documented; its clients are the desktop and mobile apps. The only outside triggers are `@bot` on X
  and routines, which run *"on a schedule or, where supported, after an event"*: *"Cursor account
  integrations can start a routine from an event, such as a Slack message or a GitHub notification"*
  ([routines](https://docs.x.ai/grok-bot/skills-routines-and-automations); no list of events). So a PR
  a shiftlead session opens could, at most, start a routine through a GitHub notification.
- **Grok Bot driving shiftlead: possible, not worth building.** Two routes exist. On the desktop app,
  Bots can run commands on the person's computer, *"Ask every time"* by default, with *Always allow*
  and *Never allow* the other choices and an admin cap
  ([approvals](https://docs.x.ai/grok-bot/approvals-security-and-privacy)); the docs name no
  limit on which commands, so a Bot could in principle run `ao`. And Bots can reach private services
  by routing through the person's desktop, or with Tailscale or Cloudflare Tunnel on their computers;
  Cloudflare Tunnel publishes private HTTP services at a hostname
  ([private networks](https://docs.x.ai/grok-bot/private-networks)), so a Bot could in principle
  reach shiftlead's UI (the page does not mention the browser). Either way the Bot acts as the person: an `ao` call with no `SHIFTLEAD_SESSION` *is* the person
  to shiftlead (§4.8a), all of a person's Bots share one cloud computer, whose *"command line
  credentials"* are *"available across your Bot roster"* (approvals page), and none of it is recorded as a session's act. That is a person-shaped hole in
  the grants, not an integration.
- **The honest use case is a split, not a pipe.** Grok Bot for the office and browser work around a
  project (inbox, tickets, a vendor portal), shiftlead for the repo work. Where they meet is the
  person: a Bot's finding becomes a brief or a board item by hand. No code is warranted for that.

## What to learn

Gathered with the other two surveys' lessons, for discussion, in the
[lessons ADR](2026-10-13-agent-product-lessons.md).

1. **Routines learned by demonstration.** *Show it once, it saves the steps, takes corrections,
   runs it later.* shiftlead's nearest things are briefs (`docs/briefs/`) and scheduled policies;
   neither is learned from watching the person. A brief drafted from a session the person drove —
   "save this as a brief" — is the shiftlead-shaped version. *A note for whoever next designs
   briefs; not filed.*
2. **Auto-review rules an admin can enforce.** Per-action approval rules with *Ask first* winning a
   conflict and an admin-locked rule shown as such map onto shiftlead's profile policies; *"Required
   by your admin. You can't edit or delete this rule"* is a clear way to show an org-level policy on a
   person's settings. *A pointer for the Settings page.*
3. **Analytics that name the serving model.** Even with routing hidden, each request says which
   model served it. shiftlead's run logs could carry the model a turn actually used where the tool
   reports it, for when a profile's model is changed or a fallback happens. *A note, not filed.*

**Not wanted:** one shared computer for every agent (the docs' own warning says why), memory the
person cannot read, and a model chosen by the vendor.

## What was checked

Re-read at the primary source: the Cursor acquisition (cursor.com, 2026-08-14), the cloud computer,
the shared computer and memory lines (docs overview), *Execution on Local Computer*, Auto-review and
*"no model picker"* (docs settings page), plans and billing (cursor.com plans page), and the Musk

private-networks pages. Not re-read: that no API, SDK, MCP server or CLI exists (the agent found

lines (Implicator, citing docs), the Security page's contents, and Vellum's breakdown
([vellum.ai](https://www.vellum.ai/blog/official-grok-bot-breakdown), 2026-08-20, a competitor) for

agent's report also cited a $200/month standalone price and a 14-day trial (Vellum), which the plans
page contradicts — the trial is a usage credit and the plans are as above — and a "free full access to
Claude Opus 5.5" claim (36Kr), uncorroborated and left out.
