## TD-2028: A test run that dies keeps its temporary files for three days in every seat that ran it, and the shared temporary disk runs out of file slots

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-19 (ao-samscrape-samup, through ao td add --repo; drafted by ao-shiftlead-techlead-ao-1)
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 1734b68f50574dbb8dfe087be920004e

**Why:** On 2026-11-20 (UTC) kmaster's `/tmp`, a 16 GB tmpfs of 1,048,576 inodes that every session shares, ran out of inodes and no Claude Code session on the machine could run a command (reported by samscrape's `ao-samscrape-samup`, who fixed the same in samscrape TD-469, PR #1128). Each seat's `TMPDIR` is its own scratch, `/tmp/shiftlead-1000/<scratch>/` (design §4.6 *A session's scratch*), so each seat's test runs get their own `pytest-of-kmaster/`, and a seat lives for days.

TD-1890's `tmp_path_retention_count = 1` should leave one run there, and TD-1053 already took the bare `mkdtemp()` probes out of the tests (`tests/test_no_temp_leaks.py` holds that). What it misses, read on 2026-11-19 (local) after the cleanup: in scratch `163e8fcd` six run directories stood, 164,080 inodes, and four of them (`pytest-51`, `-52`, `-75`, `-76`, 27k–53k inodes each) still held pytest's `.lock`; in `763f42dd` two runs held 114,944. A run that dies before its end — a precheck's timeout, a killed suite, the worker deaths of TD-2012 — leaves its `.lock`, and pytest's cleanup skips a locked directory until the lock is three days old (`LOCK_TIMEOUT`), so each dead run stays for three days in each seat that ran it.

`tmp_path_retention_policy = "failed"`, the reporter's suggested fix, was tried on #3977's first head and refused: it removes a passing test's directory at once, so a later test whose name starts the same is given the same path, and `tests/test_ui_inbox.py`'s counts test failed every time (TD-1890's log).

**Location:** tests/conftest.py (scratch_dir, the session fixtures); pyproject.toml ([tool.pytest.ini_options], tmp_path_retention_count)

**Fix:** Remove a dead run's directory without waiting three days. pytest writes the run's pid into each `pytest-N/.lock`; at a run's start (a `pytest_configure` or session fixture in `tests/conftest.py`), remove each sibling `pytest-N` under the run's own base temp's parent whose `.lock` names a pid that is not running, and leave a live one (another run in the same scratch) alone. Keep `tmp_path_retention_count = 1` and the `all` policy (TD-1890's reasons). Signal nothing: the check is `os.kill(pid, 0)` or `/proc/<pid>` alone. A test holds it: a scratch base temp with a locked run of a dead pid and one of a live pid, and only the dead one removed.

**Done when:** After a day of normal seat runs, each `/tmp/shiftlead-1000/<scratch>/pytest-of-kmaster/` holds no `pytest-N` whose `.lock` names a dead pid, and reads under about 60k inodes (`du -s --inodes`, a full run's size), stated in the Log with the date read.
