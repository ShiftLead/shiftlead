## TD-2265: An early question from a session stops counting on the Queue tab when its card draws it grey

**Priority:** Low
**Type:** debt
**Added:** 2026-11-26
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 6fc755c770504fd5b942768ab1e70e62
**Part of:** TD-2231

**Why:** Design TD-2231 (§4.4 *A question whose entry only waits is asked early*, *The count is by the mark*; §4.5 screens 6 and 12; §4.5a *Inbox page: the count* and *team card: Answer needed / Doing*): an item carrying the *asked early* or *waiting, then yours* mark (`early`, `then_yours`, set by `item_home` in `src/shiftlead/ui/queue.py`) — an open `ask --lift` from a session about an entry asked early or *waiting, then yours*, a `decide` line covering only entries asked early, and one covering any entry *waiting, then yours* — counts in no **Needs you (n)**, top bar number, Sessions rollup count, team card's *asked you* line or rail, wherever it is drawn. Today `inbox_sections` (`src/shiftlead/ui/inbox.py`) leaves out of `count` and `queue_n` only an early board line, so an early or *waiting, then yours* `ask --lift` (and a *waiting, then yours* line) puts a 1 on the Queue tab that no card shows; the team card's *asked you* line (`ask_blocks`, `src/shiftlead/ui/org.py`) counts every open ask in `needs`; and the Sessions page's first paint (the `/` handler in `src/shiftlead/ui/app.py`) calls `inbox_sections` without `entries_open`, and so does the counts keeper's recount (`Readings._counts_now`), so no mark is set on either and every page's top bar, the rollup and `ao inbox --counts` count the grey items.

**Location:** src/shiftlead/ui/inbox.py; src/shiftlead/ui/org.py (ask_blocks); src/shiftlead/ui/app.py (the / handler, _counts_now); tests/test_queue_asked_early_items.py, tests/test_ui_team_summary.py; design §4.4, §4.5 screens 6 and 12

**Fix:** 1. In `inbox_sections` (`src/shiftlead/ui/inbox.py`), `counted` leaves out every `needs` row carrying `early` or `then_yours`, a board line and a mail item alike (today: `not (e.get("early") and e.get("row") == "board")`); `count`, `queue_n` and `overdue_n` read it as today. Update the comment above it to cite §4.4 *The count is by the mark* and TD-2231.
2. `ask_blocks` (`src/shiftlead/ui/org.py`) passes over a row carrying `early` or `then_yours`, so the team card's *asked you* line, the rollup's *asked you* and its needs-you menu's member lines count none of them; its docstring says so.
3. The Sessions page's `/` handler (`src/shiftlead/ui/app.py`, the `inbox_sections` call under `h.needs_cache["rows"] = []`) passes `entries_open`, the open entries of `h.ledger_view`'s reading, as `card_mail` does, so its first paint's top bar, rollup and `needs_cache` rows carry the marks. With the open entries passed, a covered board line is also homed on its entry's card (`_item_home`, TD-1380) as the Inbox page homes it, so the top bar's Inbox and Queue split now equals the Inbox page's: an existing test of `/` or `_counts_now` that changes for that is meant to.
3b. The counts keeper's recount (`Readings._counts_now`, `src/shiftlead/ui/app.py`, behind `/api/person/inbox?counts=1`, every page's top bar, the rollup's poll and `ao inbox --counts`) passes `entries_open` from `self.ledger_view(fleet, got["entries"], got.get("handed") or ())` and `roots` from `self.repo_roots()`, as `card_mail` does; the `needs_cache["rows"]` it keeps then carry the marks `ask_blocks` reads. A failed ledger reading is `ledger_view`'s empty one, and the count reads no marks (counted until the next good read); nothing else is added for it. The recount reuses `counts_now`'s repos memo for the ledger reading; the defs read and `ledger_for_you` are new work on this path, accepted (a count that misreads is worse than one that costs a read). The numbers' hovers (the `needs_title` string in `src/shiftlead/ui/templates/inbox.html`, and the rail's *Needs you* line) are unchanged, on purpose (§4.4): a grey item is still an open question.
4. Nothing else changes: the card's drawing (`rewrite` in `src/shiftlead/ui/queue.py`), the rail (`rail_rows`, which already passes over both marks), §4.10's depths and telling, and §6 rule 13's mute stay as they are.
5. Tests, beside `tests/test_queue_asked_early_items.py`'s fixtures: an open early `ask --lift`, an open `ask --lift` whose entry is *waiting, then yours*, and an undecided line covering one member *waiting, then yours* and one plain `decision (paul)` member each give `count` 0 and `queue_n` 0 through `inbox_sections`; an overdue undecided line covering a member *waiting, then yours* gives `overdue_n` 0 (the Sessions rollup's *m overdue* and `ao`'s `overdue` read it); an ordinary open `ask` still counts 1, and so do a state row, a steer and a stuck row; `ask_blocks` over those rows returns only the ordinary ask; the Sessions page's first paint, with an early `ask --lift` and its entry open, draws the top bar's Queue number 0; the counts keeper's recount over the same fixtures gives `needs` 0 and `queue_n` 0, and `ask_blocks` over the `needs_cache` rows it kept returns no ask; with `ledger_view` empty the early ask counts 1, and with no cards or no roots an early ask whose `about` is a bare `TD-n` counts 1 (one naming its repo is marked without them); the top bar's Inbox and Queue split on `/` and from the recount equals the Inbox page's for a covered board line; the card's item is drawn as before. These tests are TD-2242's (an early lifting ask's `count` and `queue_n`), so this build's PR archives TD-2242 with it.

**Done when:** Through `inbox_sections`, an open `ask --lift` about an entry asked early or *waiting, then yours*, a line covering only entries asked early, and a line covering any entry *waiting, then yours* count 0 in `count` and `queue_n` (an overdue such line 0 in `overdue_n`); `ask_blocks` leaves them out, so the team card's and the rollup's *asked you* read 0 for them; the Sessions page's first paint and the counts keeper's recount read the marks (the `needs_cache` rows they keep carry them), so every page's top bar, the rollup and `ao inbox --counts` count them 0 (and 1 while the ledger reading is empty); an ordinary open ask counts 1; the tests in Fix item 5 pass.
