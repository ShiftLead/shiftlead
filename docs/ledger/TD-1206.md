## TD-1206: The sync pass still posts a `sync-check` SHIP for a lock's sync that no check now reaches: drop `review_body`, `posted` and the lock sync's note

**Priority:** Low
**Type:** debt
**Added:** 2026-10-28 (grinder-ao-2, from TD-1015)
**Owner:** grinder
**Kind:** build
**Status:** Open
**Location:** `src/sessionorc/sync.py` (`judge`'s non-bump branch, `review_body`, `REVIEWER`'s SHIP use), `src/sessionorc/agent_sync.py` (the *sync of dev-cadence …* note), `tests/test_sync_pass.py` (`MECHANICAL`, the SHIP-comment tests); design §6 *Sync* step 3

**Why:** TD-1015 took the lock's road out of `sync.check`, so its only *mechanical* verdict is a bump (`kind: bump`). `sync.judge` still has the branch that posts the home's own `cadence-review: SHIP · sync-check` for any other mechanical verdict, keeps `posted` on the entry, and `agent_sync` writes a *merged … — sync of dev-cadence <commit>, n files* note for it. Nothing reaches them now; `test_sync_pass.py` exercises them only through a stubbed check that returns the old lock-shaped verdict. TD-1015 left them to keep its PR to its Done when.

**Fix:** `judge` takes the bump's road for every mechanical verdict (or treats a mechanical verdict without `kind: bump` as the home's own error); drop `review_body`, the `posted` key, the `post_sync=False` `_check_bump` still writes into its result, and the lock sync's note wording; `block_body` and `REVIEWER` stay (the gate's BLOCK). Move `test_sync_pass.py`'s pass tests from `MECHANICAL` to `BUMP` with `compare_review` stubbed. Reword §6 *Sync* step 3's last sentence, which names this entry.

**Done when** no code path posts a `sync-check` SHIP, `posted` is gone from the sync entries, and `pdm run test` passes.
