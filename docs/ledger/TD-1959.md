## TD-1959: The Focus page's file links follow only the session's starting worktree, so work moved to another branch or worktree is hard to open

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-18 (paul, through Add entry; drafted by ao-shiftlead-techlead-ao-1)
**Owner:** designer
**Kind:** design-first
**Status:** Open
**Id take:** 9f406d5f6fa14ac09e361573a46b73c7

**Why:** seen by Paul on 2026-11-18 on the Focus page of `ao-shiftlead-td-1153`. A running session sometimes moves its work somewhere its record does not say: here it checked out branch `td-1953-tools` inside its own worktree `.claude/worktrees/td-1153`, and elsewhere sessions have gone on in another worktree. The Git card then reads *td-1953-tools · 4 unpushed* and its file links point into `td-1153`. In this case they open the right file, but nothing on the card says the branch is not the worktree's own name, so the person cannot tell whether the links reach the work. Where a session really works in another worktree, the card and its links read the record's directory, so the files the session is changing cannot be opened from the page at all. Paul asked for a second link that opens where the session is working now.

A path the session prints with a brace set, such as `docs/mockups/reviews/2026-11-18-td1953-tools-house-{1440,420}.png`, is not a link today: the path reader has no `{` in a run, so it cuts the run at the brace, resolves the cut prefix, finds no file and leaves it text. Paul asked whether such a path should link too, opening the first file it names that exists or else the worktree.

**Design PR:** #4154

**Location:** design §4.5a rows *Focus side panel, Git card: changed files*, *the pick*, *Focus pane: a path is a link*, §4.6 *A path in the pane is a link*, §4.2 (the record's `git` and `files`); `src/shiftlead/ui/static/app.js` (`AO.pathRuns`, `AO.fileUrl`, `AO.pathLinksHtml`, `AO.gitFiles`); `src/shiftlead/ui/app.py` (`git_root` from the record's `dir`); `src/sessionorc/agent.py` (`_resolve_paths`); `src/shiftlead/adapters/claude_code/` (`cwd` in the status-line payload, `hook.py`, and in transcript turns)

**Fix:** design first. Two parts, each a sentence in the design and a row in §4.5a before it is built:
1. **Where the session is working.** The card names the directory it reads. Where the session's tool reports a working directory other than the record's (Claude Code's status-line payload and its transcript turns carry `cwd`), the card adds a link that opens that directory in the editor, beside the existing ones, and its changed files and recent files resolve against the directory each was written in. Where the branch differs from the worktree's name, the card says so in its summary (*worktree td-1153 · on branch td-1953-tools*). The design round settles whether the Git card's reading follows the reported directory or stays on the record's.
2. **A brace set in a path.** A run holding one `{a,b,…}` set (no nesting, at most eight choices) is carried into the run (`AO.pathRuns` admits it) and expanded before it is resolved. The link opens the first choice that resolves to a readable file. Where none does, it stays text, unless the design round prefers opening the session's folder.

**Done when:** On a session that checked out another branch in its worktree, the Git card names both the worktree and the branch. On a session whose tool reports a working directory other than its record's, the card holds a link that opens that directory. A printed path with a brace set opens the first file it names that exists. Each is covered by a test.
