## TD-1959: The Focus page's file links follow only the session's starting worktree, so work moved to another branch or worktree is hard to open

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-18 (paul, through Add entry; drafted by ao-shiftlead-techlead-ao-1)
**Owner:** designer
**Kind:** design-first
**Status:** Open
**Id take:** 9f406d5f6fa14ac09e361573a46b73c7

**Why:** seen by Paul on 2026-11-18 on the Focus page of `ao-shiftlead-td-1153`. A running session sometimes moves its work somewhere its record does not say: here it checked out branch `td-1953-tools` inside its own worktree `.claude/worktrees/td-1153`, and elsewhere sessions have gone on in another worktree. The Git card then reads *td-1953-tools · 4 unpushed* and its file links point into `td-1153`. In this case they open the right file, but nothing on the card says the branch is not the worktree's own name, so the person cannot tell whether the links reach the work. Where a session really works in another worktree, the card and its links read the record's directory, so the files the session is changing cannot be opened from the page at all. Paul asked for a second link that opens where the session is working now.

A path the session prints with a brace set, such as `docs/mockups/reviews/2026-11-18-td1953-tools-house-{1440,420}.png`, is not a link today: the path reader has no `{` in a run, so it cuts the run at the brace, resolves the cut prefix, finds no file and leaves it text. Paul asked whether such a path should link too, opening the first file it names that exists or else the worktree.

**Design PR:** #4154

**Location:** design §4.5a rows *Focus side panel, Git card: changed files*, *the pick*, *working in*, *Focus pane: a path is a link*, §4.6 *A path in the pane is a link*, §4.2 (the record's `git`, `files` and `cwd`); `src/shiftlead/ui/static/app.js` (`AO.pathRuns`, `AO.fileUrl`, `AO.pathLinksHtml`, `AO.gitFiles`); `src/shiftlead/ui/app.py` (`git_root` from the record's `dir`); `src/sessionorc/agent.py` (`_resolve_paths`, `rpc_paths`); `src/sessionorc/agent_tick.py` (the hook event applied, the status read); `src/sessionorc/agent_serve.py` (`_view`); `src/shiftlead/adapters/claude_code/hook.py` (`cwd` in the payload)

**Fix:** Built as design §4.2 *The record's `cwd`*, §4.3 (the hook payload's `cwd`), §4.6 *A path in the pane is a link* and §4.5a *Focus side panel, Git card: working in* (TD-1959; builds TD-1988 and TD-1989):
1. **Where the session is working.** The record carries `cwd`, the folder the session's tool reports in its hook payloads (Claude Code's and Gemini CLI's), and the status read its `cwd_root`; the Git card's summary names the worktree beside its branch where they differ, and a *working in* link opens the moved folder where it is another worktree, repository or outside any. The card's lines, its pick and the recent files stay on the record's own worktree (the steer's answer, m-f50b27f86e43). A relative path the session prints resolves against `cwd` first, then `dir`, and its press opens the deeper root's folder first.
2. **A brace set in a path.** A run holding one `{a,b,…}` set (no nesting, two to eight choices) is asked one entry per expansion; the first choice that resolves to a readable file is the link, and none leaves it text.

**Done when:** On a session that checked out another branch in its worktree, the Git card names both the worktree and the branch. On a session whose tool reports working in another worktree, repository or outside any, the card holds a link that opens that folder. A printed path with a brace set opens the first file it names that exists. Each is covered by a test.
