**Why:** TD-1718's design: a run of `/shiftlead-feedback` at an install whose person cannot push to shiftlead writes a feedback report, its approved findings with every name of the install taken out, for the person to submit as an issue. This build is the verb that writes it, deterministically, so the scrub is code and not an agent's care.

**Location:** design §4.7 Feedback (Reports from other installs); src/shiftlead/feedback*.py, cli.py

**Fix:** Build `ao feedback report --findings <file> --out <file> [--json]` and the constant `feedback.UPSTREAM` (`ShiftLead/shiftlead`), as design §4.7 *Feedback* bullets *The build the install runs*, *What a report carries, and what never leaves*, *`ao feedback report`* and *The report's shape* (under *Reports from other installs*) say: the fields kept (`days` a whole number, `noise` 0 to 1 at two places) and the refusals (exit 2, nothing written); the commit and the build's day from `direct_url.json`'s `file://` checkout, its path percent-decoded (`null` elsewhere); the scrub, names first in one pass, one alternation longest first, so no placeholder is matched again (records' id, name and profile from `ao status --json`, teams, repos' names and roots from `ao repo --all --json` but the three, hosts, the hostname and its short name, `$USER`, git's global user.name, each word of it, and user.email; whole words, case-insensitive, three characters or more), then the patterns in the design's order (URLs, emails, paths by the given boundary, mail ids and UUIDs, then the 32-character runs, then other repos' refs); `what` and `fix` cut to 300 characters; the Markdown file (title line, table drawn from the block, marker line, one fenced `json` block, `v: 1`); the publish check over that file with the written accept file (shiftlead's and ledgerboard's names as case-free character-class globs; none for agent-cadence), and exit 0, 1 (its lines, the report still written) or 2 (it cannot run, or the file is refused). Tests: a findings file holding every kind of name and pattern comes out with each replaced by its placeholder (a UUID as `<id>`, a ShiftLead URL kept, another URL `<url>`, a first name from user.name) and the check passing; a record named `seat` leaves `<seat>` whole; a name the scrub misses (one only `publish-names` lists) exits 1 with the check's line; an unknown area, a bad count and a bad id are refused; no `direct_url.json` gives `null` commit and build day.

**Done when:** Done when `ao feedback report` writes a report in the design's shape from a findings file, scrubbed by the two passes, its publish check run with the accept file and its exit as the design gives it, with tests for each kind of name and pattern, each refusal, and the build read and unread.
