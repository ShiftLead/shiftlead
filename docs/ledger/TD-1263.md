## TD-1263: A selection in the Focus pane cannot run past the pane's edge, and a copied line that wrapped comes back broken with padding

**Priority:** Medium
**Type:** debt
**Added:** 2026-10-30 (Paul, through Add entry; drafted by ao-shiftlead-term-copy)
**Owner:** designer
**Kind:** design-first
**Status:** Open
**Location:** `src/shiftlead/ui/static/app.js` (the Focus terminal's setup, `scrollback: 0`; `copySel` and copy on select; `AO.cutRows`, TD-494's join; `AO.wheelStep`); `src/shiftlead/ui/pty_bridge.py` (the `scroll` message, `copy-mode -e` and `scroll-up` / `scroll-down`); design §4.6 *Scrollback is tmux's, reached through tmux* and *The mouse is the browser's*; §4.5a *Copy / Paste* and *copy on select*

**Why:** Paul, 2026-10-30: *Right now in the focus terminal, selecting multiple lines (for copy) does not scroll as you get to the edges of the terminal window … Also, when a line wraps, there are extra spaces added to the selection, so that if "abcdef" were on a line boundary and I selected and copied it the paste would be something like "abc    def".* Copying out of a session is how the person takes an agent's output (a plan, a command, a path) somewhere else, and today they can copy only what fits on one screen, and must repair every wrapped line by hand.

Two causes, both in how the pane is built:

1. **No scroll while selecting.** The selection is xterm.js's own (§4.6: the attach sets no mouse option), but xterm.js runs with `scrollback: 0`, because tmux owns the history (TD-022). xterm.js's drag autoscroll can only scroll its own buffer, which holds exactly the screen, so a drag past the top or bottom has nowhere to go. The wheel reaches tmux's history through the bridge's `scroll` message (`copy-mode -e`, `scroll-up`), but tmux then repaints the screen in place, and the xterm.js selection, held in screen rows, stays on the same rows while different text moves under it. So a selection longer than one screen cannot be made in any way.
2. **Wrapped lines copy as broken lines.** xterm.js's `getSelection()` joins rows only where the row is marked `isWrapped`. A row is almost never marked that way here: tmux redraws its client with cursor moves, and Claude Code (Ink) breaks its own lines at the width with hard newlines and indents each continuation row (two columns under `⏺`, more in lists and boxes). So a copy of `abcdef` split across a boundary is `abc`, a newline, and the continuation's indent before `def`, which reads as `abc    def` wherever the paste flattens the newline. No terminal on this road knows these rows are one line, so the fix is a rule about what the rows look like, not a flag to read. TD-494's rule (`AO.cutRows`: the row above is full to its last column) covers a word cut mid-word, but not Ink's word wrap, where the row above stops short of the width.

**Fix:** a design round first, since (1) changes §4.6's *the mouse is the browser's* model. Directions to weigh:

- (1) **Keep the selection in history coordinates and ask tmux for the text.** While a drag is held past the top or bottom edge, the page sends `scroll` messages at a steady rate (the wheel's road). The bridge reports the pane's scroll position (`#{scroll_position}` / `#{history_size}`), so each end of the selection is a (history line, column) pair, and the highlight is redrawn from it after each repaint (`term.select`, clipped to the screen). On release, the bridge answers the range with `capture-pane -p -J -S <a> -E <b>`, trimmed to the end columns, and that is what Copy and copy on select write. Alternative: hand a drag that leaves the pane to tmux's own copy mode (`mouse on`, `copy-pipe` to the client by OSC 52). This is cheaper but reverses TD-174, so weigh it against Shift+click and copy on select, which would no longer be the browser's.
- (2) **Join at copy time, in one pure function** (`AO.copyText(rows, …)`, tested like `AO.cutRows`): join a row to the next when tmux marks it wrapped (`capture-pane -J` does this where tmux knows the wrap, which fits (1)'s road), or when TD-494's cut rule holds, sharing that rule rather than copying it. Then drop the continuation row's leading indent, up to the indent of the line it continues. For Ink's word wrap, weigh a rule such as *the next row's first word would not have fitted in the row above's free columns* (the test a wrapper makes) against false joins of real short lines, and decide whether a *copy as typed* choice (the raw rows) stays reachable, e.g. Alt+drag or a second Copy.

**Done when:** in a Focus pane, a drag held past the top or bottom edge scrolls tmux's history and grows the selection, and its copy is every line it covered, more than one screen included. A line Claude Code wrapped (mid-word or at a word) copies as the one line it was, with no newline or padding at the wrap. Real line breaks and indentation the program printed are kept. Tests drive the join function over fake rows (a cut row, a word-wrapped indented row, a real short line), and §4.6 and §4.5a *Copy / Paste* say what a copy is.
