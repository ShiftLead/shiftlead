## TD-2067: A killed test run leaves its agent children running for good, and no sweep stops them

**Priority:** Low
**Type:** debt
**Added:** 2026-11-22
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 82bc65f7f0654a738ef04cc5824ac72e

**Why:** a test's agent child (`tests/_agent_child.py`) outlives a pytest run that dies, and nothing ever stops it. On 2026-11-22 kmaster held 39 of them, from 11 precheck worktrees whose directories were already gone, started between 2026-11-06 and 2026-11-20 and reparented to init or `systemd --user`. No precheck or test run was live. Together they held about 1.2 GB, and those sampled each used 1.2 to 1.4% of a CPU for as long as they lived, on the machine where loaded runs already fail for no fault of the PR (TD-2037).

The harness sweeps what a killed run leaves in tmux servers, scratch roots and pytest directories (`sweep_stale_test_servers`, `sweep_stale_scratch_roots`, `sweep_dead_pytest_runs`), but not this process: `subprocess_agent` stops its child only in fixture teardown, which a killed run skips. The only remedy is `tests/README.md`'s `pkill -f tests/_agent_child.py`, which also kills the children of any concurrent run, and which a session's kill guard refuses. What killed these runs was not traced.

**Location:** tests/conftest.py (subprocess_agent, the sweeps), tests/_agent_child.py, tests/README.md (After a killed run)

**Fix:** Tie the child's life to its owner, so it ends however the owner ends. For example, `subprocess_agent` passes `stdin=subprocess.PIPE` (the `Popen` has no stdin today) and keeps `proc.stdin` open for the child's whole life, and `_agent_child.py` gets a new reader that cancels the serve task on EOF, since `serve_until_signal` stops only on SIGINT and SIGTERM. Check any choice against xdist workers (`PR_SET_PDEATHSIG` fires when the creating *thread* exits, so it needs care). Replace the README's `pkill` with a recipe that cannot touch a live run.

**Done when:** A test kills a pytest process holding `subprocess_agent` with SIGKILL and sees its `_agent_child.py` exit within a few seconds, while a concurrent run's child stays up; `tests/README.md` no longer tells anyone to `pkill` every child.
