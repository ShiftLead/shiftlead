## TD-1201: `ao td reserve` hands out ledger ids and says *reserved*; `ao td next` stays as its alias, and the briefs, help and memories say `reserve`

**Priority:** Medium
**Type:** debt
**Added:** 2026-10-28 (the designer, from TD-1200's design)
**Owner:** grinder
**Kind:** build
**Status:** Open — build
**Part of:** TD-1200
**Location:** `src/shiftlead/cli.py` (`cmd_td_next` ~3452, `_td_next_send` ~3492, the `next` subparser and its help ~5099); the package briefs `src/shiftlead/briefs/entry.md`, `grinder.md`, `designer.md`, `sweeper.md`; the docstrings and comments that name `ao td next` in `src/sessionorc/agent_ids.py`, `settle.py`, `agent_rank.py` and `src/shiftlead/cli.py` (`_td_repo`, `cmd_td_next`, `_td_branch`); `docs/ledger/README.md`; `docs/claude-memory/` (the memories and `MEMORY.md` lines that name `ao td next`); `tests/test_td_next.py`, `tests/test_sweep_seat.py` (its assertion at :67 that the sweeper brief names `` `ao td next` ``)

**Why:** TD-1200: `ao td next` reads like a question but spends an id on every call, so sessions run it as a probe and leave gaps in the ledger.

**Fix:** as design §4.7 *Entries* (`ao td reserve`) says. (1) A `reserve` subparser under `td` with `next`'s flags (`--repo`, `--count`, `--held`, `--json`), calling the same `td_next` RPC; the RPC keeps its name. Its plain output is one line an id, `reserved TD-1234`, or `TD-1234 (not reserved on origin's counter)` where the reply's `reserved` is false; `--json` unchanged. (2) `next` stays as an alias with the same flags: its standard output stays the bare ids one a line, and it adds `ao td next is now ao td reserve — it reserved TD-1234, TD-1235` on standard error after the call (`— it handed out …` where `reserved` is false), with `--json` or without, after the other standard-error lines, and only on a reply that gave ids; its `--json` output is `reserve`'s, byte for byte; its help line says it is the old name of `reserve`. (3) `ao td --help` (*take the next free id* becomes *reserve the next free id*) and the `reserve` help line say every call spends the ids it prints and a probe of the home is `ao repo` or `ao status`; the `--json` help names `{repo, ids, unread, reserved, why, warnings, taken_by, taken_by_line}` and `held` true with `--held`, not the stale `{repo, ids, unread}`. (4) The package briefs, `docs/ledger/README.md`, the docstrings and comments named above, and the memories' present-tense instructions say `ao td reserve`; history, dated lines, merged PR text and the ledger's entries stay as written, and the RPC and function names (`td_next`, `rpc_td_next`, `cmd_td_next`, `_td_next_send`) stay. (5) Tests: `reserve`'s output and JSON, the alias's bare stdout and its stderr line (with and without `--json`, and none on a refusal), `--held` through both; `test_sweep_seat.py`'s brief assertion takes `` `ao td reserve` ``.

**Done when** `ao td reserve` hands out ids and prints *reserved TD-n*; `ao td next` still works, prints the bare ids and names its new name on standard error; no package brief, help text or present-tense memory says `ao td next` but as the alias; `pdm run test` and `pdm run lint` pass.
