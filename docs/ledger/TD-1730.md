## TD-1730: The pair bound's addressee-side sum has no test that reaches it alone

**Priority:** Low
**Type:** debt
**Added:** 2026-11-12
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 44ff29a398bd4f62a9f7167818550a99
**Location:** src/sessionorc/agent_mail.py _check_bounds; tests/test_td_max_seat_one_open.py

**Why:** #3573 (TD-1728) made `agent_mail._check_bounds` refuse when either side's summed pair tally is at the bound: `if sum(t.count for _, t in mine) >= limit or sum(t.count for _, t in theirs) >= limit:`. No test in `tests/test_td_max_seat_one_open.py` reaches the `theirs` sum alone. Every case tallies through `_both`, which writes the same count to both sides, so `mine` is at the bound whenever `theirs` is; the one-sided case (`test_records_that_are_no_seat_are_refused_at_todays_count_by_id`) tallies the sender's side only.

Evidence (mutation, run in a worktree on origin/main e21f3e3ca, restored after): changing that line to `if sum(t.count for _, t in mine) >= limit:` leaves all 19 tests in the module passing (`19 passed`). Dropping the `mine` sum instead fails one test, so only the addressee side is unguarded. The design's rule (§4.9 *A scaled seat's bounds*, §4.10 *A bounded exchange*) refuses on either side's sum, and the pre-PR code did the same with `theirs.count >= limit`.

**Fix:** Add a test in `tests/test_td_max_seat_one_open.py` that tallies only the addressee's records (`_tally(g["ao-tl"], "ao-a", 5)`, or spread over `ao-tl` and `ao-tl-2`) and expects `check("ao-a", ["ao-tl"])` to raise; then rerun the mutation above and see it fail.

**Done when:** Dropping the `theirs` sum from `_check_bounds` fails a test in `tests/test_td_max_seat_one_open.py`.
