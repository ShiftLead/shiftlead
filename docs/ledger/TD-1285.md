## TD-1285: This repo is public, but a fork's PR gets no forge CI, and ShiftLead offers its precheck line, which runs the fork's code on the machine

**Priority:** medium
**Type:** debt
**Added:** 2026-10-30 (Paul, session `td-191`: "We should probably record TDs in agent-cadence and shiftlead for this as well")
**Owner:** grinder
**Kind:** build
**Status:** Open. The shape is agreed (Paul, 2026-10-30): the same decision as agent-cadence TD-192, Actions on fork PRs only, for this repo and for what ShiftLead shows about a fork's PR. Decided 2026-10-30 (Paul: "show the precheck line"): once a fork's PR has green forge CI, ShiftLead shows the person its precheck line, with `--fork-ok` (agent-cadence#TD-207's override; `precheck.py` refuses every fork's PR without it). Ready to build.
**Location:** `.github/workflows/ci.yml` (`workflow_dispatch` only, TD-1035); `AGENTS.md` (*A PR's gate is its `cadence/precheck` status, not GitHub Actions*, ~131); `docs/briefs/`; `src/sessionorc/cadence.py` `precheck_typed()` (the `precheck.py --pr` line a session is told to type) and its callers in `agent.py`; `src/sessionorc/reports.py` (the PR row's `fork`); `src/sessionorc/sync.py` `decline()` (already declines a fork)

**Why:** TD-1033 and TD-1035 moved this repo's gate to the local precheck, because the account's Actions minutes were one shared pool. A public repo runs Actions free, so that reason lapses here. The local gate also has a cost on a fork's PR. `precheck.py --pr` checks out the fork's head and runs its `pdm run lint` and `pdm run test` on the person's machine, with their `gh` token and home directory in reach.

The sync pass already declines a fork before it prechecks. But where ShiftLead tells a session or the person how to gate a PR, it offers the same `precheck.py --pr` line whether or not the PR is a fork's. agent-cadence decided this for itself in TD-192 (2026-10-30): `ci.yml` runs on a fork's PR only, it is not required, and a fork's precheck is the person's, after reading the diff and seeing that run green. agent-cadence#TD-207 adds the refusal to `precheck.py` itself, for every consumer.

**Fix:**
1. `ci.yml` runs on `pull_request` with a job `if: github.event.pull_request.head.repo.full_name != github.repository`, and keeps `workflow_dispatch`. It is not a required check. A run on this repo's own PRs would gate them anyway (agent-cadence's `ci` row judges every check run when the base requires none), so they skip it.
2. Where ShiftLead reads a PR's gate or offers the precheck line, a fork's PR reads the forge's CI first. Once that is green, it shows the person the precheck line with `--fork-ok`, named as theirs to run after reading the diff. While the CI is not green, it shows only the CI. It never hands a session the line for a fork's PR. The sync pass's `forked` decline stays.
3. `AGENTS.md` and the briefs say so, replacing TD-1035's *run only by hand*.

**Done when** a fork's PR runs this repo's CI in Actions, the person sees a fork's precheck line (with `--fork-ok`) only once its forge CI is green, no ShiftLead surface hands a session that line, and the docs say how a fork's PR is gated.

**Related:** agent-cadence#TD-192 (the decision), agent-cadence#TD-207 (`precheck.py`'s refusal), ledgerboard#TD-003, TD-1033, TD-1035.
