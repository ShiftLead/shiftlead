**Why:** TD-1064: Paul's Add entry session for contractmatch (2026-10-26) ran on kmaster, not on the contractmatch container node where cm-grind's team runs, so it had no Flutter and could gate only the PRs that touch no frontend code. `entry_plan` reads the local host's registry and `repo_teams(org, host_name())`, and `api_entry_session` creates with no `host`, so the session always lands on the home.

**Fix:** as §4.9 and §4.5a say. `entry_plan` resolves the team the repo's teams give (as now), then that team's host after `place:` (`t.host`, which the plan already reads for `attach`). Where the host is another, the plan carries `host`, the repo's path there as the start reads it (`org.checkout(t.repo, t.host)` after `with_repos`: the org file's project path first, else that host's registry), and the line *…, in a new worktree on <host>*. What the session is resolved from follows the host: for a container node, whose checkout is the home's own directory, `repoconfig.discover`, `entry_role`, `team_reader`, `resolve_role` and `entry_text` read the home's checkout as now; for a machine node they read as the New session form does (`host_files` and `repoconfig.load_text`, §4.4a *The New session form on another host*), and `entry_role` passes those `files` to `teams.entry_role`, so a feature opens the flow's design role. A container node is one in `containers.container_nodes()` (hosts.yml's `container:` entry, as `host_worktrees` tells it); any other node reads through `host_files` and `host_branch` even where its path is also a directory on the home. `teams._checkout`'s own directory test is left as it is. The host is the team the session carries (the first servicing team, `repo_teams`); the Team pick does not move it. The name test: `name_check` routed with `host` always (a node's records are `id@node` at the home); the worktree test `host_worktrees` on every node; the branch test the home's own for a container node, and for a machine node a new **`host_branch {host, dir, name}`** read (`{exists}`, link method `branch`, `modes.HOME_ONLY`, ungated as `host_worktrees`; a node's *unknown link method* refusal answered as `{exists: null}`), asked by the plan and again at the press; the default's search (`ENTRY_TRIES`) reads the node once per plan — `host_worktrees` once, the routed name check per candidate only where the listing passes it, `host_branch` only where both pass — a failed candidate skipped with no words, and the first failed read ends it with the plan answering `default: ""`, the host's words as `name_why` and the button disabled (the 409 stays for an exhausted search alone, so `api_entry_hand`'s plan read never fails on a node); a typed name is read in the Name row's order (routed name check, worktree, branch), three reads at most. `entry_name_why` takes the node's checkout path (not the home's root) for every test; `host_branch` at the node verifies `refs/heads/<name>` — found `true`, exit 1 `false`, exit 128, a timeout or an OS error `null` (never `entry_branch_exists`'s *False on any failure*). `api_entry_session` creates with `host`, `dir` and the worktree base the node's path, `reach_block` keyed by the home's registered root as now, and `team_reader` given the node's `cfg` on a machine node (its `directory` the home's root, then not read); a team with no checkout there disables the session way with the start's words — `org.unlanded[team]` for a repo's team, else, where `org.checkout` gives no path, the sentence `_checkout` writes, with *Open a session* as its `where`; `teams.plan` is not run — never creating on the home's root. A host that does not answer or a link that is down, whichever read met it, makes the plan's `why` *<host> did not answer*, and an `exists: null` *<host> did not say whether <name> is free*, the session button disabled and **Hand to the techlead** untouched. A repo no team services, or a team on this host, is as today.

**Done when:** tests show (a) a plan for a repo whose team `place:` puts on a container node names that host, the path `org.checkout` gives (an org-file project path, and a registry path), the line *…on <host>*, and the press creates with `host` set to it; (b) a typed `entry-1` held by a suspended session in the node's main checkout is refused in the name check's words, the routed `name_check` asserted; (c) on a machine node the role, reader and ledger are read through `host_files`, and an existing branch there is refused in the Name row's words; (d) an unreachable node disables the session way with *<host> did not answer*, and a team with no checkout on its host with the start's refusal (a repo's team and an org-file team each), while `entry_add` (the mail way) still answers; (e) a team on this host, and a repo no team services, plan and create as today; (f) a plan on a node with three live entries makes one `host_worktrees` call. `pdm run test` and `pdm run lint` pass.
