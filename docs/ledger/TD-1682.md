**Why:** **Why:** #3479 (TD-1589 slice 2) forks the status line's report into a child that, by design §4.4 *A report*, is "out of the status line's process group and holding none of its pipes" (`aside`, `src/shiftlead/adapters/claude_code/hook.py`: `os.setpgid(0, 0)`, `os.closerange(3, 1024)`). The one test, `test_a_lagging_agent_still_finds_the_reporter_alive_and_the_line_does_not_wait` (tests/test_statusline.py), cannot tell if the process-group half is there. Probe on origin/main 9dd02dbf2: in `aside`, replace `os.setpgid(0, 0)` and `os.closerange(3, 1024)` with `pass`, run `PYTHONPATH=$PWD/src pdm run pytest -q tests/test_statusline.py`: 8 passed. (Replacing the child's `fn(REPORT_WAIT)` with `fn(REPORT_TIMEOUT)` does fail it, so the wait is pinned; the group is not.) The group matters because the tool cancels a still-running status line's group: a child left in it is killed at the next redraw, and the lagging-host refusal (`unreadable`) comes back with nothing red. `closerange` is redundant for the pipes the test hands over (fds 0-2 are re-pointed at /dev/null anyway), and a pipe above fd 2 is not exercised.

**Fix:** Add to that test (or a sibling): run the status line in a subprocess started in its own process group, record the reporter child's `getpgid` (the FakeAgent can read `/proc/<pid>/stat` while it lags, as it already reads `/proc/<pid>`) and assert it differs from the parent's; and hand the subprocess an extra pipe (`pass_fds`), read it to EOF in the test, and assert it closes before the lag (`run` alone waits only on its capture pipes). Revert `setpgid` locally and see the new assertion fail before committing.
