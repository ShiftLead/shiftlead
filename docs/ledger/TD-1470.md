**Fix:** Design first (§6, the tick's policies; §4.4 *The card's status*; §4.10). Paul's suggestion: one home-side check, run every tick. It finds any open ask, decide item or ready PR that no live session has been able to act on for more than N minutes, and raises a *needs you* on its card that names why:
- limited;
- interactive;
- capped;
- parked at its ceiling;
- released;
- home down.

The per-cause entries (TD-1434, TD-1435, TD-1441, TD-1443) become the reasons it reports, rather than each building its own alarm. Also in scope: a send never goes missing. `ao msg`, `ao td add` and `ao progress` already fail loudly against a stopped home: `main` catches `AgentUnavailable` and exits 3 with an error line (`src/shiftlead/cli.py`, `_unavailable`; design §4.7). The three filings lost on 2026-11-06 came from `ao` itself missing, so the shell said *command not found* and no CLI code ran, or from a session that did not act on the failed send. Say how a session learns its send did not land and sends it again: the brief's rule to read the exit, a spool the next `ao` drains, or the check above seeing the session's work stalled. Say where the check lives so it still runs when one seat is the stuck one, and what N is per kind.

**Done when:** The design names the check, its N per kind, the reasons it reports and where the card shows them, and how a send to a down home fails. Builds carrying `Part of: TD-1470` make it so. A test: an open ask whose only able seat is limited for more than N minutes makes its card read *needs you* with the reason *limited*.
