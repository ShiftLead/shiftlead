## TD-1984: A Queue card shows no Start session while another session holds its entry

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-18 (paul, through Add entry; drafted by ao-shiftlead-techlead-ao-1)
**Owner:** designer
**Kind:** design-first
**Status:** Open
**Id take:** d9afb9a27d994764a04f2f98a879f90c
**Blocked by:** decision (paul)

**Why:** Seen by Paul on 2026-11-18 (21:31 local) on the Queue: the card around TD-1977 had one item waiting on him, a Do item from ledgerboard's board (cut the v3.5 release, ledgerboard TD-151), and neither the item nor the card's header drew **Start session**. He expects every Queue card for an entry that is not done to offer it, so he can always start a session on the work in front of him.

The button was absent by design. At that moment grinder-ao-2 held TD-1977, the card's `start` entry (it dropped the claim at 04:32 UTC, a minute later). Design §4.5 screen 12 *Three verbs: Start session* says that with none of the person's own sessions on the card and another session holding the entry an item starts on, the button is absent, the row says *held by <name>*, and a stale press is refused 409. A board item that is no entry, like this release line, starts on the card's `start`, so it too drew nothing; §4.5a's *Queue card: Start session / Open session* row says the same. The card then showed no way to start work and no word saying why (the item row did not read *held by grinder-ao-2*; only the header's holder pill named it).

The rule exists so a press never starts a second session on an entry a worker is building. Paul's word asks for the opposite default: the person is never left without the button on open work.

**Ask:** Should the grinders build Start session on a card whose entry a worker holds, or run one more review round first?

**Design PR:** #4179

**Location:** design §4.5 screen 12 *Three verbs: Start session*; §4.5a *Queue card: Start session / Open session*; src/shiftlead/ui/templates/queue_card.html, queue_row.html (the holder test); /api/ledger/start (the 409 held-by refusal)

**Fix:** Design first: §4.5 screen 12 *Three verbs: Start session* (the holder rules, *Started from an item*) and §4.5a's *Queue card: Start session / Open session* row. Make Start session drawn on every card whose entry is open, on its Decide and Do items and in the header by the existing count, whoever holds the entry, keeping only the exclusions that are not about a holder (a red PR, a fork's PR, a stopped holder's state row, a stuck row) unless the round finds one of those is the same complaint. Say what a press does while another session holds the entry the item starts on: likely a session of the person's own on a fresh worktree and branch, its prompt naming the holder and its claim, with the 409 *held by <name>* road removed or kept only for a stale page; or, where two sessions on one entry is the wrong answer, what the person is offered in its place, so a held card is never bare. Say too where a board item from another repo (this one a ledgerboard release) starts: on the card's `start`, as now, or in that item's own repo. Then file the build with `Part of:` this entry (the template's holder test in `queue_card.html` and `queue_row.html`, `/api/ledger/start`'s refusal, and their tests).

**Done when:** The design says Start session is drawn on every open entry's card whoever holds it, and what a press does while another session holds the entry, and its build is filed with `Part of:` this entry.
