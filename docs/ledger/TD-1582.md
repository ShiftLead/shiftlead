**Location:** src/shiftlead/cli.py (ao reply, ao inbox text, ao --skill); src/shiftlead/briefs/fact-checker.md; tests/test_briefs_layout.py; design §4.3 The untrusted-flags guard, §4.7, §4.9b The fact-check

**Why:** TD-1576's design (design §4.3 *The untrusted-flags guard*, §4.7 `ao reply`, §4.9b *The fact-check*): Gemini CLI 0.66.0 asks before any shell command carrying an option word that appeared in an earlier command's output, under yolo too and whatever a policy says, so ao-grind's Gemini fact-check seat stopped on every `ao msg --reply-to` (four prompts in five minutes, 2026-11-10). The design gives the seat's road positional forms, so nothing on it is an option the guard can stop on.

**Fix:** Build design §4.3 *The untrusted-flags guard* and §4.7's `ao reply` and `ao inbox` text:

- **`ao reply <id> '<text>'`** in `src/shiftlead/cli.py`: a subcommand of exactly two positional words, the entry's id and the text, sending exactly what `ao msg --reply-to <id> "<text>"` sends (the same `msg` RPC, kind `reply`, the addressee the entry's sender, its `about` kept), refused where that send is refused and printing what it prints, its *when it is read* lines included; `--json` as on any command. Words past the second are refused with the usage line (*unrecognized arguments*, `_parse`'s existing refusal for any command but `msg`) and nothing is sent; a text led by `-` goes after `--`. It takes no `--pick`, `--answer` or `--verdict`; a session's reply to an `ask` carrying `--pr`, which requires a `--verdict`, meets the home's own refusal (`agent_mail.py`, *a reply to PR #n's ask says what the read came to: --verdict …*), printed as `ao msg` prints it — `ao reply` reads nothing first. Share the code path with `cmd_msg`'s reply branch rather than copy it. Name it in `ao --skill`'s Mail section beside `--reply-to`, one clause: the reply with no option word, a brief's road.
- **`ao inbox` text** (`cmd_inbox`): print the PR an `ask` carries (*PR #n*, beside its `about`), and under an `ask` carrying `entry` the indented line *a request to file an entry: the home moves it to the techlead seat*, as design §4.7 says.
- **The fact-checker brief** (`src/shiftlead/briefs/fact-checker.md`), its road as design §4.3 lists it: *Read the waiting asks* with `ao inbox` (text, not `--json`), the `entry` case read from the line above; the not-a-fact-check reply and *The reply* with `ao reply <id> '…'`, the text one single-quoted argument holding no `'` (write `’`), never a heredoc or `$(…)`; the model line as `head -1 "$AGENT_MODEL_FILE"`, else `echo "$AGENT_MODEL"`; files named relative from the worktree; a search for an option's name written without its dashes (`git grep -n "reply-to" <sha>`); and *You change nothing* naming `ao inbox` and `ao reply` as its only `ao` (the Rules' `ao msg person "…"` on an identity mismatch stays: it carries no option word). Add one line saying why: a Gemini seat's tool stops on an option word, or an absolute path, it has seen in an earlier output, so keep to these forms. Keep the brief's other wording.
- **The check**: a test in `tests/test_briefs_layout.py` reading the whole built-in fact-checker brief and asserting that every backticked command in it that starts with `ao `, `git `, `gh `, `head ` or `echo ` carries no whitespace-separated word led by `-` other than `-1`, `-n` and a bare `--` (on the tool's safe list), and none led by `/`. Update any test asserting the brief's old `ao msg --reply-to` / `ao inbox --json` words (`grep -rn "reply-to\|inbox --json" tests/ | grep -i fact`).
- **Tests for `ao reply` and the inbox text** beside `ao msg`'s reply tests: it sends what `--reply-to` sends (same envelope fields); a session's reply to a `--pr` ask prints the home's `--verdict` refusal; it is refused as `--reply-to` is on an entry not in the caller's inbox; a third word is refused with nothing sent; and `ao inbox`'s text shows an ask's PR and its `entry` line.
- **One live run, by hand, recorded in the PR**: on a scratch home (`scripts/look_home.py`, design §4.9b), an unattended Gemini seat on the fact-checker brief under `permission_prompts: skip` answers one fact-check `ask` of a small doc PR end to end with no `needs-you` on its record, after reading a diff that names `--reply-to` and `--json`, its reply quoting an option word in a finding. Say in the PR body the seat's record states, the reply's id, and the Gemini CLI version. The automated live smoke is TD-1577's, never this build's.

Nothing in the Gemini adapter changes: the guard is the tool's, and no setting or policy lifts it (design §4.3).
