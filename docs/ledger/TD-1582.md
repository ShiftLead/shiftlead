**Why:** TD-1576's design (design §4.3 *The untrusted-flags guard*, §4.7 `ao reply`, §4.9b *The fact-check*): Gemini CLI 0.66.0 asks before any shell command carrying an option word that appeared in an earlier command's output, under yolo too and whatever a policy says, so ao-grind's Gemini fact-check seat stopped on every `ao msg --reply-to` (four prompts in five minutes, 2026-11-10). The design gives the seat's road positional forms, so nothing on it is an option the guard can stop on.

**Fix:** Build design §4.3 *The untrusted-flags guard* and §4.7's `ao reply` and `ao inbox` text:

- **`ao reply <id> '<text>'`** in `src/shiftlead/cli.py`: a subcommand of exactly two positional words, the entry's id and the text, sending exactly what `ao msg --reply-to <id> "<text>"` sends (the same `msg` RPC, kind `reply`, the addressee the entry's sender, its `about` kept), refused where that send is refused and printing what it prints, its *when it is read* lines included; `--json` as on any command. Its positional's dest is `reply_to`, never `id`: `_run` resolves a string `args.id` as a session name. Words past the second are refused with the usage line (*unrecognized arguments*, `_parse`'s existing refusal for any command but `msg`) and nothing is sent; a text led by `-` goes after `--`. It takes no `--pick`, `--answer` or `--verdict`; a session's reply to an `ask` carrying `--pr`, which requires a `--verdict`, meets the home's own refusal (`agent_mail.py`, *a reply to PR #n's ask says what the read came to: --verdict …*), printed as `ao msg` prints it — `ao reply` reads nothing first. Share the code path with `cmd_msg`'s reply branch rather than copy it. Name it in `ao --skill`'s Mail section (`src/shiftlead/skill.md`) beside `--reply-to`, one clause: the reply with no option word, a brief's road.
- **`ao inbox` text** (`cmd_inbox`), text mode only, for any `ask` carrying the field, open or closed: ` · PR #n` on the head line after the `about` and before the status; and *carries entry: a request to file a ledger entry, a techlead seat's to file* as the first indented line under the head, before the text (design §4.7).
- **The fact-checker brief** (`src/shiftlead/briefs/fact-checker.md`), its road as design §4.3 lists it:
  - *Read the waiting asks* with `ao inbox` (text, not `--json`); the `entry` case keyed on its *carries entry* line.
  - The not-a-fact-check reply and *The reply* with `ao reply <id> '…'` — the placeholder `<the ask's id>` becomes `<id>`, and the not-a-fact-check text's *team's* becomes *team’s*, so no `'` stands inside a span. The rule in the brief's words: the text is one single-quoted argument holding no `'` anywhere, code included (`’` where English wants one; code holding a `'` cited by file:line or written with `’`), never a heredoc or `$(…)`.
  - The model line keeps its words (*the first line of the file `$AGENT_MODEL_FILE` names, else `$AGENT_MODEL`, used unchanged*) and adds the commands in parentheses: `head -1 "$AGENT_MODEL_FILE"`, else `echo "$AGENT_MODEL"`.
  - A file at the head read only as `git show <sha>:<path>`; a search for an option's name written without its dashes (`git grep -n "reply-to" <sha>`).
  - The first paragraph's sentence *never end your turn to ask a person a question in the pane — mail it, then end the turn: you are woken when the answer lands, and a loop on `ao wait` or `ao inbox` is never how you wait* becomes: this seat asks nobody a question, in the pane or by mail — what it cannot settle is a `BLOCK` finding saying so — and a loop on `ao wait` or `ao inbox` is never how it waits.
  - The Rules' identity-mismatch line becomes `ao msg person '…'`.
  - *You change nothing* names `ao inbox` and `ao reply` as its only `ao` (with `ao msg person '…'` on an identity mismatch).
  - One line saying why: a Gemini seat's tool stops on an option word, or on a word led by `/`, `./`, `../` or a URL's scheme or ending in a script's suffix, that it has seen in an earlier output, so keep to these forms. Keep the brief's other wording.
