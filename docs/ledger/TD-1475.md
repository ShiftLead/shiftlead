**Priority:** Medium
**Type:** debt
**Added:** 2026-11-06
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 406baebc01d8438fbd36de5c96e2e914
**Part of:** TD-1443
**Location:** src/sessionorc/agent_tick.py (the stall check, screen_at, work_at); src/sessionorc/agent_common.py (STALL_AFTER); src/shiftlead/adapters/gemini, claude_code (volatile_rows); design §4.2, §4.3

**Why:** TD-1443's design, third build. `stalled?` (agent_tick.py, the check after the screen, gone and title branches) reads `last_output`, the pipe-pane log's mtime, which every spinner and elapsed-time repaint moves, and runs only when no earlier branch fired; Gemini's title `✦ Working…` sets `working` first. So `fact-check-ao-1` read *working* for a day and a half on one hung request.

**Fix:** Design §4.2 *Liveness cross-check*, §4.3 *An adapter names its volatile rows* (TD-1443).
- The adapter contract gains `volatile_rows` (not `hosts.yml`'s `volatile`) (src/shiftlead/adapters/*): row regexes or screen regions a spinner, a timer or a footer repaints. Gemini: its spinner line, the *still on it…* timer and its footer; Claude Code: its spinner line and status line. None named: nothing masked.
- The tick keeps per record `screen_at`: the last tick the captured pane's text changed with the volatile rows masked (a hash of the masked text, kept in memory and on the record), and `work_at`: the last hook event naming work (a tool use, a prompt, a stop — not a heartbeat or a notification).
- The stall check (agent_tick.py, now beside `STALL_AFTER`'s use) reads `max(screen_at, work_at)` instead of `last_output`, and neither clock runs while a tool call is open (a pre-tool hook seen without its post-tool hook) or a subagent is live (`subagent_at`, agent_common.py), and runs on every record the tick leaves `working`, whichever branch set it (a title verdict among them); a screen verdict naming another state still wins.
- §6's *Stall* policy (prompt, then wrap up; not built) is not part of this build.
- A tool call is open while the host agent's `_open_calls` (`_track_call`, agent_tick.py, TD-950; keyed by the adapter's per-call id, every thread) holds one for the record: a pre-tool event opens it, its post-tool event closes it, and — new in this build; `_track_call` clears today only on exit, a subagent's stop, `subagents_reset`, `subagent_stopped` (a TaskStop, TD-1277) or its own end — a stop, a session start or the adapter's prompt event clears them all (Claude Code: `tool_use_id`, `UserPromptSubmit`); an interrupted call fires neither its post-tool event nor a stop, and the next prompt clears it. Gemini's hooks carry no per-call id (`gemini/hook.py`'s `translate`), so for Gemini no call is open and only the masked screen and work events hold the clock. `_open_calls` is in memory (capped); `tool_open_at` on the record is the restart-safe half: after a restart it stands until a stop, a session start, the prompt event, the first post-tool event for the record (with parallel calls open before the restart the first one's end clears it, accepted) or `OPEN_TOOL_CEILING` clears it. `tool_open_at` (on the record, node-owned, so a restart keeps it) is the oldest open call's opening while any is open. It holds the clocks for at most `OPEN_TOOL_CEILING` (3 h, beside `STALL_AFTER`). A live subagent is a subagent hook within `stall_after`. The masked text's hash and `screen_at` are kept together on the record, node-owned as `subagent_at` is: a host-agent restart that finds the same hash keeps `screen_at`.
- `stalled_ticks` (on the record, node-owned): 0 when not `stalled?`, one more each host-agent tick while it is; TD-1473's `seat_able` reads it, so the stall test compares no clock across hosts; kept across a host-agent restart as `screen_at` is.

**Done when:** Tests: a Gemini pane whose only change for 21 minutes is its spinner and its *still on it…* timer, with its title `✦ Working…`, reads `stalled?`; one whose transcript rows change reads `working`; a work-naming hook event within the window keeps it `working`; a Claude Code Bash call silent for 25 minutes (a pre-tool hook with no post-tool hook yet) and a live subagent keep it `working`; an adapter naming no `volatile_rows` behaves as before for a static pane; a screen verdict of `limited` wins over the stall check.
A tool call open 25 minutes keeps it `working`, one open past `OPEN_TOOL_CEILING` with nothing new reads `stalled?`; two parallel calls, one closed, keep it `working` while the other is open; an interrupted call is cleared by the next prompt; a restart with the same masked text keeps `screen_at`. `stalled_ticks` counts 1, 2, … while `stalled?` and returns to 0 when the state leaves it. A restart keeps `stalled_ticks`; a restart with a call open 10 minutes still reads `working` at 25. A Gemini record running a long tool reads `working` or `stalled?` from the screen and work clocks alone, no call ever open in `_open_calls`.
