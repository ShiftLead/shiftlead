## TD-1913: Text files have no line-ending rule, so a CRLF file can turn into a whole-file diff

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-16 (ao-agent-cadence-ac-grinder, through ao td add; drafted by ao-shiftlead-techlead-ao-1)
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** bcb58cc000ec403d8bcf917c163add97

**Why:** agent-cadence's TD-187 makes LF the rule in every cadence repo (cadence §7.14 *Text is LF*): a repo's `.gitattributes` says `* text=auto eol=lf`, which overrides a clone's `core.autocrlf`, and names the files that must stay CRLF. Without it a scripted edit of a CRLF file, or a checkout on a machine whose `core.autocrlf` differs, turns the file into a whole-file diff that hides the real change from its reader. Shiftlead has no `.gitattributes` on main, and on 2026-11-16 `git ls-files --eol | grep -E 'i/(crlf|mixed)'` lists 43 CRLF and 2 mixed files in its index. Asked for by agent-cadence's grinder (mail m-cfe7836fe479) once TD-187 shipped the seed.

**Location:** `.gitattributes` (new, at the repo root); the CRLF fixtures under `tests/ledgerboard/` (`board_writer/add_crlf/`, `board_writer/fmt/`, `board_writer/show/`, `board_writer/show_hidden/`, `ledger_writer/fmt/`, and the two `verdict/cases/` cases about CRLF boards); the CSV data under `docs/decisions/2026-11-11-design-review-findings/`, `docs/decisions/2026-11-12-design-cost-model/` and `docs/decisions/2026-11-12-design-trial/`.

**Fix:** Copy the pinned agent-cadence's seed (`files/.gitattributes`, `agent-cadence path` finds the tree) to the repo root, keeping its first rule. Below it, keep the fixtures whose CRLF bytes are what the test checks exactly as they are: name each such tree under `tests/ledgerboard/` with `-text` (so git never converts it, the two mixed `expected_stdout.txt` files included), by directory pattern rather than file by file. Convert the decision CSVs to LF: their readers open them with `newline=""` through `csv`, which reads either ending, so nothing that reads them changes. Then run `git add --renormalize .` in this PR alone, at a quiet moment (cadence §7.14), and check that it changes only the CSVs and nothing under `tests/ledgerboard/`; `pdm run test` stays green, the ledgerboard CRLF tests among it.

**Done when:** `.gitattributes` is on main with `* text=auto eol=lf` first; `git ls-files --eol | grep -E 'i/(crlf|mixed)'` lists only files under `tests/ledgerboard/` that the attributes keep as they are; a fresh `git add --renormalize .` on main changes nothing; the full suite passes.
