**Why:** Part of TD-2129 (design §4.6 *Where a session's working files go*). Earlier sessions left files in `~/.cache`, `/var/tmp` and `~/ao-shots`. ShiftLead did not make those paths its own, so nothing removes them by rule: the person sees one list and answers.

**Ask:** Should the grinders build the design that gives each kind of session working file one cleaned place, or run one more review round first?

**Location:** docs/leftovers, design §4.6

**Fix:** On kmaster, read-only, list the direct children of `~/.cache`, `/var/tmp` and `~/ao-shots` owned by this uid. For each: its size; its newest write, the newest modification time under it by a walk bounded at 60 seconds an entry; whether it is a symlink (never followed); and, for a directory that is a git worktree or clone, its origin (or *none*), its branch, its uncommitted count (`git status --porcelain` lines) and its unpushed count (`git rev-list --count HEAD --not --remotes`). Every git call runs as `git --no-optional-locks`, and each entry's newest write is taken before any git call on it, so the listing writes nothing, a refreshed index included. Sort each into the first group it fits, a name shape being a prefix of the name:
- **Kept, by name:** a tool's own cache in `~/.cache`: `agent-cadence`, `claude`, `claude-cli-nodejs`, `copilot`, `dconf`, `evolution`, `event-sound-cache*`, `fontconfig`, `google-chrome-for-testing-headless`, `gstreamer-1.0`, `helm`, `huggingface`, `ibus`, `ibus-table`, `mesa_shader_cache`, `mesa_shader_cache_db`, `Microsoft`, `motd.legal-displayed`, `mozilla`, `ms-playwright`, `node-compile-cache`, `node-gyp`, `pdm`, `pip`, `pnpm`, `pyright-python`, `qdtools`, `samscrape-precheck`, `tracker3`, `ubuntu-report`, `update-manager-core`, `virtualenv`; `~/ao-shots/pwlib`; `/var/tmp/pc.*`.
- **Kept, by state:** anything written in the last 3 days or whose walk was cut short, held by a process (`/proc/<pid>/` cwd, root, exe, maps or fds; where `/proc` or a process of this uid cannot be read, every entry is held, as TD-2132's copies are), named by a current brief or memory (a literal `grep -rF` of its path, in both its `~/` and its `/home/<user>/` form, `/var/tmp/<name>` for that place, over `src/shiftlead/briefs/`, `docs/briefs/` and `docs/claude-memory/`; its bare name is never the test), a registered git worktree with an uncommitted count above zero or locked, or a symlink whose target lies in a live record's scratch.
- **Needs your word:** a registered worktree whose `HEAD` is detached and holds commits no branch or remote has (`git rev-list --count HEAD --not --branches --remotes` above zero), and a git clone that is not a registered worktree with an uncommitted or unpushed count above zero or a count that cannot be read (shown *unreadable*: an unborn `HEAD`, no remotes). A directory otherwise proposed is checked for a `.git` anywhere below it, by the same bounded walk, and such a nested tree is judged the same way, its directory going to this group where the tree has work or cannot be read, and kept by state where the tree meets a kept-by-state rule. Its commits live nowhere else, so it goes only where the person's note names it.
- **Proposed for removal:** in `~/.cache`, every loose file or symlink not kept, and a directory whose name starts `ao`, `aw`, `rv`, `rev`, `td`, `tl`, `inb`, `sent`, `tmp.`, `pct`, `dpr`, `pr`, `log`, or a letter and a digit (`g1`, `r10s`); in `/var/tmp` and `~/ao-shots`, every entry not kept, `~/ao-shots/scripts/` included, since the scripts there are one-off.
- **Unsure:** any other directory in `~/.cache`. It is kept, and counted.

A registered worktree on a branch with no uncommitted changes is not kept by state whatever its unpushed count, since its commits stay on its branch in its repo once the worktree goes, and is then sorted by its name as any other entry; the list says so beside it. The repository is public, so `docs/leftovers/TD-2146.md` holds the proposed and needs-your-word groups by name, each with its size, its newest write, *link* for a symlink (never its target), and for a git tree its branch (or *detached*, or *unborn*) and counts where its origin is a public repository, else by a key and its size alone, as *a git tree of another repo*, the key the first 12 hex digits of the SHA-256 of its absolute path, so its name names no private repo; the kept groups and the unsure are counts alone. The full list is the run's own working file and is not kept: the committed file is what the answer and TD-2147 read. A PR of `docs/leftovers/` alone runs the full precheck, which is accepted.
