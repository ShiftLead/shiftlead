**Kind:** build
**Status:** Open

**Part of:** TD-1577
**Location:** design §4.3 *The conformance suite* *The live smoke, unattended*; scripts/conformance.py

**Why:** TD-1577's design (§4.3 *The live smoke, unattended*): the live walk declares its profile with `permission_prompts: all` and answers each permission as the person, so it never runs a seat the way an unattended one is launched and could not have seen TD-1576's untrusted-flags prompt. The smoke runs the real tool as a seat is launched and passes only when a reply lands on its ask's thread with no `needs-you`.

**Fix:** Build §4.3 *The live smoke, unattended* as written: `--smoke` on `scripts/conformance.py`, keeping the walk's two homes and its refusals but one (never in CI, never without `--profile`, never on a profile with no `config_dir` or on the adapter's own default home, generalised from `scratch_profile`'s Claude Code-only check to each adapter's (Gemini CLI's `~/.gemini`); a `config_dir` shared with other profiles is not refused for the smoke, as `scratch_profile` refuses it for the walk) and differing from the walk in three things: `scratch_profile` keeps the live profile's own `permission_prompts` for the smoke (it forces `all` for the walk) and the launch is `unattended`; the seat's brief is composed by `teams._brief` for `--role` (default `fact-checker`), the role resolved from the `.shiftlead.yml` of a checkout the launch code takes as a parameter (the smoke passes its scratch clone; TD-1649's judge passes the checkout it starts in) over the built-in roles with no org overlay, its one seat member there, `{repo}` filled as a team start fills it, `{lane}` the member's, `flow` `None`, `{techlead}`, `{manager}` and `{context}` empty, handed as the create's first prompt — a role with no seat line, or more than one, refused unless `--brief <file>` is given, which replaces the role's template and is composed with the same slots; the ask is a plain `ao msg --kind ask`, never `--pr`. The seat is created with `name`, `adapter`, `profile`, `dir` the clone, `role`, `unattended` and the brief as its `prompt`, and no `seat`, `team`, `supervised`, `controllers` or `worktree`, in a scratch clone whose `origin` is a local bare repository with the same commits. Right after the create and before the first hook, one ask as the person (`ao msg --kind ask` from the scratch home, `SHIFTLEAD_SESSION` and every other session variable removed from the send's environment as the walk removes them), *reply to this ask with the token `<nonce>` and nothing else*, the nonce 12 hex digits from `secrets`, new each run; pass when any reply lands on that ask's thread (read from the scratch home's person inbox) within 10 minutes and the record never read `needs-you`, the output saying whether it carried the nonce, which no pass waits on; a record `exited` after the reply is no failure, one `exited` before it fails; fail at the first `needs-you` (pane captured with `capture-pane -e`, the record's `pending` printed) or at 10 minutes (the record's state); the last line *seat smoke: passed* or *seat smoke: failed — <step>: <what it read>*, with the tool's `--version` (*the seat smoke* in its output and help, never the promote's smoke of §6). However it ends, it kills the seat it started, stops the walk's host agent and removes its scratch homes and clone, unless `--keep` names them. The seat's launch, its ask and its reply read live in `scripts/seat_run.py`, beside `scripts/conformance.py`, imported by it and by TD-1649's `scripts/judge.py`. No tick runs it.

**Done when:** `pdm run conformance <adapter> --profile <p> --smoke` passes on a Claude Code seat profile, and run against Gemini CLI 0.66.0 with the fact-checker brief from before TD-1582 (`--brief` from `git show 405ccf10c:src/shiftlead/briefs/fact-checker.md`, or the brief at the last `origin/main` commit before TD-1582's merge; Gemini CLI 0.66.0 installed for the run, the fixtures having been read on 0.64.0) it fails at `needs-you` on the untrusted-flags prompt (TD-1576); both runs' last lines in the PR.
