## TD-1542: An item on a kept completed card draws no Start session: Do and Decide items about an archived entry show only Done

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-07 (Paul, through ao-led-tds-ledger; drafted by ao-shiftlead-techlead-ao-1)
**Owner:** designer
**Kind:** design-first
**Status:** Open — designing (rounds running): §4.5 screen 12 *Three verbs: An item on a kept card*, §4.5a *Queue card: Start session / Open session*; build TD-1618. Class: in-repo (one screen's control and its road, nothing outside this repo), cap 4 rounds.
**Id take:** 0155a7f914524d6086b8da0db5c77419
**Location:** design §4.5 screen 12 *Three verbs: Start session*, *Recently completed*; §4.5a *Queue card: Start session / Open session*; src/shiftlead/ui/queue.py (attach, put); src/shiftlead/ui/app.py (api_ledger_start)

**Why:** Since TD-1468, a Do or Decide item about an archived entry draws on that entry's completed card, kept in Recently completed (§4.5 screen 6 *Every item that needs the person draws on a card*). Design §4.5 screen 12 *Three verbs: Start session* puts Start session on every Decide and Do item but a red PR, a fork's PR, a stopped holder's row or a stuck row. The same paragraph also says "a completed card has no `start` and no button", and an item's Start session starts on the card's `start`. So an item on a kept card draws no Start session: only Done shows, and Answer… is in the ⋯. To redirect the work, the person must start a session by hand.

Seen 2026-11-07 by Paul through `ao-led-tds-ledger` (m-89f5d7001d44), on three Do items now drawn on kept cards: shiftlead#TD-1025, shiftlead#TD-1044 and agent-cadence#TD-219. Paul's rule (2026-10-26, quoted in screen 12): *being able to start a session should always be available on Do or Decide items*. The two rules were written before kept cards existed and now disagree.

**Design PR:** #3352

**Fix:** Design first (§4.5 screen 12 *Three verbs: Start session*, §4.5a *Queue card: Start session / Open session*): an item on a kept completed card draws Start session, on the item's own entry and on its repo's team. The design must also say what that session's prompt names as the entry, given that it is archived; the recommendation is the item and its archived entry, read as history. The header of a completed card keeps drawing no button. Then build it in `src/shiftlead/ui/queue.py` (`attach`, `put`, `start`) and `/api/ledger/start` in `src/shiftlead/ui/app.py`, which today read the card's `start`. Two places drop it: `item_start` (`queue.py`) returns nothing where the card's `start` is empty, and `card_mail` (`app.py`) builds its cards by id from the open cards alone, so a kept card's id is absent. The build changes both.

**Done when:** The design says it. Tests: a Do item and a Decide item on a kept card each draw Start session, posting `{repo, id, card, item}` for the item's entry on that repo's team. The completed card's header draws none. A plain completed line is unchanged.
