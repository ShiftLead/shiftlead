## TD-2080: Temporary files keep exhausting the machine's shared temporary disk and stopping every session

**Priority:** High
**Type:** debt
**Added:** 2026-11-22 (Paul, through Add entry; drafted by the inodes session)
**Owner:** designer
**Kind:** design-first
**Status:** Open
**Id take:** 836829581a81449fb9a003c8bd63d991

**Why:** kmaster's `/tmp` is one 16 GB tmpfs of 1,048,576 inodes shared by every session on the machine. When its inodes run out, no command starts in any session of any repo, with bytes still free. It ran out on 2026-10-26 (TD-1053), 2026-11-15 (TD-1890) and 2026-11-20 (TD-2028), reached 89% on 2026-11-04 (TD-1384), and failed prechecks on 2026-11-19 (TD-1974's log). Paul, 2026-11-22: a couple of sessions have had to clean up, and we want a lasting solution.

Each past fix closed one leak (TD-1053, TD-1384, TD-1890, TD-2015, TD-2028, TD-2032), and the next leak found the same shared pool. Four things stay true after all of them:

- **One pool, shared fate.** Every seat's scratch is under `/tmp/shiftlead-1000/` (`scratch_root`'s default), so one seat's test runs can stop every other session, including the person's own.
- **Nothing reacts to pressure.** The disk sweep runs hourly and goes by age and state (an ended record's scratch after `scratch_keep_hours`, an unowned one an hour after its last write). It never takes a live seat's scratch or git work, and nothing in it reacts to free space. One suite run leaves tens of thousands of inodes (pytest's current run held about 51,000 when read), so several seats can fill the pool between passes.
- **Nobody is told.** The low-inode warning is drawn only in `ao disk`, at under a tenth free, which leaves little time and reaches nobody who is not already looking.
- **Much of it has no owner.** The sweep by design leaves everything outside `shiftlead-<uid>/`.

Read on 2026-11-22 at 36% (377,032 inodes): 165,740 in seats' scratch, 88,996 in `/tmp/claude-1000` (still written to that day, though ShiftLead's own seats moved off it), 50,983 in `/tmp/pytest-of-kmaster`, and 57,397 in 661 other top-level directories more than two days old, such as review clones at `/tmp/rv` and `/tmp/r4047`. `systemd-tmpfiles` removes only what is ten days idle. The root disk, by contrast, had 5.1M inodes and 34 GB free.

**Ask:** Should the grinders build the design that gives unattended seats their own temporary space and clears it before it fills?

**Context:** Temporary files have repeatedly filled the disk every session shares. This design moves unattended seats to a pool of their own, clears what can be rebuilt when it runs low, and warns you before it is full. Its review rounds ended with nothing left that changes the builds.

**Design PR:** #4357

**Location:** `src/sessionorc/scratch.py`, `src/sessionorc/agent_tick.py` (the hourly sweep), `src/sessionorc/diskbook.py` (the warning), `src/sessionorc/hosts.py` (`scratch_root`), `tests/conftest.py`, design §4.6 *A session's scratch* and *The disk sweep*

**Fix:** Design this as one mechanism rather than a seventh leak fix, in §4.6 *A session's scratch* and *The disk sweep*. The design round settles each of these, measuring before it chooses:

1. **Separate the pools.** Stop seats' scratch and test runs from sharing the pool the machine and the person's sessions depend on: a dedicated mount for `scratch_root`, a disk-backed root, or a per-seat limit. Weigh test speed and disk wear on the root disk, which is 78% full, and the 48-byte path limit.
2. **React to pressure.** Run a reclaim pass as soon as inodes cross a threshold, not at the next hourly pass, taking what is safely rebuildable first (dead test runs, build leftovers), with the sweep's existing protection of git work unchanged.
3. **Tell someone early.** Raise a board item or notification while there is still time to act, naming the largest holders, once per episode.
4. **Cover what has no owner.** Decide what happens to `/tmp/claude-<uid>`, bare `/tmp` review clones and other top-level leftovers: find who still writes them and move those writers to their scratch, and say what may be removed and when.
5. **Consider more headroom.** Raising `nr_inodes` on `tmp.mount` is a cheap machine change that is the person's to make. It buys time and is no fix alone.

A change to the machine's mounts goes to the person as a board item. ShiftLead runs on other people's hosts too, so the design must also hold where `/tmp` is not a tmpfs.

**Done when:** In tests with the free-space reading stubbed (this machine allows no unprivileged mount), a reclaim starts without waiting for the hourly sweep and removes dead and finished test runs while keeping git work, and one warning reaches the person before the pool is full. With `seat_root` set, a seat started unattended has its temporary files under it and a person's session does not. On kmaster, which runs with no `seat_root` so that it meets what a default install meets (Paul, 2026-11-23), no session needs a manual temporary-space cleanup for 30 days after the builds are live.
