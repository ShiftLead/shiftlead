**Location:** src/sessionorc/agent_inbox.py (_reread_board, _answer_orphan_one, rpc_board_edit, rpc_ledger_decide, _ledger_road); src/sessionorc/agent_sync.py; src/sessionorc/agent_rank.py; src/sessionorc/queue.py; src/shiftlead/ui/inbox.py, src/shiftlead/ui/queue.py; design §4.4 Every write the home lands is read at once, The card's status

**Why:** Build TD-1471, slice 2 of 3 (design §4.4 *Every write the home lands is read at once*, *The card's status*; §4.5 screen 6). Only board presses re-read at once today: an orphaned question's answer (`_answer_orphan_one`) and a sync merge re-read nothing, and between a press and its landing (a fetch, a commit, a PR, a merge: seconds) every view shows the state the person just answered — *needs you* after the answer (TD-1364, TD-1368), an old answer on the line.

**Fix:** - **Every landed write re-reads at once** (`src/sessionorc/agent_inbox.py` `_reread_board`, which TD-1507 made read the ledger with the board): call it after an orphaned question's answer lands (`_answer_orphan_one`, after `board.add`) as the presses already do. A merge the home makes outside its board tree — a sync merge (`agent_sync.py` `_sync_merge_in`, once `sync.merge` lands) — re-reads with a fetch first (`_reread_board(root, fetch=True)`: a fetch of the default branch with the explicit refspec, then the board read from origin rather than the tree, whose head is as old as its last press), never the tree as it stood. A rank landing (`agent_rank.py` `_rank_flush`, after `board.land_rank`) re-reads the same way as a press (it landed in the tree). The design's table (§4.4 *Every write the home lands is read at once*) is the list: each row with *a PR the home merges* re-reads at once; a gate sweep's open PRs do not.
- **The `applying` mark**, kept apart from the reading: `self._applying` `{root: {board_key: {act, answer, at}}}` in memory, never in `self._repos` nor saved by `repos_store`. `rpc_board_edit`, `rpc_board_reply`, `rpc_ledger_decide`, `_ledger_road` and `_answer_orphan_one` set the press's mark (for a ledger decide or road, keyed by its entry: `ledger:<repo>#TD-n`, read on the entry's member) and push `repos` before the write-back starts; `_reread_board` clears it with the re-read; a failed write-back clears it and pushes `repos` again before raising its error. `_repo_view` and the Queue's pass (`_queue_pass`, `sessionorc.queue`) lay the marks over the board items and the entry rows they build from, so a tick's read in the meantime keeps the mark (it is not in the reading the tick replaces), and a restart starts with none.
- **The views**: the Inbox row (`src/shiftlead/ui/inbox.py`) and the Queue member line (`src/sessionorc/queue.py`, `src/shiftlead/ui/queue.py`) read `applying`: *answered — applying* for `act: decide`, *applying <act>* for the rest, in the place *answered — waiting on <asker>* takes (design §4.4 *The Queue*'s member order), and a member under a mark is no need (*The card's status*: no *needs you*, no amber, not counted).
- Tests:
  - A decide press on a `decision (paul)` member: before the write-back returns (a write-back stub that blocks), the `repos` push carries the mark, the card reads *answered — applying* with no *needs you*, the counts drop it, and a tick's read in that window keeps it; after it lands, the lifted entry and no mark.
  - A write-back that fails: the mark is gone, the row as before, the press's error returned.
  - An orphaned question's answer, the checkout stale: the new board line is in the next `repos` push.
  - A sync merge, the board tree last reset before an unrelated merge: the re-read reads origin's new head, never the tree's older one (no regression of board or ledger).
  - A restart mid-press: no mark after it; `repos_store`'s saved reading never carries one.

**Done when:** Every write the home lands on origin (design §4.4's table) re-reads board and ledger at once, and a press's row reads *answered — applying* (or *applying <act>*) from the press to its landing, never *needs you*; tests pin each view against a just-landed write with a stale checkout.
