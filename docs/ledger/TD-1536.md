**Why:** TD-1527's design (§4.5 screen 6 *A design links its synopsis*; §4.5a *Queue card: what needs the person* and *Queue page: card*): the person judges a design from its plain-words synopsis, `docs/synopses/TD-<design>.md`, and the Queue card and the Inbox must link it — through the person's editor link, with GitHub beside it for the phone.

**Fix:** Build §4.5 screen 6 *A design links its synopsis* and the two §4.5a sentences, on top of TD-1531's design-PR link (this build reuses its resolution: the item's entry or its one-hop `Part of` parent, and whether the link was read from the entry's open design PR or from its `Design PR:` section):
- **Existence and copy.** For the entry the design link resolved to, the synopsis path is `docs/synopses/TD-<design>.md` in that entry's repo. Its ref is the open design PR's `head` where the link came from the open PR, else `origin/<default>`; it is drawn only where `git cat-file -e <ref>:<path>` succeeds in the repo's checkout on the repos registry's host, the answer cached per (ref sha, path) so a commit is asked once (a head not in the checkout's objects reads as absent).
- **The editor target.** Before the merge: the worktree whose branch is the PR's `branch`, from `git worktree list --porcelain` in the repo's checkout, read once per repo reading beside `prs.open` (in the repo reading, `src/sessionorc/`, a held path), and the file on that worktree's disk; after it, the file in the repo's main checkout, on disk. The link is `editor_file_link(path)` (`src/shiftlead/ui/common.py`), drawn by the `file_link` macro, so its folder first is `checkout_of`'s — never a hand-built `vscode://` URL. No editor link under `open_in: none` or where the file is not on that disk.
- **The GitHub link.** `<base>/blob/<branch>/docs/synopses/TD-<design>.md`, `<base>` derived from `review.pr_url` on the entry's repo's root (as *· design #n*'s link is), `<branch>` the PR's `branch` before the merge and the default branch after. With no editor link, *synopsis* itself carries this URL and no *GitHub* word is drawn; with no base and no editor link, nothing is drawn.
- **Drawing.** An item about a design (mail by `about`, board line by `Context:`, a `decision (…)` entry's own held row) ends its first line ` · design #n · synopsis · GitHub` on its Queue card and its Inbox row (`inbox_row.html`'s `head`, `board` and `ledger` macros; `queue_row.html` / `queue_card.html`), only where it draws *· design #n*. A design entry's own line on the Queue — the card header's title where it is the top entry, its row under another — ends its title with `synopsis · GitHub`, by its own id alone (its own section or open design PR, never its parent's), so a build's row draws none.
- **Tests:** a steer about TD-n whose section reads `#12`, with the file on `origin/<default>`, draws `· design #12 · synopsis · GitHub` on its card and Inbox row, *synopsis* a `data-file-link`; with the file absent from origin it draws `· design #12` alone; with an open *TD-n design: …* PR whose head holds the file and a worktree on its branch, *synopsis* opens the worktree's file and *GitHub* the PR branch's blob; with no worktree on that branch *synopsis* links GitHub and no *GitHub* word is drawn; under `open_in: none` the same; an item about a round entry `Part of` TD-n draws TD-n's synopsis; a build's row under a design draws none; the design entry's own card header draws `synopsis · GitHub`; the cat-file answer is asked once per (sha, path) across two reads.

**Done when:** An item about a design whose synopsis file exists at the design link's ref draws `· synopsis` (the person's editor file link) and `· GitHub` (the forge blob) after `· design #n` on its Queue card and Inbox row, and the design entry's own Queue line ends its title with them; *synopsis* links GitHub where there is no editor link; the tests pass.
