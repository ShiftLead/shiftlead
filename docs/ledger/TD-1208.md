## TD-1208: `seams.descends` reads only the roster's first dev-cadence clone, and `OLDEST`/`OLDEST_V2` are private commits: once dev-cadence cuts over to agent-cadence's orphan history, no pin's age reads

**Priority:** High
**Type:** debt
**Added:** 2026-10-28 (dc-tds, through `ao td add --repo`; drafted by techlead-ao-1)
**Owner:** grinder
**Kind:** build
**Status:** Open. Slice 1 is pickable now and must merge before `~/agent-cadence` joins the roster (dev-cadence TD-191 step 6.3). Slice 2 waits for agent-cadence's seed commit.
**Location:** `src/sessionorc/seams.py` (`descends`, `age`), `src/sessionorc/cadence.py` (`OLDEST`, `OLDEST_V2`), `src/sessionorc/agent_ids.py` (the v2 refusal, ~590); `tests/` for `seams.age`; design §5 *The seams* → *Which dev-cadence*

**Why:** dev-cadence is cutting over to `ShiftLead/agent-cadence`, a new repo whose history is one snapshot commit with no parents, so it shares no commits with `ShiftLead/dev-cadence` (dev-cadence `docs/plans/2026-10-26-public-scrub.md`, *Amendment 2026-10-28*, decided by Paul; its step list names this PR). After the cutover the roster holds two source clones: `~/dev-cadence`, which keeps the old commits, and `~/agent-cadence`. `descends` reads ancestry in `next(...)`, the first clone `cadence.is_source` accepts, so a pin's age is read in whichever clone comes first. If `~/agent-cadence` comes first, it holds neither a pin's old `ref` nor `OLDEST` (`6d92209`) and `OLDEST_V2` (`b9236c8`), which are private dev-cadence commits. `merge-base --is-ancestor` then exits neither 0 nor 1, so every un-moved pin's age falls to the forge's compare on its own `source` (dev-cadence), which answers only while `gh` reaches that repo, now to be archived. A pin already moved to agent-cadence is worse: no clone holds both it and `OLDEST`, and agent-cadence's forge holds no `OLDEST`, so its age reads as unknown every time, and that repo shows the warning *dev-cadence's age not read*. More seriously, the age check (§5 *Which dev-cadence*) stops guarding anything once pins move, because no moved pin can be measured against the oldest commit this build reads.

**Fix:** two slices.
1. `descends` tries every source clone on the roster in turn and answers from the first that holds both commits (`merge-base --is-ancestor` exit 0 or 1). It goes to the forge only when none holds them, and then on the pin's own `source`. Tests: a fixture roster with two source clones, neither listed first by luck, where one holds the commits and the other is an orphan history; with each clone first, an old-history pin is read correctly.
2. Once agent-cadence's seed commit exists, it becomes a second known oldest point: a pin is at or after `OLDEST` (or `OLDEST_V2`) if it descends from that commit **or** from the seed, since the seed carries a tree newer than both. Add it to `cadence.py` beside `OLDEST`/`OLDEST_V2`, with the commit and where it came from. `age`'s cached `old` keys on it too. Tests: a pin on the orphan history descends; one on neither history does not.

§5 *Which dev-cadence* changes in the slice that changes each behaviour: ancestry is read in each of the roster's dev-cadence checkouts, and the oldest point is either history's commit.

**Done when:** with `~/dev-cadence` and `~/agent-cadence` both on the roster, in either order, `ao doctor` and the seams read a real age for a pin on either history. `pdm run test` passes.

**Related:** TD-1012 (`OLDEST`), TD-1144 (`OLDEST_V2`), TD-1014 (the pin read as a lock); dev-cadence#TD-191 (the cutover, whose step 6.3 this must precede)
