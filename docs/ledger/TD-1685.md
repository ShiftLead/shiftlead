## TD-1685: An unattended Claude Code launch stopped at the Bypass Permissions dialog reads working, never needs-you

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-11
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 5f9e5399f0bb4705b246fa02d8bcdf62
**Location:** src/shiftlead/adapters/claude_code/ (its screen rules); tests/conformance/fixtures/claude-code/

**Why:** The seat smoke (TD-1648) launched Claude Code 2.1.322 unattended under `permission_prompts: skip` on the `conformance` profile (`~/.claude-conformance`), whose home had never accepted `--dangerously-skip-permissions`: the tool stopped at its one-time *WARNING: Claude Code running in Bypass Permissions mode — No, exit / Yes, I accept* dialog before any hook, and the record read `working` for ten minutes, never `needs-you`, and the host agent logged *the brief … was not sent: no hook since its launch*. An unattended seat or member on a fresh profile home would sit the same way, its card saying it works while it waits on a person.

**Fix:** Add a screen rule to the Claude Code adapter's manifest that reads the Bypass Permissions acceptance dialog as `needs-you` (a `question` pending naming the dialog), with a captured pane as its fixture (the seat smoke's `capture-pane -e` output in TD-1648's PR #3495 has one), so the card and the smoke see it at once. Never answer it: accepting it is the person's (it writes the tool's own settings).

**Done when:** A launch stopped at the dialog reads `needs-you` by screen within the stall window, held by an offline fixture test; the seat smoke on a profile home that never accepted it fails at `needs-you`.
