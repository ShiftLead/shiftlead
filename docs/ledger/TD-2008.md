**Why:** PR #4194 (TD-1946 slice 2, `_prune_rules` in src/sessionorc/agent_tick.py) promises in its docstring that a dry run "removes and touches nothing", each removal going through `_Removal`. Only tests/test_disk_reading.py exercises `dry`, and its integration test sets `runs_keep_days: 0` and holds only an old run log and a stale scratch directory. Mutation probes, each changing one `if rm.unlink(f):` to `(f.unlink() or False)` and each run with `PYTHONPATH=$PWD/src pdm run pytest -q tests/test_disk_reading.py tests/test_disk_sweep.py tests/test_disk_book.py`, left the run exactly as at baseline (one environment failure, `test_every_adapter_s_transcripts_outlive_a_sweep_through_its_roots_and_symlinks`, fails with and without the change): the upload `.part` rule, the run-log age rule, the promote-log age rule and the attachment age rule. Replacing `rm.rmdir(folder)` with `folder.rmdir()` also leaves the run unchanged. A dry run that deletes a stale upload part, an old promote log or an old attachment would pass the suite.

**Location:** tests/test_disk_reading.py

**Fix:** Add a dry-run test with `runs_keep_days` above zero holding an old upload `.part`, an old run log, an old promote log and an old attachment (with its folder), that checks each is listed in `would_remove` and still on disk.

**Done when:** Each of the five mutations listed in Why makes a test in tests/test_disk_reading.py fail.
