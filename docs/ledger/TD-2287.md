## TD-2287: A forgotten login named default still resolves to the tool's own home

**Priority:** Low
**Type:** debt
**Added:** 2026-11-26
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 80874266617e467ca3f2a58565a3c40c
**Part of:** TD-2280

**Why:** §4.9e *A record's `profile`* says a forgotten login's records resolve to no login, and a launch, resume or relaunch on its name is refused as unknown (TD-2280). That holds for every name but `default`: on a host with no `profiles.yml`, `profiles.load` returns `{"default": Profile(name="default"), **kept}` (`src/shiftlead/profiles.py`, `load`), so a forgotten `claude-code:default` still resolves to the placeholder, the tool's own home with no `config_dir` — its records read that folder, which may not be the login's, and usage and the gate see a live `default` account (found by TD-2280's round 1 Fable review, F5 in `docs/reviews/TD-2280.md`). `default` is a valid login name, and the switch-over's `--answers` suggests for a login the first profile's name on its folder (§4.9e), which is `default` on a home that ran on the implicit profile. Nothing tests that a forgotten name is unknown to the profile reader either (F10).

**Location:** src/shiftlead/profiles.py; tests/

**Fix:** In `profiles.load`, add the placeholder `default` — at either site, no `profiles.yml` or one that declares no profile — only where no login of any tool, live or forgotten, holds the name `default` (a name is unique on its host across tools, so a forgotten `gemini:default` withholds it too) (read `logins.yml`'s `forgotten:` beside `_from_logins`); a record with no `profile` then resolves as a record named `default` does: the live login of that name, the placeholder, or unknown where it is forgotten. Where the placeholder is withheld, `load` still returns `"default"` as the default name, and its checks that the declared default is a profile (and its `next(iter(out))` over an empty `out`) are not run where `out` held no declared profile and `profiles.yml` names no `default:` (an explicit `default:` naming an undeclared profile still raises, as today), so every other reader of `load()` — usage, the gate, `for_adapter` — reads on; only `get(None)` refuses. A reader with `with_logins=False` (the switch-over's, the Settings page's profile cards) reads no `forgotten:` and always gets the placeholder. There, `get(None)` (a launch with no profile) refuses *`default` is a forgotten login's name: add its folder again, or name a login* in place of *unknown profile 'default'; known: […]*. Add tests (tests/test_profiles.py or the logins tests): a forgotten login, `default` among them and at both placeholder sites, raises `KeyError` from `profiles.get`, gives `None` from `account_of`, and is absent from `for_adapter`; a launch with no profile gets the refusal above; a host with no logins and no `profiles.yml` still gets the placeholder; a forgotten `gemini:default` withholds the claude-code placeholder; a `profiles.yml` that declares no profile, beside a forgotten `default`, `load`s without raising. Design: §4.9e, in *A record's `profile`*, its *forgotten login's records* item.

**Done when:** On a switched host, a forgotten login named `default` is unknown to `get`, `account_of` and `for_adapter` as any forgotten name is, the placeholder stands only where no login holds `default`, and the tests above pass.
