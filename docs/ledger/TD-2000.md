## TD-2000: A test's child agent can outlast its five-second stop and fail the precheck

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-19
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 65af90d94e6243ea95479aa1a1e3e028

**Why:** The precheck of PR #4178 (a ledger-only PR, its docs command `pdm run test-docs`) ended `845 passed, 1 error` twice running, on the same test, and recorded cadence/precheck = failure both times: `ERROR tests/test_help.py::test_the_help_page_carries_every_paragraph_once` at teardown, `RuntimeError: child agent ignored SIGTERM` from tests/conftest.py:525. The child agent logged its startup and the store backup and then did not exit within the fixture's 5-second `proc.communicate(timeout=5)` after `send_signal(SIGTERM)`. The same module alone passes (`pdm run pytest -q tests/test_help.py`, twice, 5 passed), so the failure shows only under the parallel run: a fixed wall-clock bound in the teardown that a loaded run exceeds. It blocks every PR's gate while it lasts.

**Location:** tests/conftest.py

**Fix:** In tests/conftest.py's child-agent fixture, wait for the process to exit with a condition and a longer bound (or find why the agent is slow to leave on SIGTERM under load, e.g. a backup thread holding shutdown), so a loaded run does not turn a slow exit into an error.

**Done when:** Three consecutive precheck runs of a ledger-only PR show no teardown error from the child-agent fixture.
