**Why:** Build TD-1437, slice 1 of 3 (design §6 *Promote*, *The live ref*; §4.4 the event runner). A check run against the forge cannot see what the home runs: the live commit is only `promotes.<repo>.live` on the home. This slice gives the forge a ref to read, and sweeps a repo's gates soon after it moves.

**Ask:** Go with TD-1450, a build of TD-1437's design, once TD-1437's end-of-rounds item is answered Go? Answered on the board's decide item for TD-1450 (Go | Not yet), beside TD-1437's own.

**Fix:** - **The tag** (`src/sessionorc/promote.py`, `src/sessionorc/agent_promote.py`): for each repo with a `promote:` block, when the pass that reads **live** (a full one or an in-flight watch, `survey`) finds it at a commit that `origin/main` holds and that differs from the stored `live_ref` (or none is stored) — a promote or a rollback concluding, or a hand-installed copy `check` reads — push it once per such commit (compared with `live_ref`, never the previous in-memory reading, so the first pass after the restart a shiftlead promote causes still pushes), off the loop, from the registered checkout: `git push --force-with-lease=refs/tags/promote/live:<lease> origin <live>:refs/tags/promote/live`. It is a tag, not a branch.
  - The lease is **`promotes.<repo>.live_ref`**, the sha the home last pushed, written to `~/.shiftlead/promotes/<repo>/live_ref` after each landed push and read from there at the home's start, since a promote of shiftlead restarts the home (`_promotes` is in memory only).
  - The home pushes only with a stored lease, or onto an absent tag. With none stored, it reads `git ls-remote origin refs/tags/promote/live refs/heads/promote/live`: no tag, it pushes (empty lease); a tag already at the live sha, it adopts it as the lease (a push that landed before its lease was stored) and pushes nothing; any other tag, or a branch of that name (which may shadow the tag), is someone else's.
  - A push refused for its lease re-reads with the same two-ref `ls-remote` as the no-lease read: a tag already at the live sha is adopted as the lease, with no note; no tag (and no branch) clears the lease with no note, and the next pass pushes onto the absent tag. Otherwise a refusal, or a tag or branch found that is someone else's, clears the stored lease and sends the person one `system` note (`_system_note(PERSON, …)`, as the *promoted* notes go), once per sha the tag or branch was found at, its text as §6 *The live ref* writes it. Nothing is pushed until the tag is absent. No board edit: the home writes boards only by PR.
  - Any other failure is logged and retried on the next full pass. A live that is *unknown*, or not on `origin/main`, pushes nothing.
- **The sweep after it** (`src/sessionorc/agent_tick.py` `_sweep_pass`, near :1645, with `gatesweep.due()`): a push that lands clears that repo's `_swept_on[root]`, so `due()` sweeps it on the next tick. While that repo's sweep is running (`_swept_on` is set before it runs), the push instead adds the root to a set `_resweep` beside `_swept_on`, read when that run ends, which clears `_swept_on[root]` then.
- **The lift PR is a work order** (§4.4 *A live check's lift PR is the team's at once*; `src/sessionorc/workorders.py`): `is_lift_order` beside `is_sync_order`. An open PR whose head is `lift/TD-<n>/<name>` (what `gatesweep.lift_branch` gives a gate: `event (live)` → `lift/TD-n/live`), `<name>` matching `live`, `live-[0-9]+` or `live-td[0-9]+`, not a draft and not a fork, is an order from its first reading whatever its checks but red (a red one is an order already), stamped `lift_since` at that reading as a sync PR is stamped `sync_since` (`red_prs` skips a PR with neither), and, as a sync, not an order while a live record holds it: title the PR's, priority its entry's, `Context` the PR's URL and the gate, page kind *pickable*, the grinders' pick list. No `green` test: a fresh lift PR's precheck is pending until its taker runs it.
- Tests:
  - A concluding promote pushes the tag once; an unchanged reading pushes nothing.
  - The lease is `live_ref`. An absent tag is pushed. A present tag with no lease, at another sha, sends the one `system` note and pushes nothing, once per found sha. A refused push clears the lease and sends the note once per found sha.
  - A failed push is retried on the next full pass.
  - An *unknown* live, a commit off `origin/main`, and a repo with no `promote:` block push nothing.
  - A landed push makes the repo due on the next tick, also while its sweep runs.
  - A `lift/TD-n/live` PR (and `live-2`, `live-td5`) is a `pr:` order from its first reading, pending or `not_run` included; `lift/TD-n/livefoo` and a draft are not.
  - A tag already at the live sha with no lease is adopted, not reported; a branch `promote/live` is reported.
  - The lease survives a restart of the home between two pushes: no report, the second push lands.
  - A push that landed before its lease was written (the stored lease older) is refused, finds the tag at live, adopts it, and sends no note.

**Done when:** The home keeps `promote/live` on each promoted repo's origin at the live commit, moved once per change, and sweeps that repo's gates on the next tick. Tests cover each case above.
