**Why:** Build TD-1437, slice 1 of 3 (design §6 *Promote*, *The live ref*; §4.4 the event runner). A check run against the forge cannot see what the home runs: the live commit is only `promotes.<repo>.live` on the home. This slice gives the forge a ref to read, and sweeps a repo's gates soon after it moves.

**Fix:** - **The tag** (`src/sessionorc/promote.py`, `src/sessionorc/agent_promote.py`), for each repo with a `promote:` block, as §6 *The live ref* writes it:
  - **The read.** Each full pass that reads **live** at a commit `origin/main` holds (a hand-installed copy `check` reads among them) with no promote or rollback of the repo in flight (`promote.inflight(repo)` is `None`), and the in-flight watch pass (`survey`) that finds one concluding there (a smoke that fails concludes nothing: `_smoke_failed` starts its rollback, which is then in flight, and the pass that concludes the rollback reads), runs one `git ls-remote --refs origin refs/tags/promote/live refs/heads/promote/live` from the registered checkout, off the loop. A live that is *unknown*, or not on `origin/main`, reads and pushes nothing; so does a full pass while a run is in flight, its smoke included (`phase: smoke`), though `check` already reads the new commit: a tag at a build whose smoke then fails would lift a gate no rollback puts back. So too while the repo's failure stands (`failed.json`, `promote.failed(repo)`: a run that did not conclude, or a failed smoke that rolls nothing back — a rollback's own, no `from`, or `from` the commit itself), though `check` may read a commit of `origin/main` as live: the failed build is never tagged, nor a rollback whose own smoke failed. The failure is read as the pass leaves it, after any conclusion the pass makes (`survey` clears `failed` on `_conclude`'s note): a rollback's concluding watch pass reads — and before any start the same pass makes (`survey` starting the next `auto` run after `_conclude`), so the concluded build is read. Dismiss (`ao promote clear`, the row's press; `agent_promote.rpc_clear_promote`) moves the failure's `sha` into `~/.shiftlead/promotes/<repo>/untagged` when it clears `failed`, never when it clears `held`, and only when that `sha` is live as `check` reads it at the press (`promote.read_live(root, check)`, off the loop, never the cached `self._promotes[name]["live"]`, which is empty after a restart and stale while `live_why` is set), an *unknown* or absent answer counted as live (fail closed); a failure at a sha that is not live writes nothing and leaves a standing file as it is. It holds `_promote_lock` across both writes and writes `untagged` before it clears `failed`, so no pass reads between them: a full pass whose live is that sha reads and pushes nothing, and the first pass that reads with another live commit deletes the file and reads, one that reads nothing keeping it (§6 *The home reads the tag before it acts*). The sha compared is the ref's own object as `ls-remote` prints it (an annotated tag's is its tag object's, so it never reads as at live; `--refs` leaves out its peeled `^{}` line). A read that fails (`promote._git` answering `None`: no answer, refused, timed out) is no reading: no push, the lease and the noted lines kept, logged, read again on the next full pass; only an answered read finds a ref absent.
  - **The action, by what it finds**: a branch `promote/live` (it may shadow the tag): keep the lease, push nothing, and send the person the branch note (*delete the branch*, `git push origin :refs/heads/promote/live`, as §6 writes it), the tag's noted line neither read nor cleared while the branch stands; otherwise the tag at the live sha, adopt it as the lease if the lease differs, push nothing; no tag, push onto the absent tag (empty lease); the tag at the stored lease, the lease not the live sha, push with the lease; the tag anywhere else (at another sha with no lease, or at neither lease nor live) is someone else's: clear the stored lease, push nothing, and send the tag note (its text as §6 writes it). Each note goes through `_system_note(PERSON, …)`, as the *promoted* notes go, once per ref and sha it was found at. No board edit: the home writes boards only by PR.
  - **The push**: `git push --force-with-lease=refs/tags/promote/live:<lease> origin <live>:refs/tags/promote/live`. It is a tag, not a branch. A push refused for its lease changes nothing (the next read acts on what is there); any other failure is logged and retried on the next full pass.
  - **What is stored**: the lease **`promotes.<repo>.live_ref`**, the sha last pushed or adopted, in `~/.shiftlead/promotes/<repo>/live_ref` after each landed push or adoption; `untagged` beside it (a sha, in no reading or `ao promote status`), written by Dismiss of a failure whose sha is live as read at the press (unknown counted as live) and deleted by the first pass that reads with another live commit; and each ref's last note in `live_ref_noted` beside it: at most two lines, one per ref, ref and sha (`refs/heads/promote/live <sha>`, `refs/tags/promote/live <sha>`), a new note of a ref replacing that ref's line alone, so a branch note never suppresses a tag note and a tag noted before a branch came and went is not noted again; a ref's line is cleared by any read that does not find that ref at its noted sha (the branch gone, the tag absent or elsewhere), and the tag's line by a landed push; a pass that reads nothing (a run in flight, a failed read, a live *unknown* or off `origin/main`, a failure standing, live at the `untagged` sha) keeps both, so a ref removed and put back at its noted sha within it is not noted again. Both are read from their files at every read, never held in memory from the home's start: the press's and the rollback's own `survey([root], {}, True, …)` (`agent_promote.py`) carry no earlier reading, and a promote of shiftlead restarts the home (`_promotes` is in memory only); the reading's `live_ref` is a copy for `ao promote status` (its `--json`'s `promotes.<repo>.live_ref`, §4.7).
- **The sweep after it** (`src/sessionorc/agent_tick.py` `_sweep_pass`, near :1663, with `gatesweep.due()`): a push that lands, or an adoption that changes the lease, clears that repo's `_swept_on[root]`, so `due()` sweeps it on the next tick. The read and push run in `survey`'s thread under `_promote_lock` (`agent_promote.py`, so no promote moves live between them), so `promote_mod.survey` returns a fourth value, the roots whose push landed or whose adoption changed the lease (its callers near :48, :143 and :190 take it), and the loop does the clearing. `_swept_on[root]` reads the same for a sweep running and one finished, so `_sweep_pass` holds a root in a set `_sweeping` while its sweep runs; a landed push or such an adoption for a root in `_sweeping` adds it to a set `_resweep` beside `_swept_on` instead, read when that run ends, which clears `_swept_on[root]` then.
- **The lift PR is a work order** (§4.4 *A live check's lift PR is the team's at once*; `src/sessionorc/workorders.py`): `is_lift_order` beside `is_sync_order`. An open PR whose head is `lift/TD-<n>/<name>` (the reading's `branch`, not its `head`, which is the sha; what `gatesweep.lift_branch` gives a gate: `event (live)` → `lift/TD-n/live`), `<name>` matching `live`, `live-[0-9]+` or `live-td[0-9]+`, not a draft and not a fork, is an order from its first reading whatever its checks, red included (no `ORPHAN_AFTER` wait), stamped `lift_since` at that reading as a sync PR is stamped `sync_since` (in `src/sessionorc/reports.py`, beside `_sync_flag` and `sync_since`; `workorders.red_prs` learns the third key and skips a PR with none of them), and, as a sync, not an order while a live record holds it: title the PR's, priority its entry's, `Context` the PR's URL and the gate, page kind *pickable*, the grinders' pick list. No `green` test: a fresh lift PR's precheck is pending until its taker runs it.
- Tests:
  - A concluding promote pushes the tag once; an unchanged reading pushes nothing.
  - An absent tag is pushed; a tag at the stored lease is pushed with it; a tag already at the live sha (no lease, or an older one: a push whose lease write was lost) is adopted, with no note.
  - A tag at another sha with no lease, and a tag at neither lease nor live, each clear the lease, send the tag note and push nothing, once per found sha, also across a restart of the home (`live_ref_noted`); the tag deleted afterwards is pushed on the next full pass, and a later move to the same sha is noted again. A press's or a rollback's own full read sees the stored lease: live moved by hand since (a hand-installed copy, or a concluding push that failed), the tag at the lease is pushed with it, never read as someone else's.
  - A branch `promote/live` keeps the lease, sends the branch note once per its sha, pushes nothing and leaves the tag's noted line as it was; once it is deleted, the tag is read as the action list says. A branch noted at a sha and a tag then found someone else's at that same sha sends the tag note too; a branch noted, deleted (whatever the tag then is), and pushed again at the same sha is noted again; a foreign tag noted, deleted and pushed by the home, then moved back to the same sha is noted again.
  - A tag deleted, or moved, or a branch pushed, between promotes (lease equal to live) is seen on the next full pass.
  - A push refused for its lease changes nothing, and the next read acts on what it finds.
  - A full pass during a promote's smoke (`phase: smoke`, `check` reading the new commit) reads and pushes nothing; the pass that concludes it pushes.
  - A standing failure reads and pushes nothing though `check` reads a commit of `origin/main`: a run that did not conclude, a failed smoke with no `from` (the tag stays where it was), and a rollback whose own smoke failed; once Dismiss clears it, a full pass with live still at the failure's sha (`untagged`) reads and pushes nothing, and the first that reads with another live commit deletes `untagged` and pushes, while a later promote's smoke (a pass that reads nothing) keeps it; Dismiss of a hold writes no `untagged`; Dismiss of a failure at a sha that is not live writes no file; a second failure's Dismiss leaves the first failure's `untagged` standing; Dismiss after live moved by hand writes no file; Dismiss with `check` answering unknown writes the file; a pass started while Dismiss holds the lock reads only after both writes; a concluding pass that also starts the next `auto` run reads before the start.
  - A failed smoke's pass reads and pushes nothing; the rollback's concluding pass finds the tag at the lease, the put-back live, and pushes nothing.
  - A foreign annotated tag whose object differs from the live commit reads as someone else's; its peeled `^{}` line is never read.
  - A read that fails pushes nothing and keeps the lease and the noted lines: a foreign tag noted, a failed read, then the same tag: no second note.
  - A foreign tag noted at a sha, a branch then pushed (its note sent) and deleted, the tag still there: the tag is not noted again.
  - A failed push is retried on the next full pass.
  - An *unknown* live, a commit off `origin/main`, and a repo with no `promote:` block read and push nothing.
  - A landed push, and an adoption that changes the lease, each make the repo due on the next tick, also while its sweep runs (`_sweeping`, `_resweep`).
  - The lease survives a restart of the home between two pushes: no note, the second push lands.
  - A `lift/TD-n/live` PR (and `live-2`, `live-td5`) is a `pr:` order from its first reading, pending or `not_run` included; `lift/TD-n/livefoo` and a draft are not.

**Done when:** The home keeps `promote/live` on each promoted repo's origin at the live commit, read on every full pass and moved once per change, and sweeps that repo's gates on the next tick. Tests cover each case above.
