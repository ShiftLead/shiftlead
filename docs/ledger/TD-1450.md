**Why:** Build TD-1437, slice 1 of 3 (design §6 *Promote*, *The live ref*; §4.4 the event runner). A check run against the forge cannot see what the home runs: the live commit is only `promotes.<repo>.live` on the home. This slice gives the forge a ref to read, and sweeps a repo's gates soon after it moves.

**Ask:** Go with TD-1450, a build of TD-1437's design, after its Hold revision (TD-1554)? Answered on the board's end-of-rounds item for TD-1437 (Go | One more round | Hold: <note>).

**Fix:** - **The tag** (`src/sessionorc/promote.py`, `src/sessionorc/agent_promote.py`), for each repo with a `promote:` block, as §6 *The live ref* writes it:
  - **The read.** The home tags only a commit a run finished at (§6 *The live ref*, TD-1554). Each full pass that reads **live** at the commit `promote.finished(repo, live)` says a run finished at (`last.json`'s `sha` with `done` set, written by TD-1559's `_passed`), a commit `origin/main` holds, with no promote or rollback of the repo in flight (`promote.inflight(repo)` is `None`), and the in-flight watch pass (`survey`) that concludes a run there, runs one `git ls-remote --refs origin refs/tags/promote/live refs/heads/promote/live` from the registered checkout, off the loop. Every other pass reads and pushes nothing: a live that is *unknown* or not on `origin/main`; a run in flight, its smoke included (`phase: smoke`), though `check` already reads the new commit (a tag at a build whose smoke then fails would lift a gate no rollback puts back); a run that did not finish, `last.json` naming its commit with no `done` (a run that failed after `check` read it, a failed smoke that rolls nothing back, a rollback whose own smoke failed); and a copy installed by hand, which `last.json` does not name. Nothing else is read for it, `failed.json` included: the one test is `finished`. A smoke that fails concludes nothing (`_smoke_failed` starts its rollback, which is then in flight), and the pass that concludes the rollback reads. A concluding pass that also starts the next `auto` run reads before the start. The sha compared is the ref's own object as `ls-remote` prints it (an annotated tag's is its tag object's, so it never reads as at live; `--refs` leaves out its peeled `^{}` line). A read that fails (`promote._git` answering `None`: no answer, refused, timed out) is no reading: no push, the lease and the noted lines kept, logged, read again on the next full pass; only an answered read finds a ref absent.
  - **The action, by what it finds**: a branch `promote/live` (it may shadow the tag): keep the lease, push nothing, and send the person the branch note (*delete the branch*, `git push origin :refs/heads/promote/live`, as §6 writes it), the tag's noted line neither read nor cleared while the branch stands; otherwise the tag at the live sha, adopt it as the lease if the lease differs, push nothing; no tag, push onto the absent tag (empty lease); the tag at the stored lease, the lease not the live sha, push with the lease; the tag anywhere else (at another sha with no lease, or at neither lease nor live) is someone else's: clear the stored lease, push nothing, and send the tag note (its text as §6 writes it). Each note goes through `_system_note(PERSON, …)`, as the *promoted* notes go, once per ref and sha it was found at. No board edit: the home writes boards only by PR.
  - **The push**: `git push --force-with-lease=refs/tags/promote/live:<lease> origin <live>:refs/tags/promote/live`. It is a tag, not a branch. A push refused for its lease changes nothing (the next read acts on what is there); any other failure is logged and retried on the next full pass.
  - **What is stored**: the lease **`promotes.<repo>.live_ref`**, the sha last pushed or adopted, in `~/.shiftlead/promotes/<repo>/live_ref` after each landed push or adoption; and each ref's last note in `live_ref_noted` beside it: at most two lines, one per ref, ref and sha (`refs/heads/promote/live <sha>`, `refs/tags/promote/live <sha>`), a new note of a ref replacing that ref's line alone, so a branch note never suppresses a tag note and a tag noted before a branch came and went is not noted again; a ref's line is cleared by any read that does not find that ref at its noted sha (the branch gone, the tag absent or elsewhere), and the tag's line by a landed push; a pass that reads nothing (a run in flight, a failed read, a live *unknown* or off `origin/main`, a live no run finished at) keeps both, so a ref removed and put back at its noted sha within it is not noted again. Both are read from their files at every read, never held in memory from the home's start: the press's and the rollback's own `survey([root], {}, True, …)` (`agent_promote.py`) carry no earlier reading, and a promote of shiftlead restarts the home (`_promotes` is in memory only); the reading's `live_ref` is a copy for `ao promote status` (its `--json`'s `promotes.<repo>.live_ref`, §4.7).
- **The sweep after it** (`src/sessionorc/agent_tick.py` `_sweep_pass`, near :1663, with `gatesweep.due()`): a push that lands, or an adoption that changes the lease, clears that repo's `_swept_on[root]`, so `due()` sweeps it on the next tick. The read and push run in `survey`'s thread under `_promote_lock` (`agent_promote.py`, so no promote moves live between them), so `promote_mod.survey` returns a fourth value, the roots whose push landed or whose adoption changed the lease (its callers near :48, :143 and :190 take it), and the loop does the clearing. `_swept_on[root]` reads the same for a sweep running and one finished, so `_sweep_pass` holds a root in a set `_sweeping` while its sweep runs; a landed push or such an adoption for a root in `_sweeping` adds it to a set `_resweep` beside `_swept_on` instead, read when that run ends, which clears `_swept_on[root]` then.
- **The lift PR is a work order** (§4.4 *A live check's lift PR is the team's at once*; `src/sessionorc/workorders.py`): `is_lift_order` beside `is_sync_order`. An open PR whose head is `lift/TD-<n>/<name>` (the reading's `branch`, not its `head`, which is the sha; what `gatesweep.lift_branch` gives a gate: `event (live)` → `lift/TD-n/live`), `<name>` matching `live`, `live-[0-9]+` or `live-td[0-9]+`, not a draft and not a fork, is an order from its first reading whatever its checks, red included (no `ORPHAN_AFTER` wait), stamped `lift_since` at that reading as a sync PR is stamped `sync_since` (in `src/sessionorc/reports.py`, beside `_sync_flag` and `sync_since`; `workorders.red_prs` learns the third key and skips a PR with none of them), and, as a sync, not an order while a live record holds it: title the PR's, priority its entry's, `Context` the PR's URL and the gate, page kind *pickable*, the grinders' pick list. No `green` test: a fresh lift PR's precheck is pending until its taker runs it.
- Tests:
  - A concluding promote pushes the tag once; an unchanged reading pushes nothing.
  - An absent tag is pushed; a tag at the stored lease is pushed with it; a tag already at the live sha (no lease, or an older one: a push whose lease write was lost) is adopted, with no note.
  - A tag at another sha with no lease, and a tag at neither lease nor live, each clear the lease, send the tag note and push nothing, once per found sha, also across a restart of the home (`live_ref_noted`); the tag deleted afterwards is pushed on the next full pass, and a later move to the same sha is noted again. A press's or a rollback's own full read sees the stored lease: a concluding push that failed since, the tag at the lease is pushed with it, never read as someone else's.
  - A branch `promote/live` keeps the lease, sends the branch note once per its sha, pushes nothing and leaves the tag's noted line as it was; once it is deleted, the tag is read as the action list says. A branch noted at a sha and a tag then found someone else's at that same sha sends the tag note too; a branch noted, deleted (whatever the tag then is), and pushed again at the same sha is noted again; a foreign tag noted, deleted and pushed by the home, then moved back to the same sha is noted again.
  - A tag deleted, or moved, or a branch pushed, between promotes (lease equal to live) is seen on the next full pass.
  - A push refused for its lease changes nothing, and the next read acts on what it finds.
  - A full pass during a promote's smoke (`phase: smoke`, `check` reading the new commit) reads and pushes nothing; the pass that concludes it pushes.
  - A live no run finished at reads and pushes nothing though `check` reads a commit of `origin/main`: a run that failed after `check` read it, a failed smoke with no `from` (the tag stays where it was), a rollback whose own smoke failed, a copy installed by hand at main's head, and a legacy `last.json` with no `done`; the press of a hand install (TD-1559) that concludes pushes; a run at a later head that concludes after a failure pushes; a concluding pass that also starts the next `auto` run reads before the start.
  - A failed smoke's pass reads and pushes nothing; the rollback's concluding pass finds the tag at the lease, the put-back live, and pushes nothing.
  - A foreign annotated tag whose object differs from the live commit reads as someone else's; its peeled `^{}` line is never read.
  - A read that fails pushes nothing and keeps the lease and the noted lines: a foreign tag noted, a failed read, then the same tag: no second note.
  - A foreign tag noted at a sha, a branch then pushed (its note sent) and deleted, the tag still there: the tag is not noted again.
  - A failed push is retried on the next full pass.
  - An *unknown* live, a commit off `origin/main`, and a repo with no `promote:` block read and push nothing.
  - A landed push, and an adoption that changes the lease, each make the repo due on the next tick, also while its sweep runs (`_sweeping`, `_resweep`).
  - The lease survives a restart of the home between two pushes: no note, the second push lands.
  - A `lift/TD-n/live` PR (and `live-2`, `live-td5`) is a `pr:` order from its first reading, pending or `not_run` included; `lift/TD-n/livefoo` and a draft are not.

**Done when:** The home keeps `promote/live` on each promoted repo's origin at the live commit only while a run finished at it (`promote.finished`), read on every full pass that may tag and moved once per change, and sweeps that repo's gates on the next tick. Nothing reads `failed.json` or an `untagged` file for the tag. Tests cover each case above.
