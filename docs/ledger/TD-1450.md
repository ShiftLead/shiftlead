**Fix:** - **The tag** (`src/sessionorc/promote.py`, `src/sessionorc/agent_promote.py`), for each repo with a `promote:` block, as §6 *The live ref* writes it:
  - **The read.** Each full pass that reads **live** at a commit `origin/main` holds, and the in-flight watch pass (`survey`) that finds a promote or a rollback concluding there (or a hand-installed copy `check` reads), runs one `git ls-remote origin refs/tags/promote/live refs/heads/promote/live` from the registered checkout, off the loop. A live that is *unknown*, or not on `origin/main`, reads and pushes nothing.
  - **The action, by what it finds**: the tag at the live sha and no branch, adopt it as the lease if the lease differs, push nothing; neither, push onto the absent tag (empty lease); the tag at the stored lease and no branch, the lease not the live sha, push with the lease; anything else (a tag at another sha with no lease, a tag at neither lease nor live, or a branch `promote/live`) is someone else's: clear the stored lease, push nothing, and send the person one `system` note (`_system_note(PERSON, …)`, as the *promoted* notes go), once per sha the tag or branch was found at, its text as §6 writes it. No board edit: the home writes boards only by PR.
  - **The push**: `git push --force-with-lease=refs/tags/promote/live:<lease> origin <live>:refs/tags/promote/live`. It is a tag, not a branch. A push refused for its lease changes nothing (the next read acts on what is there); any other failure is logged and retried on the next full pass.
  - **What is stored**: the lease **`promotes.<repo>.live_ref`**, the sha last pushed or adopted, in `~/.shiftlead/promotes/<repo>/live_ref` after each landed push or adoption, and the sha last noted in `live_ref_noted` beside it; both read at the home's start, since a promote of shiftlead restarts the home (`_promotes` is in memory only).
- **The sweep after it** (`src/sessionorc/agent_tick.py` `_sweep_pass`, near :1645, with `gatesweep.due()`): a push that lands clears that repo's `_swept_on[root]`, so `due()` sweeps it on the next tick. The read and push run off the loop, so the pass returns the roots whose push landed and the loop does the clearing. `_swept_on[root]` reads the same for a sweep running and one finished, so `_sweep_pass` holds a root in a set `_sweeping` while its sweep runs; a landed push for a root in `_sweeping` adds it to a set `_resweep` beside `_swept_on` instead, read when that run ends, which clears `_swept_on[root]` then.
- **The lift PR is a work order** (§4.4 *A live check's lift PR is the team's at once*; `src/sessionorc/workorders.py`): `is_lift_order` beside `is_sync_order`. An open PR whose head is `lift/TD-<n>/<name>` (the reading's `branch`, not its `head`, which is the sha; what `gatesweep.lift_branch` gives a gate: `event (live)` → `lift/TD-n/live`), `<name>` matching `live`, `live-[0-9]+` or `live-td[0-9]+`, not a draft and not a fork, is an order from its first reading whatever its checks but red (a red one is an order already), stamped `lift_since` at that reading as a sync PR is stamped `sync_since` (`red_prs` skips a PR with neither), and, as a sync, not an order while a live record holds it: title the PR's, priority its entry's, `Context` the PR's URL and the gate, page kind *pickable*, the grinders' pick list. No `green` test: a fresh lift PR's precheck is pending until its taker runs it.
- Tests:
  - A concluding promote pushes the tag once; an unchanged reading pushes nothing.
  - An absent tag is pushed; a tag at the stored lease is pushed with it; a tag already at the live sha (no lease, or an older one: a push whose lease write was lost) is adopted, with no note.
  - A tag at another sha with no lease, a tag at neither lease nor live, and a branch `promote/live` each send the one `system` note and push nothing, once per found sha, also across a restart of the home (`live_ref_noted`); the tag deleted afterwards is pushed on the next full pass.
  - A tag deleted, or moved, or a branch pushed, between promotes (lease equal to live) is seen on the next full pass.
  - A push refused for its lease changes nothing, and the next read acts on what it finds.
  - A failed push is retried on the next full pass.
  - An *unknown* live, a commit off `origin/main`, and a repo with no `promote:` block read and push nothing.
  - A landed push makes the repo due on the next tick, also while its sweep runs (`_sweeping`, `_resweep`).
  - The lease survives a restart of the home between two pushes: no note, the second push lands.
  - A `lift/TD-n/live` PR (and `live-2`, `live-td5`) is a `pr:` order from its first reading, pending or `not_run` included; `lift/TD-n/livefoo` and a draft are not.

**Done when:** The home keeps `promote/live` on each promoted repo's origin at the live commit, read on every full pass and moved once per change, and sweeps that repo's gates on the next tick. Tests cover each case above.
