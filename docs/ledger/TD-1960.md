## TD-1960: The designer and techlead briefs do not yet say who judges a design's verdict

**Priority:** Medium
**Type:** feature
**Added:** 2026-11-19
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 3df7631a412e4f3cb11e3e8143ac9051
**Part of:** TD-1911

**Why:** TD-1911's design (§4.9c *Who ends a design's rounds*, §4.9b *It judges a design's verdict*) makes the team's techlead seat the judge of a design's counted verdict, with the cadence's default judge standing in where the seat cannot judge. The seat answers no end-of-rounds item for the person: a seat answering one waits on TD-1910's `decide` delegation. The designer's and the techlead's briefs do not say this yet: the designer brief here still raises the item by hand-applied rules written before agent-cadence TD-281 and TD-288 counted the verdict.

**Location:** docs/briefs/designer-ao-1.md, src/shiftlead/briefs/designer.md, src/shiftlead/briefs/techlead.md (not techlead.stage.md), docs/briefs/techlead-context.md, tests/test_briefs_layout.py; design §4.9c *Who ends a design's rounds*, §4.9b

**Fix:** Write the design's rules into the briefs, as §4.9c *Who ends a design's rounds* and §4.9b *It judges a design's verdict* say them:
- **The designer**: the built-in template `src/shiftlead/briefs/designer.md` gains a paragraph of its own, *How a design's rounds end*, beside its *How much the person sees* paragraph, carrying every rule below, since §4.9c is ShiftLead's rule for any install's designer; this repo's `docs/briefs/designer-ao-1.md` keeps in its *How a design is reviewed here* paragraphs only what is this repo's (the Fable rules, the class and cap, `[far-reaching]`'s paths as §4.9c lists them), points at the template's paragraph, and drops its hand-applied end-of-rounds rules (its *The rounds end as §4.8 says*, *A fix no review has read recommends One more round* and *The end-of-rounds item* bullets, where the counted verdict replaces them; the item stays for a far-reaching design, raised as `next: item` says). The rules:
  - mark the design routine or far-reaching beside its class: far-reaching where a passage its own PR changes says who may act, answer, merge or decide for the person (a role's or seat's rights, a flow's seats, a permission, a delegation, what reaches the person), the passages named on the record's `Reach:` line, a passage that only says how a write is made being routine; or where any of its builds names a file `[far-reaching]`'s `paths` match; any doubt far-reaching;
  - after the closing fact-check run `review_stats.py --verdict TD-<design>` and follow its `next:`;
  - on `next: judge` send the `judge TD-<design>` ask to the seat the brief's `{techlead}` slot names (the PR's number and head, the record's path, the design's section files as the plan, and `--verdict`'s output pasted whole) with `--bound 7200`, and end the turn while it waits; copy the reply's `cadence-judge:` line into `Verdict:` with a `judge` row, never asking again;
  - run the cadence's default judge at once, a fresh subagent on `review-model`'s last model, where the `{techlead}` slot reads `none`, the team's question seat is the person or absent, the send's reply carries `routed` or the ask closes `rerouted` (then `ao msg --withdraw <id>`), the seat declines (a decline writes no `judge` row; only a judge run that returns a line does), or the ask lapses at its bound (it closes there, so nothing is withdrawn; a later reply is not copied, so the record holds one `judge` row);
  - on the judge's Go file the builds with no item and send the person one uncounted `note`; a judge's Go never satisfies the `reach` row, so a build matching `[far-reaching]` still waits for a person's Go.
- **The techlead seat** (`src/shiftlead/briefs/techlead.md`, beside its other answering rules; not `techlead.stage.md`, which is the held-PR reader's stage text; and `docs/briefs/techlead-context.md`'s primer where it lists what the seat answers):
  - its *An `ask`: only when the answer is already written down* rule names three kinds the seat reads instead, a held PR, a screenshot ask and a judge ask; the judge ask carries no `--pr`, so its reply takes no `--verdict`;
  - a `judge TD-<design>` ask is answered by a fresh subagent on `review-model`'s last model with the cadence's fixed judge prompt, the section files saved beside it from the PR head (read by ref) as its plan and `--verdict`'s output written to a file of the seat's own as its verdict, never checking the PR out; its `cadence-judge:` line sent verbatim with `--source` the record's path; a `CONFIRM` raised only on a decision of the person's it names with where it is written, the line kept in the judge line's form; a seat whose tool cannot start that subagent declines. It answers no end-of-rounds item for the person.
- **Tests** in `tests/test_briefs_layout.py` (or beside it), one case per rule, each asserting its tokens in the template's text (the rule text, so the `none` case holds whatever the slot renders to): the techlead template carries `judge TD-`, `cadence-judge:` and the judge ask among the kinds read instead; the designer template's *How a design's rounds end* paragraph carries `--verdict`, `next: judge`, `[far-reaching]`, `Reach:`, and one case per fallback (`none`, the question seat, `routed`, `rerouted` with `--withdraw`, declines, the lapsed bound).
Both briefs are held paths (`docs/briefs/**`): the PR waits for its reader. This build's Go is the person's either way, since the design is marked far-reaching; the `reach` row holds it until that Go is recorded only once TD-1961's table is on main (either may merge first).

**Done when:** The designer template's *How a design's rounds end* paragraph ends a design's rounds by `--verdict`'s `next:`, with the techlead its `{techlead}` slot names as judge and the default judge as its fallback in each case §4.9c names, and marks reach by the passage test; this repo's designer brief keeps only its own rules and points at it; the techlead's brief names the judge ask among the kinds it reads and judges by the fixed prompt; each new brief test passes, and `pdm run test` passes.
