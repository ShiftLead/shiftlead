## TD-2323: The rules for writing your Go on a design's review record can be removed and every test still passes

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-26
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 6ef6139845ba49ebb3372c9445aa2867

**Why:** Eight rules of the home's record pass (design §4.4 *The same pass records a design's Go*; `src/sessionorc/gatesweep.py`, built by #4838, TD-2225 slice 1) can each be taken out of the code with every test still passing. On `origin/main` at ea08ab2b2, each change below was made alone in a scratch clone and run against the eight test modules that name `gatesweep` or `gate_sweep` (`test_record_pass.py`, `test_gate_sweep.py`, `test_workorders.py`, `test_filing_orders.py`, `test_repo_facts.py`, `test_stage_audit_end.py`, `test_stage_work.py`, `test_ui_red_prs.py`): 269 passed for every one.

The two header rules, which decide what the pass writes on a review record:

1. `write_record`: dropping `and not DATE_HEAD.match(d[1].strip())` passes. The design says *a line starting with a date is left*; with the change, `write_record` turns a record reading `**Decided:** 2026-11-14` and `**Go by:** pending` into `**Decided:** 2026-11-24 — 2026-11-14`.
2. `record_owed`: `go_owed = go is None or …` changed to `go is not None and …` passes, so a record with a dated `Decided:` and no `Go by:` line would never be owed the Go.

The first live pass (PR #4848) met such a record, `docs/reviews/TD-1829.md` (a dated `Decided:`, no `Go by:`): its diff adds `**Go by:** paul` and leaves `Decided:`, which is the two rules above, held by no test. `test_a_record_naming_a_judge_or_already_dated_is_left` reads as covering rule 1, but its one dated record also names a judge, is only asserted absent from `record_owed`, and is never passed to `write_record`. TD-2225's Fix item 5 asks that a record that names a judge, *or already has a date*, is untouched.

The six guards on whether the pass writes at all:

3. One record PR per UTC day: dropping `_remote_has(root, branch) or` passes (a day's branch pushed with no pull request), and so does dropping `or prs(root, "--head", branch)` (a merged pull request whose branch was deleted). Dropping both fails: `test_a_second_pass_on_the_day_or_while_one_is_open_writes_nothing` sets up a state that satisfies the two at once.
4. `_held_by_records`: dropping `or q["state"] != "closed"` passes, so a merged record PR would hold its records for the re-ask window, and a design gated again and given a new Go inside it would go unrecorded until the window ends.
5. The same line: dropping `reports.sweep_of(q["head"]) != "record" or` passes, so any closed pull request whose body has a `- record: TD-n` line would hold that record.
6. The window: `<= lb.SWEEP_REASK_DAYS` changed to `<` passes; the test reads only the day after the close and the day past the window.
7. A closed pull request whose date the forge did not give: `day is None or` changed to `day is not None and` passes, though the docstring says such a pull request holds its records too.

**Location:** tests/test_record_pass.py; src/sessionorc/gatesweep.py

**Fix:** In `tests/test_record_pass.py`: (1) a record with a dated `**Decided:**` and `**Go by:** pending` keeps its `Decided:` through `write_record`, and one with a dated `Decided:` and no `Go by:` is owed and gets the `Go by:` line alone. (2) Set up each half of the one-a-day rule alone (the branch on the remote with no pull request; a merged pull request with its branch deleted). (3) A merged record PR, and a closed pull request on another head with a `- record:` line, hold nothing. (4) A record PR closed exactly `SWEEP_REASK_DAYS` before still holds, and one with no `closedAt` holds. Each test fails with its line taken out.

**Done when:** Each of the changes in the Why, made alone, fails a test in `tests/test_record_pass.py`.
