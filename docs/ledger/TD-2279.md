## TD-2279: A login's name is refused where another tool's login on the host already has it

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-26
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 933817e93e2e40469b32ff9df98fda81
**Part of:** TD-2232

**Why:** TD-2232's design (§4.2b *Names are fixed*, §4.9e *A record's `profile`*): a login's name is unique on its host across every tool, a forgotten login's among them, so a stored record's `profile`, the login's bare name, goes on resolving to its login and account. Today `logins.name_taken` (`src/sessionorc/logins.py`) checks only the same tool, so `ao login add gemini --name grind` beside `claude-code:grind` is allowed; `profile_name` then reads both under their keys and every record written as `grind` resolves to no profile (TD-2232's probe at a5f15d01c: `get(grind) -> unknown profile 'grind'`), and `_account_key` (`src/sessionorc/agent_spend.py`) falls back to a key no reserve is kept under.

**Location:** src/sessionorc/logins.py, src/shiftlead/profiles.py, src/shiftlead/switchover.py; design §4.2b Names are fixed, §4.9e A record's profile

**Fix:** 1. `logins.name_taken` (`src/sessionorc/logins.py`) refuses a name any other login on the host has, of any tool, live (`data["logins"]`) or forgotten (`data["forgotten"]`), skipping the key being added, so a take-back (`add_login`'s `back`) still passes; the same tool's forgotten name stays `add_login`'s own refusal, as today. Its words are §4.9e *A record's `profile`*'s: a live holder's *`<name>` is `<tool>:<name>`'s name on this host: a login's name is unique on its host*, a forgotten one's *`<name>` is the forgotten login `<tool>:<name>`'s name, kept for its own folder: give another name*. A take-back whose name another tool's live login holds (a hand-edited file only) is refused with the live words. `name_taken`'s docstring and the module docstring (line 6, today *a name is unique per tool on a host*) say a name is unique on its host across every tool, citing §4.2b *Terms used below*, **Names are fixed**, and TD-2232.
2. `add_login`'s suggested name (`suggest(suggested, taken)`) takes as `taken` every bare name on the host, live and forgotten, of every tool, not its own tool's alone.
3. The switch-over's `_name_blockers` (`src/shiftlead/switchover.py`) keeps today's check, folded by `naming.tools_id(tool, name)` with its words, and adds two: two logins of one host whose `login.name` is the same string, whatever their tools — blocker *`<a>` and `<b>` would both be named `<name>`; a login's name is unique on its host*; a container node's login named as a home login of another tool that a team on that node lists, and a login named as a profile of that host that makes no login (a `shell` profile's, or an unregistered adapter's) of another adapter — the same words, naming the other. Each cure is *give one of them another name in the answers file*, as today.
4. The profile reader (`profiles._from_logins`, `src/shiftlead/profiles.py`) answers a forgotten login's bare name from `forgotten:` with its folder and account (`account_of` gives the account), marked so that a launch on it is refused as on any forgotten login; a live login of the name, which only a hand-edited file holds, is read over it. `logins.profile_name` and `_from_logins` keep the key form for a file edited by hand to hold one name under two tools; their docstrings say nothing shiftlead writes makes one (§4.9e).
5. Tests, beside `logins.py`'s own: a scratch `logins.yml` holding `claude-code:grind` (account `claude-code:acct-1`): adding `gemini:grind` is refused with item 1's live words and the file is unchanged; adding a forgotten `gemini:old`'s name `old` as a `claude-code` login is refused with the forgotten words; a take-back of a forgotten login on its folder still passes; a suggested name skips another tool's; a record written as `grind` still reads `profiles.get("grind")` and its account `claude-code:acct-1` after a `gemini:reader` login is added; after `claude-code:grind` is forgotten, `profiles.account_of("grind", "claude-code")` still gives `claude-code:acct-1` and a launch on `grind` is refused. `tests/test_login_verbs.py`'s assertion that `gemini:grind` is added beside a live `claude-code:grind` (`# per tool`, ~line 225) changes to expect item 1's refusal; `tests/test_launch_on_login.py::test_profile_name_is_the_bare_name_unless_two_tools_share_it` stays, as item 4's hand-edited file (its `LOGINS` fixture is written by hand). In the switch-over's tests: an answers file naming `claude-code:~/.claude` and `gemini:~/.gemini` both `paul` is a blocker; one naming two `claude-code` logins `Grind` and `grind` is still a blocker by today's fold; one naming a `gemini` login after a `shell` profile of that host is a blocker.

**Done when:** No path shiftlead writes (`ao login add`, its suggested name, the switch-over's answers; `ao host up`'s provisioning is TD-2070's) gives two logins of one host one name, and a record written under a login's bare name still resolves to that login's account after another tool's login is added and after the login is forgotten, with item 5's tests passing.
