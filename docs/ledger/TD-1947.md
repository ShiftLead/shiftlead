## TD-1947: A session's window is pinned at one grid, and the bridge attaches at it and carries out the person's fit

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-17
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** e7d54c8dd4164fefbf11a193a3266980
**Part of:** TD-1919

**Why:** TD-1919's design (design §4.6 *Attach behaviour with another client present*, *Fit to window: the person resizes on demand*): a session's window follows its clients today, and every resize or reattach makes Claude Code repaint over lines tmux has kept — 5 to 13 of 30 streamed paragraphs repeated on a width change, 3 to 4 lost on a height change; pinned, none in 8 of 8 runs. This is the host side: the pin, the grid the bridge attaches at and reports, and the fit it carries out.

**Location:** design §4.6 Attach behaviour with another client present, Fit to window; §5 person.terminal.grid; src/sessionorc/tmux.py (new_session, status_off), the host agent's start, src/shiftlead/ui/pty_bridge.py, src/shiftlead/ui/app.py (the terminal websocket), tests/test_resize_repaint_live.py

**Fix:** As design §4.6 *Attach behaviour with another client present* and *Fit to window: the person resizes on demand* say, and §5 `person.terminal.grid`:
1. **The pin.** `Tmux.new_session` (`src/sessionorc/tmux.py`) chains `set-option -w … window-size manual` and `resize-window -x <cols> -y <rows>` into the same invocation as `remain-on-exit`, the grid from `person.terminal.grid` (absent, 120 × 40) passed in by the host agent; the host agent's start pins every `ao-*` session whose window is not yet `manual` at the size it has, beside `status_off`, never through the server's global options.
2. **The setting.** `person.terminal.grid` in `settings.yml` (§5): two positive ints, columns and rows, validated by `set_settings` as the other `person.terminal` keys are; read at each session start.
3. **The bridge** (`src/shiftlead/ui/pty_bridge.py` and the terminal websocket in `src/shiftlead/ui/app.py`): read the window's size before the attach and open the attach's pty at it; send `{"grid": [cols, rows]}` before the first pane byte and whenever the five-second reading of the window changes (the reading that today makes the `{clients, window}` frame, which this frame replaces; the rows counted with the status bar's lines, which are none); a `{"fit": [cols, rows]}` message runs `resize-window` on the session's window and resizes the pty with it, then sends the `grid` frame; a `{"resize": …}` message is ignored (logged once per attach). A read-only attach's `fit` is dropped, as its keys are.
4. **Tests:** the unit tests of the pin's argv, the start's pin of an unpinned session (private tmux socket), the bridge's grid frame and fit; the live test's pinned mode (`tests/test_resize_repaint_live.py`) runs through the real `new_session` rather than its own `set-option`, and a fit at idle that grows the grid leaves every paragraph once.

**Done when:** A new `ao-*` session's window reads `window-size manual` at `person.terminal.grid`, a host agent start pins an unpinned one at its size, the bridge attaches at the window's size and sends the `grid` frame, a `fit` resizes the window and a `resize` changes nothing, each under a test, and the live test's pinned mode passes through `new_session`.
