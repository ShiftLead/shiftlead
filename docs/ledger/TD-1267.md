## TD-1267: Copy's toast in the Focus pane says nothing when a selection stops at the screen's edge or a wrapped line copies as rows

**Priority:** Medium
**Type:** debt
**Added:** 2026-10-30 (the designer, from TD-1263)
**Owner:** grinder
**Kind:** build
**Status:** Open
**Part of:** TD-1263
**Location:** `src/shiftlead/ui/static/app.js` (the Focus terminal's `copySel`, the copy-on-select `mouseup` listener, `#tcopy`'s click, `AO.toast`); `tests/test_ui.py` or a new `tests/test_ui_focus_copy.py`; design §4.6 *A selection is one screen, and a copy is its rows*, §4.5a *Copy / Paste* and *copy on select*

**Why:** TD-1263 decided not to scroll a selection past the pane's edge or join a wrapped line at copy time (neither behaves the same every time), and to point the person to the Transcript instead. Today a drag stops at the edge and a wrapped line copies broken with no word from the page, so the person finds the limit by pasting.

**Fix:** as §4.6 *A selection is one screen* writes it:
- Track a selection drag: a primary-button `mousedown` on the terminal starts one and resets the mark, so a release the page never saw (outside the window) leaves nothing stale; while it is held, a `mousemove` (on the document, since the pointer leaves the pane) whose `clientY` is above the top or below the bottom of xterm.js's `.xterm-screen` marks it *past the top* or *past the bottom* by one pure function, e.g. `AO.pastEdge(clientY, screenRect, cell)` → `"top"|"bottom"|null`, true when the pointer is at least one cell height (`cellH()`, the wheel's measure) beyond that edge; the page's next `mouseup` reads and clears the mark before the copy-on-select listener's `selMoved` return, and the note is drawn only if the selection is non-empty and `term.getSelectionPosition()` at that release starts on row 0 (past the top) or ends on row `term.rows - 1` (past the bottom); its rows are screen rows because the buffer holds only the screen (`scrollback: 0`, so the view never scrolls), with `start` before `end`. A Shift+click clears the mark and is no drag; Copy, Ctrl+C and Ctrl+Shift+C are not a release and never draw the edge note.
- One pure function picks the note, e.g. `AO.copyNote({edge, rows, firstMulti, transcript})` → the note's words or `""`: the edge's note first; the first-copy note only when the copied text holds a newline, no earlier copy of the page's load held one, and the header draws **Transcript**, read at the copy (the release, for copy on select: `copySel` runs synchronously from the `mouseup`) from `#ftranscript`'s `hidden` class and nothing else, an absent `#ftranscript` counting as hidden, so the condition stays the header's; the edge's wording without a Transcript is *copy a screen at a time*.
- `copySel(edge)` (Copy, Ctrl+C, Ctrl+Shift+C, copy on select; only the `mouseup` passes `edge`, the rest call it bare) keeps its boolean return, which `#tcopy` reads for its *select text in the terminal first* toast, and appends the note to *copied* or *clipboard blocked …* after a dash; the edge note goes on *clipboard blocked …* too; a drag past the edge with copy on select off, or drawn disabled for want of a secure context, toasts the note alone, without its dash, with `ok` false (a hint, not a copy) and the 7 s. A toast with a note stays 7 s and keeps its colour: `AO.toast` gains a sixth argument `ms` that, when given, replaces its `link ? 10000 : good ? 3000 : 7000` timing, so *copied — …* stays green; one without a note is unchanged.
- The page-load flag for *first copy of several rows* is taken synchronously when a copy whose text holds a newline calls the write, so two quick copies draw one note; the write's `then` draws the note, and its rejection gives the flag back and draws none, so a blocked write never carries the first-copy note and spends nothing.

**Done when:** in a Focus pane, a drag held past the top or bottom of the terminal and released toasts *copied — the selection stops at the screen's edge; Transcript has the whole conversation* (copy on select on) or the note alone (off), every time; the first copy of several rows on a fresh load adds *— as the screen's rows; Transcript has wrapped lines whole* and the second does not; on a `shell` record (or any record whose header draws no Transcript) the edge note reads *— the selection stops at the screen's edge: copy a screen at a time* and the first-copy note is never drawn; a one-row copy inside the screen toasts *copied* as today. Tests drive `AO.pastEdge` (above and below by a cell or more; inside one cell of either edge, null) and the note function over each case (edge with and without a Transcript, edge with copy on select off, first and second multi-row copy, a blocked multi-row copy drawing no first-copy note and spending no flag, a one-row copy, edge and multi-row together); a UI check on a scratch home shows the edge toast, its shot named in the PR.
