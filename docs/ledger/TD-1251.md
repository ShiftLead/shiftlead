## TD-1251: Nothing runs board write-back's push under a non-English git, so dropping `c_locale=True` passes

**Priority:** Medium
**Type:** debt
**Added:** 2026-10-30 (test-audit-ao-1, auditing the last ten merged PRs)
**Owner:** grinder
**Kind:** build
**Status:** Open
**Location:** `src/sessionorc/board.py` (`_land`: `_git(t, "push", …, c_locale=True)`; `_git`'s `c_locale` branch); `tests/test_board.py` (`test_a_push_the_forge_refuses_reads_apart_from_an_unreachable_origin`)

**Why:** #2688 (TD-1242) made `_land` run the push under `LC_ALL=C` so `_push_refusal` can match git's English `remote: error:` and `! [remote rejected]` words. The test's hooks and git run in the test environment's locale, which is English, so it would read the same without the setting. Probe at `origin/main` b2d1a3724: deleting `, c_locale=True` from the `_git(t, "push", …)` call in `_land` and running `PYTHONPATH=$PWD/src pdm run pytest -q tests/test_board.py -k forge_refuses_reads` gives `1 passed`. On a machine whose git speaks German the reason would then be None and the refusal would read *origin could not be reached* again, the fault TD-1242 fixed, with no test failing.

**Fix:** run the same push in the test under a non-English `LANG`/`LC_ALL` for the process (or assert `_git` with `c_locale=True` passes `LC_ALL=C` in its env, and that `_land` sets it) and keep the existing assertions.

**Done when:** deleting `c_locale=True` from `_land`'s push fails a test.

**Related:** TD-1242, #2688
