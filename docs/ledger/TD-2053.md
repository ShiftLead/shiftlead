**Why:** The design replaces the auditor seats with audits a flow lists, each started on a clock with its own brief, and turns two free-pick work orders, a decided board line and a pull request nobody holds, into support seats, since a format-3 flow has no lane.

**Ask:** Should the builders start on audits that run on a clock and the two new support seats?

**Fix:** Build design §4.9c *Audits start on a clock* and *Two of the five are not seats today*: an audit's run record, its lease and its count from a merge commit, its three outcomes, the plain board line for an audit's other; a session started for each decided board line and each unheld pull request, on the seat's model.

**Done when:** An audit starts when its clock comes round and never while its last run holds its lease; a lost run is offered again once. The board-answers seat never takes a decided line whose Context is an entry whose record waits on the person; held, for a pull request, means any record names it. Both seats start only while the team is started, in schedule and not held by the usage gate.
