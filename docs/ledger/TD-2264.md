**Why:** Audit of #4734 (TD-2068 slice 7), which adds the `last_login` read behind `ao new`'s default login (design §4.9e *The launch on a login*). Two pieces of it have no test:

- `rpc_last_login` (`src/sessionorc/agent.py`) answers nothing stored where `logins.yml` cannot be read (`except logins.LoginError: data = None`). With the handler made to catch `ZeroDivisionError` instead, tests/test_launch_on_login.py and tests/test_new_on_login.py passed at eb5547a84 (34 passed). Probe (a temporary test, `logins.yml` holding `logins: [`): unchanged, the call answers `{}`; changed, it raises `LoginError`. The tests of an unreadable file cover `last_login` alone.
- `last_login` is in `identity.READS` (`src/sessionorc/identity.py`), as design §4.4a's first table row lists it among the served reads. With the name removed, the 24 files under `tests/` that name `identity.` or `READS` (23 test modules and `tests/conftest.py`), with the two above, passed at eb5547a84 (788 passed). Probe: `identity.judge(Channel("unknown"), None, "last_login")` answers no refusal unchanged, and refuses with an identity mismatch and raises an alarm changed.

With all eight changes of TD-2262, TD-2263 and TD-2264 made together at eb5547a84, the 196 test modules that name the touched modules, calls or the director passed (`pytest -n 4`: 4811 passed, 8 skipped); the whole suite was not run to a result.

**Location:** tests/test_launch_on_login.py; src/sessionorc/agent.py rpc_last_login; src/sessionorc/identity.py READS

**Fix:** In `tests/test_launch_on_login.py`, call `last_login` with an unparsable `logins.yml` and assert `{}`; in the identity tests, assert `last_login` is served on an unknown channel with no alarm.

**Done when:** Each of the two changes fails a test.
