**Why:** TD-1543's design (§4.5 screen 12 *Three verbs: Have a session do it*; §4.5a *Due strip / Inbox board row, Queue card item, Repo page board row: Have a session do it*): an `act` line offers **Have a session do it** beside **Done**, so that a step a session could do is not left to the person (Paul, 2026-11-07). Today an `act` line gives only Done, Answer… and Start session.

**Ask:** Held with its design TD-1543 until Paul answers its end-of-rounds item (Go, One more round or Hold) on docs/user_attention.md.

**Fix:** Build the button and its road, as §4.5 screen 12 *Three verbs: Have a session do it* and §4.4 *Decide* write them:

- **The one test of the mark.** A helper in `src/sessionorc/board.py`, `marked_for_person(text)`, says whether a line is marked for the person: it takes the line's words after its `(session …) —` lead and before its first field (`Context:`, `Parts:`, `Due:`, `Hide until:`, `Answers:`, `Lifts:`, `Decided:`, `Closed:` — `FIELD_NAME_RE`'s names plus `Due:`, which is `WRITER_FIELD_RE`'s set), with any reply cut first (`ledgerboard.reply_span`, so a Reply on a marked line keeps it marked), read from its start where it has no lead (the cut written in `sessionorc`, since `sessionorc` imports nothing from `shiftlead.ui`), collapses its spaces, folds its case, drops a trailing `.` or `!`, and tests whether it ends with *only you can do this*. The page's draw and the agent's check both call it, and its tests cover both callers with the same cases (a trailing field, a period, mixed case, the words mid-text).
- **The button.** On an open `act` line (its parsed kind exactly `act`; a kindless line, which ledgerboard reads by act's rule and the page as Decide, draws none), after its **Done**, draw **Have a session do it** wherever the line is drawn with its Done as an answer: a Queue card's item, the Inbox's board row and due strip, and the Repo page's board. Where it sits: in a whole-drawn card item's answer row (`answer_row`), after its Done; on the Inbox row, the due strip and the Repo page's board, after the footer's Done (`mfoot`); on a card item not drawn whole, behind its ⋯ beside Done. Draw it by the line's kind, never from an `Answers:` field, as `inbox_row.html` draws a look's *Works* / *Not right…* pair. The free-pick test is one function in `src/shiftlead/ui/app.py`, beside `road_refusal`: `repo_boards`' per-checkout entry gains its result as a precomputed boolean, `board_reading` (`src/shiftlead/ui/inbox.py`, which cannot import `app.py`) copies it onto each `act` row with the other conditions below as one flag, and the three templates read only that flag. Set it only where all four hold:
  - **A lane would take the work.** A team servicing the board's repo, in `org.yml`, has `free-pick` among its members' lanes or its current flow's stages: the same read as `road_refusal`'s `design-first` branch (`src/shiftlead/ui/app.py`), with `free-pick` for `design-first`. Look the team up by the board's checkout: the repo root whose `docs/user_attention.md` is the board, the key `repo_boards` already uses. A team that has never run draws the button. The flag and the stale press's 409 call one function, so they never disagree.
  - **The line is undecided.** It carries no `Decided:`.
  - **The line has no `Answers:`.**
  - **The text is not marked for the person.** `marked_for_person` is false.

  No other Do item draws it.
- **The press** posts the board row's `decide` act (the `BOARD_ACTS` road) with the fixed answer *have a session do it* and `answers: []`, which the app already accepts. Where no lane would take the work, the app refuses with 409: where no team services the repo, `road_refusal`'s existing first branch and words, *no team services <repo>: nobody would read the line*; else *no lane of <repo> takes a work order: nobody would take the work*. These words are new: `road_refusal` reads only `design-first` lanes today, so it gains a road for this press, the same function the flag calls.
- **The agent's check sits where the line is found.** `_board_answer` in `src/sessionorc/agent_inbox.py` sees only the action and the answer, never the line, and today raises on any answer when `answers == []`. Let it pass the fixed text *have a session do it* through when `answers` is empty, and do the kind check in `src/sessionorc/board.py` after `_find` locates the line on the fresh tree (in `edit_line`, beside its *already decided* refusal). There, re-parse the found line with ledgerboard. These checks apply only where the answer is not one of the found line's own `Answers:` (an answer the line offers is decided as today, whatever its words). The fixed text is compared exactly as the page sends it, *have a session do it*. Accept the fixed text only on an `act` line with no `Answers:` and no `Decided:` for which `marked_for_person` is false. Refuse any other answer on an `act` line, and the fixed text on any other kind, in these words: on a decided line, the existing *this item is already decided: Reply says more to its session, Done closes it*; on a line with `Answers:`, another kind or a kindless line, *have a session do it is an act line's answer: this item's answers are its own*; on a marked line, *this step is marked only you can do this: Done closes it once you have*; any other answer on an `act` line, the existing *a decide records one of the item's own answers, word for word: anything else is a Reply (design §4.4)*. Nothing reads a kind the page sent; a test holds that.
- **The write is the board half alone**, never the decide lift, whatever the line's `Context:` names, so the line stays open. In `board.write_back`, when the answer is the fixed text on an `act` line, still call `_lift_ledger(t, text)`: where it returns a path (the `Context:` names this repo's entry and a gate), pass that path as `ledger=` with `board_only=True` to ledgerboard's `plan_edit`, so `_decide_ledger` writes no ledger file and `closes()` reads the ledger as it stands; where it returns None, pass neither, since ledgerboard refuses `board_only` on a line with no gate and the board alone is written already. `lifts = None` alone is not enough on a gate line, since `_decide_ledger` falls back to the `ledger` directory beside the board. Either way the fixed text is no lifting answer, so the line stays open. On a repo whose ledger is v1, ledgerboard refuses the gate line's press in its own words, as it refuses any decide lift there; that is out of scope. Today `_lift_ledger` and `ledgerboard`'s `_decide_ledger` would run the lift for a `Context:` naming one entry and a gate, and `decide_lift` refuses an `act` line.
- **The decided line still covers its entries**, as §4.5 says, at both sites that drop an entry's own row:
  - `asked_entries` in `src/shiftlead/ui/queue.py` skips decided lines, and `split_later` calls it with `[*due, *ahead]`, while `board_horizon` (`src/shiftlead/ui/inbox.py`) has already moved a decided row to `hz["waiting"]`. Pass the waiting rows to it too, and count an open `act` line decided *have a session do it* as asking.
  - The card's own cover in `queue.py` (the loop after *a board line that names an entry is the question itself*) takes only lines whose `want` is in `WANTS`, and a waiting row's want is `read`. Let such a line cover there too, whatever its section.

  A decided `decide` line is unchanged at both.
- **After the press.** The row is drawn as any decided row: under *Waiting on them*, uncounted, until a session closes the line; its waiting words name the start row where the team is stopped, and where the team has never run (no record, so no start row) they read the existing *waiting on the next session to read <repo>'s board*; nothing new is drawn for it. It comes back among the Do items only as a stuck row or once `BOARD_WAIT_DAYS` pass. Back, it is drawn by `inbox_row.html`'s decided branch (`{%- elif e.decided %}`, which draws no answers), with the controls a returned decided row has today: Reply, Snooze and Done in the Inbox's footer, Done behind a card's ⋯. There is no second Have a session do it, since the flag is false on a decided line. Nothing here changes those controls. The line is a work order through `workorders.py`'s existing filter, unchanged.
- **Help.** `tests/test_help.py` holds `help.py`'s `HELP` to the bullets under §4.5a *The help text* word for word, and each key to one `SCREENS` group. So the build PR adds a bullet to that list in `docs/design/4.5a-controls.md`, *- **Have a session do it** (Inbox board row) — <the wording>*, and the matching `Help` in `src/shiftlead/ui/help.py` with the key `board-have-a-session-do-it`, beside `board-go-with-it` and in the same `SCREENS` group (Inbox). The wording: *Asks a session to do this step: it goes to the repo's team as a work order. The session does it, hands it to the repo it belongs to, or, if only you can do it, gives it back to you with the exact steps to copy. Nothing runs from the press.* Run the doc-bound help tests, and the tests that read §4.5a's rows as keys (`grep -ln 4.5a tests`, run in the background) for the new row *Have a session do it*.
