## TD-2050: ao stage end: the one command that ends a stage, checked by the home

**Priority:** Medium
**Type:** feature
**Added:** 2026-11-22
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** ad53bc6787a640fc99881d62355d0e4e
**Blocked by:** TD-2048, decision (paul)
**Part of:** TD-1954

**Why:** The design has a session end its stage by naming one outcome, which the home checks against the facts before it writes the move. This is the only way a session changes where an entry is.

**Ask:** Should the builders start on the command a session ends its stage with?

**Fix:** Build design §4.9c *An outcome is the session's word, checked*, *A verdict is on the stage record*, *One holder ends a stage* and *Where an outcome goes*, and §4.7 `ao stage end` and `ao stage show`: the call to the home, one repo's calls taken one at a time, each outcome's fact checked, a refusal that names the fact, the move written, the verdict with its head, the review comment the home posts for a ship or a changes wanted, limits and the cap. An audit's outcomes and their checks are TD-2053's, not this entry's.

**Done when:** Each outcome is refused when its fact does not hold and taken when it does; a call from a session that is not the holder is refused; a repeated call is answered with where the entry went; with the home unreachable the command fails. A limit's fourth move and the 26th move at a cap of 25 go to the person. Settled and written down: how the home finds the entry's branch and pull request at the first work pushed. `ao stage end` never waits for a pull request. Lands with no session calling it.
