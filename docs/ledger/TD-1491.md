**Fix:** Design first: `/shiftlead-feedback`, a procedure doc plus a thin skill that points at it (as `/cadence` does), reviewing seats' transcripts for machinery friction.

Phase 1, local:
- the person picks the seats and a window;
- a deterministic extractor script condenses each transcript (assistant text, prompts, doorbell lines, tool errors), reading Claude Code's project directories (`~/.claude/projects/*/*.jsonl`) and Gemini's chats (`~/.gemini/tmp/<profile>/chats/session-*.jsonl`; its `history/` directory is empty), so the agents read condensed text;
- one agent per seat, with a fixed finding schema (date, what, how often, why, fix);
- dedupe against the open and archived ledgers of shiftlead, agent-cadence and ledgerboard by id and title, not by keyword alone;
- group the findings by cause, with a noise figure;
- the person approves before anything is filed, and each part goes to the repo that owns it.

Phase 2, reports from other users, with a privacy design round of its own:
- they install ShiftLead from a clone (`pip` from `file://<clone>`), so their ledger is local, and the repo is public, so a fresh fetch is always possible. Dedupe runs on their machine after `git fetch`;
- the report carries only structured findings: new ones (category, the symptom in the agent's words, frequency, fix) and *+1 on TD-n* counts for known ones, with the ShiftLead commit. It never carries transcript text or quotes;
- it passes the publish check (agent-cadence's `cadence_layer.py --publish-check`, with its `publish-gate` and `publish-names` keys), and the person approves it before it is sent;
- off by default. The channel is an issue template first and an aggregator later.

**Done when:** Phase 1's design names the extractor's inputs and output, the finding schema, the dedupe rule and the approval step, and its builds carry `Part of: TD-1491`. Phase 2 has its own privacy design round before any build.
