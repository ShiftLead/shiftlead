## TD-1946: The person can read what the disk sweep holds, frees and keeps on every host

**Priority:** Medium

**Why:** The person cannot see what the disk sweep frees or keeps, so a disk that fills again looks like the sweep's failure or nobody's (TD-1921). Design §4.6 *The sweep's reading* and §4.7 `ao disk` show it per host, before a pass and after it.

**Ask:** The disk clean-up design ran a fifth review round, which closed two gaps; should a session run one more round before the build?

**Location:** design §4.6 *The sweep's reading*, §4.7, §4.4a (the `act` link method); src/sessionorc/, src/shiftlead/cli.py

**Fix:** Build design §4.6 *The sweep's reading* and §4.7 `ao disk`: each pass writes `disk.json` in the host's home from TD-1945's pass result (per kind the bytes held and removed this pass, each kept item with its why, the free space of the file system holding `scratch_root`, in bytes and inodes by `os.statvfs`) and keeps a dated line per pass for 30 days, from which the 30-day totals are read; the host agent answers `disk` (the reading) and `disk_dry_run`, which name no record, so a node's goes over the `act` link method addressed by a `host` param as `name_check` is (§4.4a): both join `agent_common.NODE_ACTS`, the `host` routing `name_check` has in `agent_remote._act_host`, in the act path's guard that refuses an `id` naming no remote record, and in `agent_link`, and `identity.READS`, never `modes.NODE_ACTS` (a session's offline set, which `name_check` is not in), and the home's act path picks `DIGEST_TIMEOUT` for them by method name, as `DIGEST_READS` does for reads, where every other act keeps `ACT_TIMEOUT`; a dry run removes nothing, writes no `disk.json`, leaves the worktree pass's cursor, runs every kind under one deadline, `SWEEP_DRY_S` (240 s, checked between steps as `worktree_holds`' `deadline` is, so the reply comes at most one step past it and the lock frees when the thread ends), weighing worktrees in path order from the first and saying *partial* when it stops short, and is refused while a pass holds the sweep's lock; `ao disk [--host] [--dry-run] [--json]` prints every host's, `disk` and `disk_dry_run` with no `host` at the home asking itself and every node at once (new code in each handler: its own result and each node's through `_route_act` with `host` set, under `asyncio.gather`) and returning `{host: entry}`, each entry the reading or `{"error": "<why>"}` (a node's `RpcError`, timeout or refusal such as *a pass runs*, never failing the call), with `host` that host's route alone; off the home either one returns the bare reading carrying its `host` field (the link pops the `host` param before the handler runs), which the CLI keys by that field so `--json` prints `{host: entry}` either way; the home's own refusal (*a pass runs*) its own entry as a node's is; and the CLI waiting `DIGEST_TIMEOUT` plus `CALL_TIMEOUT` (as `ao feedback`'s reads do); at a node it reads its own host alone and refuses another with the link's own refusal (`agent_remote._node_mux`'s *… ask the home*); a host that does not answer named *unreachable*, and a `scratch_root` under a tenth free of bytes or of inodes drawn as a warning, a file system reporting no inode count (`f_files` 0) drawing no inode warning.

**Done when:** In a scratch home, after a sweep `ao disk --json` prints each kind's bytes held, removed in the pass and in 30 days (a pass dated 31 days back left out), each kept item's why and `scratch_root`'s free space; with that free space under a tenth, of bytes or (a separate case) of inodes, by a test's stubbed reading, `ao disk` prints the warning, and a stubbed `f_files` of 0 draws none; `ao disk --host <node> --json`, and a node's own `ao disk --json`, print the same `{host: entry}` shape, one entry; after a host-agent restart the bytes held read *partial* until each item is measured; a node's `ao disk --host` naming another host is refused; `ao disk --dry-run` lists what a pass would remove, is refused while a pass runs, and leaves `disk.json` and the worktree pass's place unchanged; with two nodes each stubbed to take 200 s, `ao disk --json` prints one entry per host in under 400 s; with one stopped, its entry is an error reading *unreachable* while the other answers; a node's dry run refused as *a pass runs* is that host's entry while the others answer; a node's `ao disk --dry-run` whose pass is stubbed to take 200 s answers at the home (past `ACT_TIMEOUT`), and one stubbed past `SWEEP_DRY_S` answers *partial* inside it; a session's `ao disk` on a node whose home cannot be reached is not refused by the offline gate (`modes.offline_refusal`).
