**Fix:** - **The worked reading.** In `src/sessionorc/agent_tick.py`'s rule 8 start (`_work_start`, ~2460, where `started` is pruned to `WORK_DAY`), before `_work_held` reads the bounds: for each instant in `started` not in the home's team record's new `work_worked` list, read it *worked* when any of the team's records (`records`, live and ended) holds a `progress` entry with `source == "declared"`, `status` `claimed` or `done`, and `at` ≥ that instant and < the next instant in `started` (none: no upper end). A carried waiting claim keeps its old `at` (`copy.deepcopy`, ~3033) and so never matches. Append each newly worked instant to `rec["work_worked"]`; prune `work_worked` to the instants still in `started`, and pop it when empty, as `work_started` is. The tick's change check (~2220, `rec.get("work_started") == starts`) compares `work_worked` too, so a newly worked start is written.
- **Read it where the team is not being started too.** The reading runs on every tick a team has `work_started`, not only when a mark stands, so a start is marked worked while its records still hold the claim; put it in the per-team loop (~2207) before `_work_mark`, or in a helper both call — the builder's choice, one reading.
- **The cap.** `_work_held` (~2554): `if len([t for t in started if t not in worked]) >= agent_common.WORK_STARTS_DAY` holds `{why: day, count: <that number>}`. `WORK_EARLY` still reads `started[-1]`, every start. `WORK_STARTS_DAY` stays 3; the comment at `agent_common.py:89` says idle starts.
