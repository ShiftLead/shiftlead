**Type:** feature

**Owner:** grinder
**Kind:** build

**Location:** design §4.7 *Feedback*, §4.3 `conversations`, `marks_errors`, `read_transcript`, §4.4a NODE_READS, §4.8a; src/sessionorc/adapters.py (TranscriptEntry, Conversation); src/shiftlead/adapters/claude_code, gemini; src/sessionorc/agent_common.py (NODE_READS, ACT_TIMEOUT); src/sessionorc/agent_remote.py (_route_read); src/sessionorc/identity.py (READS); the RPC handlers; src/shiftlead/cli.py; tests/test_transcript.py, tests/test_identity.py

**Why:** TD-1491's design (§4.7 *Feedback*) gives the `/shiftlead-feedback` procedure a deterministic extractor that condenses a seat's transcripts over a window into text an agent reads. It reads through each tool's adapter, never a tool's files from core. The 2026-11-06 review the procedure replaces read Claude Code's and Gemini's files by hand.

**Fix:** Build §4.7 *Feedback*'s extractor and §4.3's additions:

- **§4.3**: `TranscriptEntry.error` on a `tool` entry, which `to_dict` carries only when True. The Claude Code adapter sets it in `read_transcript` from the tool result's `is_error`. The class attribute `marks_errors` is True for Claude Code, and False where unset; Gemini CLI's is TD-1719. Add the optional `conversations(cwd, profile) -> list[Conversation] | None`, where `Conversation` is `(id, first_at, last_at, size)`, oldest first, read from each file's head and tail only. Claude Code reads the profile's `projects/<munged cwd>/*.jsonl`. Gemini CLI reads the top-level chats of the projects whose `.project_root` names `cwd`. The conformance suite (TD-112) names it among the reads an adapter declares.
- **RPCs**: add `conversations {id, since, until}` and `transcript_digest {id, conversation, profile, since, until, zone, skip}`, both added to `NODE_READS` and to `identity.READS` (never gated).
  - `conversations` asks every profile the adapter's `profiles()` lists. It keeps one entry per `id`, preferring the record's own profile. It refuses a shell with *a shell has no transcript*, and answers `{marks_errors, conversations}`. Both are bounded by one constant, `DIGEST_TIMEOUT = 300` s, by RPC name: the CLI calls them with `_timeout=DIGEST_TIMEOUT`, and the home's `_route_read` forwards them to a node's record with it, not `ACT_TIMEOUT`, the node serving them as `rpc_conversations` and `rpc_transcript_digest` through `_read`. A node forwards no read: at a node, another host's record is *no session*. Agent adapters without the method are refused *the <adapter> adapter lists no conversations (§4.3)*.
  - `transcript_digest` takes `profile` as required. It pages `read_transcript` back by `before`, 100 turns a page, until it holds a dated entry older than `since`.
  - Each line form is as §4.7 lists them, rendered in the caller's `zone: {name, offset}` (the offset where the name is null or unresolvable), with `since` inclusive, `until` exclusive and the first `skip` entries at `since` dropped:
    - day lines;
    - `HH:MM` leads, with continuation lines indented;
    - a prompt cut to three lines;
    - whole text;
    - a `✗` line's `<call>` cut to 120 characters, its result kept to three lines or 300 characters, and `→ (no result)`;
    - collapsed calls;
    - the subagent line, never counted in a run, and a lone `sidechain` entry's;
    - compaction;
    - no thought.
  - An undated entry, of any kind, takes the instant before it. A reply that would pass 4 MiB as JSON ends at the last prompt before that point, else at the last entry before it. It always holds at least one entry, and an entry that alone passes the point is written to 64 KiB with *(cut)*. That prompt or entry opens the next reply. `next` is then `{at, skip}`, `skip` counting the window's entries at that instant consumed, written or not; otherwise it is null. Every reply opens with its first entry's day line; the CLI drops one that repeats the last it wrote.
- **CLI**: the `ao feedback` parser, whose bare form prints usage and exits 2, and `ao feedback digest <seat>… --since <when> [--until <when>] --out <dir> [--part-bytes N] [--skip <conversation>…] [--list]`.
  - `<when>` is a local day or an instant. The CLI resolves `--since` and `--until` (a local day or an RFC 3339 instant; `--until` now) once to UTC instants, sends `zone` (`TZ`, else `/etc/localtime`, and the offset in minutes), and writes RPC instants (UTC) local; and bounds each call at 300 s.
  - `--skip` is repeated, once per conversation, matched by id in every record.
  - The calling session's own conversation, its `SHIFTLEAD_SESSION` record's `adapter_id`, is always skipped where there is one. A conversation an earlier record listed is listed only under that one.
  - The CLI calls again with `next`'s `since` and `skip` until `next` is null.
  - It writes `<dir>/<record id>.txt` (the id as `ao status --json` prints it), or `<record id>.1.txt` and on, split at a conversation header, else the last prompt before the bound, else the last entry before it, never inside an entry. Each conversation goes under its `## <id> · <profile> · <first_at> → <last_at>` header; a part that starts inside a conversation repeats the header with *(continued)* and its day line.
  - It prints the `--json` index §4.7 gives, `{since, until, records: [...]}`.
  - A record with none in the window gets no file. A record whose host does not answer, or whose read is refused or passes its bound, is listed with its `error`, and the others go on; the run exits 1.
  - `--list` needs no `--out` and prints one row per conversation (record, id, profile, local span, size), or each record's `conversations` answer under `--json`.
  - It writes nothing outside `<dir>`.
- Update `tests/test_transcript.py`'s `NODE_READS` set.
