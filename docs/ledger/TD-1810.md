## TD-1810: The repo reading stamps each open PR filing or not (TD-1804's reading)

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-14
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** b1954c77816447a4871e03ae11982c0a
**Part of:** TD-1804

**Why:** The repo reading must say which open PRs are filing PRs before any order can be read from them (design §4.4 *A filing PR nobody holds is a work order*, TD-1804). Today the changed files are read only for `held`, and only where the repo has a held key.

**Location:** design §4.4 A filing PR nobody holds is a work order (A filing PR); src/sessionorc/reports.py (pr_reading, _held_flags), workorders.py (filing_paths), agent_tick.py (the pr_reading call)

**Fix:** Build the reading half of design §4.4 *A filing PR nobody holds is a work order*, the bullet *A filing PR*:
- `reports.filing(files, root) -> bool`: true when every changed file is under the repo's ledger (`ledger.ledger_path`: a v2 directory, its `archive/` included, or a v1 ledger's one file) or is the board (`workorders.board_rel`) or the board's archive (`workorders.archive_rel`); an empty file list is false. Mind the import direction: `reports` may need the two paths passed in rather than importing `workorders`, if that would cycle.
- In the held read (`reports._held` or wherever `held.match` is applied in `pr_reading`): stamp `filing` and `filing_head` on every open PR that is not a sync PR, once per head, carried from `olds` as `held` is, and read again for a changed head — whatever the held key, so a repo with an empty key reads files for `filing` alone (and leaves `held` as today). One `pr_files` call serves both `held` and `filing` when both are due; the reads share `HELD_READS`, rows never read first, oldest first; a failed read keeps the last word; a PR never read carries no `filing`.

**Done when:** The repo reading carries `filing` and `filing_head` on each open non-sync PR it has read, true exactly when its changed files are all ledger, board or board archive, with tests for: a ledger-only PR, a ledger-and-board PR, a PR touching one other file, a repo with an empty held key (still read), a changed head (read again), a failed read (last word kept), and one `pr_files` call serving `held` and `filing` together.
