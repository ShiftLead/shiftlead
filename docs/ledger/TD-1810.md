**Location:** design §4.4 A filing PR nobody holds is a work order (A filing PR); src/sessionorc/reports.py (pr_reading, _held_flags, pr_files, LIFT_PREFIX), held.py (the paginated file reader, pr_read), gatesweep.py (LIFT_BRANCH), workorders.py (filing_paths), agent_tick.py (the pr_reading call)

**Fix:** Build the reading half of design §4.4 *A filing PR nobody holds is a work order*, the bullet *A filing PR*:
- `workorders.filing_paths(root)` (POSIX strings relative to the root): always both `ledger.ledger_path` and `ledger.archive_path` of it, with no layout test (a v2 directory, its `archive/` included; a v1 file and its archive file), the board (`workorders.board_rel`) and the board's archive (`workorders.archive_rel(board_rel(root))`).
- `reports.filing(files, paths) -> bool`: true when every changed file is one of `paths` or under a directory among them; false for an empty list; a file matches a path when it is that path or under it as a directory (`f == p or f.startswith(p + "/")`). `reports` never imports `workorders`. `pr_files` returns a renamed file's old name (`previous_filename`) beside its new one, for `held` and `filing` alike; `held.pr_read` (`ao pr held`'s own read) reads the files the same way — the paginated reader moves into `held` (which `reports` imports; `reports.pr_files` calls it), and `pr_read` keeps `mergedAt` (`held_missed` reads it) by its own call; the short-of-`changedFiles` error goes, and the merged-without-its-read check (design §6) matches a renamed file's old name too; design §4.7 `ao pr held` and §6 say so — both names and every file (paginated, never `gh pr view`'s 100-file cap), so the reading and the merge gate never disagree.
- `pr_reading` takes `filing=` (the paths) beside `held=`; the tick passes `workorders.filing_paths(root)` as it passes the held key (two checkouts sharing one reading: the first root's). In the held read (`reports._held_flags`): stamp `filing` and `filing_head` on every open PR that is not a sync PR and whose head branch is not under `lift/` (a new constant `reports.LIFT_PREFIX`, which `gatesweep.LIFT_BRANCH` becomes; `reports` never imports `gatesweep`), once per head, carried from `olds` as `held` is, read again for a changed head, whatever the held key (an empty key reads files for `filing` alone and leaves `held` as today; a `lift/` PR's `held` is still read as today, only its `filing` is not). One `pr_files` call serves both when both are due; the reads share `HELD_READS`, due rows oldest first by `created` as today; a failed read keeps the last word; a PR never read carries no `filing`.
- This build touches a held path (`src/sessionorc/**`): once green, its author asks the techlead reader (`ao msg --kind ask --pr <n>`).

**Done when:** The repo reading carries `filing` and `filing_head` on each open PR (not a sync or lift PR) it has read, true exactly when its changed files, renamed files' old names included, are all ledger (v2 directory, or v1 file and archive), board or board archive, with tests for: a ledger-only PR, a ledger-and-board PR, a PR touching one other file, a file renamed into the ledger, an empty file list, a PR on any `lift/` branch, live or not (not stamped), a repo with an empty held key (still read), a changed head (read again), a failed read (last word kept), one `pr_files` call serving `held` and `filing` together, and a file renamed out of a held path read held by both the reading and `ao pr held`.
