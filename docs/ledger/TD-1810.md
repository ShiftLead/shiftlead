## TD-1810: The repo reading stamps each open PR filing or not (TD-1804's reading)

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-14
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** b1954c77816447a4871e03ae11982c0a
**Part of:** TD-1804

**Why:** The repo reading must say which open PRs are filing PRs before any order can be read from them (design §4.4 *A filing PR nobody holds is a work order*, TD-1804). Today the changed files are read only for `held`, and only where the repo has a held key.

**Location:** design §4.4 A filing PR nobody holds is a work order (A filing PR); src/sessionorc/reports.py (pr_reading, _held_flags), workorders.py (filing_paths), agent_tick.py (the pr_reading call)

**Fix:** Build the reading half of design §4.4 *A filing PR nobody holds is a work order*, the bullet *A filing PR*:
- `workorders.filing_paths(root)`: the ledger's paths (`ledger.ledger_path`: a v2 directory, its `archive/` included; or a v1 ledger's file and its `ledger.archive_path`), the board (`workorders.board_rel`) and the board's archive (`workorders.archive_rel`).
- `reports.filing(files, paths) -> bool`: true when every changed file is one of `paths` or under a directory among them; false for an empty list. `reports` never imports `workorders`. `pr_files` returns a renamed file's old name (`previous_filename`) beside its new one, for `held` and `filing` alike.
- `pr_reading` takes `filing=` (the paths) beside `held=`; the tick passes `workorders.filing_paths(root)` as it passes the held key (two checkouts sharing one reading: the first root's). In the held read (`reports._held_flags`): stamp `filing` and `filing_head` on every open PR that is neither a sync PR nor a lift PR (`reports.lift_of(branch)`), once per head, carried from `olds` as `held` is, read again for a changed head, whatever the held key (an empty key reads files for `filing` alone and leaves `held` as today). One `pr_files` call serves both when both are due; the reads share `HELD_READS`, due rows oldest first by `created` as today; a failed read keeps the last word; a PR never read carries no `filing`.

**Done when:** The repo reading carries `filing` and `filing_head` on each open PR (not a sync or lift PR) it has read, true exactly when its changed files, renamed files' old names included, are all ledger (v2 directory, or v1 file and archive), board or board archive, with tests for: a ledger-only PR, a ledger-and-board PR, a PR touching one other file, a file renamed into the ledger, an empty file list, a lift PR (not stamped), a repo with an empty held key (still read), a changed head (read again), a failed read (last word kept), and one `pr_files` call serving `held` and `filing` together.
