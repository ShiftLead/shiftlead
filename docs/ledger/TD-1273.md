## TD-1273: No test resolves both a joined run and a row's own run it covers, so `AO.pathProvider`'s *the joined run wins* rule is untested

**Priority:** Medium
**Type:** debt
**Added:** 2026-10-30 (test-audit-ao-1, auditing the last ten merged PRs)
**Owner:** grinder
**Kind:** build
**Status:** Open
**Location:** `src/shiftlead/ui/static/app.js` (`AO.pathProvider`: `const links = (paths) => runs.filter((r) => paths[r.path]).filter((r, i, ok) => !ok.slice(0, i).some((k) => r.start < k.end && k.start < r.end))`); `tests/test_ui_focus_paths.py` (`WRAP_PROBE`)

**Why:** #2721 (TD-1259) comments *a joined run the host resolved wins over a run of the row alone it covers* and drops overlapping links. Probe at `origin/main` 255921409, with `PYTHONPATH=$PWD/src pdm run pytest -q tests/test_ui_focus_paths.py tests/test_ui_transcript_paths.py`: replacing the overlap filter `!ok.slice(0, i).some((k) => r.start < k.end && k.start < r.end)` with `true` gives all passed. `test_a_path_that_wraps_or_is_cut_across_rows_is_one_link_on_every_row` resolves only one of the two runs in each case (the whole path, or the row's own `src/a/b.py` where the joined `src/a/b.pyand` is no file), so two links over the same cells are never produced. With the filter gone a row whose joined and own runs both resolve hands xterm two overlapping links.

**Fix:** a `WRAP_PROBE` screen where the joined run and the row's own run it covers are both files; assert one link, the joined one.

**Done when:** replacing the overlap filter with `true` fails a test.

**Related:** TD-1259, #2721
