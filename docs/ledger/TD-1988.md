## TD-1988: The Focus page's Git card and file links follow the folder the session's tool reports working in

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-18
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 0c9dd298f224443ba2308e0a7afb6013
**Part of:** TD-1959

**Why:** A session that moves its work — checks out another branch in its worktree, or goes on in another worktree — leaves the Focus page reading its starting folder: the Git card does not say the branch is not the worktree's own, and a file the session prints from where it moved resolves against the wrong folder or not at all (TD-1959, design §4.2 *The record's `cwd`*).

**Location:** src/shiftlead/adapters/claude_code/hook.py and src/shiftlead/adapters/gemini/hook.py (the payload mapping); src/sessionorc/agent_hook.py (`rpc_hook`, the off-loop real path); src/sessionorc/agent_tick.py (the hook event applied; the launch; the status read, `_refresh_git`); src/sessionorc/models.py (the host-owned set); src/sessionorc/gitinfo.py; src/sessionorc/agent.py (`_resolve_paths`, `rpc_paths`); src/sessionorc/agent_serve.py (`_view`); src/shiftlead/ui/cards.py and src/shiftlead/ui/common.py (`editor_link`, `editor.cwd_url`); src/shiftlead/ui/app.py (`git_root`, `paths_for`, the Transcript page); src/shiftlead/ui/static/app.js (`AO.gitFiles`, the Git card summary, `AO.fileUrl`, `AO.openFile`); design §4.2, §4.3, §4.6, §4.5a

**Fix:** Build design §4.2 *The record's `cwd`*, §4.3 (the hook payload's `cwd`), §4.6 *A path in the pane is a link* and *A path in a transcript is a link too* (resolution against `cwd`, the press's folder) and §4.5a *Focus side panel, Git card: working in* (TD-1959):
1. **The field.** `cwd` on the record, host-owned beside `git` (§4.4a; `models.py`'s host-owned set), written from a hook payload's `cwd` by the Claude Code and Gemini CLI adapters (each `hook.py` maps it onto every event it translates, set before its branches; an event it drops writes nothing) and applied where the hook event is (`agent_tick.py`, as `transcript` is), stored as its real path and cleared when it equals `dir`'s real path (both resolved, so a symlinked `dir` is still itself). Only the main thread's live events write it: an event carrying `subagent` writes none, nor any applied with `queued=True` (stale or not), nor a permission event (`_await_permission`, never `_apply_event`). Compare the raw payload `cwd` with the last raw value first and resolve the real path only on a change, off the event loop, in `rpc_hook` (`agent_hook.py`) before the synchronous `_apply_event`, written only where its raw value is still the side table's last when the resolve ends, so an older event's slow resolve never overwrites a newer one; the last raw value is an in-memory side table beside `_git_checked`, dropped at a launch and on a forget. A new run's launch (start, resume, restart) clears `cwd` and `cwd_root`; an `exited` record keeps them. No other adapter writes it; a `shell` record never has it.
2. **The status read** (`agent_tick._refresh_git`, `GIT_EVERY`): `git.top` — `dir`'s top level as a real path, the press's folder choice's input on the page and in `/api/paths`, a node's record included; `git.worktree` — the folder name of `dir`'s top level where that is a linked worktree by git's test (`rev-parse --git-dir` differs from `--git-common-dir`, so a submodule is not one), absent on a main checkout; and the record's own `cwd_root` field, host-owned beside `cwd` in `models.py`'s set and written here, never computed in `agent_serve._view` — the git top level of `cwd` where that is not `dir`'s top level, else, where `cwd` is in no repository and outside `dir`, `cwd` itself; written only where `cwd` is an existing directory, absent otherwise; where `dir` is in no repository, `cwd`'s top level where it has one, else `cwd` outside `dir`. Its git calls reuse `gitinfo`'s 5-second timeout. A hook event that changes `cwd` clears `cwd_root` and makes the record's status read due (`_git_checked.pop(id)`); `_refresh_git` takes `cwd` before its thread runs and writes `cwd_root` (and sets `_git_checked`) only where the live `cwd` still equals it, else writes no `cwd_root`, leaves `_git_checked` unset (the record due) and writes `git` and `files` as ever. Nothing else reads `cwd`: `files`, `git_files`, Ready to close, the reap and the wind-down's checks stay on `dir`.
3. **`paths`** (`agent.rpc_paths`, `_resolve_paths`): a relative run resolves against `cwd` where the record has one, then against `dir`, the first that answers, both within the one ask (two `_resolve_paths` passes); an absolute or `~/` run is unchanged. The transcript page's asks are the same RPC and resolve the same way.
4. **The folder link** (`ui/cards.py` `record_editor`, `ui/common.py` `editor_link`): the Focus view serves `editor.cwd_url` beside `editor.url` — `editor_link(cwd_root, reach)`, under `record_editor`'s own gate (`here or reach`), absent under `open_in: none`, served under `folder_first: false` too (only a press's first launch honours it) — and the Transcript page is handed it beside its folder link the same way, there absent under `folder_first: false` as its folder link is. `/api/paths` (`ui/app.py` `paths_for`, the `id:` context) makes the same choice server-side: a resolved path under the record's `cwd_root` by the deeper-root rule gets `editor_link(cwd_root, reach)['url']` as its `folder`.
5. **The page** (`static/app.js`): the Git card's summary reads *worktree <folder> · on branch <branch>* before its unpushed count where `git.worktree` is present and is not the branch's name, and *worktree <folder> · detached at <sha>* on a detached head (read from the record, so a remote record's card draws it too); a *working in <path>* line under the summary, above the pick, where the record has `cwd_root`: the full path cut from its left with an ellipsis where the card is narrow and whole on hover, a link to `editor.cwd_url`, text where the view serves none. A pane or transcript file link whose resolved path lies under `cwd_root`, where `cwd_root` is the deeper of it and `git.top` (else `dir`, where it is in no repository) that holds the path (a worktree under the main checkout's `.claude/worktrees` lies under both), launches `editor.cwd_url` first in place of the Session card's folder link. The pane's cache (`AO.pathProvider`'s and `AO.pathsAsker`'s `known`) and the Inbox and Queue `id:` askers key on the record's `cwd` as well as the run; the pane drops its cache and relinks when the feed brings a new `cwd`; the server writes the record's `cwd` on an Inbox or Queue row as `data-paths-cwd` beside `data-paths-ctx` (`ui/common.py` `paths_ctx`'s rows), and `AO.itemAsker` keeps one asker (its `meta` with it) per context and `cwd` pair, the `ctx` string `/api/paths` reads unchanged; the transcript page's asker lives as long as the page, a move seen at its next load.
6. **Tests**: `cwd` and `cwd_root` are each in exactly one ownership set (host-owned, `test_models`), and a node's clearing of `cwd` reaches the home's copy through the overlay; a hook payload with another `cwd` sets the field and one with `dir` clears it; a subagent's event, a queued one and a permission event write none; a launch clears both fields; a record whose `cwd` is another worktree carries that worktree's top level as `cwd_root`, one in a subdirectory of its own worktree carries none, one outside any repository carries `cwd` itself, and one whose folder was deleted carries none; a changed `cwd` clears `cwd_root` until the next status read; `git.worktree` on a linked worktree, absent on the main checkout and on a submodule; `paths` resolves a relative run against `cwd` before `dir`, and falls back to `dir` where `cwd` answers nothing; a run answered `null` before a move is asked again after it; a hook event landing mid status read leaves `cwd_root` unwritten and the record due; with `dir` in no repository and `cwd` an ancestor of it, a file under `dir` launches the Session card's folder; a `cwd` in a subdirectory of `dir` resolves first there; `/api/paths` with an `id:` context gives a path under `cwd_root` that folder's link, and none under `folder_first: false`; a reach record gets `editor.cwd_url` through its reach; the summary reads *worktree td-1153 · on branch td-1953-tools* on a linked worktree with another branch, the plain branch where the folder's name is the branch's and on the main checkout, the detached form on a detached head, and is drawn on a remote record; the *working in* line is drawn with its link, and as text under `open_in: none` and on a remote record; a file under a worktree nested in `dir`'s top level launches the worktree's folder first, and one under `dir` alone the Session card's.

**Done when:** On a session that checked out another branch in its linked worktree, the Git card's summary names both the worktree and the branch; on a session whose tool reports working in another worktree, the card holds a *working in* link that opens that folder, a relative path it prints resolves there and its press opens that folder's window first; `cwd` and `cwd_root` are host-owned and reach the home from a node; each case in the Fix is covered by a test.
