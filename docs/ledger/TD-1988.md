## TD-1988: The Focus page's Git card and file links follow the folder the session's tool reports working in

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-18
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 0c9dd298f224443ba2308e0a7afb6013
**Part of:** TD-1959

**Why:** A session that moves its work — checks out another branch in its worktree, or goes on in another worktree — leaves the Focus page reading its starting folder: the Git card does not say the branch is not the worktree's own, and a file the session prints from where it moved resolves against the wrong folder or not at all (TD-1959, design §4.2 *The record's `cwd`*).

**Location:** src/shiftlead/adapters/claude_code/hook.py (the payload mapping); src/sessionorc/agent_tick.py (the hook event applied; the status read, `_refresh_git`); src/sessionorc/models.py (the host-owned set); src/sessionorc/gitinfo.py; src/sessionorc/agent.py (`_resolve_paths`, `rpc_paths`); src/sessionorc/agent_serve.py (`_view`); src/shiftlead/ui/app.py (`git_root`); src/shiftlead/ui/static/app.js (`AO.gitFiles`, the Git card summary, `AO.fileUrl`); design §4.2, §4.6, §4.5a

**Fix:** Build design §4.2 *The record's `cwd`*, §4.6 *A path in the pane is a link* (resolution against `cwd`, the press's folder) and §4.5a *Focus side panel, Git card: working in* (TD-1959):
1. **The field.** `cwd` on the record, host-side beside `git` (§4.4a; `models.py`'s host-side list), written from a hook payload's `cwd` by the Claude Code adapter (`adapters/claude_code/hook.py` maps it onto every event it translates, set before its branches; an event it drops writes nothing) and applied where the hook event is (`agent_tick.py`, as `transcript` is), stored as its real path and cleared when it equals `dir`'s real path; no other adapter writes it; a `shell` record never has it.
2. **The status read** (`agent_tick._refresh_git`, `GIT_EVERY`): `git.worktree` — the folder name of `dir`'s top level where that is a linked worktree (its `.git` a file), absent on a main checkout; and the record's own `cwd_root` field, host-owned beside `cwd` in `models.py`'s set and written here, never computed in `agent_serve._view` — the git top level of `cwd` where that is not `dir`'s top level, else, where `cwd` is in no repository and outside `dir`, `cwd` itself; absent otherwise, and cleared with `cwd`. Nothing else reads `cwd`: `files`, `git_files`, Ready to close, the reap and the wind-down's checks stay on `dir`.
3. **`paths`** (`agent.rpc_paths`, `_resolve_paths`): a relative run resolves against `cwd` where the record has one, then against `dir`, the first that answers, both within the one ask (two `_resolve_paths` passes); an absolute or `~/` run is unchanged.
4. **The page** (`static/app.js`): the Git card's summary reads *worktree <folder> · on branch <branch>* before its unpushed count where `git.worktree` is present and is not the branch's name (read from the record, so a remote record's card draws it too); a *working in <~/path>* line under the summary, above the pick, where the record has `cwd_root`, a link by the editor button's folder form on it, drawn where the editor button is; a pane file link whose resolved path lies under `cwd_root` and not under `dir`'s top level launches `cwd_root`'s folder first in place of the Session card's.
5. **Tests**: a hook payload with another `cwd` sets the field and one with `dir` clears it; a record whose `cwd` is another worktree carries that worktree's top level as `cwd_root`, and one in a subdirectory of its own worktree carries none; `paths` resolves a relative run against `cwd` before `dir`; the summary reads *worktree td-1153 · on branch td-1953-tools* on a linked worktree with another branch and the plain branch on the main checkout; the *working in* line is drawn with its link, and as text under `open_in: none`.

**Done when:** On a session that checked out another branch in its linked worktree, the Git card's summary names both the worktree and the branch; on a session whose tool reports working in another worktree, the card holds a *working in* link that opens that folder, and a relative path it prints resolves there; each covered by a test.
