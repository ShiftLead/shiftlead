**Fix:** In `src/shiftlead/feedback.md`, write design §4.7 *Feedback*'s *Reports from other installs* into the procedure. The mode, before step 1's checkout check: `ao repo --all --json` (a failing `ao` stops), no entry named `shiftlead` is report mode; else `gh api repos/ShiftLead/shiftlead --jq .permissions.push`, `true` file mode, anything else or a `gh` not installed or not signed in report mode, a signed-in `gh` that fails stops; said with why in the first message, file mode also saying its filings are unscrubbed and public and offering report mode. Report mode's steps: step 1's seven-day proposal and no `feedback:` PR search; step 5's three sparse shallow clones into the scratch directory (a failed or empty clone *not deduped*), the build's day in place of `last`, *recurred* sent with `recurs`, *fixed after your build* named and not sent; step 7's groups with findings and no parts, *include*/*edit*/*merge*/*drop* and *counts:*; step 8's findings file (with `names` from the digest index), `ao feedback report`, its exit 1 loop through *edit*, its exit 2 stopping the run, the report shown whole with what the scrub cannot catch, its path and the form's address, and nothing sent; the clones removed. File mode's intake: step 1's `gh issue list … > <scratch>/reports.json`, never printed, and `ao feedback intake`'s output as the listing (login, age, findings, refused ones, the 100 limit), the person's pick, seats optional, a reports-only run skipping the window, the digest and the agents; step 4's seat `report #<number>`, merged only with reports' findings, the cause *inferred*, outside noise; step 5's `recurs` and build days, `known` counts open / *fixed since the report* / *no such entry*; step 7's per-report lines, groups in the session's own words naming the report in Why, counts by login, one report note per entry (`feedback report #<a>[, #<b>…]: seen <count>`) beside at most one seat note, *notes:* answering both, *close*/*leave* for refused reports; step 8's `Closes #<number>` lines with what each became, the no-PR close with its comment (*nothing new*, *already noted on TD-n*, *listed for <repo>'s maintainers*, *not read: <why>*), a cut report named, and the reports-only PR title with no `Window:` line. Change step 1's last-run search to keep only titles of the form `feedback: <since> → <until>`. Add `.github/ISSUE_TEMPLATE/feedback-report.yml`, an issue form: title `feedback report: `, no label, a line that the report is public, what it holds and that only the submitter's read catches what the scrub cannot, one required textarea with no `render`. Run `ao feedback --skill` and read it against the design.

**Done when:** Done when `ao feedback --skill` prints both modes and the intake as the design gives them, the issue form is in the repo, and a test holds the procedure's mode check, the `Closes` line and the reports-only title.
