**Status:** Open
**Part of:** TD-1285
**Location:** `src/sessionorc/cadence.py` (a new `precheck_person`); `src/sessionorc/reports.py` (`pr_reading`'s open rows: `precheck_line`); `src/sessionorc/agent_inbox.py` (the snooze kinds); `src/sessionorc/sync.py` (read: it declines a fork's PR); `src/shiftlead/teamrun.py` (`red_prs`, its `whose`); `src/shiftlead/ui/repo.py` (`pr_rows`); `src/shiftlead/ui/inbox.py` (a new `fork_pr_rows`, beside `red_pr_rows`); `src/shiftlead/ui/queue.py` (`item_home`'s refs, `want_of`, `item_ref`, the start test and `attach.put`'s `red` flag, ~264–274); `src/shiftlead/ui/app.py` (the two places that add `red_pr_rows`, ~1193 and ~1706); `src/shiftlead/ui/templates/repo_part.html` (`pr_row`, the `info-prs` hover); `src/shiftlead/ui/templates/inbox_row.html` (the red PR row's neighbour); `src/shiftlead/ui/static/app.js` (the `data-copy` handler, ~1030); `src/shiftlead/ui/static/app.css`; tests in `tests/test_ui_red_prs.py`, `tests/test_ui_queue.py`, `tests/test_ci_not_run.py` (its `pr_rows` call) and beside `pr_reading`'s

**Why:** TD-1285: since slice 1 (#2762) a fork's PR is no work order and no session is given its precheck line, which runs a stranger's code on the machine. Paul decided on 2026-10-30 that the person is shown the line once the fork's forge CI is green. The techlead answered the steer m-3529963efc91 with *count it* (m-1b3c7442eb02): no session may run the line, so nothing else moves the PR, and §4.5a already counts the PRs only the person can cure. The design is §4.5 screen 11 *Review*, §4.5a *Repo page, Review* and *Inbox row: fork's PR*, and §4.4 *A fork's PR is no work order*.

**Fix:**
1. `cadence.precheck_person(root, pr)`: the line the person types, never a session's, led by `cd <shlex.quote(root)> && `. In a pinned repo (`pinned(root)`, which reads `docs/cadence.toml` and resolves no tree) it is `agent-cadence run precheck.py --pr <pr> --fork-ok` (the console script, which resolves the pin from the checkout it runs in); otherwise it is `python3 [files/]scripts/precheck.py --pr <pr> --fork-ok`, as `precheck_typed`'s layout arm builds it, and, in that layout arm alone, None where that file is not on disk. It never calls `tree()`, which can block for minutes. `precheck_typed` is unchanged: its `typed()` line is the home venv's Python and launcher, which is a session's.
2. `precheck_line` is added per checkout in `agent_tick`'s `_read_repos`, after the reading is taken (~3656–3664), never inside `pr_reading`: one reading is shared by every checkout of a remote (`by_remote`), so each checkout's `prs` is a copy whose fork rows get `precheck_person(root, n)` for its own `root`. A GitLab reading's rows get none (it carries no `prechecked`).
3. *Ready to precheck* is one function in `teamrun`, read by the Inbox, the Queue and the Repo page: open, `fork`, not `draft`, not `conflicting`, `checks == "green"`, `prechecked is False` and `precheck_line` set. A sync PR is never ready.
4. `red_prs`: past `ORPHAN_AFTER`, a fork's PR that is not held reads `whose` *its author's*, checked before `DRAFT_WHOSE`. The Org facet's *· n red* and its hover take it as they are.
5. `pr_rows` gives each row `fork` (with `checks`, for the tag's title) and `fork_line` (`{line, diff}`) while the PR is ready. `diff` is the PR's URL plus `/files` (GitHub's diff page; a GitLab row is never ready). The line's `title` is *type it in a terminal on <home>, where <root> is*, `<home>` the home's host name (the `host` reading's `home`, else `host_name()` on the home), never a per-repo field: every reading is the home's. `pr_row` draws a `tag` **fork** titled as §4.5 screen 11 words it: *no CI on this head yet* with `checks` *none*, and the approval clause with *red* or `not_run`. With `fork_line`, it draws a second line: *yours, after reading the diff:*, the line in `mono`, a `btn sm ghost` **Copy** and a **diff ↗** link (`target="_blank" rel="noopener"`). The `info-prs` hover gains *a fork's PR is its author's; once it is ready to precheck its line is yours to run, after reading the diff*.
6. `fork_pr_rows(repos, records)` in `inbox.py`: one row per ready fork's PR in every repo, serviced or not, with `row: "fork_pr"`, `title`, `at`/`age` from the PR's `created`, no `branch`, `sid`/`id` `fork_pr:<repo>:<n>`, the text *`<repo>` #<n> · fork · CI green · <author>*, `line` (the `precheck_line`), `url` (the diff), and subject `kind_subject("fork's PR", "<repo> #<n>")`. `app.py` adds it wherever it adds `red_pr_rows`. `agent_inbox`'s snooze kinds gain `fork_pr`, in the list and in the refusal's words. `inbox_row.html` draws the row with the line titled as the Review row's, **Copy**, **Open** (the diff, not the PR as a red PR's Open is) and **Snooze ▾**. It is not added to `agent_notify`'s told rows (§4.10 *Not told*).
7. `queue.py`: `item_home` reads a `fork_pr` row's refs from its title alone; `want_of` gives it `do`; `item_ref` gives `''`, so it is in no *waits on me*; its item draws *#n fork — CI green, yours to precheck* with the line, **Copy** and **Open**, and no Start session, Answer row or ⋯ (the start test at ~264 excludes `fork_pr` beside `red_pr`; `attach.put` gives the item a `fork` flag beside `red`, and the two reads of `red` take it too: `items_start` ~603, so a card whose only item is a fork's PR keeps the header's Start session, and the page header's *Do n* ~712, which leaves it out, as a red PR is, counted on its card's pill alone). The item's macro draws no ⋯ and an empty `start`, as the red PR row's does.
8. Copy, on both rows, is a `data-copy` button. The `data-copy` branch of the document click handler gains a refusal: a write that rejects or throws toasts *clipboard blocked (needs https or localhost)*, false, as `AO.copyWith` does, which cures every `data-copy` button at once.
9. Tests: `precheck_person` in a pinned root, an unpinned root with the script and one without it (None), each led by `cd`; two checkouts of one remote, each fork row's line naming its own root; a fork row of `pr_reading` carries `precheck_line` and a row that is not a fork's does not. *Ready* is true only for a green fork's PR that is not a draft, not conflicting and has `prechecked is False`, and false with `prechecked` true, with red, pending, none or `not_run`, and for a GitLab-shaped row (no `prechecked`). `red_prs` gives *its author's* for a fork's PR past `ORPHAN_AFTER`, a fork's draft included. `pr_rows` and the rendered `pr_row` carry the tag and, while ready, the line and Copy. `fork_pr_rows` gives a row in a serviced and an unserviced repo. The Queue places it on the card whose entry its title names, its `item_ref` is `''` and it is absent from *waits on me*, counted on the Queue tab, and otherwise on the Inbox, counted there. A snooze of `fork_pr:<repo>:<n>` is accepted.

**Done when:** a fork's PR ready to precheck is counted for the person, as a Do item on its card or a *Needs you* row on the Inbox, and its Repo page row draws the **fork** tag and the line with **Copy** and **diff ↗**. The line is the person's form, with `--fork-ok`, and nothing runs it. The row and the line go once a `cadence/precheck` status is on the head. The tests above pass.
