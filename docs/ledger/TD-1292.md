**Why:** TD-1285: since slice 1 (#2762) a fork's PR is no work order and no session is given its precheck line, which runs a stranger's code on the machine. Paul decided on 2026-10-30 that the person is shown the line once the fork's forge CI is green. The techlead answered the steer m-3529963efc91 with *count it* (m-1b3c7442eb02): no session may run the line, so nothing else moves the PR, and §4.5a already counts the PRs only the person can cure. The design is §4.5 screen 11 *Review*, §4.5a *Repo page, Review* and *Inbox row: fork's PR*, and §4.4 *A fork's PR is no work order*.

**Fix:**
1. `cadence.precheck_person(root, pr)`: the line the person types, never a session's. In a pinned repo it is `agent-cadence run precheck.py --pr <pr> --fork-ok` (the console script, which resolves the pin from the checkout it runs in); otherwise it is `python3 [files/]scripts/precheck.py --pr <pr> --fork-ok`, as `precheck_typed`'s layout arm builds it. `precheck_typed` is unchanged: its `typed()` line is the home venv's Python and launcher, which is a session's.
2. `pr_reading` (GitHub): each open row with `fork` true gets `precheck_line`, `precheck_person(directory, n)`. The reading is made where the checkout is, so a node's repo gets its own line. The GitLab reading gets none and carries no `prechecked`.
3. *Ready to precheck* is one function in `teamrun` (or `reports`), read by the Inbox, the Queue and the Repo page: open, `fork`, not `draft`, not `conflicting`, `checks == "green"`, `prechecked is False` and `precheck_line` set. A sync PR is never ready.
4. `red_prs`: past `ORPHAN_AFTER`, a fork's PR (not a sync PR) that is not held reads `whose` *its author's*, checked before `DRAFT_WHOSE`. The Org facet's *· n red* and its hover take it as they are.
5. `pr_rows` gives each row `fork` (with `checks`, for the tag's title) and `fork_line` (`{line, diff}`) while the PR is ready. `diff` is the PR's URL plus `/files` (GitHub's diff page). `pr_row` draws a `tag` **fork** titled as §4.5 screen 11 words it: *no CI on this head yet* with `checks` *none*, and the approval clause with *red* or `not_run`. With `fork_line`, it draws a second line: *yours, after reading the diff:*, the line in `mono`, a `btn sm ghost` **Copy** and a **diff ↗** link (`target="_blank" rel="noopener"`). The `info-prs` hover gains *a fork's PR is its author's; once it is ready to precheck its line is yours to run, after reading the diff*.
6. `fork_pr_rows(repos, records)` in `inbox.py`: one row per ready fork's PR in every repo, serviced or not, with `row: "fork_pr"`, `sid`/`id` `fork_pr:<repo>:<n>`, the text *`<repo>` #<n> · fork · CI green · <author>*, `line` (the `precheck_line`), `url` (the diff), and subject `kind_subject("fork's PR", "<repo> #<n>")`. `app.py` adds it wherever it adds `red_pr_rows`. `agent_inbox`'s snooze kinds gain `fork_pr`, in the list and in the refusal's words. `inbox_row.html` draws the row with **Copy**, **Open** (the diff) and **Snooze ▾**.
7. `queue.py`: `item_home` reads a `fork_pr` row's refs from its branch and title, as a red PR's; `want_of` gives it `do`; `item_ref` gives `<repo>#<n>`; its item draws *#n fork — CI green, yours to precheck* with the line, **Copy** and **Open**, and no Start session, Answer row or ⋯ (the `!= "red_pr"` start test takes `fork_pr` too).
8. Copy, on both rows, goes through `AO.copyWith` (or a `catch` that toasts *clipboard blocked (needs https or localhost)*), not the bare `data-copy` handler, whose refusal is silent.
9. Tests: `precheck_person` in a pinned and an unpinned root; a fork row of `pr_reading` carries `precheck_line` and a row that is not a fork's does not. *Ready* is true only for a green fork's PR that is not a draft, not conflicting and has `prechecked is False`, and false with `prechecked` true, with red, pending, none or `not_run`, and for a GitLab-shaped row (no `prechecked`). `red_prs` gives *its author's* for a fork's PR past `ORPHAN_AFTER`, a fork's draft included. `pr_rows` and the rendered `pr_row` carry the tag and, while ready, the line and Copy. `fork_pr_rows` gives a row in a serviced and an unserviced repo. The Queue places it on the card whose entry its branch names, counted on the Queue tab, and otherwise on the Inbox, counted there. A snooze of `fork_pr:<repo>:<n>` is accepted.

**Done when:** a fork's PR ready to precheck is counted for the person, as a Do item on its card or a *Needs you* row on the Inbox, and its Repo page row draws the **fork** tag and the line with **Copy** and **diff ↗**. The line is the person's form, with `--fork-ok`, and nothing runs it. The row and the line go once a `cadence/precheck` status is on the head. The tests above pass.
