## TD-1704: The status line's reporter child could go back to a five-second wait and no test would fail (#3512)

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-12
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 4f3b2dea5de146da8eb7e34a77b35adb
**Location:** tests/test_statusline.py; src/shiftlead/adapters/claude_code/hook.py (aside)

**Why:** Found by the test seat auditing #3512 (TD-1696). The PR's one new test, `test_the_reporter_outwaits_a_hooks_bound_and_never_overlaps_the_next_report` (tests/test_statusline.py), asserts only the constants: `REPORT_WAIT > 5.0` and `3 * REPORT_WAIT < STATUSLINE_REFRESH`. The fix is that the forked reporter waits that long, and that line is `fn(REPORT_WAIT)` in `aside` (src/shiftlead/adapters/claude_code/hook.py:382). Only a coarse test would catch it going back.

Probe on origin/main (cecdf508b): change hook.py:382 to `fn(5.0)` (the old bound) and run `pytest -q tests/test_statusline.py`: 10 passed. Reverted afterwards. Not caught because the `home` fixture (:173) replaces `aside` with `lambda fn, wait=...: fn(hook_mod.REPORT_WAIT)`, so no test runs the real child's call, and no test reads the `timeout` that `report_usage` hands the socket steps. The same mutation on #3517's `review_pr` clause fails its test, so that PR is covered.

**Fix:** Add a test that runs the real `aside` child's callable (or `report_usage` as the child calls it) with the socket helpers stubbed, and asserts every step receives `REPORT_WAIT`. Check by setting hook.py:382 to `fn(5.0)`: the test fails.

**Done when:** A test fails when the `aside` child passes a bound other than `REPORT_WAIT` to the report, shown by setting hook.py:382 to `fn(5.0)`.
