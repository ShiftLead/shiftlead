## TD-1755: The pre-review script: scripts/design_prep.py checks a design's prep file at a commit and prints the pass line every reviewer meets first

**Part of:** TD-1720

**Why:** Part of TD-1720's design (§4.9c *What a design's author prepares before a review*): the pre-review script that checks a design's prep file against its commit and gates every reviewer. Of the 510 design-review findings a script could catch, its four checks would have caught at most 225, all but 9 of them only through what the author declares.

**Ask:** Should TD-1720's builds go ahead as written after four review rounds, which ended at the cap with one build-changing finding in round 4 (fixed, and read by round 4's second review) and two recurring topics, which designs the gate holds and what a waiver matches? Go, One more round, or Hold with a note.

**Location:** scripts/design_prep.py, tests/test_design_prep.py

**Fix:** Build `scripts/design_prep.py` as design §4.9c *What a design's author prepares before a review* says, from *The prep file* through *The gate*, with `tests/test_design_prep.py`:
- `--entry TD-<design>` reads `docs/reviews/TD-<design>.prep.yml` at the commit (yaml.safe_load; the four keys `claims`, `rules`, `new`, `waive`, each a list, any absent or empty; an unknown key or a malformed item is NOT PREPARED). A claim has `says` and one of `at` (`path` or `path:line`, with optional `has`) or `count` (`glob`, optional `grep`, optional `lines`) with `is`; it runs no command.
- `--rev <commit>` (default `HEAD`) and `--base <commit>` (default the merge base with the local `origin/main`): every commit is read in a temporary detached worktree added to the invoking worktree's repository at a fresh `mktemp -d` path named `design-prep-*` under the temp dir, removed in a `finally`, every git and subprocess call under a `timeout`; each run first lists the worktrees (`git worktree list --porcelain`) and removes each `design-prep-` one whose directory is gone with `git worktree remove --force`, never a bare `git worktree prune`; with `HEAD` and uncommitted or untracked changes under the read paths or to the prep file (`git status --porcelain` on them), NOT PREPARED. `--advisory` prints the same lines under `design-prep: ADVISORY · …` and exits 0.
- The changed text: lines added against the base in `docs/design/`, `docs/briefs/`, `docs/ledger/`, `docs/synopses/`, `docs/glossary.md`. The rules' text: every paragraph of every file under `docs/design/`, `docs/briefs/`, `docs/synopses/`, of `docs/glossary.md`, and of the ledger entries the PR adds or changes, a paragraph a block between blank lines, except that each top-level list item with its continuation lines, each table row is one of its own, and in a ledger entry each `**Field:**` body is one paragraph, lists inside it included. Every match is on a paragraph with whitespace runs collapsed to one space; `has` exact within one line of the raw file, fenced lines included. Fenced blocks are read by no check.
- The four checks in the section's order: rules (`find` a Python regex; terms whole-word, case-insensitive; a `find` matching fewer than two paragraphs is a flag); claims (`at` a repo path or `agent-cadence:<path>` in the pinned tree, the line in range, `has` present; `count` over the glob at the commit equal to `is`; the path scan of the changed text: a maximal run of `[A-Za-z0-9_./-]` holding `/` and ending in a file extension, a `:<line>` after it and any trailing `.,;:)` dropped, not starting `~` or `/`, not part of a URL, not inside a token holding `<`, `*` or `$`, a markdown link's target resolved against its file's directory and any other against the repo's top or the pinned tree, or a `new` path that does not exist yet and whose `by` entry, in the ledger, its archive or added by the PR, holds the path in its Fix — a `new` path that exists is a flag); pointers (a design `§<n>` against `docs/design.md`'s index, `§<n> *Title*` against the section file's bold leads and headings, the title equal, ignoring case and trailing punctuation, to the lead whole or its part before a colon or an opening parenthesis, a `§` skipped when the word before it or before the first `§` of its comma- or *and*-joined list is *cadence*, *ADR*, *SPEC* or *rationale*, or a link or a file name; `TD-<n>` in the ledger, its archive or the PR's new entries); tools (`agent-cadence run ledger.py --check --since <base>` and `pytest tests/test_synopses.py tests/test_design_doc.py tests/test_history.py -q` in the temporary tree with its `src` first on `PYTHONPATH`, each under 300 s: ledger errors and pytest exit 1 are flags; a tool that will not start, a timeout or another pytest exit is one that could not run).
- Each flag's file and text as the section's *A flag's file and text* lists them (a rule's flag is its rule, file and paragraph, whitespace collapsed; a rule waiver names `rule`, `file` and `text`, and hides that rule's flag on a paragraph beginning with its text, which is at least eight words or the whole paragraph; a rule flag's `<what>` leads with the rule's name and the missing terms); `<what>` prints the text verbatim; a paragraph's flag gives the line the paragraph starts. A waiver hides every flag with its check, file and text; a waiver hiding nothing is a flag no waiver hides; `waived <n>` counts the flags hidden.
- Exits as *Its result is a pass line* writes them: NOT PREPARED (2) decided before any check; then every check runs; any flag left is FAIL (1), listing too each tool that could not run; with no flag, a tool that could not run, a crash, or an unresolvable commit or base is CANNOT RUN (3); else PASS (0) with the commit, the base and its counts.
- The script runs its tools under `sys.executable` and is run as `pdm run python scripts/design_prep.py`. The tests build a scratch repo per case (git init, a fake `origin/main` ref, design and ledger files) and cover each check passing and failing, a phrase wrapped across lines, a glossary-shaped list of bullets read item by item, a markdown link's relative target, a waiver on one rule paragraph leaving another's drift flagged, a paragraph rule waiver shorter than eight words and not the whole paragraph refused as NOT PREPARED, a not-repeated flag hidden by a waiver on the prep file whose text is the rule's name, a rule waiver leaving another rule's flag on the same paragraph standing, a Fix whose bullets are read as one paragraph, a path ending a sentence with a full stop, a title matching a lead's part before its colon, a title cited without its trailing full stop, term matching (`pass` against *bypass*), a count by files and by lines, a `new` path with and without its build and once it exists, a pointer after *cadence* and in a cadence list skipped, a waiver hiding two flags and a stale waiver, the exit precedence (flags with a tool that could not run is 1), a dirty work tree and an untracked design file refused, `--advisory` exiting 0 on a FAIL, `--rev` leaving no worktree behind and a stale one pruned, and each NOT PREPARED and CANNOT RUN cause.
Fixed, not reviewed; the builder checks it: F67 (docs/reviews/TD-1720.md).

**Done when:** Done when `scripts/design_prep.py` and its tests are merged, `pdm run test` and `pdm run lint` pass, and the tests' scratch repos show a PASS on a non-empty changed text and, with one rule's term changed in one place, a FAIL naming that paragraph.
