**Type:** feature

**Kind:** build
**Status:** Open

**Part of:** TD-1153

**Why:** TD-1153's design (§4.9 *A team's own page*: *A repo's team lands as a PR*, *While the PR is open, and after it merges*; §4.4 *A definition PR is the team's at once*, *The RPC*): a repo-defined team's edit made on its page is committed by the home on its own branch and opened as a PR it never merges. Today the Members dialog draws Add member and Remove disabled on such a team.

**Location:** src/sessionorc/board.py, src/sessionorc/agent.py, src/shiftlead/ui/app.py, src/shiftlead/ui/team_page.py, src/shiftlead/org.py; design §4.4 *A definition PR is the team's at once*, §4.9 *A team's own page*

**Fix:** 1. `propose_file {repo, path, base, text, branch, title, body}` at the home's host agent, in `src/sessionorc/board.py`'s write-back tree (`_tree`, one press at a time, forty seconds, the tree reset after, the refusals and their words as a board edit's: `refused_push`, `_push_refusal`): refuse unless origin's `path` is `base` byte for byte; write `text`, commit that file alone (`--only`) as `title`, push `branch`, `gh pr create`, answer the number; a push whose open failed closes nothing it did not open but deletes its own branch. `branch` must match `team/[a-z0-9._-]+/\d{8}-\d{4}` and `path` be `.shiftlead.yml`; anything else refused. No org vocabulary in `sessionorc` (§4.4 *The RPC*).
2. `POST /api/teams/{name}/definition` on a repo team: TD-1929's checks against the home's checkout, then `propose_file` with the branch `team/<team>/<YYYYMMDD-HHMM>` (local time of the press), the title *team <team>: <summary, else "definition edited on its page">*, a body naming the person's press and the page; refused while the repo reading holds an open PR on a `team/<team>/` head (*PR #<n> holds an edit of <team>: merge or close it first*).
3. The page: **Propose as PR** and its summary field on a repo team in place of **Save**; while a `team/<team>/` PR is open, the proposed block beside the current one, the PR's link, *the team runs on the checkout's definition until it merges and the checkout is pulled*, **Edit** disabled with the reason; after a merge with the repo's pull off, *merged — <repo>'s checkout reads it once pulled (pull is off)*.
4. **Add member** and **Remove** on a repo team: their one-line edit (`edit_members`' logic on the file's text, no longer refused for a repo's file) proposed the same way, creating and winding down nothing; disabled while a `team/<team>/` PR is open; the dialog's old disabled reason goes (§4.5a *Team page: Members*).
5. Tests: `propose_file` against a local bare origin — the commit holds one file, the branch name checked, the base mismatch refused touching nothing, a refused push in the forge's words, the tree reset after; the route's refusal while a team PR is open; Add member on a repo team proposes and creates nothing.

**Done when:** A repo team's definition edit, and its Add member and Remove, made on the team's page open a PR on `team/<team>/<stamp>` changing `.shiftlead.yml` alone, never merged by the home; the page shows the open PR; the tests above pass.
