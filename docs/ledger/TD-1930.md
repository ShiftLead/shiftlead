## TD-1930: A repo team's edit on its page is opened as a pull request by the home

**Priority:** Medium
**Type:** feature
**Added:** 2026-11-17
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 50cfefcc94e24ac29a937172566d110d
**Blocked by:** TD-1929, TD-1931
**Part of:** TD-1153

**Why:** TD-1153's design (§4.9 *A team's own page*: *A repo's team lands as a PR*, *While the PR is open, and after it merges*; §4.4 *A definition PR is the team's at once*, *The RPC*): a repo-defined team's edit made on its page is committed by the home on its own branch and opened as a PR it never merges. Today the Members dialog draws Add member and Remove disabled on such a team.

**Location:** src/sessionorc/board.py, src/sessionorc/agent.py, src/shiftlead/ui/app.py, src/shiftlead/ui/team_page.py, src/shiftlead/org.py; design §4.4 *A definition PR is the team's at once*, §4.9 *A team's own page*

**Fix:** 1. `propose_file {repo, path, base, text, branch, title, body}` at the home's host agent, in `src/sessionorc/board.py`'s write-back tree (`_tree`, one press at a time, forty seconds, the tree reset after, the refusals and their words as a board edit's: `refused_push`, `_push_refusal`): refuse unless origin's `path` is `base` byte for byte (*<path> on origin is not your checkout's: pull <repo>, or push the checkout's own commit, then edit again*), and first a repo whose forge is not GitHub (*proposing needs a GitHub repo*); inside the same lock, refuse when `gh pr list --state open` shows a head starting with `branch` up to its last `/` (*PR #<n> holds an edit on <prefix>: merge or close it first*); write `text`, commit that file alone (`--only`) as `title`, push `branch`, `gh pr create`, answer the number; where the push landed and the open failed, delete the pushed branch before the refusal (no PR exists, none is closed). `branch` must match `team/[a-z0-9._-]+/\d{8}-\d{4}` and `path` be `.shiftlead.yml`; anything else refused. No org vocabulary in `sessionorc` (§4.4 *The RPC*).
2. `POST /api/teams/{name}/definition` on a repo team, the same route as TD-1929's, its refused branch replaced: TD-1929's `edit_block` and `check_edit` against the home's checkout, then `propose_file` with `base` the checkout text `edit_block` started from with the branch `team/<team>/<YYYYMMDD-HHMM>` (local time of the press), the title *team <team>: <summary, else "definition edited on its page">*, a body naming the person's press and the page. Refused first, touching nothing, each in §4.9's words and in §4.9's order (these, then `propose_file`'s): the team's name is not one a branch can carry (`[a-z0-9._-]+`; the page draws **Propose as PR** disabled before any call, *<team>'s name cannot be a branch: edit the file by hand*); the checkout holds an uncommitted `.shiftlead.yml`; the checkout is off the repo's default branch; the repo reading's open PR rows (drafts among them) hold one whose head `reports.team_of` reads as the team's, one changing other files included (*PR #<n> holds an edit of <team>: merge or close it first*). `propose_file`'s own refusals (base, lock, GitHub, push) are drawn on the page in their words.
3. The page: **Propose as PR** and its summary field on a repo team in place of TD-1929's disabled **Edit**; while a `team/<team>/` PR is open, the PR's link, *the team runs on the checkout's definition until it merges and the checkout is pulled*, **Edit** disabled with the reason; with the repo's pull off, *<repo>'s pull is off: this is the checkout's definition, which may be behind origin*, always.
4. **Add member** and **Remove** on a repo team: their one-line edit (`org.members_edit` on the file's text, TD-1929) through `check_edit` and proposed the same way, creating and winding down nothing; disabled while a `team/<team>/` PR is open; the old disabled reason goes from the page and from `help.py`'s Members entry, and **Open file** stays beside them for a hand edit (the wording the build's, §4.5a *Team page: Members*).
5. Tests: `propose_file` against a local bare origin — the commit holds one file, the branch name checked, the base mismatch refused touching nothing, a refused push in the forge's words, a push that landed with a failed open deleting its branch, a second call while the first one's PR is open refused (the same-minute and next-minute cases), a non-GitHub repo refused, the tree reset after; the route's refusals (a name a branch cannot carry, uncommitted file, off the default branch, a team PR open); Add member on a repo team proposes and creates nothing; the page's Definition section with a PR open and with pull off.
6. Blocked by TD-1931 so that no definition PR is ever opened with no taker: the order ships first.

**Done when:** A repo team's definition edit, and its Add member and Remove, made on the team's page open a PR on `team/<team>/<stamp>` changing `.shiftlead.yml` alone, never merged by the home, and never two at once; the page shows the open PR's link and the pull-off line; the tests above pass.
