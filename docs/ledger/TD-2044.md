## TD-2044: The Focus terminal loses a reply's last lines when Claude Code compacts while idle: they are written over on the screen and never reach tmux's history

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-21 (paul, through Add entry; drafted by ao-shiftlead-techlead-ao-1)
**Owner:** grinder
**Kind:** evaluation
**Status:** Open
**Id take:** 8e1827f110414a12b85ba3c12a0c09d3

**Why:** Paul, 2026-11-21, on `ao-shiftlead-flows`'s Focus scrolled back in tmux's copy mode: a reply ends *Decisions for you* with item 1 only, and the next line is *⎿ Referenced file docs/mockups/reviews/td1954-src/table.py*; the session's Transcript holds items 2 and 3 (*Does Hunt take a hunt entry?* and *Anything else that tripped you in the prototype?*), then *— compacted 11/21/2026, 2:19:03 PM —*. The loss is in tmux's own history, not the browser: `ao tail ao-shiftlead-flows -n 5000` (tmux's capture) has the same cut, item 1 then the *Referenced file* lines and *● Compacted while idle, before the prompt cache expired · turn off with "idleCompaction": false in settings.json*. The same pane has a second idle compaction earlier (Wednesday's) with the same shape: a reply cut mid-word (*…/worktr*), a recap line printed twice, then the *Referenced file* lines. So both times the lines just above the compaction's own output were written over, never kept.

This is not TD-794's resize damage: the window has been pinned since TD-1919 (`window-size manual`, design §4.6 *Attach behaviour with another client present*), and nothing resized it between the reply and the compaction. The reading to check is that Claude Code's idle compaction (Claude Code 2.1.330 on kmaster) repaints its last frame by moving the cursor up over the reply's tail and erasing it, then prints the compaction's lines in its place; tmux keeps in history only what scrolls off the top, so lines erased in place on the screen are gone, and no refresh or tmux option can bring them back. The harm: the person reads a reply back in the Focus and silently misses its last questions — here two of three *Decisions for you* — with nothing on the page saying lines are missing, and these are exactly the lines that ask the person something.

**Location:** design §4.6 *Scrollback is tmux's, reached through tmux* (TD-022) and *Attach behaviour with another client present* (the pinned window, TD-1919); §4.5 the Prompts card's *not in the terminal's history* row, which offers the Transcript; `src/shiftlead/adapters/claude_code/` (the adapter, where a version's repaint note goes); `src/sessionorc/tmux.py` (the session options, `history-limit`, the `window-size manual` pin); `tests/test_resize_repaint_live.py` (TD-794's live Claude Code test, the model for the reproduction)

**Fix:** an evaluation, then a build.
1. **Reproduce it on a scratch home** (`scripts/look_home.py`) with a Claude Code session in a throwaway profile, as TD-794's live test does (`tests/test_resize_repaint_live.py`): print a long reply, then compact it, by `/compact` first and by an idle compaction if `/compact` does not show it. Compare `tmux capture-pane -p -S -` before and after, and record the raw output with `tmux pipe-pane -o` so the escape sequences that erase the lines (cursor up, erase line, erase display) are named, with the count of lines lost against the height of the frame Claude Code redrew.
2. **Check the standard cures before inventing one**: whether `"idleCompaction": false` (the setting Claude Code's own line names) removes the idle case; whether a manual `/compact` loses lines the same way; and what tmux and other multiplexers recommend for a TUI that erases in place (`scroll-on-clear` and similar options in tmux 3.5a's manual). A change to the person's Claude Code settings is the person's to make (it is never set by shiftlead or a session): if the setting is the cure, it goes to the person as a proposal.
3. **Then the shiftlead part**, each a design sentence before code: where the loss is Claude Code's alone, what the Focus does about it, for example a mark at a compaction line that offers the Transcript at that point, as the Prompts card's *not in the terminal's history* row does (design §4.5); and a note in the Claude Code adapter's notes with the version it was seen on, so the next sighting is recognised and not re-filed.
4. If Claude Code's own repaint is the cause, the upstream report is the person's (outward-facing): draft it with the reproduction for them.

**Done when:** the reproduction's counts and the named escape sequences are written here, the standard cures are tried and their results written, and whatever shiftlead changes has a design sentence and a filed build entry of its own (or is shown unnecessary).
