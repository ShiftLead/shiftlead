## TD-1384: Test runs and prechecks still leak directories into kmaster's shared /tmp, which reached 89 % of its inodes on 2026-11-04

**Priority:** High
**Type:** debt
**Added:** 2026-11-04 (session `ao-led-tds-ledger`, through `ao td add`; drafted by ao-shiftlead-techlead-ao-1)
**Owner:** grinder
**Kind:** build
**Status:** Open
**Location:** `tests/` (a suite run's new top-level `/tmp` entries; `tests/test_no_temp_leaks.py`, the TD-1053 guard, which reads only `tempfile` calls in test files); `tests/test_containers.py` (`_pinned_node`, `test_host_up_ships_the_pinned_agent_cadence_tree_into_the_containers_cache` and its neighbours, which make the shipped cadence trees read-only, `0o555`/`0o444`, as the launcher leaves its own); `docs/cadence.toml` (`precheck`, whose `TMPDIR` is `/var/tmp/pc.*` but whose clean worktree `precheck.py` makes before the command runs). Outside this repo: agent-cadence's `scripts/precheck.py` (`tempfile.mkdtemp(prefix="precheck-<pr>-")` under `/tmp`, removed in a `finally` with `shutil.rmtree(…, ignore_errors=True)`) and its shell tests (`tests/test_p1_registry.sh`, `tests/test_p2_report.sh`: `TMP=$(mktemp -d)`).

**Why:** TD-1053's *a full suite run leaves no new directory at /tmp's top level* no longer holds on kmaster. `/tmp` is a tmpfs of 1,048,576 inodes every session shares; when it fills, no command in any session starts (TD-1053, 2026-10-26). On 2026-11-04 it reached 89 % (reported by `ao-led-tds-ledger`): 3,845 top-level `tmp*` directories (≈421k inodes, 273 made that day), 37 leaked `precheck-<PR>-*` clean worktrees of ShiftLead PRs (≈118k inodes; 6 made after agent-cadence#TD-210's SIGTERM fix of 2026-10-31, e.g. precheck-2779, -2790, -2795), and `pytest-of-<user>` runs (≈137k). Not every leak is this repo's: the fixture names the `tmp*` directories held (`alpha beta config delta delta-elsewhere`, `config repo1 … repo4`) are agent-cadence's shell tests', not shiftlead's (`grep -rl delta-elsewhere` finds them only there), and the precheck worktree is made and removed by agent-cadence's script. Also reported: a test of `test_containers.py` leaves its cadence tree read-only, so pytest's own basetemp cleanup fails and leaves a `garbage-<uuid>` directory, and a person's `rm -rf` fails until `chmod -R u+w` (read in the test, not yet reproduced: its purge asserts the shipped tree gone, so the leftover is likely `tmp_path/cache`'s tree or a neighbouring test's).

**Fix:** (1) run the full suite under a fresh empty `TMPDIR` and with `/tmp`'s top level listed before and after, and move each test that leaves an entry to `tmp_path` (or, for a subprocess or `src/` code that takes `tempfile`'s default, give it the test's `TMPDIR`); widen `test_no_temp_leaks.py` where the leak is a pattern it can name. (2) Every test that makes a tree read-only restores `u+w` in its teardown (a fixture's `finally`), so pytest's basetemp cleanup succeeds; confirm no `garbage-*` is left. (3) File the agent-cadence half on its ledger with `ao td add --repo agent-cadence` and name it here in Related: its shell tests' `mktemp -d` without a `trap … EXIT`, and why `precheck-*` worktrees still escape `precheck.py`'s `finally` (a `SIGKILL`, or `rmtree`'s `ignore_errors` hiding a read-only file), and whether the clean worktree belongs under the command's disk-backed temp root rather than `/tmp`. What remains on kmaster's `/tmp` after the merge is the person's to clear (a shared directory, as TD-1053's was).

**Done when:** a full `pdm run test` run leaves no new top-level `/tmp` entry and no `garbage-*` under its basetemp, and the agent-cadence entry for its shell tests and the precheck worktree is filed and named in Related (its own Done when covers *a precheck leaves no new top-level `/tmp` entry*).

**Related:** TD-1053 (the first leak, its guard test), TD-1052 (the precheck's `TMPDIR` under `/var/tmp`), agent-cadence#TD-210 (precheck worktree removed on SIGTERM).
