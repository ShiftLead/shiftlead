## TD-1242: A push the forge refuses reads *origin refused the push (<the forge's reason>)*, apart from an unreachable origin, on the board write-back and the rank flush

**Priority:** Medium
**Type:** debt
**Added:** 2026-10-29 (the designer, from TD-1239's design)
**Owner:** grinder
**Kind:** build
**Status:** Open
**Part of:** TD-1239
**Location:** `src/sessionorc/board.py` (`unreachable`, `_why`, `_land`'s `git push` at ~:371, `_git` at ~:131); `src/shiftlead/ui/templates/queue_card.html` (the *not landed — retrying* note, ~:63); `tests/test_board.py` (beside `test_origin_out_of_reach_refuses_the_press_and_lands_nothing`)

**Why:** design §4.4 *Board write-back*, the sentence after *It is refused, touching nothing, when origin cannot be reached*, and §4.4 *A move lands* (TD-1239). Today every failed push raises `unreachable(_why(cp, "git push"))`, and `_why` keeps stderr's last line. A forge that took the push and refused it therefore reads as an outage, with git's generic *failed to push some refs*. On 2026-10-29 that hid GitHub's GH007 for every board write-back and rank flush.

**Fix:**
1. `_land` runs its `git push` under `LC_ALL=C`, so git's own last line, the fallback reason, is English. The status tokens and `remote:` lines need no locale, since git never translates them. Give `_git` an `env` (or a `c_locale`) argument for this, merged onto `os.environ` as `gitinfo`'s `_run` does (`gitinfo.py` ~:561), so the push keeps `HOME` and its credential helper. Every other call keeps its environment.
2. A failed push whose output holds a `remote: error:` line, or a `! [remote rejected]` or `! [rejected]` status line, raises `Refused(f"origin refused the push ({reason}): the edit was not made")`, through a helper beside `unreachable` (say `refused_push(reason)`). The reason is the first `remote: error:` line, with its `remote: error:` prefix and surrounding whitespace stripped. Git pads each `remote:` line with trailing blanks. Else it is the parenthesis that ends the `! [remote rejected]` or `! [rejected]` line. Else it is `_why`'s last line. Cut it at 200 characters. Read stderr, then stdout, as `_why` does.
3. Any other failed push keeps `unreachable(_why(cp, "git push"))`, and the `gh` steps keep theirs. The `except Refused` path stays as it is: nothing was pushed, so the tree is reset and no branch is deleted.
4. The Queue card's *not landed — retrying* note takes `title="{{ c.not_landed }}"`, the flush's refusal, which `agent_rank`'s `state["not_landed"]` already holds. The rank flush's log warning already prints the refusal, so it needs no change. `ao queue`'s *not landed — retrying* (`cli.py` ~:3623) stays bare, and so does §4.5a's grip row: a hover on a display-only note is no control, so the row's help-bound wording is left alone.

**Done when:** a test gives the fixture's bare origin a `pre-receive` hook. `tests/test_board.py`'s `repo` fixture drops `with_origin`'s return, so find the origin with `git remote get-url origin` in the repo, write the hook into its `hooks/` after the fixture, and `chmod +x` it. The hook that prints `error: GH007: Your push would publish a private email address.` to stderr and exits 1. Git prefixes `remote: ` and prints `! [remote rejected] HEAD -> board/… (pre-receive hook declined)`. The test asserts that the refusal reads `origin refused the push (GH007: Your push would publish a private email address.): the edit was not made`, does not contain *could not be reached*, and leaves the tree at origin's head with no branch on origin. A second case's hook prints nothing and exits 1, and the refusal reads `origin refused the push (pre-receive hook declined): the edit was not made`. A push that cannot connect (a bad remote URL) still reads *origin could not be reached (git push: …)*. A render test in `tests/test_queue_card_box.py`, by its `card(c)` pattern with `c["not_landed"]` set, pins the note's escaped `title`. `pdm run test` and `pdm run lint` pass.
