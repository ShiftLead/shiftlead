**Why:** Part of TD-1899's design: the home reads who worked each closed entry from its closing commit's trailers, so the Queue can draw it (TD-1933).

**Location:** src/sessionorc/ledger.py (history, recent, completed); src/sessionorc/queue.py (completed members); design §4.4 What closed

**Fix:** Build design §4.4 *What closed, and by which PR*, its **Who closed it** (TD-1899), and *Completed cards*' members carrying it.

- `sessionorc.ledger.history`'s log format (both of its `git log` calls, the old file's `-p` and the directory's `--name-status`) becomes `%x00C %H %cI %s%x1d%(trailers:only,unfold,separator=%x1f)`. `_commit_line` splits the line at its first `\x1d` before it reads the sha, instant and subject, so `SQUASH` still reads the subject's end; the rest is the trailers, split at `\x1f`, each at its first `: ` into a key and a value. `Event` gains the trailers as its sixth member, which `_log_events` and `_dir_events` both carry from `_commit_line`; `Change` gains `by`, which `_replay` sets beside `closed`, `pr` and `sha` when it closes an entry, from that commit's trailers alone. The history makes no second git call.
- Each `recent` and `completed` entry carries `by`: None where the commit has no `Merged-by:` trailer, else `{built, reviews, precheck, merged, override}`, parsed exactly as §4.4 says. `built` is the session co-authors (an address's local part equal to the name), in order, each once. `reviews` is `{model, verdict}` per `Review:` trailer. `precheck` and `override` are booleans. `merged` is the `Merged-by:` value before its first ` (`.
- The Queue reading's completed-card members and archived rows carry `by` beside `sha` (`src/sessionorc/queue.py`, *Completed cards*).
- Tests: a commit with every trailer (two session co-authors, the model's and the person's left out, two reviews, one in the `(sonnet, independent) at … (SHIP)` form and one in the `(fact-check, doc-only) at … (SHIP)` form); one with `Merged-by:` and no `Review:` or `Precheck:`; one with `Merge-override:`; one with no trailers (`by` None); a squash subject ending `(#n)` still read as its PR with the trailers after it; both the old file's history and the directory's; and an entry with no sha.

**Done when:** The ledger reading's `recent` and `completed` entries, and the Queue reading's completed-card members, carry `by` as design §4.4 *What closed* says, read from the same log with no second git call, with the tests the Fix lists passing.
