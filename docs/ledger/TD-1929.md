**Why:** TD-1153's design (§4.9 *A team's own page*: *The definition, as text*, *Every edit is checked before it is written*, *An org.yml team is written in place*): a team's definition is edited on its page as text, checked, and an `org.yml` team's edit written in place.

**Location:** src/shiftlead/org.py, src/shiftlead/ui/app.py, src/shiftlead/ui/team_page.py; design §4.9 *A team's own page*, §4.5a *Team page: Definition*

**Fix:** 1. **The splice**, `org.edit_block(text, team, read, edited) -> str` in `src/shiftlead/org.py`, pure on the file's text: `read` the indent-stripped block the page drew (`org.team_block`, TD-1928), `edited` the person's lines; returns the new file text or raises `ValueError` with the reason. The key's indent put back on every non-blank line, the file's own line ending (`\n` or `\r\n`) on every line. Refusals, in this order and in these words (§4.9 *Every edit is checked before it is written*): the block on file is not `read` (*the definition changed since you opened it: reload*); the edited lines, parsed alone, are not a mapping of one key, the team's own (*a team is renamed by hand: settings follow its name*, or *one team per block: add a team by hand* for a second key); the new text does not parse (the parser's words; a tab in an indent among the causes); the whole file parsed with the team's key taken out of `teams:` differs from the old file parsed the same way (*the edit reached past <team>'s block*).
2. **The org check**, `org.check_edit(source, text) -> tuple[list[str], list[str]]` (refusals, warnings): builds the org with the candidate text standing in for its file from a scratch copy, writing nothing under `~/.shiftlead/` — an `org.yml` candidate written to a temporary file, read by `org.load` and passed through `with_repos` with the live registry; a repo's written as `.shiftlead.yml` in a temporary directory passed to `with_repos` as `stand_in`, keyed by the repo's registry entry as written, beside the live `org.yml`; either read through `with_settings` with the live `settings.yml` — then refused on `_team`'s refusal, `with_settings` raising, a note `with_repos` returns naming the candidate's file (it skips a file it cannot read or merge with a note and never raises, so the note is the failure), or the edited team absent from the built org; and on `shared_names` or `flowdefs.unfollowable` only where the same check on the unedited text does not fire, so a fault another team already carries never blocks this edit; each in its words; a brief a member names that the checkout does not hold is a warning, never a refusal.
3. **The member edit split**: `edit_members`' one-line text edit becomes `org.members_edit(text, team, …) -> str`, the text in and out, its refusals worded without naming `org.yml`; `edit_members` keeps the read, the org check (`check_edit`), the write and the restore around it, so Add member and Remove make the same checks as Save. TD-1930 calls `members_edit` on a repo's text.
4. `POST /api/teams/{name}/definition {read, edited}` for an `org.yml` team, calling `teamrun.save_definition(call, team, read, edited)` beside `add_member` and `remove_member`: `edit_block`, `check_edit`, then the write, `org.load` again and the bytes restored if it fails, as `edit_members` does, then `_commit(call, "org: <team> definition edited")` (§4.9 *What is left at the home has a history*), a failed commit leaving the file written and refusing nothing; nothing created or wound down. One `threading.Lock` in the UI process (the Members routes run in worker threads) serialises every `org.yml` write: Save, Add member, Remove; − / + and up to write `settings.yml` and are not held, the check reading the settings as they stand at its call. A repo team's call is refused (*a repo's team is proposed as a PR*), and on a repo's team the page draws **Edit** disabled with *changed by PR* until TD-1930 replaces it with **Propose as PR**.
5. The page's Definition section (TD-1928) gains **Edit** (a text area of the block), **Save** and **Cancel**; a refusal drawn under the text area in the check's words with the text kept; warnings under it (§4.5a *Team page: Definition: Edit, Save, Cancel*).
6. Tests: each refusal of both steps with a file it fires on; comments and spacing outside the block byte-identical after a save, a CRLF file kept CRLF; a comment inside the block kept; a quoted key; a flow-style one-line team edited; a tab-indented edit refused; a repo candidate `_team` refuses, whose file `with_repos` skips with a note, refused; an unfollowable flow or a twice-named session another team already carries not refusing this team's edit, and one the edit brings refused; a block that adds a sibling team at its end refused; two Saves sent at once serialised; a save that `org.load` rejects restores the bytes; the `commit_defs` call with its words; Add member through `members_edit` gives the file it gave before; a live team's card reads *definition changed — Apply* after a save that adds a member line (the existing reading, not new code).

**Done when:** An `org.yml` team's definition is edited on its page and written in place and committed, every refusal of §4.9 *Every edit is checked before it is written* drawn in its words, and the file outside the block byte-identical; Add member and Remove go through the same org check; the tests above pass.
