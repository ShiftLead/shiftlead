## TD-2240: Pressing Go or Not yet on a held question leaves a change the weekly check calls unreviewed

**Priority:** Low
**Type:** debt
**Added:** 2026-11-26
**Owner:** designer
**Kind:** design-first
**Status:** Open
**Id take:** fc119590bff14c2c9441d005e70c018f
**Escaped from:** TD-2172

**Why:** Audit of #4703 (TD-2186). Design §4.5 screen 6 *The ledger's entries that wait on you* says the pair's press is the sweep's own line, "so the write is the decide lift", with ledgerboard's `plan_add` then `plan_edit` "both in the press's one commit". Design §4.4 *The board PR's merge is a tool merge* says its review row passes a board PR by a carve-out, among them "a decided line that lifts a gate as `decide-lift`", and "A decided append whose Context names a gate is judged as a decide lift (ledgerboard's `lift_pr_verdict`), and it passes only as one."

The one commit and those carve-outs cannot both hold. `add_gate_decided` (`src/sessionorc/board.py`) adds the line and decides it in one commit, so the item's file is not in the PR's base tree. The pinned agent-cadence's `lift_pr_verdict` takes only one item's change from an open file that the base holds (`_one_items_change`), so that verdict refuses such a commit; and the gate does not even consult it, `row_lift_pr` returning early because `board_gate_answers` pairs only items the base already holds. The quoted sentence on a decided append is wrong about the pin for the same reason.

Probe at `5d637bd` (a temporary test over `tests/test_gate_pair.py`'s repo: press through `ledger_decide`, then `lift_pr_verdict` over `origin/main~1` and `origin/main`):

- Go: subject `shiftlead: decide … Should TD-190 go ahead?: Go (session n/a)`, files the entry and the archived item, `carve_out` False, `lift-board-diff`: "the board changes are not one item's file changed in place or moved to archive/".
- Not yet: the same, `carve_out` False, `lift-board-diff`.

None of the other carve-outs in `check_cadence.py` takes it (the board-edit and append one wants board files alone, the ledger lift a lift subject), so the review row falls to the ordinary review, which wants a `cadence-review:` comment that the host agent's merge never gets. `--since` then lists the person's own press under *merged outside step 5*, which §4.4 says the weekly read never does for a tool merge. #4703's tests read the commit's files and never the merge gate's verdict, and no line of `docs/reviews/TD-2172.md` takes up the carve-out.

**Design PR:** #4762

**For agent-cadence:** A carve-out in check_cadence.py's review row for a board PR whose one commit adds a gate's decide line and decides it, the entry's ledger change beside it. Why: shiftlead's "gate's own pair" press (its design §4.5 screen 6, TD-2172, built as sessionorc.board.add_gate_decided) writes the gate sweep's own line (Context: TD-n decision (paul), Answers: Go | Not yet, Go its lift) with ledgerboard's plan_add and then decides it with plan_edit on the same tree, landed as one host-agent PR. Under the pin (180d10c) row_lift_pr returns None for it because board_gate_answers pairs only items the base already holds, row_board_edit_pr refuses it (_appends_gate_answer), and lift_pr_verdict's _one_items_change refuses a file the base lacks (lift-board-diff), so the review row falls to ordinary review and check_cadence --since lists the person's own press as merged outside step 5. Two merges cannot replace it: the add alone, a decide line with its detail block, passes no append carve-out (classify_direct). Wanted: pass it as decide-lift (a tool merge) when the added item is ledgerboard's _sweep_item uncovered line for that entry's gate, decided once, and the ledger change is byte for byte decide_lift()'s for Go, or the Not yet close ("— kept waiting.", noted on the entry). Probe in shiftlead's TD-2240 (probe at 5d637bd over tests/test_gate_pair.py's repo). shiftlead's TD-2271 bumps the pin and tests the pair's commit against the review row once this lands.

**Location:** docs/design/4.5-ui.md screen 6; docs/design/4.4-host-agent.md (the board PR's merge); src/sessionorc/board.py add_gate_decided

**Fix:** Design first, in §4.5 screen 6 and §4.4 *The board PR's merge is a tool merge*. The one commit stays or changes only with agent-cadence, since landing the press as two merges does not work under the pin: the first, adding a `decide` line, passes no append carve-out with a detail block (`classify_direct` sends it to a reviewed PR) and cannot be written without one (a `decide` needs its block). So ask agent-cadence, through `ao td add --repo agent-cadence`, for a carve-out that takes a gate's line added and decided in one commit with the ledger bytes `decide_lift()` writes, and the *Not yet* close; say in the design what the weekly read shows until the pin has it, as §4.9c *A move to the person is the entry's decision* does for its own pull request, and correct the sentence on a decided append whose Context names a gate. File the build.

**Done when:** The design says that the weekly read lists the pair's press until a named agent-cadence change is in the pin, or how its pull request passes the merge gate's review row; the ask of agent-cadence and the build are filed, and the build's test holds the pair's commit to the gate's review row (not to `lift_pr_verdict` alone) once the pin has the carve-out.
