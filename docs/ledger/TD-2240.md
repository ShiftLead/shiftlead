**Why:** Audit of #4703 (TD-2186). Design §4.5 screen 6 *The ledger's entries that wait on you* says the pair's press is the sweep's own line, "so the write is the decide lift", with ledgerboard's `plan_add` then `plan_edit` "both in the press's one commit". Design §4.4 *The board PR's merge is a tool merge* says its review row passes a board PR by a carve-out, among them "a decided line that lifts a gate as `decide-lift`", and "A decided append whose Context names a gate is judged as a decide lift (ledgerboard's `lift_pr_verdict`), and it passes only as one."

The one commit and those carve-outs cannot both hold. `add_gate_decided` (`src/sessionorc/board.py`) adds the line and decides it in one commit, so the item's file is not in the PR's base tree. The pinned agent-cadence's `lift_pr_verdict` takes only one item's change from an open file that the base holds (`_one_items_change`), so that verdict refuses such a commit; and the gate does not even consult it, `row_lift_pr` returning early because `board_gate_answers` pairs only items the base already holds. The quoted sentence on a decided append is wrong about the pin for the same reason.

Probe at `5d637bd` (a temporary test over `tests/test_gate_pair.py`'s repo: press through `ledger_decide`, then `lift_pr_verdict` over `origin/main~1` and `origin/main`):

- Go: subject `shiftlead: decide … Should TD-190 go ahead?: Go (session n/a)`, files the entry and the archived item, `carve_out` False, `lift-board-diff`: "the board changes are not one item's file changed in place or moved to archive/".
- Not yet: the same, `carve_out` False, `lift-board-diff`.

None of the other carve-outs in `check_cadence.py` takes it (the board-edit and append one wants board files alone, the ledger lift a lift subject), so the review row falls to the ordinary review, which wants a `cadence-review:` comment that the host agent's merge never gets. `--since` then lists the person's own press under *merged outside step 5*, which §4.4 says the weekly read never does for a tool merge. #4703's tests read the commit's files and never the merge gate's verdict, and no line of `docs/reviews/TD-2172.md` takes up the carve-out.

**Ask:** Should the grinders build the change that lets the merge check pass your held-question presses once agent-cadence has its two rules?

1. `gate-pair`: a host-agent PR under ledgerboard's decide subject (`<tool>: decide <id> <head>: <answer> (session n/a)`, the item's id after `decide`) whose one commit (a) adds one `decide` item file the base lacks, landing closed under `archive/<YYYY-MM>/` with no open file at base or head, (b) the item being, as item_file() writes it, Context `TD-n decision (<person>)`, Answers `Go | Not yet` with no default, `Lifts: Go`, a detail block, decided once by edit_item() with a `Decided:` dated within lift_pr_verdict's window (from a day before the PR's creation to a day after its merge) and the Log line's date within a day of the creation and not after the merge, and (c) the entry's ledger file changed byte for byte as decide_lift() writes it for Go, or for Not yet the line closed `Closed: <date> — kept waiting` (no period) and noted on the entry. Compare the item structurally, never against gate_sweep's own `_sweep_item` bytes: shiftlead's line differs from the sweep's (it carries `Lifts: Go`, no `Session:` line, no entry Context in the detail block, and the Ask read from the parsed entry). Today row_lift_pr returns None for it (board_gate_answers pairs only items the base holds, so lift_pr_verdict, whose _one_items_change would refuse a file the base lacks, is never reached) and row_board_edit_pr takes no PR with a ledger file. Two merges cannot replace it: the add alone, a decide line with its detail block, passes no append carve-out (classify_direct). Built in shiftlead as sessionorc.board.add_gate_decided (its design §4.5 screen 6, TD-2172).

2. `set-lift`: a host-agent PR whose subject is `<tool>: lift decision (<p>) on TD-<design> and its builds TD-a, TD-b (session n/a)` and whose one commit lifts that one gate, as lift_gate() would, on each named entry and changes nothing else but each covering board item closed `— lifted`. Today LIFT_SUBJECT_RE refuses the subject, so row_ledger_lift_pr returns None, and ledger_lift_verdict would refuse the second ledger file (ledger-lift-files). Built in shiftlead as **Go now** (its design §4.4 *Go now lifts the design and its builds*, TD-2021).

Both keep the person checks the existing lifts make, which "as decide_lift() writes it" and "as lift_gate() would" stand for: the answerer is the gate's person and on the base board's `People:`, undelegated, the entry's Log line is the one decide_lift writes with the answer (`gate lifted` for Go, `kept waiting` for Not yet), and the verdict's tripwire flags are empty. Today ledgerboard's `tripwire()` cannot give that for the pair's Go: it reads covering items at the base alone (`cov_b`), so a gate lifted with an item the same diff adds gets `tripwire-no-decided`, which also flags the gates row (`row_gates`; a ⚠ on a merged PR). So `gate-pair` needs ledgerboard's tripwire to count an item added and decided in the diff as the covering answer — a ledgerboard change, brought to agent-cadence by its vendored copy. Use exactly the names `gate-pair` and `set-lift`, and land each name in check_cadence.py only with the code that passes it: shiftlead's TD-2271 lifts when the name appears there.

Likewise `set-lift` likely needs ledgerboard's lift subject parser (`LIFT_SUBJECT_RE`, `lift_subject_parts`, `subject_kind`) to take the set's subject, unless check_cadence.py parses it itself. Say which landed in ledgerboard: shiftlead vendors ledgerboard and its conformance vectors. shiftlead's TD-2271 waits on each name appearing in agent-cadence's check_cadence.py, then bumps the pin and tests both merged presses against the review row.
