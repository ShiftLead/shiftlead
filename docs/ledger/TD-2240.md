## TD-2240: Pressing Go or Not yet on a held question leaves a change the weekly check calls unreviewed

**Priority:** Low
**Type:** debt
**Added:** 2026-11-26
**Owner:** designer
**Kind:** design-first
**Status:** Open
**Id take:** fc119590bff14c2c9441d005e70c018f
**Escaped from:** TD-2172

**Why:** Audit of #4703 (TD-2186). Design §4.5 screen 6 *The ledger's entries that wait on you* says the pair's press is the sweep's own line, "so the write is the decide lift", with ledgerboard's `plan_add` then `plan_edit` "both in the press's one commit". Design §4.4 *The board PR's merge is a tool merge* says its review row passes a board PR by a carve-out, among them "a decided line that lifts a gate as `decide-lift`", and "A decided append whose Context names a gate is judged as a decide lift (ledgerboard's `lift_pr_verdict`), and it passes only as one."

The two cannot both hold. `add_gate_decided` (`src/sessionorc/board.py`) adds the line and decides it in one commit, so the item's file is not in the PR's base tree. The pinned agent-cadence's `lift_pr_verdict` takes only one item's change from an open file that the base holds (`_one_items_change`), so such a commit never passes.

Probe at `5d637bd` (a temporary test over `tests/test_gate_pair.py`'s repo: press through `ledger_decide`, then `lift_pr_verdict` over `origin/main~1` and `origin/main`):

- Go: subject `shiftlead: decide … Should TD-190 go ahead?: Go (session n/a)`, files the entry and the archived item, `carve_out` False, `lift-board-diff`: "the board changes are not one item's file changed in place or moved to archive/".
- Not yet: the same, `carve_out` False, `lift-board-diff`.

In `check_cadence.py` none of the other carve-outs takes it either (the board-edit and append one wants board files alone, the ledger lift a lift subject), so the review row falls to the ordinary review, which wants a `cadence-review:` comment that the host agent's merge never gets. `--since` then lists the person's own press under *merged outside step 5*, which §4.4 says the weekly read never does for a tool merge. #4703's tests read the commit's files and never the merge gate's verdict, and no line of `docs/reviews/TD-2172.md` takes up the carve-out.

**Location:** docs/design/4.5-ui.md screen 6; docs/design/4.4-host-agent.md (the board PR's merge); src/sessionorc/board.py add_gate_decided

**Fix:** Design first, in §4.5 screen 6 and §4.4 *The board PR's merge is a tool merge*. Decide which gives way. Either the press lands as two merges, the line added under the append subject and then decided as a decide lift: the sweep's item carries a detail block, which the pinned `classify_direct` sends to a reviewed PR rather than the append carve-out, so this road adds the line without one. Or the one commit stays and agent-cadence gains a carve-out for a line added and decided together (asked through `ao td add --repo agent-cadence`, the design saying what the weekly read shows until the pin has it, as §4.9c does for the stage's end-of-rounds item). Say in the same place whether a decided line that an answered steer or ask appends with a gate in its Context has the same gap. File the build.

**Done when:** The design says how the pair's board pull request passes the merge gate's review row, or that the weekly read lists it until a named agent-cadence change is in the pin; the build is filed, and its test holds the pair's commit or commits to the pinned `lift_pr_verdict` or carve-out the design names.
