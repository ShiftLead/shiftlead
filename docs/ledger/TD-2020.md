## TD-2020: An answered question reads as unanswered when the person answered it twice in one day: the Queue picks the older answer

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-19
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** d9c5da64908d457a856e3369638241e0

**Why:** Paul, 2026-11-19, on shiftlead#TD-794's card: TD-1947 and TD-1948 drew *needs you (decision)* with **Lift the hold** although he had answered their end-of-rounds question *One more round* and the round it bought, TD-2016, was open. Three decided lines covered them, all `Decided: 2026-11-19` and `Closed: 2026-11-19` (board 2026-11-19-ce64f83c carried to TD-2010, 515d3733 to TD-2009, 444b54c4 to TD-2016). `board_hold` (`src/sessionorc/queue.py`) picks one line by `(decided, open, closed, -at)`, dates alone, so the tie fell to the smallest `at` (ce64f83c, at 19), whose TD-2010 is archived; it returned None and the hold went back to the person. Read on the live board with the promoted install, 2026-11-19: the newest answer, 444b54c4, was never picked. A press of **Lift the hold** there would have been a Go mid-round, the case TD-1926 closed. It happens on any day the person answers the same design's question more than once, which a bought round a few hours long now makes common.

**Location:** design §4.4 The card's status (One line answers); src/sessionorc/queue.py (board_hold, _board_lines)

**Fix:** Design §4.4 *The card's status* (*One line answers*) first, then `board_hold`: the newest answer must win on a same-day tie. §4.4 itself specifies the tie-break today (*then the smaller `at`*, 4.4-host-agent.md's *One line answers*); this reverses it, so the design sentence changes in the same PR. Read each line's time where the board has one (the decide write's `Decided:` time, or the item's archive commit), else order a tie by `Closed:`'s *carried to* entry's `Added:`/id, the later first, never by `at`, which is a line position in a board file and says nothing of order across the archive's per-item files. A design change rather than a tie-break is open to the design: a line closed *carried to TD-m* holds while any covering line's carried-to entry is open and filed for it, whichever line is newest. A test with three same-day lines carried to two archived entries and one open one, in either file order.

**Done when:** On a board whose covering decided lines tie on `Decided:` and `Closed:` dates, the member reads *answered — waiting on* the newest answer's open carried-to entry (TD-1947 on 2026-11-19's board reads *answered — waiting on TD-2016*), under a test that holds in either file order, and §4.4 says the rule.
