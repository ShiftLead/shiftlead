## TD-2159: A review stage gives its count of findings, and the posted review comment carries it

**Priority:** Medium
**Type:** feature
**Added:** 2026-11-25
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** e4f0ddc027854ca48fea4addbc94bcbc
**Part of:** TD-2077

**Why:** Part of TD-2077 (design §4.9c *What a run records, for comparing flows*, §4.7 `ao stage end`). The home's `cadence-review:` comment for a review stage writes 0 findings for a ship and 1 for changes wanted, since the session gives no count, so a pull request's findings cannot be compared between flows.

**Location:** src/shiftlead/stage_end.py, src/shiftlead/cli.py, src/shiftlead/flows3, design §4.9c

**Fix:** Add `--findings <n>` to `ao stage end` (`src/shiftlead/cli.py`, the `stage_end` call in `src/shiftlead/stage_end.py`): taken with `ship` and `changes-wanted` alone, refused on any other outcome; `changes-wanted` refused without it or with 0, `ship` without it reading 0. Write `findings` on the review row and post `n` as the comment's count in place of today's 0 or 1. Tell a review stage's session to give it, in the built-in flows' review briefs under `src/shiftlead/flows3/` and the text a review stage's session is told (§4.9c *What a stage's session is told*).

**Done when:** Tests show `--findings` refused on a non-review outcome, `changes-wanted` refused without a count above 0, `ship` reading 0 without one, the row's `findings` and the posted comment's count both equal to `n`, and a review stage's brief naming the option.
