## TD-2195: No test shows an audit's later run waits while the team is at its limit

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-25
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 22862ff667ec446fbb59c506bc561245

**Why:** `stage_audit.choose` (#4582, TD-2065 slice 2) has two guards on `s.within_size`: the first-run start and the due-run start (`if not holds_lease(run, s) and s.may_start and s.within_size and due(run, every, s, now)`). With `and s.within_size` dropped from the second, the 106 tests of `test_stage_size.py`, `test_stage_pass.py`, `test_stage_audit_pass.py`, `test_stage_tick.py` and `test_stage_audit.py` all pass; dropping it from the first fails `test_an_audit_waits_while_the_stages_fill_the_team_limit`. No test has an audit with a run on record, due, and a team at its limit, so a later run of an audit would start over the team's `most`. Evidence: the one-line edit in a worktree on `origin/main`.

**Location:** src/shiftlead/stage_audit.py; tests/test_stage_audit.py

**Fix:** In `tests/test_stage_audit.py` add a `choose` case with a run on record, `every` past, `may_start` true and `within_size` false: it returns None, and with `within_size` true it returns the start. Check it fails with the guard reverted.

**Done when:** `and s.within_size` removed from the due-run start in `choose` fails a test.
