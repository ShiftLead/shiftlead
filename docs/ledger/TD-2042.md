## TD-2042: A built-in tests-first flow: one stage writes failing tests, the next makes them pass and opens the pull request

**Priority:** Low
**Type:** feature
**Added:** 2026-11-21
**Kind:** build
**Status:** Open
**Id take:** ab94e7f44c814037874e63dc358fb227
**Blocked by:** decision (paul)
**Part of:** TD-1954

**Why:** Paul, 2026-11-21, in TD-1954's conversation, on the trial flow two lesser models wrote from the description alone: "I like the test driven development flow - we should consider adding it as a builtin (maybe a TD for after we get the design figured out)." TD-1954 names five built-in flows (build, build-review, td, one-owner, hunt); tests-first is not among them.

**Ask:** Once the Flows design (TD-1954) has merged, should a tests-first flow be added to the built-in flows?

**Fix:** Add a built-in flow in which one stage writes failing tests for the entry and pushes the branch with no pull request, a second stage on another model makes them pass and opens the pull request, and the pull request is then reviewed and merged as in build-review. It is written in the flow format TD-1954's design settles, with nothing the Flows page cannot show or edit, and it passes the flow check.

**Done when:** The flow is listed among the built-ins on the Flows page, a team can pick it, and an entry run through it shows a tests-only push before the pull request opens.
