## TD-2042: A built-in tests-first flow: one stage writes failing tests, the next makes them pass on the same pull request

**Priority:** Low
**Type:** feature
**Added:** 2026-11-21
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** ab94e7f44c814037874e63dc358fb227
**Blocked by:** TD-2056, decision (paul)

**Why:** Paul, 2026-11-21, in TD-1954's conversation, on the trial flow two lesser models wrote from the description alone: "I like the test driven development flow - we should consider adding it as a builtin (maybe a TD for after we get the design figured out)." TD-1954 names three built-in flows (td, build-review, build); tests-first is not among them.

**Ask:** Once the cut-over to the new flows has run, should a tests-first flow be added to the built-in flows?

**Fix:** Add a built-in flow of two build stages and a review: the first stage writes failing tests for the entry and opens the pull request, a second stage on another model makes them pass on the same pull request, and the pull request is then reviewed and merged as in build-review. The first stage's work is accepted with its checks red, because the entry goes on to another build stage (TD-1954's design, *An outcome is the session's word*). It is written in format 3, with nothing the Flows page cannot show or edit, and it passes the flow check.

**Done when:** The flow is listed among the built-ins on the Flows page, a team can pick it once the cut-over has run, and an entry run through it shows the tests pushed by the first stage and made to pass by the second, on one pull request.
