## TD-2125: A session that fails partway through starting leaves a stray shell behind

**Priority:** Low
**Type:** debt
**Added:** 2026-11-23
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** a3bc827db47340e89185edf73b869168

**Why:** If a create raises after its tmux pane has started, for example when the run's scratch owner file cannot be written, the pane stays up with no record. The next tick adopts it as a nameless shell with no directory, so the person sees a stray session and its turns count as outside shiftlead. The independent review of #4450 found this by reading the code; it has not been reproduced.

**Location:** src/sessionorc/agent.py (create)

**Fix:** In `create` (`src/sessionorc/agent.py`), when a step between the pane's start and the record's insertion raises, kill the pane it started before the error leaves, so nothing is left to adopt. This is a held path, so the pull request goes to the techlead.

**Done when:** A test makes the owner write fail during a create: the create reports the error, no pane remains, and a following tick adopts nothing.
