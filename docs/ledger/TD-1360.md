## TD-1360: A new entry is filed with ledger.py new: entry.md and every brief that files one name it, once ledger.py new can file here

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-04 (the designer, from TD-1286's design)
**Owner:** grinder
**Kind:** build
**Status:** Open
**Blocked by:** TD-1357, TD-1358, agent-cadence#TD-188
**Part of:** TD-1286
**Location:** `src/shiftlead/briefs/entry.md` (the number, the shape, the Summary row step); every brief under `src/shiftlead/briefs/` and `docs/briefs/` that files an entry; `AGENTS.md`

**Why:** `ledger.py new --id TD-n` is the helper for a new entry, but here it refuses every filing: it writes the take's `**Taken by:**`, and this ledger's `Fields:` line declares vocabularies, so `--check --since` reads `Taken by` as an undeclared field and `new` refuses (tried 2026-11-04 at the pin 9c61e5a; agent-cadence's main, 6894299, has the same `ledger.py`). agent-cadence#TD-188 replaces `Taken by` with the cadence's own `Id take` field, which needs no declaration. Until it lands, `entry.md` gives the entry's shape to type, and keeps a step adding a Summary row the v2 ledger no longer has (TD-1286).

**Fix:** As design §4.4 *A session writes the ledger and the board only through the helpers* and §4.9 *Two ways out*, once agent-cadence#TD-188 is built (itself after ledgerboard#TD-010; it lands as agent-cadence's ledgerboard v2.4 vendor):
1. In this PR, `agent-cadence bump` past it and vendor the ledgerboard release the bumped tree names (`scripts/vendor_ledgerboard.sh`, as TD-1330 vendored v2.3; design §5 *The seams*), carrying the bump's `cadence-changes.md` asks. If TD-188 as built asks `ao td reserve` to print the take's `Id take` (its step 3), that is this build's too. **Land the bump and the briefs together**: once the pinned gate requires `Id take` (TD-188's step 4), an entry typed by the old `entry.md` fails it.
2. `entry.md` files the whole entry with `ao td reserve`'s id and `agent-cadence run ledger.py new --id TD-n` and its flags (`--title`, `--priority`, `--type`, `--added`, `--owner`, `--kind`, `--part-of`, `--blocked-by`, `--location`, `--field Team=…`/`Waits=…`, `--why`/`--fix`/`--done-when` from files the seat writes in its scratch directory, `-` for at most one of them; `--added "<date> (<the person>, through Add entry; drafted by <session>)"` as §4.9 *How it lands* asks; `--status` only when not Open), and since `new` commits nothing, the seat commits the path it prints in its PR; its Summary row step is removed; every other brief here and `AGENTS.md` that tells a session to file an entry names the same command. Check it by filing this PR's own ledger edits through the helpers.

**Done when:** `ledger.py new --id` files an entry in this ledger, and no brief, template or `AGENTS.md` line tells a session to type a new entry.
