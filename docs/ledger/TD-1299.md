## TD-1299: Narrow Focus: one screen — the strip, the tray, the input bar with the composer as a sheet, the ⋯ sheet, the switcher, the grid rules and the home-screen manifest

**Priority:** Medium
**Type:** feature
**Added:** 2026-11-01 (phone-view, from TD-003's design)
**Owner:** grinder
**Kind:** build
**Status:** Open — the design's review rounds run first, then Paul's go.
**Blocked by:** decision (paul)
**Part of:** TD-003
**Location:** `src/shiftlead/ui/templates/focus.html`, `base.html` (the viewport meta, the manifest link), a new `static/manifest.webmanifest` and icons; `src/shiftlead/ui/static/app.css` (the `@media (max-width: 720px)` Focus rules — `.termbox { height: 50vh }`, the static composer, `.focus .side`, the rail row — replaced by the narrow query's one-screen rules), `app.js` (`AO.focus`, `fill()`, the composer, the resize sender, the read-only line, `openTerm()`'s reconnect); `src/shiftlead/ui/help.py`; tests `test_ui.py`, `test_ui_focus_rail.py`, `test_design_doc.py`

**Ask:** Now the phone layout's review rounds have converged, should a grinder build the narrow Focus?

**Why:** TD-003's design: §4.5 *Phone layout* and §4.5a *the strip*, *the tray*, *the input bar · ⌨*, *the sheet (⋯)*, *the switcher*.

**Fix:**
1. **The screen**: under the narrow query (`(max-width: 720px), (pointer: coarse) and (max-height: 500px)`, one `matchMedia` the CSS and `app.js` share; a popped-out window excluded, by `body.popped` in the CSS and the same mark in `app.js`; read with no keyboard up — latched while anything editable has focus, read again on blur — and a crossing relays the page out in place with one grid, no reload) Focus is pinned to the visual viewport and never scrolls — `position: fixed; inset: 0`, `100dvh`, on iOS the `visualViewport`'s height and `offsetTop` from its `resize` and `scroll`; Focus's own viewport meta adds `interactive-widget=resizes-content` and `viewport-fit=cover` (other pages keep `base.html`'s); the safe-area insets as padding. The top bar, the identity line, the acts line and the side panel are not drawn; `AO.holdBar` does not run (`--barh` 0), `AO.termFill` and `fill()` leave the terminal to the screen's column, and `.termbox`'s 360 px `min-height` is lifted; the terminal runs from the strip (and the existing banners) to the key bar.
2. **The strip** (its ▲ n counted from every record's state, seeded into the template and kept from the light stream's `state` deltas, `SHAPE_KEYS`), **the tray**, **the input bar · ⌨** and the composer as a sheet, **the sheet (⋯)** with each side-panel card opened as a sheet, **the switcher**, each as its §4.5a row says; kept current from the pushed delta as the header is.
3. **The grid**: it changes for the keyboard (rows, the terminal following the visual viewport's settled height), a turn (both) and a pinch (both), each through the 150 ms rule; *the keyboard is up* is the terminal's focus (`focusin` / `focusout` on xterm.js's helper text box), which hides the input bar and turns `1–9` to `⌄`; the permission tray and every sheet lie over the terminal and send nothing, the Watching tray standing in the key bar's place; the terminal refitting when a sheet closes; the terminal's helper text box at 16 px (no iOS zoom); **a tap** on the terminal has its default prevented in the touch handler (§4.6), so only ⌨ focuses it.
4. **A link** opens on a press held still 500 ms and lifted, read by the TD-986 touch listeners (10 px, `AO.TOUCH_SLOP`, makes it a scroll; a second finger a pinch); at the press a synthetic `mousemove` (real `clientX` / `clientY`, dispatched on xterm.js's screen element) lets the terminal's own link readers hover the cell, each given `hover` / `leave` callbacks by the page (`WebLinksAddon`'s options, the `linkHandler`'s, the path provider's) that record and clear the link; on a lift 500 ms or more after the press, its default prevented, the recorded link is opened through its reader's own open with an event carrying `ctrlKey` (`AO.paneLink` reads the modifier first, then its scheme gate), nothing when none was recorded or on a sooner lift — opened from the lift, a user gesture, never from the timer; no `mousedown` is ever synthesised, so no focus, selection or mouse report; the narrow terminal is `user-select: none` and `-webkit-touch-callout: none`; the long press's `contextmenu` stays prevented (§4.6).
5. **Home screen**: `manifest.webmanifest` (`display: standalone`, `start_url` and `scope` `/`, name, theme colour, icons at 192 and 512), and for iOS `<link rel="apple-touch-icon">`, `apple-mobile-web-app-capable` and `apple-mobile-web-app-status-bar-style` `black-translucent`; the `/events` and `/term` sockets reconnect on `visibilitychange` and `online`; the disconnected banner opens with *is Tailscale on?*.
6. **Help**: §4.5a help entries for the strip, the tray, the input bar, the sheet and the switcher, written in `help.py` and the design's list in the same PR.
7. Tests: the narrow template draws the strip, the input bar and the sheet's rows for each card the record draws and nothing of the header's two lines; the sheet draws no Copy, copy on select, Pop out or VS Code; a record with no agent's input bar reads *Type a command…* and its sheet has no Wrap up, Message or agent cards; an unattended record draws the tray's Take over and the input bar's *Message* with no ⌨; an ended or scheduled one neither bar; the manifest and the touch icon are served; the held press (a scripted pointer): no open before 500 ms, none after 10 px of travel or a second finger, the recorded URL opened on the lift through `AO.paneLink` with a `ctrlKey` event (a non-http(s) one refused); each reader has one `hover` callback, the recorder inside `AO.paneLinkHandler`'s own, nothing opened with nothing recorded, and `document.activeElement` never the terminal's text box afterwards.
