## TD-2239: After the switch to logins, usage reserves and readings would be looked up under a doubled account key

**Priority:** High
**Type:** debt
**Added:** 2026-11-26
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 61d35002dc904fa288d2872ba73b2f87

**Why:** Audit of #4680 (TD-2068 slice 1). On a switched host the usage key of a profile read from a login carries the tool twice, `claude-code:claude-code:paul`, so it matches no key kept under the account's own, `claude-code:paul`.

The design promises one key through the switch-over. §4.2b *What the switch-over makes*: "**An account per key, unchanged**: `<adapter>:<account:>`, else `<adapter>:<profile name>` (`profiles.account_of`), so no reserve, reading or ledger moves." §4.9e *A record's `profile`*: a lookup of a profile by name, "and of its account", gives the login of that name.

The code: `logins.add` writes a login's `account` as a whole key (`<tool>:<name>`), and `logins.account_of` returns it, or the login's own key. `_login_profile` (`src/shiftlead/profiles.py`, #4680) puts that whole key in `Profile.account`, where a profile of `profiles.yml` holds the bare name. `_usage_key` (`src/sessionorc/agent_common.py`) and `_account_key` (`src/sessionorc/agent_spend.py`) then put the tool in front of what the adapter's `account_for` answers.

Probe at a5f15d01c on a scratch home, each login written by `logins.add` and `logins.save` and read through the registered Claude Code adapter:

    written   : claude-code:grind added under claude-code:paul
      logins.account_of      : claude-code:paul
      adapter.account_for    : claude-code:paul
      usage key (_usage_key) : claude-code:claude-code:paul
    written   : claude-code:grind added
      usage key (_usage_key) : claude-code:claude-code:grind

Read from the code, not probed: `_gate_reserves` looks the reserve up under `_account_key`'s answer, so one kept under `claude-code:paul` is not found and the usage gate has no line to hold a session at; the tick keeps readings under `_usage_key`'s answer, while a switched team's schedule reads them under `logins.account_of`'s (`_login_resets`, `src/sessionorc/agent_settings.py`), so it finds none.

`tests/test_profiles.py::test_a_switched_host_answers_a_profile_by_a_logins_name` writes `account: acct-1` by hand, a shape `logins.add` never writes, asserts a whole key in `Profile.account` for a login with no `account` (`api.account == "claude-code:api"`), and composes no usage key. Nothing live is harmed until a host is switched.

**Location:** src/shiftlead/profiles.py, src/sessionorc/agent_common.py, src/sessionorc/agent_spend.py

**Fix:** Give a profile made from a login the account in the shape a profile of `profiles.yml` holds it, the name after the tool, so `<adapter>:<account>` is the account's own key; or have every composer of the key take a whole one. Check the other readers of `profiles.account_of` for the same assumption. Add the dated line to the history. Due before the cut-over.

**Done when:** A test writes a login with `logins.add`, under a named account and under its own, and reads from the profile road a usage key equal to the account's key; a reserve kept under that key is what the gate reads for the login's name.
