## TD-2270: The design still says a launch must name its login, which a launch on another machine no longer does

**Priority:** Low
**Type:** debt
**Added:** 2026-11-26
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** f1fab680f543422fa6d79b604a7de79d

**Why:** Audit of #4750 (TD-2068 slice 10). The PR let a `create` given `seat_model` and `login_list` with **no** login pick the login on its own host (`rpc_create` and `_pick_here`), and wrote that in §4.9e *A team on a node*. Two earlier sentences of the design still say the create names the login:

- `docs/design/4.3-adapter-contract.md`, the `model` comment on `launch`: "the host agent hands it only to a create naming a login and a `seat_model`". A create naming no login, with a list and a model, hands the picked login's tool the model too.
- `docs/design/4.9e-switch-over.md` *The launch on a login*, *The record*: "**The `create` that makes it** names the login (its key, or its bare name where one login of the host has it), the `seat_model` and the `login_list`". The home's launch for a team on a node names no login (`stage_start.on_node`).

A session building the node half from either sentence would expect such a create to be refused.

**Location:** docs/design/4.3-adapter-contract.md; docs/design/4.9e-switch-over.md

**Fix:** In both places, say that a fresh agent launch (not a held record, a resume or a shell) may instead give the `seat_model` and the `login_list` with no login, in which case the host picks first (§4.9e *A team on a node*). History lines under §4.3 and §4.9e.

**Done when:** Neither sentence says the create must name a login, and each points at or states the no-login pick.
