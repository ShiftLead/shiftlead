**Why:** An unstamped item from a node's session draws on another repo's card (TD-1541): contractmatch's ask m-60befff817b5 (`about: TD-064`) draws on shiftlead's completed card `shiftlead#TD-064` while contractmatch's TD-064 stands open. Its sender's record exists and names `/home/kmaster/contractmatch`, but the Inbox's callers (`src/shiftlead/ui/inbox.py`) pass view dicts, whose `id` for another host's record is `<id>@<host>` (`agent_serve`), and `asker_repos` keys them by that while `mail_repo` looks the sender up by its bare id — so it finds none, the ref stays bare, and the bare `kept:TD-064` key takes it. The home's callers pass `Session`s keyed by their bare `id`, which can collide across hosts. Design §4.5 screen 6 *A mail item's bare ref is its sender's repo's* now says how the sender is found, adds the team step, and says what an item no step names may match.

**Fix:** Build design §4.5 screen 6 *A mail item's bare ref is its sender's repo's* (TD-1541), §4.4 *the answered-question link*, and §4.10 *A question the work settled closes itself*:
1. **The sender's record by its whole address.** `asker_repos` keys each record by its whole address: a view dict's `id` as given; a `Session`'s `id`, with `@<host>` added where its `host` is set and is not the home's. `mail_repo` takes `records` as `{address: root}` and looks the sender up by its `from` as written, then by its bare id. An item the person sent (its `from` the person, who has no record) reads its first addressee (`to`) the same way.
2. **A record on another host is never named by its root's last component.** `asker_repos` gains `host`, the home's own host name: the home's callers pass `self.host`; the UI's callers (`src/shiftlead/ui/inbox.py`'s two `asker_repos` calls) are given the host the home's `id` reading names (as `app.py` reads `id_info["host"]`), passed down from their route. `name_of` names a root by `repo_roots`, its last-component fallback only for a record whose `host` is empty or `host`.
3. **The team step, one helper.** `queue.team_repos(records, name_of) -> {team: repo}`: each record with a `team` and a root `name_of` names, a record whose root names none skipped; a team whose records name exactly one repo maps to it, one naming several is left out. `mail_repo` gains `teams` and, where the orphan stamp and the record name nothing, looks up the entry's `team`. `asker_repos` builds it from its records with its own `name_of`; `agent_attention`'s settling builds it from its live records named by its own `_record_repo` (the node's roster), as it names the sender now.
4. **No repo, no key — one choke point.** `queue.own_refs(found, None)` returns only the refs written qualified (`<repo>#TD-n`), dropping bare ones, so every reader agrees: `first_ref`, `held_refs`, `named_refs`, `kept_or_loose`, the Queue's mail hold and its answered-question link (`_mail_hold`), Telegram's card (`mail_card`), and their callers in `src/shiftlead/ui/inbox.py`, `agent_notify.py`, `queue.py`'s reading. An item `mail_repo` names no repo for draws in the Inbox; its qualified refs read as written. Grep every `own_refs`/`first_ref` caller passing a possibly-None repo and check none relied on the old one-repo bare lookup.
