**Why:** An unstamped item from a node's session draws on another repo's card (TD-1541): contractmatch's ask m-60befff817b5 (`about: TD-064`) draws on shiftlead's completed card `shiftlead#TD-064` while contractmatch's TD-064 stands open. Its sender's record exists and names `/home/kmaster/contractmatch`, but the Inbox's callers (`src/shiftlead/ui/inbox.py`) pass view dicts, whose `id` for another host's record is `<id>@<host>` (`agent_serve`), and `asker_repos` keys them by that while `mail_repo` looks the sender up by its bare id — so it finds none, the ref stays bare, and the bare `kept:TD-064` key takes it. The home's callers pass `Session`s keyed by their bare `id`, which can collide across hosts. Design §4.5 screen 6 *A mail item's bare ref is its sender's repo's* now says how the sender is found, adds the team step, and says what an item no step names may match.

**Fix:** Build design §4.5 screen 6 *A mail item's bare ref is its sender's repo's* (TD-1541) and §4.10 *A question the work settled closes itself*:
1. **The sender's record by its whole address.** `asker_repos` keys each record by its whole address: a view dict's `id` as given; a `Session`'s `id`, with `@<host>` added where its `host` is set and is not the home's. `mail_repo` takes `records` as `{address: root}` and looks the sender up by its `from` as written, then by its bare id. `agent_attention`'s caller, which keys `live` by bare id over `graph.get(e.from_) or graph.get(bare)`, keeps its own naming (`_record_repo` asks the node) and gains only the team step.
2. **A record on another host is never named by its root's last component.** `asker_repos` gains `host` (the home's own host name; each caller passes its own: `agent_serve`'s `self.host`, the UI's from the home's reading). `name_of` names a root by `repo_roots`, its last-component fallback only for a record whose `host` is empty or `host`.
3. **The team step.** `mail_repo` gains `teams` (`{team: repo name}`), built by `asker_repos` from the same records: each record with a `team` and a root it names (by 2), a record whose root names none skipped; a team whose records name exactly one repo maps to it, one naming several to none. Where the orphan stamp and the sender's record name nothing, the entry's `team` looks it up.
4. **No repo, no key.** An item `mail_repo` names no repo for is read as no repo's: its bare refs match no open card's bare `TD-n`, no `kept:` and no `design:` key, and make no loose card (`held_refs`, `kept_or_loose` and their callers in `src/shiftlead/ui/inbox.py`, `agent_notify.py`, `agent_attention.py`, `queue.py`'s Queue reading), so it draws in the Inbox. A ref it writes qualified (`<repo>#TD-n`) reads as written.
