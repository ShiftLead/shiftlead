**Why:** An unstamped item from a node's session draws on another repo's card (TD-1541): contractmatch's ask m-60befff817b5 (`about: TD-064`) draws on shiftlead's completed card `shiftlead#TD-064` while contractmatch's TD-064 stands open. Its sender's record exists and names `/home/kmaster/contractmatch`, but the Inbox's callers (`src/shiftlead/ui/inbox.py`) pass view dicts, whose `id` for another host's record is `<id>@<host>` (`agent_serve`), and `asker_repos` keys them by that while `mail_repo` looks the sender up by its bare id — so it finds none, the ref stays bare, and the bare `kept:TD-064` key takes it. The home's callers pass `Session`s keyed by their bare `id`, which can collide across hosts. Design §4.5 screen 6 *A mail item's bare ref is its sender's repo's* now says how the sender is found, adds the team step, and says what an item no step names may match.

**Fix:** Build design §4.5 screen 6 *A mail item's bare ref is its sender's repo's* (TD-1541), *An item about a design links the design's PR*, §4.4 *the answered-question link*, and §4.10 *A question the work settled closes itself*:
1. **The sender's record by its whole address.** `asker_repos` keys each record by its whole address: a view dict's `id` as given (`agent_serve._view` already writes `<id>@<host>` for another host's record and the bare `id` for the home's own); a `Session`'s `id`, with `@<host>` added where its `host` is set and is not the home's. `mail_repo` takes `records` as `{address: (host, root)}` and a `name_of(host, root)`, calls it with the orphan stamp's `(host, repo)` (the stamp's `host`, empty for the home's) and with the found record's pair, and looks the sender up by its `from` as written, then by its bare id. An item the person sent (its `from` the person, who has no record) reads its first addressee — `to`'s first element, by the address it writes — the same way; only `asker_repos` meets such an item (`_mail_hold` reads only asks and steers to the person, and the settle skips the person's).
2. **A record on another host is never named by its root's last component.** `asker_repos` gains an optional `host`, the home's own host name: the home's callers pass it — `agent_notify.py` its `self.host`, and `queue.reading`, a module function, gains a `host` argument that its one caller, `agent_tick.py` (`queue_mod.reading(...)`), passes as `self.host`; the UI's callers (`inbox_sections` and `ledger_for_you` in `src/shiftlead/ui/inbox.py`) pass none, since their view dicts' keys already say the host. A record is the home's own where its key is bare (its pair's host then empty or the home's); `asker_repos`' `name_of(host, root)` names the root by `repo_roots`, its last-component fallback only where the host is empty or the home's.
3. **The team step, one helper.** `queue.team_repos(records, name_of) -> {team: repo}`: every record with a `team`, of any role, live or ended as the caller passes it, whose root `name_of` names; a record whose root names none skipped, one with no `team` ignored; a team whose records name exactly one repo maps to it, one naming several (a seat in another repo's checkout) is left out. `mail_repo` gains `teams` and, where the orphan stamp and the record name nothing, looks up the entry's `team`. `asker_repos` builds it from its records with its own `name_of`; `agent_attention._settle_by_work` builds it from its live records named by its own `_record_repo` (the node's roster): before the order runs it names, beyond the senders it names now, every live record whose `team` is the `team` of an open item that carries no `repo`, so the team step has its names.
4. **The settle's keys.** `_settle_by_work` keys `live` by each record's address in the graph (`graph`'s key, `<id>@<host>` for another host's) instead of the bare id, and `names` by `(host, root)` — an orphan stamp's by its `host` (the home's where empty) and `repo` — since two hosts can hold the same path; `live`'s values are `(host, root)` pairs and the `name_of(host, root)` it passes `mail_repo` reads `names` by the pair.
5. **No repo, no key — one choke point.** `queue.own_refs(found, None)` returns only the refs written qualified (`<repo>#TD-n`), dropping bare ones, so every reader agrees: `first_ref` (a bare `about` drops and a qualified ref in the words is the first), `held_refs`, `named_refs`, `kept_or_loose`, the Queue's mail hold and its answered-question link (`_mail_hold`), Telegram's card (`mail_card`), `design_link` (`src/shiftlead/ui/queue.py`: its mail branch reads `own_refs(_refs(about), repo)` instead of building `ref` bare where `repo` is empty; its board and ledger branches are unchanged), and their callers in `src/shiftlead/ui/inbox.py`, `agent_notify.py`, `queue.py`'s reading. An item `mail_repo` names no repo for draws in the Inbox; its qualified refs read as written. `item_home`'s red PR and fork PR branches pass `e.get("repo")`, which `red_pr_rows` and `fork_pr_rows` always set (the reading's name, else its root's last component), so they keep their reading; a board line with no `repo_name` does not go through `own_refs` and keeps its one-repo lookup. Update `own_refs`'s and `item_home`'s docstrings (*a row with none is looked up bare* no longer holds for mail). Grep every `own_refs`/`first_ref` caller passing a possibly-None repo and check none relied on the old one-repo bare lookup.
