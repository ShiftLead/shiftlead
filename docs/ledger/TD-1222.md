## TD-1222: *Working* and *waiting* overlap (a session with its own running work reads *waiting* when it has an ask out), and *unseen* competes with both for the pill

**Priority:** Medium
**Type:** debt
**Added:** 2026-10-29 (Paul, through Add entry; drafted by ao-shiftlead-work-wait)
**Owner:** designer
**Kind:** design-first
**Status:** Open
**Location:** `docs/design/4.2-state-feed.md` (*Unseen idle*; *Waiting*; *Working on its own*, its **One order** sentence), `docs/design/4.5-ui.md` (*The card's anatomy*, the *waiting* and *working* pills), `docs/design/4.7-cli.md` (`ao status`, *a wait the home reads wins*); `src/shiftlead/ui/cards.py` (the pill composition after `waiting_view`: `own_work` is drawn only `if … not d["wait_reason"]`), `src/shiftlead/cli.py` (`own = None if waiting or s.get("pending") else own_work(s)`)

**Why:** Paul, 2026-10-29: *Our "WORKING" and "WAITING" statuses seem to overlap, or at least not be well-defined. I might see either value when a claude code session is waiting on a background process. I would expect waiting to only be used when another session (or a person) has to do work for the session to continue. I would expect working or be the status whenever an agent is active or has processes running (bg or otherwise).* The design draws an `idle` session *waiting* when the person inbox holds an open `ask`/`steer` from it naming a reference, or a seat holds its ask for a claim's PR, and *working* when a live subagent or background shell runs (TD-734, TD-761). Where both read, §4.2's **One order** puts the wait first (*since what needs someone outranks what runs*), and the card and `ao status -v` follow it. So a session that ended its turn on a background `gh pr checks` wait, a `Monitor`, or a reviewer subagent reads *working* if it has no ask out and *waiting* if it has one. The pill then changes with something the person cannot see in the work. It also says the session is stuck on someone while its own process is still running. The person reads *waiting* as "someone has to act", so they may answer or nudge a session that would have gone on by itself. They also cannot rely on *working* to mean "leave it alone".

**Fix:** design first: change §4.2's **One order** so live own work (`subagents_live`, `shells_live`) draws *working* whether or not a wait reads. *Waiting* is then drawn only for an `idle` session with nothing of its own running and a wait the page reads: a person's or another session's work is all that lets it go on. Keep the wait visible beside a *working* pill (the slot or the hover, e.g. *working · 1 shell · waiting on you: TD-222*), since the ask is still open. Take *idle · unseen* out of the pill order and make **unseen its own mark** (Paul, 2026-10-29: *maybe we make "unseen" independent of working/idle so it just denotes that there is info in the session that the user has not seen*). The mark is shown beside whatever the pill reads, when a turn has ended since the last Focus. Today's test, `since > seen_at` on an `idle` record (a missing `seen_at` counts as unseen), cannot carry it: `since` moves on every state change, so the round names the stamp it compares (the last Stop's time, say). So a session that answered and then started a background shell reads *working* and unseen. The pill then answers only *what is it doing*, and no pill gives way to *unseen*. Paul settled the two questions on 2026-10-29: *unseen should not show on unattended cards. it should move a card up the list*. So the mark stays off `unattended` sessions, as §4.2 *Unseen idle* says today, and an unseen card still sorts above its peers with the same pill. Then fix the same order in §4.5's pill text and §4.7's `ao status` line, and record the reversal of the 2026-10-15 order in `docs/design-history.md`. The build changes `cards.py` and `cli.py` (one helper they share, as `ending.own_work` is) and their tests.

**Done when:** the design states the one order and *unseen* as a mark independent of the pill, and a card and `ao status -v` both read *working* for an `idle` record with a live background shell or subagent and an open ask naming a reference. With no own work, the same record reads *waiting*. An interactive record that finished a turn after its last Focus shows the unseen mark whether its pill reads *working*, *waiting* or *idle*. A test pins each case.
