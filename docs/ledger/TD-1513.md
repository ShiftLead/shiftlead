**Ask:** Should TD-1482's builds (TD-1513, TD-1514: the design's history one file per ledger entry with design-history.md frozen, and a board conflict resolved by agent-cadence's replay) go ahead as written after four review rounds ended at the cap, every build-changing fix read by a later review?

**Fix:** Build design §4.4 *Two PRs' records merge in either order*, its first item, in one PR:
1. **`scripts/history.py <section> [--grep <text>]`**: prints a section's record: first every `docs/history/*.md` file's lines under its `## §<section>` heading, newest first by the line's date, a tie by the file's name in plain string order (`TD-10.md` before `TD-9.md`), then later in the file first (the key `(-date, name, -line)`); then `docs/design-history.md`'s heading or headings for it (`## 6. Policies …`; `## §4.4a (second half) …` and the three `§4.10` headings map by their leading number; `Title and status` to `title`) as written, in file order, undated bullets (any `- ` bullet with no leading date: `- undated: …`, `- (TD-015): …`, `- No dated facts removed.`, 43 of them) kept in place, no frozen line re-sorted. A line is a `- ` bullet with its indented continuation lines. A heading's number equals the argument exactly (`4.4` reads no `4.4a` heading, `4.1` no `4.10`). The indexed sections are `docs/design.md`'s `- **§<n>**` bullets, plus `title`; a heading's number matches with or without its leading `§`. Exit 1 with a message on a section not indexed.
2. **`tests/test_history.py`**: every `docs/history/` file but `README.md` is named `TD-<n>.md` or `<YYYY-MM-DD>-<slug>.md` (the slug the branch lowercased, every character outside `[a-z0-9]` written `-`, runs collapsed), there is no subdirectory, blank lines pass anywhere, and each file has only `## §<section>` headings naming an indexed section (as step 1 reads them) or `## §title`, with only `- YYYY-MM-DD ` bullets and their continuations under them, and nothing else (no `# ` title, no prose before the first heading); `docs/design-history.md`'s sha256 over its raw bytes (`read_bytes()`) equals a constant in the test (the file as this PR leaves it), so any later change to it fails, the hash a function of a path so the test shows it failing on a changed `tmp_path` copy; every `TD-<n>.md` names an entry the branch's ledger holds, open or archived (an orphan left by a renumber fails; a bought round's entry is on main or filed in the same PR — TD-1511 was filed by #3141 before #3152 wrote its round); and the reader's order on a fixture (a tie, a frozen section with an undated line, a section with two frozen headings, `4.1` against `4.10`), and a stray prose line failing.
