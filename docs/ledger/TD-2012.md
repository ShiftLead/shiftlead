## TD-2012: The full suite's workers die near the end of its UI tests, so main's precheck and every PR's go red

**Priority:** High
**Type:** debt
**Added:** 2026-11-19
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** b73c2e0c1d854da8b48f93544491f018

**Why:** Main's own precheck is red, and so is every PR's (#4217, #4218 on 2026-11-19), for one reason: near the end of the full suite, several pytest-xdist workers die ("[gwN] node down: Not properly terminated"). Each dies while running a UI test that drives pages through a TestClient: `test_ui.py::test_pages_and_shell_flow`, `test_settle_pages.py`, `test_sweep_switch.py`, `test_ui_build_chip_pages.py`, `test_no_agent_pages.py`, `test_ui_focus_reaped.py`. Every one of them passes run alone, and all 158 pass together without xdist. While main's precheck is red no PR can pass the gate. The cause is not read yet. Candidates: something late in the run signals or exits the worker process (a test's `os._exit`, a kill of a process group or pid it did not start); memory; or the shared `/tmp`, which ran to 100% of its inodes the same day (the precheck's tree ran under `/tmp/shiftlead-1000/…` on one run, `/var/tmp` on another).

**Location:** tests/ (the UI page tests run under pytest-xdist)

**Fix:** Reproduce with `pdm run test` in a clean worktree at `origin/main` (or `agent-cadence run precheck.py` on a PR). Then find what ends the workers: run with `-p no:randomly` and xdist's `--max-worker-restart=0`, read which test ran last on each dead worker, bisect the test files that ran on it before it died, and look for a test that sends a signal, calls `os._exit`/`sys.exit` in-process, or kills by process group. Fix the cause in that test, or its fixture.

**Done when:** Main's precheck passes the full suite with no worker crashing, on two runs.
