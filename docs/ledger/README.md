# Technical Debt

Ledgerboard: 2

Known issues, compromises, and deferred work. Add an entry any time a problem is identified but not immediately fixed — no exceptions, however small (cadence §2: `agent-cadence path cadence.md`).

**This directory holds open work only, one `TD-NNN.md` per entry** (Ledgerboard 2, TD-1195). A new entry is a new file, its id from `ao td reserve`. No summary table is stored: `agent-cadence run ledger.py --summary` prints it from the entries, and the Queue and Repo page show it. An open entry's **Status** is `Open`; its notes go in its **Log**, one dated line each (`agent-cadence run ledger.py note TD-n "…"`). When an entry is fully resolved, `agent-cadence run ledger.py archive TD-n --why "…" --pr <n>` moves its file into [`archive/`](archive/) and writes its closed form: a dated Status (`Resolved <date>`; `--dropped` and `--superseded-by` for the other closes) and a **Resolved** line in place of **Fix**, with a pointer (`--pointer`) to whichever doc or code now carries the lasting content. An entry that is only *partly* resolved stays here, with what shipped and what remains in its Log.

IDs are `TD-` plus a number zero-padded to three digits (four from TD-1000 on), assigned in order and never reused. Priority is a field, never part of the ID.

Two header lines follow **Added:** so a worker can filter the entries instead of re-reading them (TD-118): **Owner** — who moves the entry next (`designer`, `grinder`, `paul`; the anchor seat is retired, design §4.9b *No anchor seat*). Another repo's work is never an entry here: it is filed on that repo's ledger, with `ao td add --repo <repo>` (its techlead drafts it), and what waits on it here names it as `<repo>#TD-NNN` in `Blocked by` (Paul, 2026-10-28); **Kind** — what the next step is (`build`, `design-first`, `live-check`, `evaluation`, `decision`). Every open entry carries them; keep them true as the work moves. A third, **Waits**, is retired (TD-1392, design §4.4 *An entry says what it waits for*): a wait on a date or an event is a **gate** in `**Blocked by:**`, after its ids — `until YYYY-MM-DD` (a UTC day, *`**Blocked by:** until 2026-11-20`*), or `event (<name>)` with an `**Event (<name>):**` section of one plain line and one `check:` line, written first (`ledger.py edit TD-n --section "Event (<name>)" --from <file>`, then `ledger.py set TD-n --blocked-by "<the ids>, event (<name>)"`); a wait no check can see is a judgment entry blocked on by id, or `until` the day of the next look. What waits on the person is a bare `Blocked by: decision (paul)` — never `decision (paul) — <text>`, which `ledger.py set` refuses — written in three steps in one PR: an `**Ask:**` in the body saying what lets it go (`ledger.py edit TD-n --section Ask --from <file>`), then the gate (`ledger.py set TD-n --blocked-by "<the ids>, decision (paul)"`), then a `decide` item on `docs/user_attention.md` whose Context is exactly `TD-n decision (paul)` (design §4.4 *What waits on the person*: the merge gate refuses a decision with no board item) — an `Owner: paul` entry carries the gate too, since an Owner says who moves an entry next and holds nothing (TD-1374, TD-1375) — never a `Waits:` line. A design entry names the PRs that wrote it in a **`Design PR:`** section of its body, a section as `**Ask:**` is — `#3025, #3136`, oldest first, one number per design PR — written by the designer in each design PR (`ledger.py edit TD-n --section "Design PR" --from <file>`, design §4.9c *The designer records its PR*); an item about the entry draws *· design #n*, a link to the last (design §4.5 screen 6 *An item about a design links the design's PR*, TD-1531). **Pickable is derived, never written** (cadence §2.4, TD-228): an entry is pickable while its `**Blocked by:**` names nothing still open and no decision, and no open entry is `Part of:` it, so what waits on another entry or on a person's word says so there, with its pointer; what nothing blocks and a grinder still cannot build — a live look, an evaluation, the person's edit — is said by its **Kind** or its **Owner**, and its Log says what is next. **Part of** (cadence §2.4, TD-1129) names the one parent an entry is a part of, in this ledger: each build of a design, and each subtask of a feature, writes `**Part of:** TD-n`, and the parent's own `Blocked by:` keeps only what must land first, never its parts (a part blocked by its parent is a cycle `ledger.py --check` refuses). A parent is ordered after its parts and archives with its last one, in that part's PR (design §4.9c *A design entry archives with its last build*); a design still listing its builds in `Blocked by:` is read the old way until it is backfilled. A `live-check` is followed on its line by its build's last merged PR — `**Kind:** live-check #<n>`, written by the PR that makes the entry a live check, which also writes its `event (live)` gate (an `**Event (live):**` section, *The build is live.* and `check: file-contains shiftlead@promote/live docs/ledger/TD-n.md "**Event (live):**"`, then `event (live)` in `**Blocked by:**`) — and once the event runner lifts that gate, the PR being live, the check is in a `free-pick` lane whose owner it has (design §4.9b *A live check waits on a gate for its build to be live*, TD-320, TD-1437); a gate's name is never reused (`live`, then `live-<digits>`, and `live-td<m>` for a fix's), and those names are the live checks' alone; cadence's script reads the word alone. A grinder's pick list is therefore `ao repo` (its pickable entries, a live check whose `event (live…)` gate has lifted among them), and `python3 scripts/ledger.py --list --pickable yes --owner grinder --kind build` lists the builds alone; the designer's is `--owner designer --kind design-first`. The line below is the one list of the **Owner** and **Kind** words (cadence §2.12): `scripts/ledger.py` flags a value outside it, and `tests/test_ledger.py` reads its sets from it and checks the two lines' shape, so a new word is added there and nowhere else.

Fields: Owner = designer | grinder | paul; Kind = build | design-first | live-check | evaluation | decision
