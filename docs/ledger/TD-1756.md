**Location:** docs/briefs/designer-ao-1.md

**Fix:** In `docs/briefs/designer-ao-1.md`, under *How a design is reviewed here*, write as design §4.9c *What a design's author prepares before a review* says, from *The prep file* through *The gate*:
- whether the gate holds is decided once, by the brief a design's round 1 starts under, and recorded: before round 1's first run of the script the sender writes `gated (TD-1720)` on the design entry's Log (`ledger.py note`) and commits it, which a later round's sender reads, no note meaning ungated: a design whose round 1 starts under this brief is gated in every later round, bought rounds and `Hold` revisions included; one whose round 1 began earlier (a designer started before the merge keeps its brief) is not, in any round — its prep file optional, the script run with `--advisory` where the file exists, no script step in its reviewers' prompts;
- the author writes `docs/reviews/TD-<design>.prep.yml` with the draft: every claim about what existing code, a doc or another section does, every rule stated in two or more places with terms the author chooses (never inferred), the `new` paths; whoever applies a round's fixes keeps it true at every fix; the checklist (TD-1757) is read before drafting once it is in the brief;
- whoever sends a review (not the fact-check trial's ask, which is outside the gate, with no row and no line) runs `pdm run python scripts/design_prep.py --entry TD-<design>` on the commit the review will read and sends it only on a PASS, or on its own CANNOT RUN, filed with `ao finding` and sent in the pass line's place;
- every reviewer's prompt (fact-checks and design reviews) begins with `git fetch origin` and `pdm run python scripts/design_prep.py --entry TD-<design> --rev <commit> --base <the base on the sender's pass line>`, the one command a reviewer runs that is not a read, from its own worktree, never the main checkout (with the main checkout's `.venv` interpreter where its worktree has no environment); on exit 1 or 2 it replies `NOT PREPARED` with the script's lines and nothing else, and the review gets no row in the record; on exit 3, or any output whose first line is not `design-prep:`, it goes on if it can read the commit, its reply leading with the CANNOT RUN line, else its whole reply is that line and the review gets no row; and the sender files it; a NOT PREPARED where the sender's run passed is re-run, filed, and the review sent again to go on as on a CANNOT RUN;
- the PR body's `**Rounds**` list: one line per review, written when its row is, `R<n> · <round> · <role> · <pass line, or the sender's filed CANNOT RUN line>` (`R<n>` the record's id, `<round>` cadence §4.8's; no line for a review that ended NOT PREPARED or was never sent, one line for a review sent again), and a last `final · <pass line>`, run on the commit that merges — the head once the closing fact-check's fixes and the bookkeeping after them (the item, the builds' blocks, Asks and Fix, the Status) are in — and again whenever the head moves, a FAIL there mended with no new review (a mend that changes the design, or a waiver added or widened, listed as a fix no review has read), a CANNOT RUN there filed and written in the line;
- each fact-check checks every claim added or changed since the last (round 1's every claim) at its `at`, reads every waiver, and raises an undeclared claim (minor) or a waiver hiding a fault (build-changing when what it hides is); the closing fact-check also reads the rounds list against the record's rows (a mismatch a minor finding), raises a round 1 whose lines carry pass lines on an entry with no gated note, and the end-of-rounds item and PR body for restated rules;
- the ways out: `new` for a path a build creates, `waive` for a false alarm, a NOT PREPARED mended; before a later round's first run in a PR of its own, the author drops the waivers that PR's text no longer needs.
