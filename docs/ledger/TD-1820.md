**Why:** Found by the test-audit of #3781 (TD-1807). The tick's wiring of the composer rows has no test: `tick()` in `src/sessionorc/agent_tick.py` builds `waiting` from `_composer_candidate` and fills `self._composer_tails` with `capture_tail(sid, COMPOSER_LINES, raw=True)`, which `_at_waiting_composer` reads. Every new test in `tests/test_stall_clock.py` fills `agent._composer_tails` by hand (`_composer`) and calls `_stall_check`; nothing else in `tests/` names `_composer_tails`. Probe: replacing the `waiting = [...]` line with `waiting = []` left the five TD-1807 tests passing (`PYTHONPATH=$PWD/src pdm run pytest -q tests/test_stall_clock.py tests/test_finished_tick.py tests/test_agent.py tests/test_agent_split.py tests/test_subagents_live.py`: only six failures, the same six that fail unmutated in this scratch worktree with `unknown adapter 'gemini'`, an install without that entry point). The feature would then never fire live (`raw is None` returns False), and no test would say so.

**Location:** tests/test_stall_clock.py

**Fix:** Add a test that drives a real `tick()` over a fake tmux whose `capture_tail` returns the `idle-composer.txt` rows for a tick-set `working` claude-code record, and asserts the record reads `idle` after the tick, and that a hook-set `working` record's raw rows are not captured. Re-run the probe: it must fail.
