## TD-1340: A Queue card with two or more Decide or Do items draws the header's Start session beside the items', and its session walks every item in turn

**Priority:** medium
**Type:** debt
**Added:** 2026-11-03 (the designer, from TD-1338's design)
**Owner:** grinder
**Kind:** build
**Status:** Open
**Part of:** TD-1338
**Location:** `src/shiftlead/ui/queue.py` (`items_start` ~608, which becomes a count); `src/shiftlead/ui/templates/queue_card.html` (the header's Start session ~36–43, `{% if c.items_start %}`); `src/shiftlead/ui/app.py` (`api_ledger_start` ~3207, its `why_key` and the `queue` reading's *waits on me*); `src/shiftlead/repoconfig.py` (`WORK_OPENING` ~130, `WORK_ITEM` ~139, `work_text` ~281); `src/shiftlead/ui/help.py` (`card-start` ~689); `tests/test_ui_queue.py`, `tests/test_repoconfig.py`, the help's doc-bound tests

**Why:** TD-1338 (Paul, 2026-11-03: *there are times that there are multiple questions on a single card that it would make sense to handle in the same session*; he chose *keep both*): a card with several Decide and Do items has no button that starts one session on all of them, so the person starts from one item and pastes the others' ids in by hand.

**Fix:** as designed in §4.5 screen 12 *Three verbs: Start session* (*Started from the header on a card with items*) and §4.5a *Queue card: Start session / Open session*:
- **The count:** the card carries how many of its Decide and Do items draw a Start session of their own (a red PR, a fork's PR and an item *answered — waiting on <asker>* do not count; an item *with you in <name>* counts, since it draws Open session), in place of the boolean `items_start`. The header draws its Start session, or its Open session by the holder rule, where that count is 0 or 2 or more, and nothing where it is 1.
- **The header's title** on a card with two or more: *Start one session for all n items on this card, one at a time*, n the count, as its `title` and `aria-label`; on a card with none it keeps `help_title('card-start')`.
- **The road** is unchanged on the wire: `{repo, id, card}` with no `item`, on the card's `start`. `api_ledger_start` reads the card's *waits on me* from the `queue` reading, and where it names two or more items, `work_text` takes a new first sentence in place of the `why_key` one — a constant beside `WORK_ITEM` (say `WORK_ALL`), swapped in as `WORK_ITEM` is: *I opened this session from the Queue to work through every item that waits on me on the card around {id}, one at a time: for each, read it, tell me its goal and what each answer leads to, and wait for my answer before the next.* `work.md` is unchanged; the id list and the closing sentences stand. With one item or none left at the press, the `why_key` sentence as before.
- **The help:** `card-start` drops *It is drawn only where no item on the card asks you anything: each such item has its own.* and says it is drawn where no item asks anything, or beside the items' where two or more do, to take them all in one session. (§4.5a's help list is reworded here, in this build, never in a design PR.)

**Done when** a card with two Decide or Do items draws the header's Start session beside both items' buttons, with the *all 2* title; a card with one draws none in the header; a card with a red PR and one ledger item draws none; a header press on a two-item card opens a session whose prompt starts with the walk sentence and whose *waits on me* names both, and a press when only one is left takes the `why_key` sentence; once the session runs every button on the card reads Open session; the help's doc-bound tests pass with the new `card-start`; and `pdm run test` passes.

**Related:** TD-1338 (the design); TD-1246 (the item's Start session and the header rule this changes); TD-1316 (the *answered* item, which draws no Start session).
