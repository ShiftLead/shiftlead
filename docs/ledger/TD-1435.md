What wakes a session for an ask it has already read:
- **The doorbell** (`_decide_wake`, `src/sessionorc/agent_wake.py:528`) does not. It reads only mail past the `mail_decided` watermark (`mail.undecided_mail`) and moves the watermark past what it rang.
- **Rule 4's idle nudge** (`_idle_nudge`, `src/sessionorc/agent_tick.py:1298`, after `IDLE_NUDGE`, 20 minutes) does, but only for a record with a seat. Its line (`_nudge_line`, `agent_tick.py:2874`) names *N questions waiting* from `asks_waiting` (open asks, read or not) when `s.seat` is set and `seat_due` is due. On a record with no `seat`, the line names only claimed open work (`_open_ref`) and outcomes owed to the person (`_owed_part`), never an open ask from another session. This record has `seat: None` (`ao --json status`), although it holds the team's techlead role and is asked as one. The nudge it got read *you have been idle 20 minutes: you owe 1 outcome on m-cff7a98452d6*, with the TD-1428 and TD-233 asks open.

The same missing seat explains the second gap. `message_edge` (`src/sessionorc/mail.py:472`) lets a reply through to an ask from a session the replier may not otherwise write to only when `asks_seat(me)` (`mail.py:530-537`). So `ao msg --kind reply --reply-to m-7bdae3194ee7` from this record to `ao-agent-cadence-ac-grinder` (another repo's grinder) was refused (*cannot message …*, §4.10). `ao inbox` has no close, so that ask stays *open, no bound* until its asker withdraws it or the person closes it.

**Fix:** Design first (§4.10 *Mail*, §6 rule 4, §4.9b on seats). First find out why a team's techlead session carries no `seat` on its record: whether a hand-started or older techlead session is never given one, or loses it. Then decide between these:
- An open ask counts toward rule 4's idle line for every record, not only a seat's: *you have N questions waiting — run `ao inbox`*, once per idle stretch, as a seat's line does now.
- A reply on an ask's own thread is allowed from whoever the ask was addressed to, not only from a question seat. Or there is an `ao inbox close <id> --why` for an ask the record cannot answer.
- The techlead's brief (`src/shiftlead/briefs/techlead.md`, a held path) says to work every open ask to an answer, a hand-off or a filed entry before ending a turn.

**Done when:** The design says why this record had no seat and whether a record with no seat is nudged for its open asks. A test: an idle, unattended record holding one read, open ask from another session gets the *questions waiting* line. Another test: a reply on the thread of an ask from a cross-repo seat is accepted, or the ask is closable.
