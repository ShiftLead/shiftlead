## TD-2124: The disk sweep can delete the attachments of a session started while it runs

**Priority:** Low
**Type:** debt
**Added:** 2026-11-23
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 74a0e900ce5a46a8960f398fe8acc913

**Why:** The hourly disk sweep's age rule for attachments tests only the live ids read at the start of the pass. A session started under a reused id after that reading is missing from them, so its attachment files past the keep age can be removed while it is live. TD-2092 closed the same gap for run and round logs, and the independent review of #4445 named this one by reading the code; it has not been reproduced.

**Location:** src/sessionorc/agent_tick.py (_prune_rules)

**Fix:** In `_prune_rules` (`src/sessionorc/agent_tick.py`), read the live records again just before removing an attachment by age, as `log_live_now` does for a log, and keep a folder whose id a live record now holds. This is a held path, so the pull request goes to the techlead.

**Done when:** A test shows a session created after the sweep's reading keeps its old attachment through that pass, and the suite passes.
