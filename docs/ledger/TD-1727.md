**Location:** src/sessionorc/agent_tick.py (the tick's pass, beside setup_note's), src/sessionorc/agent_mail.py (_system_note), src/sessionorc/paths.py; design §4.3

**Why:** The seat smoke runs by hand, and an upgrade no entry names (TD-1576's) goes unnoticed. TD-1650 designs the home's part: design §4.3 *An upgraded seat tool asks for the smoke* (compare each seat profile's newest launch version with the last one noted, and note the person once per change, spending nothing).

**Fix:** 1. On the home's tick, at most every `VERSION_EVERY` (an hour): for each profile a seat record runs on (a record carrying `seat`, exited ones included; the home's records, never the org's files — `sessionorc` imports no `shiftlead`), take the newest such record on that profile carrying `tool_version` and compare it with `~/.shiftlead/tool_versions.json`'s `{<profile>: {version, at}}` (a path in `src/sessionorc/paths.py`).
2. No entry for the profile: write it, send nothing. A different string: write the new version, then send one `_system_note(PERSON, …)` naming the adapter (its registered name), the profile, the old and new versions, the host the record ran on, and the smoke's command line (`pdm run conformance <adapter> --profile <p> --smoke`, one prompt and one reply of the profile). The same version again sends nothing. A profile no seat record runs on is not read. Nothing is run.
3. Home only (a node sends its records; the home compares).
4. Tests: first sight writes and sends nothing; a change sends one note and a second tick none; a move back to the older version is a change; a profile only non-seat records run on is skipped; a pool member's profile is read; no record carrying a version leaves the file alone.

**Done when:** The home notes the person once when a seat profile's tool version changes from the one it last noted, spending nothing and running nothing, as design §4.3 *An upgraded seat tool asks for the smoke* says; tests as the Fix lists.
