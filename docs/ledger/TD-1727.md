**Why:** The seat smoke runs by hand, and an upgrade no entry names (TD-1576's) goes unnoticed. TD-1650 designs the home's part: design §4.3 *An upgraded seat tool asks for the smoke* (compare each seat profile's newest launch version with the last one noted, and note the person once per change, spending nothing).

**Fix:** 1. On the home's tick only (guard on the home's mode; a node's tick skips it), at most every `VERSION_EVERY` (an hour, a monotonic timer as `SETUP_EVERY`): for each profile a seat record runs on (a record carrying `seat`, exited ones included; the home's records, never the org's files — `sessionorc` imports no `shiftlead`) and each host such a record ran on, take the most recently created (`created`) such record carrying `tool_version` and compare it with `paths.home() / "tool_versions.json"`'s `{<profile>: {<host>: {version, at}}}` (`at` the UTC time written). A record's empty `profile` (the default) is keyed `""` and said *the default profile*.
2. No entry for the profile and host: write it, send nothing. A different string is a change. The changes one tick finds go in one `_system_note(PERSON, …)`, a line each naming the adapter's `label`, the profile, the old and new versions, the host, and the smoke's command with the adapter's registered `name` (`pdm run conformance <name> --profile <p> --smoke`, one prompt and one reply of the profile; `--profile <default>` for the default profile; a node's line says *run it on <host>*, from a checkout there). At most one note every `VERSION_NOTE_EVERY` (a day): a tick inside it sends none and writes nothing, so the next note says *moved from* the last noted version to the newest. Send first, then write the file (as `_setup_notes` does). The same version again sends nothing; the file is never pruned. A profile no seat record runs on is not read. Nothing is run; no techlead is told.
3. Home only (a node sends its records; the home compares).
4. Tests: first sight writes and sends nothing; a change sends one note and a second tick none; a move back to the older version is a change; two hosts on different versions of one profile are two entries and never re-note each other; two changes in one tick are one note; a change inside `VERSION_NOTE_EVERY` waits and is noted from the last noted version; the newest record is by `created`; the default profile's `""` key and words; a node's line says where to run it; a profile only non-seat records run on is skipped; a pool member's profile is read; no record carrying a version leaves the file alone.

**Done when:** The home notes the person once when a seat profile's tool version changes from the one it last noted, spending nothing and running nothing, as design §4.3 *An upgraded seat tool asks for the smoke* says; tests as the Fix lists.
