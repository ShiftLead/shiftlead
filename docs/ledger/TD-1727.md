**Location:** src/sessionorc/agent_tick.py (the tick's pass, beside setup_note's), src/sessionorc/agent_mail.py (_system_note); design §4.3

**Why:** The seat smoke runs by hand, and an upgrade no entry names (TD-1576's) goes unnoticed. TD-1650 designs the home's part: design §4.3 *An upgraded seat tool asks for the smoke* (compare the newest launch version per adapter, seat profile and host with the last one noted, and note the person once per change, spending nothing).

**Fix:** 1. `VERSION_EVERY` and `VERSION_NOTE_EVERY` live in `src/sessionorc/agent_tick.py` beside `SETUP_EVERY`. On the home's tick only (guard on the home's mode; a node's tick skips it), at most every `VERSION_EVERY` (an hour, a monotonic timer as `SETUP_EVERY`): for each adapter and profile a seat record runs on (the record's `adapter` and `profile`; a record carrying `seat`, exited ones included; the home's records and its nodes', `self._graph()`, never the org's files — `sessionorc` imports no `shiftlead`) and each host such a record ran on, take the most recently created (`created`) such record carrying `tool_version` and compare it with `paths.home() / "tool_versions.json"`'s `{noted_at, versions: {<adapter>: {<profile>: {<host>: {version, at}}}}}` (`at` the UTC time a version was written, `noted_at` the UTC time the last note went). A record's empty `profile` (the default) is keyed `""` and said *the default profile*.
2. No entry for the adapter, profile and host: write it, send nothing. No record left carrying a version (forgotten): keep the stored one, send nothing. A different string is a change. The changes one tick finds go in one `_system_note(PERSON, …)`, led by a sentence ended with a full stop and a line break — *A seat tool changed version; no seat smoke has passed on it.* or *<n> seat tools changed version; no seat smoke has passed on them.* (its subject, `mail.subject_of`) — then a line each naming the adapter's `label` (the record's `adapter` name where `adapters.get` raises `KeyError`, the lookup inside the pass's own guard (`_setup_notes` guards only the call); the pass never raises), the profile, the old and new versions, the host, and the smoke's command with the adapter's registered `name` (`pdm run conformance <name> --profile <p> --smoke`, one prompt and one reply of the profile; a line about the default profile reads `--profile <default>` and says the smoke walks the profile `profiles.yml` makes default only if it has a `config_dir` set aside, else it cannot be smoked (a seat launched with `""` and one with the default's name are two keys, accepted); a line about the home's own host says *Run it:*, a node's *Run it on <host>, from a checkout there:*). At most one note every `VERSION_NOTE_EVERY` (a day) since `noted_at` (wall clock, so it survives a restart): a tick inside it sends none and writes no change (a first sight it still writes), so the next note says *moved from* the last noted version to the newest. Send first, then write the file (the changed versions and `noted_at`), as `_setup_notes` does; new here: write it by a temporary file and a rename, `noted_at` kept in memory too; an unreadable file reads as empty; a `noted_at` in the future reads as lapsed. The same version again sends nothing; the file is never pruned. A profile no seat record runs on is not read. Nothing is run; no techlead is told.
3. A node compares nothing: it sends its records, and the home compares (Fix 1's guard).
4. Tests: first sight writes and sends nothing; a change sends one note and a second tick none; a move back to the older version is a change; two hosts on different versions of one profile are two entries and never re-note each other; two adapters' seats on `""` on one host are two entries and never re-note each other; two changes in one tick are one note, whose subject is its lead sentence (singular and plural); a change inside `VERSION_NOTE_EVERY` waits and is noted from the last noted version, across a restart too; a first sight inside the window is written; the default profile's line reads `--profile <default>` and says it is smoked only if set aside; the newest record is by `created`; the default profile's `""` key; a node's line says *Run it on <host>, from a checkout there:* and the home's own *Run it:*; a profile only non-seat records run on is skipped; a pool member's profile is read; no record carrying a version leaves the file alone; an unreadable file reads as empty; a `noted_at` in the future reads as lapsed; an unregistered adapter's line falls back to its name and the pass does not raise; a node's tick skips the pass; a session made a seat in place (no launch) carries no version until its next launch and is skipped; one whose seat is dropped is no longer read.
