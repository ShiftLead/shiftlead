## TD-1530: test_a_hook_before_the_bound_keeps_the_ordinary_road failed under a precheck: its 0.5 s bound can lapse before the test's first hook

**Priority:** Low
**Type:** debt
**Added:** 2026-11-07
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** e9d99bff4a84426792b01a1313a9eec4
**Location:** tests/test_first_prompt.py (test_a_hook_before_the_bound_keeps_the_ordinary_road); src/sessionorc/agent_wake.py (the first-prompt bound)

**Why:** #3181's first precheck, on bfbeb38 on 2026-11-07 (a clean worktree running the whole suite), failed at `tests/test_first_prompt.py:239`. The PR changed only `_brief_restart`, the brief clause and the templates. The failure was `assert rec.first_prompt_error is None`, which read `'no hook since launch'`, and the log said *the brief of ao-w was not sent: no hook since its launch*. The same head passed `pdm run test` locally.

The test patches `FIRST_PROMPT_BOUND` to 0.5 s and sends the first hook (`rpc_hook(w, state="working")`) only after `_start` returns. Under a loaded run, `_start` plausibly takes more than 0.5 s from the launch, so the tick marks *no hook since launch* before the test's hook arrives. That is a race in the test, not in the rule. This is the sibling of TD-1218, which is the other first-prompt flake in this file.

**Fix:** Confirm the race first:
- Under load, time `_start`'s return against the launch, for example by running this file beside a second full suite.
- Read where the bound's clock starts in `agent_wake.py`.

If it is the race, make the test hold the bound until its hook has landed, without lengthening what the rule says:
- send the hook before the bound can lapse, for example by patching `FIRST_PROMPT_BOUND` only after `rpc_hook(…, state="working")`; or
- start the bound's clock from a time the test controls.

Do not just raise the timeout.

**Done when:** The cause is named in this entry. Either the test passes in the full suite under load, or this entry says why the flake cannot recur.
