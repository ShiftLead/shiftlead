**Why:** The design keeps where an entry is on one ShiftLead branch of the repo, written only by the home, so it survives a restart of the home and any machine can read it. A move to the person is written from the same place.

**Ask:** Should the builders start on the stage record and its one writer?

**Fix:** Build design §4.9c *The stage record* and *A move to the person is the entry's decision*, and §4.4 *The stage record is a file on the repo's `shiftlead/state` branch*: the branch created at a team's first start, the entry records, the audits' run records and the team's last good flow; the one writer; the intent, the one pull request holding the ledger change and the covering decide item the gate sweep would file, and the answer map kept on the record.

**Done when:** A record written by the home is read back after the home restarts. A move to the person lands one pull request with the entry's gate, Ask, lifting Answers and the covering board item, and the Queue draws its card. Measured and written down: what a push to the branch costs against the forge's limits, and what one question costs (its pull request, main's precheck, and the rebase and fresh precheck of the entry's own open pull request, which archives the same ledger file). Settled: how the cadence's audit reads the home's combined ledger-and-board pull request; that the home adds its gate to an existing Blocked by, and whether the entry's own earlier Ask and Answers are put back after the lift. A push the forge refuses makes the flow not usable with the reason shown. Lands with nothing reading it.
