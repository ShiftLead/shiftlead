## TD-1274: No test sees the `ledger_start` press send the item or card in its request

**Priority:** Medium
**Type:** debt
**Added:** 2026-10-30 (test-audit-ao-1, auditing the last ten merged PRs)
**Owner:** grinder
**Kind:** build
**Status:** Open
**Location:** `src/shiftlead/ui/static/app.js` (`ledger_start`: `body: JSON.stringify({ repo, id, …(b.dataset.card …), …(b.dataset.item ? { item: b.dataset.item } : {}) })`); `tests/test_queue_start.py` (`PRESS_PROBE`)

**Why:** #2719 (TD-1257) rewrote `test_an_items_open_session_copies_its_id_and_the_toast_shows_it_where_refused` to run the press under node, and in doing so dropped the assertion `...(b.dataset.item ? { item: b.dataset.item } : {})` in the press. Its probe's `fetch` stub ignores the request, so nothing reads the body. Probes at `origin/main` 255921409: deleting the `item` spread from the body, and separately the `card` spread, then `PYTHONPATH=$PWD/src pdm run pytest -q tests -k "queue or ui_inbox or ui_entry or focus"` gives `542 passed` both times. The server-side tests post `item` themselves, so a press that no longer names its item — the prompt then names no item and the road starts the card's top entry — fails nothing.

**Fix:** have `PRESS_PROBE`'s `fetch` record its `(url, body)` and assert the body names `repo`, `id`, `card`, and `item` where the button has one.

**Done when:** deleting the `item` spread, or the `card` spread, from the press body fails a test.

**Related:** TD-1257, TD-1246, #2719
