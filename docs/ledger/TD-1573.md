## TD-1573: An open entry no lane takes is silent, and the team card's bar and Start count it differently: a mechanical no-lane check

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-10
**Owner:** designer
**Kind:** design-first
**Status:** Open
**Id take:** d81d9d3eb6374216abe73b0097aab25f

**Why:** An open entry that no lane of its repo's teams can take sits unpicked, and nothing says so. Worse, the team card and Start disagree about it. Seen 2026-11-10 (Paul, through `ao-led-tds-ledger`, m-8a8fb4fd3858): ledgerboard TD-058 was filed `Kind: design-first` with `Owner: techlead`. lb-grind's `td` flow gives its designer the lane `[design-first, owner:designer]` and its grinder `free-pick`, so by `ledger.lane_matches` (design §6 rule 6) no lane took it. The team card's bar counted *1 design*, by Kind alone. Start's dialog said *Nothing to pick … grinder: 0 · designer: 0*. It was fixed by hand (ledgerboard #197, `Owner: designer`), but nothing would have said so.

The design promises one reader, so the card, the Repo page and `ao repo` cannot disagree (§4.4 *In a team's lanes*, `ledger.in_lanes`). But that reader names *the rest*, what no lane of the team takes, for the *pickable* kind alone, by `Owner:`, and says *design* and *live check* have none. So a `design-first` entry whose `Owner:` no designer lane names is counted under *design* on the bar, is in no member's count, and is in no *rest*. Some checks already exist, each for one case only: `ledger.NO_LANE` flags an `evaluation`, `ledger.NO_KIND` flags an entry that fits no page kind, and `queue.py` can draw *no lane takes it* for those page kinds (`queue.NO_LANE`). None of them asks the general question: does any lane of the teams serving this repo take this open entry?

Paul asks for the general check and that it be **mechanical**: code in the home, the writer path and the CLI, computed by the same `lane_matches` the pick uses, never a session or an LLM judging it.

**Location:** src/sessionorc/ledger.py (lane_matches, in_lanes; new lane_gap); src/sessionorc/agent_tick.py (the mark step); src/sessionorc/queue.py (the no_lane mark beside NO_LANE); src/shiftlead/teamrun.py (repo_lanes, lanes, lane_kinds); src/shiftlead/cli.py (ao repo, ao team start); src/shiftlead/ui/org.py, repo.py, repo_board.py; src/shiftlead/ui/static/app.js (Start dialog); design §4.4 Repo facts, In a team's lanes (An entry no lane takes is marked); §4.5 screen 11; §4.5a team card: Repo facet, Start; §4.7

**Ask:** Held with its design TD-1573 until Paul answers its end-of-rounds item (Go, One more round or Hold) on docs/user_attention.md.

**Design PR:** #3497, #3574

**Fix:** Design first (§4.4 *Repo facts*, *In a team's lanes*; §4.5 screen 11; §4.5a *team card: Repo facet* and Start; §4.7 `ao td add`, `ao repo`), then builds.

1. **The check.** For an open entry whose gates leave it pickable, find the lanes of every team whose repo is the entry's repo (`teamrun.repo_lanes`) and test it with `ledger.lane_matches`. If no lane takes it, say so and name the header field that keeps it out, e.g. *Owner techlead; the designer lane needs owner:designer*. Run it at three points:
   - **At filing and on a header edit** (`ao td add`, `ledger.py new` and `set` through the home where it is reachable): print a warning line. Refuse only where no `Owner`/`Kind` value could ever match any lane of the repo's teams.
   - **On the tick**, for entries that landed any other way: a row on the Repo page and on the team card.
   - Settle how the check reads lanes before a team's first start, when no record carries a lane, the way the Start dialog reads the plan's lanes (§4.5a *What the lanes hold, before the start*).
2. **One count.** The team card's bars and Start's lane counts read the same lane match, so they never disagree. `ledger.in_lanes`' own `design` list already holds only what a lane takes; the count that disagreed is the repo-wide kind bar (`kind_of`, by `Kind:` alone), which drew TD-058 as *1 design*. That bar draws an entry no lane takes in its own *no lane* count, not under *design*, through a widened *rest* in `in_lanes` (past the *pickable* kind) or a reading beside it.
3. **`ao repo`** lists entries no lane takes as their own group, *no lane*, not under *design*. The Repo page's *no lane takes these* fold carries them too.
4. **A test**: a `design-first` entry with `Owner: techlead`, in a repo whose only team runs the `td` flow, is reported as taken by no lane, naming `Owner`.

**Done when:** Done when the design says the check, where it runs and its words (design §4.4 *An entry no lane takes is marked*; §4.5a *team card: Repo facet*, **Start**; §4.5 screen 11; §4.7 `ao repo`), and its builds land: the home marks a *design* or *live check* entry no lane takes, and a *pickable* one tagged with a team no lane carries, and notes the taker once where the miss is the entry's `Owner:` and no live record holds it claimed (TD-1686); the bar, the Repo page, `ao repo` and Start draw it as *no lane* with its why (TD-1687), with the test of ledgerboard TD-058's case. The filing-time warning the Fix first asked for is replaced by the note to the taker (the home writes no ledger; Paul took that default, m-fed64e2e360a, 2026-11-11).
