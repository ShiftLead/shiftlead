**Why:** TD-1577's design (§4.9b *A model's fitness, before the role*): the Gemini fact-check trial read a model's judgment off live PRs, where a seat that never answers and a model that answers badly look alike, and only after weeks (TD-1214: four verdicts, 0 caught, 9 missed). A fixed set of planted-defect cases, scored mechanically, gives a model's fitness for a role before it takes the role.

**Fix:** Build §4.9b *A model's fitness, before the role* as written:
- `tests/judgment/fact-checker/<case>/`: `change.patch` against the commit `case.toml` pins, and `case.toml` listing each planted defect (id, file, line range in the patched file, one sentence); at least ten cases, at least three clean; each defect checked by hand against the code at the pinned commit, never by a model. A test holds the set's shape (the patch applies to its pinned commit, each range lies inside the patched file, the counts).
- `pdm run judge <role> --profile <p>` (a `pyproject.toml` script): the seat launched as `--smoke` launches it (TD-1648's code, shared), and per case a scratch clone at the pinned commit with the patch applied, committed and pushed to the clone's `origin` (a local bare repository whose default branch is the pinned commit, so the brief's `git fetch origin` and *not on origin* rule read it), the role's own ask sent about that commit as a plain `ask` (never `--pr`), the reply held to its `cadence-review:` first line and findings table (`file:line` each); the mechanical match (file and a line in range; one-to-one, first in reply order); caught, missed, false, `none` at 10 minutes; the bar (misses ≤ 1 in 10 of defects, cases with a false finding ≤ 1 in 5 of answered cases, `none` ≤ 1 in 5 of cases); never in CI.
- `docs/judgment/fact-checker.md`: one row per run (date, profile, `<adapter>/<model>`, caught, missed, false, none, minutes, passed), its first row the Gemini trial's tally to 2026-11-10 marked as the trial's baseline (TD-1214), not a run.

**Done when:** The fact-checker set holds at least ten cases (three clean) and passes its shape test in CI; a `pdm run judge fact-checker --profile gemini-reader` run (or another seat profile the person names) is recorded as a row of `docs/judgment/fact-checker.md` under the baseline row, quoted in the PR.
