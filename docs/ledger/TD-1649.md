**Why:** TD-1577's design (§4.9b *A model's fitness, before the role*): the Gemini fact-check trial read a model's judgment off live PRs, where a seat that never answers and a model that answers badly look alike, and only after weeks (TD-1214: four verdicts, 0 caught, 9 missed). A fixed set of planted-defect cases, scored mechanically, gives a model's fitness for a role before it takes the role.

**Fix:** Build §4.9b *A model's fitness, before the role* as written:
- `tests/judgment/fact-checker/<case>/`: `change.patch` against the commit `case.toml` pins (a commit of `origin/main`), and `case.toml` listing each planted defect (id, file, line range in the patched file, one sentence); at least ten cases and ten planted defects (a miss allowed only where the answered cases hold ten or more), at least three cases clean; each defect checked by hand against the code at the pinned commit, never by a model. A test holds the set's shape (the patch applies to its pinned commit, each range lies inside the patched file, a case's ranges in one file never overlap, the counts), skipping, saying so, where a shallow clone lacks the pinned commit (the precheck's full clone holds it); `.github/workflows/ci.yml`, run only on a fork's PR and by hand, takes `fetch-depth: 0` so it never skips either.
- `pdm run judge <role> --profile <p>` (a `pyproject.toml` script): the seat launched as `--smoke` launches it (TD-1648's code, shared), the role, its seat line and its brief resolved from the checkout the run starts in at its head, never from a case's clone (which holds only the diff); the cases one after another, each with a seat of its own in its case's clone, the ask sent as the person right after the create and the reply read from the scratch home's person inbox, the seat ended at its reply or at 10 minutes; per case a scratch clone at the pinned commit with the patch applied, committed and pushed to the clone's `origin` (a local bare repository whose default branch is the pinned commit, so the brief's `git fetch origin` and *not on origin* rule read it), one fixed ask text, the same each run, `fact-check PR #<the case's ordinal> at <sha>: every claim the diff makes`, as a plain `ask` (never `--pr`); the mechanical match: a reply with no `cadence-review:` first line scores `none` (malformed), else each list item and paragraph after it is a finding, catching a defect when any `path:line` or `path:a-b` it names is the defect's file and in or overlapping its range, one-to-one, first in reply order then `case.toml`'s, a finding naming no location false; caught, missed, false, `none` at 10 minutes; the bar (misses ≤ 1 in 10 of the defects in answered cases, caught and missed counting answered cases only, cases with a false finding ≤ 1 in 5 of answered cases, `none` ≤ 1 in 5 of cases); never in CI; each case's seat killed at its end and the scratch homes and clones removed at the run's, unless `--keep`.
- `docs/judgment/fact-checker.md`: one row per run (date, profile, `<adapter>/<model>`, caught, missed, false, none, minutes, passed), its first row the Gemini trial's tally to 2026-11-10 marked as the trial's baseline (TD-1214), not a run.

**Done when:** The fact-checker set holds at least ten cases (three clean) and passes its shape test in CI; a `pdm run judge fact-checker --profile <p>` run on a seat profile whose reply road meets no prompt (a Claude Code one the person names, or `gemini-reader` once TD-1582 has built TD-1576's road) is recorded as a row of `docs/judgment/fact-checker.md` under the baseline row, quoted in the PR.
