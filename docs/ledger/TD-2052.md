## TD-2052: The merge by the home: the gate run for one pull request, the merge, and what a refusal does

**Priority:** Medium
**Type:** feature
**Added:** 2026-11-22
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** c92cbf24c2c4478092ee0c9a5ec02ef4
**Blocked by:** TD-2050, TD-2051, decision (paul)
**Part of:** TD-1954

**Why:** The design makes merge a place an outcome goes: the home runs the repo's gate and merges, so no session and no model is spent on it, and a refusal sends the entry where the flow says.

**Ask:** Should the builders start on the merge the home makes when an outcome goes to merge?

**Fix:** Build design §4.9c *The merge gate under a flow*: the record marked merging by the call, the tick running the gate's own script for that pull request, the merge and the close; the four endings (passes, a cause a session can cure, a cause only a person can cure, no reading); reconcile finishing a record left merging.

**Done when:** A ship whose head moved is refused and takes the flow's refused move; a row only a person can cure sends the entry to the person with Try the merge again and spends no limit; no reading is retried for an hour, then goes to the person; a crash mid-merge is finished by reconcile and spends no limit. Every row of the gate is sorted as curable by a session or the person's, and the refused row is carried to the next build session in the record's move reason. A push after `ao stage end` only fails the head check.
