**Fix:** The home's stamp, its words and the CLI, in five places:

- `src/sessionorc/models.py`: `MailEntry.unanswered: dict | None` (`{by, state, at, since?, ended?, held?, lapsed?, gate?, cap?, modal?, resets?, kind?, start_at?, waiting?}`), serialised and carried on every copy as other envelope fields are. The send RPC takes no `unanswered` from its caller; only the take-up branch writes it.
- `src/sessionorc/agent_mail.py`, the send path where `taken` is closed as `asked_person` (`follow` runs on `named`, which is `[PERSON]` here): resolve the first of `taken.to` with a side-effect-free walk over `_successor` — never `follow` itself, which writes `forwarded` into the sender's reply. Compute the state, first match wins, in §4.9b's order, *the question's time* being `taken.at`, *live* a state not `exited`, `closed` or `scheduled` (`mail._NOT_LIVE`), and an `exited`/`closed` record's *end* its `ended.at`, else `closed_at`, else `since`; `by` the walk's last address, whether or not a record stands there (`<name>` the record's name, else `by`): `gone` (the walk ends on no record), `suspended` (`suspended.at`; before the ceilings, since a suspended seat keeps its fill mark and Restart refuses it), `fills_exhausted` (`restart_ceiling.why == "fill"`, `held` from the mark), `restart_ceiling` (any other `why`, or none — a crash's ceiling is `{at, count}`; words naming Restart on a non-seat, Resume on any seat's non-fill ceiling (a lost brief's or a failed scheduled start's among them)) — on either ceiling, `gate` with the `resets` when the profile is also gated, its words per §4.9b: a seat's fill ceiling *the fill waits*, a non-seat's *Restart refuses until then*, any seat's non-fill ceiling none — `unreachable` (the predicate `away` applies to each addressee, `host != self.host` and the link down, moved into one helper on a record that both call — `away` filters out the person, so it is empty for this send; before the record's other fields, which are stale while a node's link is down), `scheduled` (`start_at`; before the not-live states it would otherwise match), `gated` (a live record or a seat only; `_profile_over`, the tick's own reading, reachable from the mail mixin, called with the record's `team`; a seat on call's profile is its definition's; `resets` from its row when it has one, else the *until its usage reading resets* form), `limited` (`cap` = `pending.text`, as `mail.read_when` quotes it, `modal` from `limit_is_modal`, read only for a home-host record as the send reads it; no reset is stored), `not_filled` (a seat whose newest record is not live, created before the question's time, its end at or before it), `ended` (any other not-live record: its end later than the question's time, or — a non-seat's — at or before it, with no `since` and the *before the question was sent* words), `needs_you` (`kind` = `pending.kind`; words for permission and question, *on you* for any other kind), else `working` (`stalled?` included) / `idle` with `waiting` = `len([i for i in record.asks_ids(home=…) if i != taken.id])` — never `asks_waiting() - 1`, since the walked record (a refilled seat's newest) may not hold the taken entry. `lapsed` on any state after the ceilings: `fill_lapsed.at` when later than the question's time. Set it on `entry` before the copy loop, so every copy carries it — the person inbox's, the sender's outbox, and any `landed` controller copy — and give `_copy` `unanswered=dict(entry.unanswered) if entry.unanswered else None`, since `dataclasses.replace` would share the dict. A `--thread` that takes nothing up writes none.
- One function owns the fixed words per state (§4.9b's sentences, both `fills_exhausted` forms, both `limited` tails, `<time>` local as the Inbox draws times); `working`/`idle` end with `mail.read_when` called with `lapses=False`, a session sender (`person=False`) and the kwargs the send already computes (`rings`, `cache`, `modal_limit`, `unreachable`). The UI (TD-1431) and the CLI both call it — never two copies.
- `src/shiftlead/review.py` (`walk`): an ask `pr_reads` gives as not `open` with `replied_at` None — closed with no reply landed (`asked_person`, a lapse or an expiry among them) — reads as the `last is None` branch does (`next`, or `later` while an earlier link is unpassed), never `asked`; a reply with no verdict still reads `asked`. Tests, on a team with a `chain` (`ao pr held` calls `walk` only then): after a take-up `ao pr held <n>` names the reader's turn; a verdict-less reply still reads `asked`; a closed `asked_person` ask with a later `pass` reply reads `passed` (`turn` None, the last reader named as the merger); a lapsed or expired ask with `replied_at` None reads `next`.
- `src/shiftlead/cli.py`: `ao inbox` prints the words indented under an entry carrying `unanswered`; the `ao msg` reply to a send that took a question up prints them before its *when it is read* lines (`unanswered` under `--json`).
- Tests, one per state: `gone` (a forgotten addressee); `suspended` (a suspended seat that also holds a fill mark); `fills_exhausted` plain and held; `restart_ceiling` on a non-seat (a crash ceiling with no `why`: the Restart words) and on a seat's why-less `{at, count}` ceiling (a lost brief's or a failed scheduled start's: the Resume words); a fill mark on a gated profile carrying `gate`, and a gate reading with no `resets`; `unreachable` (a limited node record on a down link); `scheduled` (a scheduled seat); `gated` on a live record, and none for a closed non-seat on an over-line profile (it reads `ended`); `limited` modal and capped; `not_filled`; `ended` for a fill live at the ask and ended after it, for a closed record with no `ended` (by its `closed_at`), and for a non-seat ended before the ask; `lapsed` on a seat refilled after a lapse; `needs_you` with `pending.kind` `permission` and `prompt`; `working` for a `stalled?` record; `idle`, a seat holding only the taken question reading `waiting` 0, and a refilled seat whose newest record does not hold it reading 0. Also: a `landed` controller copy carries it (a `--thread` ask `--about` a member the sender controls, with a second controller); the outbox copy carries it; the reply's forwards are unchanged; a `--thread` on a question to the person writes none; a send through the RPC dispatch carrying `unanswered` has it dropped and named in the reply's `ignored` (`_drop_unknown`), the stored entry carrying none.

**Done when:** A `--thread` ask that takes up an open question to a session carries `unanswered` with the state §4.9b *Why it did not answer* names, on every copy — the person's, the sender's outbox and any landed controller's; `ao inbox` and the `ao msg` reply print its fixed words; `ao pr held` reads a closed ask with no reply as the link's turn; the tests above pass.
