## TD-1747: A Claude Code session whose login expired reads as working, so the seat smoke times out and a seat's card never asks for the login

**Type:** debt

**Kind:** build

**Why:** TD-1648's seat smoke on the Claude Code `conformance` profile (2026-11-13 00:35Z, Claude Code 2.1.323) failed `timeout: no reply within 600s; the seat reads working`, while the seat's pane read *Login expired · Please run /login* and *Not logged in · Run /login* from its first turn. The record read `working` for ten minutes against a tool that could do nothing, so the smoke named a timeout rather than the login, and a real seat (or member) whose credentials expire would sit as `working` on its card, never `needs-you` or `limited`, with nothing to tell the person a login is wanted.

**Location:** src/shiftlead/adapters/claude_code/ (state rules); scripts/conformance.py (the smoke's failure step); design §4.2, §4.3

**Fix:** Read the Claude Code adapter's state rules (src/shiftlead/adapters/claude_code/) for what a turn that ends on *Login expired · Please run /login* / *Not logged in · Run /login* reports through its hooks and its screen, and make such a session read as something the person must act on (`needs-you` with the login as its `pending.text`, or the adapter's own signal if one fits better), designed in §4.2 / §4.3 first if the state table has no row for it. Then the seat smoke's failure line names it (`login` rather than `timeout`). A test from a captured pane or hook payload of that screen.
