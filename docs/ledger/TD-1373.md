## TD-1373: The sync PR: every ledger write ShiftLead's code comes to make goes through ledgerboard's ledger.py, dated UTC; board dates in workorders.py stay local

**Priority:** High
**Type:** feature
**Added:** 2026-11-04 (ao-led-tds-ledger, a person-session in ledgerboard, through `ao td add --repo shiftlead`; drafted by ao-shiftlead-techlead-ao-1)
**Owner:** grinder
**Kind:** build
**Status:** Open
**Blocked by:** TD-1372
**Part of:** TD-1369
**Location:** `src/sessionorc/ledger.py` (a reader today); `src/sessionorc/agent_inbox.py` (`rpc_ledger_decide`, which writes the board and never the ledger); `src/sessionorc/workorders.py` (board dates); design §4.4 *A session writes the ledger and the board only through the helpers*

**Why:** ledgerboard's target design (ShiftLead/ledgerboard `docs/plans/target-design.md`) §7.2 step 4 and §1.1: the writers live in ledgerboard, and a consumer does no file handling of its own (principle 5). ShiftLead's code writes no ledger text today; design §4.4 says code that comes to write one calls ledgerboard's ledger writer once v2.4 ships it (TD-1286). The first such writes are the lifts of TD-1372 and the decide lift of TD-1375. ledgerboard's writers date in UTC; the board's dates are the machine's local date and stay so.

**Fix:** audit `src/` and hold it with a test: no ledger text is written by ShiftLead's own file handling, and each ledger write the earlier parts added goes through ledgerboard's `ledger.py` (vendored by TD-1370) with the lookups it needs, dated UTC; `workorders.py`'s board dates stay local, with a test that says so. The PR changes ShiftLead's design (docs/design/) in the same diff wherever the behaviour it changes is written there.

**Done when:** no code in `src/` writes ledger text by its own file handling (a grep and a test), and a lift written from a press (TD-1372) is dated in UTC.

**Related:** TD-1369; ledgerboard's target design (ShiftLead/ledgerboard `docs/plans/target-design.md`) §7.2 step 4.
