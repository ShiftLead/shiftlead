## TD-1726: Each launch reads its tool's version through the adapter's tool_version() and writes it on the record

**Priority:** Medium
**Type:** feature
**Added:** 2026-11-11
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 23b2cff0fadd41f9973714b913ca126d
**Part of:** TD-1650
**Location:** src/sessionorc/adapters.py (OPTIONAL_METHODS), src/shiftlead/adapters/claude_code, src/shiftlead/adapters/gemini, src/sessionorc/agent.py (launch), src/sessionorc/models.py, scripts/seat_run.py, scripts/conformance.py; design §4.3

**Why:** A seat's tool can be upgraded with no entry naming it (TD-1576), and nothing records which version a seat runs on. TD-1650 designs the read: design §4.3 *An upgraded seat tool asks for the smoke* (each launch reads the tool's version through the adapter's optional `tool_version()` and writes it on the record).

**Fix:** 1. An optional adapter method `tool_version(env) -> str | None`, looked up with `getattr` as `setup_note` is (never in `OPTIONAL_METHODS` or `implements`; listed in the comment at `src/sessionorc/adapters.py` ~50–198): run `[self.binary, "--version"]` in `env`, bounded by `VERSION_TIMEOUT` (10 s), answer its output's first line stripped, None on any failure (a binary `env`'s PATH cannot resolve, a non-zero exit, the timeout). Implement it for Claude Code (`src/shiftlead/adapters/claude_code/`) and Gemini CLI (`src/shiftlead/adapters/gemini/`, its lazy `binary`); a later adapter (Grok Build, TD-1637) adds its own.
2. The launch (`src/sessionorc/agent.py` ~1764–1815): after `ad.launch` builds the spec and before the pane is made, call it off the loop (`asyncio.to_thread`) with the environment the launch hands tmux (the host agent's, `spec.env` over it), and write the answer on the record as `tool_version`, a new optional `Session` field in `NODE_OWNED` (`src/sessionorc/models.py`; `test_models` pins each field to one set), so a node's record carries it to the home. None writes nothing; the launch goes on either way.
3. The seat smoke (`scripts/conformance.py` ~433) prints the adapter's read, *version unknown* where it answers None; `scripts/seat_run.py`'s `tool_version(binary)` is removed, its callers on the adapter's method.
4. Tests: each adapter's method against a fake binary on a PATH in `env` (prints a version; hangs past the bound; exits non-zero; absent from PATH); the launch writes the field, a missing method or None writes none; a node's record carries the field to the home (`apply_node`).

**Done when:** Every launch of an adapter that implements `tool_version()` writes the tool's version on the record, bounded and spending nothing, as design §4.3 *An upgraded seat tool asks for the smoke* says, and the seat smoke's last line prints the same read; tests as the Fix lists.
