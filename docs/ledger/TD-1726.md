## TD-1726: Each launch reads its tool's version through the adapter's tool_version() and writes it on the record

**Priority:** Medium
**Type:** feature
**Added:** 2026-11-11
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 23b2cff0fadd41f9973714b913ca126d
**Part of:** TD-1650
**Location:** src/sessionorc/adapters.py (OPTIONAL_METHODS), src/shiftlead/adapters/claude_code, src/shiftlead/adapters/gemini, src/sessionorc/agent.py (launch), src/sessionorc/models.py, scripts/seat_run.py, scripts/conformance.py; design §4.3

**Why:** A seat's tool can be upgraded with no entry naming it (TD-1576), and nothing records which version a seat runs on. TD-1650 designs the read: design §4.3 *An upgraded seat tool asks for the smoke* (each launch reads the tool's version through the adapter's optional `tool_version()` and writes it on the record).

**Fix:** 1. `tool_version()` on the adapter contract (`src/sessionorc/adapters.py`: the method in `OPTIONAL_METHODS`, the comment list at ~50–198 as the design's method list has it): `<self.binary> --version`, its first line stripped, bounded by `VERSION_TIMEOUT` (10 s), None on any failure. Implement it for Claude Code (`src/shiftlead/adapters/claude_code/`) and Gemini CLI (`src/shiftlead/adapters/gemini/`, its lazy `binary`); a later adapter (Grok Build, TD-1637) adds its own.
2. `scripts/seat_run.py`'s `tool_version(binary)` and `scripts/conformance.py`'s call use the adapter's method, so the smoke's last line prints the same read.
3. The launch (`src/sessionorc/agent.py` ~1764, before `ad.launch`) calls it off the loop (`asyncio.to_thread`) for an adapter that implements it and writes `tool_version` on the record (`src/sessionorc/models.py`, a new optional field, saved and pushed as the record's other fields, a node's to the home); a failure or timeout writes none and the launch goes on.
4. Tests: each adapter's method against a fake binary on PATH (prints a version; hangs past the bound; exits non-zero); the launch writes the field and a missing method writes none; the conformance suite checks the optional method as it checks the others.

**Done when:** Every launch of an adapter that implements `tool_version()` writes the tool's version on the record, bounded and spending nothing, as design §4.3 *An upgraded seat tool asks for the smoke* says, and the seat smoke's last line prints the same read; tests as the Fix lists.
