## TD-1726: Each launch reads its tool's version through the adapter's tool_version() and writes it on the record

**Priority:** Medium
**Type:** feature
**Added:** 2026-11-11
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 23b2cff0fadd41f9973714b913ca126d
**Part of:** TD-1650
**Location:** src/sessionorc/adapters.py (the optional-method comment), src/shiftlead/adapters/claude_code, src/shiftlead/adapters/gemini, src/sessionorc/agent.py (launch), src/sessionorc/models.py, scripts/seat_run.py, scripts/conformance.py; design §4.3

**Why:** A seat's tool can be upgraded with no entry naming it (TD-1576), and nothing records which version a seat runs on. TD-1650 designs the read: design §4.3 *An upgraded seat tool asks for the smoke* (each seat's launch reads the tool's version through the adapter's optional `tool_version()` and writes it on the record).

**Fix:** 1. An optional adapter method `tool_version(env) -> str | None`, looked up with `getattr` as `setup_note` is (never in `OPTIONAL_METHODS` or `implements`; listed in the comment at `src/sessionorc/adapters.py` ~50–198): run `[self.binary, "--version"]` in `env`, bounded by `VERSION_TIMEOUT` (10 s, one constant in `src/sessionorc/adapters.py`), answer the first line of its stdout, stripped, only when it holds a digit; None on any failure (a binary `env`'s PATH cannot resolve, a non-zero exit, the timeout, no such line). Implement it for Claude Code (`src/shiftlead/adapters/claude_code/`) and Gemini CLI (`src/shiftlead/adapters/gemini/`, its lazy `binary`); a later adapter (Grok Build, TD-1637) adds its own.
2. The launch (`src/sessionorc/agent.py` ~1764–1815), for a create carrying `seat` only (a seat's extra carries `seat` and reads; an interactive or plain launch, and a worker line's extra, read nothing): after `ad.launch` builds the spec and once, before `_take_name` and the `_start` tries (under the create's locks, capped by the bound), a scheduled or held create reading at its own launch, unless the create's `argv` replaced the spec's (an override reads nothing), call it off the loop (`asyncio.to_thread`) with `{**os.environ, **spec.env}`, and write the answer on the record as `tool_version`, a new optional `Session` field in `NODE_OWNED` (`src/sessionorc/models.py`; `test_models` pins each field to one set; add it to design §4.4a's node-owned list if the design PR has not), so a node's record carries it to the home. None writes nothing; the launch goes on either way.
3. The seat smoke (`scripts/conformance.py` ~433–442) calls the walked adapter's `tool_version` itself, in its own environment as the walk starts (no spec `env` over it), before its first step (its seat is launched with no `seat`, so its record carries none), and prints the answer in its header and on its last line, a pre-launch failure's among them, *version unknown* where it answers None or the adapter has no such method; `scripts/seat_run.py`'s `tool_version(binary)` is removed (its 30 s timeout and stderr fallback with it: the method's 10 s bound and stdout rule replace them), its callers on the adapter's method.
4. Tests: each adapter's method against a fake binary on a PATH in `env` (prints a version; prints a banner line with no digit; hangs past the bound; exits non-zero; absent from PATH); a seat launch writes the field, as do a seat's extra, a pool member, a resumed seat and a scheduled create at its launch; an interactive launch, a worker line's extra and an `argv` override read nothing; the smoke prints *version unknown* for an adapter without the method; a missing method or None writes none; a node's record carries the field to the home (`apply_node`).

**Done when:** Every seat's launch (a create carrying `seat`, no `argv` override) of an adapter that implements `tool_version()` writes the tool's version on the record, bounded and spending nothing, as design §4.3 *An upgraded seat tool asks for the smoke* says, and the seat smoke reads through the same method itself and prints it on its last line; tests as the Fix lists.
