**Why:** Part of TD-2080: every session on a host shares one temporary pool, so one seat's test runs can stop them all (design §4.6).

**Location:** design §4.6 The two temporary pools; src/sessionorc/scratch.py, hosts.py, agent.py

**Fix:** Build design §4.6 *The two temporary pools*: the `bulk_root` host setting (§5) with its start-time refusals, the record's `bulk` field, the twin directory made, kept across a restart and Resume, re-made, touched and swept with its `scratch` twin, and the env (`SHIFTLEAD_SCRATCH` and `TMPDIR` the bulk twin, the adapter's `scratch_env` the `scratch_root` twin). `ao disk` reads both pools (§4.7). Once it is live, write an `act` board line for the person, ending *only you can do this*: mount a dedicated `tmpfs` on kmaster and set `bulk_root`.

**Done when:** With `bulk_root` unset, a run's env and directories are as before. With it set, a test makes the bulk twin refuse writes (this machine allows no unprivileged mount, so no real full file system) and a session still runs a command through its tool's temp directory, and the twin follows its `scratch` through restart, Resume and the sweep. Once the person has mounted the pool on kmaster, `ao disk` reads both pools and a new seat's `TMPDIR` is on the bulk mount.
