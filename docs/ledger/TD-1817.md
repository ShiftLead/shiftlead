## TD-1817: Build TD-1815: a subagent's event ends a no-channel tool's main-thread permissions, and the Grok hook forwards a child's events

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-14
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** da132c0fa1484167926f95938dc8568e
**Part of:** TD-1815

**Why:** TD-1815 designs how a Grok child's permission prompt, which names no thread (captured on 1.0.77: the parent's `sessionId`, no `subagentType`), is read and cleared: design §4.2 *A subagent's event, for a tool with no channel* and §4.3 *A subagent's events* (Grok Build's). Until this is built, `adapters/grok/hook.py` drops every child payload, so a child's prompt reads as the main session's and nothing but the main thread's next event clears it: a foreground spawn reads `needs-you` through the child's whole run.

**Location:** src/sessionorc/ (the pendings stack's main-thread permission end); src/shiftlead/adapters/grok/hook.py; tests/conformance/ (the Grok subagent sequence); tests/test_grok_hook.py

**Fix:** As design §4.2 *A subagent's event, for a tool with no channel* and §4.3 *A subagent's events* (Grok Build's) say:

1. **Core** (`src/sessionorc/`, where a main-thread event removes a no-channel tool's main-thread permissions): for an adapter with no permission channel, an event carrying `subagent` (a subagent's tool event, a `SubagentStart` or `SubagentStop` carrying `subagent`) that opens no prompt and is not `stale` (the apply's own predicate, which already gates the existing ends) also removes every main-thread permission entry, with `sure=False`, and nothing else: no question, no subagent's own entry, and nothing written into `kept`, so a stack it empties goes back to `kept`. An adapter with a permission channel is unchanged: a subagent's event ends none of its main-thread entries. In `agent_tick.py`'s apply, it is a branch of its own after the existing ends, run for a `SubagentStart` too: the existing end is guarded by `not starting`, and a `SubagentStart` must still stay out of `_end_waiters`.
2. **The Grok hook** (`src/shiftlead/adapters/grok/hook.py`): forward a child's `PostToolUse`, `PostToolUseFailure`, `PermissionDenied`, a `StopCancelled` with `reason` `permission_rejected` or `permission_cancelled` (any other child `StopCancelled` dropped), `SubagentStart` and `SubagentStop` (with `subagent_delta` +1 and −1), each with `subagent` (the child's id: `subagentId` on `SubagentStart`, which fires on the parent's `sessionId`; `sessionId` on the rest), `subagent_seen`, and no `adapter_id`, `state`, `pending`, `turn`, `turn_end`, `transcript` (a child's payload names its own `updates.jsonl`) or `call` (a tool event keeps its `event` and `tool_use_id` where the payload has them; a start, a stop and a `StopCancelled` carry no `event`) (a child's `PostToolUse` after the main `Stop` must not set `working`, nor its `StopCancelled` `idle`); drop every other child payload; a `Notification` is never a child's, whatever it carries (its `idle_prompt` stays the main session's; one carrying `subagentType` is sent with no `adapter_id` and no `transcript`); a `SubagentStart` with no string `subagentId` is sent with its `subagent_delta` and no `subagent`; send a `Notification` `permission_prompt` as the main session's permission, as today; send a `PostToolUse` of `kill_command_or_subagent` with a string `toolInput.task_id`, on either thread, with `subagent_stopped: <task_id>`, a command's id too (core moves no count for an id it does not list), with no `subagent_seen` on a main-thread kill. Rewrite the module docstring's line that says child payloads are dropped.
3. **Tests**: the offline conformance suite runs `fixtures/grok/captured/hooks-subagents.jsonl` as a sequence (§4.3 *The conformance suite*'s sequence form) and asserts the record after each step: the spawn's prompt `needs-you`, ended by `SubagentStart`; the child's prompt `needs-you`, ended by the child's `PostToolUse` back to `working`; the count back to 0 after `SubagentStop`; the killed background child's count ended by the kill; the record's `adapter_id` and `transcript` stay the parent's at every step. The capture holds no background child's prompt and no two-child case, and §4.3 forbids a hand-written fixture, so those are core unit tests: a child's event ending a main-thread permission restores `kept` (`idle` when the main thread had stopped); two open main-thread permissions both ended by one child's event; a main-thread question left standing by a child's event; a child's event ending nothing for an adapter with a permission channel; a `SubagentStart` ending a main-thread permission of an adapter with no permission channel, staying out of `_end_waiters`, and ending nothing for one with a channel. `tests/test_grok_hook.py`'s TD-1815 test is rewritten to assert the forwarded shape, with a hook test that a child's `PostToolUse` and `StopCancelled` carry no `state`, a child's `PostToolUse` and `SubagentStop` no `adapter_id` or `transcript`, a child's `SubagentStart` (on the parent's `sessionId`) a `subagent` equal to its `subagentId`, and a child's `StopCancelled` of another reason dropped, and a core test that a child's event after the main `Stop` leaves the record `idle`. An `idle_prompt` ending a background child's open prompt is the accepted cost §4.3 names; no test asserts otherwise.
4. A line under `## §4.3` in `docs/history/TD-<this entry>.md` saying it is built.

**Done when:** The Grok hook forwards a child's prompt-ending tool events and its start and stop, and core ends a no-channel tool's main-thread permissions on a subagent's event as §4.2 *A subagent's event, for a tool with no channel* says; the captured subagent sequence passes the conformance suite with the record asserted at each step, and the core cases above are tested.
