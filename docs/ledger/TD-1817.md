## TD-1817: Build TD-1815: an unplaced prompt in core, and the Grok hook forwards a child's events

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-14
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** da132c0fa1484167926f95938dc8568e
**Part of:** TD-1815

**Why:** TD-1815 designs how a Grok child's permission prompt, which names no thread (captured on 1.0.77: the parent's `sessionId`, no `subagentType`), is read and cleared: design §4.2 *An unplaced prompt* and §4.3 *A subagent's events* (Grok Build's). Until this is built, `adapters/grok/hook.py` drops every child payload, so a child's prompt reads as the main session's and nothing but the main thread's next event clears it: a foreground spawn reads `needs-you` through the child's whole run.

**Location:** src/sessionorc/ (the pendings stack, Pending.unplaced, SubagentStart's end); src/shiftlead/adapters/grok/hook.py; tests/conformance/ (the Grok subagent sequence); tests/test_grok_hook.py

**Fix:** As design §4.2 *An unplaced prompt* and §4.3 *A subagent's events* (Grok Build's) say:

1. **Core** (`src/sessionorc/`): a neutral event field `unplaced: true` on a hook-road permission. With the record's `subagents` at 0 it is a main-thread permission as today; above 0 it is pushed on the `pendings` stack as an entry with `Pending.unplaced` set and no `subagent`. An unplaced entry ends on whatever ends a main-thread permission of a tool with no permission channel (a main-thread event with no pending, through the same path that removes those permissions), and on any subagent's tool event whatever its `subagent`; a `subagents_reset` and the session's end drop it. A subagent's tool event still ends no other main-thread entry. For a tool with no permission channel, a `SubagentStart` (`subagent_delta` +1) ends the main-thread permissions, not its questions or its unplaced entries. `Pending.unplaced` round-trips through the record (absent when false, as the subagent fields are).
2. **The Grok hook** (`src/shiftlead/adapters/grok/hook.py`): forward a child's `PostToolUse`, `PostToolUseFailure`, `PermissionDenied`, a permission's `StopCancelled`, `SubagentStart` and `SubagentStop`, each with `subagent` (the child's `sessionId`), `subagent_seen` and no `adapter_id`; drop every other child payload; send every `Notification` `permission_prompt` with `unplaced: true`; read a `PostToolUse` of `kill_command_or_subagent` naming a subagent, on either thread, as `subagent_stopped: <its task_id>`. Rewrite the module docstring's line that says child payloads are dropped.
3. **Tests**: the offline conformance suite runs `fixtures/grok/captured/hooks-subagents.jsonl` as a sequence (§4.3 *The conformance suite*'s sequence form) and asserts the record after each step: the spawn's prompt `needs-you`, ended by `SubagentStart`; the child's prompt an unplaced entry, ended by the child's `PostToolUse` back to `working`; the count back to 0 after `SubagentStop`; the killed background child's count ended by the kill. Core unit tests: an unplaced prompt with `subagents` 0 is a plain main-thread permission; one with a child counted, ended by a child's event, restores `kept` (`idle` when the main thread had stopped); ended by a main-thread event; not ended by a `SubagentStart`; a main-thread permission ended by `SubagentStart` only for a tool with no permission channel. `tests/test_grok_hook.py`'s TD-1815 test is rewritten to assert the forwarded shape.
4. A line under `## §4.3` in `docs/history/TD-<this entry>.md` saying it is built.

**Done when:** The Grok hook forwards a child's prompt-ending tool events and its start and stop, marks every `permission_prompt` `unplaced`, and core reads an unplaced prompt as §4.2 *An unplaced prompt* says; the captured subagent sequence passes the conformance suite with the record asserted at each step, and the core cases above are tested.
