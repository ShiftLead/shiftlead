## TD-2219: After the rename to builder, a person's old grinder brief addition is said to be unread rather than silently dropped

**Priority:** Low
**Type:** feature
**Added:** 2026-11-25
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 70c220f00fe54484a87b3ae3258ef958
**Blocked by:** TD-2056
**Part of:** TD-2215

**Why:** TD-2215 (design 4.9c *The person's own rules under a flow*): once the removal build (TD-2056) renames `grinder` to `builder`, every session in the builder role reads the person's layer file `shiftlead/briefs/builder.md`, so a layer still holding `grinder.md` would add nothing and say nothing. The design keeps no fallback to the old name; the session's *Your own rules* says the file was not read.

**Location:** src/shiftlead/layers.py, src/sessionorc/brief.py

**Fix:** Design 4.9c *The person's own rules under a flow*, and §4.8's carve-out from *no retired-words table*. In `shiftlead/layers.py`, a map of retired role names, `RETIRED = {"builder": "grinder"}`, read only here and never to resolve a role. Where `brief_parts(role, …)` finds, in a layer (one's own or followed), no `shiftlead/briefs/<role>.md` but the retired name's file, that layer's part is the old file's part (`path`, `ref`, `root`, `head` as now, so the layer's head line stays) with one key more, `say`: the line *shiftlead/briefs/grinder.md is read by nothing: grinder is now builder, and it applies once renamed builder.md*. In `sessionorc.brief.layered`, a part carrying a string `say` puts that text under its head in place of the file's, the file still read for its sha so it stays among the sources (renaming or removing it then marks the brief changed, §6 rule 7; a `builder.md` written beside it is no source and applies at the next start); a blank retired file gives no line, `layered` dropping it before `say` is read; `sessionorc` never imports `layers`. A layer holding both files reads `builder.md` alone and says nothing of the old one; each layer is judged apart, so a followed layer's `builder.md` reads beside the own layer's line. Every reader of `layers.person` gets it with no change of its own (a member's start, `ao new`, the New session form, and a stage's, an audit's and a job's session). This lands in TD-2056's pull request or after it, never before, since before the rename `grinder.md` is the file read.

**Done when:** Tests with a temp own layer holding only `shiftlead/briefs/grinder.md`: a `builder` brief's *Your own rules* is that layer's head line and the one line, with the file in `sources`; with `builder.md` beside it, `builder.md`'s text alone; with neither, *none*. Two layers, a followed one holding `builder.md` and the own one only `grinder.md`: the followed text and the own layer's line, each under its head, in the listing's order. A blank `grinder.md` gives no line. Removing `grinder.md` after the start marks the recorded brief changed. A replay (`brief_mod.fill` of the recorded parts) gives the same text and sources. The same through a stage session's launch (`stage_start.launch`).
