## TD-1303: A look's screenshots are drawn from the pushed commit they were sent at, not only from origin's default branch, so a design round's mockups show in the card

**Priority:** medium
**Type:** debt
**Added:** 2026-11-02 (Paul, in the TD-1293 session; drafted by ao-shiftlead-td-1293)
**Owner:** designer
**Kind:** design-first
**Status:** Designed 2026-11-02 (the designer) — §4.10 *A look* (*A look's shots are the pushed commit's*), §4.7 `--shot`, §4.4a `host_shot`, §4.5a row *Inbox row: a look*. Build TD-1307.
**Location:** `src/sessionorc/shots.py` (`_spec`, `read`, `exists`: `origin/<default>:docs/mockups/reviews/<name>` only); `src/shiftlead/ui/inbox.py` (`look_shots`, `_shot_on_origin`, `_shot_on_host`, ~1300–1370); `src/shiftlead/ui/app.py` (the `/repo/<name>/shot/<name>` route, ~1785–1802); `src/shiftlead/cli.py` (`_shot_path`, `--shot`); `src/sessionorc/mail.py` (the envelope's `shots`); `src/shiftlead/ui/templates/inbox_row.html` (`shots`, the *gone* chip); `docs/design/4.10-messages.md` (*A look*, ~1182); `docs/design/4.5a-controls.md` (row **Inbox row: a look**); `docs/design/4.7-cli.md` (`--shot`); `docs/design/4.4a-home-and-nodes.md` (`host_shot`, TD-300)

**Why:** Paul (2026-11-02), on m-bd4361450211, TD-1293's A-or-B ask: its four screenshots were drawn as bare file names he could not open. The mockups were on `design/td-1293-queue-top`, pushed and unmerged, and a look is served only from what `origin/<default>` holds (`shots.py`'s docstring: "what a look shows is what was merged"; §4.10 *A look* calls a look "a builder's question about a merged change"), so the A, B and now shots read as *not on origin's default branch* (only the *before* shot was on main). That rule was written for a builder's look at a merged change; designers now send looks during a design round, before anything merges, and that is when the person most needs to see the image. Pointing agents at full paths does not help: the message renderer links only absolute `http(s)` URLs (`src/shiftlead/ui/render.py`, `_link`), and a long path in a terminal wraps and is not linked either. Paul chose this over a VS Code link to the sender's worktree (which dies when the worktree is removed) and over GitHub blob links in the text.

**Fix:** design first, then the build. `ao msg --shot` records the commit the shots were sent at — the sender's `HEAD` — in the envelope beside `shots` (one `shots_at` sha per message), and refuses the send, in words that say to commit or push, when `<sha>:docs/mockups/reviews/<name>` does not exist (an uncommitted or untracked mockup) or when no remote-tracking ref of `origin` contains that commit (read locally, as the sender last fetched). The reader serves `<sha>:docs/mockups/reviews/<name>` when origin still holds the commit (it is reachable from some `refs/remotes/origin/*` of the reading checkout — one that has not fetched the commit, or still holds a deleted branch's ref, simply falls back), falling back to `origin/<default>` as today — so a look sent before the change, or one whose branch was deleted after a squash merge, draws as now. The path, name and size rules, the four-shot cap and *never the working tree* stay; only "merged" becomes "pushed". `host_shot` (TD-300) and the link's `shot` method take the sha for a sender on another host (`reading(repo, name, head)` has none today), and the presence cache `_shot_seen` keys on it too, so one look's answer never stands for another's same-named file. The design PR rewrites §4.10 *A look*, §4.5a **Inbox row: a look**, §4.7 `--shot` and §4.4a's `host_shot` paragraph ("merged images only"); the dated fact goes to the history.

**Done when** a look sent from an unmerged, pushed branch draws its images in the Inbox row and the Queue card, a look sent before the change and one whose branch is gone draw as today, an unpushed or uncommitted send is refused with the commit-or-push line, and the design's four sections say so.
