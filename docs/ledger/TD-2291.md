## TD-2291: Resuming a session with changes can fill in a login other than the one last used for its tool

**Priority:** Low
**Type:** debt
**Added:** 2026-11-26
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 4877dccdd619471493a29538822657ec

**Why:** Audit of #4777 (TD-2068 slice 16). Design §4.9e *A session the person starts* says a "Resume with changes… lands on the login its record's profile names, else the newest of its tool's", where "the newest" is `last_login`'s, which holds one line per tool: the login the person last started on that tool.

`login_prefill` (`src/shiftlead/ui/app.py`) takes the first option of the record's tool from `login_options`, which moves only the newest line of all of `last_login` to the front and keeps the rest in the `tools` read's order. So for any tool but the one used most recently, the form fills in the first login the read lists, whatever `last_login` says of that tool.

Probe at b739cde95: the `tools` read holding `claude-code:work`, `gemini:old`, `gemini:recent` in that order; `last_login` answering `{"claude-code": "claude-code:work", "gemini": "gemini:recent"}`; `login_prefill(login_options(read, last), "", "gone", "gemini")` answers `gemini:old`.

`tests/test_new_form_login.py` `test_a_filled_in_form_picks_the_login_asked_for_else_the_records_profile_else_the_last_used` asks the fallback only for a tool whose last used login is also that tool's first in the options, and for a tool with no login, so it passes either way.

It shows only where the record's profile names no login of the home's and the record's tool has two or more logins.

**Location:** src/shiftlead/ui/app.py login_prefill, login_options; tests/test_new_form_login.py; docs/design/4.9e-switch-over.md A session the person starts

**Fix:** Have the fallback take `last_login`'s line for the record's tool, and the first login of that tool only where it holds none. Where first-listed is meant instead, that is a change to §4.9e first.

**Done when:** A test with two logins of a tool that is not the one last used, the second of them on `last_login`'s line for that tool, reads the second from a Resume whose profile names no login.
