## TD-2154: A home settings file nested too deeply crashes its reader instead of reporting a problem

**Priority:** Low
**Type:** debt
**Added:** 2026-11-24
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 456f5b0be3904389bce8276da0658297

**Why:** The independent review of TD-2150's PR found that the home's own YAML files are still read by a bare `yaml.safe_load`, so one nested past the parser's depth raises RecursionError where its reader catches only `yaml.YAMLError`: `agent_doctor._parse_error` (settings.yml, hosts.yml), `hosts.py` (three reads of hosts.yml), `settings.py` (two reads of settings.yml), `logins.py` (logins.yml, which would crash instead of raising LoginError), `containers.py` (profiles.yml and the config edit's two reads) and `defs.py` (`_parses`, whose caller does not catch it). Only the person writes these files, so it is less likely than a repo's file, but a crash in `ao doctor` or the host agent's settings read is worse than a reported problem. In shiftlead, `org.py`, `profiles.py` and `ui/settings_page.py` read the same way.

**Location:** src/sessionorc/agent_doctor.py, hosts.py, settings.py, logins.py, containers.py, defs.py; src/shiftlead/org.py, profiles.py

**Fix:** Read each of those through `sessionorc.yamltext.load` (TD-2150), or `shiftlead.repoconfig.parse_yaml` in shiftlead, so a file nested too deeply is the same bad file its reader already reports, and check each caller's except clause still covers it.

**Done when:** No `yaml.safe_load` of a home file remains in src/ outside those two readers, and a test shows `ao doctor` and the settings read report a settings.yml nested past the parser's depth as invalid rather than raising RecursionError.
