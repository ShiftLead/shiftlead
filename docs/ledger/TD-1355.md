## TD-1355: An entry held on decision (paul) draws its own gate card, not the open board item that asks the same question, so the person's answer lands as a new item

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-04 (ao-led-tds-ledger, a person-session in ledgerboard, through `ao td add --repo shiftlead`; drafted by ao-shiftlead-techlead-ao-1)
**Owner:** grinder
**Kind:** build
**Status:** Open — found live 2026-11-04 on ledgerboard#TD-023; the cause is not yet found. The design already says what to draw, so this is a build, not a design.
**Location:** where a board line attaches to an entry and replaces its row: `src/shiftlead/ui/queue.py` (`item_home`, `CONTEXT`, the card index it looks refs up in), `sessionorc.queue.refs`, `src/shiftlead/ui/inbox.py` (`ledger_for_you`, whose *linked* set leaves out only an entry an open **decided** line names), the Queue card's and Repo page's For you rows (`src/shiftlead/ui/templates/inbox_row.html`, the *ledger · your decision* row with **Lift the hold** and **Answer…**); design §4.5 screen 12 *Three verbs* (*A board line that names the entry is the question itself and is drawn instead of the entry's own block*), §4.5 Repo page *For you* (*A board line whose `Context:` names the entry is drawn in the row's place*), §4.5a *Inbox row: ledger entry*, §4.4 *Board write-back*.

**Why:** an entry gated on `decision (paul)` whose Blocked by points at a board item is answered by deciding that item; a second question drawn beside it makes the person answer the wrong one. On 2026-11-04 ledgerboard#TD-023's Blocked by read *decision (Paul) — say Go, One more round or Hold on the board's TD-023 item*, and ledgerboard's board held that item open (session `lb-designer`, `Context: TD-023 / PR #74`, `Answers: One more round (default) | Go | Hold: <note>`). The UI drew only the entry's gate card, with **Lift the hold** and **Answer…**. Paul typed *one more round* into **Answer…**; ShiftLead appended a new, already-decided person item (ledgerboard PR #116, merged), and a session then needed PR #117 to note it on TD-023 and close that item, while the designer's own item stayed undecided until it was decided by hand later that day. The design says the board item is drawn in the entry's place, so its answers — and its default — are the ones pressed and its own line is decided through the board write-back; the code did not do that here. Seen once, on a `Context:` of `TD-023 / PR #74` in another repo's board, so the ref parse (a ref followed by ` / PR #n`), the repo the bare `TD-n` is looked up in, and *linked* counting decided lines only are each a candidate.

**Fix:** reproduce on a scratch home with a second repo whose entry is `Blocked by: decision (paul) — …` and whose board holds an open `decide` item with `Context: TD-n / PR #n` and `Answers:`; find which step loses the link, and make it as §4.5 screen 12 *Three verbs* and the Repo page's *For you* say: the board item is drawn in the entry row's place on the Queue card, the Repo page and the Inbox's *Later*, with its answers, its default and **Answer…**, and pressing one decides that board line (§4.4 *Board write-back*'s decide road), never appending a new item. When ledgerboard v2.4 is vendored (TD-1286's ledger half), its `board.py decide` lifts the gate on Go in the same write (ledgerboard#TD-034, `decide_lift`): the vendor PR takes that road for this press too; until then the decide road stands as it is. Done: a test that an entry with an open undecided board item naming it draws that item, not **Lift the hold**/**Answer…** on the entry, and that an answer decides the item; and a live read on the next such hold.
**Related:** TD-1286 (the v2.4 vendor that brings `decide_lift`), TD-1316 (an answered question's hold), TD-909/TD-914 (the three verbs), ledgerboard#TD-023, ledgerboard#TD-034, ledgerboard#116, ledgerboard#117.
