## TD-1608: A question-seat test sets a seat limited without parking the tick, so a tick can make it able and fail the precheck

**Priority:** Low
**Type:** debt
**Added:** 2026-11-11
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** d0a00dca1813467aa030a5bd4df80951
**Location:** tests/test_question_seat.py (test_a_sessions_ledger_request_lands_on_the_unable_techlead_seat_not_the_fact_check_seat)

**Why:** The precheck of #3339 (a tests-only PR) went red on `tests/test_question_seat.py::test_a_sessions_ledger_request_lands_on_the_unable_techlead_seat_not_the_fact_check_seat` (1 failed, 5682 passed). The file passes alone three times in a row. The failure was `ao-asker cannot ask ao-tl again: its question m-… is still open`: the general `msg` went to `tl`, the seat the test made `limited`, rather than to the able `fc`.

The test sets `agent.sessions[tl].state = "limited"` by hand and never calls `park_ticks(agent)`, unlike its neighbours (lines 348 and 481). A tick that lands between the two calls re-reads `tl`'s real pane and replaces the state, so `tl` reads able and takes the second ask. The first ask is still open, so it is refused.

Found by: grinder-ao-2, on #3339's precheck (2026-11-11).

**Fix:** Call `await park_ticks(agent)` at the top of the test, before it sets the states by hand, as the file's other tests that set a state do. Then run the file in a loop under the full suite's ordering to check that it holds.

**Done when:** The test parks the tick before it sets the states by hand, and a precheck no longer fails on it.
