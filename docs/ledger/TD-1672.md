**Ask:** Will you let TD-1569's design (a person's Start goes ahead while a seat is busy, leaving the seat running, and a refused start names each session's reason and its own fix), reviewed to the cap of four rounds with one closing fix no review has read (F83, TD-1672's help text), go to its build TD-1672, or buy one more round, or hold it with a note?

**Fix:** Build §4.9a *A busy seat is left alone* and *A refused start says why* as written (with §4.9's name rule and §4.5a's Start row):
- **The reading**: one pure function, `(team, crew rows, waiting, skip=None) -> {busy, orphans, closes, why}` (a given `skip` replaces the computed busy for `finished`, `closes` and `why`). `rows`, `start` and `_close_concluded` all call it, and only where the crew has a live record; a start of a team with none is unchanged. `orphans` are each live, unsuspended record with `seat` set, no sweep mark and no mark `_pairing` passes over (sat out, `scale`, `run_only`, `superseded_by`), whose name is absent from `seat_names(team, crew)`; they only take away `startable`. The start's first reading needs only `busy` and takes no waiting reading; `_close_concluded` reads waiting strictly (`waiting_of_home(strict=True)`), a failure propagating as today.
  - **Busy** is over `crew()`, for every record `finished` treats as a seat (`seat` set, or the name is in `seat_names`). The on-call manager and filled extra seats count. A standing manager never does, nor a sweep seat (`sweep-<team>`), which refuses as today. A seat is busy when it is live, not suspended, named exactly a seat name or carrying `scale` with a seat name once its suffix is stripped (a suffixed record without `scale` refuses as today), and is not `idle` with nothing running and clean and pushed (`_unsafe_to_close`).
  - **`finished`** (`src/sessionorc/work.py`) gains `skip`. A skipped record is left out of the live set before it is read: no clause, not in `names`, still counted in `held_asks` and `manager_of`. A crew whose only live records are skipped reads None.
  - **`closes`** are the names when the crew reads concluded with busy skipped. **`why`** is that call's.
- **The start** (`src/shiftlead/teamrun.py` `start`), a person's only (`caller` None), keeps its order:
  - The `list` it reads for `_start_moves` moves before the name check, and the reading is taken from it.
  - Each busy seat that is a launch is dropped from `held`, from the verdicts `keep_mail_for` reads (its signature unchanged), and from the creates. A busy seat with no launch only goes into `skip`. The plan stays whole.
  - `_close_concluded` gets the skip ids alone and keeps its own fresh `list` read, calling the reading itself with `skip` given, so the first read's busy governs. The post-close re-read stays.
  - A busy on-call manager's record id is `lead_id`.
  - The result gains `left_running: [{name, state}]`, printed by `cli.prose`, carried under `--json` and in the toast.
  - The early refusal is the plan's: from the first list, the records `_start_moves` reads as renamed or removed that are live and not `idle` with nothing running and clean and pushed refuse before anything is closed, in its own *still running … by Apply* words. An idle, clean one is closed as today.
  - The card can offer a Start this refusal then refuses (a suffixed seat record without `scale`, a live renamed member): accepted.
  - `_mark_team_start` (`src/sessionorc/agent_tick.py`) passes over live records with `seat` set when it asks whether the team was already running, for all three callers (a person's start, a schedule's, rule 8's replay), so such a start writes `usage_at_start`.
  - A create that loses to rule 8's member replay is a `PartialStart`, as today.
- **State words**: in `busy`, `leaves` and `left_running`, `state` is the record's, or where it is `idle` the reading's words (*idle, shell live*, *idle, subagent live*, *idle, unpushed work*).
- **The rollup** (`src/shiftlead/ui/org.py` `acts`): the team's ⋯ where `startable` reads `[entry, new-team, start, wind-down, stop-now]` on a live group and `[start, entry, new-team, wind-down, stop-now]` on a stopped one, Start with the card's confirm (design §4.5a *rollup: press and menus*).
- **Rows** (`teamrun.rows`): add `busy: [{name, state}]` and `startable: {closes, leaves}` or None. `startable` is None where the reading has an orphan, where no waiting reading was given (a failed one, passed as `{}`, reads as nobody waiting: the strict press may then refuse, accepted). `live` and `concluded` stay unchanged.
- **The card** (`src/shiftlead/ui/repo.py`, `group_head.html`). Where `startable` is set, it governs the controls:
  - `repo.py` copies `startable` into the group (and the rollup's) only where the row's `live` equals the card's own count, as it guards `concluded`. `group_head.html` builds Start's `data-confirm`, `data-closes` and a new `data-leaves` from it, never from `concluded.names`. `data-confirm` is set wherever `leaves` is non-empty: *Start ao-grind? It first closes …; it leaves techlead-ao-1 running (working)*, or, with nothing to close, *Start ao-grind? It leaves techlead-ao-1 running (working)*.
  - In `src/shiftlead/ui/static/app.js`, the *nothing to pick* dialog adds the leave clause, and the start toast reads `o.left_running` itself (*left running: techlead-ao-1 (working)*).
  - Start, Wind down and Stop now are all drawn whatever `g.stopped` reads (the template's two branches joined there), `data-moved` as today.
  - The *not concluded* line is hidden.

  Everything else reads `live` and `concluded` as today.
- **Help text** (`src/shiftlead/ui/help.py`, bound to design §4.5a's help list; run its doc-bound tests, `grep -ln 4.5a tests`):
  - `start` gains a sentence: *A seat still busy — answering, running a command, or holding work it has not pushed — is left running, and the start says so.* Its last clause keeps *a session holding uncommitted or unpushed work refuses the start*, which is now true of the sessions Start closes.
  - `not-concluded` reads *Says why this team cannot be started yet* and is not drawn where Start is offered.
- **Rule 8 is unchanged.** A test holds that a live seat keeps the team from reading wound down.
- **The refusal** (`NamesHeld`). Each holder dict gains `clause` and `cure`, which `_close_concluded` builds from its own `list` read and the reading before it raises. `NamesHeld` only formats them. They are carried in `--json`'s `holders` and printed per holder by its text, which the toast shows. The one global cure line goes, as design §4.9 now says.
  - **`clause`**:
    - the reading's `why` clause beginning with the name of the holder's record (read from the same `list` by the verdict's `holder` id, since a suffixed holder's record name differs from the launch's) and a space;
    - *finished*, then the team's clauses, for an idle declared member or an idle seat with no clause of its own;
    - *your session …* for a person's session; *<name> sat out by its flow, still <state>* for a live sat-out record;
    - today's words for a suspended holder;
    - else the bare state (no failed-waiting case: that failure propagates).
  - **`cure`**:
    - Close (`ao close <id>`, or Close on the card) for a holder whose clause is *idle, not declared*, or that is finished, and that is clean and pushed;
    - what `_unsafe_to_close` says of it (*3 uncommitted*, *2 unpushed*, git state not known yet), to be settled before its Close, for a holder whose clause is *idle, not declared*, or that is finished, that is not clean and pushed;
    - what it waits on, for a waiting holder;
    - for a person's session, to close it yourself; for a suspended holder, today's words; for a sat-out record, let it wrap up, or Close it once idle (none of these offered Kill);
    - else let it finish, or Kill that one session (`ao kill <id>`), never a team stop.
