## TD-2002: The start's tools read holds every host agent's stop and loads the test suite

**Priority:** High
**Type:** Debt
**Added:** 2026-11-19
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 02bfb02c58a04a15901b23fcfc7fb6cd

**Why:** Since #4173 (TD-1973) every host agent reads this host's tools at start — each supported tool's real `--version`, a node process for Gemini — on the loop's default executor, which `asyncio.run` joins at its end. Two things followed. A stop waited for the read's remaining `--version` runs (up to `VERSION_TIMEOUT`, 10 s, each), so the suite's child agents failed teardown with *child agent ignored SIGTERM*; and the suite starts hundreds of host agents, each running `gemini`, `claude` and `grok --version` at once (30 `gemini --version` seen at once, load 42 on 16 cores), so prechecks went from about 280 s to 1000–1300 s and timing tests failed. Main's own precheck has been red from c5445547d (#4173) on, and every PR's precheck since, #4177 among them.

**Location:** src/sessionorc/agent.py, src/sessionorc/tools.py, tests/conftest.py

**Fix:** The read runs in a daemon thread of its own (`agent._in_daemon_thread`), awaited as the executor was, which holds no stop; `tools.READ_AT_START`, a test knob, lets conftest (and `_agent_child.py`, by `AO_TEST_TOOLS_AT_START`) turn the start's read off; §4.2b says both.

**Done when:** A child agent whose start read is stuck in a slow `--version` exits 0 within 5 s of SIGTERM (`test_a_stop_is_never_held_by_the_start_read`), the suite's host agents make no start read, and the precheck passes.
