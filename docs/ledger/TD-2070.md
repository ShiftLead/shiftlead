**Why:** A team may run on a node, whose logins the home does not read. The node has to pick the login itself and tell the home when no login it has offers the model, and a container node needs a logins file made for it (design 4.9e, A team on a node; design 4.9d, A team on a node; design 4.2b, On a node).

**Ask:** Should the builders build the launch on a login for a team on a node?

**Fix:** Build the node's side of design 4.9e The launch on a login. The home sends a launch with the list as names and the model; the node's host agent calls the same pick on its own logins and answers with the login it took, none usable, or no login offers the model. On the last the home starts nothing, or ends the holder it had named, clears it, spends no offer, and marks the team cannot run naming the model until its list or flow changes; for a built-in seat the set is marked so for that seat. The move down the list runs on the node's tick as on the home's, from the list on the record. The spend a node sends names the login beside the account. ao host up adds to a container node's logins.yml each login a list names that the node lacks, as design 4.2b On a node says, and touches none it has; it adds none whose bare name another tool's login on the node has, live or forgotten, by TD-2279's helper `logins.name_holder` over the node's file as the home reads it, and says so in its result, a line naming both, with design 4.9e A container node's logins.yml's words (TD-2232); the window's move, not this build, writes the file from the node's profiles. In the greeting of the link a node reports switched and the home says whether it is cut over; a switched node whose home is not cut over refuses a launch with the design's words. Rewrite design 4.4a's provisioning passage for logins in the same pull request.

**Done when:** On a fixture home and container node, both switched: a stage's session for a node's team starts on the node's first usable login offering the model and its record at the home holds that login; a node none of whose logins offers the model answers so, the home starts nothing, or ends the holder it had named with no offer spent, and the team's page says cannot run with the model named; the same for a tech lead of a set; a session on the node whose login is limited moves to the next on the node's tick; the node's spend names the login; the node's greeting reports switched; ao host up adds a listed login the node lacks and keeps the ones it has; ao host up adds no listed login whose name another tool's login on the node has, and names both.
