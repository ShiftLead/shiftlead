## TD-1284: A Queue card's entry the person's own session holds reads *with you in <name>* and is no want

**Priority:** Medium
**Type:** debt
**Added:** 2026-10-30 (the designer, from TD-1281)
**Owner:** grinder
**Kind:** build
**Status:** Open
**Part of:** TD-1281
**Location:** `src/sessionorc/queue.py` (`_state`, `row`, `_status`); `src/shiftlead/ui/queue.py` (`want_of`, `attach`, `card_wants`, `_card_kinds`, `branch`, `_seg`, `queue_view`'s `items_start` and `n`); `src/shiftlead/ui/app.py` (`card_mail`, which builds `attach`'s callables); `src/shiftlead/ui/templates/queue_card.html` (the header's items, and the top entry's state at its line 46), `queue_row.html` (`state`, the `needsyou` class, the holder pill), `inbox_row.html` (the `ledger` macro's `qneed` span and card-mode foot); `tests/test_queue.py`, `tests/test_queue_wants.py`, `tests/test_queue_start.py`, `tests/test_queue_card_spine.py`, `tests/test_queue_card_verbs.py`; design §4.4 *A row's state*, *The card's status*; §4.5 screen 12 *Three wants*, *Three verbs: Start session*; §4.5a *Queue card: what needs the person*, *Queue card: Start session / Open session*

**Why:** TD-1281: a card whose `decision (paul)` or `Owner: paul` entry the person is already working in their own interactive session read *needs you*, amber, with the *Decide 1* pill, and counted in **Needs you (n)** and the header's *Decide · Do*, so a card the person is working competed with the ones that truly wait on them.

**Fix:** as §4.4 and §4.5 screen 12 write it. The field is `with_you` throughout (not `with`, a Jinja and Python keyword):
- **The reading.** `_state` returns a third value, the chosen record's `_holder` dict (`{id, name, state}`, else `None`), beside its word and `needs`, and the word *with you in <name>*, for an `Owner: paul` or `decision (paul)` entry with a claim (its `claims`, from `held`) whose record has `unattended: false` — `card_session`'s nested `mine` helper's `not s.get("unattended")` test, no new filter — the chosen record the first such by id (`sorted(..., key=lambda c: str(c[0].id))`, as `card_session`'s `mine` sorts), `<name>` its name, so the word and Open session name the same session (not the first claim's, since an unattended worker may also hold it). It runs after the *held (person)* test and before the owner and decision tests, so a held entry keeps *held (person)*, an idle interactive holder never reads *stalled*, and a red PR on the entry is the row's `pr`, not its word (on purpose, §4.4). `row` sets `holder` to that dict (not `_holder(claim[0][0])`) and `with_you` to its `name` on such a row. The row **keeps its `needs`** (`owner` or `decision`); `card_entries`'s docstring says a `needs` row with `with_you` is no want though under *waits on me*. The id lists read `needs` and stay as they are — `card_entries` still puts the entry under *waits on me*, so `item_start` and `/api/ledger/start` (`app.py`, which checks `card_entries(card)[0]`) accept a press on it unchanged. Every need test reads a row with `with_you` as no need: `_status`'s `any(r["needs"] for r in rows)` becomes `any(r["needs"] and not r.get("with_you") for r in rows)`, so the card's status falls to the next word (*ready* where nothing else waits; the card is In progress by the claim and draws *d/m done*; `ao rank --list` prints *ready*). Only the claim counts, not the `td-<n>` name (accepted, §4.4). An entry claimed only by unattended records reads as now.
- **The item.** The card's ledger item for that entry (the Inbox's row from `shiftlead.ui.inbox.ledger_for_you`, attached to the card) takes a want `with_you`: `attach` gains a callable beside `start`, `with_of(card id, ref) -> name`, which `card_mail` builds from the cards it already holds (`by_id[c]`'s `top` and `rows`); `put` asks it only for a ledger item (`e.get("row") == "ledger"`, whose ref is `<repo>#TD-n`), and where it names one sets `want` to `with_you`, `kind` to `''` (overriding the `_item_kind` its caller passed), puts the name as `with_you` in the dict handed to `drawn` (which the `ledger` macro reads; the item dict `card_wants` collects needs no new key), and computes `go` (`start(card, ref)`) as for `WANTS`, so the item draws **Open session**. `ledger_for_you`'s own holder field is not the test. The start road calls `card_mail` with no cards, so `with_of` (like `start`) is `None` there; the road reads only item ids, so the want does not matter to it. `want_of`'s and `card_wants`'s docstrings name the new want; `card_wants` gains a `with_you` list, counted in none of `n` (`n.decide` and `n.do` stay Decide and Do alone, so the pill and `queue_view`'s header `decide` / `do` sums leave it out). `queue_view`'s `items_start` counts a `with_you` item, so the header draws no second Open session. The card draws it in the header after Decide and Do, grey: its own section (`qsec qwith`, `data-sec="with_you"`), not the `want` macro's `qsec qwant`, whose heading `app.css` colours amber; in `inbox_row.html`'s `ledger` macro, where `e.want == 'with_you'`, the head's *held by* / *claimed by* span (`e.held`) is not drawn, the word naming the session as a row's word replaces its pill, the `qneed` span reads *with you in <name>* and the card-mode foot (`mfoot`) *with you in <name> — an answer here still writes the decided line on <repo>'s board* in place of *waits on you, with no date…*; its answers, Open session and ⋯ unchanged. No board-line path (`k-{{ e.want }}`) sees the want: only a ledger item takes it.
- **The marks.** `branch` and so `_seg` give a row with `with_you` `open` (grey), not `needs`, and `_seg`'s title its state word, not *yours to do* / *your decision*; `_card_kinds` adds no `do` or `decide` for a row with `with_you`, so the kind pick does not list the card for it. In `queue_row.html` the `state` macro draws the row's word *with you in <name>*, not `needs_word`, where `with_you` is set (class `qstate s-with`, the default muted `.qstate` colour, no new CSS), the row's `needsyou` class is `r.needs and not r.with_you`, and the row's holder pill is not drawn beside the word, as for *held by* (line 120's `not (r.state or '').startswith('held by')` gains `and not r.with_you`). `queue_card.html`'s header (line 46) is unchanged: it keeps the top entry's holder pill and draws no state while `t.needs`, the item's line carrying the word. `_mail_status` and `card_edge` read only Decide and Do and the status, so neither changes; a test holds both.
- **What stays.** An `ask`, `steer`, look or board line about the entry stays Decide or Do and counted; the Inbox's *Later* row and the Repo page's board lines are unchanged; the Repo page's For you column draws the entry by the Inbox's `ledger` row (`repo_part.html` `brow`, `fy_rows`), which takes no `want`, so it is unchanged there too, and a *with you* row reaches `queue_row.html`'s `state` on the Repo page only where `fy_rows` lacks its id; only the Queue's `card_mail` attaches items; the top bar is unchanged (a ledger need enters no count).

**Done when:** a card whose only open member is a `decision (paul)` entry claimed by an `unattended: false` record reads In progress with status *ready* (and `ao rank --list` prints *ready*), its edge not amber, out of the **Needs you (n)** filter, the header's `needs_you` count and the kind pick's Decide; its item is drawn *with you in <name>* in its line and foot, with no *held by* beside the word, with Open session (and none in the header), counted in neither the pill nor the page header's `decide` / `do`; a press of that item's Open session reaches the start road and goes to the session, never refused; the top entry's header keeps its holder pill, naming the interactive record where an unattended one also claims the entry, and draws no state word; a non-top row in that state reads *with you in <name>* with no holder pill beside it, grey on its spine, its parent's meter segment grey and titled with the word; the same with `Owner: paul`; the same entry claimed by an unattended record keeps *needs you*; an entry claimed by an unattended record first and an interactive one reads *with you in <the interactive one>* and its holder is the interactive one; a held entry the person's session claims reads *held (person)*; an open `ask` about the claimed entry keeps the card *needs you* and on the pill; an idle interactive holder does not make the card *stalled*; with the claim gone (the record exited) the entry is Decide or Do again; the Inbox's *Later* row for the entry (no card holds it) and the Repo page's For you row for it are unchanged. Tests cover each case.
