## TD-1280: A `TaskStop` of a background subagent (the main thread's, or a subagent's) ends it on the record, so Ready to close reads *no subagents running* at once

**Priority:** Medium
**Type:** debt
**Added:** 2026-10-30 (the designer, from TD-1277)
**Owner:** grinder
**Kind:** build
**Status:** Open
**Part of:** TD-1277
**Location:** `src/shiftlead/adapters/claude_code/hook.py` (the `TOOL_EVENTS` branch, beside `SubagentStart` / `SubagentStop`); `src/sessionorc/agent_tick.py` (`_apply_subagents`, and the open-calls drop that pops a thread on `subagent_delta < 0`); `tests/test_claude_adapter.py`, `tests/test_subagents_live.py`; design §4.2's hook table (the `SubagentStart`, `SubagentStop` row), *A waiter is keyed by its call*, *Ready to close* (*No live subagents*)

**Why:** TD-1277: Claude Code (2.1.314, checked) sends no `SubagentStop` for a background subagent its caller stops with `TaskStop`, so the record's `subagents` stays at one until a restart, and Ready to close reads *✗ no subagents running* on an idle session for good.

**Fix:** as §4.2's table row writes it:
- **The adapter.** A `PostToolUse` with `tool_name == "TaskStop"`, on either thread, adds `subagent_stopped: <id>` to the tool event it already returns — the main thread's tool branch and the subagent tool branch (`hook.py`, the early return for an `agent_id`) alike — adding no `subagent_seen` of its own: the main thread's stop carries none, so `subagent_at` stays where it was, and a subagent's stop keeps the `subagent_seen` that branch already sets (its caller is alive) — the id being `tool_input.task_id`, else `tool_input.shell_id`, as a string; an empty, missing or non-string id adds nothing. The adapter does not judge whether the id is a subagent's: it cannot see the record.
- **The core.** `_apply_subagents` reads `subagent_stopped`: if the id is in `subagent_ids`, remove it and take `subagents` down by one (never below 0); otherwise nothing, so a stopped shell's, a teammate's name or an id already gone moves no count. It takes no part in the `s.subagents > len(s.subagent_ids)` fallback of an unidentified `SubagentStop`. The open-calls drop pops the stopped id's thread as a `SubagentStop`'s does, and the stopped id's waiter and every entry of that id, permission or question, end — for any non-empty string id, listed or not, since an unlisted shell's or teammate's id has none and an agent counted with no id may still have a waiter keyed by its `agent_id`: `_end_waiters(sid, None, <id>, None)` and `_end_entries` on `p.subagent == <id>` (not the thread end's `p.kind != "permission"` exclusion) with `sure=True`, as separate calls made beside (never in place of) the ones the event already makes for its own thread, and outside the `stale` gate, since a stopped subagent's waiter is dead whatever the event's age. They matter only while another subagent stays counted: when the stop takes the count to 0, the existing `running and not s.subagents` branch ends every subagent's waiter and entry, and the two end the same entries. The stopped id's ends run first (before the `queued` gate), so their `sure=True` is the session's last sure end and the zero branch's `sure=False` finds nothing; keep that order. A queued (replayed) event still moves the count and ends the stopped id's entries, since `_apply_subagents` and these ends run before the `queued` gate; only the open-calls step is skipped, as for every queued event. A failed stop is a `PostToolUseFailure`, not in `TOOL_EVENTS`, and sends nothing. Nothing else of the event changes: it is the sending thread's `PostToolUse`, with its `call: end` (and, on the main thread, its state).
- A later `SubagentStop` for the same id (should a future Claude Code send one) finds it gone and moves no count by TD-960's rule.

**Done when:** through the hook's payloads (a `SubagentStart` with `agent_id` *X*, then a main-thread `PostToolUse` of `TaskStop` with `tool_input: {task_id: X}`), the record reads `subagents: 0`, `subagent_ids: []`, and the Ready to close row reads *✓ no subagents running*; a `TaskStop` of an id not listed (a shell's `b…` id) moves nothing; a `TaskStop` from inside a subagent of a listed id ends it too; `subagent_at` does not move on a main-thread `TaskStop`; a `TaskStop` with `shell_id` and no `task_id` ends a listed id; one with no id or a non-string id adds nothing; an agent counted with no id stays counted (accepted), but its pending permission keyed by the stopped id ends; a stopped subagent's pending permission ends while a second subagent stays counted; a `SubagentStop` of *X* after the `TaskStop` moves nothing; two listed subagents and a `TaskStop` of one leave one. Tests cover each case.
