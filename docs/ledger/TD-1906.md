**Why:** #4029 (TD-1843 slice 5) added `Mail._person_replied_at` (`src/sessionorc/agent_mail.py`), whose docstring says it returns "the `at` of the newest message" the person sent on a question, and ends `return max(got) if got else None`. Its tests, `tests/test_person_replied_at.py`, never send two replies after the answer, so the newest-versus-oldest choice is untested. Evidence: in a scratch worktree on `origin/main`, change that line to `min(got)` and run `PYTHONPATH=$PWD/src pdm run pytest -q tests/test_person_replied_at.py tests/test_queue_replied_forms.py tests/test_stuck_handed_rows.py tests/test_ui_answered_hold.py`. 45 passed, as on main. The same revert on `mid != e.closed_by` fails a test, so that half of the function is covered. A person who replies twice would see the press line say "You replied <age> ago" for the first reply, not the latest, and no test would notice.

**Location:** tests/test_person_replied_at.py; src/sessionorc/agent_mail.py (_person_replied_at)

**Fix:** In `tests/test_person_replied_at.py`, send a second reply after the first and assert `replied_at` is the second's `at`. Cover the `go_with_it` case with two replies too.
