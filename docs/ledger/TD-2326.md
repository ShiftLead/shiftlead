## TD-2326: The design's account of the tool listing leaves out two things each login row now carries

**Priority:** Low
**Type:** debt
**Added:** 2026-11-26
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 3e6e3a4869bf49fb9322de571d7381c7

**Why:** Design §4.2b, **The read** (`docs/design/4.2b-tools.md`, line 186 at `b9d02f7c3`), gives each login row of the `tools` reply as `logins: [{name, label, folder, account, state, till, mismatch, warnings, note, pin, settings, version}]`. Every other field the host agent adds at a read is in that text (`till`, an account's `gauges`). Two keys a login row carries are not:

- `ended_records`, added by #4851 (TD-2288): `_login_tree` writes `"ended_records": None` (`src/sessionorc/tools.py`, line 273) and `_tools_gauges` fills it at each read (`src/sessionorc/agent_settings.py`, line 170). §4.9e *A record's `profile`* says the count is given *on the login's row of that read*, and #4851 left The read's shape as it was.
- `lists`, from #4406 (TD-2064): `_tools_gauges` adds `{teams, sets}` to each login row on the home, and nothing on a node or where the settings file cannot be read (`agent_settings.py`, line 173). §4.2b *The page* and §4.5a *Tools page: a login* describe the line the page draws from it, and neither names the key.

Probe at `b9d02f7c3`: the keys `_login_tree` builds and `_tools_gauges` sets, less the keys in the design's `logins: [{…}]`, are `['ended_records', 'lists']`.

So a client written from The read's shape does not know of either field, among them the one the Forget confirm needs.

**Location:** docs/design/4.2b-tools.md; src/sessionorc/agent_settings.py (_tools_gauges); src/sessionorc/tools.py

**Fix:** In §4.2b *The read*, add `ended_records` and `lists` to the login row's shape, with a clause each beside the ones for `till` and `gauges`: `ended_records` the count §4.9e *A record's `profile`* defines, filled by the host agent at each read; `lists` `{teams: [{name, label}], sets: [{name, label}]}`, `label` null where none, the switched teams and the built-in sets whose login list names the login (`builtinstore.login_lists`), filled at each read on the home and absent on a node or where the settings file is there and cannot be read. The history line goes to `docs/history/TD-2326.md` under §4.2b. No code changes.

**Done when:** §4.2b *The read*'s login row names every key a `tools` reply's login row carries, `ended_records` and `lists` among them, gives the shape of each `teams` and `sets` element, and says when `lists` is absent.
