## TD-2316: Session briefs and two design sections still give board commands that the board's writer now refuses

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-26
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 62eed12814c348fa95c4de410985ab3d

**Why:** Since the board became one file per item (ledgerboard v3.0, synced by TD-1881, #3968), a board item is named by its id and the replay command is gone. Run on 2026-11-26:

- `ao board edit done --line 3 --expect x` answers *error: refused: a board item is named by its id since ledgerboard v3.0, not by --line and --expect: --key board:<8 hex>, as `ao board show` prints it* (`src/sessionorc/board.py`, `branch_edit`).
- `agent-cadence run board_edit.py done --line 3 --expect x` answers *board_edit: --expect and --line retired with ledgerboard v3.0: name the item by --id*.
- `agent-cadence run board_edit.py replay` answers *board_edit: ledgerboard v3.0 retired `replay` (TD-248): … keep both sides' item files*.

What sessions are still told:

- `src/shiftlead/briefs/grinder.md`: a decided line is closed *with `ao board edit done --line <n> --expect "<the line's start>" --why "<what was done>"`*, and again in the `--carried-to` form. For a pull-request order: *a sweep PR's by `board_edit.py replay` at the stop*, *one that conflicts is replayed onto main's board and merged, and one whose replay refuses is closed unmerged*, and *a board conflict by `board_edit.py replay`*.
- `src/shiftlead/briefs/job/pr/sweep.md`: *replayed onto main's board (`agent-cadence run board_edit.py replay …`) … one whose replay refuses is closed unmerged*. `job/pr/filing.md` names `replay` for a board conflict.
- `src/shiftlead/briefs/sweeper.md`: two `board_edit.py done --board {board} --line <n> --expect …` commands.
- `docs/briefs/grinder-ao-1.md` and `designer-ao-1.md`: resolve a board conflict by `board_edit.py replay`, and archive by an `ARCHIVE_AT` count that no script in the pinned agent-cadence or under `src/sessionorc` holds.
- `docs/design/4.7-cli.md`: the `ao board edit` paragraph is headed `done|snooze --line <n> --expect "<start>"` and says `--carried-to` *works with `--line`/`--expect` and `--key` alike*. `docs/design/4.9a-winding-down.md` (*What a session does with a decided line*) closes a line with the `--line` form.

Every replay refuses, so the pull-request rule above, read literally, closes any conflicting sweep PR unmerged. Design §4.4 *What the taker does* says the opposite: such a PR *keeps both sides' item files*, an edit of one item is re-done through the writer, and it is merged; it is closed only where the edit cannot be re-done, and a closed `notices/` PR then counts as the person's no for the re-ask window. Design §4.4 *Two PRs' records merge in either order* says *Where this section, or a brief, still names `board_edit.py replay` for a board conflict, the conflict is settled this way*, as `AGENTS.md` does here, but the briefs still say otherwise (and a package brief reaches sessions of other repos), and that sentence says nothing of `--line`.

Met while auditing #4837, which edited the same paragraph of `grinder.md`, and other lines of `designer-ao-1.md`.

**Location:** src/shiftlead/briefs/ (grinder.md, sweeper.md, job/pr/); docs/briefs/; docs/design/4.7-cli.md; docs/design/4.9a-winding-down.md; docs/claude-memory/

**Fix:** 1. In the package briefs and the two repo briefs, name a board item by its id: `ao board edit done --key board:<8 hex>`, and agent-cadence's `board_edit.py done --id <id>`.
2. Replace every `replay` instruction with design §4.4's rule: keep both sides' item files and re-do an edit of one item through the writer. For a sweep PR, follow *What the taker does*, which closes it unmerged only where the edit cannot be re-done. Drop the `ARCHIVE_AT` sentence: `done` moves the item into `archive/<YYYY-MM>/`.
3. In design §4.7 and §4.9a, write the `--key` form alone, and drop the *Where … still names* sentence of §4.4 once nothing does, with the history line in `docs/history/TD-<n>.md`.
4. Correct the memories that give the retired forms (`steer-replies-land-on-the-board.md`, `summary-table-conflicts-resolve-row-wise.md`, `decided-in-the-filing-pr.md` and its `MEMORY.md` line). Check against the one-file-per-item board what else they and `board-changes-close-and-add.md` (with its `MEMORY.md` line) say: that last one still gives the `ARCHIVE_AT` archive and restoring the board file, and the first two still read or restore `docs/user_attention.md`, now a stub.

**Done when:** No brief, design section or memory tells a session to name a board item by line or to run the replay command, and a test fails if a package brief does.
