## TD-2288: Tell the person why a forgotten login's sessions read nothing

**Why:** TD-2280 makes it deliberate that a forgotten login's records read nothing until its folder is added again (§4.9e *A record's `profile`*), and the person is not told so. The Transcript page shows *no transcript for `<id>`: the tool's file is not on `<host>`* (`AgentServer.rpc_transcript`, `src/sessionorc/agent.py`), which is false — the file is there, the login is forgotten — and Forget's confirm and its help (`tools-forget`, `src/shiftlead/ui/help.py`) do not say the login's ended sessions stop reading (found by TD-2280's round 1 Fable review, F6 in `docs/reviews/TD-2280.md`).

**Location:** src/sessionorc/logins.py, src/sessionorc/agent.py, src/sessionorc/agent_logins.py, src/sessionorc/tools.py; src/shiftlead/cli.py, src/shiftlead/ui/ (app.js, help.py, the forget route)

**Fix:** 0. A record's login key (§4.9e, in *A record's `profile`*): one helper, beside `logins.profile_name` in `src/sessionorc/logins.py` — the record's `login`, else its `profile`, else `default`; taken whole where it holds a `:` (`profile_name` writes a name two tools share as its key), else `<adapter>:<name>`; it is in `forgotten:` where that key is, or, for the bare `default` of a record with no `profile`, where any `<tool>:default` is (the placeholder is withheld by name across tools, TD-2287), the words then naming that login. Fix 1 and 2 use it alone. A test with a shared name (`claude-code:x` and `gemini:x`, the record's `profile` `claude-code:x`) and one with an empty `profile`.
1. `rpc_transcript` (and so `ao transcript` and the Transcript page): in its `t is None` branch (the adapter takes the unknown profile's `KeyError` and returns `None`), where its login key is a key in the host's `logins.yml` `forgotten:`, refuse with *no transcript for `<id>`: its login `<name>` is forgotten on `<host>`; adding its folder again gives it back* in place of *the tool's file is not on `<host>`*. `rpc_transcript_digest` keeps its words: a forgotten login's conversations are not listed.
2. The count: the host agent counts its ended records (`state in ENDED`: closed and exited; a suspended one is live and refuses the forget) whose login key is the login's, and gives it as `ended_records` on each login's row of the `tools` read, filled afresh on each call as `gauges` are (the kept read is made only at start and on Check again; `src/sessionorc/tools.py` builds the rows) and in `rpc_login_forget`'s reply (`src/sessionorc/agent_logins.py`), so a node host's count is that node's. The Tools page's **Forget this login** confirm (`src/shiftlead/ui/static/app.js`) reads the row's `ended_records`: where it is above 0 the confirm adds *n ended sessions ran on this login: they read nothing until its folder is added again* (*1 ended session ran on this login: it reads nothing until its folder is added again* for one); at 0 it is as today. `ao login forget` (`src/shiftlead/cli.py`) prints the same line from the reply after it forgets.
3. The `tools-forget` help gains a clause in these words: *Its ended sessions read nothing until the folder is added again.* (the help list is bound to `help.py`; run the doc-bound help tests).
Tests for 0, 1 and 2. Design: §4.9e, in *A record's `profile`*, its *forgotten login's records* item, §4.2b *⋯ on a login*, §4.5a *Tools page: a login* ⋯ row.

**Done when:** A forgotten login's record's transcript refusal names the forgotten login and the way back, Forget's confirm and `ao login forget` count the ended sessions that stop reading, the help says so, and their tests pass.
