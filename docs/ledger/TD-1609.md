## TD-1609: Usage reserve per account: settings keyed by account, every line reader through _gate_reserves, and the per-profile file migrated

**Priority:** High
**Type:** debt
**Added:** 2026-11-11
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** c66c24d8c8d545c69b01c09b4700b8a0
**Part of:** TD-1581
**Location:** src/sessionorc/settings.py; src/sessionorc/agent_spend.py (_gate_reserves); src/sessionorc/agent_tick.py; src/sessionorc/agent_settings.py (rpc_gate, set_settings); src/shiftlead/profiles.py; design §6 Usage gate (A reserve is the account's), §5, §4.2a

**Why:** TD-1581's design (§6 *Usage gate*: *A reserve is the account's*; §5 `usage_gate:`; §4.2a *An account has one billing*): a quota is one number per account, but its reserve was set per profile, so a raise on one profile left the others on the same account running to their old line (kmaster, 2026-11-07). This build moves the setting and every reader of it to the account, and migrates the per-profile file.

**Fix:** As §6 *Usage gate* *A reserve is the account's* says (the design is the text; where this restates it and the two differ, the design wins):
- `usage_gate:` is keyed by the account's usage key, `<adapter>:<account>` as `agent_common._usage_key` gives it (`account_for`: the profile's `account`, else its name; an unresolved profile is `<adapter>:<profile>`). A key is an account key when it is `<adapter>:<rest>` with `<adapter>` in `adapters.names()`, whether or not a profile here names it. `settings.reserves()` and `settings.amounts()` return `{account: {label: …}}`.
- Every reader reads by account: `_gate_reserves(whole, profile)` (src/sessionorc/agent_spend.py) resolves the profile and returns the account's reserves or amounts, and `_enforce_usage_gate`, `_projection_notes`, `_profile_over`, `_usage_only_due` (src/sessionorc/agent_tick.py) ask it; the spend readers of amounts (agent_spend.py's metered `pct` and the spend mark, the `settings.amounts()` and `usage_gate` reads there and in agent_settings.py) read the account's amount; the `gate` RPC (`rpc_gate`, with `_amount_rows`) answers `{accounts: {<key>: {profiles, billing, reserves | amounts, windows}}}`. Team reserve priority (`settings.team_extra`) unchanged.
- `set_settings` takes `{account, reserves}` (`_reserves_change`, `_amounts_change`, `_lay_gate` write `usage_gate.<account>`); a `profile` argument resolves to its account and the reply names the account and the profiles it moved. The billing and labels are the account's profiles' (one billing), or for an account only a node names, its node `spend` and usage calls under the key; with none, the set is refused naming the account as unseen. A unit that does not fit the billing is refused, naming it.
- One billing (§4.2a): profiles with one usage key and different billing are no load error; `ao doctor`'s profiles check names them, `set_settings` refuses a reserve on the account naming them, and the account's entry is read only by the profiles whose billing fits its unit.
- Migration, once, by the home's host agent at its start (never a node, a CLI read or a page read): every `usage_gate:` key that is no account key is a profile, resolved by the adapters that know it; per label the account keeps, among its profiles' reserves and any entry already under the account, the largest per-day reserve where any is per day, else the largest flat one (a metered account: the smallest amount); the profile keys are removed in the same write through `set_settings`'s writer; one `system` note names what moved, from which profile, and each other profile's value; a profile key no home adapter resolves is removed and named in the note with its value.

**Done when:** Every reader of a line reads the account's reserve: two profiles on one account read one line, and `set_settings {account, reserves}` moves both. Tests: kmaster's shape — `grind` week 1, `grind-fable` 3, `grind-ask` 5, `grind-sonnet` 5 on `claude-code:paul`, all flat — migrates to `claude-code:paul` week 5, the profile keys gone, one note naming each; a flat 30 and a per-day 5 on one label migrate to the per-day 5; two amounts migrate to the smaller; an account entry already written counts among them; a second start migrates nothing and sends no note; a profile key no home adapter resolves is removed and named in the note; a key `claude-code:nodeacct` no home profile names is read as an account key and kept; `set_settings {profile: grind}` writes `claude-code:paul` and names the account and its profiles; a team reserve priority still lowers its sessions' line on any profile of the account; a metered account takes an amount and refuses a percent, and its window's `pct` is the account's spend over the account's amount; a file with a metered and a subscription profile on one usage key loads, `ao doctor` names it, a set on the account is refused, and the existing entry is read by the profiles whose billing fits; the same account name under two adapters is two accounts; the `gate` RPC answers by account with each account's profiles; a profile no adapter resolves reads `<adapter>:<profile>`.
