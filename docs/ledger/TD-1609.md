## TD-1609: Usage reserve per account: settings keyed by account, every line reader through _gate_reserves, and the per-profile file migrated

**Type:** debt
**Added:** 2026-11-11
**Owner:** grinder
**Kind:** build
**Status:** Open

**Location:** src/sessionorc/settings.py; src/sessionorc/agent_spend.py (_gate_reserves); src/sessionorc/agent_tick.py; src/sessionorc/agent_settings.py (rpc_gate, set_settings); src/shiftlead/profiles.py; design §6 Usage gate (A reserve is the account's), §5, §4.2a

**Why:** TD-1581's design (§6 *Usage gate*: *A reserve is the account's*; §5 `usage_gate:`; §4.2a *An account has one billing*): a quota is one number per account, but its reserve was set per profile, so a raise on one profile left the others on the same account running to their old line (kmaster, 2026-11-07). This build moves the setting and every reader of it to the account, and migrates the per-profile file.

**Fix:** As §6 *Usage gate* *A reserve is the account's* says (the design is the text; where this restates it and the two differ, the design wins):
- `usage_gate:` is keyed by the account's usage key, `<adapter>:<account>` as `agent_common._usage_key` gives it (`account_for`: the profile's `account`, else its name; an unresolved profile is `<adapter>:<profile>`). `settings.reserves()` and `settings.amounts()` return `{account: {label: …}}`.
- `_gate_reserves(whole, profile)` (src/sessionorc/agent_spend.py) resolves the profile to its account and returns the account's reserves (amounts for a metered account); every reader asks it: `_enforce_usage_gate`, `_projection_notes`, `_profile_over`, `_usage_only_due` (src/sessionorc/agent_tick.py) and `rpc_gate` (src/sessionorc/agent_settings.py), which today reads `settings_mod.reserves`/`amounts` directly. Team reserve priority (`settings.team_extra`) unchanged.
- `set_settings` takes `{account, reserves}` (`_reserves_change`, `_amounts_change`, `_lay_gate` write `usage_gate.<account>`); a `profile` argument is resolved to its account and the reply names the account and the profiles it moved. A unit that does not fit the account's billing is refused, naming it.
- `profiles.yml` (src/shiftlead/profiles.py, beside `_metered_dirs`): a metered and a subscription profile naming the same account (`account`, else name) is the file's error, named (§4.2a).
- Migration, once, at the home's first read of a `settings.yml` holding a `usage_gate:` key that is no account key: each such key is a profile, resolved to its account; per window label the account keeps, among its profiles' reserves and any account entry already written, the one whose line is lowest at the migration's instant; the profile keys are removed in the same write through `set_settings`'s writer; one `system` note to the person names what moved, from which profile, and each other profile's old value; a key that resolves to no profile the home knows is kept, read by none, and named in that note.

**Done when:** Every reader of a line reads the account's reserve: two profiles on one account read one line, and `set_settings {account, reserves}` moves both. Tests: kmaster's shape — `grind` week 1, `grind-fable` 3, `grind-ask` 5, `grind-sonnet` 5 on `claude-code:paul` — migrates to `claude-code:paul` week 5 (the lowest line), the profile keys gone, one note naming each; a flat and a per-day reserve on one label migrate to the one with the lower line at the instant; an account entry already written counts among them; a second load migrates nothing and sends no note; a key naming no known profile stays, read by none, named in the note; `set_settings {profile: grind}` writes `claude-code:paul` and names the account and its profiles; a team reserve priority still lowers its sessions' line on any profile of the account; a metered account takes an amount and refuses a percent; a `profiles.yml` with a metered and a subscription profile on one account is refused, naming both; `rpc_gate` returns the account's reserves for each profile; a profile no adapter resolves reads `<adapter>:<profile>`.
