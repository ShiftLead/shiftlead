## TD-1609: Usage reserve per account: settings keyed by account, every line reader through _gate_reserves, and the per-profile file migrated

**Priority:** High
**Type:** debt
**Added:** 2026-11-11
**Owner:** grinder
**Kind:** build
**Status:** Open

**Part of:** TD-1581
**Location:** src/sessionorc/settings.py; src/sessionorc/agent_spend.py (_gate_reserves); src/sessionorc/agent_tick.py; src/sessionorc/agent_settings.py (rpc_gate, set_settings); src/shiftlead/profiles.py; design §6 Usage gate (A reserve is the account's), §5, §4.2a

**Why:** TD-1581's design (§6 *Usage gate*: *A reserve is the account's*; §5 `usage_gate:`; §4.2a *An account has one billing*): a quota is one number per account, but its reserve was set per profile, so a raise on one profile left the others on the same account running to their old line (kmaster, 2026-11-07). This build moves the setting and every reader of it to the account, and migrates the per-profile file.

**Fix:** As §6 *Usage gate* *A reserve is the account's* says (the design is the text; where this restates it and the two differ, the design wins):
- `usage_gate:` is keyed by the account's usage key, `<adapter>:<account>`; a key holding a `:` is an account key, read as one whether or not a profile here names it; a key holding none is a profile's and no reader reads it. `settings.reserves()` and `settings.amounts()` return `{account: {label: …}}`.
- The adapters (§4.3): `account_for` answers only for a profile naming its adapter (claude_code and gemini today answer for any profile in profiles.yml); a new optional `profiles()` lists the profiles naming the adapter, each `{name, account, billing}`. With node usage and spend calls, it is the host agent's list of accounts and their profiles.
- Every reader reads by account: `_gate_reserves(whole, profile)` (src/sessionorc/agent_spend.py) resolves the profile and returns the account's reserves or amounts, and `_enforce_usage_gate`, `_projection_notes`, `_profile_over`, `_usage_only_due` (src/sessionorc/agent_tick.py) ask it; the spend readers of amounts (agent_spend.py's metered `pct` and the spend mark; the `settings.amounts()` and `usage_gate` reads there and in agent_settings.py) read the account's amount. The `gate` RPC keeps its reply's shape here, each profile's entry carrying its account's reserves, so `ao gate` and the Settings page work between this build's promote and TD-1610's, which changes the shape with its readers. Team reserve priority (`settings.team_extra`) unchanged.
- `set_settings` takes `{account, reserves}` as well as today's `{profile, reserves}`, a profile resolved to its account, both writing `usage_gate.<account>` (`_reserves_change`, `_amounts_change`, `_lay_gate`) and the reply naming the account and its profiles. Billing and labels are the account's profiles' (one billing), or for an account only a node names, its node calls'; with none and no profile, refused naming the account as unseen; with no reading, a label is accepted unchecked. A unit that does not fit the billing is refused, naming it.
- One billing (§4.2a): profiles with one usage key and different billing are no load error; `ao doctor`'s profiles check names them, `set_settings` refuses a reserve on the account naming them, and the account's entry is read only by the profiles whose billing fits its unit.
- The migration (§6 *The migration*), the host agent's second write outside `set_settings` beside `_migrate_scale` (src/sessionorc/agent.py), which stays as it is: once per tick, before `_enforce_usage_gate`, walk `usage_gate:` of `settings.read()` (a dict; None is never migrated or written) for a key holding no `:`; with none, nothing more. Each such key (`""` the default profile) moves to its profile's account through the adapter the profile names (`profiles()`, called only then); per label the account keeps, among the entries whose unit fits its billing (the others removed and named), the one whose line is lowest on the window's last day (flat `r`: `100 − r`; per-day `d`: `100 − d`; tie: per-day, then the first profile by name; metered: smallest amount). Resolve first; then load, edit and save with no await between, then push to the nodes (`_push_settings`) and commit (`_commit_defs`) as `rpc_set_settings` does after its save; before it, commit the file as it stands (`defs.commit`, which makes none when it is committed already), the commit holding it as it stood being the tree's last change to `settings.yml`, read with git; on a home that is no tree (`defs.is_tree`), copy it to `settings.yml.before-TD-1581`, never overwritten. One `system` note: what moved, from which profile, each other profile's value, each profile whose line rises (a flat `r` kept over its per-day `d`, at any `days_left` 1..window length with `d × days_left > r`), and the commit (or copy) to restore from. A key whose profile no adapter here resolves is removed and named with its value.
- Names: a profile name holding `:` or `.` is named by `ao doctor`'s profiles check and its reserve refused.
- The `gate` RPC between this build and TD-1610: its profile list comes from `profiles()`, each with its account's reserves; a profile whose account has no entry is omitted, as today.
