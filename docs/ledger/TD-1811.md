**Fix:** Build the order half of design §4.4 *A filing PR nobody holds is a work order* — the bullets *The order*, *What the pages read* and *What the taker does* — on TD-1810's `filing` stamp:
- `FILING_AFTER = timedelta(days=1)` beside `ORPHAN_AFTER` in `agent_common.py`.
- `workorders.is_filing_order(pr, now, after, key)` beside `is_sync_order`, `key` the held key the reading was read at (the tick's `_held_keys` union over one remote's roots, which `_red_prs` computes as the read pass does): `filing` true with `filing_head` the row's head; with a key, `held` read at that head and key (`held_head`, `held_key`) and empty (unread: not yet); with an empty key, no fresh `held` needed, but a row carrying a non-empty `held` (kept from an earlier key) is never one; not a draft or fork; checks not red or `not_run`, not conflicting; `created` at least `after` ago; no reader asked of it reading *waiting* in `pr_orders.reads`.
- `workorders.red_prs` takes `filing_after` and `key` as keyword-only arguments (absent: no filing order, so existing callers and tests stand) and reads such a row with one `told` memory for every PR order, one entry per PR, its `red_since` field holding the spell's stamp (`created` for a filing PR) (`agent_tick._red_prs` replaces `pr_orders.told` with its result whole): its spell stamp is `created`; no holder (`holds_pr`) → an order; every holder `idle` → told once (`pr_note`: *filing PR #<n> has been open since <t>: merge it or say why*, told from a red note by `filing` with checks neither red nor `not_run` and not conflicting), `ORPHAN_AFTER` later still idle → an order. A red or conflicting filing PR stays the red rule's alone. The memory entry is kept while the row carries `filing` true and its stamp is `created`, whether or not the row passes that tick.
- `pr_order`: `filing: true` (by `pr_note`'s row test), `filing_since` (`created`), priority *Medium*, `Context` the URL and *filing, open since <date>, nobody holds it: review and merge it, or close it if superseded*; after every other PR order in `red_prs`' sort; in `teamrun.lane_entries` after the sync orders and before the lane's entries.
- `workorders.red_holders(open_prs, records, now, after, filing_after, key)` gates a filing row by `is_filing_order`, so the reading's `held` names a filing PR's holders. `_red_prs` writes the numbers the test passes, holders aside, as `pr_orders.filing: [n…]` (every repo, served or not); `teamrun.red_prs` lists exactly those (never re-running the test, TD-652; never `DRAFT_WHOSE`), with `word` *filing*, sorted by `since` with the rest, `red_title` leaving filing rows out as the facet's count does, carrying `filing_since` and `since` (the stamp its age reads: `red_since` for a red row, `filing_since` for a filing one), which every page that ages the row (`ui/repo.py`, `ui/org.py`) reads in place of `red_since`; the Repo page's Review row (`ui/repo.py`, `repo_part.html`) draws a *filing <age>* tag, not red-styled, titled *ledger and board files only, open since <date>*, and reads *nobody's — the grinders' order* or *held by <name>* for it; the facet's *· n red* (`ui/org.py`) leaves *filing* rows out. `red_pr_rows` (`ui/inbox.py`) and the cards' order map (`ui/org.py`, the `pr_orders` it puts among a card's entries) pass over a filing order (no Inbox row, no Do item). A seam-unserved repo (`seams.unserved`, where `_red_prs` lists no order) gets no filing order and an empty `pr_orders.filing`; a test holds it. The Queue's stalled read is unchanged.
- `ao repo` (`cli.py`): a filing branch in the order print loop, as the lift case has, printing the line `pr:<n> · <title> · filing, open since <date>: nobody holds it`, counted on the first line as *n filing PRs nobody holds* apart from the red count (today orders less sync and lift).
- The taker's path, where a grinder reads how to take a `pr:<n>` order — `src/shiftlead/briefs/grinder.md` (its red, sync and lift paths; a filing order taken before the lane's entries and counted in its *Out of work* test) and `src/shiftlead/team_skill.md` (the work-order line): read the comments and standing first (where a reader asked of it returned findings, act as the author: fix and ask again); note a live author; check the files are still a filing PR's, else drop saying so; where `ao pr held` reads it held at merge, ask the reader; close with a comment where everything is on main or moot, drop a moot entry from a partly moot PR, renumber an id taken on main (`ao td reserve`, `ledger.py renumber`); else bring it up to main, fact-check it always at the head it merges (the cadence's review row reads no head), precheck and merge; a finding or precheck it cannot mend ends in a close with the rest filed, never a drop leaving the PR open; just before a renumber, a close or the merge, read the PR again (open, at the head read) and end the claim as done where it was merged or closed meanwhile.
