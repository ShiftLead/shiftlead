## TD-2228: Nothing tests that the home notes a session's spend when it offers it work

**Priority:** Medium

**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 62c3b19230a34450990a922c5843a413

**Why:** #4663 (TD-2158 slice 4) has an offer keep the holder's spend sums in the stage record's `spent_before`, so the row that ends the holder counts only its own run (docs/design/4.9c-flows.md, *Each holder leaves a `run`*). The tick's pass hands the reader on in `_make` of src/shiftlead/stage_pass.py: `stage_make.offer(..., team=f.team, spent=reach.spent, version=version)`. No test would catch that argument going.

Removing `spent=reach.spent` from that `offer` call, alone, left the 21 stage test modules passing (898 passed at 957e4b75b), and `pdm run test` at 6cb9bb90b passed with it removed (10153 passed, 24 skipped; TD-2227's two changes applied in the same run). `offer` then drops the holder's id from `spent_before`, and `run_of` in src/shiftlead/stagerecord.py writes `models: null` where there is no value from the offer, so every run the tick offered would record no spend. The tests cover `offer` called directly (`test_an_offer_keeps_the_holders_sums_under_its_bare_id`), `reach_for` building the reader (`test_the_reach_reads_a_sessions_spend_from_the_seat_ledger`) and the pass's other handoff, to `make` (`test_a_home_write_hands_make_the_holders_record_and_its_spend`), not the pass's handoff to `offer`.

**Location:** tests/test_stage_pass.py

**Fix:** In tests/test_stage_pass.py: a `step` that makes an offer with a reach whose `spent` returns sums, asserting the record's `spent_before` holds them under the holder's bare id.

**Done when:** Removing `spent=reach.spent` from `_make`'s `stage_make.offer(...)` call fails a test.
