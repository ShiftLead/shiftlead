## TD-1701: A live session's PR with its reader (review_pr) reads as a red PR nobody holds and is ordered to the grinders

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-12
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** b9fe42d332d24eb5aff15ac3d5820049
**Location:** src/sessionorc/workorders.py (holds_pr); docs/design/4.4-host-agent.md (A red PR nobody holds is a work order)

**Why:** A claim whose PR is with its reader keeps that PR as `review_pr` (TD-150), not `pr`, and `workorders.holds_pr` reads only `pr`. Design §4.4 *A red PR nobody holds is a work order* defines *holds* the same way. So a live session's own PR, once it turns red or conflicting, is listed as `pr:<n>`, *a red PR nobody holds*, and handed to the grinders while its author is at work on it.

Seen on 2026-11-12 at 01:31 UTC. `ao-shiftlead-designer-ao-1` was `working` with a claim on TD-1556 carrying `review_pr: 3504`, and `ao repo` printed `holds TD-1556 → #3504`. In the same reading, #3504 (its design PR, conflicting since 00:31 UTC) was `pickable pr:3504 … grinders`, and both grinders were rung twice in twenty seconds to take it. A grinder that took it would rebase another session's design PR in the middle of its rounds.

`agent_ids.py` (:272) and `agent_tick.py` (:1747) already read `pr or review_pr` as the claim's PR. Only the red-PR holder test leaves `review_pr` out.

**Fix:** 1. Design §4.4 *A red PR nobody holds is a work order*, *A live record holds it*: the clause on a `progress` entry naming the PR adds *or its `review_pr` is `n`*, citing TD-150, with a line in `docs/history/TD-1701.md`.
2. `src/sessionorc/workorders.py` `holds_pr`: `e.ref == f"pr:{n}" or e.pr == n or e.review_pr == n`.
3. A test in the existing `holds_pr` / `red_holders` tests: a live record whose claim carries only `review_pr: n` holds PR n, and the PR is not an order.

**Done when:** A red or conflicting PR named as `review_pr` on a live record's claim is not listed as a `pr:<n>` order, and the test fails when `holds_pr`'s `review_pr` clause is removed.
