**Why:** An unattended seat that stops for a person on every reply is not unattended. Paul: *having to babysit an unattended seat defeats the purpose* (through `ao-led-tds-ledger`, m-0d47f834a8fa, 2026-11-10). On the evening of 2026-11-10, ao-grind's fact-check seat (`ao-shiftlead-fact-check-ao-1`; profile `gemini-reader`, gemini-3.5-flash-lite; launched with the adapter's `--approval-mode yolo`, `src/shiftlead/adapters/gemini/__init__.py` `YOLO`) raised a NEEDS YOU permission prompt about four times in five minutes, and Paul allowed each one. Its chat shows four `ao msg --reply-to m-… "cadence-review: SHIP …"` calls in that span, one per verdict, while every other call (git, `ao inbox`) ran unprompted. Earlier the same prompt read *CRITICAL SECURITY WARNING: Untrusted Command Flags Detected … --reply-to … sourced from external untrusted input … Allow once / No* (Paul's screenshot, 2026-11-10 20:25).

The cause, as reported: Gemini CLI has its own guard against untrusted flags (the installed 0.66.0's bundle carries `hasUntrustedFlags` and that warning). Yolo does not lift the guard, and it offers no *always allow*. It fires when a command's flag value came from tool output, and a reply's message id comes from `ao inbox`, so every reply the seat sends stops. The fact-checker brief's one road for a verdict is `ao msg --reply-to <the ask's id> "…"` (`src/shiftlead/briefs/fact-checker.md`), so this blocks the seat's whole job. The seat's chats before 2026-11-09 hold no reply at all, so this path is new in practice.

An aside for the same round: in this run the seat returned SHIP with 0 findings on all four PRs it read (#3262, #3248, #3267, #3268), TD-1470's Hold revision among them. Whether flash-lite reads closely enough to be the fact-check is TD-1214's question (the Gemini fact-check trial), and this entry hands the run to it as evidence.

**Fix:** Design first (§4.3 the adapter contract and its conformance suite; §4.2a profiles and `permission_prompts`; §4.10 replying; §4.7 `ao msg`), then a build. The fix is **mechanical**: no session judges whether to allow anything. Options to weigh:

- **(a) A reply path that takes no id from the model.** For example `ao msg --reply-to next`, or `ao reply "…"`, answering the caller's oldest open ask; or the verdict written to a file the home reads. The command line then carries no value from tool output for the guard to flag. Settle which ask *next* means when several are open, and how the fact-checker brief names it.
- **(b) The Gemini settings layer's policy engine allowing `ao msg`**, if a policy rule lifts this guard. Verify against the installed CLI (`~/.npm-global/lib/node_modules/@google/gemini-cli/package.json` reports 0.66.0) before relying on it. A change to the person's Gemini settings is the person's to make (it is their tool's config), so the adapter can only propose it.
- **(c) A conformance case** in the adapter's suite: an unattended gemini seat answers an `ask` end to end, read through `ao inbox` and replied through the brief's road, with no prompt raised. This holds whichever of (a) or (b) is chosen.

**Done when:** Done when the design names the reply road an unattended Gemini seat takes without a prompt, and a build lands it with the conformance case: an unattended gemini seat answers a fact-check `ask` end to end with no NEEDS YOU.
