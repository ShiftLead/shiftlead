## TD-2077: Comparing flows needs its metrics recorded from the start: check what a flow's run leaves behind, and add what is missing

**Priority:** Medium
**Type:** feature
**Added:** 2026-11-22
**Owner:** designer
**Kind:** design-first
**Status:** Open
**Id take:** e2bc2ad999f44aaca0105c8f8481d75b
**Blocked by:** decision (paul)

**Why:** Paul, 2026-11-22: we will want to compare how effective our flows are, particularly on defects that trace back to designs, and the metrics for it must be in place shortly after the flows are implemented, before weeks of running pass unrecorded. Some instrumentation exists: a defect a design missed names it on its Escaped from line (cadence 2.13), each design's review record holds its rounds, models, tokens and findings and review_stats.py reads them, the home keeps spend per seat, and the frame (ADR 2026-11-18) keeps each run's tool and version and asks for a content hash of a flow so results can be benchmarked, which design 4.9c has not taken up and no build records. Nothing has checked that these, with what a format-3 flow's stage record keeps, are enough to compare one flow with another. TD-934, archived 2026-11-22, asked for such a measurement and it was not carried.

**Ask:** Should the grinders build the design that records what each flow's run leaves behind, or run one more review round first?

**Design PR:** #4512, #4533

**Fix:** Once the stage record and the home's acts are built, read what a finished entry leaves behind and say whether each of these can be read per entry and summed per flow, by the flow's name, and by a content hash of the flow if a run is to record one (decide whether, and where): the stages it entered, each with its model, tool, tool version and login; tokens and cost per stage, weighted as the 2026-10-08 prompt-cache decision does; wall time per stage and from filed to merged; each move back for changes and each limit or cap reached; review findings per pull request by class; questions that went to the person; offers lost and sessions moved to another login; and defects afterwards, by Escaped from naming the design entry, with reopened and follow-up entries. A closed stage record leaves the state branch's head after thirty days and stays in its history (design 4.9c): say whether the history or a copy is what a comparison reads, and check that an Escaped from line can be joined to the flow its design ran under. Check that a baseline exists for the first shape's td flow from the 2026-11-11 and 2026-11-12 decisions' data, taken before the switch-over. File a build for each reading that is missing, to land before or just after the window (TD-2073), and write the list of readings into design 4.9c.

**Done when:** A table says, for each reading above, where it is recorded or which build adds it; the builds are filed; and design 4.9c names what a flow's run records for comparison.
