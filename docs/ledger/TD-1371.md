## TD-1371: Ids and origins: adopt origin_key, emit the lowercased origin path in ids, prefer an exact path match in the ledger reader's _find

**Priority:** High
**Type:** feature
**Added:** 2026-11-04 (ao-led-tds-ledger, a person-session in ledgerboard, through `ao td add --repo shiftlead`; drafted by ao-shiftlead-techlead-ao-1)
**Owner:** grinder
**Kind:** build
**Status:** Open
**Blocked by:** TD-1370, agent-cadence#TD-214
**Part of:** TD-1369
**Location:** `src/sessionorc/ledger.py` (the cross-repo id resolver, `_origin`, `_find`, `__call__`, ~763–810), `sessionorc.queue.refs` and `src/shiftlead/ui/queue.py` (`item_home`), wherever a `<repo>#TD-n` is written or looked up

**Why:** ledgerboard's target design (ShiftLead/ledgerboard `docs/plans/target-design.md`) §7.2 step 4, its first item; §3.2 and §4.1 define `origin_key` and the multi-component `<repo>` grammar. Two repos whose origins end alike resolve to the wrong one by suffix match; ledgerboard's `origin_key` is the one key every consumer uses. Step 4 follows agent-cadence's step 3 (agent-cadence#TD-214, whose own ids part is agent-cadence#TD-217).

**Fix:** use the module's `origin_key` for the repo a `<repo>#TD-n` names, emit the lowercased origin path where ShiftLead writes such an id, and make `_find` prefer an exact path match over a suffix match. The PR changes ShiftLead's design (docs/design/) in the same diff wherever the behaviour it changes is written there.

**Done when:** a test with two roots whose origins share a suffix resolves each `<repo>#TD-n` to its own repo, and ids ShiftLead writes carry the lowercased origin path.

**Related:** TD-1369; ledgerboard's target design (ShiftLead/ledgerboard `docs/plans/target-design.md`) §7.2 step 4.
