## TD-2032: A seat that runs no tests after a test run died keeps the dead run's files as long as the seat lives

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-21
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** c9682321636943c59cde9fe9800ca342

**Why:** TD-2028's build (#4280) removes a dead run's `pytest-N` only when a later run starts under xdist in the same seat's scratch (`$TMPDIR/pytest-of-kmaster/`). A seat that runs no suite after its run died keeps the dead run for as long as the seat lives: the host agent's disk sweep never removes a live record's scratch (design §4.6 *The disk sweep*), and pytest's own cleanup skips a locked directory for three days and runs only at a run's end in that same base temp.

Read on 2026-11-21 00:00 UTC, about seventeen hours after #4280 went live (TD-2028's second look): designer-ao-1's scratch `163e8fcd`, an idle live seat, still held four runs locked by dead pids (`pytest-51`, `-52`, `-75`, `-76`, all from before the build), 162,583 inodes, and had run no suite since. In grinder-ao-1's scratch an xdist run from main removed its two dead runs at once (10,034 inodes down to 79), so the sweep works where a run comes. The machine's `/tmp` is one tmpfs every session shares, so 160k inodes held by an idle designer count against every seat.

**Location:** tests/conftest.py (the dead-run sweep #4280 added)

**Fix:** Widen the sweep #4280 added in `tests/conftest.py` (the xdist controller's sessionstart) from the run's own base temp's parent to every seat's: each `pytest-N` under `<scratch_root>/shiftlead-<uid>/*/pytest-of-<user>/` whose `.lock` names a pid that is not running, with the same three safeties TD-2028's Fix names (an empty or unreadable lock counts as live; the pid check signals nothing, a `PermissionError` counting as alive; `pytest-current` and the run's own directory skipped). The scratch root is the parent of the seat's own scratch (`$TMPDIR`'s parent when it is a `shiftlead-<uid>` directory); a run outside a seat (no such parent) sweeps only its own base temp's parent, as now. Any seat's next suite then clears every seat's dead runs. A test holds it: two scratch directories under a fake root, a dead-pid run in the other one removed and a live-pid and an empty-lock run kept.

Keep it in the tests: the host agent's disk sweep knowing pytest's layout would put test-runner knowledge in `sessionorc` (design §4.3's spirit), so it stays out.

**Done when:** A full-suite run in one seat removes a dead-pid `pytest-N` from another seat's scratch, under a test; and on the live machine, a day after it merges, no `/tmp/shiftlead-1000/<scratch>/pytest-of-kmaster/` holds a `pytest-N` whose `.lock` names a dead pid, stated in TD-2028's Log with the date read.
