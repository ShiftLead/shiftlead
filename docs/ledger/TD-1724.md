**Why:** The Queue tells the person a team is stuck when it is the person's own interactive session sitting idle (TD-1529's card read *td-1529 stalled*, 2026-11-11), and the state words that stand for a session (*with you in <name>*, *held by <name>*, *stalled*) are plain text, so the word does not take the person to the session. TD-1567 designs both: design §4.4 *The person's own session is never stalled*, §4.5 screen 12 *A holder's word opens the holder*, §4.5a *Queue card: holder's word*.

**Ask:** Should TD-1567's builds (TD-1724 the Queue's words and links, TD-1725 a finished design's claim letting go) get one more round to read the closing fact-check's fix F58, go ahead as written, or is this the wrong design (Hold, with a note)?

**Fix:** 1. `queue._state` / `_state_word` (src/sessionorc/queue.py): a row any live record with `unattended: false` claims is never *stalled* — no claim on it is read by `_holder_stuck` — and its holder is the first such record by id whatever other claim stands. A row waiting on the person reads *with you in <name>* first, as today. Any other such row keeps the PR words (*#n conflicting*/*#n failing* · *being fixed*, *in review #n*, the pill beside them) and reads *with you in <name>* where it would read *held by <name>*. On such a row a red PR reads *· being fixed* while some claim's record on it is not idle or stuck (`_holder_stuck` over every claim, not `if claims`), else the bare *#n conflicting*/*#n failing*. Its `need` stays None and it gets no `with_you` (that mark, `mine` in the reading, stays the need rows' alone: it hides the pill, draws `s-with` over the PR words, withholds the press mark and is skipped by `lay_held`); the word is the row's `state`, as *held by* is, and the row's `holder` is the person's record. So `_state` returns the person's record apart from the `with_you` gate — say `(word, need, holder)` with `with_you`, `answered` and `applying`'s gate set from a record only where `need` is set (today's `mine`), and the holder from the person's record on any row: no grey *with you* item (§4.5 screen 12 *Three wants*), no change to the card's need. A stopped holder's state row still makes the card *needs you* (TD-1453).
2. *Stalled*'s holder: the row carries the record a *stalled* stands for (never `claim[0][0]`, today's `holder` at ~queue.py:1313) — the first by id of the claims' records `_holder_stuck` reads — as its `holder` (the pill and the word name one session; `ao card`'s holder follows); a red PR nobody holds has none. The card carries `stalled_holder`, the holder of its first stalled row that has one, the top entry first and then the rows as drawn (`_status`'s `[top, *rows]`, never the pick order), computed where the status is and re-read wherever the status is re-read (`lay_held`, ~queue.py:1062).
3. `queue_row.html` (~126) hides the pill when the state starts with *held by* or *with you in*, and macro `state`: *with you in <name>* (the `with_you` branch's too, linking `r.holder`, while *answered — waiting on <asker>* in that branch stays plain), *held by <name>* and *stalled* are `<a href="/focus/<id>">` wherever the row has a holder — the Repo page's board rows among them (`repo_part.html` draws them with these macros; its fallback rows in `repo_board.py` carry no holder and stay plain; its *For you* column's `fy_boards`/`fy_rows` rows, drawn by `inbox_row.html`'s `row`, are Inbox rows and stay as the Inbox draws them), keeping the word's class, colour and mark; the Repo page's builds line (`queue_row.html` ~56) keeps *held by* plain. `queue_card.html` header (~47): the top entry's pill stands and *held by* is not drawn, as today; one rule at ~47: a top entry whose state starts with *with you in* and that has no need draws the word as a link and no pill (today it would draw `holder(t.holder)` and the plain word both); its *stalled* beside the pill links the stuck record, and where the card's status is *stalled* too the header draws only the status's; the card's status *stalled* links `stalled_holder`, plain where it has none. *Needs you* is never a link. A link's hover changes colour only (§4.5 *A hover changes colour, never layout*).

Tests: TD-1529's case — an idle `unattended: false` record holding a derived claim on an entry with no `decision (paul)` reads *with you in <name>*, never *stalled*, and the card's status is not *stalled*; the same row with an open PR reads *in review #n* with the session's pill; an unattended idle holder still reads *stalled*, its pill the stuck record's; each word's link goes to the right Focus, a need row's *with you in* among them and a Repo fallback row plain, the header's *with you in* drawn once; a red PR nobody holds reads a plain *stalled*; a red PR held only by the person's idle session reads the bare *#n failing*, and with a working unattended co-holder *#n failing · being fixed*; a top entry and card both *stalled* draw one *stalled* in the header; `ao card` prints the words with no link, and `ao card --json`'s `card` carries `stalled_holder` as it carries every key (§4.7).
