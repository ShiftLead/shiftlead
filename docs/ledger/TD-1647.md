**Location:** design §4.3 *The conformance suite* *A seat's life end to end*; tests/conformance/ (stub_cli.py, test_seat_life.py, fixtures/*/manifest.json)

**Why:** TD-1577's design (§4.3 *A seat's life end to end, in CI, with no model*): the offline suite reads each adapter method alone and the live walk needs a person, so no test runs a seat's life — a launch, an ask delivered and read, an `ao` command run, the reply landing, the seat closing. A stub CLI replaying the adapter's own captured fixtures runs it in CI with no model, for every registered agent adapter, a new one included from its first fixture.

**Fix:** Build §4.3 *A seat's life end to end, in CI, with no model* as written:
- `tests/conformance/stub_cli.py`: one tool-neutral stub, run as the adapter's `binary`; it writes its argv and its `SHIFTLEAD_*`/`CADENCE_*` environment to a file, replays the manifest's `life` payloads from `captured/hooks.jsonl` through the hook command the adapter's layer names, read from that layer (stdin, the pane's environment, the captured session id replaced by the launch's), prints the `life` composer pane after the start and each turn, and reads typed lines: the first prompt plays a turn; a line of the doorbell's shape (built from `mail.unread_line`) plays a turn that runs the stub brief's two commands, the inbox read and the reply, `{id}` and `{text}` filled per open ask (today `ao inbox --json` and `ao msg --reply-to {id} "{text}"`, the fact-checker brief's road; TD-1582 changes them to `ao reply`).
- Each harness in `tests/conformance/_harness.py` gains `stub_setup(tmp)`: Gemini CLI's writes a scratch machine layer naming the hook command and points the adapter's machine-layer path at it (as `tests/test_gemini_adapter.py` does); Claude Code's does nothing. The declaration check holds that every agent adapter's constructor takes `binary`.
- A `life` key in each adapter's `tests/conformance/fixtures/<adapter>/manifest.json`: the indices of the start, turn and end payloads and the composer pane, from captured fixtures only; `end` empty where the captures hold no end hook (Gemini CLI's), the case then reading the end off the pane.
- `tests/conformance/test_seat_life.py`, parametrized over `agent_adapters()`: the adapter registered built with `binary` set to the stub, `stub_setup` run, on the suite's private tmux socket and scratch home; launch assertions (unattended under `skip`: the profile's `unattended_args`, else the adapter's; under `all`: none of them, and the adapter's `asking_args`; the id or resume; the layer names the hook command); an unattended seat with the stub brief asked from a second record with a nonce; states by hook (`idle`, then `working`/`idle` per turn, never `needs-you`); the nonce on the asker's thread; once the case closes the seat, the end reported (by hook, or off the pane where `end` is empty) and the record closed. An adapter with no `life` fails, never skips.

**Done when:** `test_seat_life.py` passes in CI (`pdm run test`) for Claude Code and Gemini CLI on their captured fixtures, with no model, no network and no `/etc/shiftlead/` layer, and a registered agent adapter whose manifest names no `life` fails it.
