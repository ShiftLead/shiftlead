**Why:** TD-1577's design (§4.3 *A seat's life end to end, in CI, with no model*): the offline suite reads each adapter method alone and the live walk needs a person, so no test runs a seat's life — a launch, an ask delivered and read, an `ao` command run, the reply landing, the seat closing. A stub CLI replaying the adapter's own captured fixtures runs it in CI with no model, for every registered agent adapter, a new one included from its first fixture.

**Ask:** Will you let TD-1577's design for testing a model integration apart from the model's judgment (a stub-CLI seat life in CI, an unattended seat smoke, a planted-defect set scored by a program), reviewed to the cap of four rounds with every build-changing fix read by a later review, go to its builds TD-1647, TD-1648 and TD-1649, or buy one more round, or hold it with a note?

**Fix:** Build §4.3 *A seat's life end to end, in CI, with no model* as written:
- `tests/conformance/stub_cli.py`: one tool-neutral stub, run through a wrapper the case writes as the adapter's `binary`, which passes the stub's script path ahead of the tool's arguments; it writes the argv after it and its `SHIFTLEAD_*`/`CADENCE_*` environment to a file, replays the manifest's `life` payloads from `captured/hooks.jsonl` through the hook command the adapter's layer names, read from that layer as written (a resolved path or bare `shiftlead-hook`; stdin, the pane's environment, the captured session id replaced by the launch's), prints the `life` composer pane after the start and each turn, plays the `end` payload on `SIGHUP` or `SIGTERM` (the host agent's close, `rpc_close`, kills the tmux session), writes a line saying so to its file, and then exits (only exits where `end` is empty), and reads typed lines: any first line plays a turn, its text never read (the stub brief is one line); a line of the doorbell's shape (built from `mail.unread_line`) plays a turn that runs the two commands of the stub's script, a file the case writes and the wrapper names, the inbox read and the reply, `{id}` and `{text}` filled per open ask: the read always `ao inbox --json` (the stub's own read, whatever the brief reads), the reply the fact-checker brief's road (`ao reply {id} '{text}'`, TD-1582 built it; a change to that road changes the stub's script with the brief).
- Each harness in `tests/conformance/_harness.py` gains `stub_setup(tmp, monkeypatch)`, `hook_command(argv, env)` (the hook command the launch's layer names, read from its argv and environment), `session_id(argv, env)` (the launch's `--session-id` or `--resume`, with the payload field that carries a captured id) and `skip_flags` (the spellings the launch assertions read); the stub imports the harness (the wrapper names the adapter) and calls the two readers on its own argv, and writes its pid beside its argv, the case seeing its exit by the pid's end where it writes no end line; Gemini CLI's `stub_setup` writes a scratch machine layer naming the hook command and patches the adapter's `MACHINE_LAYER` and `_lstat` to it (as `tests/test_gemini_adapter.py` does); Claude Code's does nothing to its layer; all put the suite's own `shiftlead-hook` on the pane's `PATH`; Grok Build's harness is TD-1637's, which lands after this build (§4.3 *A seat's life end to end*: its hook file read from the scratch `GROK_HOME`, its session id `-s` or adopted from the start payload). This build adds to the declaration check that every agent adapter's constructor takes `binary` (§4.3's Protocol block names it); TD-1648 adds the `default_home()` check, neither waiting on the other.
- A `life` key in each adapter's `tests/conformance/fixtures/<adapter>/manifest.json`: `start` (one index), `turn` (a list of indices, with no permission or notification payload among them), `end` (one index) and `composer` (one entry of the manifest's `panes` whose expected `composer` is empty, captured or written; Claude Code's captures hold no idle composer pane); the payloads from captured fixtures only; `end` empty where the captures hold no end hook (Gemini CLI's), the stub then only exiting.
- `tests/conformance/test_seat_life.py`, parametrized over `agent_adapters()`: the adapter registered built with `binary` set to the wrapper, `stub_setup` run, on the suite's private tmux socket and scratch home; launch assertions (unattended under `skip`: the profile's `unattended_args`, else the adapter's; under `all`: no skip flag (`--dangerously-skip-permissions`; each of `--approval-mode yolo`, `--approval-mode=yolo`, `--yolo`, `-y`, as `_without_yolo` drops them), the profile's other `unattended_args` passing through (run with a profile holding one other argument, and with one declaring none, whose adapter default is dropped), and the adapter's `asking_args`; the id or resume; the layer names the hook command); an unattended seat with the stub brief, asked as the person (`ao msg --kind ask` from the scratch home, `SHIFTLEAD_SESSION` and every other session variable removed from the send's environment as the walk removes them) with a nonce; states by hook (`idle`, then `working`/`idle` per turn, never `needs-you`); the nonce on the ask's thread in the scratch home's person inbox; once the case closes the seat with the host agent's close, the stub's line that it played the end payload where `life` names one, and always the stub's exit and the record `closed`. An adapter with no `life` fails, never skips.

**Done when:** `test_seat_life.py` passes in CI (`pdm run test`) for every registered agent adapter on its captured fixtures (Claude Code and Gemini CLI when this lands; Grok Build's, TD-1637, adds its `life` and harness in its own PR), with no model, no network and no `/etc/shiftlead/` layer, and a registered agent adapter whose manifest names no `life` fails it.
