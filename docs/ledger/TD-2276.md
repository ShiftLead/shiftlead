## TD-2276: A restart on the home machine forgets which built-in seats another machine cannot run

**Priority:** Low
**Type:** debt
**Added:** 2026-11-26
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 607fe825ed5c48f8b4b3395be5a7932b

**Why:** Found by the fact-check of the docs audit of #4760 (TD-2068 slice 12). Design §5 puts "each set's `node_cannot_run`" on the home's `host` record, beside the teams, and §4.9d *Where a seat's session launches* says the mark is "read only while the set's list and the seat's model are the ones it names" and that the home sends no launch of that seat to that node while it stands.

`HostStore.load` (`src/sessionorc/store.py`) rebuilds the record from the keys it names, and `builtins`, which `rpc_builtins_node_cannot` writes, is not one (`teams` is, so a team's mark survives). The host agent loads the record once at start, so the next save writes the file without the marks.

Probe at 22675a930: `HostStore.save` of `{"teams": {...}, "builtins": {"default": {"node_cannot_run": {"sweeper": {"node1": {...}}}}}}`, then `load()`: the answer has no `builtins` key; setting `last_tick` on it and saving leaves `teams` and `last_tick` alone in the file.

So each restart of the home's host agent, a promote's included, forgets every set's mark: the node is asked again and refuses again, and until then `ao builtins show --json` shows no mark. `builtins` is the one key the source reads or writes on that record that `load` drops.

**Location:** src/sessionorc/store.py HostStore.load

**Fix:** Keep `builtins` in `HostStore.load`, shape-checked as the keys beside it are, and name it in the class's docstring.

**Done when:** A test saves a set's node mark, loads the record with a new `HostStore`, saves it again and reads the mark both times.
