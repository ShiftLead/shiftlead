**Why:** TD-1573's design (§4.4 *An entry no lane takes is marked*): an open entry of a kind a lane word takes that no lane of its repo's teams takes is counted under its kind and named nowhere (ledgerboard TD-058: `Kind: design-first`, `Owner: techlead`, drawn *1 design* while Start read *designer: 0*). This build is the home's half: the test, the mark, and the once-only note to the session the id was given to.

**Fix:** As design §4.4 *An entry no lane takes is marked* says:
- **`ledger.lane_gap(entry, lanes) -> str | None`** in `src/sessionorc/ledger.py`, `lanes` a list of `(lane words, team)`: None where some lane takes the entry, else the `why` words in the design's order (the team, then the kind word — naming the team for a tagged entry — then the owner words). It tests only an entry whose `for_page` is `design` or `live-check` — or `pickable` whose `team` names a team no record of the repo carries — whose `Owner:` is not `PERSON_OWNER`, not marked `needs_team`, and which reads `pickable: yes` once `_unwaited` and a dropped `settling` mark have read it — so a pickable entry, the person's, and one held by a decision, an open id or an open part are never marked.
- **The mark step** on the host agent's instance (`src/sessionorc/agent_tick.py`), on the event loop, on every reading it stores — `_refresh_repos` (before its `changed` compare, ~4183) and `_reread_board` (`agent_inbox.py`, a press's re-read) — after the settle pass the reader thread ran: drop any `no_lane` the reading carries; take the repo's lanes from every record carrying a lane — live or ended, `repo` the checkout, never `superseded_by`, teamless ones included (the selection `shiftlead.teamrun.in_repo` makes, written in `sessionorc`); mark `no_lane: {why}`; move each marked entry out of its kind in the ledger reading's `by_kind` into `no_lane`; set the ledger reading's `no_lane: [{id, why}]` beside `needs_team`. Nothing on an unserved repo or one no record carries a lane for. `entries_before`'s readings are not marked. `in_lanes` is unchanged.
- **The Queue** (`src/sessionorc/queue.py`): `_status`'s all-members test and `_wait`'s `far()` also read the `no_lane` mark.
- **The note**: `no_lane_noted.json` beside `ids.json`, keyed by origin, per repo `{from, marked: {id: since (UTC ISO wall time)}, ids: [..]}`, written on the event loop; a reading with `error` changes nothing in it. A repo with no key: the first pass that reads a lane writes it, records every marked id in `marked` and `ids`, sends nothing. After that, each pass updates `marked` (an id whose mark lapsed leaves it) and, for an id marked for `NO_LANE_NOTE_AFTER` (30 minutes) and not in `ids`, where `ids.json`'s `given` (`agent_ids.py`) holds it with a `by` that resolves to a record the home holds (the record id `td_next` wrote, `<id>@<host>` from a node; not the person; ended is fine), sends that record a `system` note in the design's template (`<id>`, `<repo>`, `<why>`), and records the id in `ids` whether a note went or not; `ids` pruned to the ids the reading holds open.
- **Tests**: ledgerboard TD-058's case — a `design-first` entry with `Owner: techlead`, a repo whose one team's records carry `[design-first, owner:designer]` and `[free-pick, owner:grinder]` — is marked with *Owner techlead: the lanes that take design-first take owner:designer* and counted in `by_kind`'s `no_lane`, not `design`; a pickable `Owner: paul` build (untagged), a design-first `Owner: paul` entry, a settling and a waiting entry a lane would take once settled, and a live check blocked by a decision are not marked; a team-tagged entry of a team with no record, and a kind no lane takes, give their own words; a pickable entry tagged with a team no record carries is marked; a mark is dropped at the next pass once a record's lane takes it; an unchanged mark does not change the stored reading; the note is sent once, to the taker, only after 30 minutes of mark, and not on a repo's first pass.

**Done when:** The home's reading marks an entry no lane of its repo's teams takes with `no_lane: {why}`, naming the field that keeps it out; `by_kind` counts it under `no_lane`; the Queue reads it as no lane takes it; the session its id was given to gets one `system` note; the tests above pass.
