## TD-2103: Sweep detached worktrees that have fully landed

**Kind:** design-first
**Status:** Open

**Blocked by:** decision (paul)
**Part of:** TD-2080

**Why:** Part of TD-2080: `worktreesweep.weigh` returns `detached` before its age and landed checks, so a detached worktree is kept forever. Read on 2026-11-23: 24 clean detached worktrees whose HEAD is already in `origin/main`, about 3.4 GB across shiftlead, samscrape, agent-cadence and contractmatch.

**Ask:** Should the grinders build the design that lets the disk sweep remove old detached worktrees?

**Context:** The hourly disk sweep keeps every worktree that is not on a branch, however old. This design removes one once it is old, clean, already in the default branch and no session's record points at it, which frees about 360 MB today. A removal cannot be undone, so it comes to you. The independent judge raised it because one fix to the plain-words summary needed a second correction; every fix that changes the build has been read by a review.

**Design PR:** #4411

**Location:** src/sessionorc/worktreesweep.py, design §4.6 *The disk sweep*

**Fix:** Design the rule first, since it changes what the sweep deletes: a detached worktree goes through the same age filter and `worktree_holds`, with *landed* meaning its HEAD is an ancestor of the default branch on origin. Settle how a seat's idle home worktree (such as `grinder-ao-1`, detached between tasks) is protected while its seat exists.

**Done when:** A detached worktree that is old, clean, landed, with no operation in progress, no commit only in its reflog, a `HEAD` that did not move during the pass, and held by no session's record, is removed. One failing any of those is kept while the reason stands, and `ao disk` says why.
