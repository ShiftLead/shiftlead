## TD-1831: Build TD-1829: the person's answer to a gated entry lifts its decision (paul) on the press, and Lift the hold writes no work order

**Why:** TD-1829's design (§4.4 *Board write-back*: *The person's answer to a gated entry lifts on the press*): **Lift the hold** wrote a `go ahead` work order whose session had to drop `decision (paul)`, and the pinned `ledger.py set` refuses that to every session but the person's own. So the press now lifts the gate itself, through ledgerboard's `plan_lift`, in the commit its write lands. Any other answer to a gated entry lifts the same way, and its line stays the work order for the words.

**Location:** src/sessionorc/board.py (the lift write); src/sessionorc/agent_inbox.py rpc_ledger_decide; src/shiftlead/ui/templates/inbox_row.html; tests/

**Fix:** 1. **The write** (`src/sessionorc/board.py`): one write-back that lands, in one commit of the host agent's tree on origin's head, the lift and its board half. It reads the entry from the tree's ledger and, where it carries `decision (<p>)`, runs `covers()` for that gate on the tree's board, then picks a case (§4.4 *Board write-back*) from `covers()` given the entry's own repo's board alone. With several covering items, the cases apply in this order: (d) refuse, then (b) close every such decided item, then (c), then (a). The cases:
   - (a) nothing covers: `ledgerboard.ledger.plan_lift(led, id, gate, by, answer=words, suffix="no board item")`;
   - (b) an open, decided item covers it and lists no other gated entry: where a live record other than the person's own holds its `board:<key>` by an unexpired claim, `Refused("board:<key> is being acted on by <holder>: …")`; else the same lift with no suffix, plus `lb_board.plan_edit` `done` on that item, why `lifted`, so its `Closed:` ends `— lifted.`;
   - (c) an open item covers it and lists another gated entry: the lift with suffix `shared board item left open`;
   - (d) an open, undecided item covers it and lists no other gated entry: `Refused("TD-n's hold is asked on board:<key>: answer it there")`, nothing written.

   *Lists another gated entry* is the item's `Context:` entry or a bare `Parts:` id, open in the tree's ledger, not the pressed entry, carrying the same gate (a `<repo>#TD-n` not counted, as the tripwire's shared case). `by` is `lb_board.who_answered(board_text, answerer(root, board_text))`; refuse *only <p> lifts <p>'s hold* where it is not the gate's `<p>`; pass no `people` or `answered_by`. **Lift the hold** (`go ahead`) writes the lift alone. Any other answer also writes `add_decided`'s line in the same commit. An answer ledgerboard reads as waiting-only writes the line alone, with no lift. An entry with no gate writes the line alone, as today. ledgerboard's `Refused` is the press's refusal, in its words.
2. **The press** (`src/sessionorc/agent_inbox.py` `rpc_ledger_decide`): it calls the write above in place of `add_decided`. It stays `person_only` with no road, so no session passes. It takes a new `lift: bool`, which only **Lift the hold**'s buttons send (`app.js` sets it from a `data-lift` on them; their `words` stay *go ahead*); the same words in **Reply** are an answer. It skips both the `for_page == "for-you"` lookup's refusal and the `_decided_covers` refusal for `lift=True` alone, needing only an open entry carrying `decision (<p>)` in the reading. It refuses `lift=True` beside a `road`, `answer` or `go`. It makes case (b)'s held-claim test on the loop, from the records, and hands the write the `board:<key>`s held. The write returns `{lifted: true}`, or `{gone: true}` with nothing written where the tree's entry no longer carries the gate (the press then says *TD-n is no longer held*); every other answer keeps it. Its return says `lifted` where it lifted, so the page's toast reads *hold lifted on TD-n* rather than *decided*.
3. **The page** (`src/shiftlead/ui/templates/inbox_row.html`, `src/shiftlead/ui/static/app.js`): the **Lift the hold** buttons' titles say the press lifts the hold on TD-n, never *written on <repo>'s board as…*. The toast and the leave-on-press follow §4.5 screen 6 rule 4: the row leaves on the press, and no *answered — waiting on a pick* word is drawn for it. Also change the buttons' `data-confirm` texts and `rpc_ledger_decide`'s docstring (*The ledger itself is never written*), which say otherwise (`git grep 'go ahead' -- src/shiftlead/ui/templates`).
4. **Tests**: update those that hold the old press, among them `tests/test_ui_answered_hold.py`, `tests/test_queue_answers_in_place.py`, `tests/test_queue_card_verbs.py` and `tests/test_board.py` (`git grep -l "go ahead\|Lift the hold" tests` lists the rest). Add a board test on a scratch repo and its bare origin for each of the four cases, plus an ungated entry and a waiting-only answer. Each asserts the entry's Blocked by and Log, the board file, and that ledgerboard's `tripwire(base_tree, head_tree, subject, repo)` returns `[]` for the landed commit. Also an agent test that a session caller is refused, and one that Lift the hold passes where an open decided line covers the entry.
5. History: a `## §4.4` line in `docs/history/TD-<this>.md` once built. TD-1829 archives with its last build, TD-1833 (design §4.9c), not here.
