## TD-1831: Build TD-1829: the person's answer to a gated entry lifts its decision (paul) on the press, and Lift the hold writes no work order

**Type:** debt

**Kind:** build

**Part of:** TD-1829

**Why:** TD-1829's design (§4.4 *Board write-back*: *The person's answer to a gated entry lifts on the press*): **Lift the hold** wrote a `go ahead` work order whose session had to drop `decision (paul)`, and the pinned `ledger.py set` refuses that to every session but the person's own. So the press now lifts the gate itself, through ledgerboard's `plan_lift`, in the commit its write lands. Any other answer to a gated entry lifts the same way, and its line stays the work order for the words.

**Location:** src/sessionorc/board.py (the lift write); src/sessionorc/agent_inbox.py rpc_ledger_decide; src/shiftlead/ui/templates/inbox_row.html; tests/

**Fix:** 1. **The write** (`src/sessionorc/board.py`): one write-back that lands, in one commit of the host agent's tree on origin's head, the lift and its board half. It reads the entry from the tree's ledger and, where it carries `decision (<p>)`, runs `covers()` for that gate on the tree's board, then picks a case (§4.4 *Board write-back*):
   - nothing covers: `ledgerboard.ledger.plan_lift(led, id, gate, by, answer=words, suffix="no board item")`;
   - an open, decided item covers it and lists no other gated entry: the same lift with no suffix, plus `lb_board.plan_edit` `done` on that item, why `lifted`, so its `Closed:` ends `— lifted.`;
   - an open item covers it and lists another gated entry: the lift with suffix `shared board item left open`;
   - an open, undecided item covers it and lists no other gated entry: `Refused("TD-n's hold is asked on board:<key>: answer it there")`, nothing written.

   `by` is `answerer()`'s; pass `people` and `answered_by="any"` only where the board says `Answered by: any`. **Lift the hold** (`go ahead`) writes the lift alone. Any other answer also writes `add_decided`'s line in the same commit. An answer ledgerboard reads as waiting-only writes the line alone, with no lift. An entry with no gate writes the line alone, as today. ledgerboard's `Refused` is the press's refusal, in its words.
2. **The press** (`src/sessionorc/agent_inbox.py` `rpc_ledger_decide`): it calls the write above in place of `add_decided`. It stays `person_only` with no road, so no session passes. It skips the `_decided_covers` refusal for **Lift the hold** alone; every other answer keeps it. Its return says `lifted` where it lifted, so the page's toast reads *hold lifted on TD-n* rather than *decided*.
3. **The page** (`src/shiftlead/ui/templates/inbox_row.html`, `src/shiftlead/ui/static/app.js`): the **Lift the hold** buttons' titles say the press lifts the hold on TD-n, never *written on <repo>'s board as…*. The toast and the leave-on-press follow §4.5 screen 6 rule 4: the row leaves on the press, and no *answered — waiting on a pick* word is drawn for it.
4. **Tests**: a board test on a scratch repo and its bare origin for each of the four cases, plus an ungated entry and a waiting-only answer. Each asserts the entry's Blocked by and Log, the board file, and that ledgerboard's `tripwire(base_tree, head_tree, subject, repo)` returns `[]` for the landed commit. Also an agent test that a session caller is refused, and one that Lift the hold passes where an open decided line covers the entry.
5. **After it is live**: TD-1829's Fix asks that TD-1796's `decision (paul)` go and that TD-1796 become `Owner: paul` (its last step is the issue form's by-hand check). Write `ledger.py set TD-1796 --owner paul` in this PR. Then write an `act` line asking the person to press **Lift the hold** on TD-1796 once this build is promoted, ending *only you can do this*.
6. History: a `## §4.4` line in `docs/history/TD-<this>.md` once built. Archive TD-1829 with this build, in its PR (design §4.9c), with a `Resolved:` line.
