## TD-1748: A Claude Code turn ended on a rate limit, an overload or a server error still reads working: StopFailure's other codes change no state

**Priority:** Low
**Type:** debt
**Added:** 2026-11-13
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 0be73547a5ec4726be69d2260f40a871

**Why:** A Claude Code turn that ends on an API error fires `StopFailure`, never `Stop` (checked in Claude Code 2.1.323's hook schema: `error` one of `authentication_failed`, `oauth_org_not_allowed`, `account_on_hold`, `verification_required`, `billing_error`, `rate_limit`, `overloaded`, `invalid_request`, `model_not_found`, `server_error`, `unknown`, `max_output_tokens`, `cloud_credential_error`). TD-1747 made the account's codes read `needs-you`; every other code still changes no state, so a turn that ended on an overload, a server error, a bad model id or a rate limit leaves the record reading the `working` its `UserPromptSubmit` left, until the stall window reads it `stalled?` (twenty minutes), never rung though the composer waits. Found while building TD-1747.

**Location:** src/shiftlead/adapters/claude_code/hook.py; design §4.2

**Fix:** Decide in design §4.2's state table what each remaining `StopFailure` code reads: the turn has ended and the composer waits, so `idle` is the plain reading for `overloaded`, `server_error`, `invalid_request`, `model_not_found`, `max_output_tokens` and `unknown` — but a session rung at once after a failed turn may fail again, and `rate_limit` is a cap, whose reading (`limited` with a reset, as the usage poll and the `usage-limit` screen rule give it, or `idle` left to the poll) must not ring a session into the cap (§6 *Usage*). Then map them in `src/shiftlead/adapters/claude_code/hook.py`'s `_stop_failure`, with a test per row.

**Done when:** Every `StopFailure` code reads a state §4.2's table names, no turn ended on an API error reads `working`, and a rate-limited one is never rung into its cap. A test holds each row.
