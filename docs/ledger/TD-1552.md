## TD-1552: A board line whose Context names only a PR draws on that PR's entry's card

**Priority:** Low
**Type:** debt
**Added:** 2026-11-07
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** cfbe5813a94b498f856ea269b7217f24
**Part of:** TD-1538
**Location:** src/shiftlead/ui/queue.py (item_home); src/sessionorc/queue.py (only_pr, pr_card); design §4.5 screen 6 Every item that needs the person draws on a card

**Why:** Design §4.5 screen 6 *Every item that needs the person draws on a card* now says that a board line whose `Context:` names no entry but names a PR (`PR #n` or a bare `#n`, as the board's own Format line writes it) ties by that PR as a mail item's PR does (TD-1538). Today `item_home` reads a board line's `Context:` for entries alone, so such a line that needs the person stays in the Inbox, and TD-1468's Done when asked for a board line tied by its PR that nothing could read.

**Fix:** In `src/shiftlead/ui/queue.py` `item_home`, the board branch: where the line's `Context:` (as `CONTEXT` cuts it) names no entry (`named` empty) and names a PR, read that PR with the line's `repo_name` through `pr_entry` (src/sessionorc/queue.py), whatever `needs` is: where the entry it names is in `index` (an open card), the line draws on that card, `tied: {by: "pr", ref: <the entry>}` — so a line not yet due (the card attachment's `coming` road, which calls `item_home` with no `needs`) follows the PR's entry to its open card as a line naming that entry does; only where the line needs the person (`needs`) does it take `pr_card`'s rest, the entry's kept card (`kept_or_loose`) or the PR's own loose card `loose:<repo>#<n>`, as the mail branch does with `only_pr`. A line with no `repo_name` stays in the Inbox.

The PR is the `Context:`'s first match of `(?<![\w./-])#(\d+)\b` (`PR #3142`, `#3142` and `(#3142)` read 3142; `agent-cadence#164`, `owner/name#12`, `a.b#3` and `TD-12` read nothing). A helper beside `only_pr` in `src/sessionorc/queue.py` (say `context_pr(text)`) reads the number, so the board's reader and any later caller read it alike.

The line is tied, never named: `line_names`, `covered_by` and `asked_entries` keep reading entries alone, so a PR-tied line covers no ledger row, and §4.4's `carried` (closed `decide` lines whose `Context:` names an entry) never reads it. A `Context:` that names an entry keeps today's road (its PRs are words, never a second anchor). The design link (§4.5 screen 6 *An item about a design links the design's PR*, `design_link`) draws nothing for a PR-only line, as for an `about: #n`. A board line never closes `merged`: it leaves the card by its own Done or decide, as today. `needs_person` already excludes decided, `watch` and `fyi` lines; no change there.

**Done when:** Tests in `tests/test_queue_kept_loose.py` (beside TD-1468's PR-only tests): an undecided `decide` line on a repo's board whose `Context:` is `PR #164` draws on the open card of the entry #164's title names (`tied.by: pr`); with #164 found only in `recent`, the same by its title; with the entry #164 names archived and on a completed card, on that card, kept; with #164 naming no entry, on `loose:<repo>#164`, counted on the Queue tab; the same line with `Context: #164` alike; a line not yet due (`coming`, `needs` false) whose `Context:` is `PR #164` moves to the open card of #164's entry, and stays in the Inbox where #164's entry is on no open card (no kept or loose card); a line with no `repo_name` stays in the Inbox; a line whose `Context:` is `TD-9 / PR #164` ties by TD-9 as today; `Context: agent-cadence#164` names no PR and stays in the Inbox; a PR-tied line covers no ledger row (TD-9's own held row still draws its answers); a closed (decided) PR-only line stays where it is drawn today; a PR-only `watch` or `fyi` line stays in the Inbox; a PR-only line draws no *· design #n*. The Queue tab and the Inbox tab still add up to what waits on the person.
