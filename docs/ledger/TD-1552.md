## TD-1552: A board line whose Context names only a PR draws on that PR's entry's card

**Priority:** Low
**Type:** debt
**Added:** 2026-11-07
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** cfbe5813a94b498f856ea269b7217f24
**Part of:** TD-1538
**Location:** src/shiftlead/ui/queue.py (item_home); src/sessionorc/queue.py (only_pr, pr_card); design §4.5 screen 6 Every item that needs the person draws on a card

**Why:** Design §4.5 screen 6 *Every item that needs the person draws on a card* now says that a board line whose `Context:` names no entry but names a PR (`PR #n` or a bare `#n`, as the board's own Format line writes it) ties by that PR as a mail item's PR does (TD-1538). Today `item_home` reads a board line's `Context:` for entries alone, so such a line that needs the person stays in the Inbox, and TD-1468's Done when asked for a board line tied by its PR that nothing could read.

**Fix:** In `src/shiftlead/ui/queue.py` `item_home`, the board branch: where the line's `Context:` (as `CONTEXT` cuts it) names no entry (`named` empty) and names a PR, read that PR with the line's `repo_name` through `pr_entry` (src/sessionorc/queue.py) and let the entry it names stand in for an entry the `Context:` would name, whatever `needs` is: where that entry is in `index` (an open card), the line draws on that card, `tied: {by: "pr", ref: <the entry>}` — so a line not yet due (the card attachment's `coming` road, `queue.py` ~311, `needs` false), a decided line and a `watch` or `fyi` line (`inbox.py` ~2279, `needs` false) follow it as lines naming that entry do today. Only where the line needs the person (`needs`) does it take `pr_card`'s rest: the entry's kept card or its loose card `loose:<repo>#TD-n` (`kept_or_loose([entry])`, `tied.ref` the entry), or, where the PR names no entry, the PR's own loose card `loose:<repo>#<n>` (`tied.ref` `<repo>#<n>`). Set `by = "pr"` in the board branch itself (today's `by = "pr"` sits in the mail-only `not kind` branch) and keep the closing `kind != "board" and by != "pr"` guard, so the board's `by` is never rewritten to `about`/`words`. A line with no `repo_name` stays in the Inbox.

The PR is the `Context:`'s first match of `(?<![\w./-])#(\d+)\b` (`PR #3142`, `#3142` and `(#3142)` read 3142; `agent-cadence#164`, `owner/name#12`, `a.b#3`, `PR#164` (no space, as the board's format never writes it) and `TD-12` read nothing). A helper beside `only_pr` in `src/sessionorc/queue.py` (say `context_pr(text)`) reads the number, so the board's reader and any later caller read it alike.

The line is tied, never named: `line_names`, `covered_by` and `asked_entries` keep reading entries alone, so a `Context:`'s PR covers no ledger row (a line's `Parts:` still covers its ids as today), and §4.4's `carried` (closed `decide` lines whose `Context:` names an entry) never reads it. A `Context:` that names an entry keeps today's road (its PRs are words, never a second anchor). The design link (§4.5 screen 6 *An item about a design links the design's PR*, `design_link`) draws nothing for a PR-only line, as for an `about: #n`. A board line never closes `merged`: it leaves the card by its own Done or decide, as today. `needs_person` already excludes decided, `watch` and `fyi` lines; no change there. `design_link` already returns nothing for a `Context:` with no entry ref; no change there either.
