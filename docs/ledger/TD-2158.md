## TD-2158: Each stage a session ends records its model, tool, login, spend and the flow's version, and a lost offer leaves a row

**Priority:** Medium
**Type:** feature
**Added:** 2026-11-24
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** e4f0ddc027854ca48fea4addbc94bcbc
**Blocked by:** decision (paul)
**Part of:** TD-2077

**Why:** Part of TD-2077 (design §4.9c *What a run records, for comparing flows*). A comparison of flows needs each stage's model, tool, version, login and spend, and a flow's version, kept on the entry's stage record; today the session record that holds them is forgotten a day after it closes, the record has no flow version, and a lost offer leaves no row.

**Ask:** Should the grinders build the design that records what each flow's run leaves behind, or run one more review round first?

**Location:** src/shiftlead/stage_end.py, src/shiftlead/stage_make.py, src/sessionorc/agent_mail.py, design §4.9c

**Fix:** Write `run` as §4.9c *What a run records, for comparing flows* lists it on every history row that ends a holder: an accepted `ao stage end`'s row (`src/shiftlead/stage_end.py`), and each write of the home's that clears a holder, attached in one place, where `stage_make.make` ends the held holder: the *offer again* act's `lost` row (`{from: <stage>, to: <stage>, outcome: "lost", by: "home", reason: <the act's case>, run, at}`, its case `lost`, `silent`, `stopped` or `to-person`, written before it clears the holder or asks the person), and for a reconcile case that clears one (`close`, `wait-for-parts`, `re-enter`, `team-moved`, and those that go to the person), the row that write makes, or an `ended` row (`{from: <stage>, to: <stage>, outcome: "ended", by: "home", reason: <its case>, run, at}`) where it makes none; `rewrite-flow` and `renumbered` keep or move the holder and write no `run`, and the person's answer carries none where the question cleared the holder, but where the record was only marked waiting with its holder kept (`_mark_waiting`), `_answer` is the write that clears it and its `answer` row carries that holder's `run`. `run` holds `session`, `team`, `flow`, `model`, `tool`, `tool_version`, `login`, `login_moves` (`null` until TD-2068 and TD-2069 put them on the session record), `started` (the session record's `created`), `ended`, `models` (per model the tokens by kind, `turns`, `figure` and `unweighed`, summed from `seat_spend.json`'s rows for that record over every day), `asks`, `flow_hash`; read from the session record, for a node's session the home's mirror of it; `null` for a field it does not hold, and all but `session` `null` where the record is forgotten. `_ask` writes `{from: <stage>, to: "person", outcome: "ask", by: "home", reason: <its case>, at}`, with the cleared holder's `run` where it cleared one, in the same commit as the question's intent (its `put_entry` or `record_intent` write) for the second loss, a pull request closed, an entry merged and left open, a stage gone, and an answer naming a stage that has left the flow, and none for a gate asked again or for an entry that already carries the home's gate (marked waiting, nothing asked), which writes an `ended` row with the `run` where it cleared a holder. A move a limit or the cap stops (`_apply` in `stage_end.py`) writes its `blocked` (`{to, count}`, with `cap: true` where the cap stopped it) on its row as well as on the record. `_came` reads the history without its `lost`, `ended` and `ask` rows, and `ao stage end`'s repeat check (`stage_end.py`, today `history[-1]`) reads the last row whose `by` is not `home`, and answers a repeat with where the entry is now (the record's stage or wait). Count `person_asks`, a home-owned session record field, in the home's message handler (`rpc_msg`, `src/sessionorc/agent_mail.py`) as each ask or steer to the person lands. At each offer write `flow_hash` on the record (the SHA-256 of the canonical JSON text §4.9c gives: the flow copy's text and each stage's resolved brief with its package and version, sorted keys, no spaces, UTF-8), rows copying it; at the first offer under a new hash write that text to `flows/versions/<hash>.json` in the offer's commit. No act reads any of it; an audit's run writes none of it.

**Done when:** Tests show every `run` field on an accepted stage end's row, on each of the offer-again act's four `lost` rows, on a reconcile case's row (none on the person's answer row where the question cleared the holder, and the holder's `run` on it where `_mark_waiting` kept one), and on an `ended` row where a write clears a holder with no row of its own (`team-moved` among them, with no `ask` row), none on a `rewrite-flow` or a renumber (a missing field `null`, a forgotten record's all `null` but `session`); `run.models` equal to the session's `seat_spend.json` sums at that moment; `run.team` and `run.flow` kept after the record's own are rewritten; a blocked move's row carrying its `blocked` after an answer clears the record's; an `ask` row, with the cleared holder's `run` where there was one, for each listed home question in the commit of its intent, none for a gate asked again, a gate already carried writing an `ended` row where it cleared a holder and none beside a session's own move to the person; what a fresh session is told, and a repeated stage end's answer, unchanged by `lost`, `ended` and `ask` rows; a retry after a home row (the merge gate's refusal, a re-entry) matched and answered with where the entry is now; a retry after another session's row or the person's `answer` row still refused; `person_asks` counted on a send to the person and not on any other; a flow replaced mid-stage leaving the offered hash on the row; two flow copies differing by one brief hashing apart and each hash's text written once under `flows/versions/`; and no act's choice changing with these present or absent.
