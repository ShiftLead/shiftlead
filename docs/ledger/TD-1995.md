## TD-1995: The New session form refuses a typed prompt while the layer listing fails, though it sends no brief

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-19
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 63b19f75d12b4a98b33f66eee7bfb623
**Blocked by:** decision (paul)
**Part of:** TD-1962

**Why:** The New session form reads the person's layers for any role with a template or a definition, even when its prompt box is filled, whose composed brief is then never sent (`ui/app.py`, the New session handler: `form_person` before `text = prompt.strip() or brief`). So while the layer listing fails the form refuses (400) a start that would not have used the layers, unlike `ao new --prompt`, which reads none; and a Start session that landed on the form for a failed listing (its prompt filled) cannot be pressed on with such a role until the listing is mended. Design §4.8 *The person's own additions*, **A listing that fails** (TD-1962) says a typed prompt reads no layer, on the form as on `ao new`.

Until it is built, a Start session that lands on the form for a failed listing cannot be pressed on with a role that has a template (the default `techlead` among them).

**Ask:** The design for what a failed layer listing does to each start ended its review rounds; should the grinders build it?

**Location:** src/shiftlead/ui/app.py (the New session handler); design §4.8 *A listing that fails*

**Fix:** In the New session handler in `src/shiftlead/ui/app.py`, skip `form_person` and `preset.compose` when `prompt.strip()` is non-empty, as `cli._launch_defaults` does for `--prompt`; a whitespace-only prompt counts as empty, and the away-host branch takes the same condition. `resolve_role` and `team_brief_ids` still run, so a bad role or team is still refused 400; `made_from` stays `None` for a typed prompt, as now. With an empty prompt and a role that has a template or a definition, a failed listing is still refused 400 in the listing's words. The member-line form (a team's member submit) is not changed: it reads the team's plan whatever its prompt.

**Done when:** The New session form with a prompt typed starts while the layer listing fails, for any role, and with no prompt and a role that has a template or a definition it is refused 400 in the listing's words, as design §4.8 *A listing that fails* says. Tests beside the New session form's own (tests/test_ui_*.py), with `layers.person` patched to raise `ListingError`, hold: a typed prompt with a templated role starts; an empty prompt with the same role is refused 400 in the listing's words; a role with neither a template nor a definition starts with no prompt typed.
