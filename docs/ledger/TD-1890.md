## TD-1890: A passing test run keeps every test's temporary directory, and three runs fill the shared temporary disk's file slots

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-15
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 98f4bb509610419ebbf99941396437d4

**Why:** kmaster's `/tmp` is a 16G tmpfs with 1,048,576 inodes. pytest keeps its last three runs' `tmp_path` directories (`/tmp/pytest-of-kmaster/pytest-N`, its default `tmp_path_retention_count = 3` and policy `all`), and one `pdm run test` of this suite leaves about 97,000 to 148,000 inodes there. On 2026-11-15 at 10:15 UTC the tmpfs read 100% of its inodes used with 48% of its bytes (`df -i /tmp`: 1,041,455 used), and a judge run (`pdm run judge`) and two full suites failed with `No space left on device` (ERRORs in test_ui_inbox, test_worktree_reap and others). Every session on the machine shares that `/tmp`, so a red precheck or a failed scratch home anywhere can be this and not the PR. Removing the five finished runs' directories (no pytest running) freed about 410,000 inodes.

**Location:** pyproject.toml ([tool.pytest.ini_options]); tests/conftest.py (scratch_dir)

**Fix:** Set `tmp_path_retention_count = 1` in `pyproject.toml`'s `[tool.pytest.ini_options]`, so a run's start removes every earlier run's `pytest-N` and only the newest is kept (at most one run's 97k–148k inodes, against three). Not `tmp_path_retention_policy = "failed"`: it removes a passing test's directory at once, so a later test whose name shares its first 30 characters is given the same path (`…se0` again, not `…se1`), and a module-scoped agent still holding a session there refuses the new one by the anchor rule (`tests/test_ui_inbox.py::test_ao_inbox_counts_from_a_session_with_no_ui_is_refused_in_words` fails under it, every time, and passes without it).

**Done when:** `pyproject.toml` sets `tmp_path_retention_count = 1`, and after a `pdm run test` `/tmp/pytest-of-<user>/` holds one `pytest-N` directory.
