## TD-2283: A built-in seat on another machine that loses its brief is not relaunched after that machine refuses once

**Priority:** Low
**Type:** debt
**Added:** 2026-11-26
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 3a91eaea8a5c4e599048613b587ad8fc

**Why:** Found by the fact-check of the docs audit of #4768 (TD-2068 slice 14). Design §4.9d *How each one runs* says rule 1's replays of a seat on a node "send its launch record's list as names, so the node picks again, and its refusal of that list counts toward no restart ceiling, the set's mark holding the replay as it holds a fill". The docstring of `_lost_brief` says "A replay that failed after its close is retried on the next tick (`_closed_by_tick`)".

A lost-brief replay the node refuses is made once and never again. The tick closes the record, `_replay` returns through `_node_list_refused` with no `restarts` entry, and on every later pass `_closed_by_tick` is False, since it wants a last `restarts` entry of that rule carrying `error`; the record is `closed`, so `_lost_brief` returns at once (`src/sessionorc/agent_tick.py`). The mark's check before the replay returns the same way, with no entry.

Probe at 0cdfc7bb6, with the fixtures of `tests/test_builtin_fill_login.py`: the held tech lead seat on a node, `idle` and marked *no hook since launch*, the node closing it and refusing the `create`. Three passes of `_lost_brief`, for *no login usable* and for *no login offers*: pass 1 sends `close` and `create`; passes 2 and 3 send nothing; `restarts` is empty and `seat_due` None. So the replay with its kept scratch directory and its "why it came" line is dropped, and nothing tells the senders of its open questions. Only rule 3, where the seat comes due, would start it again; the probe did not run that rule.

`test_a_nodes_list_refusal_of_a_replay_is_no_restart` says "a wait is asked again" and passes because it calls `_replay` twice itself.

**Location:** src/sessionorc/agent_tick.py _lost_brief, _closed_by_tick, _replay; docs/design/4.9d-teams.md How each one runs; tests/test_builtin_fill_login.py

**Fix:** Keep a refused or held lost-brief replay retryable: mark the closed record so that `_lost_brief` takes it again on a later pass, still writing no `restarts` entry and counting nothing, and send it once the node answers or the set's mark lifts. A seat that rule 3 fills first must not be started twice. Where rule 3 is meant to take the seat over instead, that is a design change to §4.9d and §4.1 *A launch whose hook never comes is recovered* first, for the tech lead.

**Done when:** A test runs `_lost_brief` itself on a built-in seat on a node whose `create` is refused for its list, and finds the replay sent again on a later pass once the refusal or the mark is gone, with `restarts` unchanged by the refusals.
