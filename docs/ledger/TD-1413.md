## TD-1413: The UI cuts one Queue card from its own view, serves it with the person's mail cut to ids, and says how each attached item found its entry

**Priority:** Medium
**Type:** feature
**Added:** 2026-11-05
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** ee6bcbf973aa4d768f10fb38f203926d
**Part of:** TD-1411
**Location:** src/shiftlead/ui/queue.py (item_home, ledger_home, attach, new card_view); src/shiftlead/ui/app.py (GET /api/queue/card); design §4.7 ao card, §4.5 screen 6 What tied it, §4.4 One owner

**Why:** TD-1411's design (§4.7 *`ao card`*, §4.4 *One owner*, §4.5 screen 6 *What tied it*): a card's attachments are the UI's (`card_mail`, `attach`), so the one card `ao card` prints is cut from the page's own view by one function, served by the UI with the person's mail cut to ids, and every attached item says how its entry was found. This is the UI half; TD-1414 is the command.

**Fix:** As design §4.7 *`ao card`* and §4.5 screen 6 *What tied it* say:

1. **`tied`**: `item_home` (`src/shiftlead/ui/queue.py`) returns `tied: {by, ref}` beside `home`, `on_card`, `on_row` and `mentions`.
   - `by` is where its first held ref (the one that sets `on_card`) was read: `context` for a board line; for mail `about` when the ref came from `about`, else `words` (subject and text, read as one, as today); `pr` for a red PR (branch and title, read as one); `title` for a fork's PR.
   - `ref` is that ref as the index matched it: normalised by `_refs`, and for a board line a bare `TD-n` qualified with the line's `repo_name`.
   - `ledger_home` returns `tied: {by: "entry", ref: "<repo>#TD-n"}`.
   - An `inbox` home has `tied: None`. Nothing on the page draws it.
2. **`attach`'s raw row**: `attach` takes `raw=False`. With `raw=True`, each item also carries:
   - `row`, the Inbox row it was drawn from (`e`, the dict passed to `put`, minus any rendered markup);
   - `tied`, from that row;
   - `repo`, a board line's `repo_name`, else the row's repo.

   The page calls it as today and is unchanged.
3. **`card_view(queue, mail, id, now, fleet, *, words)`** in `src/shiftlead/ui/queue.py` returns `{card, wants, mentioned, mail, at}` for the card that holds `id`, as `card_index` reads `id`.
   - `card` is `queue_view`'s shaped card for it, every key but `lines` and `wants`.
   - `wants` is its `card_wants`, each item keyed by `item` (`item_ref`).
   - `mentioned` is the items that name one of its rows beside their own.
   - It returns None for an id no open card holds. A `<repo>#TD-n` among the reading's `completed` cards' entries returns `{completed: {closed, pr}}`, `pr` possibly None.
   - With `words=False`, each item whose `row` is mail (no `row` kind of `board`, `ledger`, `red_pr` or `fork_pr`) is cut to `{id, kind, from, at}`, `from` being the sender's name, and `mail` is `ids`; else `mail` is `full`.
4. **`Readings.card(id, words)`** in `src/shiftlead/ui/app.py` is the one read behind both roads.
   - `ledger_view`, today a closure in `_inbox_routes` set as `h.ledger_view`, becomes a `Readings` method that the closure's callers use, so `card_mail` runs on a `Readings`.
   - `Readings.card` sets what `queue_page` sets before its reads: `uiconf.set_read` from the `settings` RPC, and `repos_omit(REPOS_OMIT_INBOX)`.
   - It then calls the `queue` and `list` RPCs, then `card_mail(self, fleet, card_index(queue), None, cards)` with `attach`'s `raw=True`, then `card_view(..., words=words)`.
5. **`GET /api/queue/card?id=<id>`** answers `await h.card(id, words=False)` as JSON:
   - 404 `{error}` for an id no open card holds;
   - 200 with `completed` for a completed card;
   - 503 `{agent_down: true}` when the host agent does not answer.

   It never carries a mail's words.

**Done when:** Tests show that:
- `item_home` gives `tied` for each case: a board line's context, mail's `about` and `words`, a red PR's `pr`, a fork's PR's `title`, a bare ref on another repo's board (its `ref` qualified with the line's own repo), and `inbox` with None;
- `ledger_home` gives `entry`;
- `card_view` finds a card by its top entry, a row, an archived row, a bare `TD-n` and an origin path, and answers None and `completed` as above;
- under `words=False` no mail item carries `subject`, `text` or `answers`, while a board line keeps its text, detail and answers;
- `Readings.card` gives the same card the Queue page draws for the same readings;
- the endpoint answers the three statuses;
- the Queue page's and the Inbox's existing tests pass with `ledger_view` moved.
