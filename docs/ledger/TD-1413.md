## TD-1413: The UI cuts one Queue card from its own view, serves it with the person's mail cut to ids, and says how each attached item found its entry

**Type:** feature
**Added:** 2026-11-05
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** ee6bcbf973aa4d768f10fb38f203926d
**Part of:** TD-1411
**Location:** src/shiftlead/ui/queue.py (item_home, ledger_home, attach, new card_view); src/shiftlead/ui/app.py (GET /api/queue/card); design §4.7 ao card, §4.5 screen 6 What tied it, §4.4 One owner

**Why:** TD-1411's design (§4.7 *`ao card`*, §4.4 *One owner*, §4.5 screen 6 *What tied it*): a card's attachments are the UI's (`card_mail`, `attach`), so the one card `ao card` prints is cut from the page's own view by one function, served by the UI with the person's mail cut to ids, and every attached item says how its entry was found. This is the UI half; TD-1414 is the command.

**Fix:** As design §4.7 *`ao card`* and §4.5 screen 6 *What tied it* say:

1. **`tied`**: `item_home` (`src/shiftlead/ui/queue.py`) returns `tied: {by, ref}` beside `home`, `on_card`, `on_row` and `mentions`. `by` is the field its first held ref was read from: `context` for a board line; for mail `about`, else `subject`, else `text`, the first whose refs hold it; `branch` or `title` for a red PR; `title` for a fork's PR. `ref` is the ref as written in that field. `ledger_home` returns `tied: {by: "entry", ref: "<repo>#TD-n"}`. An `inbox` home has `tied: None`. Nothing on the page draws it.
2. **`attach`'s raw row**: `attach` takes `raw=False`. With `raw=True`, each item also carries `row`, the Inbox row it was drawn from (`e`, the dict passed to `put`, minus any rendered markup), `tied` from that row and `repo` (a board line's `repo_name`, else the row's repo). The page calls it as today, so the page is unchanged.
3. **`card_view(queue, mail, id, now, fleet, *, words)`** in `src/shiftlead/ui/queue.py` returns `{card, wants, mentioned, mail, at}` for the card that holds `id`, as `card_index` reads `id`. `card` is `queue_view`'s shaped card for it, minus `lines`; `wants` is its `card_wants`; `mentioned` is the items naming one of its rows beside their own. It returns None for an id no open card holds, and `{completed: {closed, pr}}` for one on a completed card. With `words=False`, each item whose `row` is mail (no `row` kind of `board`, `ledger`, `red_pr` or `fork_pr`) is cut to `{id, kind, from, at}`, `from` the sender's name, and `mail` is `ids`; else `mail` is `full`.
4. **`GET /api/queue/card?id=<id>`** in `src/shiftlead/ui/app.py` runs the same reads as `queue_page` (`queue`, `list`, `card_mail` with no `drawn` and `raw=True`) and answers `card_view(..., words=False)` as JSON: 404 `{error}` for an id no open card holds, 200 with `completed` for a completed card, 503 `{agent_down: true}` when the host agent does not answer. It never carries a mail's words.

**Done when:** Tests show that:
- `item_home` gives `tied` for each case: a board line's context, mail's about, subject and text, a red PR's branch and title, a fork's PR's title, a bare ref on another repo's board (`repo` the line's own), and `inbox` with None;
- `ledger_home` gives `entry`;
- `card_view` finds a card by its top entry, a row, an archived row, a bare `TD-n` and an origin path, and answers None and `completed` as above;
- under `words=False` no mail item carries `subject`, `text` or `answers`, while a board line keeps its text, detail and answers;
- the endpoint answers the three statuses;
- the Queue page renders unchanged (its existing tests pass).
