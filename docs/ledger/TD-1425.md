## TD-1425: The gate sweep's notices PRs ask again what the person answered: a closed-unmerged PR holds nothing, and other dedupe gaps

**Type:** debt

**Owner:** grinder
**Kind:** build

**Id take:** 250b6fb7f2784b5c92397026767f6d1b
**Location:** src/sessionorc/gatesweep.py (`_other_board`, `plan`, `visibility`, `_gh`, `_own_board`); tests/test_gate_sweep.py; design §4.4 *An entry says what it waits for*

**Why:** Asked by the person's session `ao-led-tds-ledger` (m-023567140b8f). The gate sweep asks the person again a question they already answered, when the answered item was closed while its gate still stands. Seen 2026-11-05: Paul's Go on TD-1392 (#2955) closed its decide line *lifted* before the decide lift existed, so `decision (paul)` stayed on TD-1392 and its four builds, and the sweep (#2962) filed five new *Go | Not yet* items for them. An independent review of #2963 (TD-1376 slice 2) reproduced the shape cross-repo against the fake forge. A closed lifting answer neither covers (ledgerboard's `covers()`) nor counts as answered within the window (`_answered_within`, `src/sessionorc/ledgerboard/__init__.py`). `gatesweep.py`'s only dedupe on another repo's board is an open `notices/<repo>-sweep-<date>` PR (`_other_board`). So a notices PR the person closes unmerged is opened again with the same items the next day (the dedupe reads open PRs only; `test_a_closed_or_merged_notices_pr_and_another_repos_sweep_branch_hold_nothing` asserts the merged half). And a decided-Go item closed by hand while the gate stands is filed again. Lower, from the same review:
- a notices PR merged but not yet fetched gives a duplicate (`plan` reads `origin/<default>` unfetched; `_lift` guards its ask-once item with a PR-body search, `_swept_about`);
- `visibility()` reads only `gh repo view`, so a GitLab-hosted board is never written (it fails closed);
- `gh` infers the repo from the directory and may target an upstream remote (pass `--repo`);
- items' words go unescaped into another repo's PR body, so an `@name` notifies;
- `_own_board`'s `opened` is unused.

`sweep()` itself is ledgerboard's, and its half goes to ledgerboard as an entry of its own.

**Fix:** In `src/sessionorc/gatesweep.py`:
- a closed-unmerged notices PR whose body names an item's Context holds that item for the re-ask window (as a closed-unmerged lift PR is never reopened, design §4.4 *The check*, cadence §2.14);
- read the other repo's board after a fetch, or guard with a PR-body search as the lift path does;
- read a GitLab repo's visibility through `glab api` as TD-1388 step 5 does, or say in the run's log that it is skipped;
- pass `--repo <origin path>` to every `gh` call;
- escape `@` in item words copied into another repo's PR body;
- drop `_own_board`'s unused `opened`.

A closed decided lifting answer whose gate still stands should file one act item (*answered Go but not lifted*) instead of a new question. That is `sweep()`'s, in ledgerboard; take it up here once its release is vendored.

**Done when:** Tests against the fake forge:
- a notices PR closed unmerged holds its items for the re-ask window;
- a merged notices PR not yet fetched files no duplicate;
- every `gh` call carries `--repo`;
- an `@name` in an item's words reaches the PR body escaped.
