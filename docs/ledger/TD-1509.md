## TD-1509: A bare TD-n on a red PR, a fork PR or a question is its own repo's, never another repo's card

**Why:** Build TD-1471, slice 3 of 3 (design §4.5 screen 6 *Where a row is drawn*, *A bare ref elsewhere*; §4.4 *The card's status*). A card was matched to another repo's TD-051 (m-2895830be375): a board line's bare `TD-n` is its own repo's since TD-1400, but a red PR's and a fork PR's title or branch, and a question's `about` or words, are looked up bare (`item_home`, `src/shiftlead/ui/queue.py` :76–78; `card_index` adds a bare id where one repo holds it), so a red PR titled TD-051 in repo A draws on repo B's TD-051 card whenever B alone holds it, A's archived or on no card.

**Fix:** - **The asker's repo**: a question's repo is its asker's record's (`MailEntry.from_` looked up in the records the reading carries — live, ended or kept — their `repo` root's last component, as a board line's `repo_name` is), else an orphaned question's `orphaned.repo`, else none. Built once where the rows are built and passed to each reader below.
- **The three readers of a question's ref read it alike** (`queue.mail_card`'s docstring): `item_home`'s mail branch (`src/shiftlead/ui/queue.py`), the Queue's mail hold (`_mail_hold`, `src/sessionorc/queue.py` near :206, which calls `first_ref`), and Telegram's card (`agent_notify._card` → `queue.mail_card`, `src/sessionorc/agent_notify.py` near :68): each qualifies a bare `TD-n` with the asker's repo (`<repo>#TD-n`) where there is one, before the lookup.
- **A red PR's and a fork PR's bare refs** (title, branch; `item_home` near :72–75) are qualified with the row's `repo` (carried, `src/shiftlead/ui/inbox.py` near :775) before the lookup, as a board line's `Context:` is.
- A row with no repo keeps the bare lookup (`card_index`'s one-repo rule). `line_names` and `asked_entries` follow the same rule where they read these rows.
- Tests: two repos, A with TD-051 archived and B with an open TD-051 card: a red PR in A titled *TD-051 …* is not drawn on B's card (it stays in the Inbox); a question about bare TD-051 from a session of A is not on B's card, nor answers B's member (the mail hold), nor names B's card on Telegram; one from a session with no repo, B alone holding it, is.

**Done when:** A bare `TD-n` on a red PR, a fork PR or a question is read as its own repo's entry wherever the row names a repo, so no row draws on another repo's card; tests pin the two-repo case for each.
