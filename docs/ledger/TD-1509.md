## TD-1509: A bare TD-n on a red PR, a fork PR or a question is its own repo's, never another repo's card

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-07
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 1a489cf49d3a45379a9eec9043c7eff3
**Part of:** TD-1471
**Location:** src/shiftlead/ui/queue.py (item_home, line_names, asked_entries); src/sessionorc/queue.py (card_index, the mail link); src/shiftlead/ui/inbox.py; design §4.5 screen 6 Where a row is drawn

**Why:** Build TD-1471, slice 3 of 3 (design §4.5 screen 6 *Where a row is drawn*, *A bare ref elsewhere*; §4.4 *The card's status*). A card was matched to another repo's TD-051 (m-2895830be375): a board line's bare `TD-n` is its own repo's since TD-1400, but a red PR's and a fork PR's title or branch, and a question's `about` or words, are looked up bare (`item_home`, `src/shiftlead/ui/queue.py` :76–78; `card_index` adds a bare id where one repo holds it), so a red PR titled TD-051 in repo A draws on repo B's TD-051 card whenever B alone holds it, A's archived or on no card.

**Fix:** - `item_home` (`src/shiftlead/ui/queue.py`): a red PR's and a fork PR's bare refs (title, branch) are qualified with the row's `repo` (`<repo>#TD-n`, `src/shiftlead/ui/inbox.py` near :775 carries it) before the lookup, as a board line's `Context:` is; a question's (`about`, else words) with its asker's record's repo where the record names one (the record's `repo` root's name, as the board line's `repo_name`). A row with no repo keeps the bare lookup (`card_index`'s one-repo rule).
- The card's status's mail link (`src/sessionorc/queue.py`, *A `decision (paul)` member whose question the person has answered*): a bare first ref is the asker's repo's where its record names one, else the one-open-member rule as now.
- `line_names` and `asked_entries` follow the same rule where they read these rows.
- Tests: two repos, A with TD-051 archived and B with an open TD-051 card: a red PR in A titled *TD-051 …* is not drawn on B's card (it stays in the Inbox); a question about bare TD-051 from a session of A is not on B's card, nor answers B's member; one from a session with no repo, B alone holding it, is.

**Done when:** A bare `TD-n` on a red PR, a fork PR or a question is read as its own repo's entry wherever the row names a repo, so no row draws on another repo's card; tests pin the two-repo case for each.
