## TD-1386: The home's witness log: `witnessed/<month>.jsonl`, its kinds, and the two writers (precheck-fail, press)

**Priority:** Medium
**Type:** feature
**Added:** 2026-11-04 (the designer, from TD-1295's design)
**Owner:** grinder
**Kind:** build
**Status:** Open
**Part of:** TD-1295
**Location:** new `src/sessionorc/witness.py` (`KINDS`, the press words, `append`, `prune`, `WITNESS_KEEP_MONTHS`); `src/sessionorc/paths.py` (`witnessed/`); `src/sessionorc/promote.py` (`precheck_on_main`'s status pass) and `src/sessionorc/reports.py` (the open-PR read, `OPEN_PR_FIELDS`); `src/sessionorc/agent.py` (`rpc_witness_press`), `src/sessionorc/modes.py` (`HOME_EDITS`), `src/sessionorc/mail.py` (`PERSON_ONLY`), `tests/test_person_only.py`; the press sites: `src/shiftlead/teamrun.py` (`apply`, `start`), `src/shiftlead/cli.py` (`ao host rebuild`), `src/shiftlead/ui/app.py` (`new_submit`), `src/sessionorc/agent_inbox.py` (`rpc_inbox_hand`) and `src/sessionorc/agent_notify.py` (`rpc_push_subscribe`) (Send to reviewer and push on, recorded inside the RPC); the tick (`agent_tick.py`, the monthly prune); `agent_common.BACKUP_MEMBERS`; design §4.4 *The home keeps a log of what it witnesses*

**Why:** TD-1295's design: a wait on an event the home sees is answered by a count of what the home witnessed, and the home keeps no such record today — mail is pruned 12 h after it is read, a press leaves only a `log.info` line, and a precheck's failure only a forge status.

**Fix:** as design §4.4 *The home keeps a log of what it witnesses* says: the log (one line a record, `{id, at, kind, repo, text}`, `id` `w-<YYYYMMDDTHHMMSSZ>-<4 hex>`, redrawn in `append` while it collides, filed in the UTC month of `at`, append-only, read sorted by `at`; `witnessed/start` written by the agent at its start when absent, never by an append, nothing dated before it written), one entry point `witness.append` on the agent's loop (a detached writer hands its record over), `KINDS` with each kind's text shape and declared class (both `public`), and the two writers:
- `precheck-fail` (GitHub repos to start): where the home reads a head's `cadence/precheck` (main's in `precheck_on_main`'s pass; an open PR's in the open-PR read) and finds it changed (a new head; the rollup context's state or `startedAt`/`createdAt` moved — first check the status context carries them, and where it does not, re-read a red head's list at each reading), read `commits/<sha>/statuses` (100 a page, every page followed) and record each `failure` or `error` created at or after both `start` and the retention boundary and not yet recorded, `at` the status's `created_at`, `status <id>` in the text, the id matched as a whole token (followed by a space or the text's end) in the month file of its `created_at` (read on demand, cached); `FAILED <id>` node ids only on the status the home's own main run set (matched by `precheck.json`'s sha and the status's `target_url` or time), none otherwise;
- `press` through the new person-only home edit `witness_press {word, target, dir}` (`HOME_EDITS`, `mail.PERSON_ONLY` and the person-only test's list; refused when forwarded from a node by a home-mode check of its own, as `push_subscribe`'s, since `PERSON_NODE_BOUND` reads only an `id`); the record's `repo` mapped at the home by `witness.repo_named(dir)` (the real path matched against the registered roots, the root's basename, else none), each word saying whether it carries a `dir`, one that does with an empty or unmatched `dir` not recorded; sent after success by `teamrun.apply` (when it applied anything) and `teamrun.start` (`start` alone: a Start never goes through `apply`), `dir` the team's `Launch.dir` — so the team card's routes and `ao team flow --apply`/`ao team start` alike — by the New session form's `new_submit` (`new-session`, the form's directory; the plain create and `member_submit`, never a scheduled start), by `ao host rebuild` (no `dir`); and recorded inside the person-only RPC itself for Send to reviewer (`inbox_hand`, `dir` the entry's sender's session record's) and push on (`push_subscribe`, no `dir`, when the endpoint is new and the post names no held `replaces` — `push.subscribe` returns which case it took, or the RPC reads `push.json`'s devices before it); the UI process as the person, the CLI with its own identity, swallowing a refusal; a word not in the table refused.
The prune on the first tick of each UTC month, `WITNESS_KEEP_MONTHS` 13 (the current month and the twelve before); `witnessed/` in `BACKUP_MEMBERS`. A writer's failure is a log line and never fails the act it records. No `msg` kind: it is added with the first wait that needs it.

**Done when:** tests that each writer appends its record with the text shape the design gives (`FAILED` ids on the home's own main run's status only, none on a PR's); that the open-PR read writes a PR's `precheck-fail` as main's pass writes main's; that a head whose status list holds fail, pass, fail writes two records dated by the statuses' `created_at`, a red re-run green between two readings still one, a re-read of an unchanged status none, a status created before `start` on a head first read after it none, a status older than the kept months none, a restart with an open head's status older than two months none twice, and status ids `12` and `123` on one head two records (the token match); that an `error` status counts as red; that `ao team start` and `ao team flow --apply` write `start` and `apply` with the team's repo, as the card's Start and Apply do, the New session form's plain create and `member_submit` write `new-session` and a scheduled start none, `ao host rebuild` writes `host-rebuild` with no repo, Send to reviewer writes `send-to-reviewer` from inside `inbox_hand`, and push on writes `push-on` for a new endpoint and nothing for a renewal naming a held `replaces`; that a press on a directory in no registered repo, or with an empty `dir`, writes nothing, and `repo_named` maps a checkout through a symlink to its registry name; that `witness_press` forwarded from a node is refused; that `witness_press` is refused to a session (the CLI going on) and for an unknown word, and that a failed Apply sends none; that `start` is written at the agent's start, once; that a colliding id is redrawn; that an unreadable line is skipped on read; that a record from a detached writer lands whole beside one from the loop; that a late record goes in its own month's file and reads in `at` order; that the prune keeps thirteen months; that `witnessed/` is in the nightly tarball; that a node host writes no record; and that a writer's failure leaves its act standing.

**Related:** TD-1295 (the design); TD-1387 (the query); TD-1388 (the check); agent-cadence#TD-227 (agent-cadence PR #108, from this design's ask, m-8e4a849462ee): a red `cadence/precheck` description names its failing tests, pytest's `FAILED` node ids or `run_tests.sh`'s `FAILED:` line, ahead of the command; until it reaches shiftlead with an agent-cadence bump, a PR's `precheck-fail` names no test, and after it the writer may take a PR's test names from the description.
