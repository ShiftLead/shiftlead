## TD-1386: The home's witness log: `witnessed/<month>.jsonl`, its kinds, and the three writers (precheck-fail, press, msg)

**Priority:** Medium
**Type:** feature
**Added:** 2026-11-04 (the designer, from TD-1295's design)
**Owner:** grinder
**Kind:** build
**Status:** Open
**Part of:** TD-1295
**Location:** new `src/sessionorc/witness.py` (`KINDS`, the press words, `append`, `prune`, `WITNESS_KEEP_MONTHS`); `src/sessionorc/paths.py` (the `witnessed/` dir); `src/sessionorc/promote.py` (`precheck_on_main`'s pass that sets `precheck_failed`) and `src/sessionorc/reports.py` (the open-PR read, `OPEN_PR_FIELDS`, each row's `failing`); `src/sessionorc/agent.py` (`rpc_witness_press`), `src/sessionorc/modes.py` (`HOME_EDITS`); the press sites: `src/shiftlead/ui/app.py` (the team Apply and Start routes, `api_team_flow_apply`; Send to reviewer), `src/shiftlead/cli.py` (`ao host rebuild`), push on (`push_subscribe`'s caller); `src/sessionorc/agent_mail.py` (`_msg` and `_system_note`); the tick (`agent_tick.py`, the monthly prune); `agent_common.BACKUP_MEMBERS`; design §4.4 *The home keeps a log of what it witnesses*

**Why:** TD-1295's design: a wait on an event the home sees is answered by a count of what the home witnessed, and the home keeps no such record today — mail is pruned 12 h after it is read, a press leaves only a `log.info` line, and a precheck's failure only a forge status.

**Fix:** as design §4.4 *The home keeps a log of what it witnesses* says: the log (one line a record, `{at, kind, repo, text}`, one append-only file per UTC month, written by the agent process alone through one entry point, `witness.append`, on the agent's loop — a detached writer hands its record to the loop — so no two lines interleave; an unreadable line skipped), `KINDS` with each kind's text shape, and the three writers:
- `precheck-fail`: where the home reads a head's `cadence/precheck` status (main's in `precheck_on_main`'s pass; an open PR's in the open-PR read) and finds it changed since its last read, read the head's status list (`commits/<sha>/statuses`) and record each `failure` not yet recorded, keyed by the status id in the text; main's record carries the `FAILED <id>` pytest node ids its log names, a PR's the status description. Ask agent-cadence (its techlead, by `ao msg`) for the failing node ids in `precheck.py`'s description, and name the ask here;
- `press` through the new person-only home edit `witness_press {word, target, repo}` (`HOME_EDITS`, refused to a session caller; the UI process calls it as the person), sent after the act succeeds by each place that composes a press: the team card's Apply and Start routes (a Start that first applies a changed definition sends `apply` then `start`), `ao host rebuild` run by the person, Send to reviewer, push on; a word not in the table refused;
- `msg` in `_msg` and in `_system_note`: the header alone, never the body, `repo` from the sending session's record (empty for a system note), `team` in the text where the entry carries one.
The prune on the first tick of each UTC month, `WITNESS_KEEP_MONTHS` 13; `witnessed/` in `BACKUP_MEMBERS`. A writer's failure is a log line and never fails the act it records.

**Done when:** tests that each writer appends its record with the text shape the design gives (a `FAILED` id carried for main's run, a PR's status description for a PR, a body never carried, a system note recorded through `_system_note`); that a head whose status list holds fail, pass, fail writes two records, a red re-run green between two readings still one, and a re-read of an unchanged status none; that a Start applying a changed definition writes `apply` then `start`; that `witness_press` is refused to a session and for an unknown word and that a failed Apply sends none; that a record from a detached writer lands whole beside one from the loop; that the prune keeps thirteen months; and that a writer's failure leaves its act standing.
