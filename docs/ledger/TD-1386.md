**Why:** TD-1295's design: a wait on an event the home sees is answered by a count of what the home witnessed, and the home keeps no such record today — mail is pruned 12 h after it is read, a press leaves only a `log.info` line, and a precheck's failure only a forge status.

**Location:** new `src/sessionorc/witness.py` (`KINDS`, the press words, `append`, `prune`, `WITNESS_KEEP_MONTHS`); `src/sessionorc/paths.py` (`witnessed/`); `src/sessionorc/promote.py` (`precheck_on_main`'s status pass) and `src/sessionorc/reports.py` (the open-PR read, `OPEN_PR_FIELDS`); `src/sessionorc/agent.py` (`rpc_witness_press`), `src/sessionorc/modes.py` (`HOME_EDITS`), `src/sessionorc/mail.py` (`PERSON_ONLY`), `tests/test_person_only.py`; the press sites: `src/shiftlead/teamrun.py` (`apply`, `start`), `src/shiftlead/cli.py` (`ao host rebuild`), `src/shiftlead/ui/app.py` (`new_submit`), Send to reviewer and push on's callers in `src/shiftlead/ui/app.py`; the tick (`agent_tick.py`, the monthly prune); `agent_common.BACKUP_MEMBERS`; design §4.4 *The home keeps a log of what it witnesses*

**Fix:** as design §4.4 *The home keeps a log of what it witnesses* says: the log (one line a record, `{id, at, kind, repo, text}`, `id` `w-<YYYYMMDDTHHMMSSZ>-<4 hex>`, redrawn in `append` while it collides, filed in the UTC month of `at`, append-only, read sorted by `at`; `witnessed/start` written by the agent at its start when absent, never by an append, nothing dated before it written), one entry point `witness.append` on the agent's loop (a detached writer hands its record over), `KINDS` with each kind's text shape and declared class (both `public`), and the two writers:
- `precheck-fail` (GitHub repos to start): where the home reads a head's `cadence/precheck` (main's in `precheck_on_main`'s pass; an open PR's in the open-PR read) and finds it changed (a new head; the rollup context's state or `startedAt`/`createdAt` moved — first check the status context carries them, and where it does not, re-read a red head's list at each reading), read `commits/<sha>/statuses` (100 a page, every page followed) and record each `failure` or `error` created at or after `start` and not yet recorded, `at` the status's `created_at`, `status <id>` in the text, the id looked up in the month file of its `created_at` (read on demand, cached); `FAILED <id>` node ids only on the status the home's own main run set (matched by `precheck.json`'s sha and the status's `target_url` or time), none otherwise;
- `press` through the new person-only home edit `witness_press {word, target, repo}` (`HOME_EDITS`, `mail.PERSON_ONLY` and the person-only test's list; refused from a node by `PERSON_NODE_BOUND`), sent after success by `teamrun.apply` (when it applied anything) and `teamrun.start` (`start` alone: a Start never goes through `apply`), the team's repo — so the team card's routes and `ao team flow --apply`/`ao team start` alike — by the New session form's `new_submit` (`new-session`, its repo), by `ao host rebuild` and push on (no repo) and Send to reviewer (the entry's sender's repo); the UI process as the person, the CLI with its own identity, swallowing a refusal; a word not in the table refused.
The prune on the first tick of each UTC month, `WITNESS_KEEP_MONTHS` 13 (the current month and the twelve before); `witnessed/` in `BACKUP_MEMBERS`. A writer's failure is a log line and never fails the act it records. No `msg` kind: it is added with the first wait that needs it.

**Done when:** tests that each writer appends its record with the text shape the design gives (`FAILED` ids on the home's own main run's status only, none on a PR's); that a head whose status list holds fail, pass, fail writes two records dated by the statuses' `created_at`, a red re-run green between two readings still one, a re-read of an unchanged status none, a status created before `start` on a head first read after it none, and a restart with an open head's status older than two months none twice; that an `error` status counts as red; that `ao team start` and `ao team flow --apply` write `start` and `apply` with the team's repo, as the card's Start and Apply do, and the New session form's Start writes `new-session`; that `witness_press` is refused to a session (the CLI going on) and for an unknown word, and that a failed Apply sends none; that `start` is written at the agent's start, once; that a record from a detached writer lands whole beside one from the loop; that a late record goes in its own month's file and reads in `at` order; that the prune keeps thirteen months; and that a writer's failure leaves its act standing.

**Related:** TD-1295 (the design); TD-1387 (the query); TD-1388 (the check); the ask that agent-cadence's `precheck.py` put the `FAILED` node ids in its red status's description, carried by the techlead (m-8e4a849462ee), until which a PR's `precheck-fail` names no test.
