## TD-1277: A background subagent stopped with `TaskStop` sends no `SubagentStop`, so Ready to close reads *no subagents running* ✗ on an idle session for good

**Priority:** Medium
**Type:** debt
**Added:** 2026-10-30 (Paul, through Add entry; drafted by ao-shiftlead-techlead-ao-1)
**Owner:** designer
**Kind:** design-first
**Status:** Designed 2026-10-30 (the designer, this PR): §4.2's hook table, the `SubagentStart`, `SubagentStop` row — a `PostToolUse` of `TaskStop`, on either thread, ends the listed subagent it names. Checked on Claude Code 2.1.314: no `SubagentStop` follows a `TaskStop`. Built by TD-1280.
**Location:** `src/shiftlead/adapters/claude_code/hook.py` (the `SubagentStart` / `SubagentStop` branch, :182); `src/sessionorc/agent_tick.py` (`_apply_subagents`, :4991); `src/shiftlead/ui/cards.py` (the *no subagents running* row, :1311, which reads the raw `subagents`); `src/sessionorc/agent_common.py` (`subagents_live`, :1099); design §4.2's hook table (the `SubagentStart`, `SubagentStop` row), *Ready to close* (*No live subagents*) and *Working on its own*

**Why:** Paul saw it on 2026-10-30 on `ao-agent-cadence-sl-tds` (interactive, `idle` since 18:53Z, its turn ended, tree clean, branch pushed): its Ready to close panel read *✗ no subagents running*, so the session could not be closed, though nothing ran. The record carried `subagents: 1`, `subagent_ids: ["a32b5763999b5edfe"]`. That subagent was a background *Fable design review of plan* the session launched on 2026-10-29 and then stopped itself with `TaskStop` at 2026-10-30T04:49Z: its transcript (`…/subagents/agent-a32b5763999b5edfe.jsonl`) ends at 04:49:34Z with *[Request interrupted by user]*, and the main transcript records *Successfully stopped task: a32b5763999b5edfe*. No `SubagentStop` reached the record for it, so the count has stood at one for sixteen hours. §4.2 promises that *a lost `SubagentStop` never draws a session working for good* — and the pill does go back to plain `idle` past `STALL_AFTER` (20 minutes), since `subagents_live` reads `subagent_at` — but Ready to close reads the raw count, which only a `SessionStart` of `startup`, `resume` or `clear`, or the process's exit, resets. So any session that stops a background subagent stays unclosable until it is restarted, and the person is shown a check that is false. The record's `subagent_at` read 19:48:02Z, the moment the session compacted while idle (its transcript's `compact_boundary`), so a compaction moves `subagent_at` too — not checked which hook did it; it also means a stale count can draw an idle session *working* for twenty minutes after a compaction.

**Fix:** a design round on §4.2, then the build. The likely cure is in the adapter: a `PostToolUse` of `TaskStop` on the main thread whose result names a subagent id the record lists is that subagent's end (a `subagent_delta: -1` with its `subagent`, as `SubagentStop` sends). Check first, on a scratch session, whether a current Claude Code fires `SubagentStop` for a stopped background agent at all, and what hook fired at the 19:48Z compaction. Rejected as the whole cure: having the Ready to close row read `subagents_live` — a live background agent can sit silent past `STALL_AFTER`, and Close would kill it. Done is: a session that `TaskStop`s its only background subagent reads *✓ no subagents running* at once, with a test through the hook payloads, and §4.2's table row names `TaskStop`.

**Related:** TD-734 (*Working on its own*, the count and `subagent_at`), TD-960 (a `SubagentStop` for an id no start announced), TD-090 (`SessionStart` of `compact` keeps the count).
