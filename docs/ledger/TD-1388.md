## TD-1388: The event runner answers `check: host-log` from the witness log

**Priority:** Medium
**Type:** feature
**Added:** 2026-11-04 (the designer, from TD-1295's design)
**Owner:** grinder
**Kind:** build
**Status:** Open
**Blocked by:** TD-1387, TD-1376, ledgerboard#TD-045
**Part of:** TD-1295
**Location:** the event runner (TD-1376: `src/sessionorc/agent_tick.py`, `src/sessionorc/ledger.py`); `src/sessionorc/witness.py`; the vendored ledgerboard release that carries `host-log` (`src/sessionorc/ledgerboard/`); design §4.4 *The home keeps a log of what it witnesses* (*The check*)

**Why:** TD-1295's design: ledgerboard's `host-log <kind> "<text>" [times N]` check (its TD-045) is answered by the host; until the runner answers it, a wait on what the home witnesses can be written only as the retired `Waits: event` line, which nothing resolves.

**Fix:** as design §4.4 *The check* and ledgerboard's TD-045 plan (rules 1, 2, 5, 6, 7) say: in the runner, parse `host-log <kind> [times <N>] "<text>"` with the vendored `parse_check()`; `since` = `gate_added()` for the gate, `after` 00:00 UTC of the day after; count with `witness.count` for the ledger's own repo alone; passed when the count reaches N, the evidence the N-th record's id (`ledger.py lift`'s `evidence=`), passed winning over retention; not yet when fewer; never impossible; error when `since` is `None`, the kind is unknown, its declared class is more private than the ledger's repo, that repo's visibility is unknown (the forge's `isPrivate`, read with the repo facts), the log is unreadable, or fewer than N are held and `covers_from` is after `after`. Vendor the ledgerboard release that carries TD-045 if TD-1376's vendor does not already, and pass `today` to every `set` and `edit` that can add a gate.

**Done when:** tests that a `host-log` gate lifts once its Nth record comes, citing that record's id; that a record dated the gate's own `gate added` day never counts, and one at 00:00 UTC the next day does; that a record of another repo never counts; that `times` before the text parses and after it is refused (by `parse_check()`); and that each error outcome — `since` `None`, an unknown kind, a `private` kind on a public ledger, an unknown visibility, a short count with `covers_from` after `after` — reaches the sweep as an error, while N records held past retention still pass.

**Related:** TD-1295 (the design); TD-1386, TD-1387; TD-1376 (the event runner); TD-1385 (a live check's gate, which may use it); ledgerboard#TD-045.
