## TD-1388: The event runner answers `check: host-log` from the witness log

**Priority:** Medium
**Type:** feature
**Added:** 2026-11-04 (the designer, from TD-1295's design)
**Owner:** grinder
**Kind:** build
**Status:** Open
**Blocked by:** TD-1390, TD-1376, ledgerboard#TD-048
**Part of:** TD-1295
**Location:** the event runner (TD-1376: `src/sessionorc/agent_tick.py`, `src/sessionorc/ledger.py`), running agent-cadence's `hostlog.py`; new `docs/ledger/log-sources.toml`; `.shiftlead.yml` (`held:`); `docs/cadence.toml` (`precheck`); `src/sessionorc/reports.py` (the repo facts reading gains each repo's visibility); the vendored ledgerboard release that carries `host-log` (`src/sessionorc/ledgerboard/`); design §4.4 *The home keeps a log of what it witnesses* (*The source*, *The check*)

**Why:** TD-1295's design: ledgerboard's `host-log <source> [kind <kind>] [times <N>] "<text>"` check (its TD-045, revision 2) is answered by the host running agent-cadence's reader, `hostlog.py`, over a source the repo declares; until the event runner runs it, a wait on what the home witnesses can be written only as the retired `Waits: event` line, which nothing resolves.

**Fix:** as design §4.4 *The home keeps a log of what it witnesses* (*The source*, *The check*) and ledgerboard's TD-045 plan (revision 2, rules 1, 2, 9, 11, 13 and *What a consumer must do*) say:
1. **Declare the source**: add `docs/ledger/log-sources.toml` with `[sources.witnessed]` as the design gives it, and add the file to `.shiftlead.yml`'s `held:` (a change to it waits for its reader; the host file's one root bounds what it can reach). This PR is held for that reason.
2. **Validate at the merge gate**: `docs/cadence.toml`'s `precheck` runs `agent-cadence run hostlog.py validate --repo-config docs/ledger/log-sources.toml --ledger docs/ledger`, which needs the agent-cadence pin to carry `hostlog.py`: this PR lands after that bump.
3. **Run the reader per gate** in the event runner (TD-1376): for each gate whose check `parse_check()` reads as `host-log`, run `agent-cadence run hostlog.py check --repo-config - --host-config <store>/host-log.toml --repo <id> --visibility <public|private> [--since <gate_added()>] '<check line>'` off the loop, one gate at a time, with a fixed 120 s hard timeout; the repo's `log-sources.toml` on stdin from the tree the sweep read the ledger from (empty when absent); `--repo` the repo's `<repo>` id (its origin's path); `--since` left out when `gate_added()` gives none.
4. **Map the answer**: `passed` lifts through `ledger.py lift` with the reader's `evidence`; `not yet` and `error` go to `sweep()`; `none` leaves the gate out of `sweep()`'s results; a non-zero exit, output that is not one JSON object, or the timeout is `error`; the reader's `problem` goes to the home's log, never the board.
5. **Read each repo's visibility**: the repo facts reading gains it once per repo per agent start (`gh repo view --json isPrivate`; GitLab's project `visibility` through `glab api projects/<url-encoded path>`); `private` only for a private repo, `internal` and unknown passed as `public`.
6. **Vendor** the ledgerboard release that carries TD-045 if TD-1376's vendor does not already, and pass `today` to every `set` and `edit` that can add a gate or change a check.

It also waits for agent-cadence's `hostlog.py` (an agent-cadence entry its techlead files from TD-045, not yet numbered) to reach shiftlead with an agent-cadence bump: name that entry in `Blocked by` once it has an id.

**Done when:** tests, with the reader stubbed by a script printing given JSON, that a `passed` answer lifts the gate citing its evidence; that `not yet` and `error` reach `sweep()` as they are; that `none` keeps the gate out of `sweep()`'s results, neither lifted nor filed; that a non-zero exit, non-JSON output and the 120 s timeout each reach the sweep as `error`; that the reader is given the repo's `log-sources.toml` from the tree the ledger was read from (and empty input when the file is absent), the repo's origin path as `--repo`, `--visibility private` only for a private repo (`internal` and unknown give `public`), and `--since` the gate's `gate_added()` (left out when it gives none); that the `problem` reaches the home's log and not the board; and, against the real reader once it is vendored, that a `host-log witnessed kind press "apply ao-grind"` gate added yesterday lifts on a press recorded today and not on one recorded yesterday.

**Related:** TD-1295 (the design); TD-1386 (the log), TD-1390 (its records carry the repo's id, and the host file); TD-1376 (the event runner); TD-1385 (a live check's gate, which may use it); ledgerboard#TD-045 (revision 2) and agent-cadence's `hostlog.py` entry.
