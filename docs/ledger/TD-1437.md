**Why:** ledgerboard's target design §4.2 (*Live checks use it*) and §7.2 step 4: "the build is deployed" becomes an event gate on the live-check entry, and ShiftLead stops reading PR numbers from the `**Kind:** live-check #<n>` line. TD-1385 moved the open live checks' retired `**Waits:**` lines to gates, but no typed check yet stands for *the build is live*, so the `Kind:` line's `#<n>` still holds a live check out of the lanes until its build is live (design §4.9b *Live is read, never declared*). Neither road written so far fits as it stands (the techlead's answer to TD-1385's steer, 2026-11-06):
- **`ref-includes <repo>@<deploy-ref> <commit>`** (the target design's example): the gate sweep's `event_checks.py` asks the forge, and no deploy ref exists there — the live commit is only `promotes.<repo>.live` on the home; and the build PR that makes the entry a live check cannot name the squash commit, which exists only after its merge.
- **`host-log witnessed kind promote "(#<n>)"`**: `witness.KINDS` has no promote kind, and the reader counts from 00:00 UTC of the day after the gate's `gate added` line (design §4.4 *The check*), so a promote on the build's merge day — the usual case with `auto` on — is never counted.

**Design PR:** #3025, #3082, #3097, #3117, #3136, #3188, #3225, #3243

**Ask:** Go with TD-1437's builds as revised by TD-1554 (Paul's Hold: no Dismiss, a failure blocks only its own commit, the tag follows only a commit a run finished at, a hand install tagged by a press)? Answered on the board's end-of-rounds item for TD-1437 (Go | One more round | Hold: <note>).

**Fix:** Design how a live check waits for its build to be live as a gate, in §4.9b and §4.4: which check stands for *the build is live* (a deploy ref the home pushes on each promote, a promote kind in the witness log with a count that sees the merge day, a gate the merging session writes once the squash commit exists, or another), who writes it and when, and how the open live checks whose build is not yet live move to it. Then file the builds, each `Part of:` this entry; the build that lands it drops the `Kind:` line's `#<n>` as what holds (`ledger.py` `built`, `LiveReader`, `kind_of`, `_buildlike`, `queue.py`'s live-check reads).

**Done when:** The design names the check and its writer, its builds are filed, and once they land a test shows a live check whose build is not live is held by its gate alone, with no open live-check entry pickable the moment the `Kind:` line stops holding.
