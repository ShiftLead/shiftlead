## TD-1211: A `repo add` test sometimes finds a `gh` call it says never happens, and fails a PR's precheck at random

**Priority:** Low
**Type:** debt
**Added:** 2026-10-28 (grinder-ao-1, from #2633's precheck)
**Owner:** grinder
**Kind:** build
**Status:** Open
**Location:** `tests/test_repo_adopt.py` (`test_a_pinned_checkout_is_added_and_an_adopt_over_a_pinned_origin_is_refused`, ~387; the `world` fixture's `GH_LOG`)

**Why:** #2633's precheck on 482f1f0 (a change to design text and a docstring only) failed this one test, at `assert not world["log"].exists()  # no PR`: the fake `gh` had logged a call. The same test passed in the precheck of the commit before, in a full `pdm run test` on the branch, and five times alone and with its file under `-n 4`. So something other than the refused `--adopt` reaches `gh` under load. The likeliest is the reading that `ao repo add` (the step before) starts at the home, which reads the repo's PRs through `gh`, landing after `park_ticks` and before the assert. A random red precheck costs a PR a 3–4 minute re-run and reads as a real failure until someone looks.

**Fix:** find what wrote `gh.log` (log `argv` in the fake and read it on a failure). If it is the add's reading, the test asserts on the adopt's own calls, such as no `pr create` line in the log, rather than on the log's absence, or it waits for the add's reading to finish before the `--adopt`. Check lines 117, 193, 216 and 241 of the same file for the same shape.

**Done when** the test asserts only what the refused adopt does, and `pdm run test` passes.
