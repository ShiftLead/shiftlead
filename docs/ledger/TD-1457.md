On 2026-11-06 the techlead's `ao msg --kind reply --reply-to m-7bdae3194ee7` to `ao-agent-cadence-ac-grinder` (another project's grinder, whose ask reached it by the question-seat edge) was refused: `message_edge`'s reply branch (`src/sessionorc/mail.py` ~530) passes only when the replier's own `seat` has `trigger: asks` (`asks_seat(me)`), and the record had lost its `seat`. `ao inbox` has no close, so the ask stayed open.

**Fix:** - **The edge.** In `message_edge`, the last branch (`kind == "reply"`, `replied` an `ask` from the sender's own inbox, `target` on the asker's `superseded_by` chain) drops `asks_seat(me)`: any record answers an `ask` that reached it, back to its asker's chain, whatever either's team, project or seat. The edge keeps its name `question seat` in the returned string only if a caller keys on it; otherwise name it `asked`, and update the docstring's list and every test that asserts the name.
- Nothing else widens: a `reply` on any thread but an `ask` in the sender's own inbox, and every other kind, between unrelated projects, is still refused; depth and pair bounds hold.
- Tests: a reply from a record with no seat, on the thread of an `ask` from another project's record in its inbox, is accepted (and to a resumed asker on its chain); the same reply on a `note`'s thread, or to a record off the chain, is refused; a reply by a seat is unchanged.

**Done when:** A record answers an `ask` in its own inbox from any project, seat or not, and nothing else widens. Tests cover each case above.
