## TD-2108: The disk sweep removes detached worktrees that have fully landed

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-23
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 34d3e06c42f5443792713f15526e0c39
**Part of:** TD-2103

**Why:** Part of TD-2103, which designs the rule: the disk sweep keeps every detached worktree, so old ones that have fully landed are never reclaimed. Read on 2026-11-23 with the rule applied read-only: 15 of the 26 detached worktrees under a worktree root would go, about 430 MB. The entry's 3.4 GB counted worktrees the sweep's other tests keep, mostly ignored build output (one holds 2.1 GB).

**Location:** src/sessionorc/worktreesweep.py, src/sessionorc/gitinfo.py, src/sessionorc/agent.py, src/sessionorc/agent_tick.py, tests/test_worktree_sweep.py, design §4.6 *The disk sweep*

**Fix:** Build design §4.6 *The disk sweep*, the paragraph **A detached worktree**:

- `gitinfo.detached_landed(wt, root=...)` answers `yes`, `no` or `unreadable` by `git merge-base --is-ancestor HEAD origin/<default>`, reading the pin as `landed_of` does.
- `worktreesweep.weigh` drops its `detached` return. A detached worktree takes the transcript guard, the seat guard, the age filter, `detached_landed`, then `gitinfo.worktree_holds`, with the whys the design gives.
- `Agent._seat_home(wt)` answers `seat's home: <id>` for a record in any state, on this host or a linked container node, with a `team` badge and its `dir` at or inside `wt`. `sweep` takes it as a callable, passed by `_sweep_worktrees`, and `_one` asks it again just before the removal. A dry run asks it too, so `ao disk` shows the why.
- `tests/test_worktree_sweep.py`: the fixture test states the detached worktree as its second difference from `reap_worktrees.sh`, and the first test's detached case changes with the rule.

**Done when:** A detached worktree that is old, clean, landed on `origin/<default>` and held by no seat's record is removed by the sweep. One with a commit not on `origin/<default>`, with changes, written within `worktree_keep_days`, or at a record with a `team` badge in any state is kept, and `ao disk` names the why. Tests cover each case, the fixture against `reap_worktrees.sh` included.
