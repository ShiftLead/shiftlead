## TD-2108: The disk sweep removes detached worktrees that have fully landed

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-23
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 34d3e06c42f5443792713f15526e0c39
**Part of:** TD-2103

**Why:** Part of TD-2103, which designs the rule: the disk sweep keeps every detached worktree, so old ones that have fully landed are never reclaimed. Read on 2026-11-23 with the rule applied read-only: 12 of the 26 detached worktrees under a worktree root would go, about 360 MB. The entry's 3.4 GB counted worktrees the sweep's other tests keep, mostly ignored build output (one holds 2.1 GB).

**Location:** src/sessionorc/worktreesweep.py, src/sessionorc/gitinfo.py, src/sessionorc/agent.py, src/sessionorc/agent_tick.py, tests/test_worktree_sweep.py, design §4.6 *The disk sweep*

**Fix:** Build design §4.6 *The disk sweep*, the paragraph **A detached worktree**:

- `gitinfo.detached_landed(wt, root=...)` answers `yes`, `no` or `unreadable` by `git merge-base --is-ancestor HEAD origin/<default>` through `_git_rc` (0, 1, any other), reading the pin as `landed_of` does.
- `worktreesweep.weigh` drops its `detached` return. A detached worktree takes the transcript guard, the record guard, the age filter, the operation-in-progress test, the reflog test, `detached_landed`, then `gitinfo.worktree_holds`, with the whys the design gives. The module docstring's *never a detached worktree* goes.
- `Agent._record_home(wt)` answers `record: <id>` for a record in any state, on this host or a container node, whatever its team or role, with its `dir` at or inside `wt` by one helper lifted out of `_reap_idle`'s nested `inside`, which `_reap_idle` then calls too, a record with no `dir` or an empty one skipped inside it, and `<host> unreachable` for a container node whose link is down. `sweep` takes it as a callable, passed by `_sweep_worktrees`, and `_one` asks it again just before the removal. A dry run asks it too, so `ao disk` shows the why.
- `_one` reads a detached worktree's `HEAD` commit before the weigh and compares it under the create's locks before `remove`; one that moved is kept, *detached: HEAD moved*. A dry run does neither read. `gitinfo._git` gains an `input=` argument for the reflog test.
- `tests/test_worktree_sweep.py`: the first test's `kept[detached] == "detached"` changes with the rule. The fixture test against `reap_worktrees.sh` states the detached worktree as its second difference, in its title or docstring and in both final assertions, beside `empty`. New tests cover an operation in progress, an `unreadable` *landed*, an `exited` and a `closed` record at the worktree, a container node's record with its link up, a record with an empty `dir`, a sibling worktree whose name shares a prefix, a reflog-only commit, a down link at a node's seat record, and a `HEAD` that moves between the weigh and the removal.

**Done when:** A detached worktree that is old, clean, landed on `origin/<default>`, with no operation in progress, no commit only in its reflog and no session record at or inside it, is removed by the sweep. One with a commit not on `origin/<default>`, a commit only in its reflog, changes, an operation in progress, a write within `worktree_keep_days`, a `HEAD` that moved during the pass, or such a record in any state while that record exists, is kept, and `ao disk` names the why. Tests cover each case, the fixture against `reap_worktrees.sh` included.
