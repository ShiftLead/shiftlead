## TD-1578: The Inbox's row for a lift order in an unserviced repo reads conflicting with no age

**Priority:** low
**Type:** debt
**Added:** 2026-11-11
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 56874912f5e048bab77772445809065d
**Location:** src/shiftlead/ui/inbox.py (red-PR rows); design §4.4 A live check's lift PR is the team's at once

**Why:** TD-1450 slice 2 (#3280) made a live check's lift PR (`lift/TD-n/live`) a `pr:` order from its first reading, whatever its checks. The Inbox's rows for orders in a repo no team services (`src/shiftlead/ui/inbox.py`, the `teamrun.pr_orders` loop, about :792) special-case only `sync`; a lift order falls into the red branch, which reads `red_since` and `checks`. A green or pending lift carries neither, so its row reads *conflicting* with no age and an empty `since` (`repo #1900 · conflicting · author`), and never says *lift*. Found by #3280's independent review.

**Fix:** In `src/shiftlead/ui/inbox.py`'s red-PR rows, give an order carrying `lift` its own branch beside `sync`'s: `since` its `lift_since`, its words `lift` and the order's `lifts TD-n event (…)` (`workorders.lift_context`'s, the order's `entry` and `gate`), its author. Test it in the Inbox's red-PR row tests (`tests/test_ui_red_prs.py`), and run the page on a scratch home (`scripts/look_home.py`) with a fixture lift PR for the UI check.

**Done when:** An unserviced repo's Inbox row for a lift order reads *lift* with its gate and its age since `lift_since`, never *conflicting*; a test covers a green and a pending lift.
