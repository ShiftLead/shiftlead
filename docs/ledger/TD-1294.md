## TD-1294: #2767's tests do not pin four behaviours of the fork-PR row: the `open` state test, the Queue's `red_pr`/`fork_pr` want, and the two fork exclusions from Start session

**Priority:** medium
**Type:** debt
**Added:** 2026-10-31 (test-audit-ao-1, auditing #2767)
**Owner:** grinder
**Kind:** build
**Status:** Open
**Location:** `src/shiftlead/teamrun.py` `ready_to_precheck`; `src/shiftlead/ui/queue.py` (`row in ("red_pr", "fork_pr")`, `items_start`, the `do` count); `tests/test_fork_pr_line.py`, `tests/test_ui_queue.py`, `tests/test_ui_queue_cards.py`

**Why:** Evidence by reverting one line of #2767 in a worktree and running every test file that names `fork`, `red_pr`, `items_start` or `ready_to_precheck` (27 files, 759 tests); each run still passed, all 759:
- `ready_to_precheck`: `p.get("state", "open") == "open" and p.get("fork")` reduced to `p.get("fork")`. Its docstring says "open"; no test gives a closed or merged fork row.
- `queue.py`: `if row in ("red_pr", "fork_pr"): return "do"` reduced to `("red_pr",)`. A fork row would fall through to another want.
- `queue.py`: `sum(1 for m in c["wants"]["do"] if not (m.get("red") or m.get("fork")))` reduced to `not m.get("red")`. The Do count would include fork items, which start no session.
- `queue.py`: `items_start = any(not (m.get("red") or m.get("fork")) …)` reduced to `not m.get("red")`. A card of fork items alone would offer Start session.
The other mutants of this PR (the draft, conflicting, sync and checks conditions, `FORK_WHOSE`, `_fork_lines`' copy, `--fork-ok`) were caught. #2762 and #2759 were checked the same way and their mutants all failed a test.

**Fix:** add a case to each: a closed fork row is not ready; a Queue card holding a fork item reports `want == "do"`, counts it in neither `do`'s Start count nor `items_start`.

**Done when** each of the four reverts above fails a test, and `pdm run test` and `pdm run lint` pass.
