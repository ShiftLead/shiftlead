**Why:** Build TD-1437 (4), from TD-1554's Hold revision (design §6 *Promote*, *The hold*, *A copy installed by hand*; §4.5a *Inbox row: promote*; §4.7 `ao promote`). Paul's Hold on TD-1437 (m-8e970f0e4961): *drop Dismiss. A failure blocks only the failed commit; auto retries once main moves past it, and Promote or a rollback clears it. Tag only a commit a run finished at, and say how a hand install is tagged.* Today a failed promote stops every promote of the repo until the person presses Dismiss (`ao promote clear`). This slice makes a failure block only its own commit and removes Dismiss. It also writes the record the tag reads, `last.json`'s `done`, and lets the person press Promote to run a hand install again so that it is tagged.

**Ask:** Go with TD-1559, a build of TD-1437's design after its Hold revision (TD-1554)? Answered on the board's end-of-rounds item for TD-1437 (Go | One more round | Hold: <note>).

**Fix:** - **A failure blocks only its own commit** (`src/sessionorc/promote.py` `unmet`, `survey`; `src/sessionorc/agent_promote.py`), as design §6 *Promote* writes it:
  - `unmet`'s `failed` precondition, and `promote.acts`' (`promote.py` near :864, which today returns `None` for any `failed`, so the row's `auto` reading and its settle clock vanish), apply to the policy alone, and only while `failed.json`'s new field **`blocks`** is main's head. `fail` writes `blocks`: a promote's own `sha`, a rollback's `from` (a person's rollback or the smoke's, so a smoke-started rollback that cannot start or does not conclude blocks the commit the smoke failed on); a `failed.json` with no `blocks` (written before this build) blocks its `sha`. So: `auto` starts nothing at that commit and starts at a later head as ever, the settle and the wait unchanged. A press (`press=True`), Promote of main's head (the failed sha among them) or a rollback, is never refused by a failure.
  - **Every start clears it** — a press's, `auto`'s retry at a later head, the smoke's rollback — under `_promote_lock`, after `start` returns with the intent written: a start that raises (`make_tree`'s `ValueError`, `Popen`'s `OSError`) leaves `failed.json` as it was, and `failed.json` and `inflight.json` never stand together. Between main moving past the blocked commit and the retry's start, the failure row reads the policy's clock (*· auto on · settles in m min*, as the `auto` row does). A run that concludes clears it (`survey`'s `clear(repo, "failed")` on the conclusion's note, near :1159, as today). A run that fails writes its own `failed.json` in place of the standing one (`fail`, as today).
  - Under the hold, a press that failed leaves its failure beside `held.json`. The next press clears the failure as it starts and ends the hold when it concludes, as `_passed` does today. `unmet`'s held text and `cli.py`'s promote lines (near :1844, :1848) drop *or clears it*: *nothing is promoted by itself until the person promotes*.
- **No Dismiss**: remove `rpc_clear_promote` (`agent_promote.py`) and `clear_promote` from `modes.py`'s edit lists, `mail.py`, `src/shiftlead/ui/app.py`'s route, `app.js`, `inbox_row.html` (its button and the text near :1035, *until this is dismissed or a press succeeds*, which reads *until a press starts a run or a run concludes*) and `repo_part.html`'s button (the live divider's held line offers Promote, §4.5 screen 11), and `ao promote clear` (`src/shiftlead/cli.py`). An old client's `clear_promote` is answered as any unknown RPC is. AGENTS.md's *Going back* paragraph: the hold ends when a Promote concludes. It names no `ao promote clear`, no Dismiss and no *turn `auto` off first* tied to Dismiss.
- **`done`** (`promote._passed`): when a run concludes (`check` reads its commit, the run has ended, its smoke passed where the block has one), write `done` (the time) into `last.json` beside the fields `_concluded` wrote, so `last.json` names its commit with `done` set only once a run finished at it. A `last.json` without `done` (a failed run, or one written before this build) reads as not finished. Add `promote.finished(repo, live) -> bool`: `last.json`'s `sha` is `live` and `done` is set. TD-1450's tag reads it.
- **A copy installed by hand** (§6 *A copy installed by hand*): the press's refusal *live is main's head already — nothing to promote* (`agent_promote.py` near :162) stands only when `promote.finished(name, live)`. Otherwise the press is taken and runs `run` at main's head as any promote does, its smoke too. So too a rollback (`--sha`) to the live commit (`agent_promote.py` near :220): refused as *live already* only when `promote.finished(name, live)`, else taken, so a hand install of an older commit is tagged by a rollback to it (§6 *Which commit*); `--sha` of main's head stays refused (the plain press is the path). `auto` never starts it (live = main is nothing for the policy). The reading carries `by_hand: true` when live is main's head and not finished, nothing is in flight, no failure blocks that commit and no hold stands: the in-flight, failure and held rows stand in its place, never beside it (the held row's Promote is the same press). The row's *— promote to tag it* lands here, before TD-1450 pushes a tag: accepted, TD-1450 being blocked by this build alone. `ao promote status` reads *installed by hand* for it, and names the commit a failure blocks. The hand install's re-run has `from` = its own commit, so its failed smoke rolls nothing back: a failure blocking that commit, live left where it was. The row (§4.5a *Inbox row: promote*) is then drawn under FYI, uncounted, whatever `auto` says: *`<repo>` · live `<sha7>` = main · installed by hand — promote to tag it*, with Promote. A legacy `last.json` reads so until the next run concludes (accepted, §6).
- **The row** (`inbox_row.html`, `repo_part.html`): no Dismiss on any promote row. A failure row reads, under `auto` while main's head is the failed commit, *· auto retries when main moves past `<sha7>`*. A held row's Promote is the one way the hold ends.
- **Help text** (`src/shiftlead/ui/help.py`, and §4.5a's help list in the same PR, `tests/test_help.py` holding them together):
  - Remove the **Dismiss (Inbox row: promote)** item, and `help.py`'s `promote-dismiss` key (both, near :919).
  - **Promote**'s and **Promote now**'s last clause reads *it is refused, in words, while a run is in flight or the checkout is not clean on main; a failed promote never stops it — the press runs again, and clears the failure*.
  - **Snooze ▾ (Inbox row: promote)**'s last sentence reads *a snoozed hold still stops the policy, and a snoozed failure still holds back its own commit*.
- Tests (`tests/test_promote.py`, `tests/test_ui_promote.py`, `tests/test_live_divider.py`; the tests that call `clear_promote` today are rewritten to the press that replaces it):
  - `auto` with a failure at main's head starts nothing; once main moves past it, `auto` starts at the new head and its start clears the failure; a start that raises leaves it.
  - A failed rollback blocks its `from`; a smoke-started rollback that cannot start or does not conclude blocks the commit the smoke failed on.
  - A press at the failed sha is taken and clears `failed.json` as it starts, and so is a rollback. The run that concludes leaves no failure; one that fails writes its own.
  - Under the hold, a failed press then a concluding press ends both.
  - `last.json` carries `done` only after a conclusion: not after a run that failed once `check` read it, nor after a failed smoke.
  - A press with live at main's head is refused when finished, and taken when not: a hand install, or a legacy `last.json`; a rollback to the live commit likewise.
  - `acts` reads `auto`'s settle with a failure at an older commit; `by_hand` is false while a run is in flight or a failure stands at live.
  - The row shows *installed by hand* and no Dismiss anywhere. `ao promote clear` is gone.

**Done when:** A failure blocks only its own commit: `auto` retries once main moves past it, and a press clears it as it starts. Dismiss, `clear_promote` and `ao promote clear` are gone. `last.json` carries `done` only once a run finished at its commit. A hand install at main's head is drawn *installed by hand — promote to tag it*, and its Promote is taken. The help list and `help.py` agree. Tests cover each case above.
