## TD-2150: A repo file nested too deeply crashes the core's readers of repo settings instead of reporting a problem

**Priority:** Low
**Type:** debt
**Added:** 2026-11-24
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** fa18572231184063a87b4d90051db7ed

**Why:** A repo's own YAML file nested past the parser's depth makes `yaml.safe_load` raise RecursionError, and the sessionorc readers of `.shiftlead.yml` and `flow.yml` catch only `yaml.YAMLError`, so one such file crashes the read instead of being reported. #4480 (TD-2135) closed this for shiftlead's `repoconfig.parse_yaml`, but sessionorc cannot import it. Its independent review named these direct reads: `gitinfo.py` (`worktree_setup`), `held.py`, `ledger.py` (`ledger_set`), `workorders.py` (board), `settle.py` (`repo_settle`), `sync.py` (held), `promote.py`, whose docstring promises a ValueError that is never fatal to the tick, and `briefs.py` (an org flow's `flow.yml`). The review also noted that `stage_end.call` lets a `yaml.YAMLError` from a hand-edited stored flow out of the RPC. Whether each caller up the stack already catches broadly has not been checked.

**Location:** src/sessionorc/promote.py, held.py, gitinfo.py, settle.py, sync.py, workorders.py, ledger.py, briefs.py

**Fix:** Give sessionorc one small reader of a repo's YAML text that turns RecursionError into `yaml.YAMLError` (as `repoconfig.parse_yaml` does), and use it at each direct `yaml.safe_load` of a repo's own file named in the Why. Check `promote.py` first, since a crash there breaks the tick's promise.

**Done when:** A `.shiftlead.yml` nested past the parser's depth is reported as invalid YAML by the promote read and by every other reader named in the Why, with a test for the promote read, and nothing raises RecursionError.
