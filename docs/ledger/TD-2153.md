## TD-2153: A tick already reading the panes can still adopt the pane a failed session start has just killed

**Priority:** Low
**Type:** debt
**Added:** 2026-11-24
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 43b8ae2ddf214ee6b985ef08a91169fc

**Why:** The independent review of #4497 (TD-2144) found that a create's kill of its unrecorded pane does not stop a tick already in flight from adopting it. The tick reads its panes (`src/sessionorc/agent_tick.py`, `main_panes`) and awaits `capture_tail` calls before `_reconcile` checks `_starting`. A tick whose pane reading was taken while the pane was up can reconcile after the create has killed the pane and released `_starting`, and then adopt the dead pane as a nameless shell. TD-2125's failed-after-start path has the same window, and TD-2144's cancel path widens it to the whole wait for the start's thread. #4497's new create test failed 5 of 14 runs this way until its ticks were parked. A second gap the same review found: `Tmux.run`'s 15 s subprocess timeout raises `TimeoutExpired`, not `TmuxError`, so a `new-session` that made its session and then timed out kills nothing.

**Location:** src/sessionorc/agent.py (_reconcile), src/sessionorc/agent_tick.py, src/sessionorc/tmux.py (new_session)

**Fix:** In `_reconcile` (`src/sessionorc/agent.py`), never adopt a pane whose id a create released from `_starting` after the tick took its pane reading. For example, record each release with a monotonic time and give `_reconcile` the time of its reading, or keep a short set of ids killed by `_kill_unrecorded_pane` that the next reconcile skips once. In `Tmux.new_session`, treat a `subprocess.TimeoutExpired` from the chained call as a failed start: kill a session of that name only where this call can be shown to have made it. Then drop the `park_ticks` from the two TD-2144 create tests in tests/test_agent.py, or add a test that drives a tick whose reading predates the kill. Update design §4.1's create bullet, which names this entry.

**Done when:** A test shows that a tick whose pane reading was taken before a failed or cancelled create killed its pane adopts nothing. A test shows that a `new-session` that times out leaves no session it made. Design §4.1 no longer names this entry as open.
