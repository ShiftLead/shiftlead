## TD-2066: The Built-ins page and its store: one set of models and logins for the five built-in seats

**Priority:** Medium
**Type:** feature
**Added:** 2026-11-22
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** a218ca8b808f427abee279a8902c03c9
**Blocked by:** TD-2060, decision (paul)
**Part of:** TD-1153

**Why:** The five built-in seats (tech lead, manager, board answers, pull requests nobody holds, sweeper) no longer take a model from a flow or a login from a team. The person sets one set of models and logins for them and every repo uses it, or makes another set and points a repo at it, so there has to be a store for the sets and a page that sets them.

**Ask:** Should the builders build the Built-ins page and the store behind it?

**Fix:** Build design §4.9d *The built-in seats and their page* with its §4.5a rows (Built-ins page): `builtins.<set>` (label, models, logins) and `repos.<repo>.builtins` read and checked, `default` always present; the calls `builtins_new`, `builtins_delete`, `builtins_set` and `repo_builtins`, each on the person-only list, version-checked and gated on the `cut_over` marker; `/builtins` and `/builtins/<set>` with the set tabs, the head, the five seats' model picks with the login each would start on now, the logins band (the team page's, on the set's list), the repos band and Delete with its refusals; the *cannot run a seat* reading with the tab's dot, and the one function that gives a repo's set and a seat's model and login, which calls TD-2060's first-usable-login pick on the set's list; `ao builtins show`; the rail's sixth item; the team page's line *Built-in seats: set `<set>`*. Not here: starting a built-in seat's session on that model and login is the launch path's (TD-1976's design and builds) and, for board answers and pull requests nobody holds, TD-2053's; when a repo's seats run is TD-2065's. Before the cut-over the page draws *after the switch-over* and writes nothing.

**Done when:** A set's models and logins save from the page and are refused before the marker and on a stale version; `default` cannot be deleted and a set a repo names cannot be until the pick moves; a repo with no pick reads `default`; a set whose list offers no login for a seat's model says which seat it cannot run, on its tab and on the team pages of the repos that use it; `ao builtins show` prints what the page shows.
