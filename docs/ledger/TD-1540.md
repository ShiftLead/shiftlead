**Fix:** Build §4.7 `ao board edit … --carried-to` and the briefs' step:
- `src/shiftlead/cli.py` (`cmd_board_edit` ~3486, its parser ~5641): `--carried-to TD-n[,TD-m…]`, accepted with `done` only (refused with `snooze`), composes the `Closed:` reason *carried to TD-n* (several joined *TD-n and TD-m*, *TD-a, TD-b and TD-c* for three; a `<repo>#TD-n` written as given), followed by `: <why>` where `--why` is given too, and passes it as the `--why` the edit already writes — the composition and the id check live in `cmd_board_edit`, before `sessionorc.board.branch_edit`, which is unchanged, so the CLI half touches no held path; the designer brief (`docs/briefs/designer-ao-1.md`, under `docs/briefs/**`) is the one held path, so the build's PR waits for its reader — its author sends the `ask --pr` once green. It works with `--line`/`--expect` and `--key board:<key>` alike. The value is split on commas, spaces trimmed; each element must fully match the reader's id (`workorders._ID`: `TD-<n>` or `<repo>#TD-<n>`), else the edit is refused before anything is written (`td-5`, `5`, an empty element); a repeat is listed once. The ledger read is the work tree's that `branch_edit` resolves from the current directory (the tree holding the board, whatever `--board` names), and an entry there may be uncommitted and unstaged — filed by `ledger.py new` just before the close. Each bare id must be an entry of the branch's own ledger, open or archived, in either layout, read from the working tree the edit commits on as `sessionorc.ledger` reads it (`ledger_path`, `layout_at` over `ledger.fs_io(root)`, which sees an untracked file — never `git_io`); an unknown bare id is refused before anything is written, naming it; an id of another repo is not checked.
- Briefs (TD-1532 edits the same designer brief line's neighbourhood; whichever lands second rebases, no block): `docs/briefs/designer-ao-1.md` (held path; its *The answered item* line's `ao board edit done --why "carried to TD-n"` becomes `ao board edit done --carried-to TD-n`) and the packaged grinder brief, `src/shiftlead/briefs/grinder.md` (~12: *close the line pointing at it (`ao board edit done --line <n> --expect "…" --why "see TD-n"`)*, the template every free-pick lane runs and the source of the *see TD-n* closes), say `--carried-to TD-n`. `grep -rn 'carried to\|see TD-n' docs/briefs src/shiftlead/briefs` finds every place; each that closes a line for another's work names the option.
