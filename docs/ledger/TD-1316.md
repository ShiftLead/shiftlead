## TD-1316: Choosing an answer on a Queue card's needs-you item takes about ten seconds to show: make a press answer at once on every page

**Priority:** medium
**Type:** debt
**Added:** 2026-11-02 (Paul, through Add entry; drafted by ao-shiftlead-techlead-ao-1)
**Owner:** designer
**Kind:** design-first
**Status:** Open — read from the code (below); nothing measured or designed yet.
**Location:** `src/shiftlead/ui/static/app.js` (the `[data-act]` click handler from ~1172: `AO.markPending` ~1152, the `ledger` and `board` decide presses ~1440–1456 that `await act("person", …)` and only then call `AO.refreshInboxPage()`, the `finally` ~1597–1601; `PRESS_LEAVES` ~1142, which holds no decide or answer); `src/shiftlead/ui/app.py` (`/api/person/{action}` ~4869, the `board` and ledger decide acts); `src/sessionorc/board.py` (`_tree` ~267: `git fetch`; `_land` ~365: commit, push a branch, open a PR and squash-merge it; `BOUND = 40.0` ~181); `docs/design/4.5-ui.md` (screen 6 *A control answers the press*, ~994, rules 2 and 3); `docs/design/4.4-host-agent.md` (*Board write-back*, *Decide* ~1869, the forty-second bound ~1823–1865)

**Why:** Paul (2026-11-02): "Choosing an answer on the Queue page "needs you" items seems to take about 10s before the page responds. Lets do some best practices research as needed and figure out how we can make our pages more responsive. A click from a user should have a near-immediate response (beyond the notification)." A *decide* on a board line or a ledger entry is written on origin before the press returns (a ledger decide as a decided line on the repo's board, `ledger_decide` → `board.add_decided`): the host agent fetches, commits, pushes a branch of its own, opens a PR and squash-merges it (§4.4 *Board write-back*, bounded at forty seconds), and the page redraws the row only after that answer, by a full re-read. The design already asks that *a press answers in the same frame* (§4.5 screen 6, rule 2: the row is marked pending, dimmed, its age reading *deciding…*), and that a press that takes its row away leaves on the press (rule 3); but a board or ledger decide is not in rule 3's list (*a decided item is not done*, §4.4 *Decide*), so its row stands dimmed, unchanged, until the git round trip ends. To the person that reads as a page that did not respond. A mail answer (`answer`, `reply`) goes to the host agent alone and should be quick; whether it is, and whether the Queue card's item rows get rule 2's pending mark at all, is not measured. The re-read after each press (`/queue?part=1`, the whole Queue's cards) is a second cost. Every write that lands on origin (Done, Snooze, Reply on a board line; a rank move, §4.4 *A move lands*) shares the same wait.

**Fix:** design first, with the research Paul asked for:
- Measure first, on the live page: the time from press to first visible change, and to settled, for each answer kind on a Queue card (mail answer, board decide, ledger decide) and on the Inbox, split into request, host-agent work and re-read. Record the figures in the entry.
- Read the common practice and pick from it: optimistic UI (draw the result at once, roll back on refusal, as rule 3's toast that waits already does for a row that leaves), a 100 ms acknowledgement budget, accepting the write into a queue the host agent lands in the background with the row reading *decided — landing…*, and redrawing only the pressed row or card instead of the whole Queue.
- Settle in the design (§4.5 screen 6 *A control answers the press*, and §4.4 *Board write-back* if a decide is accepted before it lands): what a decided row shows the moment it is pressed, what a refusal looks like when it comes ten seconds later, and that the rule holds on every page that draws these rows (Queue, Inbox, Repo).
- Done when the design states the rule, its builds are filed `Part of: TD-1316`, and the measured press-to-change time on a decide is under a frame-and-a-bit (about 100 ms) on the live page.
