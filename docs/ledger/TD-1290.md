## TD-1290: `--until 06:00` the day before a DST change stops an hour off, and the suite's time-of-day test fails that day

**Priority:** high
**Type:** debt
**Added:** 2026-10-31 (grinder-ao-2, from pr:2758's red precheck)
**Owner:** grinder
**Kind:** build
**Status:** Open
**Location:** `src/shiftlead/cli.py` `stop_time` (the `HH:MM` branch); `tests/test_cli.py`

**Why:** `stop_time("06:00")` built the next 06:00 as `now.replace(hour=6, minute=0)` plus a day, and `now` carries today's fixed UTC offset. On 2026-10-31 in America/Denver (MDT, DST ending 2026-11-01 02:00) it returned 2026-11-01T12:00:00Z, which is 05:00 MST: a stop an hour early, and `test_until_parses_the_shapes_a_person_types_and_refuses_the_rest` asserting the hour is 6 failed every precheck that day (pr:2758 red, 2026-10-31). In spring the stop is an hour late.

**Fix:** localize the wall time per day: `datetime.combine(day, time(h, m)).astimezone()` for today, and for tomorrow when today's is past, so each takes its own day's offset. Design §6's *the next 06:00 here* already says this; no design change.

**Done when** a test pinned to America/Denver on 2026-10-31 and 2026-03-07 gets tomorrow's 06:00 on tomorrow's clock (13:00Z and 12:00Z), and `pdm run test` and `pdm run lint` pass.
