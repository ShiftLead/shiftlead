## TD-1908: A pull request closed without merging keeps failing the cadence check, so its member and then the person are asked to fix it

**Priority:** medium
**Type:** debt
**Added:** 2026-11-17
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** e556a15be8ae4c2e92ec54cec6511089

**Why:** The home's cadence reading (`sessionorc/cadence.py`) treats a PR closed unmerged like an open one. `clause` names its fail in every `ao` reply, `line` rings its member to *fix it, then report done again*, and `record` sets the Inbox row once the member was told. A PR closed unmerged on purpose — a moot gate-sweep lift, a filing PR found moot — has no review a reader would write as SHIP, so neither a `done`, a `drop` nor a BLOCK comment clears it. Seen 2026-11-16 on #4027 (TD-1741's lift, closed because #4028 had archived the entry): the member posted a BLOCK review saying so, reported `done` and then `drop`, and every `ao` reply still ends *PR #4027 fails the cadence check: review*; the row then goes to the person's Inbox.

**Fix:** Read a PR closed unmerged as settled in `sessionorc/cadence.py`, as a merged one's fail is read now. The entry already carries `closed` (`record(..., closed=closed)`, called from `agent_tick.py`), and `settled` already reads it; what is missing is that `clause` and `untold` skip only `merged`, and `record` sets `row` on a told fail whatever the state. Leave a `closed` entry out of `clause` and `untold`, and never set `row` on it in `record`. Alternatively, have `check_cadence.py` (agent-cadence) score `review` as NA on a closed-unmerged PR, as it already does for `base` and `pushed`. Choose one road, and state it in design §4.9b where the cadence reading is described.

**Done when:** A PR closed unmerged with no `cadence-review:` comment, or with a BLOCK, is not named in its member's `ao` replies, rings nobody, and draws no Inbox row. A test holds this.
