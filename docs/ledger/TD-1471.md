## TD-1471: Views the home serves read the checkout, which lags the home's own writes: every view reads its own writes until the pull

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-06 (Paul, through ao-led-tds-ledger and the techlead seat; drafted by ao-shiftlead-techlead-ao-1)
**Owner:** designer
**Kind:** design-first
**Status:** Open
**Id take:** d8ccc19709f0416996624c1a16cfcb15
**Location:** src/sessionorc/agent_inbox.py (`_reread_board`); src/sessionorc/agent_tick.py (the press hold, `PRESS_HOLD`, `_hold_pressed`; the readings); src/sessionorc/board.py (the write-back); src/sessionorc/queue.py, src/shiftlead/ui/queue.py, src/shiftlead/ui/inbox.py (the views); design §4.4 *Each reading has one owner*, §6 *Pull*, §4.5 screen 12

**Why:** Asked by Paul through the person's session `ao-led-tds-ledger` (m-247dff0b7a94), from the same review. About 7 incidents had the Queue showing state older than what had just happened:
- **Lift the hold** after a Go (TD-1433);
- *needs you* after the person answered (TD-1364, TD-1368);
- a Go recorded on the board but not applied to the ledger;
- a card matched to another repo's TD-051 (m-2895830be375);
- a board answer differing from the one chosen.

TD-1433 (#3041) fixes one case: after a press, `_reread_board` re-reads the entries it wrote from the write-back's tree and holds them over the checkout until it pulls. The rest read the checkout's ledger and board, which lag the home's own merges until the pull (design §6 *Pull*, which waits while a session in the checkout is mid-turn).

**Fix:** Design first (§4.4 *Each reading has one owner*, §6 *Pull*). Paul's suggestion: make TD-1433's fix the rule. Every view the home serves reads its own writes, from the write-back's tree or the merged commit, until the checkout has caught up. An answer's effects show at once as *answered — applying* instead of the old state. List every write the home makes (board edits, decide lifts, `queue:` rank edits, notices PRs, sync merges, `td add`) and the views each changes, and say for each whether TD-1433's hold covers it. Look at the cross-repo match (m-2895830be375, a bare `TD-051` matched to another repo's) as part of the same reading rule (§4.5 screen 12 *Where a row is drawn*), or file it apart if it is a different bug.

**Done when:** The design names, for each write the home makes, how every view it changes reads it before the checkout catches up. Builds carrying `Part of: TD-1471` make it so. A test pins each view against a just-merged write with a stale checkout.
