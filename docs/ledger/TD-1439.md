**Why:** Build TD-1434, slice 1 of 2 (design §4.5 *A taken-over member*, §4.5a the Session card's *mode* row, §4.4a the home's fields). On 2026-11-06 the techlead seat went `interactive` some time after 05:39Z, and nothing could say when, by whom, or from which control. `rpc_set_mode` writes no log line and keeps no field. The seat then slept through five messages for about 11h. This slice is the trace, which the entry says needs no design.

**Fix:** - `src/sessionorc/models.py`: three fields on the record, `mode_at`, `mode_by` and `mode_via` (str | None). They are home-owned, in `HOME_OWNED` beside `unattended` (§4.4a).
- `src/sessionorc/agent.py` `rpc_set_mode`: gains `via: str | None = None` and `caller`. When the mode actually changes (`bool(unattended) != s.unattended`), it stamps `mode_at` = now, `mode_by` = `person` when `mail.as_person(caller, self.sessions)` (no caller, or the person's own shell, TD-801), else the caller's id in the home's form and `mode_via` = `via` when it is one of `focus`, `card`, `inbox`, `cli`, else None. A call that leaves the mode as it was writes nothing. It writes one log line through the host agent's logger: name, new mode, by, via.
- **A record's start stamps too.** `create` (and so Restart and Resume, which create) writes `mode_at` = the record's `created` and `mode_via` = `start`, and no `mode_by`: a person's create and a policy's both arrive with no caller, so the start names nobody.
- **A node's member.** `agent_remote.py`'s mirror of a forwarded act (`await rpc_set_mode(**params)`, near :589) passes `caller` in the home's form (as the acting gate verified it, not `who`, which is rewritten for the node) and the press's `via`, so the home's copy is stamped as on one host. `via` is never in the params forwarded to the node: an older node refuses an unknown keyword (`bad params`), and the fields are the home's, read from its copy alone.
- `src/shiftlead/ui/app.py` (the mode act's handler) passes `via` from the press: `focus` from Focus's acts line, Watching line, more ▾ and narrow sheet, `card` from the card's more ▾. The page's `data-act="mode"` buttons carry a `data-via`, and app.js sends it. `src/shiftlead/cli.py` (`ao mode`) passes `via: "cli"`.
- The Focus Session card (`focus.html`, its view in `src/shiftlead/ui/cards.py`): the existing *mode* row (`<dd id="fmode">`, focus.html near :402) gains the stamp on an agent record; app.js's Focus delta, which today rewrites `#fmode` to the bare mode word (near :7394), fills the same text from the view. On a record with no agent it stays the bare word. It reads *interactive since `<time>` · by you from Focus*: *you* for `person`, else the session's name; the via words are *from Focus*, *from its card*, *from the Inbox*, *by `ao mode`*, and are left out when none. On a start the row names nobody: *unattended since `<time>` · from its start*. With no stamp it reads *since before this was recorded*. 
- Tests: a flip stamps all three and a same-mode call stamps nothing; a create stamps `start` with no `mode_by`, drawn with no *by*; a session caller's id lands in `mode_by`, on the home's own record and on a node member's home copy; an unknown `via` is dropped; the log line is written; a person's own shell's `ao mode` stamps `person`; a node member's flip forwards no `via` and stamps the home's copy; the Session card row draws each wording and the unstamped one.

**Done when:** `set_mode` stamps `mode_at`, `mode_by` and `mode_via` on every real change and logs it. The page and `ao mode` pass their `via`. Focus's Session card shows the mode row. Tests cover each case above.
