## TD-1677: Find and fix the common cause of the tests that fail only under a loaded full suite (TD-1218, TD-1254, TD-1612, TD-1670)

**Priority:** high
**Type:** debt
**Added:** 2026-11-11
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 9a617d8c4c1948599bc76fad089886d7
**Location:** tests/conftest.py, tests/_agent_child.py (the harness's host agent and tick); tests/test_first_prompt.py, tests/test_question_seat.py, tests/test_link.py, tests/test_stuck.py

**Why:** Four open entries each record one test that failed under a loaded full suite and passed alone: TD-1218 (`tests/test_first_prompt.py`, the tick did not mark `first_prompt_error` within its bound), TD-1254 (`tests/test_question_seat.py`, a state the test set by hand was overwritten, likely by a tick), TD-1612 (`tests/test_link.py`, a container node's checkout) and TD-1670 (`tests/test_stuck.py`, three tests reading the home's `stuck` record before the stuck pass wrote it). Three of them wait on an event (the same test failing again), so each is looked at alone, if at all. Together they look like one pattern: a test reads, or sets, state that the in-process host agent's tick or a background task writes on its own clock, and under the suite's `-n 8` load the order changes. On 2026-11-11 PR #3447 (docs only) spent two of its seven prechecks on `test_stuck` alone; each red precheck costs about five minutes and invites merging past the gate (Paul: fix the root cause rather than scope the precheck around it).

**Fix:** One investigation across the four, before any one is fixed alone.

1. **Reproduce under load.** Run the suite as the precheck does (`pdm run test`, `-n 8`) in a loop, beside a second suite for load, and the four modules alone in loops, until each named test has failed at least once or 20 loaded suites pass; record the counts.
2. **Find the shared cause.** For each failure, say what the test read or set, what writes it (the tick, a background task, the test harness's host agent in `tests/conftest.py` or `tests/_agent_child.py`), and whether the test waits for that write. Look for: assertions on state the tick writes with no wait for that tick; a test setting state the tick then overwrites; fixed time bounds that load stretches; ticks or clocks shared between cases.
3. **Fix the cause once.** Where it is the harness (a tick that runs while a test sets state, a missing way to await one pass), give the harness the means — a way to run or await one tick pass, or to pause the ticker inside a test — and move the four tests onto it; never a sleep, never a loosened assertion. Where a test is simply wrong, fix that test. Where the code has a real race, fix the code with a test that holds the order.
4. **Close the four.** Each sibling entry is archived by this PR with a pointer to the fix, or left open with what remains if its test is a different cause.

**Done when:** The shared cause (or causes) is named in the PR, with the reproduction counts before and after. 20 loaded suites in a row pass every one of the four tests, and TD-1218, TD-1254, TD-1612 and TD-1670 are each archived or say what remains.
