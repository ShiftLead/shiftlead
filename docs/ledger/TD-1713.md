**Why:** Found by the test seat auditing #3537 (TD-1380). The Repo page's For you now draws a covered row plain only when an open *undecided Decide or Do* line covers it: `fy_asks` in `src/shiftlead/ui/app.py` (~2090) filters `not b.get("decided") and want_of(b, "needs") in ("decide", "do")`, and gives the placed and `ahead` lines their *holds* line through `fy_holds`. The PR's For you test (`test_the_repo_pages_for_you_draws_the_line_once_and_the_covered_rows_plain`) has one line, undecided and a Decide, so neither filter is exercised.

Probe on origin/main (69d9d637b), each run `pytest -q tests/test_queue_covers_once.py tests/test_ui_queue.py tests/test_ui_inbox_ledger.py tests/test_ui_inbox.py`, each 211 passed: (1) drop `not b.get("decided") and` from `fy_asks`, so a decided line hides rows it no longer asks; (2) drop `and want_of(b, "needs") in ("decide", "do")`, so any line, a Read for one, hides the rows; (3) replace `fy_holds(b)` with `dict(b)` in the `ahead` comprehension (~2123), so a not-yet-due line draws no *holds*. Reverted afterwards.

**Fix:** Extend the Repo page For you test with a decided line and a Read line covering rows (both leave the rows drawn) and an ahead line (its holds line drawn).

**Done when:** A test fails for each of the three mutations above: a decided line hides no For you row, a line that is not a Decide or Do hides none, and an `ahead` line carries its *holds* line.
