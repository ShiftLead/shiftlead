## TD-2037: Test workers crash in the UI page tests under load, so a precheck goes red for no reason in the PR

**Priority:** Low
**Type:** debt
**Added:** 2026-11-21
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 3dcb67c9c51745788ed24abdbceaea34

**Why:** On 2026-11-21 three runs of the full suite on PR #4298 (two prechecks and one local run) failed because pytest-xdist workers crashed. The tests they were running were UI page tests (tests/test_ui.py, test_settle_pages.py, test_sweep_switch.py, test_ui_build_chip_pages.py, test_ui_focus_rail.py, test_ui_inbox.py, test_no_agent_pages.py), and the set changed every run. Each one passed when run alone, and a fourth precheck on the same head passed (254s). kmaster's load average was 13 to 19 at the time, with 14 GB available. A crash like this turns a precheck red for a reason that has nothing to do with the PR, and the author pays for another full run.

**Location:** tests/test_ui*.py, tests/test_settle_pages.py, tests/test_sweep_switch.py, tests/test_no_agent_pages.py; pyproject's pytest/xdist options

**Fix:** Find out what kills the worker: a run with `-p no:randomly`, `--max-worker-restart=0` and faulthandler on, under load (two suites at once reproduced it), to see whether it is a segfault, an OOM kill or an `os._exit` inside a page test's server thread. Then fix the cause, or bound the UI tests' workers (an xdist group) if it is memory.

**Done when:** Two full suites run at once on kmaster finish with no worker crash, or the entry names the cause and why it cannot be helped.
