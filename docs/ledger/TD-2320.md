## TD-2320: Forget goes ahead while a session launched on the login is still running

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-26
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 579465fae2e34ea29989eeae3c60ecd2

**Why:** Forget is to be refused while a live session runs on the login (§4.2b *⋯ on a login*). `LoginsMixin._login_users` (`src/sessionorc/agent_logins.py`) matches a record by `(s.login or s.profile) == name`, the login's bare name, but a launch on a login writes the record's `login` as the key `<tool>:<name>` (`agent_common`'s launch resolve returns `"login": lk`). So a live session launched on a login never matches, and Forget of the login it runs on goes ahead while it runs. Found while building TD-2288, whose `logins.record_key` reads a record's login key the design's way.

**Location:** src/sessionorc/agent_logins.py _login_users; tests/test_login_verbs.py

**Fix:** Match a live record by its login key: `logins.record_key(s.adapter, s.login, s.profile) == lk` in `_login_users`, which also takes a profile written as a shared name's key whole. A test: a live record with `login: claude-code:grind` refuses `login_forget grind`.

**Done when:** Forget of a login is refused while a live session launched on it (its record's `login` the key) runs, and the test passes.
