## TD-1385: A live check waits on an event gate, not the `Kind: live-check #<n>` comment — once the home's log can express a home-witnessed event (TD-1295)

**Priority:** High
**Type:** feature
**Added:** 2026-11-04 (the designer, split from TD-1375 at Paul's ask, relayed by ao-led-tds-ledger m-0dd01d81fbf5)
**Owner:** grinder
**Kind:** build
**Status:** Open
**Blocked by:** TD-1375, TD-1295
**Part of:** TD-1369
**Location:** `src/sessionorc/ledger.py` (`kind_of`, the live-check Kind comment, `BUILT`), `src/sessionorc/queue.py`; design §4.4 *Whether an entry may be picked*, §4.9b (a live check)

**Why:** ledgerboard's target design (ShiftLead/ledgerboard `docs/plans/target-design.md`) §7.2 step 4: a live check waits on an event gate rather than the `Kind: live-check #<n>` comment. Some live checks wait on something only the home witnesses (TD-300: the next look a cm-grind member sends), which none of v2.4's three typed checks (`pr-merged`, `file-contains`, `ref-includes`) can express; that needs `host-log` (TD-1295 here, its check type in ledgerboard). Built before TD-1295, those entries would lose their hold and become pickable, so this part, split from TD-1375, waits on it while the rest of TD-1375 does not (Paul, 2026-11-04).

**Fix:** write and read a live check's wait as an event gate (a typed check where one fits, `host-log` where the event is the home's), and drop the `Kind: live-check #<n>` comment as what holds; convert each open live-check entry in the same diff, none left without a hold. The PR changes ShiftLead's design (docs/design/) in the same diff wherever the behaviour it changes is written there.

**Done when:** a test that a live check's event gate keeps it out of the lanes until it lifts, a home-witnessed one (`host-log`) included, and no open live-check entry is pickable the moment the comment stops holding.

**Related:** TD-1375 (the rest of the former whole), TD-1295 (`host-log`), TD-1369, TD-300; ledgerboard's target design §4.2 (*Later: `host-log`*), §7.2 step 4.

**Log:**
- 2026-11-05: From TD-1295's design (2026-11-04): host-log counts only records of the ledger's own repo (ledgerboard TD-045 rule 7), so TD-300's wait (a cm-grind member's look, contractmatch's) can be no shiftlead host-log gate: it goes to until + a re-check entry (target design §7.3) unless contractmatch's ledger carries it, and this entry's host-log Done-when case uses a shiftlead event (a precheck-fail or a press).
