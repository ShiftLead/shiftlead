## TD-1923: A run sent away at its context bound reads early and waits on the person, so nobody restarts it

**Priority:** High
**Type:** debt
**Added:** 2026-11-17
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 8ae43dbfe6f6425ba3244ed830825dce
**Part of:** TD-1900

**Why:** A run the home itself sent away at its context bound (§6 rule 5's line) declares `ao progress restart` and is read early when it reported nothing done inside `RESTART_EARLY`, so no rule performs it and it waits on the person: designer-ao-1 sat idle twenty hours that way on 2026-11-15/16 with the person's One more round on TD-1829 behind it (TD-1900).

**Fix:** Build design §4.9a *Early is decided from the record*, the paragraphs *A pushed commit is new work* and *A run past its context bound is not early*, and *What counts toward the ceiling* (TD-1900):

1. `gitinfo.pushed_since(directory, since_iso, timeout=5.0)`: the newest commit sha of the branch's upstream with a committer date at or after `since_iso` (`git log @{upstream} --since=<iso> -1 --format=%H`, under `read_only_env`), else None — None on no upstream, a failed or timed-out read, or a directory not a worktree.
2. `agent.rpc_progress`'s `restart` branch reads `pushed_since(s.dir, s.created)` before `_restart_reading` and hands it in; `_restart_reading(s, now, pushed=None)` decides in this order: `said and not new` (a repeat, early, as today); `thrice`, only when `pushed` is None; a `pushed` sha → `{"early": False, "repeat": None, "words": "not early: pushed <sha[:7]> this run", "pushed": sha}`; inside `RESTART_EARLY` and not new, where `models.context_over(s)` → `{"early": False, "repeat": None, "words": "not early: context over its bound"}`; then today's branches. The mark keeps `pushed` as `restart_wanted.pushed`.
3. The replay (§6 rule 1) copies the mark's `pushed` into the `restarts` entry beside `done` and `left`; `_counted` leaves out a `wanted` entry with a `pushed` sha, as it does one with a new `done`.
4. A brief change or a relaunch still overrides the whole restart reading (`{early: False, repeat: None, words: None}`), as today, so neither new word is replied there.
5. Comments: the *a run that is over before it began did not run out of context* comment in `rpc_progress` (and the like one in `models.py`) names the two exceptions; `_idle_nudge`'s docstring names its `restart_wanted` return (design §6 rule 4).
6. Tests (`tests/test_restart_reading.py`, the tick's): inside `RESTART_EARLY`, nothing new, over its bound → not early, *context over its bound*, and rule 2 replays it when idle, clean and pushed; the same under its bound → early; a repeat of the same `done` over its bound → still early; a pushed commit since `created` → not early, *pushed <sha> this run*, and not a repeat though the claim is in the last two entries' `left` (the 2026-11-15 sequence: two prior entries leaving TD-1895, the third run pushed); the same with nothing pushed → repeat; `_counted` leaves out an entry with `pushed`, and counts four context-bound restarts with nothing pushed so the fourth trips `restart_ceiling`; `pushed_since` on a branch with no upstream → None.

**Done when:** A restart whose run pushed a commit since its record began is not early, not a repeat of a claim left and not counted toward the ceiling; one declared over the record's context bound with nothing new and no repeat is written not early (*not early: context over its bound*); rule 2 performs both on the next tick; a repeat of the same `done` stays early; tests above pass.
