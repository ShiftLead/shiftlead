## TD-1923: A run sent away at its context bound reads early and waits on the person, so nobody restarts it

**Priority:** High
**Type:** debt
**Added:** 2026-11-17
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 8ae43dbfe6f6425ba3244ed830825dce
**Part of:** TD-1900

**Why:** A run the home itself sent away at its context bound (§6 rule 5's line) declares `ao progress restart` and is read early when it reported nothing done inside `RESTART_EARLY`, so no rule performs it and it waits on the person: designer-ao-1 sat idle twenty hours that way on 2026-11-15/16 with the person's One more round on TD-1829 behind it (TD-1900).

**Fix:** Build design §4.9a *Early is decided from the record*, the paragraph *A run past its context bound is not early* (TD-1900):

1. `agent_common._restart_reading`: in the `inside and not new` branch, where `context_over(s)` (models.py) reads the record's last context reading over its `context_bound`, return `{"early": False, "repeat": None, "words": "not early: context over its bound"}`. The repeat branches (`said and not new`, `thrice`) run first and stay early whatever the reading. A brief change or a relaunch keeps zeroing the reading as today.
2. The ceiling is unchanged: such a restart counts as any wanted restart does.
3. `_idle_nudge`'s docstring names its `restart_wanted` return (design §6 rule 4 now says it).
4. Tests (the restart reading's own test file, and the tick's): a record inside `RESTART_EARLY`, nothing new, context over its bound → not early, words as above, and rule 2 replays it when idle, clean and pushed; the same under its bound → early; a repeat (same `done` again, or a claim left by the last two runs) over its bound → still early; the ceiling counts it.

**Done when:** A restart declared over the record's context bound, with nothing new done and no repeat, is written not early (*not early: context over its bound*) and rule 2 performs it on the next tick; a repeat stays early; tests above pass.
