## TD-2269: A team on another machine stays marked unable to run after the person changes the flow's model

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-26
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 5eb71d3ad1fb451d908347d284ae3d2e

**Why:** Audit of #4755 (TD-2068 slice 11). Design §4.9d *A team on a node* says the home "marks the team *cannot run*, naming the model, until its list or its flow changes". `node_cannot_run` (`src/shiftlead/team_show.py`) reads the mark as standing while the flow's **name** and the login list equal the mark's. It is given no model of the flow, and nothing in `src/` removes or refreshes the mark because the flow's models changed: `rpc_team_node_cannot` alone writes it, replacing it whole, and it otherwise goes only with the team's whole entry on the `host` record. A node team's flow is a repo's, changed by a pull request, or a package's (§4.9c: an org flow is not usable by a team on a node). So when the person cures the refusal by changing that flow's seat model, under the same name, to one a login on the node offers, the mark stands: `team_show` still says *cannot run*, naming a model the flow no longer asks for, and `on_node` (`src/shiftlead/stage_start.py`) sends no launch for the team.

Probe at 1124538c8: `team_show.view` for a team on `node1`, flow `build`, with `node_mark={model: opus, logins: [claude-code:a], flow: build}` and the team read as switched. With the flow's one stage on `opus`, and again with it on `sonnet`, `cannot_run` reads "ao-grind cannot run build: no login in its list offers opus on node1".

§4.9d's next sentence says "the read draws it only while the team's list and flow are the ones it names", which a build can read as the flow's name alone. The same sentence also lets a mark come back: with the list changed and then put back, and no new refusal recorded in between, `node_cannot_run` returns the old words again and the node is not asked a second time.

No test of the mark changes a flow's models.

**Location:** src/shiftlead/team_show.py node_cannot_run; docs/design/4.9d-teams.md

**Fix:** Read the mark as none where its `model` is no longer one the team's flow asks for (a stage's or an audit's), and say so in §4.9d *A team on a node*, with its history line. For a list changed and put back, either drop the mark at the write that changes the team's list or flow, or write in §4.9d that it returns.

**Done when:** A test marks a node team *cannot run* for a model, edits the flow so no stage or audit asks for that model, and reads no `cannot_run`; §4.9d says what an edited flow and a list put back do to the mark.
