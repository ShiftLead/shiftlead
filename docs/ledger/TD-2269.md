## TD-2269: A team on another machine stays marked unable to run after the person changes the flow's model

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-26
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 5eb71d3ad1fb451d908347d284ae3d2e

**Why:** Audit of #4755 (TD-2068 slice 11). Design §4.9d *A team on a node* says the home "marks the team *cannot run*, naming the model, until its list or its flow changes". `node_cannot_run` (`src/shiftlead/team_show.py`) reads the mark as standing while the flow's **name** and the login list equal the mark's. It is given no model of the flow, and nothing removes the mark when a flow is saved (`rpc_flow_save` re-keys renamed stages only). So when the person cures the refusal by editing that flow's seat model to one a login on the node offers, the mark stands: `team_show` still says *cannot run*, naming a model the flow no longer asks for, and `on_node` (`src/shiftlead/stage_start.py`) sends no launch for the team.

Probe at 1124538c8: `team_show.view` for a team on `node1`, flow `build`, with `node_mark={model: opus, logins: [claude-code:a], flow: build}` and the team read as switched. With the flow's one stage on `opus`, and again with it on `sonnet`, `cannot_run` reads "ao-grind cannot run build: no login in its list offers opus on node1".

§4.9d's next sentence says "the read draws it only while the team's list and flow are the ones it names", which a build can read as the flow's name alone. The same sentence also lets a mark come back: with the list changed and then put back, `node_cannot_run` returns the old words again, and nothing asks the node a second time.

No test of the mark changes a flow's models.

**Location:** src/shiftlead/team_show.py node_cannot_run; docs/design/4.9d-teams.md

**Fix:** Read the mark as none where its `model` is no longer one the team's flow asks for (a stage's or an audit's), and say so in §4.9d *A team on a node*, with its history line. Where the list changed and was put back, either drop the mark when `team_show` or the pick first reads it as stale, or write in §4.9d that it returns.

**Done when:** A test marks a node team *cannot run* for a model, edits the flow so no stage or audit asks for that model, and reads no `cannot_run`; §4.9d says what an edited flow and a list put back do to the mark.
