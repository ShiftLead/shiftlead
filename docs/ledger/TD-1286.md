## TD-1286: Sessions here still type ledger entries and board items by hand: every write goes through the helpers, as Paul's rule asks of every ledgerboard repo

**Priority:** medium
**Type:** feature
**Added:** 2026-10-30 (Paul, ledgerboard session `led-tds`: "Every repo that uses ledgerboard should only use the helpers (ledger.py, board.py) and never edit the ledger or board by hand")
**Owner:** designer
**Kind:** design-first
**Status:** Open 2026-10-30: filed held; the rule and its tools are agent-cadence#TD-206 and ledgerboard#TD-008, whose design rounds have not run
**Blocked by:** agent-cadence#TD-206, decision (Paul) — the board helper's design rounds, which settle this entry's question, then Paul's go
**Location:** `src/sessionorc/board.py` (`add`, `add_decided`, `edit_line`, `_insert`); the Add entry flow and `ao td` (each ledger write); the team briefs and seat templates that tell a session to write a ledger or board file; `docs/cadence.toml` (the pin that brings `ledger.py` and `board.py`); `scripts/vendor_ledgerboard.sh` (v2.3)

**Why:** Paul set the rule on 2026-10-30: every repo that uses ledgerboard writes its ledger and its board only through the helpers, `ledger.py` and `board.py`, never by hand. agent-cadence carries it (agent-cadence#TD-173 and its builds agent-cadence#TD-197 to agent-cadence#TD-202 for the ledger, agent-cadence#TD-206 for the board and for every consuming repo), and ledgerboard#TD-008 adds the board writers it needs. ShiftLead is one of those repos, and its sessions still type ledger entries and board items by hand wherever a brief or a seat tells them to write one. Its own code already goes through ledgerboard for most board writes (`board.py` adds plain and decided items through `item_line()` and `decided_line()`, and edits through `edit_line()`), but has no writer for a new `decide` item with `Answers:` and a detail block, or for an archive.

**Ask:** should ShiftLead's own code keep calling ledgerboard's writers in process, or call `ledger.py` and `board.py` like every session must?

**Fix:** design first, after agent-cadence#TD-206's rounds:
- **Sessions:** every brief, seat template and procedure here that tells a session to write a ledger or board file names the `ledger.py` or `board.py` command instead, so no session in this repo types either file; the cadence check's ledger and board rows (agent-cadence#TD-201, agent-cadence#TD-206) then hold PRs to it.
- **Code:** the Ask's answer. Either `board.py` (here), the Add entry flow and `ao td` keep calling ledgerboard's writers in process, which are the same writers the helpers wrap, or they shell out to `ledger.py` and `board.py`. Either way they gain the v2.3 writers for a new `decide` item and the archive.
- **The pin and the vendor:** bump to the agent-cadence that carries `ledger.py`'s commands and `board.py`, and vendor ledgerboard v2.3 (after TD-1282 brings v2.2), each consumer's `fmt` PR beside it.

**Done when:** no brief, seat template or procedure here tells a session to edit a ledger or board file, the Ask is answered and built, and this repo pins and vendors the releases that carry the helpers.

**Related:** agent-cadence#TD-206 (the board helper and the rule for every consuming repo), agent-cadence#TD-173 and agent-cadence#TD-202 (the ledger's), ledgerboard#TD-008 (the board writers, v2.3); TD-1282 (vendors v2.2 first).
