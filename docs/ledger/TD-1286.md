**Type:** feature

**Owner:** designer
**Kind:** design-first
**Status:** Designed 2026-11-04 (the designer) — design §4.4 *A session writes the ledger and the board only through the helpers*, §4.9 *Two ways out*; builds TD-1356 (the pin bump and AGENTS.md), TD-1357 (the shipped briefs), TD-1358 (docs/briefs), TD-1360 (new entries through ledger.py new, after agent-cadence#TD-188), TD-1359 (the code's ledger half, after ledgerboard v2.4). **Location:** `src/sessionorc/board.py` (`add`, `add_decided`, `edit_line`, `_insert`: the board half, TD-1330); `src/shiftlead/briefs/entry.md` (the drafting brief the Add entry flow and `ao td add` hand an ask to), `AGENTS.md` and `docs/briefs/` (each step that tells an agent to write a ledger entry or board item); `src/sessionorc/ledger.py` (the ledger half, v2.4); `docs/cadence.toml` (the agent-cadence pin, whose wrappers name the helper commands); `scripts/vendor_ledgerboard.sh` (v2.3)

**Why:** Paul set the rule on 2026-10-30: every repo that uses ledgerboard writes its ledger and its board only through the helpers, `ledger.py` and `board.py`, never by hand. agent-cadence carries it (agent-cadence#TD-173 and its builds agent-cadence#TD-197 to agent-cadence#TD-202 for the ledger, agent-cadence#TD-206 for the board and for every consuming repo), and ledgerboard#TD-008 adds the board writers it needs. ShiftLead is one of those repos, and its sessions still type ledger entries and board items by hand wherever a brief or a seat tells them to write one. Its own code already goes through ledgerboard for most board writes (`board.py` adds plain and decided items through `item_line()` and `decided_line()`, and edits through `edit_line()`), but has no writer for a new `decide` item with `Answers:` and a detail block, or for an archive.

**Fix:** the agents' half design first, after agent-cadence#TD-206; the code's halves are builds:
- **Agents:** the Add entry flow and `ao td add` write no file; they hand the words to a drafting seat, whose brief (`src/shiftlead/briefs/entry.md`) has it write the entry by hand, and `AGENTS.md` and `docs/briefs/` tell a session to write ledger entries and board items. Each of those names the `ledger.py` or `board.py` command instead, so no agent here types either file; the cadence check's ledger and board rows (agent-cadence#TD-201, agent-cadence#TD-206) then hold PRs to it. `entry.md`'s step adding a Summary row is stale besides, since the v2 ledger has none.
- **Code (Paul, 2026-10-30: "ShiftLead's own board.py should call ledger.py and board.py. Any place in shiftlead that makes ledger or board edits should do so"):** every ledger or board edit ShiftLead's code makes goes through the helpers. Since ledgerboard's target design §1.1 (Paul's go 2026-11-02) the helpers are ledgerboard's writers, called in-process: the board half, `src/sessionorc/board.py` (`add`, `add_decided`, `edit_line`, `_insert`), is TD-1330; the ledger half, `src/sessionorc/ledger.py` converted to call ledgerboard's `ledger.py`, is v2.4's (target design §7.2 step 4); any later code that writes either file does the same.
- **The pin and the vendor:** v2.3's is TD-1330; v2.4's, which brings `ledger.py`, follows it.

**Done when:** no brief, seat template or procedure here tells a session to edit a ledger or board file, the Ask is answered and built, and this repo pins and vendors the releases that carry the helpers.

**Related:** TD-1330 (the board half, v2.3); ledgerboard target design §1.1, §7.2 (ledgerboard#57); agent-cadence#TD-206 (the board helper and the rule for every consuming repo), agent-cadence#TD-173 and agent-cadence#TD-202 (the ledger's), ledgerboard#TD-008 (the board writers, v2.3); TD-1282 (vendors v2.2 first).
