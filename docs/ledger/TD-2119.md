## TD-2119: A Gemini conformance walk can fail at its permission step after Enter was pressed

**Priority:** Low
**Type:** debt
**Added:** 2026-11-23
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 32f01ff066e2408ca8ad50b2fef465ca

**Why:** On 2026-11-23, one of four Gemini conformance walks that reached the permission step failed there: the walk pressed Enter on the dialog's first choice, and the record still read `needs-you` when the step gave up. The other three passed all 7 steps on the same build and profile. A walk that fails this way says nothing about the adapter, and whoever reads it has to run it again to find out.

**Location:** scripts/conformance.py

**Fix:** The cause is not yet found. Read `allow` in `scripts/conformance.py` and what the pane showed when Enter was pressed: the likely case is an Enter sent before Gemini's dialog takes input, or a hook's state not yet delivered when the step's wait ends. Reproduce it with `--capture`, which keeps each step's pane, then fix what it shows. Never launch bare `gemini` to reproduce it: its auto-updater ran a real global npm install on 2026-11-23, and adapter launches turn it off.

**Done when:** The cause is named on this entry, and ten Gemini walks in a row pass the permission step, or the step's failure names what the tool did so that a rerun is not needed to read it.
