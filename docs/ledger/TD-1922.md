## TD-1922: The touch rule in the terminal design still names the old terminal release

**Priority:** Low
**Type:** debt
**Added:** 2026-11-17
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 7e72b2409a4448678a3b2e1e81bb7a61

**Why:** Design §4.6 (`docs/design/4.6-transport.md:171`) says "**A touch does not select**: xterm.js 5.5 has no touch selection". PR #4056 (TD-1918) moved the vendored terminal to `@xterm/xterm` 6.0.0 (`src/shiftlead/ui/static/vendor/README.md:10`), and changed goal 12 in `docs/design/2-goals.md` for it, but left this sentence naming a release the repo no longer ships. The present-tense design names a version it does not run, and nothing in the PR shows xterm 6 still lacks touch selection.

**Fix:** Check whether xterm.js 6.0.0 has touch selection (a headless touch probe on the vendored file). If it has none, reword the sentence to "the vendored xterm.js has no touch selection" (no version, so the next bump leaves it true). If it has, the design's touch rule needs deciding first.

**Done when:** §4.6's touch sentence names no version, or names 6.0.0 with a probe behind it.
