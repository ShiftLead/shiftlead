## TD-1229: The forget-after-keep test failed once under the full suite and passes alone

**Priority:** Low
**Type:** debt
**Added:** 2026-10-29
**Owner:** grinder
**Kind:** build
**Status:** Open
**Blocked by:** event (forget-after-keep-flake)

**Why:** a full `pdm run test` on #2663's branch failed this one test with `assert await wait_for(gone)`. That PR changed only `docs/briefs/` and a ledger file. Within `wait_for`'s default 6 s, the closed record never left `list`. The keep is 0 s, so only a tick that did not reach the forget for 6 s explains it, which is the same shape as TD-1218 (a tick slowed under the full suite's load). A precheck that goes red for that reason costs a rerun of the whole suite and reads as the PR's fault.

**Location:** `tests/test_agent_paths.py` (`test_closed_sessions_are_forgotten_after_keep`, the `wait_for(gone)` at :88); the tick's forget of a closed record past `agent_common.CLOSED_KEEP` (patched to 0 s)

**Event (forget-after-keep-flake):** A precheck the home witnesses fails this test again.
check: host-log witnessed kind precheck-fail "tests/test_agent_paths.py::test_closed_sessions_are_forgotten_after_keep"

**Fix:** make the failing assertion print the record's state and `closed_at` and the time of the tick's last `_reconcile` (`agent_tick.py`, the forget past `CLOSED_KEEP`), as `test_first_prompt.py`'s `_unmarked` does for TD-1218, so the next failure names its cause. If the forget waits behind a tick a slow tmux call holds, the test's `wait_for` gets a longer timeout than the tick's slowest call.

**Done when** the cause is named from a failure and the test's wait outlasts the tick's slowest call, or a month of full runs passes without it.
