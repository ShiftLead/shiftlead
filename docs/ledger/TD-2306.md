**Why:** Audit of #4803 (TD-2070 slice 3): a container node's spend names the login beside the account (design §4.4a, §4.9e *A team on a node*).

Each change below to `src/sessionorc/agent_spend.py`, made alone at 04da9e813, left tests/test_spend.py and tests/test_link.py passing. The three were also made together, and the 85 `tests/*.py` files whose text holds `spend` stayed green (2519 passed, 7 skipped). The probe was one temporary test (removed after) on a node-mode agent with two metered profiles of one account, run unchanged and then with the three together.

- `_node_logins`'s `try` / `except logins.LoginError` removed. Probe, on `hookstub` (whose billing does not read `logins.yml`), a file that does not parse: unchanged, the pass makes 4 sends, none naming a login; changed, `LoginError` and no send. Its docstring says "a file the person is mid-edit on never stops the pass", and #4803's body that a node whose file does not read sends no `login`.
- In `_take_spend`, `if held.get(prof) != login:` made `if prof not in held:`. Probe, `hookstub:api` and then `hookstub:other` taken for one profile of one host: unchanged, the home keeps `hookstub:other`; changed, it still keeps `hookstub:api`.
- In `_refresh_spend_inner`, only the first login of an account's group kept (`if not g["logins"] and (login := ...)`). Probe, the two profiles, each a login: unchanged, both are sent with their logins; changed, one is sent with none.

The test of this behaviour, `test_a_switched_nodes_spend_names_the_login_and_the_home_keeps_it_beside_the_profile`, runs one profile with a file that is absent or reads, and the home takes one valid login.

With the Claude Code, Gemini CLI or Grok Build adapter, a file that stays broken already stops that tool's spend on the unchanged code: their `billing_for` reads `logins.yml` too, through `profiles.get`, and answers None, so `_metered_of` takes the profile as a subscription. With those adapters the first guard matters only where the file stops parsing between those two reads; a break of it would then raise out of the pass. A break of the second or third would leave the home's `spend.json` with a stale or missing login; at 04da9e813 no code under `src/` reads that map back.

**Location:** tests/test_spend.py; src/sessionorc/agent_spend.py _node_logins, _refresh_spend_inner, _take_spend

**Fix:** In tests/test_spend.py: on `hookstub`, a switched node whose `logins.yml` does not parse still sends its spend, naming no login; a second login taken for a profile replaces the first in memory and on disk; two profiles of one account are each sent with their own login.

**Done when:** Each of the three changes fails a test.
