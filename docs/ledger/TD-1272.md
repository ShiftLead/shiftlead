## TD-1272: No test holds `AO.pathProvider`'s eight-run cap, with or without pieces

**Priority:** Medium
**Type:** debt
**Added:** 2026-10-30 (test-audit-ao-1, auditing the last ten merged PRs)
**Owner:** grinder
**Kind:** build
**Status:** Open
**Location:** `src/shiftlead/ui/static/app.js` (`AO.pathProvider`: `const runs = [...joined, ...alone].filter((r) => (r.piece ? whole <= 8 : ++whole <= 8))`); `tests/test_ui_focus_paths.py`

**Why:** #2722 (TD-1262) replaced `.slice(0, 8)` with a filter that counts wholes, not pieces; its archived entry says *the second round's catch: pieces had taken the cap's slots*. Two probes at `origin/main` 255921409, each run with `PYTHONPATH=$PWD/src pdm run pytest -q tests/test_ui_focus_paths.py tests/test_ui_transcript_paths.py`: (1) `++whole <= 8` → `++whole <= 80` gives all passed; (2) `r.piece ? whole <= 8 : …` → `r.piece ? true : …` gives all passed. The only new test of the cap, `test_a_runs_pieces_are_asked_beside_eight_runs_eight_paths_an_ask`, feeds three wholes and nine pieces, so the filter keeps every run under any bound; its name says *beside eight runs* but no row has nine. A row of nine path runs, or eight with pieces, would be underlined past the cap, or lose its pieces, and nothing fails.

**Fix:** a row with more than eight wholes, some holding `,` or `#`, in the `pathProvider` probe: assert the ninth whole is not asked and a piece of each of the first eight still is.

**Done when:** `++whole <= 8` → `++whole <= 80`, and `r.piece ? whole <= 8` → `r.piece ? true`, each fail a test.

**Related:** TD-1262, #2722
