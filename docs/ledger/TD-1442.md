**Why:** `tests/test_cadence_policy.py::test_a_merged_fail_marks_the_row_at_once_and_one_pr_is_read_a_run` failed once in #3011's precheck (head 9ec2372, a ledger-only PR) and passed on the re-run: `assert gh.ran == [842, 843]` saw `[842, 843, 843]` (line 271). That task races the test's next explicit pass, and both read PR 843.

**Fix:** In the test, make `_keep_running` start no cadence pass: set `agent._cadence_read_at = now` before the call, or monkeypatch the rule-10 block. Or await `agent._cadence_task` before the explicit pass, if it was started. `_cadence_read_at` starts at `datetime.min` (`src/sessionorc/agent.py:717`), so the first `_keep_running` in each test always starts the detached pass, and `park_ticks` does not stop it. The same hazard stands at the other `_keep_running` calls in the file: `test_a_fail_types_the_line_once…` (:222, the call that starts the task, which can overlap the explicit passes at :228 and :232), `test_a_pass_writes_the_entry…` (:207) and `test_who_is_read…` (:314). Fix them all the same way. Setting `_cadence_read_at` makes each test's explicit pass the only reader.
