## TD-1400: A board line's bare TD-n is homed on another repo's card when its own repo's entry is archived

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-05
**Owner:** grinder
**Kind:** build
**Status:** Resolved 2026-11-05
**Id take:** 54178be088a1453eacec052427315b1a

**Why:** A board line can be drawn on the Queue under another repo's card, so the person answers what looks like one repo's question on a different repo's entry. On 2026-11-05 contractmatch's board `look` line of 2026-10-22 (`Context: TD-051 (archived), TD-017`, meaning contractmatch's own archived TD-051) showed as *Decide (1)*, 7 days overdue, on ledgerboard#TD-051's card (reported by ao-led-tds-ledger, a ledgerboard person-session, through `ao td add --repo shiftlead`).

The cause, read at origin/main: `item_home` (`src/shiftlead/ui/queue.py` ~60–64, TD-1355) qualifies a bare `TD-n` in a board line's `Context:` with the line's own repo only when that qualified key is on an open card. Otherwise it looks the ref up bare, and `card_index` (`src/sessionorc/queue.py` ~80–105) resolves a bare id to whichever single repo holds it on an open card. `asked_entries` (`ui/queue.py` ~95–112) always qualifies a bare ref with the line's repo, so the two readers disagree about which entry the same line asks about. `item_home` also reads only `refs[0]`, so a line whose first ref is closed never reaches the open entry it names second. Design §4.4 *The card's status* and §4.5 screen 12 (around line 761) read a bare `TD-n` as the line's own repo's entry; the bare fallback to another repo's id does not follow that whenever the own repo's entry is archived.

**Location:** src/shiftlead/ui/queue.py (item_home, asked_entries); src/sessionorc/queue.py (card_index); design §4.5 screen 12, §4.4 The card's status

**Related:** TD-1380 (its step 2 changes `item_home`'s home lookup too), TD-1355 (the qualification this entry narrows), TD-1362 (`asked_entries`), TD-1364.

**Resolved:** 2026-11-05 (PR #2973)

**Done when:** A test where a board line from repo A names a bare `TD-n` that A holds only archived, while repo B holds `TD-n` on an open card, homes the line in the Inbox (or on A's card for a later open ref), never on B's card. A test that a line whose first ref is held by no card and whose second is held homes on the second's card. `item_home` and `asked_entries` agree on which entry each such line names.
