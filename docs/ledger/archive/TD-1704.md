**Why:** Found by the test seat auditing #3512 (TD-1696). The PR's one new test, `test_the_reporter_outwaits_a_hooks_bound_and_never_overlaps_the_next_report` (tests/test_statusline.py), asserts only the constants: `REPORT_WAIT > 5.0` and `3 * REPORT_WAIT < STATUSLINE_REFRESH`. The fix is that the forked reporter waits that long, and that line is `fn(REPORT_WAIT)` in `aside` (src/shiftlead/adapters/claude_code/hook.py:382). Only a coarse test would catch it going back.

Probe on origin/main (cecdf508b): change hook.py:382 to `fn(5.0)` (the old bound) and run `pytest -q tests/test_statusline.py`: 10 passed. Reverted afterwards. The `home` fixture (:173) replaces `aside` with `lambda fn, wait=...: fn(hook_mod.REPORT_WAIT)`, so the new test and the unit tests never run the real child's call. Only the integration test `test_a_lagging_agent_still_finds_the_reporter_alive_and_the_line_does_not_wait` runs the real `aside` child, against an agent lagging 3 s, so it pins the child's wait only from below at about 3 s; no test reads the timeout handed to the socket steps, and 5 s passes. The same mutation on #3517's `review_pr` clause fails its test, so that PR is covered.
