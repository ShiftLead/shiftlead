**Kind:** build
**Status:** Resolved 2026-11-02
**Resolved:** 2026-11-02 — #2798: `test_subscribe_and_load_keep_what_the_store_says`, failing under each of the five mutations

**Why:** each line below was changed in a scratch worktree (restored after) and `PYTHONPATH=$PWD/src pytest -q tests/test_push_store.py` still read *5 passed*:
- `subscribe`'s `elif same is not None: same.update(endpoint=ep, keys=ks)` → `pass`. The test re-subscribes the same endpoint with the same keys, so a changed `keys` for a known endpoint is never checked to be stored.
- `subscribe`'s `devices = [d for d in devices if d is not old and d is not same]` → `d is not old`. No test has `replaces` name a device while the new endpoint is already another listed device, so a duplicate id can be listed.
- `load`'s device filter `isinstance(d, dict) and d.get("id") and d.get("endpoint")` → without the `endpoint` test. No test writes a malformed `push.json`; the docstring says such devices are dropped.
- `load`'s `isinstance(doc.get(k), str) and doc[k]` → `doc.get(k)`: a non-string `key` or `public_key` in the file is passed on. Same gap.
- `subscribe`'s label cap `name[:80]` → `name`: no test gives a label over 80 characters.

**Location:** `src/sessionorc/push.py` (`load`, `subscribe`); `tests/test_push_store.py`

**Fix:** add the cases to `tests/test_push_store.py`: same endpoint with new keys; `replaces` onto an endpoint already listed (one device remains); a hand-written `push.json` with a device lacking an endpoint and a non-string `key`; an 81-character label.
