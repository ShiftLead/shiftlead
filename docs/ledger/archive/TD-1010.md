## TD-1010: `ao repo add <path> [--adopt]` registers a repo, and offers dev-cadence's adoption as a PR for one without it

**Priority:** Medium
**Type:** feature
**Added:** 2026-10-25 (the designer, from TD-1009)
**Owner:** grinder
**Kind:** build
**Status:** Done
**Part of:** TD-1009
**Location:** `src/shiftlead/cli.py` (`cmd_repo`: the `add` word, beside `init`'s dispatch; the adopt's run and the PR), a new `add_repo` RPC at the home (`agent_serve`, person-only through `agent_common.person_only`), `src/sessionorc/hosts.py` (`default_repos_registry()`, the home's `repos.txt`), `src/sessionorc/gitinfo.py` (a scratch clone); a new `tests/test_repo_add.py`; design §4.7 **`ao repo add`**, §5 *Repos*

**Why:** TD-1009 (ADR 2026-10-25, *Decision* 1): adoption is a PR the person sees, and registering a repo today is a hand-edited line in `repos.txt`.

**Fix:**
- `ao repo add <path> [--adopt]`, a person's own: the RPC refuses a session's caller as `set_settings` is. The path is resolved to its main checkout (`git rev-parse --path-format=absolute --git-common-dir`'s parent); one already in the home's roster (or the imported dev-cadence roster) is refused as there, except `--adopt` on an unserved one.
- A checkout holding `docs/cadence-sync.lock`, or dev-cadence's source (its root holds `sync.sh` and `files/`: a fresh home's first `add`, needing no dev-cadence checkout in the roster), is appended to the home's `repos.txt` (`hosts.default_repos_registry()`, or `repos_registry` where `hosts.yml` names one) by the `add_repo` RPC, person-only (`mail.PERSON_ONLY`), which then reads the repo at once; *added <name>*. The client calls the RPC; it never writes the file itself.
- One without: the dev-cadence checkout is the roster's checkout whose root holds `sync.sh` and `files/` (none: refuse, *no dev-cadence checkout in the roster: clone ShiftLead/dev-cadence and add it first*). A scratch clone of the repo (`git clone --shared <checkout> <tmp>`, its `origin` set to the checkout's, detached at `origin/<default>` after a fetch) runs `<dev-cadence>/sync.sh <tmp>` under a `timeout` — never a worktree, whose common directory is the person's checkout, where `sync.sh` writes per-clone settings; the reply lists `git status --porcelain`'s paths and ends *`ao repo add <path> --adopt` opens these n files as a PR*; the clone is removed and nothing is added.
- `--adopt`: the same run, then `git remote set-url origin "$(git -C <checkout> remote get-url origin)"` (an `origin` not on GitHub is refused, *ao repo add opens its PR on GitHub*), `git switch -c cadence-adopt`, one commit (*adopt dev-cadence <commit>*), `git push -u origin cadence-adopt` and `gh pr create --body-file` naming dev-cadence's commit; never a push to the default branch. The path is appended to `repos.txt`; the reply names the PR. The clone is removed (the branch stays on the remote).
- `--adopt` on a registered, unserved repo runs the same adopt and PR whatever the lack: `sync.sh` writes the synced files and the lock (curing a missing tree or gate) and seeds the ledger only where it is missing (curing a missing ledger); a ledger that is there and does not parse is not the adopt's to cure, so that lack's words name the reader's reason and no `--adopt`.
- Under dev-cadence TD-129 the adopt is the launcher's `adopt`, read from its build, through TD-1014's resolver; until then `sync.sh`.
- The scratch clone is made under `$TMPDIR`, a dev-cadence temp root (`$TMPDIR`, `/tmp`, `/var/tmp`, or `$CADENCE_TEMP_ROOTS`) (required: `sync.sh` appends a target outside a temp root to `~/.config/dev-cadence/repos.txt`, dev-cadence TD-068). ShiftLead never writes that roster; the `--adopt` reply and the PR body name the person's `<dev-cadence>/sync.sh <checkout>` run after the merge, which sets up the hook shim and registers the checkout, and `seams` warns while a served repo is on the home's roster but not the imported dev-cadence one (*not on dev-cadence's roster: sync-all will not reach it — `<dev-cadence>/sync.sh <checkout>`*). Tests, with the roster under a fake `XDG_CONFIG_HOME` outside every temp root (`sync.sh`'s guard skips a temp target only when the roster itself is not under one): the offer run, its clone under `$TMPDIR`, leaves the roster byte-identical; a clone placed outside the temp roots does register, so the guard is shown to be the reason.
- The lacks' cure words switch from TD-1011's interim *`<dev-cadence>/sync.sh <checkout>`, then a PR* to `ao repo add <path> --adopt`, and *adoption PR #n open* is read from the `cadence-adopt` head.
- dev-cadence's own checkout (its root holds `sync.sh` and `files/`) is added as served with no lock (§5 *The seams*), so on a fresh home it is the first `add`, which the adopt of every other repo then needs.
- `add` is a word of `ao repo` as `init` is: a repo directory called `add` is read by its path.

**Done when:**
- The word runs on the home machine only (the paths are the home's); elsewhere it is refused, *run ao repo add on the home*.
- Tests, with a temp home and two temp repos (one with a lock, one without) and a stub dev-cadence checkout whose `sync.sh` writes two files: the first is added to `repos.txt`; the second is offered (the two paths listed, nothing added, no clone left, and the person's checkout's `.git/config` and `.git/info/exclude` unchanged); `--adopt` commits on `cadence-adopt` and calls a stubbed `gh pr create` with a body file, and adds the line; once the adoption is merged on the temp origin, the next pull and reading serve the repo; a registered repo holding the lock but not `scripts/check_cadence.py` is offered and adopted the same way; the RPC refuses a session's caller; the home never merges the `cadence-adopt` PR (it is the person's); a path already listed is refused; no dev-cadence checkout is refused in the words above.
- `ao repo --help` lists `add`.

**Related:** TD-1009 (its design), TD-1011 (the unserved words name this cure), TD-590 (the roster).

**Resolved:** 2026-10-25 (grinder-ao-1, PRs #2353, #2356 and this one) — built in three slices as §4.7 `ao repo add` says. #2353: `ao repo add <path>` calls the home's `add_repo` RPC (person-only, at the home), which appends the main checkout to `repos.txt` when it holds dev-cadence or is its source, refuses one already in the roster, and returns `served` from the seams reading. #2356: a checkout without dev-cadence is offered its adoption from a `--shared` scratch clone under a dev-cadence temp root (`shiftlead/adopt.py`); `--adopt` commits it on `cadence-adopt`, pushes it, opens the PR and adds the repo unserved, and a re-run finds the open PR; the lacks' cure reads `ao repo add <root> --adopt`, or *adoption PR #n open* (`seams.with_adoption`). Slice 3: the Repo page and `ao doctor` warn while a served repo is not on dev-cadence's roster, *not on dev-cadence's roster: sync-all will not reach it* (`seams.on_cadence_roster`). The home never merges the adoption PR: an unserved repo's PRs get no gate run (TD-1011).
