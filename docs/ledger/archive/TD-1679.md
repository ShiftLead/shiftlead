**Location:** tests/test_td_max_seat_send.py test_a_seats_extras_at_their_fill_ceiling_fill_no_more; src/sessionorc/agent_mail.py _seat_pick

**Why:** `tests/test_td_max_seat_send.py::test_a_seats_extras_at_their_fill_ceiling_fill_no_more` (#3464, TD-1547) says in its docstring that "the seat's own record's fills do not count, and fills older than the window fall out". It does not pin either. The test sets the own record to `FILL_CEILING` recent fills, tl3 to `FILL_CEILING` old fills, and tl2 plus tl3 to six recent extras' fills in all — so the extras' recent total already reaches `FILL_CEILING` by itself. Probes in a worktree on `origin/main`, each with the PR's test run (`PYTHONPATH=$PWD/src pdm run pytest -q tests/test_td_max_seat_send.py -k fill_ceiling`): (1) `agent_mail._seat_pick`'s `and _recent(e.get("at"), now, FILL_WINDOW)` replaced by `and True` (the window ignored) — **passes**; (2) `for r in extras` replaced by `for r in [own, *extras]` (the seat's own fills counted) — **passes**. Only the `>=` guard itself is caught (`>=` to `>` and `if False` both fail). So the two behaviours the docstring and the design (§4.9 *The bounds*) name — a window, and the seat's own fills apart — could go back unseen: a seat's extras would be refused forever after six fills in all time, or the techlead's own restarts would shut its extras out.

**Resolved:** 2026-11-11 (PR #3485)

**Done when:** with the window ignored, or the seat's own record's fills counted, in `_seat_pick`, `tests/test_td_max_seat_send.py` fails; with the code as it is, it passes.
