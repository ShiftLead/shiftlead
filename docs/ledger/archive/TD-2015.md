## TD-2015: A test run that dies leaves its scratch directory in the shared temp folder for good

**Priority:** High
**Type:** debt
**Added:** 2026-11-19
**Owner:** grinder
**Kind:** build
**Status:** Resolved 2026-11-19
**Id take:** 0f5364a520b54f8881181f00fdea0191

**Why:** Every test run's scratch root is a `tempfile.TemporaryDirectory(prefix="aoscr-", dir="/tmp")` per xdist worker (tests/conftest.py `_scratch_root`). A run whose workers are killed, or whose session is restarted mid-run, never reaches the cleanup, so its directory stays in `/tmp` for good. On 2026-11-19, 182 such directories (back to 2026-11-18) held about 45,000 inodes of the shared `/tmp` tmpfs. That tmpfs reached 99% of its inodes the same day, and a precheck of #4218 then failed every test at setup with *No space left on device: '/tmp/aoscr-…'*, the likely cause of TD-2012's dying workers too. A crash leaks more scratch, which fills `/tmp` further, so it feeds itself.

**Location:** tests/conftest.py (_scratch_root)

**Resolved:** 2026-11-19 (PR #4222)

**Done when:** A test run removes the `aoscr-` scratch roots of runs that have ended, and a test shows a dead run's root removed (a read-only directory in it), a live run's kept, and an unowned one left alone.

**Log:**
- 2026-11-19: The precheck's own tree leaks too: its trap's rm -rf of /var/tmp/pc.* fails on read-only files a cache-sweep test leaves (test_a_dry_cache_pass_takes_no…/cache/trees/*/files/scripts/s.py, Permission denied), so each precheck leaves its tree on disk. The same fix should make those files writable, or the test should.
- 2026-11-19: archived: Resolved — Each run records its scratch root's owner and sweeps the roots of runs that have ended; the disk test's read-only trees are made writable at teardown.
