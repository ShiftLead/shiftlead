**Why:** Part of TD-2106. Nothing ages what runs outside a seat's scratch leave in shared temp space. Read on 2026-11-23: `/tmp/claude-1000` held 85,860 inodes, of which about 36,000 had been quiet for three days and held no git work, and 382 `pdm-build-*` directories sat in `/tmp`.

**Ask:** Should the grinders build the sweep that removes old build leftovers and unused Claude Code temp files after three quiet days?

**Location:** src/sessionorc/tempsweep.py, src/sessionorc/agent_tick.py, src/shiftlead/adapters/claude_code, design 4.3 and 4.6

**Resolved:** 2026-11-24 (PR #4470) — src/sessionorc/tempsweep.py, tests/test_tempsweep.py, design §4.6 tool temp

**Done when:** With fixture roots: an unused project directory, loose file and clean clone past three days and a `pdm-build-*` past a day are removed, each counted in `removed` and adding nothing to `held`. Kept: an entry written within the age; one with an old modification time and a fresh change time; one written since the oldest live outside session started, while an entry older than that start is still removed; every entry while an outside session has no start time; one a live or outside session works in; a project directory named for a live session's working directory; a clone holding git work; a symlink; another uid's entry; anything overlapping a transcript store; an entry when a session goes live between the first read and the re-read. An absent root removes nothing and leaves the reading whole. A clone whose git walk is cut short is kept. Nothing is removed where the root is a symlink or another uid's (the kind reads *partial*), where an adapter cannot name its transcript stores, or where its sessions cannot be read. A dry run removes nothing and reads *partial* past its deadline; a real pass past its budget stops and the next pass takes the rest; a scratch home's agent runs neither part. A leftover or entry whose removal fails leaves its parent's mode unchanged and is tried again next pass. A managed session's registry entry with an old `startedAt` does not extend the age. The fixture registry entry is copied from the shape of a real `sessions/<pid>.json`, with `startedAt` in milliseconds, and an outside session with no start time logs a warning.
