## TD-2159: A review stage gives its counts of findings and of those it would not ship with, and the posted review comment carries them

**Type:** feature

**Owner:** grinder
**Kind:** build
**Status:** Resolved 2026-11-25

**Why:** Part of TD-2077 (design §4.9c *What a run records, for comparing flows*, §4.7 `ao stage end`). The home's `cadence-review:` comment for a review stage writes 0 findings for a ship and 1 for changes wanted, since the session gives no count, so a pull request's findings cannot be compared between flows.

**Ask:** Should the grinders build the design that records what each flow's run leaves behind, or run one more review round first?

**Resolved:** 2026-11-25 (PR #4671)

**Done when:** Tests show the options refused on a non-review outcome (`other` among them, a job's `work-pushed` and an audit's `nothing-found`), `changes-wanted` refused without a blocking count above 0, `ship` refused with one and reading 0 for both without them, `m` above `n` refused, `--blocking` without `--findings` refused, `ship --findings <n>` alone reading `m` as 0, every refusal made before the review comment is posted, a repeated call answered as the first with any changed counts ignored (a well-formed repeat of an entry's `ship` among them), the row's `findings` and the posted comment's count both matching, the `ship` row of an `only-when` stage's pass carrying no `findings`, a review stage's session on a job's record having its `--findings` accepted and posted on its comment and its row carrying no `findings`, and the review stage's told text and brief naming the options.
