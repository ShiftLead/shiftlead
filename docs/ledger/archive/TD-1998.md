## TD-1998: The Tools read's guards against a bad known-tools table have no test

**Priority:** Low
**Type:** debt
**Added:** 2026-11-19
**Owner:** grinder
**Kind:** build
**Status:** Resolved 2026-11-19
**Id take:** fe93ad9dc899409eacb984fa0bc5be98

**Why:** PR #4173 (TD-1973) made `tools.read` survive a bad known-tools table: `known = adapters.known_tools()` sits in a `try/except Exception` ("a bad table row costs the known tools, never the supported tools' cards"), and the row loop skips `not isinstance(row, dict) or "name" not in row`. Mutation probes in src/sessionorc/tools.py, each run with `PYTHONPATH=$PWD/src pdm run pytest -q tests/test_tools_read.py`: changing the handler to `except ZeroDivisionError:` leaves 11 passed; replacing the row guard with `if False:` leaves all of tests/test_tools_read.py and tests/test_tools_shell.py passing (23 passed). The only use of `known_tools` in the tests is a monkeypatch to a well-formed list (tests/test_tools_read.py:48), so neither documented resilience is exercised: a non-dict row would raise AttributeError and a raising table would take down the whole Tools read, the very thing the comments promise cannot happen.

**Location:** tests/test_tools_read.py
