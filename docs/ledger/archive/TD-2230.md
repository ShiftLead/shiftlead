## TD-2230: The rules for a Queue card's edge colour leave out that a waiting card turns orange for an early question

**Priority:** Low
**Type:** debt
**Added:** 2026-11-26
**Owner:** grinder
**Kind:** build
**Status:** Resolved 2026-11-26
**Id take:** d9b1699150904876abd54334fd6b7d24

**Why:** Audit of #4691 (TD-2184 slice 3). The two places that state the order of a Queue card's left-edge colours leave out a rule that PR built.

- Design §4.5 screen 12 *A card* (`docs/design/4.5-ui.md`): "a 4 px left edge in the card's colour, in this order: **amber** for any Decide or Do item (or a *needs you* status, the same need read from the ledger), else **indigo** for a *yours* status ... else **teal** for Waiting, else **green** for In progress, else grey".
- Design §4.5a row *Queue page: card* (`docs/design/4.5a-controls.md`): "left edge — amber for a Decide or Do item (or a *needs you* status), else teal Waiting, else green In progress, else grey".

The code, `card_edge` in `src/shiftlead/ui/queue.py`, is amber too for a Waiting card holding an item asked early: `if n.get("decide") or n.get("do") or status == "needs you" or (group == "waiting" and n.get("early")):`. Screen 12 *A question asked early is no want while its entry waits*, further down the same file, says so ("its edge amber as a Waiting card the person is in"). So the same screen says teal in one place and amber in another, and the controls table says teal alone. `tests/test_queue_asked_early_items.py::test_a_waiting_card_holding_an_early_item_has_an_amber_edge` holds the code's rule.

**Location:** docs/design/4.5-ui.md, docs/design/4.5a-controls.md

**Resolved:** 2026-11-26

**Done when:** Both places that give the edge's order name the Waiting card holding an item asked early as amber, as `card_edge` draws it.
