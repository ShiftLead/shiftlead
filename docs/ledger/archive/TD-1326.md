## TD-1326: A new ADR supersedes ADR 2026-10-12's ledgerboard boundary in part: the file-level writers `ledger.py` and `board.py` move into ledgerboard

**Priority:** medium
**Type:** debt
**Added:** 2026-11-03 (ao-led-tds-ledger, through `ao td add --repo`, from ledgerboard's target design; drafted by ao-shiftlead-techlead-ao-1)
**Owner:** designer
**Kind:** build
**Status:** Resolved 2026-11-03: ADR 2026-11-03 supersedes ADR 2026-10-12's ledgerboard boundary in part
**Location:** a new `docs/decisions/<date>-ledgerboard-writers.md`; `docs/decisions/2026-10-12-ledgerboard-dev-cadence-shiftlead.md` (its Status line; *Decision* — *The three layers*, ledgerboard's row and its API); ledgerboard `docs/plans/target-design.md` §1.1, §1.2 (ledgerboard#57, merged)

**Resolved:** 2026-11-03 (PR #2830) — `docs/decisions/2026-11-03-ledgerboard-writers.md` moves ledgerboard's boundary to SPEC, the package (the pure module and the writers `ledger.py`, `board.py`) and the fixtures, never git, the network, the roster, forges, trackers, delivery, running a sweep or sessions; ADR 2026-10-12's Status line names it; design §8's sentence follows in TD-1330.

**Why:** ShiftLead's ADR 2026-10-12 sets ledgerboard's boundary at the formats as text: `SPEC.md`, one stdlib module and conformance fixtures, nothing else. ledgerboard's target design (agreed with Paul's go 2026-11-02, ledgerboard#57) moves the file-level writers `ledger.py` and `board.py` into ledgerboard, as a `ledgerboard/` package beside the module (§1.1), because both consumers need the same file handling and each wrote its own — the drift the ADR was written to end. The ADR is ShiftLead's, so the change is a PR here; until it lands, ledgerboard's v2.3 release contradicts the decision it cites.

**Fix:** a decided ADR is immutable (cadence §7.5), so write a new ADR that supersedes ADR 2026-10-12's ledgerboard row and API in part, and add the one clause cadence §7.5 allows to the old ADR's Status line (`… superseded by <link>`, as ADR 2026-10-25 did). The new ADR's decision: ledgerboard holds `SPEC.md`, the module, the two file-level writers (`ledger.py`, `board.py`, in the `ledgerboard/` package) and the fixtures; never git, the network, the roster, forges, trackers, delivery, running a sweep (its I/O, event checks and lift PRs stay the consumers'; its pure decisions are the module's, §1.2), sessions, or logic that knows either consumer. What a writer needs from outside — the next id, cross-repo state, who answered — is passed in, and the writer reads the clock for dates itself (§1.1; `--today` is a test and replay override); branches, commits, PRs, the id counter and attesting the session stay the consumers'. Cite the target design §1.1, and §1.2 (more format logic as pure module functions: the id rule, the sweep's decisions, the lift-PR verdict, the *needs you* list).

**Done when** the new ADR states the amended boundary, ADR 2026-10-12's Status names it, the PR is read by the techlead and merged, and ledgerboard's v2.3 release can cite it. It must merge before that release.

**Related:** ledgerboard#57 (the target design, Paul's go 2026-11-02); ADR 2026-10-25 (ShiftLead requires dev-cadence, which already supersedes part of ADR 2026-10-12); TD-1286 (the ledger and board written only through the helpers).
