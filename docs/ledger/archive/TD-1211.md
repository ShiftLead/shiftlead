## TD-1211: A `repo add` test sometimes finds a `gh` call it says never happens, and fails a PR's precheck at random

**Priority:** Low
**Type:** debt
**Added:** 2026-10-28 (grinder-ao-1, from #2633's precheck)
**Owner:** grinder
**Kind:** build
**Status:** Resolved
**Location:** `tests/test_repo_adopt.py` (`test_a_pinned_checkout_is_added_and_an_adopt_over_a_pinned_origin_is_refused`, ~387; the `world` fixture's `GH_LOG`)

**Why:** #2633's precheck on 482f1f0 (a change to design text and a docstring only) failed this one test, at `assert not world["log"].exists()  # no PR`: the fake `gh` had logged a call. The same test passed in the precheck of the commit before, in a full `pdm run test` on the branch, and five times alone and with its file under `-n 4`. So something other than the refused `--adopt` reaches `gh` under load, and what it is is unknown. `ao repo add` (the step before) leaves the new checkout for the next tick's reading, which calls `gh api graphql` (`reports._gh_counts`), and the fake logs that call. But `park_ticks` cancels the ticker and drains the detached passes, so a tick-driven reading after it is itself in doubt: a pass outliving the drain's `PASS_DRAIN`, or an RPC path not yet traced, are the other candidates. A random red precheck costs a PR a 3–4 minute re-run and reads as a real failure until someone looks.

**Resolved:** 2026-10-28 (PR #2637). The fake `gh` appends one argv a line, and the five *no PR* asserts read `_prs(world)`, the `pr create` calls, printing every call on a failure. The stray writer was not caught; the likeliest is an agent read still running in a worker thread when `world` put the fake on PATH. The lasting record is `tests/test_repo_adopt.py` (`_calls`, `_prs`).

**Done when** the test asserts only what the refused adopt does, and `pdm run test` passes.
