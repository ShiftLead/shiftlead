## TD-1902: A lifting reply whose gate was already gone has no test for a store that then fails

**Priority:** Low
**Type:** debt
**Added:** 2026-11-16
**Owner:** grinder
**Kind:** build
**Status:** Resolved 2026-11-16
**Id take:** 8b7fad15805247278aff006a4067ed77

**Why:** PR #4017 (TD-1833) wrote `_lifting_reply` in `src/sessionorc/agent_mail.py`. Its docstring and design §4.10 (*An `ask` that lifts the person's gate*) say that only a store that fails after a **landed** lift answers *the hold on TD-n is lifted; the answer was not sent*. A gate already gone (`lifted_before`) is not a landed lift, so that failure re-raises as it was.

The code splits the two cases with one line: `if "lifted" not in mark: raise`. Evidence: deleting those two lines in the worktree (`if "lifted" not in mark:` then `raise`, replaced by `if False:`) and running `tests/test_ask_lift.py`, `tests/test_ui_ask_lift.py` and `tests/test_queue_lift_here.py` gives 24 passed. The only test of a failed store, `test_a_gone_gate_a_refused_lift_and_a_failed_store`, makes the asker go away after a real lift, which is the `lifted` mark; no test fails a store after `lifted_before`. The branch is a behaviour with no test that would catch its going back, and a gone gate would then tell the person a hold was lifted that their press did not lift.

Other lines of the PR probed by the same method (#4013, #4014, #4017) all failed a test when changed; this is the one survivor.

**Resolved:** 2026-11-16 (PR #4021)

**Done when:** A test fails when `if "lifted" not in mark: raise` in `_lifting_reply` is removed, and passes with it.
