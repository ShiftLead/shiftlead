**Why:** the settings a person moves were split across two files with two write paths, and the reserves — the one Paul moves weekly — could not be set for a team or from a page; this entry makes one file the page can write.

**Fix:** three slices; the first two touch `src/sessionorc/**`, so the techlead reads them (§4.9b).
1. **The file and the RPCs**: the keys and readers; `set_settings {profile?, reserves?, teams?, repos?, person?}` — any subset, each validated, the whole file rewritten; the `settings` read; `ui.yml` retired with the migrate note; the backup member. The gate's team priority and `gated.team_extra`; the *paused · usage (team +n)* words on the card (§4.5a) ride the existing mark.
2. **The team stop time**: the tick pass and the start's stamping; `Clear`; the past-instant refusal shared with `set_stop`.
3. **The CLI**: `ao team until`, `ao team reserve`, `ao settings`, `ao schedule`'s new key path (TD-133's slice reads it there).

**Done when** (1) `ao gate grind 5h=30` and `ao team reserve ao-grind 10` leave `settings.yml` with both keys and the gate pauses an ao-grind session at 60% and a plain grind session at 70%, each card saying which line; (2) `ao team until ao-grind +2h` gives every live ao-grind member and seat that `run_until` within a tick, a member started after it carries it, and `--clear` removes it without touching a member's own earlier `ao until`; (3) `person.open_in: none` removes the editor button and a `ui.yml` left on disk is named as *migrate* and ignored; (4) `ao settings` prints the four keys with their lines and instants and `--where` names every other file and its re-read rule; (5) a session's `set_settings` and `settings` are refused; (6) the nightly backup carries `settings.yml`; (7) `pdm run test` covers each key's validation, the team line, the team stop and the migrate path.
