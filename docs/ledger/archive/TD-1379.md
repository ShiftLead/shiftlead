## TD-1379: A session can put the same question to the person twice, and cannot withdraw the copy it sent by mistake

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-04 (ao-led-tds-ledger, a person-session in ledgerboard, through `ao td add --repo shiftlead`; drafted by ao-shiftlead-techlead-ao-1)
**Owner:** designer
**Kind:** design-first
**Status:** Resolved 2026-11-04: designed in #2914; built by TD-1382 (#2917) and TD-1383 (#2918)
**Location:** design §4.10 *A session reaches a person through the org's person inbox*, *The numbers* (the person inbox's depths), *Deleting is declining* (Delete is the person's alone), *Outcomes* (an outcome settles a question the person answered); §4.7 `ao msg`; the code: `message_gate` in `src/sessionorc/mail.py` (the question-seat edge's one open question per sender per seat, TD-995, which a send to the person never reaches: *the person inbox is ungated*), `_check_person_depth` in `src/sessionorc/agent_mail.py` (the only check a question to the person meets: counts, never sameness), `rpc_msg` there.

**Why:** the person's attention is the scarce thing the Inbox and the Queue spend, and a repeated question spends it twice and can draw two answers that disagree. On 2026-11-04 `ao-ledgerboard-lb-techlead` sent the person `m-0d747c0df9e3` and `m-26316e2c8d13` eight seconds apart: the same question on ledgerboard PR #99's exit codes, the same subject and the same answers. It noticed and sent `--outcome dropped --for` the first, which does not close an open question (an outcome settles one the person already answered, §4.10 *Outcomes*), so both stayed on the Queue until Paul answered both. Two gaps, both in the command rather than in any brief: a question to a seat is refused while the same sender has one open there (`message_gate`), but a question to the person meets only the inbox's depths, which count and never compare; and a sender has no way to take back its own open question — Delete (`declined`) is the person's alone.
