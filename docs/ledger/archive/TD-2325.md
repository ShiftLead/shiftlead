## TD-2325: A stage test leaves a flow in the shared test home, so later flow tests can fail and turn a precheck red

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-26
**Owner:** grinder
**Kind:** build
**Status:** Resolved 2026-11-26
**Id take:** 6ef6139845ba49ebb3372c9445aa2867

**Why:** `tests/test_stage_tick.py::test_the_orgs_flow_shadows_the_repos_and_a_name_never_leaves_the_flows` (added by #4496, TD-2051) writes an org flow to `paths.home() / "flows" / "mine"` without setting a `SHIFTLEAD_HOME` of its own, so the flow stays in the session-wide `unit-home` of `tests/conftest.py` (`_never_this_machines_home`) for every later test in that process. An org flow shadows a repo's of the same name, so later tests in `tests/test_flows.py` that make a repo flow `mine` read the leftover format-3 one and fail.

On `origin/main` at ea08ab2b2, running that test and then three of `test_flows.py` in one process fails all three, each of which passes without it:

```
pytest tests/test_stage_tick.py::test_the_orgs_flow_shadows_the_repos_and_a_name_never_leaves_the_flows \
  tests/test_flows.py::test_a_repo_flow_is_found_by_its_directory_and_reaches_package_and_sibling_briefs \
  tests/test_flows.py::test_a_node_members_repo_stage_brief_is_read_on_its_checkout \
  tests/test_flows.py::test_an_edit_to_a_stage_brief_is_brief_changed
3 failed, 1 passed
```

Under `-n 4` it depends on which worker gets which test: of the runs of the 49 modules that name `briefs` made while auditing #4841, one had two of these failures and one had three (*flow mine (…/popen-gw3/unit-home0/flows/mine/flow.yml): a format-3 flow, which no team runs until the cut-over*). A precheck can go red on a pull request that touched none of this. The full suite passed on the same commit (10,557 passed), so the order that fails is not the usual one.

**Location:** tests/test_stage_tick.py; tests/conftest.py; tests/test_flows.py

**Resolved:** 2026-11-26 (PR #4864) — tests/conftest.py _no_flow_left_in_the_unit_home; tests/test_stage_tick.py

**Done when:** The command in the Why passes all four tests, and no test leaves a flow in the session's `unit-home`.
