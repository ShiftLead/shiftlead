## TD-1239: A push the forge refuses is reported as *origin could not be reached*, with only git's last line, so a refusal reads as an outage and hides its reason

**Priority:** Medium
**Type:** debt
**Added:** 2026-10-29 (Paul, in session ao-shiftlead-td-1190)
**Owner:** designer
**Kind:** design-first
**Status:** Resolved
**Resolved:** 2026-10-30 (grinder-ao-2) — designed in #2682; its one part, TD-1242, built in #2688.
**Location:** `src/sessionorc/board.py` (`unreachable`, `_why`, `_land`'s `git push`); `src/sessionorc/agent_rank.py` (the rank flush's *did not land* warning); design §4.4 *The edit is made on origin's head, and landed there* (*It is refused, touching nothing, when origin cannot be reached*)

**Why:** On 2026-10-29 Paul turned on GitHub's *Block command line pushes that expose my email*. From 19:27, every board write-back (lift hold, Decide) and every rank flush was refused. The host agent commits under the checkout's git identity, then `paul@nowfree.org`, and GitHub answered with `remote: error: GH007: Your push would publish a private email address.` and `! [remote rejected] … (push declined due to email privacy restrictions)`. The person saw *Decide failed: origin could not be reached (git push: error: failed to push some refs to 'https://github.com/ShiftLead/shiftlead.git'): the edit was not made*, and the log showed the same line once a minute. Two things hid the cause: `_why` keeps only stderr's last line, which is git's generic summary, and §4.4 files a push the forge reached and refused under *origin cannot be reached*. So the refusal read as an outage, or as fallout from the dev-cadence → agent-cadence move. Finding it took a probe push by hand. The fix was the person's: the no-reply address as `user.email`. The first flush after it landed (#2675).

**Fix:** design it first, then a build. (1) §4.4 tells apart a forge that could not be reached (the fetch failed, the push could not connect, `gh` is absent or signed out) from a push the forge refused (`! [remote rejected]` or `! [rejected]`, a `remote: error:` line). It gives the refused case its own words, for example *origin refused the push (<the forge's reason>): the edit was not made*. Either way, nothing is touched. (2) The reason quoted is the forge's own: the first `remote: error:` line, else the `! [remote rejected] … (<why>)` parenthesis, else git's last line, as now. (3) The rank flush's warning uses the same words. Then file the build as `Part of: TD-1239`, with a test that feeds `_land` a GH007-shaped push failure and asserts the refusal names GH007 and is not *could not be reached*.

**Done when:** the design names a refused push apart from an unreachable origin, quoting the forge's reason; and a build entry that implements it is filed as its part.
