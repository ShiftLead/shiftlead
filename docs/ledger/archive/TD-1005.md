## TD-1005: `ao doctor` on a node says when `ao` on `PATH` is not this install's, with the cure

**Priority:** Low
**Type:** debt

**Owner:** grinder
**Kind:** build
**Status:** Done
**Part of:** TD-998
**Location:** `src/shiftlead/doctor.py` (`nodes`, on a node; `HOME_ONLY`); `src/shiftlead/cli.py` (`cmd_doctor`, its caller); `tests/test_cli_doctor.py`; design §4.7 *`ao doctor`* (the **nodes** line on a node)

**Why:** TD-998: a node member that cannot find `ao` goes silent to the org, and nothing said why.

**Fix:**
- `nodes` takes the reading as arguments, as every check does: `nodes(rows, node, *, ao_on_path: str | None = None, prefix: str = sys.prefix, name: str = "")`, `cmd_doctor` passing `shutil.which("ao")` and `hosts.local_host().name`, read in the CLI's own process, never in the `doctor` RPC, which runs with the agent's `PATH`. A container node is one whose `prefix` is `containers.INSIDE_VENV`. Its tests are plain calls. The row carries `{ao_on_path, resolved, prefix, container}` as its `--json` reading.
- On a node, the row's verdict is no longer *home only*: it is *ok* or *lacking*, by the reading of `ao_on_path`, resolved (`os.path.realpath`), against `os.path.realpath(<prefix>/bin/ao)`. The same file is *ok: nodes — read at the home · `ao` on PATH*.
- No `ao` on `PATH` is *lacking: nodes — `ao` not on PATH here, only <sys.prefix>/bin/ao*. The cure for a container node (its `sys.prefix` is `INSIDE_VENV`) is *(`ao host rebuild <local host name>` at the home)*. For another node it is *(link <sys.prefix>/bin/ao into a PATH directory, e.g. ~/.local/bin/ao)*.
- Another file is *lacking: nodes — `ao` on PATH is <which> → <resolved>, not this install's*. The cure for a container node is *(the image's own `ao`: rename it in the repo's image)*; for another node *(remove or rename <which>, or put <sys.prefix>/bin/ao's link earlier on PATH)*.
- A lack counts as any lack does (exit 1): on a node, the nodes row leaves the *home only, counts as neither* list (§4.7), and `"nodes"` leaves `doctor.HOME_ONLY` and its comment.
- The two paths are compared by `realpath` whether or not each exists, so anything but this install's own `ao` is *lacking*.
