## TD-1207: `test_a_team_winding_down_keeps_its_cards_compact_and_draws_no_empty_summary` reads `groups` off the session event, which carries them only when the heads changed since the last send

**Priority:** Low
**Type:** debt
**Added:** 2026-10-28 (grinder-ao-2, failed #2625's precheck once; 6 of 6 passed alone)
**Owner:** grinder
**Kind:** build
**Status:** Done
**Location:** `tests/test_ui.py` (`test_a_team_winding_down_keeps_its_cards_compact_and_draws_no_empty_summary`, ~1925); `src/shiftlead/ui/fanout.py` (the session event's `carried` vs `plain`, and `_flush`'s `groups` event)

**Why:** the fan-out sends a session event with the heads (`groups`) only when the socket's `heads_key` differs from the new heads; otherwise it sends it plain. `_flush` sends a separate `{"event": "groups"}` on its own clock, so when it lands between the kill and the session event, the session event carries no `groups` and the test's `ev["groups"]` raises `KeyError: 'groups'`. Seen in #2625's precheck under load (`1 failed, 4616 passed`), at main 879cb5b.

**Fix:** in the test, keep the newest `groups` seen on the socket — from a session event that carries them or a `groups` event — up to the exited event, and assert on that, rather than on the session event's own key.

**Done when** the test reads the newest heads from either event and still asserts `live == 0` and an empty summary.
