**Resolved:** 2026-11-02 (PRs #2787, #2789, #2790) — (1) `src/sessionorc/push.py`, `push_subscribe` / `push_unsubscribe`, the `host` read's `push` view, `notify.push` in `set_settings`; (2) the push child in `src/sessionorc/notify.py` (`--push`, `--public`, `--key`), `_notify_pass` for both channels, `push_key`, `notify_test {channel: push, device}`; (3) `src/shiftlead/watch.py` telling by push

**Why:** TD-1302's design: §4.10 *Told on the home-screen app too*, §5 `notify.push`, §4.8 `PERSON_ONLY`.

**Fix:** as §4.10 *Told on the home-screen app too* says, the home's side only:
- `_notify_pass` reshaped so what is due no longer depends on Telegram's switch: each due row keeps its line, path and key apart, Telegram builds its message with its link, push its payload `{"body", "path", "tag"}` (`tag` the row key, `more`, `test`).
- `~/.shiftlead/push.json` (mode 600, the home its one writer, written by rename since the watch reads it): `key` (*key* / *no key* / *unreadable: <why>*), `public_key`, `last_line`, `devices` `[{id, endpoint, keys, label, since, last_ok, last_error}]`; id the first 16 hex digits of `sha256(endpoint)`; a 404 or 410 drops one; a derived public key that differs from the kept one drops them all and sets `last_line`.
- The `host` read's `push` view: the same less each device's `endpoint` and `keys` — the seam TD-1305 draws from; absent on a node.
- The child (`pywebpush` added to the `[ui]` extra, imported lazily — *pywebpush: not installed* without it): stdin carries the payloads and the devices; it signs (VAPID; `sub` is `reach.url` when `https`, else `https://github.com/ShiftLead/shiftlead`; a 401/403 reads *the push service refused the key's sender (<status>)*), posts on threads with `REQUEST_SECONDS` each, `Urgency: high`, `TTL` one hour, within `CHILD_SECONDS + REQUEST_SECONDS`, and prints each device's status (`WebPushException.response.status_code`, or the exception's class) and the derived public key — never the private key, never an endpoint in a log line. The key is read as `py_vapid`'s base64url raw scalar or as PEM. `--public` prints the public key, *no key* or its reason, run in the background (never inside a read) when a secrets config is set and there is no reading, after a Save that moves `notify.push.secrets`, and every ten minutes while *unreadable*, or *no key* with devices listed; a send child answering *no key* or a reason writes the reading first and that send's statuses are discarded; with no config set there is no reading. A successful `push_key` writes `key` and `public_key` from its answer. `--key` reads the config itself and refuses a present key, else makes a P-256 pair, writes the private half with `doppler secrets set VAPID_PRIVATE_KEY` from stdin into `notify.push.secrets` only (refused unset), and prints the public half.
- Sending: one `notified` key per row whatever the channels, set before either send; push to every device while `notify.push.on` is not false; Telegram beside it under `both`, or under `fallback` row by row after the push child, for each row (and *and more*) no push service accepted with a 2xx. Push is on when `notify.push.on` is not false, a device is listed and the key reads *key*; under *no key* / *unreadable* with devices listed no child runs, every row is not taken, `last_line` reads *push is paused: <reading>*, and the devices stay. The derived-key check runs before a send's statuses are applied, and on a change they are discarded. The watch's lines carry `tag` `watch`.
- RPCs, a person's own: `push_subscribe {endpoint, keys, label, key, replaces?}` answering `{id}` (`key` required: the subscription's application server key, base64url unpadded like `public_key`, compared as decoded bytes, refused when not the home's — a refused `replaces` leaves the old device listed) (`replaces` swaps a device's endpoint and keys, keeping its label and `since`, and adds the device when the id is no longer listed; the endpoint must be `https` to a public host, `p256dh` 65 bytes and `auth` 16, else refused naming the field), `push_unsubscribe {id}`, `push_key`; `notify_test {channel: push, device}` (whatever `notify.push.on` says; no `channel` is Telegram's; the result *delivered to <label> 14:02*, a 410 dropping the device; it stays in `HOME_EDITS`). Each refuses when the agent is not the home, as `notify_test` does, and none joins `modes.HOME_EDITS`.
- `set_settings` takes `notify.push: {on, telegram: both|fallback, secrets}` and names a bad field.
- The watch (`src/shiftlead/watch.py`) reads `push.json` and the same secrets and tells its three lines on the channels the pick names, linking `/inbox`; it tells nothing only when every channel is off (push alone when Telegram is off); a paused key sends no push and falls to Telegram under `fallback`; it never writes `push.json`.
- A paused pass still sets each due row's `notified`, so a row no channel carried is not told on resume; `push_subscribe` is refused, naming the reading, unless the key reads *key*; a key change writes `key`, `public_key` and the dropped devices at once; times are ISO strings; the watch treats a file with no reading as paused. With secrets set and no reading yet (a first start, or a Save that moved `secrets`; a restart keeps the file's reading) the pass treats push as paused. `--key`'s *a key is there* refusal writes the reading. The push `notify_test` is refused, the reading in words, while the key is paused, and *reading the key — try again shortly* while there is no reading.

**Done when** a home whose config already holds a key reads its public key in the background before any send, and a failed reading is retried no sooner than ten minutes; a test home with a fake push endpoint delivers a told row once to every device and drops a 410 one; a `replaces` subscribe swaps the device; a loopback or `http` endpoint and short keys are refused; *both* sends on both channels and *fallback* sends Telegram only for the rows no device took; rows are told with Telegram off and push on; the watch tells on the picked channels and writes no `push.json`; `--key` refuses over an existing key and words a Doppler write refusal; a paused key keeps the devices and resumes; the three RPCs refuse a session and a node; `notify_test` reaches one device; the child's stdout and the home's log hold no private key; and `pdm run test` passes.
