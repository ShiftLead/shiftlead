**Fix:** this touches `src/sessionorc/**`, so the techlead reads it (§4.9b). Slices, each its own PR:
1. **The clock and the reading** (`sessionorc`). `settle:` is read from `settings.yml` and the repo's `.shiftlead.yml` (the repo's wins key by key; built-in `{design-first: 5m}`; durations as `5m`, `1h`, `0`).
   - `ledger_seen.json` beside `ids.json` (`paths`), keyed by origin as `ids.json` is: `{<origin>: {<id>: {at, sig, held?}}}`, where `sig` is a hash of the entry's section text. It is written by the host agent beside the reading (the reader stays a pure function of the text), and a repo's first reading records every id it holds at the epoch. The agent annotates the reading's entries with the marks before any reader sees them, so `lane_matches` / `in_lanes` read them off the entry.
   - An entry that has not settled carries `settling: {until}`, and a held one carries `held: {at}`. An edit that changes `sig` while settling restarts the window, and on a held entry it ends the hold and restarts the window.
   - `lane_matches` / `in_lanes`, rule 6's `lane_seen` and rule 8's news, and every lane count treat either mark as matching no lane. `pickable` stays cadence §2.4's.
2. **Hold and the claim**. `td_hold {repo, id, release}` beside `td_next`:
   - Added to `PERSON_ONLY` (refused to every session, the person's shell passing; `tests/test_person_only.py`'s count of the list moves by one) and to `modes.HOME_EDITS` (a node forwards it and refuses it offline, as `ledger_decide`'s), and refused for an id that has settled and is not held. Release makes the entry pickable at once.
   - `rpc_progress`'s declared claim on a settling or held ledger reference is refused in the design's words, and `force` does not pass it.
   - `ao td hold <id> [--repo] [--release]`. `ao repo` prints *settles in 7m* / *held 2h* after the owner.
3. **The pages**. The Repo page's row draws the mark and **Hold** / **Release**, and the Settings page gets the **settle** field (`set_settings` gains `settle`). This repo's `.shiftlead.yml` gains `settle: {design-first: 10m}`.
- **Tests:** a new design-first entry is withheld for its window and pickable after it; a `build` entry goes at once; a repo's first reading settles every existing id; an edit inside the window restarts it, and an edit after settling does not; a hold withholds past the window until Release or an edit; a claim on a settling or held entry is refused with `--force` too; a session's `td_hold` is refused and the person's shell's passes; rule 6 tells a member of the entry only once it settles; the repo's `settle:` overrides the install's key by key; the §4.5a doc-bound tests pass.

**Done when** an entry filed `Kind: design-first` in this repo is untaken for ten minutes, a Hold pressed in that time keeps it untaken until Release, a designer's `Kind: build` entries are picked at once, and every listed test passes.
