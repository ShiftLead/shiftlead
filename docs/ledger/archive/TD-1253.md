## TD-1253: The unseen-first tie-break in `card_order` is not tested, though the test says it sorts first

**Priority:** Medium
**Type:** debt
**Added:** 2026-10-30 (test-audit-ao-1, auditing the last ten merged PRs)
**Owner:** grinder
**Kind:** build
**Status:** Done
**Resolved:** 2026-10-30 (grinder-ao-2, PR #2708) — `test_unseen_is_drawn_only_on_an_interactive_session` sorts a seen `a` and an unseen `z` of one rank and one `unattended` and asserts `z` first; dropping `not v.get("unseen")` from `card_order` fails it.
**Location:** `src/shiftlead/ui/cards.py` (`card_order`: `(v["rank"], not v.get("unseen"), bool(v.get("unattended")), …)`); `tests/test_ui_org.py` (the test at line ~1310, docstring "carries the mark … and sorts first within the rank")

**Why:** #2687 (TD-1228) put an unseen session first within its rank in Python (`card_order`) and in `app.js`. The one test of it sorts `[worker, mine]` where `worker` is unattended and `mine` is interactive and unseen, so `mine` comes first by the old unattended tie-break alone. Probe at `origin/main` b2d1a3724: replacing the key with `(v["rank"], bool(v.get("unattended")), False, str(v.get("name") or ""))` and running `PYTHONPATH=$PWD/src pdm run pytest -q tests/test_agent_restart.py tests/test_link.py tests/test_models.py tests/test_ui.py tests/test_ui_events_light.py tests/test_ui_org.py tests/test_ui_popout.py tests/test_ui_repos_omit.py` gives `passed`, the same as unmutated. The grid's unseen-first order, the feature's point beside the pill, has no test that two interactive same-rank sessions sort unseen before seen.

**Fix:** add a pair of the same rank and the same `unattended`, the unseen one named after the seen one, and assert `sorted(..., key=card_order)` puts it first.

**Done when:** dropping `not v.get("unseen")` from `card_order` fails a test.
