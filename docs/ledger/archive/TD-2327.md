**Why:** Three behaviours of a forgotten login (design §4.9e *A record's `profile`* and §4.2b *⋯ on a login*; #4851, TD-2288, and #4861, TD-2320) can be taken out of the code with every test still passing. The design states the first outright. It does not spell out the shell's exclusion (it speaks of the ended sessions that ran on the login, and read by the key's definition alone a bare shell record would be a `default`'s), and it only implies the unreadable file's words, which the code's comment gives.

1. A live record with no `login` or `profile` holds Forget of its tool's `default`. `_login_users` (`src/sessionorc/agent_logins.py`) changed so that its condition also requires `(s.login or s.profile)`: passes. #4861's body states this side effect (*Forget of the default login is refused while it runs*); the test it changed, `test_forget_and_naming_an_account_read_what_runs_and_what_is_retired`, forgets only `grind`.
2. Forget's count of ended sessions leaves a shell out. Dropping `if adapters.has_agent(s.adapter)` from `_login_ended` passes. `test_forget_and_the_tools_read_count_the_logins_ended_records` says *a live record, a shell and another login's are not* counted, but it forgets `grind` alone, and its shell row has no `login` or `profile`, so that row could only ever be counted by a Forget of a `default`. With the filter gone, such a Forget would count every ended shell as a session that reads nothing.
3. An unreadable `logins.yml` keeps the plain transcript refusal. In `rpc_transcript` (`src/sessionorc/agent.py`), `except logins.LoginError:` changed to `except ZeroDivisionError:` passes, so the `LoginError` would come out of the read in place of *the tool's file is not on <host>*.
