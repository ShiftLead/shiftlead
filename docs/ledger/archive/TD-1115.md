## TD-1115: A file path on the Queue and in the Inbox is a link: `paths` takes `repo`, `POST /api/paths` answers each run's press, and the page links the runs in an item's rendered text

**Priority:** Medium
**Type:** feature
**Added:** 2026-10-27 (the designer, from TD-1108)
**Owner:** grinder
**Kind:** build
**Status:** Resolved
**Part of:** TD-1108
**Location:** `src/sessionorc/agent.py` (`rpc_paths`: `repo` beside `id`, and neither; `_resolve_paths`); `src/sessionorc/hosts.py` (`repos()`); `src/shiftlead/ui/app.py` (`POST /api/paths` beside `/api/sessions/{sid}/paths`, 3216); `src/shiftlead/ui/common.py` (`editor_file(reach)`, `checkout_of`, `editor_link`); `src/shiftlead/ui/templates/inbox_entry.html` (`thread_row`); `src/shiftlead/ui/cards.py` (`view`'s `editor.file` for a record); `src/shiftlead/ui/templates/inbox_row.html` (`data-paths-ctx` on each mail, board and ledger row's root; the `.body` texts and `.boardreply`, the plain `Ask:` line among them); `src/shiftlead/ui/static/app.js` (`AO.pathRuns`, `AO.pathsAsker`, `AO.fillFold`, the `a.editor` click handler; `AO.ITEM_TEXT` beside `AO.TRANSCRIPT_TEXT`; a text-node linker beside `AO.pathLinksHtml`)

**Why:** TD-1108's design: a path a session names opens in the person's editor from the pane and a transcript, but the same path in a Queue card's item, an Inbox row or a message page is text Paul copies out by hand (Paul, 2026-10-27, an Add entry draft's `~/.shiftlead/attachments/draft-…/paste-….png`).

**Fix:** as design §4.6 *A path in the Inbox and the Queue is a link too* says:
1. **`paths` takes `repo`.** `rpc_paths(id: str | None = None, runs: list[str] | None = None, repo: str | None = None)` (called by keyword), `PATHS_RUNS_MAX` and `PATHS_RUN_CHARS` checked first: with `id` as today; with `repo`, a non-empty main-checkout path (an empty one refused, never read as neither) answered only when its real path is one of `hosts.local_host().repos()`'s (each real path taken) and refused otherwise, as an unknown id is, a relative run resolves against that checkout and `~` is the home's user's; with neither, every run not beginning `/` or `~/` is dropped before resolving (`./x`, `../x` relative) and answers `null`; `id` and `repo` together are refused. The bound, `PATHS_PRIVATE`, `PATHS_RUNS_MAX` and `PATHS_RUN_CHARS` are unchanged; an `id`-less `paths` is never forwarded (`agent_link`/`agent_serve` route by the `id` address; `NODE_READS` unchanged), served where it arrives, the home. `_resolve_paths`' `cwd` is the checkout's path for `repo`, `Path.home()` for neither.
2. **The row's context.** Every row `inbox_row.html`'s mail root draws, whatever its section (`ask`, `steer`, look, FYI, *answered for you*, owed, handed, orphaned), and each board and ledger row — each the `.mailrow` root `row()` draws — in both `inbox` and `card` modes, and each thread row of the message page (`inbox_entry.html`'s `thread_row`, by `t['from']`), carries `data-paths-ctx`, written by the server; trail, state and history rows carry none, and a text under a root with none is never linked. The value: `id:<record id>` for a mail-root or thread row whose `from` is a record the home knows (the `list` fleet, any state until forgotten); `repo:<root>` for a board line or a ledger row, by the root path the row already carries (`e.root`); `home` for anything else, a mail from a forgotten sender among them. So the Inbox, the message page, a Queue card's items and the Repo page's rows all carry it.
3. **`POST /api/paths`** takes `{runs, ctx}` (bare paths, as the asker sends them). `ctx` splits at its first colon — `id:<record id>`, `repo:<root>` (a root may hold colons, never empty), or the bare word `home`; an unknown prefix, non-list or non-string `runs`, or runs past `PATHS_RUNS_MAX` / `PATHS_RUN_CHARS` is a 400, checked before any `get`, never a refusal. For `id:` it reads the record by `get` first: a forgotten id (a 400 from that `get`, *no session*) is a refusal, a 503 no answer, and a record with no file form (neither on the home nor a container node with a reach) answers every run `null` without asking its host; else it asks `paths` where the context says (a record's by the road `POST /api/sessions/{sid}/paths` takes, so a node's record reaches its node by `read`). It answers `{label, file, wait, paths, refused}`: `file` the context's form with `{path}` unfilled — for a record only under `cards.view`'s own `d["editor"]` gate — `here or reach` (its host the home's, or a non-empty `hl.reach.vscode`) and `editor_link(dir, reach)` not None, so a home record with an empty `dir` has no form — `common.editor_file(reach)`, `reach` empty on the home, and none for a node record with no reach (its folder under the same gate), else `common.editor_file()` — null with every run `null` where there is none; `paths` every run asked, `{path, folder}` or `null`, `folder` a URL string or null — a record's `editor_link(dir, reach)['url']`, else the folder link's URL of the checkout the file lies in (`checkout_of`), none under `folder_first: false`; `refused` the refusal's words, the answer still 200 with every run `null` — only for a forgotten id (*no session*, from the route's own `get`) or a `repo` whose real path (`~` expanded) is not in the set of `hosts.local_host().repos()`' real paths — equality, never containment — or unreadable, checked before asking; a 400 from the RPC is never a refusal; an `unreachable` host, a failed `read` or any other error is a non-200 (the asker's failed fetch: nothing cached). The record is read by `get` once per ask, never cached across asks. A read behind the UI's gate, as the pane's route.
4. **The page.** `AO.ITEM_TEXT` (`.body, .boardreply`) names the texts walked in a row: a card's `.body.sentence` and `leads` among them, its `.subj.sentence` not. One `AO.pathsAsker` per context, made on first use, its `ask` closure keeping `file`, `label` and `wait` from its first answer, and kept for the page's life (one ask in flight, successive asks of eight, each answer cached, `null` included); a context's `ask` closure that meets `refused` or a first `file: null` sets quiet and from then on answers each batch with its runs `null` without a fetch (never `{}`); a failed fetch caches nothing, as the Transcript's. One delegated document `mouseover` for `.mailrow[data-paths-ctx]` on every page. On a row's first hover its texts' runs (`AO.pathRuns`) are asked and the row marked asked; the linker runs inside `AO.fillFold`'s `put` (both puts, the row by `closest('.mailrow[data-paths-ctx]')`, `foldBodies` keeping raw HTML), from the cache or asked then; a cache-only relink runs inside `AO.reopenFolds` over the `.mailrow[data-paths-ctx]` under its root, a no-op where there is none. Where `common.editor_file()` is None the server writes no `data-paths-ctx` on any row; a row with an empty `e.root` is `home`. Quiet is for the page's life; a reload asks again. The linked texts are `AO.ITEM_TEXT`'s alone; a *recommends*, outcome or answer-given line stays text. A text-node linker wraps each answered run in its node as an `a.editor` with `data-ctrl`, `data-label`, the transcript's `title` (as `AO.pathLinksHtml` writes it), `href` `AO.fileUrl(file, path, line, col)` from the run's own `:line:col` or `:1`, and `data-folder` / `data-wait` where it has a folder. It skips nodes inside an `a`, a `button` or a `summary`, and never redraws an element from its `textContent`, so `<code>`, `<b>` and links stay. The existing click handler presses it on Ctrl+click or Cmd+click.

**Done when:** tests show:
(a) the RPC: `paths` with `repo` resolves a relative run against a registered checkout given by its path, and refuses an unregistered path, a subdirectory of a checkout, and an empty `repo`; `id` and `repo` together are refused; with neither, an absolute and a `~/` file answer, and `./x`, `../x` and `x` answer `null`; a `PATHS_PRIVATE` path and a directory answer nothing in every form.
(b) the route: `POST /api/paths` answers a `home` attachment (`~/.shiftlead/attachments/<draft>/x.png` in a temp home) with its resolved path and the home's `vscode://file{path}` form; a `repo:` run `src/x.py` with the checkout's folder URL; an `id:` run by that record's `dir` with its folder URL, for a record on the home and for a container node's record by its reach form; each answer with `label`, `file` and `wait` once and an unresolved run `null`. An unregistered `repo:`, a subdirectory `repo:` or a forgotten `id:` is 200 with `refused` and every run `null`; an `unreachable` record's host is a non-200. A record on a node with no reach, and a home record with an empty `dir`, answer `file: null` without asking its host. An unknown `ctx` prefix, an empty `repo:` root, non-string runs and runs past `PATHS_RUNS_MAX` or `PATHS_RUN_CHARS` are 400s, returned before any `get`.
(c) the rows: a rendered Inbox mail row from a known sender (`id:…`), an FYI from a known sender (`id:…`), a row from a forgotten sender (`home`), a handed row (`home`), a board row and a Queue card's ledger item (`repo:<root>`), a board row with an empty root (`home`), a message page's thread row from a known sender (`id:…`) and from a forgotten one (`home`), and a trail row (none); under `open_in: none` no row carries `data-paths-ctx`.
(d) the page, by a node probe as `tests/test_ui_transcript_paths.py`'s: the linker over an item whose rendered text holds `<code>src/x.py</code>` and plain `~/.shiftlead/attachments/d/x.png` wraps both as `a.editor[data-ctrl]` with the `<code>` kept; `src/x.py:12` and `src/x.py:30` in one item make one ask and two hrefs ending `:12` and `:30`; a run under a `summary` stays text; one run under two contexts is asked twice; a refused context and one answering `file: null` are asked once and then answer every batch `null` with no fetch, and a new page asks again; a fold body filled later is linked from the cache with no second ask, and one filled from cache and then refetched keeps its links; a row redrawn by a poll keeps its links with no new ask.
`pdm run test` and `pdm run lint` pass.
