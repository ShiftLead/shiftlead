**Why:** TD-1671's design (§4.9 *A scaled seat's bounds*, §4.10 *A bounded exchange*) counts the pair bound between a session and a scaled seat over the seat's records: a sender whose reply-less asks fill extras spends one budget with the seat, not one per extra. Today `agent_mail._check_bounds` reads only the pair tally on the record the send picked (`_pair(me, sid)`, `_pair(records[sid], sender)`), so a sender writing to a seat with extras takes up to the seat's `max` records' worth of `PAIR_BOUND` from it.
