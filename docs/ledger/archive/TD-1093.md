## TD-1093: A peer of `agent.sock` in another pid namespace reads *unknown*, never the person

**Priority:** Medium
**Type:** debt
**Added:** 2026-10-26 (the designer, from TD-1064)
**Owner:** grinder
**Kind:** build
**Status:** Done — the fix is in #2470
**Part of:** TD-1064
**Location:** `src/sessionorc/identity.py` (`classify`, the `ProcReader` protocol, `LinuxProc` and the tests' fakes); `src/sessionorc/agent_common.py` (`_peer_pid`, re-exported in `agent.py`), `src/sessionorc/agent_serve.py` (`_dispatch`), `src/sessionorc/agent_identity.py` (`_identify`, `_id_channel`); design §4.8a *The channel* (**unknown**), *A session never gains a person-only act by crossing a channel*; §4.4a *A container that is no node has no `ao`*

**Why:** TD-1064: a container that is no node and has the home's `agent.sock` mounted into it would reach the host agent from processes whose ancestry ends at the container runtime, not at a pane, and outside the tmux server's cgroup, so `classify` reads them *outside*: the person, with every person-only act. §4.8a now says such a peer is *unknown*.

**Fix:** as §4.8a says: as the last test before *outside* — once ancestry, sid, tty, scope and the cgroup clause have placed the peer nowhere — `classify` compares the peer's `/proc/<pid>/ns/pid` link with the agent's own (`/proc/self/ns/pid`), through a new `ProcReader` method (`pid_ns(pid)`) so tests fake it; a different namespace is *unknown* with the signal `namespace` (added to `Channel.signal`'s list, so `whoami`, `ao identity`'s `kind:signal` tally and the UI banner name it). The uid's path: `_peer_pid` returns `(pid, uid)` from `SO_PEERCRED`; `_dispatch` and `_identify` carry `peer_uid`; `classify(..., peer_uid=None, own_uid=None)` applies the other-uid rule only when both are given (`own_uid` is `os.geteuid()`, the agent's effective uid, as `SO_PEERCRED`'s is). A credential with pid 0 is *unknown*, signal `namespace`, not skipped as today's `peer is not None` gate does: `_peer_pid` returns `None` only where there is no socket (an in-process call) or the platform has no `SO_PEERCRED`, a distinct value where the socket's credential cannot be read (`getsockopt`'s `OSError`), classified *unknown*, signal `unreadable`, and else `(pid, uid)` with a pid of 0 passed on, and `classify` answers pid 0 before its `stat` read (whose failure is `unreadable`); only a call through no socket is unclassified. The signal is given for a link that reads and differs, and for a peer of another uid (`_peer_pid` returns `SO_PEERCRED`'s uid beside the pid, `agent_common.py`) that no pane test places and whose link does not read; `SO_PEERCRED`'s uid is the effective uid and an unprivileged agent cannot read another uid's link, so `sudo ao` and a setuid-root client outside a pane read *unknown* (accepted, §4.8a); only under `CAP_SYS_PTRACE` does another uid's equal link stay *outside*; an unreadable `ns/pid` on a peer of the agent's own uid (non-dumpable, setuid) stays *outside*.

**Done when:** tests show (a) a peer that no pane test places and whose `ns/pid` differs from the agent's classifies *unknown*: under `enforce` a person-only act from it is refused with an alarm, under `observe` it is served and the alarm recorded (§4.8a *Observe before enforce*); (b) a peer in the agent's namespace with no pane in its chain is *outside*, as now; (c) a peer in a child pid namespace whose `ppid` chain reaches a pane classifies as that pane's session; (c1) a credential with pid 0 classifies *unknown*; (c2) a peer of the agent's uid whose `stat` reads but whose `ns/pid` link does not stays *outside*, and one of another uid (uid 0 included) that no pane test places and whose link does not read reads *unknown*; a faked readable equal link of another uid stays *outside*; (c3) a socket whose credential cannot be read classifies *unknown*, signal `unreadable`; (d) the suite's own callers (the pytest process, a pane's process) classify as before. `pdm run test` and `pdm run lint` pass.

**Related:** TD-1064 (the design), TD-077 (archived: identity by ancestry chosen over a per-session secret), TD-580 (a person's shell).

**Resolved:** 2026-10-27 (grinder-ao-2, #2470) — `classify` compares the peer's `ns/pid` with the agent's own as its last test (`ProcReader.pid_ns`), so a peer no pane places in another pid namespace reads *unknown*, signal `namespace`; another uid whose link does not read is *unknown* too, the agent's own uid *outside*; a pid of 0 is *unknown* `namespace` and an unreadable credential *unknown* `unreadable`. `_peer_pid` returns `(pid, uid)`, and `_dispatch`, `_identify` and `_id_channel` carry `peer_uid`. Seven tests in `tests/test_identity.py` cover (a)–(d).
