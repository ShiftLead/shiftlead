(Reverting `row in ("red_pr", "fork_pr")` to `("red_pr",)` is no finding: the fall-through also returns "do".) The other mutants of this PR (the draft, conflicting, sync and checks conditions, `FORK_WHOSE`, `_fork_lines`' copy, `--fork-ok`) were caught. #2762 and #2759 were checked the same way and their mutants all failed a test.

**Fix:** add a case to each: a closed fork row is not ready; a Queue card holding a fork item counts it in neither `do`'s Start count nor `items_start`.
