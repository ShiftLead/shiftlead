## TD-2322: A saved session note still tells sessions to delete review copies in the one way the briefs forbid

**Owner:** grinder

**Why:** The memory `docs/claude-memory/remove-a-review-copy-when-its-review-ends.md` (added by #4836) says under **How to apply**: *after a reviewer subagent's verdict is recorded, `rm -rf` the copy it read*.

#4841 (TD-2313), merged after it, made the opposite rule and did not touch the memory. Every package brief that gives the scratch rule now says *once the review it served is posted, release it yourself by a rename, never an `rm -rf`: `mv $SHIFTLEAD_SCRATCH/copies/<name> $SHIFTLEAD_SCRATCH/copies/.gone-<name>`* (for one, `src/shiftlead/briefs/auditor.md`), and design §4.6 *A seat releases its own* says an unattended seat's permissions allow the `mv` *where they refuse an `rm -rf`*.

Sessions in this repo load the memory index at start, and its line (`docs/claude-memory/MEMORY.md`) ends *rm each once its review is posted*. A session that follows it runs the command its brief forbids and, unattended, is refused.
