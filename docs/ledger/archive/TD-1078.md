## TD-1078: A seat is filled by an answer to its own question, and the techlead relays what came of it to the member whose question it was

**Priority:** Medium
**Type:** debt
**Added:** 2026-10-26 (the designer, from TD-1051)
**Owner:** grinder
**Kind:** build
**Status:** Done — #2429
**Location:** `src/sessionorc/models.py` (`asks_waiting` at 1413, `_asks` at 1434, its `asking` set at 1446); `src/sessionorc/agent_tick.py` (`_seat_due`, the `asks` cause and `seat_filled`); `src/sessionorc/agent_mail.py` (the `refills` reading at 897–905, the lapse, *Go with it* and decline notes at ~1119); `src/sessionorc/mail.py` (`read_when`'s seat rows); `src/shiftlead/briefs/techlead.md` (the preset's pass-up paragraph, line 18: the relay rule; `src/shiftlead/briefs/` is not a held path, `docs/briefs/` is, and this repo's `docs/briefs/techlead-context.md` restates no pass-up rule, so the build touches no held path); design §4.9b *An answer waiting counts too*, *A member's question stays the member's*; §6 rule 3 (`asks`); §4.10's `read_when` table

**Why:** TD-1051: techlead-cm-1 asked the person a `steer` of its own about designer-cm-1's question and closed; Paul's answer landed in the closed seat's mailbox, which nothing filled, and the designer waited a day.

**Fix:** `asks_waiting` counts, beside the open questions and the handed entries, each **answer waiting**: an unread entry in the seat's inbox that is the `reply` — the person's or a session's — which closed a question the record sent (its `closes`, the question's `closed_reason` *replied* — the same test `refills` keeps at `agent_mail.py:897–905`, so a later reply on a closed question counts nothing in both), or a `system` note the home wrote for that question's lapse, *Go with it* or decline — each counted only where the question, resolved by the note's `reply_to` on the seat's own outbox copy, was sent by this seat (`from_ == sid`, as `refills` tests at `agent_mail.py:897–905`); the notes' wake classes are unchanged (the lapse stays `uncharged`: `agent_inbox.py:1180` sends it so, `agent_mail.py:1122` stores it), only the count is new — which today carries no thread link (`_system_note`, `agent_mail.py:1095–1119`; the decline at ~1421 names the question only in its text), so the build gives each of those three notes `reply_to` and `root` of the question — `ask` and `steer` alike, one per question id; an answer whose question's root is a handed entry the seat still owes is not counted, the entry already being. `_asks`'s `asking` set takes the seat's own open `ask` and `steer` (`kind in ("ask", "steer")`, not `== "ask"`), so a handed entry stops counting while the seat's own `steer` on its thread waits, as it does for an `ask`. `_seat_due`'s `asks` cause carries that question's id in `member`'s place, so `seat_filled` fills it once, and reading it (`ao inbox` marks it read) ends the count. `read_when`'s `refills` is true for a person's reply to any question the seat asked, not only one on a handed entry's thread: the predicate at `agent_mail.py:897–905` drops its `replied.kind == "ask"` test (a `steer` counts), its handed-thread test, and its `sender == PERSON` test (`agent_mail.py:901`) for a question the seat itself sent, so a session's closing reply reads *fills this seat* too; the *waits in the seat's mailbox* sentence is left for a `note` and a `reply` to anything else. The member presets (`grinder.md`, `designer.md`, `hunter.md` under `src/shiftlead/briefs/`) gain one line: a seat's reply naming a question it asked the person is a deferral — keep the claim and wait for the seat's note. The techlead preset (`src/shiftlead/briefs/techlead.md`) gains §4.9b's rule: pass up what it cannot answer; a question of its own about a member's names the member's reference in `about`, answers the member with a `reply` on the member's thread naming its id (which closes the member's question, so the seat closes idle while it waits), and once answered sends the member what came of it, a `note` `--about` that reference.

**Done when:** tests hold that a closed seat (`seat: {trigger: asks}`) with an unread person reply to its own `steer` gets `seat_due` `by: asks` carrying the question's id and is filled once; that the same holds for the lapse note, the *Go with it* note and the decline note, each now carrying the question's `reply_to` and `root`; that a second person reply on an already-closed question counts nothing; that a session's reply closing the seat's own `ask` fills it and `read_when` says *fills this seat* for it; that the wake digest's *whether any wait* holds while an answer waits; that an uncharged lapse note fills the seat without spending its budget; that a note ending another session's question counts nothing; that a read answer, a reply to a question it did not send, and a plain `note` count nothing; that a second answer on another question fills again; that a handed entry with the seat's own open `steer` on its thread counts nothing and counts again once the answer lands; and that `read_when` says *fills this seat* for a person's reply to the seat's own question and *waits in the seat's mailbox* for a note. `pdm run test` and `pdm run lint` pass.

**Related:** TD-1051 (the design); TD-213 (the orphaned question); TD-1079, TD-1080.

**Resolved:** 2026-10-26 (grinder-ao-1, #2429) — `Session._asks` counts an answer waiting (an unread reply that closed the seat's own `ask` or `steer`, or the home's lapse, *Go with it* or decline note, which `_system_note(ends=…)` now gives the question's `reply_to` and `root`) by the question's id, never on a handed entry's thread; `asking` takes `steer`; `_asks_cause` puts the question's id in an `asks` due; `read_when`'s `refills` holds for any reply closing a question the seat sent, and the person's inbox read marks such a question `on_handed` for the Reply line; the techlead preset carries the relay rule and the member presets the deferral line. `tests/test_answer_waiting.py` holds the Done-when.
