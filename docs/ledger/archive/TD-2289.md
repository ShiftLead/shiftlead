## TD-2289: The design still says a change clears a team's cannot-run mark, though undoing the change brings it back

**Why:** Audit of #4783 (TD-2275). The entry's *Done when* reads "Neither §4.9d nor §5 says a change clears a node mark that returns when the change is undone", and it was archived Resolved. #4783 changed §4.9d *Where a seat's session launches* and §5, and left *A team on a node* in §4.9d, which still says it (b739cde95, lines 372-379):

- "marks the team *cannot run*, naming the model, until its list or its flow changes";
- "so a changed list, another flow, or the flow edited under its name to ask no longer for that model clears it with nothing written", followed by "Nothing removes the mark, so a list changed and then put back, with no refusal between, draws the same mark again".

The code leaves the mark unread and removes nothing at a change: `node_cannot_run` (`src/shiftlead/team_show.py`) returns None while the list or the flow's name differs from what the mark names, or the flow as read no longer asks for the mark's model, and reads the stored mark again once they are put back.

"Nothing removes the mark" is also not whole: a team's Delete pops the team's entry of the home's host record, the mark with it (`rpc_team_delete`, `src/sessionorc/agent_settings.py`, "so a new team of this name inherits no schedule or stopped mark").

§4.9e *A team on a node* says the same: the home marks the team *cannot run*, naming the model, "until the team's list or flow changes or the flow asks no longer for that model".
