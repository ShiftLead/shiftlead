**Why:** TD-1287: the row held four kinds of pick — a status, the team chips, a repo pick and a kind pick — which combine differently but are all drawn as plain chips, so Paul could not tell what a press would do. The design keeps the teams, one other pick drawn as what it is, and the find box.

**Fix:** as §4.5 screen 12 *Filters* and §4.5a write it:
- **The row.** `queue_filters.html` draws, in order: a small *teams* label (the `qsub` style the kind pick used), **All** and the team chips; the chips are the Queue page's `teams` (a team whose repo the view reads, or a picked one, as now) plus, for each repo in `view["repos"]` that no team's repo names and no team is named like, a chip named for the repo, `data-k="team"` alike, `title` *no team services this repo*, read on both sides by one rule, **an unknown chip name is a repo**: `apply_picks` reads `teams.get(t, t)` (not `teams.get(t, "")`) and `AO.qPass` the same, so a repo chip and a picked unknown name narrow to that repo on the server and in the browser with no new key and no entry added to `teams` or `team_repos`; *no team is named like* tests `team_repos`'s keys (every team with a repo, read or not, already in the ctx and in `data-teams`), not the ctx's `teams` list (which holds only teams whose repo the view reads), so a repo named like any such team draws no chip; the `- {""}` on the server and `filter(Boolean)` in the browser stay as a harmless guard (`team_repos` already omits a team with no repo, which `teams.get(t, t)` then reads as a repo of that name); the gate `q.repos | length > 1` goes, so a one-repo home with no team on it draws the chip too; each name in `picks["team"]` that no team names is drawn as a repo chip, so a picked chip whose repo is gone can be pressed off (so `?team=anything` draws a chip of that name, accepted); the team chips come first by name, then the repo chips by name, a repo chip with the `qfrepo` class (muted, italic); then a gap and the **Needs you (n)** switch — an `<a class="qf qswitch" role="switch" aria-checked>` (keeping `qf`, so the press handler's `#qfilters a.qf[data-k]` selector finds it) carrying `data-k="filter" data-v="needs-you"` and its check mark ☐ / ☑ before the words, styled apart from the chips by `.qswitch` (no chip border; the mark and the words), `title` *only the cards that need you — it narrows the teams picked, it picks none; the completed lines are hidden while it is on*, its count `#qfneedsn` as now (the page's needs-you cards, not narrowed by the chips); the mark is CSS (`.qswitch::before` from `aria-checked`), so no text is rewritten and the page without script is right at load, and Space toggles it as Enter does: the box's one `keydown` handler (`app.js` near line 4474, today `.qghead` and `.qdhead` alone) gains a branch for `#qfilters .qswitch` that calls `preventDefault()` and `click()` on Space; then the find form, whose hidden inputs carry `filter` and `team` alone. **Steering**, the repo chips and the `qkinds` span are removed, and `.qkinds` with them.
- **The picks.** `FILTERS` is `{"needs-you": …}` alone; `queue_picks` drops `repo` and `kind` (an old `repo=`, `kind=` or `filter=steering` reads as not picked, never an error — today's *unknown is dropped* rule, widened); `picks_query` writes `filter` and `team` alone; `apply_picks` loses the repo and kind branches and the steering branch, so a card passes by the chips, the switch and the find; `status_pick` is the switch alone; a team name mapped to itself is a repo with no team. `KINDS`, `_card_kinds`, the card's `kinds` field and `queue_card.html`'s `data-kinds` attribute go — `_item_kind` stays (it feeds an item's `kind`, which `test_queue_with_you.py` reads), its docstring's `KINDS` reference reworded — (the `_card_kinds` clause TD-1284 built with them), and the Queue page's `ctx` drops `kinds`. **All**'s `aria-pressed` is *no chip picked* (not `q.filtered`, which stays the *(n of m)* counts' test); **All** clears the chips only; the switch and the find keep their own state. `picks_query` gains a clear — a list value replaces the list while a string still toggles (new: today a value only toggles), its docstring reworded to say so, so `pq(picks, team=[])` is the chips cleared and the rest kept — and **All**'s `href` is that, not `/queue`.
- **The browser.** `app.js`'s Queue apply drops `picks.kind`, `picks.repo` and the steering test, its parse ignores the dropped keys from the URL and from the remembered picks (a memory holding `kind=` restores as if it held none), the press handler and its re-mark loop set the switch's `aria-checked` where they set a chip's `aria-pressed`, `AO.qFiltered`, the `popstate` handler and the two `remember()` conditions (near lines 4339 and 4483, which test `picks.repo.length || picks.kind.length`) drop `repo` and `kind`, and **All** clears `team` alone: its press is `setPicks({...picks, team: []}, true)`, so the URL keeps `filter` and `find`, the memory keeps `filter` alone (`remember()` already drops `find`), and the find box keeps its words (today it blanks them); the re-mark loop's **All** `href` is `AO.qQuery(picks, {team: []})`, with `qQuery` given the same list-replaces rule; a restored memory has its dropped keys removed before `base.html`'s head script writes the URL.
- **The mockup.** `Queue.dc.html`'s filter row is redrawn from the live row (its source still has the row before TD-911), regenerated by `gen.py`.
