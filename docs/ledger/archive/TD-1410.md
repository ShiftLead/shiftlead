## TD-1410: Focus draws tmux's green status bar in the pane, and a resize by another client leaves stale copies of it

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-05
**Owner:** grinder
**Kind:** build
**Status:** Resolved 2026-11-06
**Id take:** b47722f0523843db8d9ed80481b48e69

**Why:** Paul's screenshot of 2026-11-05 (`~/.shiftlead/attachments/draft-990505e5/paste-20261105-125118.png`): in Focus on `env-check-shell`, a shell on the contractmatch node, the pane draws tmux's own status bar, `[ao-contra0:bash*  "95e5ff94e074" 19:49 05-Nov-26`, a full-width green band. It is drawn twice, a minute apart (19:49, 19:50), and the header says *resized by another client*. Nothing in ShiftLead sets tmux's `status` option (`src/sessionorc/tmux.py` sets only `exit-empty`, `history-limit` and `remain-on-exit`), so every `ao-*` session keeps tmux's default bar. The Focus header already shows what that bar says (the session's name, its state, the host). When another client resizes the window (design §4.6 *Attach behaviour with another client present*), tmux repaints the bar on a new bottom row. The browser's terminal keeps the old copy as content, so the pane fills with stale green lines that look like output.

**Location:** src/sessionorc/tmux.py (`new-session`'s option chain); src/shiftlead/ui/pty_bridge.py (the clients frame's `#{status}`); design §4.6 *Attach behaviour with another client present*

**Resolved:** 2026-11-06 (PR #2989)

**Done when:** A test that a session `tmux.py` creates has `status` off. A look on a scratch home (`scripts/look_home.py`) in which a shell Focus resized by a second attach of another size draws no green status line, with a screenshot under `docs/mockups/reviews/`.
