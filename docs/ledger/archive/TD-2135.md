## TD-2135: A flow file nested too deeply crashes the flow check instead of reporting a problem

**Priority:** Low
**Added:** 2026-11-23
**Owner:** grinder
**Kind:** build
**Status:** Resolved 2026-11-24
**Id take:** 6da897e438f048b79524383f514ec79a

**Why:** A flow file nested past the YAML parser's depth makes the flow check raise instead of reporting a problem. `flow3.check_text("[" * 5000)` raises RecursionError, because it and `flowdefs.parse` catch only `yaml.YAMLError`. A repo's flow reaches this check by a commit, so one bad file can fail whatever page or team read is checking it.

**Resolved:** 2026-11-24 (PR #4480) — src/shiftlead/repoconfig.py parse_yaml; tests/test_flow3.py, tests/test_flows.py

**Done when:** A flow file nested past the parser's depth is reported as a problem by the flow check and by a team's load of that flow, with a test for each, and nothing raises.

- 2026-11-24: archived: Resolved — repoconfig.parse_yaml reads a text nested past the parser's depth as invalid YAML, so the flow check and a team's load report it; a test covers each.
