**Type:** feature

**Owner:** grinder

**Status:** Done — was: Partly done — **re-owned 2026-10-08 (the person's session): every half that waited on dev-cadence is built.** dev-cadence TD-036 (its PR #110) gave a board entry `Answers:` and `Decided:`. The Inbox's board rows draw the suggested answers and write the press onto the board (`inbox_row.html`, TD-142, TD-305), and a decided board line is a work order a grinder takes first (TD-380, built by TD-384). **What is left is agentorc's, and small:** `ao msg --reply-to <id> --pick <n>` still refuses text (*sends the answer itself: leave the text out*, `cli.py`), the friction note below. **Location:** `src/sessionorc/mail.py` (the message shape), `src/sessionorc/agent.py` (`rpc_msg`), `src/agentorc/cli.py` (`ao msg`), the Inbox UI (dialog today, TD-069's page), `docs/briefs/` (so leads and workers use it)

**Why:** most questions a session puts to a person have two or three expected answers — *merge it / hold it*, *yes, deploy / not tonight*, *option A / option B* — and the sender knows them when it asks. Today the person reads the question, presses Reply, and types. Offering the answers beside **Reply** and **Delete** turns the common case into one click and keeps free text for the rest.

**Resolved:** 2026-10-08 (PR #1282, grinder-ao-2) — the last half: `ao msg --reply-to <id> --pick <n> "text"` sends the picked answer, a blank line, then the text, with `answer` kept, and the home's check (`agent_mail.py`) accepts that shape; design §4.10 *Suggested answers* says so, `tests/test_cli.py::test_msg_answer_and_pick_and_the_inbox_lines_that_show_them` and `tests/test_mail.py::test_the_home_checks_that_a_picked_answer_is_one_of_them` pin it. The rest was built earlier: `answers`/`answer` on the envelope with its bounds (§4.10), the Inbox's buttons (§4.5a), the board's `Answers:`/`Decided:` (dev-cadence TD-036) and a decided line as a work order (TD-384).

**Board items too (Paul, 2026-09-18).** A board entry is a question to a person as often as mail is — *approve the `rm -r`*, *decide TD-260*, *merge or hold* — and on the Inbox page (TD-069) it should carry the same buttons. That needs the entry to say its answers, which is **dev-cadence's format, not agentorc's**: the entry format is defined in `docs/cadence.md` §3, a SYNCED file edited in dev-cadence and never here (the board file itself, `docs/user_attention.md`, is SEED — each repo's own — so its entries are written here, in a format decided there). The shape to propose there: an optional trailing field on the entry line, after `Due:`, listing a few short answers; an entry without it is exactly what it is today, so no consumer breaks. What pressing one *does* is the open part — a board item has no sender waiting on `ao wait`. The cheapest honest meaning: the answer is written back onto the entry (the same agent write-back as Snooze and Done, §4.4) as the person's decision, with the date, and the entry stays on the board until a session acts on it and removes it — so the next session in that repo reads the decision from the SessionStart hook, which already prints due items. Steps: (1) the dev-cadence change — its own ledger entry and PR in that repo, by a session there; (2) agentorc gains a board parser that reads the field — none exists yet: only dev-cadence's `scripts/nudge_user_attention.py` and `scripts/list_sessions.py` read the board today, and §4.4's write-back is unbuilt; (3) the Inbox row renders the buttons and the write-back records the press; (4) the briefs make a decided entry work — below.

**The entry is the work order (Paul, 2026-09-18; dev-cadence TD-036, merged as its PR #93): a decision generates no TD.** Which only works if a grinder reads it, and today it would not. `docs/briefs/tdgrind-ao-1.md` tells the grinder to **avoid** *anything on docs/user_attention.md awaiting Paul's decision*, picks work from the ledger unless a lane was handed to it, and defines a `free-pick` lane's *out of work* by the ledger alone (an item *parked on `docs/user_attention.md` waiting for a person* is excluded, decided or not) — so a decision Paul records changes nothing a worker looks at, and a team can declare itself out of work beside a board full of answers. That is the loop the samscrape team closed on 2026-09-17, when all three grinders declared themselves out of work with, in their lead's words to the person inbox, *every open TD gated on Paul/deploy/eval/data*. Step 4, wherever a team's standing text lives — this repo's `docs/briefs/`, contractmatch's own `docs/briefs/`, and the package's generic role templates (`src/agentorc/briefs/`, `grinder.md` among them), which is what `samscrape-grind` runs on (its `org.yml` entry names no `brief:`, and samscrape has no `docs/briefs/` or `.agentorc.yml`): a board entry carrying `Decided:` is no longer *awaiting* and is **claimable** — claim it by its `Context:` reference, ledger it first if it names none, act on the decision as written, and remove the entry in the PR that does the work; a lead's round reads the board for newly decided entries and says so to its members; and a `free-pick` lane is **not out of work while a decided entry stands unclaimed**. Until dev-cadence's parser carries `Decided:`, the briefs can only say *read the entry's text*.

**Found in the techlead trial, 2026-09-21 (manager-ao-1's friction note):** `ao msg --reply-to <id> --pick <n>` refuses text (*sends the answer itself: leave the text out*), so a reader that wants to pick an answer **and** say one more thing has to send two messages, or type the answer out and lose the `answer` index that tells the asker which was chosen. Small: let `--pick <n> "text"` send the picked answer with the text after it on the same reply, the index kept — a page's button stays text-free. Unscheduled.

**Done when** an ask sent with `--answer` shows its answers as buttons beside Reply and Delete, pressing one delivers that text as a `reply` that wakes the sender's `ao wait`, free-text Reply still works, and the bounds are in §4.10 and enforced at the RPC.
