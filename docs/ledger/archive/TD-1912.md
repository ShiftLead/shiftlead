## TD-1912: The Focus terminal draws emoji and wide characters in the same cells tmux gives them

**Priority:** Low
**Type:** debt
**Added:** 2026-11-16
**Owner:** grinder
**Kind:** build
**Status:** Resolved 2026-11-17
**Id take:** fda8a24234764dc0a485cec1459d619c

**Why:** The Focus terminal loads xterm.js 5.5.0 with the fit, WebGL and web-links addons and no Unicode addon, so xterm.js measures character widths with its Unicode 6 tables while tmux 3.5a and Claude Code use newer ones. Emoji, ZWJ sequences and symbols such as ⚠️ ✓ ✗ ① then take a different number of cells in the browser than tmux assigns them, so box drawing and wrapped lines drift in the browser (2026-11-16, Paul: text cut off and lines repeated in Focus; the duplicate in tmux's own history has a separate cause, resize churn with long lines, and this does not fix it).

**Location:** src/shiftlead/ui/static/app.js (AO.termRenderer, the terminal's setup); src/shiftlead/ui/static/vendor/README.md

**Resolved:** 2026-11-17 (PR #4055)

**Done when:** A Focus terminal shows a line of emoji, symbols and a ZWJ sequence in the same cells tmux gives it (`#{cursor_x}` after the line matches the browser's cursor column), and a test holds that the addon is vendored, loaded and active.
