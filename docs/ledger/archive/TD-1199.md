## TD-1199: `test_ui_held_bar`'s focusout is not the one its docstring names: call `decide` straight from `focusout` and the suite stays green

**Priority:** Low
**Type:** debt
**Added:** 2026-10-28 (test-audit-ao-1, from #2606)
**Owner:** grinder
**Kind:** build
**Status:** Done
**Location:** `tests/test_ui_held_bar.py` (`PROBE`, the `focusVisible = false; barOn.focusout(); out.focusout_now …` lines; `test_a_phone_scroll_sends_the_bar_away_…`'s `focusout_now` assert); `src/shiftlead/ui/static/app.js` (`AO.holdBar`, the `focusout` listener)

**Why:** `holdBar` reads the bar a frame after `focusout` (`bar.addEventListener("focusout", () => requestAnimationFrame(decide))`), because *during `focusout` the leaving element still matches `:focus-visible`*. The test asserts `focusout_now is False, "read a frame after the focus leaves, never during focusout"`, but the probe sets `focusVisible = false` before it calls `barOn.focusout()`, so a `decide` run at once sees no focus too and answers the same. Probe on `origin/main` (2026-10-28): change that listener to `bar.addEventListener("focusout", decide);` and run `tests/test_ui_held_bar.py` — 3 passed. The real bug that line prevents (a bar held by the focus that is leaving it, so it stays on screen after a Tab out) is set in no test.

**Fix:** make the fake model the browser: `focusVisible` stays true while `focusout` runs and goes false only when the queued frame callbacks run, and assert the bar is not decided until then.

**Done when** the probe keeps `focusVisible` true through `barOn.focusout()`, and `test_ui_held_bar.py` fails with the listener changed to call `decide` directly.

**Resolved:** 2026-10-28 — #2612: the probe keeps `focusVisible` true through `barOn.focusout()` and records each `:focus-visible` read; the test asserts none during `focusout` and one `False` read in the frame, and fails (`[True] == []`) with the listener calling `decide` directly.
