## TD-1046: A pinned repo's convention note carries each entry's body, and rule 12 reads a pinned root and dev-cadence's source under their own bounds

**Priority:** Low
**Type:** debt
**Added:** 2026-10-26 (the designer, from TD-1025)
**Owner:** grinder
**Kind:** build
**Status:** Resolved
**Location:** `src/sessionorc/conventions.py` (`parse`, `note`), `tests/test_conventions_policy.py`, `tests/test_cadence_pin.py` (its conventions test), `src/sessionorc/agent_tick.py` `_conventions_pass` (its call of `note`, and its *told of n new in docs/cadence-changes.md* log line); design §6 rule 12 (*In a pinned repo*)

**Why:** TD-1025: in a pinned repo the changes are dev-cadence's, read by the pinned tree's `cadence_changes.py --json` from the commit the repo's `origin/<default>` pins, and the repo holds no `docs/cadence-changes.md`, so today's note (*docs/cadence-changes.md gained … — read it on `origin/main`*) sends the member to a file that is not there, and `dev-cadence path` in a worktree branched before the bump resolves the old pin.

**Fix:** as §6 rule 12 now says: (1) `parse` keeps each entry's `body` (a string, else `""`). (2) `note(told, ref, path=None)`: with `path` (the pinned case) it says *dev-cadence's cadence-changes.md gained {count} since you started: {named} {and n more} — after rebasing onto `{ref}`, `{path}` prints its path; go on*, each named entry followed by `: ` and its body, the body's lines joined by a space, a body over 300 characters cut to its first 300 followed by `…`, an empty body leaving the name alone; three named at most as now; without `path` the words are unchanged. (3) `has_script` and `read` take dev-cadence's source as `cadence.has_script` does (`cadence.is_source`: the script at `files/scripts/cadence_changes.py`), which §6 rule 12 already names and the code lacks; `read` bounds a pinned root's run at `cadence.TREE_TIMEOUT` (it may fetch or clone dev-cadence's source under the launcher's 300 s bound), an unpinned one at 180 s as today — per call, `has_script`'s resolve (`cadence.tree`, cached) bounded on its own, so a first resolve after a bump and the run may together take two bounds, accepted; `_conventions_pass` passes `path=cadence.typed("path", "cadence-changes.md")` when `cadence.pinned(root)` — for a member whose `host` is not the home's, `path="dev-cadence path cadence-changes.md"`, the container's link (`containers.PATH_DEV_CADENCE`), since the home's interpreter and launcher paths do not exist there — its log line saying *dev-cadence's changes* there, and logs any root's reading with no entries (`entries == []`, not `None`, whose existing *gave no reading* line now carries a reason: `read` returns `(got, why)`, `why` the script's last stderr line on a non-zero exit, else `exit N, no output`, `timed out after Ns`, the `OSError`'s text, *no script* when `has_script` is false (for a direct caller: the pass skips such a root before `read`), or *output is not the script's --json* when `parse` fails, and `None` with a reading; the existing tests' `read` stubs and `test_no_script_is_no_reading` move to the tuple, and `test_the_scripts_json_is_read`'s expected view gains `body`; in `tests/test_cadence_pin.py`, `test_a_pinned_repos_conventions_run_the_pinned_trees_script_through_the_resolver` moves too — its `None` becomes `(None, "no script")`, its expected entry gains `body: ""`, and the pinned run's argv it checks stays unchanged, a stub returning `(got, None)`), pinned or not, at info (pinned: *no entries — the checkout's pin may predate dev-cadence's change*; unpinned: *no entries — the checkout may predate the migration, or still hold docs/cadence-sync.lock beside its pin*), once per root until a reading gives entries: a set of `(root, line)` pairs on the tick (`_conventions_quiet`), a pair added when it logs and dropped when its condition ends — the no-entries line when a reading gives entries, the no-tree line when `has_script` turns true; a restarted home logs it once again. A pinned root whose `has_script` is false (its tree cannot be made) logs *pinned, no tree: <the resolver's why>* at info under the same set, the why read from `cadence.tree(root)` (cached), since `has_script` returns a bool — a tree present but lacking the script logs *pinned, no tree: no scripts/cadence_changes.py in the tree* — where today it passes silently. (4) the two docstrings that stop being true say so: `read`'s (*the script asks git once per entry for its `landed`, hence the long timeout* — in a pinned repo the walk reads each pin once, and the run's bound is `cadence.TREE_TIMEOUT`) and the module's (*the words are the script's `date` and `title` fields* — a pinned note carries bodies). Nothing else in rule 12 changes: the reading, `conventions_seen` and `sort` are as today, and the entries a pinned repo gives come from dev-cadence's own change (TD-1025's text), not from this entry.

**Done when:** a test of `note` reads both wordings, the pinned one carrying each named entry's body, a body over 300 characters cut with `…`, and an empty body; a test of `parse` keeps `body`; tests of the pass on a pinned fixture root — `cadence.pinned`, `cadence.tree` and `cadence.command` stubbed, since `has_script` and `read` resolve through them, the stubbed command a script printing `--json` — (a) an entry landed after the member's `created` sends the pinned wording once (a node member's naming `dev-cadence path cadence-changes.md`) and records the heading in `conventions_seen`; (b) the migration: a member created before it whose first reading falls after it, with five entries landed at the migration, gets one note naming three and *and 2 more*; (c) a stub printing no entries (a checkout pinned before dev-cadence's change), an unpinned root whose script prints none, and a root holding a pin beside `docs/cadence-sync.lock` (read as unpinned), each send nothing, fail nothing, and log the info line once over two passes; (d) a stub exiting 2 with a stderr line logs *gave no reading — <that line>*, and one exiting 2 with none logs *exit 2, no output*; (e) a pinned root whose stubbed `cadence.tree` returns `(None, why)` logs *pinned, no tree: <why>* once over two passes, and again after `has_script` turned true and false, and a root that logged *no entries* and then loses its tree logs the no-tree line; (f) unit tests of `read` and `has_script`: dev-cadence's source root read at `files/scripts/`, each `why` text, and the pinned root's timeout `cadence.TREE_TIMEOUT` against the unpinned 180; `pdm run test` and `pdm run lint` pass.
