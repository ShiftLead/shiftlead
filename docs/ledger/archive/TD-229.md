**Why:** TD-210's *Why*, and Paul's answer to it: a team's definition belongs with the repo it works, versioned and reviewed there, and the home should hold only what no repo can.

**Fix, in slices a PR each:**
1. **The aggregate**: `ao team` reads `teams:` from every checkout in the host's registry, as the pages already do (`teamrun.org_with_repo_teams`), and one function serves both; a repo's team takes the repo as its project (name the directory's, path the registry's; an org project of that name is used as it stands) and a `projects:` key, a `host:` and a nested `{team: …}` member on it are each refused; two repos naming one team are both refused, each naming the other (today `merge_repo_teams` tests the org file alone, so the later repo wins silently); the org file wins a name and the repo's reads *shadowed*. `ao team list`, the Org page and the New session form read the one aggregate. Nothing in `org.yml` has to change for this slice: what it defines still wins.
2. **This repo's definitions**: `.agentorc.yml` (created here, or by TD-132 slice 4 if that lands first) holds `teams: ao-grind` as the org file has it today (the manager, the techlead seat, the two grinders and the designer, their lanes and briefs; no `host:`, and no `profile:` the overlay already gives) and `roles:` `grinder` and `designer` with `review: {reader: techlead, held: [src/sessionorc/**, docs/briefs/**]}`, whole: `resolve_role` replaces a layer's `review:` and `normalize_review` refuses one with no reader. While the org file still defines `ao-grind` it shadows this one, so the PR changes nothing that runs; Paul's edit of the org file (the board line) is the switch.
3. **`place:` and a node's registry**: `place: {<team>: <host>}` in the org file; the landing rule of §4.9; a link method that returns a node's registered checkouts, asked when the home's registry lacks the repo.
4. **Members…**: disabled on a repo-defined team with its reason and **Open file**; `edit_members` refuses a source that is not the org file.
5. **The history**: at the home, `~/.agentorc` initialised as a git work tree by `ao service install` when it is not one (an ignore file that tracks `org.yml`, `profiles.yml` and `settings.yml` alone; never on a node). The host agent is the one committer: after `set_settings`, on `commit_defs {message}` (a person's own, in `modes.HOME_EDITS`; the UI calls it after `edit_members` wrote), and on the reports' cadence for a hand edit; a file that does not parse is not committed; no remote is added and nothing is pushed; a commit that fails is logged and never fails the write.
6. **`ao org` and `ao org check`**, and tests: two registered checkouts each defining a team give both; the same name twice refuses both; the org file shadows; a repo's team with `projects:` is refused; a team lands on the node that holds its repo and is refused with two; a repo's team with `host:` is refused; `set_settings` leaves one commit and a failed commit leaves the setting written; a half-written `org.yml` is not committed and the next whole one is; `hosts.yml` is never tracked; `ao org check` exits 1 on a registered checkout that is missing and on a settings team nothing defines, and warns on a checkout off its default branch.
