**Why:** the anchor is the only thing that makes a merge live, and it is going away (TD-120). Every night's merges wait on a person's two commands; the design makes that a press on the Inbox or a policy of the tick, and generalizes it to any repo (Paul 2026-09-23: *these design items have to be generalized for any repo*).

**Fix:** four slices, each its own PR, in this order — the first two touch `src/sessionorc/**`, so the techlead reads them (§4.9b *The reader*).
1. **The readings and the policy** (`sessionorc.promote`, the tick): the block read from each registry checkout's `.agentorc.yml` by key alone (a missing or malformed block is logged and skipped, never fatal to the tick); `live` from `check` (cwd the checkout; a failed read keeps the last good one with `why`), `main` after the home's own `git fetch origin main`, `checks` from `gh api repos/{owner}/{repo}/commits/{sha}/check-runs` (`green` / `pending` / `failed` / `unknown` with why), each at the reports' five-minute cadence, detached from the tick; `promotes: {<repo>: {live, main, ahead, checks, auto, inflight, failed, at}}` on the `host` RPC; the three preconditions as one function that returns the first unmet one's name and text; `auto: true` acting after `PROMOTE_SETTLE` (10 min) with main still; the run detached (`start_new_session=True`, output to `~/.agentorc/promotes/<repo>/<sha>.log`), `inflight.json` written **before** the start; the outcome from `check` on later ticks — done clears the file and files the `system` note *promoted `<repo>` `<sha>` — n commits* to the person inbox; gone or past `PROMOTE_BOUND` (20 min, killed) → `failed.json` and no further promote of that repo until it is cleared. A promote of *this* repo restarts the agent mid-pass: the test is that a fresh agent finding `inflight.json` with `check` reading the wanted commit files the note and clears the file.
2. **The RPC and the CLI**: `promote {repo, sha}` — person-only, refused to a session with the same words as `set_settings`; refused, naming it, on preconditions (1) and (3), going on through (2) with the verdict in the reply; returns `{started, log}`; `clear_promote {repo}` (Dismiss's half); `ao promote [<repo>] [--sha]`, `ao promote status` and `--json`. `ao --skill` says a session never promotes (it says it already under *Never*).
3. **The Inbox row** (§4.5a, the row's text): drawn from `promotes` alone; *Needs you* and counted under `auto: false` when ahead, and on a failure; FYI while in flight; nothing but a failure under `auto: true`; **Promote**, **Snooze ▾** (the attention store, by time), **Dismiss** on a failure row only (`clear_promote`); refusals drawn in place. Regenerate nothing: the mockup already carries the row (`docs/mockups/gen.py`, PR #525).
4. **This repo's block**: `.agentorc.yml` with `promote:` alone — `run` and `check` only, since 2026-09-25: **`auto` lives in `settings.yml` (`repos.<repo>.promote.auto`, TD-146) and slice 1 reads it there**, the Settings page's switch and `ao settings` setting it — `run` the pip pair of CLAUDE.md (`~/.local/share/agentorc-venv/bin/pip install --upgrade '<checkout>[ui]' && ~/.local/share/agentorc-venv/bin/ao service install`, the checkout's path read from the cwd, never hard-coded), `check` the venv's python printing `sessionorc.build.info()["commit"]` and exiting 1 with *build unknown* when there is none, `auto: false` — then a live check on the board: main ahead → the row; the press → the note; Paul flips `auto` when he trusts it. The other repos' blocks are their own sessions' (samscrape: skaffold and the image tag; contractmatch: wrangler; dev-cadence: its sync). Fold in TD-062's last two lines: the top bar's build line, and `ao team start` printing it.

**Done when** (1) with `auto: false`, a merge to `main` draws the row on the Inbox within five minutes, **Promote** on it makes the merge live and the FYI note names the commit, and `ao promote status` agrees with `ao status -v`'s build line; (2) with `auto: true`, three merges inside ten minutes produce one promote, ten minutes after the last; (3) a `run` that exits non-zero, or hangs past twenty minutes, is a counted row with the log's tail, and a second merge promotes nothing until Dismiss; (4) `ao promote` from inside any session is refused; (5) a promote of this repo, which restarts the host agent under its own policy, still ends in the note and a cleared intent file; (6) a repo without the block has no row and `ao promote` there says so; (7) TD-062 and TD-120 archived.
