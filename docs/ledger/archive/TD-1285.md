## TD-1285: This repo is public, but a fork's PR gets no forge CI, and ShiftLead offers its precheck line, which runs the fork's code on the machine

**Priority:** medium
**Type:** debt
**Added:** 2026-10-30 (Paul, session `td-191`: "We should probably record TDs in agent-cadence and shiftlead for this as well")
**Owner:** designer
**Kind:** design-first
**Status:** Resolved 2026-10-31: a fork's PR runs this repo's CI in Actions, no session is handed its precheck line, and the person sees it with `--fork-ok` once its forge CI is green
**Location:** `.github/workflows/ci.yml` (a fork's PR and by hand since slice 1; `workflow_dispatch` only before, TD-1035); `AGENTS.md` (*A PR's gate is its `cadence/precheck` status, not GitHub Actions*, ~131); `docs/briefs/`; `src/sessionorc/cadence.py` `precheck_typed()` (the `precheck.py --pr` line a session is told to type) and its callers in `agent.py`; `src/sessionorc/reports.py` (the PR row's `fork`); `src/sessionorc/sync.py` `decline()` (already declines a fork)

**Why:** TD-1033 and TD-1035 moved this repo's gate to the local precheck, because the account's Actions minutes were one shared pool. A public repo runs Actions free, so that reason lapses here. The local gate also has a cost on a fork's PR. `precheck.py --pr` checks out the fork's head and runs its `pdm run lint` and `pdm run test` on the person's machine, with their `gh` token and home directory in reach.

The sync pass already declines a fork before it prechecks. But where ShiftLead tells a session or the person how to gate a PR, it offers the same `precheck.py --pr` line whether or not the PR is a fork's. agent-cadence decided this for itself in TD-192 (2026-10-30): `ci.yml` runs on a fork's PR only, it is not required, and a fork's precheck is the person's, after reading the diff and seeing that run green. agent-cadence#TD-207 adds the refusal to `precheck.py` itself, for every consumer.

**Resolved:** 2026-10-31 — slice 1, PR #2762 (`ci.yml` on a fork's PR; no work order, and `done`, `ask --pr` and `ao pr wait` never give the line; AGENTS.md and the briefs); the design, PR #2766; TD-1292, PR #2767 (the person's line on the Repo page and the counted row)

**Done when** a fork's PR runs this repo's CI in Actions, the person sees a fork's precheck line (with `--fork-ok`) only once its forge CI is green, no ShiftLead surface hands a session that line, and the docs say how a fork's PR is gated.
