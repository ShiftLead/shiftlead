## TD-1827: write_layer's temp file is named by pid alone, so a launch and the tick's setup_note thread race and one fails ENOENT (a test_seat_life gemini flake)

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-14
**Owner:** grinder
**Kind:** build
**Status:** Resolved 2026-11-14
**Id take:** ded6e7c74c8d40c8824e81cd406e2992

**Why:** `write_layer` in `src/shiftlead/adapters/gemini/__init__.py` writes the wanted copy through a temporary file named `.layer.json.<pid>.tmp`. A launch on the host agent's event loop (`agent.py:1821` → `machine_reading()` → `write_layer()`) and the tick's `setup_note`, run in `asyncio.to_thread` (`agent_tick.py:343` → `machine_reading()`), are two threads of one pid, and when they overlap both write that same file. The first `os.replace` moves it away, and the second fails with `ENOENT`, which fails the launch. The precheck of #3815 at e3f1fa921 failed this way under the full suite, in `tests/conformance/test_seat_life.py::test_a_seats_life_on_the_stub[gemini]`: `[Errno 2] No such file or directory: '…/home/gemini-settings/.layer.json.370719.tmp' -> '…/gemini-settings/layer.json'`. The same suite passed in this worktree at the same code (6989 passed). `src/shiftlead/adapters/claude_code/hook.py:393/446` and `src/shiftlead/cli.py:3900/6437` name their temporary files the same way. TD-1710 and TD-1749 were earlier flakes of this test with other causes.

**Location:** src/shiftlead/adapters/gemini/__init__.py write_layer; src/sessionorc/agent_tick.py setup_note thread; tests/conformance/test_seat_life.py

**Resolved:** 2026-11-14

**Done when:** Two concurrent `write_layer` calls in one process both succeed, and a test holds this. It fails if the temporary name goes back to the pid alone.

The other <pid>.tmp writers in Why (hook.py's two, cli.py's two) each run in a single-threaded process of its own (a hook, an ao client), so no two of them overlap inside one process: left as they are.
