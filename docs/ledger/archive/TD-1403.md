## TD-1403: An unserved repo's gated build counts as pickable on the org card: its reading gets no waiting mark

**Priority:** Low
**Type:** debt
**Added:** 2026-11-05
**Owner:** grinder
**Kind:** build
**Status:** Resolved 2026-11-07
**Id take:** 6d7d79200dd1472aa37aa90af08b441b

**Why:** Since TD-1395 (#2972), `ledger.kind_of` reads past an `until` or `event` gate, so a gated build's `for_page` is *pickable*; what withholds it is the home's `waiting` mark, which `settle.mark_waits` adds inside the tick's `_settle`. In a repo the home does not serve (`seams.unserved`), `_settle` is skipped, so the entry carries no `waiting` mark: `ao repo` corrects its count through `cli._unserved_lanes`, but `teamrun.lane_kinds` and the org card (`ui/org.py`) count `by_kind["pickable"]` with nothing subtracted, so that repo's *n pickable* can read one too high per gated entry. Before TD-1395 such an entry read *blocked*. Nothing becomes takeable (an unserved repo has no lanes); only the count is wrong. Found by #2972's independent review.

**Location:** src/sessionorc/agent_tick.py (_settle, the unserved branch); src/shiftlead/teamrun.py (lane_kinds); src/shiftlead/ui/org.py

**Resolved:** 2026-11-07 (PR #3126)

**Done when:** A test that an unserved repo's reading with a build `Blocked by: event (x)` (its section written) carries `waiting` and is not counted in the org card's or `lane_kinds`' *pickable*.
