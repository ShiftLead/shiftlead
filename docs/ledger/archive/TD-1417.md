## TD-1417: Two tests build tomorrow from the local date, so every precheck fails from 00:00Z to local midnight

**Priority:** High
**Type:** debt
**Added:** 2026-11-06
**Owner:** grinder
**Kind:** build
**Status:** Resolved 2026-11-06
**Id take:** 1d70a0cf2b4a4deab806f0d386f0fe70

**Why:** Since TD-1395, an `until` gate is read against the UTC day (design §4.4 *What a wait does*). Two tests still built their "tomorrow" from the local date. These are `tests/test_entry_team.py`'s module `TOMORROW` (`NOW.astimezone().date()`) and `tests/test_lane_news.py::test_an_entry_whose_wait_ends_is_told_once_and_not_before` (`now.astimezone()`). On kmaster (MST), local tomorrow is the UTC today from 00:00Z to 07:00Z. In that window the wait has already ended, and both tests fail. Every precheck failed there on 2026-11-06 from 00:00Z: #2986 and #2987, both ledger-only.

A smaller race is left in `tests/test_waits_gates.py`, which reads `NOW` once at import. A run that crosses 00:00 UTC between the import and the test sees `until TOMORROW` as today.

**Location:** tests/test_entry_team.py (TOMORROW); tests/test_lane_news.py (test_an_entry_whose_wait_ends_is_told_once_and_not_before); tests/test_waits_gates.py (NOW at import)

**Resolved:** 2026-11-06 (PR #2988)

**Done when:** Both tests pass whatever the local timezone, including between 00:00Z and the local midnight, and `pdm run test` passes.
