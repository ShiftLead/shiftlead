## TD-979: A close reaps the worktree ShiftLead made for its record, when nothing in it would be lost; the restarts keep it; `worktree_kept` says why one is kept (TD-978's build)

**Priority:** Medium
**Type:** debt
**Added:** 2026-10-22 (the designer, from TD-978)
**Owner:** grinder
**Kind:** build
**Status:** Done 2026-10-23 (grinder-ao-2)
**Location:** `src/sessionorc/agent.py` (`rpc_close` and its `reap` argument, `rpc_restart`'s close, `_cancel_start`, `rpc_create`'s `worktree_made`, and its locking: the directory's lock taken before the worktree's is let go), `src/sessionorc/adapters.py` (`external_sessions`' `blind`), `src/sessionorc/agent_tick.py` (the `is_dir` check of kept records; the closes in `_lost_brief`, `_wanted_restart`, `_brief_restart`, `_cache_restart`, which keep, and in `_finished_close`, `_sit_out_close` and `_seat_pass`, which reap), `src/shiftlead/teamrun.py` (`_close_settled`, the team Start's close), `src/shiftlead/cli.py` (`ao host down --wind-down`, `ao close` on a closed record, `ao status`), `src/sessionorc/gitinfo.py` (`ensure_worktree` reporting creation and basing the launch branch on `origin/<name>`; the reap beside it), `src/sessionorc/models.py` (`worktree_made`, `worktree_kept`, `worktree_reaped_at`, `worktree_reaping`, `branch_kept` (a map of branch to why), `branches_deleted` (a list): `Session` fields with `to_dict`/`from_dict`, `NODE_OWNED`, the view), `src/shiftlead/ui/app.py` (`resume_create`, `resume_form_url`), `src/shiftlead/ui/` (the Session card's directory line, the Git card and diff / log / PRs on a reaped record), `src/shiftlead/ui/help.py` (Close's and Kill's paragraphs); design §4.1 *A close reaps the worktree it made*

**Why:** TD-978. A closed member's worktree holds its branch at its last commit, and once another session rebases that member's open PR, the gate's `pushed` row fails on the stale local branch. Detaching the worktree's HEAD would not be enough, because the row reads `refs/heads/<branch>`, so the local branch has to go too.

**Fix:** as design §4.1 *A close reaps the worktree it made* says:
- **Which closes.** `rpc_close(..., reap: bool | str = True)`, with `reap` carried in `_route_act("close", …)`'s arguments; a missing one reaps. The person's Restart and the four tick restarts pass `reap=False`; every other caller keeps the default. A `scheduled` Cancel reaps a worktree its scheduling made, under the same tests.
- **What is reaped.** A record gets `worktree_made` when `ensure_worktree` created its worktree (it returns whether it did), or inherits it whenever `supersedes` names a record that has it and the start reused that record's worktree at the same `dir` (a restart, Resume, scheduled start, team Start, refill or New session under a closed holder's name). It is tri-state: true, false, or absent for a record from before the build. A one-time migration marks only an absent one that holds a `worktree`, a `team` and `unattended`; it is idempotent and never touches a `False`. Only such a record is reaped, and only one with an agent; any other reads *not made here*.
- **The worktree's tests, all read-only, first.** No commit test: removing the worktree loses no commit, which stays on its branch. They are `reap_worktrees.sh`'s *clean* (with its `ignored_blockers` exemptions: symlinks, a `settings.local.json` that `--settings-disposable` passes — the script owns that path — and a nested worktree `--check` judges; plus `DISPOSABLE_IGNORED` = `__pycache__`, `.pytest_cache`, `.ruff_cache`, `.mypy_cache`, `.pdm-build`, `.pdm-python`, `*.egg-info` and a real `.venv`, a knowing departure from the reaper; a nested `.git` directory always blocks), *idle* (never counting the record being closed or cancelled, by id. It is ported through ShiftLead's own seams: no live record of any adapter, a shell's included, inside the worktree, over `occupants`' host set (the host's own and sharing hosts' while linked, never a machine node's), with its own filter; and no `adapters.external_sessions()` session inside. `external_sessions()` returns `{items, blind}` as dev-cadence's `live()` does, `blind` the adapters it could not read, and a blind adapter keeps; a sharing host whose link is down keeps as *<host> unreachable*) and *nested* (`hydrate_worktree.sh --check`), each as that script defines it; *unlocked* (`git worktree list --porcelain`'s `locked`); git's own `worktree remove` refuses a modified, untracked or locked tree as well. Not its *landed*, which is the branch's. *idle* skips an external session whose tool id is one of ShiftLead's records. `reap` is `True`, `False` (a restart: keep, say nothing) or a why string, taken only from a call with no session caller as `closer` is, that the home sends when a record on a sharing host is inside (`in use by <id@host>`), which the node writes as `worktree_kept`; the node checks its own records again.
- **Port, not call.** The reaper is dev-cadence's SYNCED script and has no single-worktree mode. So the build ports its tests into `gitinfo` beside `ensure_worktree`, each with a comment naming the reaper's test, and runs the hydrate script from the main checkout.
- **Then the reap.** `--dehydrate`, never started past 40 s (`REAP_WITHIN − REAP_STEP`), then `git worktree remove` without `--force`. A refusal after `--dehydrate` hydrates again. No fetch: every test reads local state.
- **Then the branches.** After a successful remove, the checked-out branch and the launch branch (once when they are the same) are each deleted with one `git branch -D` when origin has held the tip. Reads in order: no `origin` keeps every branch as *no origin*; `git symbolic-ref refs/remotes/origin/HEAD` gives the default branch, set aside, and its absence keeps every branch as *no origin/HEAD*; then per branch `git rev-list refs/heads/<b> --not --remotes=origin` plus every value of `git reflog show --format=%H refs/remotes/origin/<b>` when `git reflog exists` says it has one, empty meaning delete, its count the *n* of a kept one (`git branch -d`'s test widened to every `origin` ref, `origin/HEAD` and the member's topic branches among them, and by the whole reflog, not `--fork-point`'s cut; `--remotes=origin` names only refs that exist, so a missing `origin/<b>` is no error; `-d` itself is not run, because a launch branch made from `origin/HEAD` tracks `origin/HEAD`'s branch until a `push -u`). `git branch -D` itself refuses a branch a worktree has checked out, written as *checked out in <path>*; a failed git read keeps as *could not be weighed*; neither raises. A kept branch writes `branch_kept[<b>]` (*n commits never on origin*, *no origin*, *no origin/HEAD*, *checked out in <path>*, *could not be weighed*) and never keeps the worktree; a deleted one is named in `branches_deleted` and the log. The branch step (every branch's reads and `-D`) is exempt from the deadline and bounded as a whole by one `REAP_STEP`, so a late remove still weighs the branches.
- **Where and how long.** After the kill, once `has_session` reads the pane gone. After the `closed` save. Under the `_dir_locks["worktree:<repo>:<name>"]` lock that `ensure_worktree`'s create takes, `<repo>` the main checkout as `worktree_path` resolves it in both, then `_dir_locks[str(directory)]`, both held until the thread returns: `asyncio.to_thread` awaited with no `wait_for`, the lock-holding section a task shielded from the call's cancellation. Each lock is awaited only for what is left of `REAP_WITHIN`; one still held keeps as *busy: a start is using it*. The re-hydrate is exempt from the deadline and runs on every exit after `--dehydrate` but a successful remove. `worktree_reaping` is stamped before `--dehydrate` and cleared at the end, holding the checked-out branch's name (or none); the host agent's start hydrates a record found with it again, as *interrupted*, or, its directory gone, stamps `worktree_reaped_at`, runs `git worktree prune`, runs *Then the branches* on the stamp's branch and the launch branch, and clears the stamp. `REAP_WITHIN = 60` is a deadline the thread reads between steps, starting none past it and never `--dehydrate` past it; each subprocess has its own `REAP_STEP = 20` timeout. The close answers after the reap, its view carrying the result. A Cancel's kept worktree is in its reply (`cancelled: true`, `worktree_kept`) and the log.
- **The record.** `worktree_kept` holds the why, or `worktree_reaped_at` the time, and `branch_kept` a kept branch. A reap clears `worktree_kept`, and so does a tick check of each closed record holding one that only asks `Path.is_dir()`; `_refresh_git`'s `due` filter, which skips closed records, is left alone. A record from before the build that the migration did not mark reads *not made here*. A marked closed record is retried by `ao close`. `ao close` on a `closed` record with `worktree_made` whose directory is there runs the reap again and kills nothing, leaving `closed_at` and `closer` as they were; on one whose directory is gone it runs *Then the branches* again on the branches `branch_kept` names, or, when there is no `worktree_reaped_at` (a directory removed by hand), reads the checked-out branch from `git worktree list --porcelain`'s stale entry at the record's `worktree`, runs `git worktree prune`, weighs that branch and the launch branch, and stamps `worktree_reaped_at`. The retry runs on the record's host as a node act, under the per-name worktree lock awaited within `REAP_WITHIN` (held: *busy*), its branch step bounded by one `REAP_STEP`, and rewrites `branch_kept`: a deleted branch leaves it for `branches_deleted`, a kept one gets its fresh why. `branch_kept` is a map of branch name to why, printed as prose by the card and `ao status`; `branches_deleted` a list. A branch with no `refs/heads/<b>`, and the default branch, are skipped, named in neither field. Never raise out of the close.
- **Started again.** `ensure_worktree` checks out a local `<name>` that is still there as it stands; otherwise it fetches with `--prune` and bases a new launch branch on `origin/HEAD`, except for a Resume, which bases it on `origin/<name>` when that exists and is not contained in `origin/HEAD`. `resume_create` sends `dir = rec["repo"]` with `worktree = rec["worktree"]` when the record has both, and `resume_form_url` fills the form's worktree field the same way.
- **The display.** The Session card's directory line reads *kept — <why>*, *reaped*, or *reaped — branch kept, <why>*. A reaped record draws no Git card and no diff / log / PRs. `ao status` prints all three fields.
- **Help.** Close's paragraph in the §4.5a help list and `help.py` loses *it is the one press that removes a worktree* and *Press it when the work is merged* for: *It reaps the worktree it made, unless that would lose something; a kept worktree says why on the Session card.* Kill's *It is not Close, which also reaps the worktree* stays. Both change in the same PR.

**Done when** these tests pass, on a scratch repo with a bare origin:
- **Reaped:**
  - a clean created worktree with its branch pushed: the worktree and its branch go, origin untouched;
  - a clean worktree with an unpushed commit: the worktree goes, the branch stays with `branch_kept`;
  - a detached HEAD weighs only the launch branch;
  - an exited shell inside does not hold it;
  - a close after a restart (the new record inherits `worktree_made`);
  - a team member's record from before the build, marked by the migration;
  - a worktree that has run `pytest` and `ruff` (its caches are disposable);
  - a Cancel, and the Close of an exited agent record (the closing record never holds its own worktree);
  - every reaping caller, parametrized: the person's Close, `ao close`, rule 9's finished and sit-out closes, a seat's close, `ao team stop --close`, a team Start, `--wind-down`, a scheduled Cancel.
- **Kept, each with its `worktree_kept`:**
  - a dirty tree;
  - an ignored scratch file;
  - a `settings.local.json` holding a new grant;
  - a nested checkout with an unpushed commit, with `hydrate_worktree.sh` present and without it;
  - a live shell record;
  - a locked worktree, read by the *unlocked* pre-test before `--dehydrate`;
  - a worktree the start found already there, as *not made here*, an anchor's among them;
  - a restart's close, for each of the five restarts;
  - a blind `external_sessions()` adapter;
  - a sharing host whose link is down;
  - a timeout, with the lock held until the thread returns and no step begun past the deadline;
  - a Cancel's kept worktree, said in its reply.
- **Branches:**
  - deleted: a branch whose tip is on `origin/<b>`; a branch another session rebased and force-pushed before the close, cleanly or with a conflict (its old tip is in the reflog); one rebased after the close;
  - deleted: a launch branch never pushed with no commit of its own (no `origin/<b>`, reached from `origin/HEAD`, no rev-list error); a launch branch whose commits went out on a topic branch cut from it; and a branch merged with a merge commit; each named in `branches_deleted`;
  - kept, with `branch_kept`: a commit made after the last push; a branch never pushed with a commit of its own (no `origin/<b>`: counted, not an error); a branch checked out in another worktree, as *checked out in <path>*; a failing git read, as *could not be weighed*; a branch with a commit of its own that no other `origin` ref holds, whose remote-tracking ref a `--prune` removed (its reflog went with it) or whose reflog entry expired, or in a repo with `core.logAllRefUpdates` off; *no origin*; *no origin/HEAD*;
  - the default branch is never deleted, and a branch checked out in another worktree is kept by git's own refusal;
  - a launch branch whose upstream is still `origin/HEAD`'s branch is weighed against `origin/<b>`, not its upstream.
- **Over the link:** a node close carries `reap`, and a restart's `reap=False` crosses the link.
- **After a reap:**
  - `check_cadence.row_pushed({"state": "open", "head": b}, root)` reads `na` for a branch another session rebased before or after the close;
  - the one-press Resume starts in a recreated worktree;
  - a Resume bases its launch branch on `origin/<name>`, and on `origin/HEAD` when that ref is stale or pruned; a refill always on `origin/HEAD`;
  - a close cancelled mid-reap keeps both locks until the thread ends, and a create waits;
  - a lock still held at the deadline keeps as *busy*;
  - a reap killed after `--dehydrate` is hydrated again at the host agent's start, as *interrupted*, and one killed after the remove becomes `worktree_reaped_at` with its branches weighed;
  - a remove that ends past the deadline still weighs the branches;
  - the migration is idempotent and leaves a post-build `False` alone, and a refill inherits `worktree_made`;
  - a session caller's string `reap` is refused;
  - `ao close` on a closed kept record reaps it and keeps `closed_at`; the tick's `is_dir` check clears a `worktree_kept` whose directory is gone; a reap that raises leaves the record closed; `ao status` prints the fields; `resume_create` sends `repo` as `dir`;
  - a reap racing a create of the same name waits, and removes nothing under the starting session;
  - the card shows *reaped* with no Git card;
  - `ao close` on a reaped record with a `branch_kept` re-weighs it: after `git remote set-head origin -a` cures *no origin/HEAD*, the branch is deleted and moves to `branches_deleted`;
  - a launch branch deleted by hand before the close is skipped, not *could not be weighed*;
  - a retry of a still-unpushed kept branch keeps it with its count updated; a retry after a rebase deletes it; a retry over two kept branches deletes one and keeps the other with its fresh why;
  - a retry on a closed record whose directory the person removed by hand reads the checked-out branch from the stale registration, prunes, weighs both branches, stamps `worktree_reaped_at`, and a later Resume's `worktree add` at the same path succeeds;
  - a retry racing a create of the same name waits for the worktree lock, or answers *busy*;
  - a default branch checked out in the worktree is skipped, named in neither field.
