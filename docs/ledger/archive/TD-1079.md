## TD-1079: The home rings a node's idle session through its node, and a ring that does not land is `doorbell_failed`, never *rung*

**Priority:** Medium
**Type:** debt
**Added:** 2026-10-26 (the designer, from TD-1051)
**Owner:** grinder
**Kind:** live-check #2439
**Status:** Done
**Location:** `src/sessionorc/agent_wake.py` (`_ring_doorbells`, 142–161: rings only `self.sessions`, and returns on a node; `_ring`, `_bell_failed`); `src/sessionorc/agent_remote.py` (routing an act to a node; the node's handler); `src/sessionorc/mail.py` (`read_when`, 736–743); `src/sessionorc/agent_tick.py:3341` (`_balance_ring`'s docstring, *nothing rings a node's idle member yet*); `src/shiftlead/briefs/manager.md` (the over-the-line paragraph's last sentence, *except one on another host … one `ao send` saying the line is clear* — the nudge's node exceptions in its step 1 and step 2 stay, the nudge being a typed line of rule 4, not the doorbell); design §4.4a *The doorbell rings a node's session through its node*, §4.10 *The doorbell* and the `read_when` table, §6 *Balance*

**Why:** TD-1051 (a): mail to designer-cm-1 and grinder-cm-1 on contractmatch's container node said *rung within a tick*, and nothing was typed, because the home rings only its own host's records and a node rings nothing.

**Fix:** the home's `_ring_doorbells` decides for every record in the graph whose link is up, the node's records included, under the same `_bell_blocked` checks, with every per-record map in `agent_wake` (`_bells`, `_ringing`, `_rang`, `_unread_rings`, `_typing`) keyed by the record's address (`id@host` for a node's, since ids are unique per host only); a node record's ring is a `ring` act routed to its node as `send` is, which the node runs through its own `_ring_typing` checks (empty composer, no send typing, the one line) and answers `typed`, `busy` or `failed`. `doorbell_failed` stays node-owned (`models.py:105`, `NODE_OWNED`): the node writes it on its own record when a retry fails, and it reaches the home in the next report; a link that drops before the verdict is the `unreachable` row's. The home judges a node's `typed` ring (`_bell_answered`, `agent_wake.py:432–450`, the held bell) from the node's report: a node serves its own hooks (`rpc_hook`, `agent_hook.py:40`) and reports fields, not events (`apply_node`/`_overlay`, `models.py:1679–1706`), so the node writes **`ring_seen: {token, at, turned, stopped}`** on its record — a new `Session` field in `NODE_OWNED` alone — set to `{at}` when it types a ring, `turned` stamped at that record's next `prompt` hook and `stopped` at the Stop after it, replaced by the next ring; the home runs `_bell_answered`'s judgement when a report first brings `stopped`, reading its own mailbox on its own clock — an entry with `read_at` at or after the home's dispatch of that ring and at or before the home's receipt of that report ends the run (the window favours *read*: a read between the Stop and the report counts, accepted), never a count the node's lagging hint held nor a node timestamp, so skew cannot flip it. The home's `_rang` entry is keyed by `(address, token)` — `token` minted by the home per dispatch, carried in the act and written by the node into `ring_seen`, so the home knows its own ring without reading a node clock; each `ring` act, a retry included, gets a fresh token, and the home ignores a `ring_seen` whose token is not the latest it dispatched for that record — and judged once: a report repeating the same `ring_seen` counts nothing, and a `ring_seen` replaced by a newer ring, or lost to a node restart, drops the pending judgement uncounted. `_bell_blocked`'s `blocked_in_wait` (`agent_wake.py:116`) compares the record's address with the forwarded wait's `id@node` caller. A node's record is never cache-restarted (`agent_mail.py:893–894` and `agent_tick.py:1211` stay the home's own host's), so its ring skips `_cache_restart`. The act is `ring {id, retry, since, line, token}`, sent as `mux.request("act", rpc="ring", …)` from `_route_act` (`agent_remote.py:480`) under `ACT_TIMEOUT` (`agent_common.py:173`) — a `LinkClosed` or a timeout is *no verdict* — routed by `agent_remote` as `send` is and handled on the node beside its `send` handler: the home runs `_bell_blocked` and keeps `_bells` on its own copy of the record, and passes the copy's `since` (the node-owned state time; `rev` is process-local and never moves on a node's copy, `models.py:1379, 1547, 1561`); the node answers `busy` when its own record's `since` differs (the state moved), the `_typing` lock is held, or the composer is not empty — except on a retry, where a non-empty composer is `failed` (*prompt-stuck*), as `_ring_typing` has it (`agent_wake.py:159–163`); the retry is a second `ring` with `retry: true`. The home checks the budget and the watermark first, charge-free, and records `_decide_wake` on `typed` alone; `busy` is the one-host *next tick looks again*, no decision, no charge, no failure, and keeps no bell; a `typed` or `failed` dispatch keeps the bell for the stretch. Unlike one host, which records `_decide_wake` before it types (`agent_wake.py:206–230`), a node's `failed` ring is not charged and leaves the mail undecided, so a later stretch rings it again — intended, the node's being the kinder; `failed` alone counts as a failure, retried once, then `doorbell_failed` written by the node; **no verdict** (the link drops first) is no failure — nothing charged, nothing written, and the next tick rings again once the link is up. A `busy` from a `since` the home's copy lagged is expected and free. `since` is whole seconds, so an idle→working→idle inside one second is not a new stretch for a node's record — one ring the one-host path would give is skipped, accepted. The act carries the line: `ring {id, retry, since, line, token}`, `line` built at the home by `mail.unread_line`, typed verbatim by the node. For a node's record the home keys the stretch on `since`, not `rev` (`_ring_doorbells` drops `_bells[id]` when `rev` moves, `agent_wake.py:154`, which never happens on a node's copy): a node's state change starts a new stretch, and a report that changes only `doorbell_failed` or `ring_seen` does not. `read_when` reads `doorbell_failed` whose `at` is no earlier than the record's `since` (the current idle stretch), after the wake-budget and lapsed-cache sentences, as *lands; its doorbell failed at <time> (<error>), so nothing was typed — read on its next look or its next `ao` reply*, before the *rung* sentence. `_balance_ring`'s docstring and the `manager` preset's one-send line go.

**Done when:** tests hold, with a fake node link, that an idle hook-confirmed node record with unread mail gets one `ring` routed to its node per idle stretch; that a `busy` verdict charges nothing and is looked at again on the next tick; that a `failed` ring is retried once and then writes `doorbell_failed`; that `read_when` for such a record says the failure and never *rung*; that a record blocked in a forwarded `wait` (caller `id@node`) is not rung;  that a ring with no verdict before the link drops charges and writes nothing and is rung again once the link is up; that the node's `doorbell_failed` report does not ring the record again in the same stretch, and a node state change (a new `since`) does start one; that a report carrying `ring_seen` with `turned` and `stopped` is judged once (the same report twice counts once), one with `turned` alone waits, an entry read before the ring's dispatch does not end the run, and a held bell is written for a node's record with no entry read by `stopped`, and none where one was read just before it; that the typed line is the home's; that a node's idle record past the cache floor is rung, not restarted; and that a down link still reads *unreachable*. A live check on contractmatch's node: a note to an idle member there is typed into its pane within a tick. `pdm run test` and `pdm run lint` pass.
