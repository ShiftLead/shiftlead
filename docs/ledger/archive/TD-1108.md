## TD-1108: A file path on the Queue page or in the Inbox is plain text: it should open in the person's editor, as a path in the pane or a transcript does

**Priority:** Medium
**Type:** feature
**Added:** 2026-10-27 (Paul, through Add entry; drafted by ao-shiftlead-techlead-ao-1)
**Owner:** designer
**Kind:** design-first
**Status:** Resolved
**Location:** `src/shiftlead/ui/queue.py` and `templates/queue_card.html`, `queue_mail.html`, `queue_row.html` (the Queue's cards and their mail); `src/shiftlead/ui/inbox.py` and `templates/inbox_entry.html`, `inbox_row.html` (the Inbox's rows and the message page); `src/shiftlead/ui/transcript.py` (`transcript_paths`) and `static/app.js` (the pane's and the transcript's link provider) for what to reuse; `src/sessionorc/agent.py` (`rpc_paths`, keyed on a record's `id` and `dir`; `PATHS_PRIVATE` in `agent_common.py`); design §4.6 *A path in the pane is a link* and *A path in a transcript is a link too*, *A file button is a file link*; §4.5 screen 12 *Queue* and screen 6 (the Inbox, *The message page*); §4.5a's Queue, Inbox and Transcript rows; §5 `person.open_in` and `person.file_link`

**Why:** Paul, 2026-10-27: "In our Queue page items might list files, lets see if we can leverage the file links we have for the terminal/elsewhere in this page as well. For example, … the png files shown in /home/kmaster/.shiftlead/attachments/draft-7d229223/paste-20261027-103218.png be links to open in vscode (or whatever the user configured). Lets also look for other places to leverage adding links (e.g. inbox) if they do not have them already." Today a path a session names opens in the person's editor from the Focus pane (TD-493) and from a transcript turn (TD-691). The same path in a Queue card's mail, or in an Inbox row or message, is text the person copies out by hand.

**Fix:** design first. The round settles:
- **Which surfaces.** The Queue's cards and their mail, the Inbox's rows and message page; and a survey of the other pages that show text naming files without a link.
- **What resolves a path.** `paths` answers for one record, on that record's host, against its `dir`. A message has a sender record, but a person's own entry and its attachments (the draft folder under `~/.shiftlead/attachments/`, at the home) have none. The round says which host and which directory resolve a run in each case, and what a run on a node's record or a closed record does.
- **The bound.** Keep §4.6's: the shape only asks, the host answers for a readable regular file, `PATHS_PRIVATE` stays text, and nothing a session wrote becomes a control (TD-071). The round checks that an attachment path at the home passes that bound, and adds §4.5a rows for each surface.
- **Images.** Whether an attachment that is an image also shows inline, or only links.

**Done when** the design names each surface, how a run on it is resolved and pressed, and its §4.5a rows, and the build entries are filed.

**Related:** TD-493 (a path in the pane), TD-688 / TD-689 / TD-691 (file links, the file button, a path in a transcript), TD-748 (the Queue), TD-071 (no control from a session's text).

**Resolved:** 2026-10-27 (grinder-ao-1, with its last part) — TD-1115 (#2561). Design: #2477.
