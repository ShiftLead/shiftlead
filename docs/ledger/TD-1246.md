## TD-1246: Start session on every Decide and Do item of a Queue card, with the item as the session's subject; Open session copies its id; the brief's id list names every item

**Status:** Open — slice 1 (Fix item 6, `thread` passes an own end) in #2710; slice 2 (items 2–4: `/api/ledger/start`'s `item`, `work.md`'s item sentence, *waits on me* naming every item; and the Done when's `thread` from a session made in the road's shape) in its PR; slice 3 (items 1 and 5, the page: Start session on each item, Open session copying its id, the help keys) left

**Location:** `src/shiftlead/ui/app.py` (`/api/ledger/start` ~:3147); `src/shiftlead/ui/templates/queue_card.html` (the header's Start session / Open session ~:36–41); `src/shiftlead/ui/templates/inbox_row.html` (the card mode's Start session note ~:1146); `src/shiftlead/briefs/work.md` (the `{opening}` slot, the id-list sentence) and `src/shiftlead/repoconfig.py` (`WORK_OPENING` ~:130, `work_text` ~:274, the first sentence by `why_key`); `src/shiftlead/ui/help.py` (`card-start` ~:612 and ~:801, the header button's title); `src/sessionorc/agent_mail.py` (`rpc_thread` ~:1387, its docstring); `src/sessionorc/mail.py` (`PERSON_ONLY` ~:129, `PERSON_SESSION` ~:171, `own_end` ~:303); `src/sessionorc/agent_common.py` (`person_only` ~:331); `tests/test_person_only.py`

**Why:** design §4.5 screen 12 *Three verbs: Start session* (*Started from an item*), §4.5a row *Queue card: Start session / Open session*, §4.7 `ao inbox --thread`, §4.8 *A person's own act is a named RPC*, ADR 2026-10-19 §9 (TD-1066; Paul, 2026-10-26: *being able to start a session should always be available on Do or Decide items*). Today Start session is once per card, in its header, and the brief's *waits on me* names ledger entries only, so a session started from a card that asks a board line hears *waits on me — none*.

**Fix:**
1. Every Decide and Do item but a red PR draws **Start session**, plain, after its answers and before its ⋯; the header draws it only on a card with no such item. The holder rules read the entry the item starts on: with none of the person's sessions on the card, an item whose entry another session holds draws no button and a stale press is refused 409 *held by <name>* (never answered with `focus`, as the road's holder lookup ~:3234 does today); an item whose entry is free draws its button though another session holds `start`. The item's button has its own title, a new help key (*the person's own session on this item: it opens on the card's entry, or on this entry, with the item as its subject*); `card-start` stays the header's, its words reworded to what is left: the header's button is drawn only where no item asks anything, so *on the one entry owned by you, else the first decision of yours* no longer applies (*on this card's top entry: no item here asks you anything*).
2. `/api/ledger/start` takes an optional `item`: `board:<key>`, `m-…` or `<repo>#TD-n`. A ledger item starts on its own entry when it is one of the card's Decide or Do ledger entries (else refused 409); any other item starts on the card's `start`. `why_key` is read from the entry it starts on, as today.
3. `repoconfig.work_text` (`WORK_OPENING`): with an `item`, the first sentence reads *I opened this session from the Queue about <item>, on the card around TD-n* and asks the session to read the item first (`ao board show <board:key>`, `ao inbox --thread <m-…>`, or the entry) and walk the person through its goal and what each answer leads to; then the id-list sentence and the closing sentences as today.
4. The id-list sentence's *waits on me* carries every Decide and Do item of the card: ledger entries as `<repo>#TD-n`, board lines as `board:<key>`, mail items as `m-…`, a red PR as `<repo>#<n>` — ids only — in the Inbox road too where the reading has the card.
5. With the person's own session on the card, every item's button reads **Open session**: it goes to that session by the header's rule and writes the item's id to the clipboard (`navigator.clipboard.writeText`); where that is refused, the toast shows the id to copy. Nothing is typed into the session.
6. `thread` passes an own end (`mail.own_end`: by hand, interactive, not unattended, no seat) whatever its `controllers`: `agent_common.person_only` gains a second keyword (say `own_end_ok`), since `session_ok` is hard-wired to `person_session`; `thread` stays out of `PERSON_SESSION`, and every other session is still refused in the one shape `tests/test_person_only.py` ~:72 asserts (*<caller> cannot …*), the refusal's *but* clause extended (*…but the person's own shell and an own end of the person's*). `rpc_thread`'s docstring (*which no session reads*) is updated. A Queue-started session has the live manager as its controller, so `person_session` would refuse it. Verify `/api/ledger/start` writes `by_person` on the record it creates and does not create it `supervised` (`agent.py` ~:1507: `by_person = as_person(caller) and not supervised and not seat`). `tests/test_person_only.py`: a third refusal constant for `thread` beside `OLD`/`NEW` and `_refusal` (~:25–34), and the class table (~:121–138, its loop ~:150–180) with `thread` passing an own end — the shells, the three `PERSONS_SESSIONS` classes, and a new controlled `by_person=True` record, which is what tells `own_end_ok` from `session_ok`; the two controlled records without the field stay refused (`mail.py` ~:299); the `PERSON_SESSION` subset test (~:82, ~:86) stands.

**Done when:** tests show a card with a board `act` item and a mail `ask` item drawing Start session on each and none in the header; a card with only a red PR (or none) keeps the header's; a start from the board item posts `item: "board:<key>"`, starts on the card's `start`, and its prompt names `board:<key>` first and in *waits on me*; a start from a ledger item that is not one of the card's Decide or Do entries is refused 409; a start from a ledger item whose entry an unattended worker holds is refused 409 *held by <name>*, and one whose entry is free while a worker holds `start` starts; with the person's own session on the card each item reads Open session and carries the id to copy; `thread` called by a session created through the real `/api/ledger/start` road, with the manager as its controller, answers, and by an unattended or seated session is refused; `pdm run test` and `pdm run lint` pass.
