## TD-1339: #2851's wiring of the pop-up menu's press and `Esc` listeners is held by no test

**Priority:** medium
**Type:** debt
**Added:** 2026-11-03 (test-audit-ao-1, auditing #2851, which built TD-1337)
**Owner:** grinder
**Kind:** build
**Location:** `src/shiftlead/ui/static/app.js` (`document.addEventListener("pointerdown", (ev) => { AO.menuPress(ev.target); }, true)`; `document.addEventListener("keydown", (ev) => { if (AO.menuEsc(ev)) ev.preventDefault(); }, true)`; the `document` `keydown` in the `#rollup` setup block, about line 4376, whose `Esc` calls `rollupClose`); `tests/test_ui_menu.py`

**Why:** `test_a_press_outside_an_open_menu_or_esc_closes_it_and_a_fold_stays_open` calls `AO.menuPress` and `AO.menuEsc` directly, and of the wiring asserts only that *a* capturing `pointerdown` listener was registered (`out.pointerdown_capture`); it never fires one. §4.5a *every page: a pop-up menu* says a press outside and `Esc` close the menu, so the listeners are the behaviour. Probes in a scratch worktree (restored after), `PYTHONPATH=$PWD/src pytest -q tests/test_ui_menu.py`, each *4 passed*: (1) delete the `document.addEventListener("keydown", … AO.menuEsc(ev) …, true);` line, so `Esc` closes no menu and `preventDefault` is never called; (2) change its `pointerdown` handler body to `{ }`, so a press outside closes nothing; (3) change that `keydown`'s `if (e.key === "Escape" && rollupMenu) rollupClose(…)` to `if (false) rollupClose(…)`. The feature is dead in all three, green. Fix: have the probe's `document.addEventListener` keep the handlers and fire a `pointerdown` and an `Escape` `keydown` through them (and a rollup `Esc`, if the probe can reach it), asserting the menu closed and `preventDefault` ran.
