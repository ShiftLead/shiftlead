**Why:** Build TD-1471, slice 1 of 3 (design §4.4 *The ledger is read against origin, as the board is*; §4.5 screen 6 *Boards are read against origin*; §6 *Pull*). The ledger reading reads the checkout's working tree, which moves only at the pull, and the pull waits while a session in the checkout is mid-turn; so every merge — the home's own presses and anyone's PR — reaches the Queue, the Inbox, the Repo page and `ao repo` only a pull later (about seven incidents, TD-1471's Why). TD-1433 patched one case with a per-press hold; the board already reads against origin file by file.

**Fix:** - **The compare** (`src/sessionorc/ledger.py` `reading`, beside `fs_io` and `git_io`): one per read, fetching nothing — the remote-tracking `origin/<default>` as last fetched (`workorders.default_branch`). `base` = `git merge-base HEAD origin/<default>`; `theirs` = `git diff --name-status <base> origin/<default> -- <both layouts' paths>` (the v1 file and the directory, `common_parent` as `entries_before` reads them, so a split on origin not yet pulled reads as origin has it; `layout_at` runs over the overlay io); `ours` = the files the checkout changed since `base` under those paths, committed, staged, unstaged or untracked (`git diff --name-only <base> -- <paths>` plus `git ls-files --others --exclude-standard -- <paths>`). **The rule is by id**, across the open files and `archive/` (an id's `TD-n.md` in either), never by file: an id whose files are in `theirs` and not in `ours` is read as origin has it (`git_io` at `origin/<default>`), absent where origin deleted it; an id origin moved into or out of `archive/` takes origin's placement and file even where the checkout edited the other one, so one id never reads as two files (which `lb.v2_problems` faults, emptying every card); the README and the rank file each as one id of its own; a v1 ledger's file and its archive file are one unit, both from origin where origin changed either and the checkout neither, else both from the checkout; both diffs run `--no-renames -z` (a move into `archive/` is a delete and an add, never an `R100 old new` line); every other id from the working tree, an id in both sets that origin did not move being the checkout's. The listing of the directory and `archive/` is built under the same rule.
- **The ledger reading's own `origin`** `{source, case, files}` (inside `ledger`, not beside it): `source` *origin* when any file came from origin, else *checkout*; `case`, as `_against_origin` has it: *matches* (neither set), *behind* (`theirs` alone), *local* (`ours` alone), *both* (an id in both sets, or no merge-base: every file the checkout's), *none* (origin holds no ledger path: the checkout's files), *skipped* (no `origin/<default>` ref: every file the checkout's); `files` the count read from origin.
- **What origin last gave stands** (the techlead's condition, m-3c38138fd62f): a failed fetch moves no ref, so the compare reads origin as last fetched; a compare whose own git fails (a timeout, a corrupt ref) keeps the last good ledger reading with its error beside it, as `_read_repo`'s failed reads do; only a ref never fetched reads the checkout (*skipped*).
- **The rest of the reading**: `history()` (`ledger.py` near :992) reads `git log` of `origin/<default>` where the ref exists, HEAD otherwise — the revision named before `--` in every `_log` call — its layout the compare's (`layout_at` over the overlay io, never `(Path(root)/rel).is_dir()` in the checkout, near :997), its archive titles from the overlay io's archive text (never `lb.load(rel, *fs_io(root))`), and a v1 sibling's io the overlay's, and the archive it reads through the same overlay io, so `windows`, `recent` and `completed` follow origin; `written()` (near :1055, called at :1200) is, for a file read from origin, the committer time of origin's last commit touching it (from the one walk below), the checkout's mtime otherwise (the TD-1316 hold's test, design §4.4 *The card's status*).
- **The fetch comes first**: the repo reading's due pass (`agent_tick.py` `_read_repo`, near :4081) fetches the default branch with the explicit refspec for every registered repo with a ledger — one with no `board:` too, since `workorders.read_boards` returns before `_against_origin` without one (near :383) — **before** it reads the ledger, and the board's read reuses it: the pass hands `read_boards` the fetch's outcome, and `_against_origin` takes a `fetch=False` (or the outcome) and compares without fetching; a failed fetch's outcome reads as its *skipped* note does now.
- **`written` in one walk**: the commit times of origin-read files come from one `git log --first-parent --diff-merges=first-parent --no-renames --format=%ct --name-only <base>..origin/<default> -- <paths>` per read, newest first — `_log`'s merge flags (near :984) but never its `--reverse` — so a true merge lists its files at the merge's time and the first time a file appears is its last commit (the first time each file appears is its last commit), never a `git log` per file.
- **A pass that began before a press** keeps the press's ledger as it keeps its board: `_refresh_repos`'s carry of a `_reread_board` newer than the pass's start (near :3672) carries `ledger` beside `boards` and `work_orders`.
- **The change test**: `ledger.stamp(root, branch)` returns `origin/<default>`'s sha (`git rev-parse --verify -q refs/remotes/origin/<branch>`; the tick caches `workorders.default_branch(root)` per root, dropped when a pass's fetch finds `origin/HEAD` moved or that ref gone, never the probes on each 2 s tick) beside the path and the newest mtime, and returns `(rel, mtime or 0, sha)` where only origin holds the ledger (None only when neither side has one), so a fetch that moves origin re-reads the ledger on the next tick (`agent_tick.py` near :3642), the rank file then read with it.
- **The fetches move the ref**: every fetch the compare relies on uses the explicit refspec `+refs/heads/<default>:refs/remotes/origin/<default>`, as `workorders._against_origin` does — every `git fetch` in `board.py` (`_tree` near :312, and the write-back's near :484 and the post-merge one near :505 that bring the press's merge in), and `_against_origin`'s whether or not the ref exists yet (its `have` condition, `workorders.py` near :166, goes, so a first fetch creates the ref), so a press's landing moves the ref a narrowed `remote.origin.fetch` would not.
- **The stamp**: the stamp the tick keeps is the one it took before the pass's fetch (`agent_tick.py` near :3640), so a fetch that moves origin costs one more ledger read, without history, on the next tick — accepted, not restamped.
- **Retire TD-1433's hold in this build** (no window with neither): `PRESS_HOLD`, `_ledger_pressed` (its field and comment in `agent.py` near :864), `_hold_pressed`, `_holds_commit` and `_pressed_entries` (`agent_tick.py`), `_carry_live`'s use there, `_reread_board`'s entries branch (`agent_inbox.py`), and `ledger.entries_at` and `ledger.with_entries` where nothing else calls them. `_reread_board` instead re-reads the whole ledger against origin with the board through `_read_repo`'s own ledger step, factored out of it (`agent_tick.py` near :4078–4125) and never a bare `ledger.reading`: `with_history=False`, carrying `windows`, `recent` and `history_error` from the old reading; the Registry and the `LiveReader` (`resolve`, `live`) giving each entry `pickable` and `live`; the old ledger kept on an error; `_settle` observing as the tick's own reading does (`fresh` as `_read_repo` decides it, never forced off), so the marks (`settling`, `held`, `waiting`) are set and an entry first seen by the re-read is recorded and settles; and `completed` derived.
- **The Queue's archive reads the same files**: `queue.reading` (`src/sessionorc/queue.py` near :591, with `archive_entries` near :459 and its call near :636–640) builds its archived entries — the *done #n* rows, the Completed cards, an archived hop of `Part of:` or `Blocked by:` — from the archive's entries the ledger step read in its own thread through the same overlay io as the open entries (`ledger.archived(io, rel)`, new: it takes over `queue.archive_entries`'s parsing — `strip_comments`, `ENTRY_HEAD`, `RESOLVED_LINE` (`queue.py` near :488–495) — and returns the entry dicts with `fields.resolved` filled; the sha-keyed cache goes with `archive_entries`), so one id never reads open and archived at once. The host agent keeps them in memory beside the reading (`self._archived[root]`, never in `self._repos`, never saved by `repos_store`): `_read_repo` and `_read_repos` return `(reading, archived)`, and `_refresh_repos` installs `_archived[root]` with the `repos` update under the same rule that carries `ledger` (a pass begun before a press's re-read, `_boards_pressed >= began`, installs neither over it), keeps it where the ledger read errs or the pass reads no ledger, and pops it when the root goes (`gone`); a press's re-read replaces it with its own. `_queue_pass` (`agent_tick.py` near :3763, `queue.reading`'s one runtime caller) hands them to `queue.reading` as `archived: Mapping[str, list[dict]] | None = None`, so the Queue, on the loop, runs no git; a root with no `_archived` entry yet (after a restart, before its first read) keeps its cards from the last Queue reading rather than drawing them without an archive. The tests that call `queue.reading` (tests/test_queue.py, test_rank.py, test_ui_queue_cards.py, test_ui_answered_hold.py, test_row_controls.py, test_ui_repo_board.py) pass the archive explicitly, through a helper over `ledger.archived`; the tests of `archive_entries`, `archive_of` and `_ARCHIVES` (tests/test_queue.py near :256, its identity-cache assertion dropped; tests/test_ledger_layout.py near :389; the name in tests/test_ledger_writes.py's list near :22) move to `ledger.archived`; `_ARCHIVES` and `_archive_stat` go with `archive_of`/`archive_entries` on the checkout. The `repos` reading carries no archive (it stays the `archived` ids it carries now).
- **The rank's prune reads the same files**: `_rank_lined` (`agent_rank.py` near :270) reads the rank file and the archive through the ledger's overlay io, never `(Path(root)/rel).read_text` and `fs_io(root)`, so a prune never weighs a stale rank file against an origin reading. A landed key already drops once the reading shows it (`_rank_pass`, `_landed`); unchanged.
- Tests (a scratch repo with a bare origin, a second clone pushing to it, the checkout left behind):
  - **A pressed Go** (the techlead's condition, TD-1433's outcome): the lifted entry leaves the card in the press's own `repos` push, with no fetch cadence waited, and stays lifted when a later tick reads the stale checkout, and when a tick's pass begun before the press lands after its re-read.
  - An entry archived on origin while the checkout holds an uncommitted edit to its open file: one entry, archived, the ledger not faulted, `case` *both*.
  - A repo with a ledger and no board: a merge on origin reaches its reading after the next due pass, unpulled.
  - A v1 ledger split into a directory on origin, not pulled: the reading reads the directory.
  - An entry's gate lifted and merged on origin by another clone, the checkout not pulled: after the next fetch the entry has the gate gone and `ledger.origin.source` *origin*; the Queue card, `ao repo`'s lanes and the Inbox's ledger rows read it.
  - An entry archived on origin (moved to `archive/`): listed archived, its `completed` row naming the PR, and the Queue draws its *done #n* row or Completed card before the pull; a new entry added on origin is listed.
  - After a press's re-read, entries still carry `pickable`, `live`, `waiting` and `settling` as the tick's reading gives them, and an entry new on origin, first seen by that re-read (after a first settled reading of the repo), is settling, not pickable; the re-read and the tick may observe at once, under `settle._STORE`.
  - A pass begun before a *Done…* press lands after its re-read: the entry the press archived stays archived in the Queue.
  - A restart: the Queue keeps each repo's last cards until its first ledger read hands it an archive.
  - Two commits on origin touching one entry: `written` is the later one's time.
  - A ledger first added on origin, the checkout without it: the stamp moves with origin, and the reading reads origin's.
  - The split-on-origin case's `windows` and `recent` read the directory's history.
  - A narrowed `remote.origin.fetch`: a press's landing still moves `origin/<default>` and its lift reads at once.
  - A v1 ledger whose entry origin moved into its archive while the checkout edited the file: one entry, read from one side.
  - The checkout's own uncommitted edit to an entry origin also changed: the checkout's copy, `case` *both*; an edit to an entry origin did not change: the checkout's, `case` *local*.
  - A rank file changed on origin re-orders the Queue on the next tick after a fetch moves origin (the stamp); a prune reads origin's rank file.
  - A failed fetch: the reading of origin as last fetched stands; a failed compare: the last good reading with its error; no `origin/<default>`: the checkout's files, `case` *skipped*.
  - A TD-1316 hold: a `done` outcome, then the entry's file changed on origin and not pulled: `written` is origin's commit time, and the hold ends.
