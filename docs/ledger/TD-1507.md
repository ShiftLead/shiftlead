**Why:** Build TD-1471, slice 1 of 3 (design §4.4 *The ledger is read against origin, as the board is*; §4.5 screen 6 *Boards are read against origin*; §6 *Pull*). The ledger reading reads the checkout's working tree, which moves only at the pull, and the pull waits while a session in the checkout is mid-turn; so every merge — the home's own presses and anyone's PR — reaches the Queue, the Inbox, the Repo page and `ao repo` only a pull later (about seven incidents, TD-1471's Why). TD-1433 patched one case with a per-press hold; the board already reads against origin file by file.

**Fix:** - **The compare** (`src/sessionorc/ledger.py` `reading`, beside `fs_io` and `git_io`): one per read, fetching nothing — the remote-tracking `origin/<default>` as last fetched (`workorders.default_branch`). `base` = `git merge-base HEAD origin/<default>`; `theirs` = `git diff --name-status <base> origin/<default> -- <ledger rel>` (renames as delete plus add); `ours` = the files the checkout changed since `base` under the ledger path, committed, staged, unstaged or untracked (`git diff --name-only <base> -- <rel>` plus `git ls-files --others --exclude-standard -- <rel>`). The reading's io (`Io`) answers a file in `theirs` and not in `ours` from origin's commit (`git_io` at `origin/<default>`), absent where origin deleted it; every other file from the working tree. The listing of the directory and `archive/` is the union under the same rule.
- **The reading's `origin`** `{source, case, files}`: `source` *origin* when any file came from origin, else *checkout*; `case` *matches* (nothing in `theirs`), *behind* (all of `theirs` read from origin), *both* (a file in both sets: the checkout's), *local* (only `ours`), *skipped* (no `origin/<default>`, or the compare's git failed, or no merge-base: then every file is the checkout's); `files` the count read from origin. Carried in the `repos` reading beside `ledger` and kept on a failed read with the last good reading.
- **The change test**: `ledger.stamp` adds `origin/<default>`'s sha to what it compares, so a fetch that moves origin re-reads the ledger on the next tick (`agent_tick.py` near :3641), the rank file then read with it.
- **Retire TD-1433's hold**: `PRESS_HOLD`, `_ledger_pressed`, `_hold_pressed`, `_holds_commit` and `_pressed_entries` (`agent_tick.py`), and `_reread_board`'s entries branch (`agent_inbox.py`), go: a decide lift's entries are origin's until the pull. `_reread_board` re-reads the ledger with the board (slice 2 makes that the rule for every landed write).
- **The rank's landed keys** (`agent_rank.py` `_queue_ranked`, `LANDED_KEEP`): a landed key is dropped as soon as the ledger reading's rank holds it, `LANDED_KEEP` staying only as the bound for a reading that never shows it.
- Tests (a scratch repo with a bare origin, a second clone pushing to it, the checkout left behind):
  - An entry's gate lifted and merged on origin, the checkout not pulled: the reading's entry has the gate gone and `origin.source` *origin*; the Queue card, `ao repo`'s lanes and the Inbox's ledger rows read it.
  - An entry archived on origin (moved to `archive/`): the reading lists it archived; a new entry added on origin is listed.
  - The checkout's own uncommitted edit to an entry origin also changed: the checkout's copy, `case` *both*; an edit to an entry origin did not change: the checkout's, `case` *local*.
  - A rank file changed on origin re-orders the Queue on the next tick after a fetch moves origin (the stamp).
  - No `origin/<default>`, and a failed compare: the checkout's files, `case` *skipped*.
  - A decide lift (the board press) shows its lifted gate with no hold, and still does after a tick reads the stale checkout.

**Done when:** The ledger reading — entries, archive, README and rank file — reads each file against `origin/<default>` as the board does, `origin` saying where it came from; TD-1433's hold is gone; each view (Queue card, Inbox ledger rows, Repo page, `ao repo`) is pinned against a just-merged entry change with a stale checkout.
