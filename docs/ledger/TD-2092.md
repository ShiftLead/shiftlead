## TD-2092: The disk sweep can delete the round log of a session started while it runs

**Priority:** Low
**Type:** debt
**Added:** 2026-11-23
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** bbe1289dfdd04d98925ac785b0253bb9

**Why:** The hourly disk sweep reads which sessions are live on the event loop, then does its file work later in a thread. A session created between the two is missing from that reading, so if its name's round log is past the keep age, the sweep removes the log of a live session. A manager restarted under an old name during a slow sweep loses its memory across runs. A throwaway test on 2026-11-23 reproduced it: a reading taken before the create, then the pass, left the record live and its round log gone. The sweep's size rule already guards a stale reading (`still_live`); the age rule for run logs does not.

**Location:** src/sessionorc/agent_tick.py (_sweep_snapshot, _prune_rules)

**Fix:** In `_prune_rules` (`src/sessionorc/agent_tick.py`), read the live records again just before removing a run or round log by age, as the size rule's `still_live` does for a folder, and keep a file a live record now names. This is a held path, so the pull request goes to the techlead.

**Done when:** A test shows a session created after the sweep's reading keeps its old round log through that pass, and the design's §4.6 rule that a round log is kept while a record of its name is live holds for such a session.
