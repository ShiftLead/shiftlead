## TD-1235: The recent-links tick test failed once in a precheck and passes alone: the read for a new tool session did not happen

**Priority:** Low
**Type:** debt
**Added:** 2026-10-29 (grinder-ao-2, seen on #2667's precheck)
**Owner:** grinder
**Kind:** build
**Waits:** event — the test fails again in a precheck or a full run
**Status:** Open — seen once; not reproduced. Read 2026-10-29 (grinder-ao-2): three runs alone passed in about 0.5 s each. The failed precheck ran beside a second precheck on the same machine.
**Location:** `tests/test_recent_links.py` (`test_the_tick_merges_newest_first_a_url_once_and_keeps_twenty`, the `asked[-1] == ("conv-2", 0)` at :209); `agent_tick.py` `_refresh_links`

**Why:** #2667's precheck on c7307c8 (2026-10-29), a clean worktree running the whole suite, failed with `assert ('conv-1', 100) == ('conv-2', 0)` at `tests/test_recent_links.py:209`. The PR adds one ledger file. After the hook names a new tool session, `conv-2`, and the test clears `_links_checked` and ticks, no read happened at all: the last read was still the earlier `conv-1` read at cursor 100. `_refresh_links` reads in a thread (`asyncio.to_thread`) and sets `_links_checked[s.id]` only once the gather returns. So a tick that overlaps the test's own tick and lands after the clear would skip the record, and so would a hook whose `adapter_id` had not landed yet. Neither is shown. This is the third flake of this shape on 2026-10-29, beside TD-1218 and TD-1229, and each one costs a rerun of the whole suite.

**Fix:** on the next failure, make the assertion print the record's `adapter_id`, `_links_checked` for the record and the whole `asked` list, so the failure names which cause it was. If a concurrent tick is the cause, the test drives `_refresh_links` directly rather than a full tick.

**Done when** the cause is named from a failure and the test cannot race it, or a month of full runs passes without it.

**Related:** TD-1218, TD-1229
