## TD-1815: A Grok child's permission prompt carries no subagent marker: how it is read and cleared

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-14
**Owner:** designer
**Kind:** design-first
**Status:** Open
**Id take:** 8488dade48164c89948e18f36e9a5cfb
**Part of:** TD-1550

**Why:** §4.3 *A subagent's events* builds a child's permission prompt as a pending of §4.2's stack keyed by the child's `sessionId` or its `subagentType`, "the walk captures that a subagent's prompt does [carry `subagentType`] … before this is built". The capture of Grok Build 1.0.77 (`tests/conformance/fixtures/grok/captured/hooks-subagents.jsonl`, TD-1637 slice 12) shows it does not: a child's `run_terminal_command` that asks raises a `Notification` `permission_prompt` carrying the **parent's** `sessionId` and no `subagentType`, so the hook cannot tell it from the main session's own prompt. The child's own tool events that end it (`PostToolUse`) carry `subagentType` and the child's `sessionId`, and §4.3 says a subagent's events clear no main pending — so read as written, the prompt sets the main session `needs-you` and nothing clears it until the main session's next tool event (for a foreground child, the `spawn_subagent` `PostToolUse`; for a background child, possibly much later).

**Design PR:** #3793

**Location:** docs/design/4.3-adapter-contract.md (A subagent's events); src/shiftlead/adapters/grok/hook.py

**Fix:** Decide in §4.3 *A subagent's events* how an unmarked prompt raised while a child runs is read and cleared, from the capture: for example, while the record counts a live child, a child's tool-ending event (`PostToolUse`, `PostToolUseFailure`, `PermissionDenied`, a permission's `StopCancelled`) also clears a main-session `permission` pending; or the prompt is read as the main session's and the stale `needs-you` is the accepted cost, as the title-less case is. Then file the build as a part of TD-1550 (the forwarding of a child's events in `adapters/grok/hook.py`, TD-1637's remaining child part).

**Done when:** §4.3 says how a Grok child's unmarked permission prompt is read and cleared, consistent with the 1.0.77 capture, and the build is filed.
