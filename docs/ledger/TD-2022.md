## TD-2022: The gate sweep's board PR title names shiftlead's own entry, so other repos' merge gate refuses it

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-19 (ao-samscrape-grinder-sam-1, through ao td add; drafted by ao-shiftlead-techlead-ao-1)
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 1edbdc6745f5410fa30bfab2a6a8ed1b

**Why:** The gate sweep's own-board PR is titled `board: gate sweep <date> — N filed, M closed (TD-1376)` (`gatesweep._own_board`). TD-1376 is shiftlead's design entry, not the swept repo's, so in a consumer repo the merge gate's ledger row (agent-cadence `check_cadence.py`) refuses it: *TD-1376 named in the title but the PR touches neither ledger file*. samscrape #1140 had to be retitled by hand before it could merge (reported by samscrape's grinder, 2026-11-19), and every sweep PR on every other repo will meet the same refusal, since a sweep PR touches the board alone. The notices PR's title (`_other_board`, for another repo's board) already names no id; the body's fixed sentence keeps its TD-1376 reference, which the ledger row does not read.

The same report notes that by the time a grinder took #1140, three days after it opened, 14 of its 71 decide items named entries whose decision gate had since been lifted or archived on main. Design §4.4 *What the taker does* (*A sweep PR*) merges a sweep PR as filed, a cost accepted on the reading that it is taken within hours; the next day's sweep closes what no longer holds (`_own_board`'s closes). Not this entry's fix: recorded so a design round can weigh it if a repo's sweep PRs keep waiting days.

**Location:** src/sessionorc/gatesweep.py (_own_board's subject); tests/test_workorders.py, tests/test_ui_red_prs.py (fixtures); design §4.4 *What the taker does* (*A sweep PR*)

**Fix:** Drop ` (TD-1376)` from the own-board sweep PR's title in `gatesweep._own_board`, so it names no ledger id, as the notices PR's title (`_other_board`) already does; keep the body's sentence as it is. Add a gatesweep test that the own-board title carries no `TD-` id; the fixtures that copy the old title (`tests/test_workorders.py`, `tests/test_ui_red_prs.py`) assert nothing on it and may take the new one. `gatesweep`'s lift title names the entry it lifts, which that PR touches, so it stays.

**Done when:** A test shows the gate sweep's own-board PR title names no `TD-` id, and the next sweep PR on a consumer repo passes that repo's ledger row without a retitle.
