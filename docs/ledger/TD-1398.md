**Why:** TD-1392's design: the `**Waits:**` line is retired. TD-1218, TD-1229, TD-1237 and TD-1254 wait on *the test fails again in a precheck or a full run*; the home's witness log records a precheck's failure as `precheck-fail`, so each moves to a `host-log` event gate once TD-1388 answers that check (a CI full run is not the home's to witness). They are the last entries with the line once TD-1385 and TD-1397 land, so the reader's second form for a wait goes with them.

**Ask:** Go once TD-1392's review rounds, which ended at the cap, are accepted? Answered on the board's 2026-11-05 decide item for TD-1392, which lists this build among its parts.

**Fix:** As design §4.4 *An entry says what it waits for* now says:
1. Each of the four trades its `Waits:` line for `event (<name>)` with its `**Event (<name>):**` section, `check: host-log witnessed kind precheck-fail "<text>"` where a record's text names the test (`ledger.py edit`, then `set --blocked-by … --field Waits=`), and a `ledger.py note TD-n "moved: Waits … → event (<name>); narrowed to a precheck's failure, its or-a-full-run half dropped"`. The PR body lists each before and after. No helper writes a `gate added` Log line in a migration (`set` logs none and `note` refuses that prefix), so the gate's age reads from the Log's first line, else `Added`, and the first sweep after the move may ask the person about the older ones as still waiting.
2. With no open entry left carrying a `Waits:` line, the reader's `Waits:` branch goes: `waits_of`, `NO_DATE` (`WAITS` stays as the `waiting.on` keys `in_lanes` counts by), every read of an entry's `waits` (`settle.py`'s `mark_waits` and `wait_refusal`, `queue.py`'s `waits` test and `_wait`, whose docstring's *a `Waits:` line in force* follows, `teamrun.py`'s waits words and hover) and their tests; the `Fields:` declaration stays until ledgerboard v2.5's vendor removes it.

**Done when:** `agent-cadence run ledger.py --list --where Waits=`, re-run on the merge's base, lists every open entry (none carries a `Waits:` line with a value); each of the four is waiting on its `host-log` gate; `ledger.py --check` passes on each; and `waits_of` is gone with its tests.
