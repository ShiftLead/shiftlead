## TD-2090: A failed board write can leave a stray file that makes every later write refuse

**Priority:** Low
**Type:** debt
**Added:** 2026-11-23
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 4c5d544ac2454b71923e09677cd1218e

**Why:** The home writes the board and ledger in a tree of its own, and after a failure `board._reset` runs `git reset --hard`, which leaves untracked files. If a write creates a new file (an archived entry, a new board item) and `git add` then fails, the file stays. The next `archive_entry` then finds the archive path already there and is refused on every pass, so the entry never archives. Found by the review of #4376; `_ask_in_tree` goes through the same reset.

**Location:** src/sessionorc/board.py

**Fix:** Make `_reset` in `src/sessionorc/board.py` also remove untracked files from the home's own tree (`git clean -fdq` after the reset), and confirm that tree is never a checkout anyone works in.

**Done when:** A test makes `git add` fail after a write that created a new file, and the next call on that tree succeeds with no leftover file.
