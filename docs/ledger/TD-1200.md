## TD-1200: `ao td next` reads like a question but takes and records an id, so a session runs it as a probe and burns one: rename it `ao td reserve`

**Priority:** Medium
**Type:** debt
**Added:** 2026-10-28 (Paul, in session `queue-deps`; drafted by that session)
**Owner:** designer
**Kind:** design-first
**Status:** Open — design first. The shape Paul agreed is in the Fix; dev-cadence's half (cadence §2.10's name for the front end) was sent to its techlead the same day
**Location:** `src/shiftlead/cli.py` (`cmd_td_next` ~3452, `_td_next_send` ~3492, the `next` subparser and its help ~5099); design §4.7 (`ao td next …` ~214, `--held` ~248), §4.4 (*A ledger entry's id is handed out by the home*, *An entry can land held* ~292, ~1595, ~1615), §4.4a (the `td_next` forwarding row ~150), §4.8 ~274, §4.9b ~118, ~122, §5 ~268; the package briefs `src/shiftlead/briefs/entry.md`, `grinder.md`, `designer.md`, `sweeper.md`; `src/sessionorc/agent_ids.py`, `settle.py`, `agent_rank.py` (the words they print); `docs/claude-memory/` (eight memories and the `MEMORY.md` index name it). 44 mentions in 23 files in all. dev-cadence: `files/docs/cadence.md` §2.10 (*shiftlead's `ao td next`*)

**Why:** `ao td next` takes the next free id from the counter on origin and records it, so every call spends one, `--held` included. Its name reads like a read ("what is the next id?"), so it gets run as one. On 2026-10-28 the drafting session ran `ao td next --held` only to check that the home answered after #2608, and spent TD-1198. A doubled call had spent TD-1148 the day before. Each spent id is a permanent gap in the ledger, and a reader can't tell a gap from an entry lost in a bad merge. Paul, 2026-10-28: *"should we rename "ao td next" to "ao td claim-next" or similar to avoid misfires?"*

**Fix:** design first, then one build. The shape proposed and agreed on 2026-10-28:
- **The name is `ao td reserve [--repo <name>] [--count <n>] [--held]`.** It says the id is taken and spoken for, and `--held` reads naturally after it. Not `claim-next`: *claim* already names `ao progress claim`, a session taking an entry to work, and two claims would invite the reverse mix-up.
- **The output says it took something:** `reserved TD-NNNN (recorded on origin)`, one a line. A script that wants the bare id passes `--json`, or `--quiet` if the design adds one.
- **`ao td next` stays for a while as an alias** that does the same thing and prints, to stderr, `ao td next is now ao td reserve — it reserved TD-NNNN`. Briefs, memories and dev-cadence's cadence §2.10 name it, and a session started from them must not break mid-run. The design says when the alias goes (one release, or once no brief or pinned cadence names it).
- **A probe of the home is a read** (`ao repo`, `ao status`). The design says so in §4.7 beside the command.
- **The words move with it:** the design sections, the package briefs, the help line, the memories and what `agent_ids`/`settle`/`agent_rank` print. History stays as written. The RPC name `td_next` can stay, since it isn't typed.

**Done when** `ao td reserve` hands out ids and says *reserved*; `ao td next` still works and names its new name; the design, the briefs and the help say `reserve`; and dev-cadence's cadence §2.10 names `ao td reserve` at shiftlead's next pin bump.
