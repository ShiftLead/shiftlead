## TD-1338: A Queue card with several Decide and Do items has no Start session that takes them all: add the header's beside the items', with a prompt that walks every item in turn

**Priority:** medium
**Type:** debt
**Added:** 2026-11-03 (Paul, through Add entry; drafted by ao-shiftlead-card-session)
**Owner:** designer
**Kind:** design-first
**Status:** Open — Paul answered *keep both* (2026-11-03, board line 530797e7): the design round, then one build.
**Location:** `docs/design/4.5-ui.md` (screen 12 *Three verbs: Start session*, ~1739–1802: *in the card's header only on a card with no such item*); `docs/design/4.5a-controls.md` (row *Queue card: Start session / Open session*, ~136; row *Queue card: what needs the person*, ~133, its last sentence; the help list, `card-start` and `card-item-start`, ~563–568); `src/shiftlead/ui/templates/queue_card.html` (the header's Start session, ~36–43: `{% if c.items_start %}` draws nothing); `src/shiftlead/ui/queue.py` (`item_start`, ~407, and where `items_start` is set); `src/shiftlead/ui/app.py` (`api_ledger_start`, ~3207–3340, `why_key` and `item`); `src/shiftlead/briefs/work.md` and `src/shiftlead/repoconfig.py` (`WORK_OPENING`, `work_text`, the first sentence by `why_key`); `src/shiftlead/ui/help.py` (`card-start`)

**Why:** Paul, 2026-11-03, through Add entry: *On our Queue page we have "Start session" next to individual TDs, which is good, but there are times that there are multiple questions on a single card that it would make sense to handle in the same session. What are your thoughts on adding a card level "start session" - should it replace the td level one?* Since TD-1246 the header draws Start session only on a card with no Decide or Do item (`queue_card.html`, `{% if c.items_start %}`). Each item's button opens a session *about this item*: the prompt names that one item and asks the session to read it first and walk the person through it. One session can already take the rest. Once the person's session is on the card, every item's button reads **Open session**, goes to it and copies the item's id, and the prompt's *waits on me* lists every item. But the person still starts from one item and pastes the others' ids in by hand, one at a time. Nothing frames the session as *these n questions, one after another*. So a card with three related questions costs three pastes, or three sessions on one card's worktree.

**Decided:** keep both (Paul, 2026-11-03, on the board line this entry put to him): the header's Start session beside the items', not in place of them — the recommendation below. The *If Paul answers replace* bullet of the Fix is moot.

The recommendation is to keep both, not replace. The item's button stays: a card often has one quick question beside slower ones, and starting there keeps the session on that question (Paul, 2026-10-26: *being able to start a session should always be available on Do or Decide items*, TD-1066). The two never fight: the holder rules are already card-wide. Whichever button starts the session, every other button on the card then reads Open session.

**Fix:** the design first (§4.5 screen 12 *Three verbs: Start session*, the two §4.5a rows, the help list), then one build:
- **The header's Start session is also drawn on a card with two or more Decide or Do items** that draw a button (a red PR or a fork's PR draws none and does not count). On a card with one such item the header still draws nothing, since that item's button does the same. Its words are left to the round. *Start session* with its title saying *all n*, or *Start on all n*; a §4.5a row's wording goes in this build's Fix, never in a help-list rewrite.
- **Its road** is `/api/ledger/start` with `{repo, id, card}` and no `item`, as now, starting on the card's `start` (§4.5a *Inbox row: ledger entry: Start session*, widened). Where the card's Decide and Do items are ledger entries, the round decides whether it starts on the first of them instead, so the claim is on an entry the person is answering.
- **Its prompt**: a new opening sentence in `repoconfig.py` (a `WORK_OPENING` key or a constant beside `WORK_ITEM`, swapped in by `work_text` as `WORK_ITEM` is), for the header pressed on a card with items; `work.md`'s template is unchanged. For example: *I opened this session from the Queue to work through every item that waits on me on the card around TD-n, one at a time: for each, read it, tell me its goal and what each answer leads to, and wait for my answer before the next.* The id-list sentence is unchanged (*waits on me* already names every item).
- **Open session** and the holder rules are unchanged (the header's follows its Start session, drawn by the same new rule). The help's `card-start` drops *drawn only where no item on the card asks you anything*.
- **If Paul answers *replace***: the item buttons and the `item` sentence go. TD-1246's slice 3 goes with them, but `item` on the road can stay for the Inbox. This entry's Fix is rewritten to that.

**Done when** a card with two or more Decide or Do items draws a header Start session beside the items'. Its session opens on a prompt that walks every item in turn. Once it runs, every button on the card reads Open session. The design says so in §4.5 screen 12 and §4.5a. `pdm run test` passes, the doc-bound help tests included.
