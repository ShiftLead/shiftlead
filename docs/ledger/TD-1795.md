## TD-1795: ao feedback intake: parse the open feedback report issues into their fixed fields, refusing malformed ones

**Priority:** low
**Type:** feature
**Added:** 2026-11-13
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** f028a54f85574a7bbbfbfa5fa2159e3a
**Blocked by:** TD-1794
**Part of:** TD-1718

**Why:** TD-1718's design: a file-mode run of `/shiftlead-feedback` at shiftlead's home reads the open feedback reports beside its seats. The reports are strangers' text on a public repo, so they are parsed by code into the fixed fields, never read loose by the session.

**Location:** design §4.7 Feedback (Reports from other installs); src/shiftlead/feedback*.py, cli.py

**Fix:** Build `ao feedback intake --issues <file> --root <shiftlead's checkout> --json [--read <number>…]` on TD-1794's `shiftlead.feedback_report`, as design §4.7 *Feedback*, *Reports from other installs*, bullet *The intake, in file mode*, says: read the saved `gh issue list --json number,title,body,author,createdAt` list, oldest first; keep titles that open `feedback report: `; from each body take the first fenced `json` block after the `<!-- shiftlead-feedback-report v1 -->` marker; run the shared rules as the report does (normalize, the pattern pass, the cut), never a copy; cut a report to its first 50 findings (`new` and `known` together, `new` first) and a count over 999; require `commit` to be 7 to 40 hex digits or `null`; refuse a report with no marker, a block that does not parse, an unknown `v`, or a field that breaks a rule, its `why` one of the fixed strings (`no marker`, `block does not parse`, `unknown v`, `<field>: bad type`, `<field>: not allowed`), never a value; drop the report's own `build_day` and derive it from `commit` in `<root>` (`git log -1 --format=%cs`, only where `git merge-base --is-ancestor <commit> origin/main` holds), `null` for a commit off it, a `null` commit, a `--root` that is no checkout, or any failing `git` call. Without `--read`, the summary `{reports: [{number, login, created_at, commit, build_day, days, seats, noise, findings, cut}], refused: [{number, login, created_at, why}], limit_reached}`; with `--read`, the named reports with `new` and `known` in place of `findings`. `login` the author's login alone; `cut` `{findings, counts, text}`; `limit_reached` when the list held 100. Exit 0 when the file was read, whatever was refused; 2 with `{error}` when `--issues` cannot be read or is not gh's list.
Tests: a report TD-1794's `ao feedback report` wrote parses back to its findings; an issue form's body (`### <label>`, a blank line, the pasted text) parses; each refusal, with a refused field's value absent from the output; a 60-finding report cut to 50, a count of 5000 to 999, both in `cut`; a hand-written report's foreign URL, bidi character and backtick handled as the report's would be; the intake's pass and the report's give the same output on one string; a commit on `origin/main` gives its day, one off it, an ambiguous short one, `null` and a bad `--root` give `null`; the summary holds no sentence of any report, `--read` only the named ones'; the author's `name` is never printed; an unreadable `--issues` exits 2.

**Done when:** Done when `ao feedback intake` parses reports as the design gives them, summary and `--read`, round-trips a report `ao feedback report` wrote, derives the build day itself, refuses each malformed kind by issue number with a fixed reason, and exits as the design gives it, with tests for each.
