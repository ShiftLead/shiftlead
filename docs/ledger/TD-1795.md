## TD-1795: ao feedback intake: parse the open feedback report issues into their fixed fields, refusing malformed ones

**Priority:** low
**Type:** feature
**Added:** 2026-11-13
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** f028a54f85574a7bbbfbfa5fa2159e3a
**Part of:** TD-1718

**Why:** TD-1718's design: a file-mode run of `/shiftlead-feedback` at shiftlead's home reads the open feedback reports beside its seats. The reports are strangers' text on a public repo, so they are parsed by code into the fixed fields, never read loose by the session.

**Location:** design §4.7 Feedback (Reports from other installs); src/shiftlead/feedback*.py, cli.py

**Fix:** Build `ao feedback intake --issues <file> [--json]`, as design §4.7 *Feedback*, *Reports from other installs*, bullet *The intake, in file mode*, says: read the saved `gh issue list --json number,title,body,author,createdAt` list; from each body take the first fenced `json` block after the `<!-- shiftlead-feedback-report v1 -->` marker; keep the report's fields (`v, commit, build_day, days, seats, noise, new, known`) and drop any other; cut `what` and `fix` to 300 characters and a report to its first 50 findings (`cut` the rest's count); refuse, naming the issue and why, a body with no marker, a block that does not parse, an unknown `v`, or a field of the wrong type (an area outside the three, a count not a positive whole number, an id not `TD-<n>`). Prints `{reports: [{number, author, commit, build_day, days, seats, noise, new, known, cut}], refused: [{number, why}]}`. Tests: a report written by TD-1794's `ao feedback report` parses back to its findings; an issue form's body (the field's `### ` heading above the pasted text) parses; each refusal; a 60-finding report is cut to 50 with `cut` 10; a field the report does not define is dropped.

**Done when:** Done when `ao feedback intake` parses reports as the design gives it, round-trips a report `ao feedback report` wrote, and refuses each malformed kind by issue number, with tests for each.
