## TD-2047: Read and check a format-3 flow: the reader, the check, the built-in flows and the standard briefs

**Priority:** Medium
**Type:** feature
**Added:** 2026-11-22
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 359154a0571c4545aacee2deca07c700
**Blocked by:** decision (paul)
**Part of:** TD-1954

**Why:** TD-1954's design makes a flow a file of stages, outcomes and limits that a check must pass. Every other build of the design reads a flow through this reader, so it comes first.

**Ask:** Should the builders start on the reader and check for the new flow format?

**Fix:** Build design §4.9c *A flow is records, not prose*, *A flow is usable only when it flows* (rules 1 to 11) and *The built-in flows*: a reader that takes a flow by its `format:` key, the check as `ao flow check <file>`, `ao flow list`, `ao org` listing a flow that is not usable and why, whether a node team can follow a repo's flow, the format-3 built-ins `td`, `build-review` and `build` under `shiftlead/flows3/`, and the standard briefs (design, build, review; docs, tests and code for audits). The trial's checker, `docs/mockups/reviews/td1954-src/trial/flowcheck.py`, is the starting point. The check also owns one more refusal: a flow with a `merge` destination is not usable in a repo the merge gate does not serve. Until the cut-over a team's flow name resolves to the first shape's built-ins only; the format-3 built-ins under `shiftlead/flows3/` are reachable by `ao flow check` and the Flows page alone, and `ao flow list` shows them as not yet in use.

**Done when:** `ao flow check` passes each format-3 built-in and refuses a flow for each of rules 1 to 10 with the stage and outcome named; rule 11 prints which stages carry the builder's independent review. Until the cut-over a `flow.yml` with no `format:` key is still read as the first shape and stays usable, and the first shape's built-ins stay in place and in use. Nothing a running team reads changes. A flow with a merge destination checked against a repo with no pinned agent-cadence is refused with that reason. `ao flow list` marks the format-3 built-ins as not yet in use, and a team's flow name still resolves to the first shape.
