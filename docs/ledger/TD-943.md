## TD-943: A team over an umbrella repo cannot see its sibling repos' PRs: `--pr`, `held:` and the PR readings are the one repo's

**Priority:** Medium
**Type:** debt
**Added:** 2026-10-21 (the designer, from TD-623; guardians-devenv TD-028 step 4)
**Owner:** designer
**Kind:** design-first
**Status:** Open. A team is on one repo (design §4.9 *Teams*): `ao progress done --pr <n>` is an integer read with `gh` in the record's checkout, `held:` globs match that repo's paths, and the red-PR and sync-PR work orders and the PR and Doing facets read that repo alone, so in an umbrella over sibling repos (dev-cadence's `docs/nested-repos.txt`) a sibling's PR number is read as the umbrella's PR of that number, a sibling path can never be held, and an open sibling PR is strandable with no page showing it. `ao team --skill` (TD-623) tells such a team to land paired PRs meanwhile.
**Blocked by:** decision (paul)
**Location:** design §4.9 *Teams*, §4.9c (`held:`), §4.8 (`ao progress`); `src/sessionorc/agent.py` (`_pr_checks`), `src/sessionorc/held.py`, `src/sessionorc/workorders.py`

**Why:** an umbrella is dev-cadence's own shape, so ShiftLead meets it on every constellation; paired PRs
work, but the sibling half has no gate and no page.

**Ask:** Paul answered *Design it* (2026-11-10), since the sibling repos will carry their own tests and so need a real gate; the design now runs with him, shape first in session, then the review rounds: Go once those rounds converge on a shape he agreed?

**Fix:** design first: a repo-qualified PR reference (`owner/repo#n` or a URL) on `--pr` and the record;
whether `held:` and the PR readings follow the umbrella's hydrated siblings; and whether a sibling PR is
gated, and by whose `gate:`.

**Done when** the design says how a team over an umbrella names, reads and gates a sibling PR, and the
builds are in the ledger.

**Related:** TD-623, guardians-devenv TD-028.
