## TD-2072: ao switch-over move and undo: the window's ten steps, the carried work, and going back

**Priority:** Medium
**Type:** feature

**Kind:** build
**Status:** Open
**Id take:** e57397f6d1ec4c85b3dc2b9b86f9d912

**Part of:** TD-1976

**Why:** The home moves from profiles and members to logins and flows in one run, with every team stopped, and can be put back until a team is started (design 4.9e, The window, Work in flight, Going back). Nothing does this today.

**Ask:** Should the builders build the switch-over's move and its undo?

**Fix:** Build ao switch-over move and undo. move runs the ten steps of design 4.9e The window in order, writing each finished step to the journal, which holds the answers' hash, and resuming from it; a changed answers file refuses a resume; a failed step leaves the host agents stopped and says so. --rehearse runs on a copy and stops or starts nothing; --host does one ssh node's steps with its own answers, journal and backup. It writes each host's logins.yml before removing profiles.yml, a container node's from that node's profiles, moves no folder, rewrites each record's login, account and profile, writes every team's settings from the answers, builtins.default, director and schedule, every team's stopped record with its time, and in step 8 the carried entries' stage records through the home's writer of the state branch and the released claims, and last the marker. After the marker the home reads built-in flows from flows3, refuses a flow with no format key, ignores a teams block in org.yml or a repo file and names it in ao org check. A fresh home with no profiles and no teams is moved with no answers. undo puts the backup back and removes the marker, on a finished window or a half-run one, then moves the journal and backup aside; it is refused once a team's record is not the one the move wrote or a session launched since is alive, after printing what is lost.

**Done when:** On a fixture home shaped like today's: move leaves every host switched, every team stopped with its picked flow, logins and counts, the marker written and the backup kept; killed after each step in turn and run again, it ends in the same state; a changed answers file refuses the resume; --rehearse leaves the real files untouched; an open entry with an open pull request has a stage record with no holder at the stage that takes its kind, and a claim with no pull request is released; undo restores every file byte for byte and moves the journal aside, a second move then runs from its first step, and undo is refused after a team's Start. A fresh fixture home is moved with no answers.
