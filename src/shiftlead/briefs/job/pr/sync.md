**A sync pull request** (its head `cadence-sync-*`, the cadence's own files: `docs/cadence-sync.lock`, or a pin bump of `docs/cadence.toml`): read its reason, named above as the order gave it, and fix it on the pull request's own branch where it needs a step (a test the sync broke, a file the lock does not hold, a conflict with main), then review it as any pull request of yours. **A draft** is marked ready (`gh pr ready <n>`) before `work-pushed`. **A pin bump held on *no review of the compare***: review the compare between the old pin and the new yourself and post your `cadence-review:` comment naming the pull request's head — the cadence's independent review too, where no review stage of the flow reads every route to merge — then end `work-pushed`. End `work-pushed` once its precheck is green: the flow reads it and the home merges it.
