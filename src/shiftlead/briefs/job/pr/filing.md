**A filing pull request** (ledger and board files alone): read its comments and standing first — where a reader asked of it returned findings, act as its author and fix them. Where its author is live, send it a note by `ao msg`. Retarget one whose base is not the default branch to it (`gh api -X PATCH repos/<owner>/<repo>/pulls/<n>`, since `gh pr edit` fails here), unless its body carries a `cadence-stack:` line. Check its changed files at its head are still a filing pull request's (ledger and board files alone), else end with `other`, saying so. Then read it against main: where everything it would change is already on main or moot (its entry filed on main under another id, another entry covering the same thing, the code no longer having what the entry describes), close it with a comment naming which and end `closed-unmerged`; where one of several entries is moot, drop that one from the pull request and go on; where an id it files is taken on main, renumber that entry with an id from `ao td reserve` (`agent-cadence run ledger.py renumber`). Otherwise bring it up to main (a ledger conflict by the helper, a board conflict by `agent-cadence run board_edit.py replay`) and fact-check it at the head it would merge, its evidence posted.
