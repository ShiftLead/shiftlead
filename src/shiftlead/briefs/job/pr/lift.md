**A lift pull request** (its head `lift/TD-n/<gate>`, opened by the home's gate sweep): run its precheck and review it as any doc-only pull request (the cadence's fact-check, the reading below its evidence), then, by the head:

- **Every lift but a live check's** first reads `origin/<default>`'s entry: where the gate is gone from its `**Blocked by:**` (lifted by a forced claim or another pull request, re-gated, archived), close the pull request unmerged with a comment saying what changed, end `closed-unmerged`, and run nothing below.
- **A `host-log` gate's lift** (its section's `check:` line on `origin/<default>` names `host-log`) is never re-run: end `work-pushed` on its Log line's evidence.
- **Another event's lift**: re-run the check, `agent-cadence run event_checks.py --json` from a worktree at `origin/<default>`, reading the entry's own row for that gate and never the exit code. *passed*: end `work-pushed`. *not yet* or *impossible*: close it unmerged with a comment naming the reading, the gate standing, and end `closed-unmerged`. *error*, no row, or a row with no outcome is no reading: end `other` with what you read (an error of your own setup — no `gh`, no credentials, no pinned tree — is mended first).
- **An `until` lift**: a dated head ends `work-pushed`. A dateless `…/until` head whose entry's date is still later is closed unmerged with a comment, ending `closed-unmerged`, where the pull request's body opens with the sweep's own sentence *The home's gate sweep (design §4.4, TD-1376) lifts …*; where it does not, it is a person's deliberate early lift, and ends `work-pushed` on your review.
- **A live check's lift** (`lift/TD-n/live`, `live-<digits>`, `live-td<digits>`): re-run the check against `promote/live` as it stands, the same way. *passed*: end `work-pushed` (a red precheck mended first, the gate standing until it merges). *not yet*: turn this pull request, on its own branch, into the fresh gate — its diff against the default branch exactly §4.9b's fresh-gate pull request's: the fresh gate's section added under §4.9b's naming rule (the next free `live-<digits>`; a gate's name is never reused), the lifted gate replaced by it in `**Blocked by:**`, the lift's own section kept, and no *gate lifted* line in the Log — then retitle it *TD-n: a fresh gate <new> in place of <old>* (`gh api -X PATCH repos/<owner>/<repo>/pulls/<n>`), its head kept, and end `work-pushed`. Offered it again and finding its diff already a re-gate, end `work-pushed` without re-running the check; a conflict with main is resolved by writing the same fresh gate again on main's copy, never by `ledger.py lift`. *error*, or no row for that gate: end `other` with what you read.

A conflict with main on any other lift is resolved by main's copy of the entry and the pull request's own lift written again on it: `agent-cadence run ledger.py lift TD-n --gate "<gate>" --by <the --by its Log line names>`.
