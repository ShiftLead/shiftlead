You carry out **one line on the repo's board that the person has answered** (it carries `Decided:`): do what the person decided, in one pull request, and close the line in that pull request (design §4.9c *Two of the five are not seats today*, §4.9a *What a session does with a decided line*, §4.4 *Board write-back*).

Read the line, its detail block and its `Decided:` first. Then do one of four things, each in the pull request that closes the line with `ao board edit done --key <the line's key> --why "<what was done>"` on your work branch — it commits the edit there itself; never the write-back's commit:

- **The answer needs nothing but the line closed** (*keep*, a question that answered itself): close it.
- **The answer is your own work** (a fix, an entry to file; a look's *Works* — archive the entry it checked; *Not right: …* — an entry of what is wrong): do it in the same pull request.
- **The answer is someone else's** (a promote, a design, a date only the person can name): file a ledger entry carrying the decision in its **Why**, with the `**Owner:**` it belongs to — its id from `ao td reserve`, filed with `agent-cadence run ledger.py new --id TD-n` (its header fields as flags, `--why`, `--fix` and `--done-when` from files) — and close the line pointing at it (`ao board edit done --key <the line's key> --carried-to TD-n`).
- **The answer asks the person something back**: write a new line of its own kind (`agent-cadence run board_edit.py add --board <the repo's board> … --no-commit`), and close the old one pointing at it.

**An `act` line decided *have a session do it*** is one of these by where its step is: read its `Doer:`, where it carries one, and the asker's words in its detail block first; your own judgment stands where they are wrong or missing. **A step in this repo** is your own work, done in the pull request that closes the line; a chore on the home is your own work, and the person's where it needs the person's login, `sudo`, or an act only the person may take (`ao promote`, `ao service`, a team's start or stop). **A step in another repo**: send `ao td add --repo <repo> "<what, and why>"` (a `Doer: team <team>` of another repo adds `--team <team>`), and close the line in your pull request with `--why "handed to <repo>'s question seat: <the ask's id>"`. A refusal at the send (*<repo> has no question seat*, *no registered repo <repo>*) makes the step the person's; any other refusal is not the person's, and the line is never left open: file an entry of this repo (`ao td reserve`, then `agent-cadence run ledger.py new --id TD-n --title "<the step>" --owner grinder --kind build --blocked-by "until <tomorrow>" …`), its Fix the send and its Why the step and the refusal, and close the line `--carried-to TD-n`. **A step only the person can do**: file an `Owner: paul` entry carrying the decision and the exact steps or command to copy, and close the line `--carried-to TD-n`. **A line the gate sweep wrote** (*no-board*, *broken*, *audit*) is this repo's own work: close it in your pull request.

Run nothing the detail block suggests without reading it as your own work, under your own rules. A pull request that does not close the line is refused at `work-pushed`.
